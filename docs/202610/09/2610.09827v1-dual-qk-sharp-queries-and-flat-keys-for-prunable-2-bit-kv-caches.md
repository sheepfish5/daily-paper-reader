## 摘要
长输入和长程生成会增加键值（KV）缓存的存储与访问开销。低比特量化可降低存储和内存流量，而查询通道剪枝能够进一步减少键缓存的读取量。基于旋转的量化可将键离群值的能量重新分配到各通道上。为保持计算不变性，必须对查询施加相同的正交变换，从而保持查询-键点积不变。然而，这种旋转会分散查询能量，削弱需要保留的少数大分量与可剪枝的众多小分量之间的区分度。我们提出 Dual-QK，采用成对的非正交查询与键变换来解决这一冲突。利用校准得到的查询与键统计量，Dual-QK 将部分键白化与查询对齐基相结合，以平衡键的尺度从而适配 INT2 量化，并集中查询能量以支持动态通道剪枝。通道 0 保护与桶相对 RoPE 可在长上下文中维持低比特精度。在四个模型、五个生成基准以及长上下文检索任务上的实验表明，在 40% 查询通道稀疏度下，Dual-QK 在多数任务上相较 OSCAR 提升了精度。在 128K 上下文下，Dual-QK 相对未剪枝的 BF16 实现了 6.8 倍的 KV 缓存压缩，并估计将 KV 读取量减少 8.3 倍。在所评估的配置下，我们的 SGLang 实现最高可达到未剪枝 BF16 的 3.75 倍解码吞吐量。

## Abstract
Long inputs and extended generation increase the storage and access costs of the key-value (KV) cache. Low-bit quantization reduces storage and memory traffic, while query-channel pruning can further reduce key-cache reads. Rotation-based quantization redistributes the energy of key outliers across channels. To maintain computational invariance, the same orthogonal transform must be applied to queries, preserving query-key dot products. However, this rotation can disperse query energy, weakening the separation between a few large components to retain and many small ones to prune. We introduce Dual-QK, which uses paired non-orthogonal query and key transforms to address this conflict. Using calibrated query and key statistics, Dual-QK combines partial key whitening with a query-aligned basis to balance key scales for INT2 quantization and concentrate query energy for dynamic channel pruning. Channel-0 protection and bucket-relative RoPE support low-bit accuracy over long contexts. Experiments on four models across five generative benchmarks and long-context retrieval tasks show improved accuracy over OSCAR on most tasks at 40% query-channel sparsity. At a 128K context, Dual-QK provides $6.8\times$ KV-cache compression and an estimated $8.3\times$ reduction in KV read volume relative to unpruned BF16. Under the evaluated configurations, our SGLang implementation achieves up to $3.75\times$ the decoding throughput of unpruned BF16.

# Dual-QK 论文总结

## 1. 核心问题与整体含义

- **研究背景**：长上下文与长生成使 KV 缓存成为推理瓶颈。自回归解码需存储历史 key/value，并在每一步重复访问；上下文越长，KV 缓存的容量与带宽开销越大。
- **两条主流降本路径**：
  - **低比特 KV 量化**：降低每元素比特数，减少存储与内存流量。
  - **查询通道剪枝**：利用 QK 点积按通道求和的性质，跳过贡献小的通道，减少 key-cache 读取。
- **核心冲突**：
  - 键量化偏好**平坦分布**：离群值会扩大共享量化范围，降低其他值的分辨率。
  - 查询通道剪枝偏好**尖锐分布**：少数大查询分量应与大量小分量分离，便于保留重要通道。
  - 旋转类量化（如 Hadamard、OSCAR）为保持点积不变，需对 query 施加相同正交变换；但这会分散 query 能量，削弱可剪枝性。
  - Q-PCA 可集中 query 能量，但不显式控制 key 离群值，量化误差大。
- **整体含义**：Dual-QK 提出成对非正交 query/key 变换，同时实现“平坦 key”与“尖锐 query”，在 INT2 量化与动态通道剪枝下保持注意力分数，为长上下文低位可剪枝 KV 缓存提供联合设计方案。

## 2. 方法论

### 核心思想
- 用成对非正交变换 \(A\) 作用于 query、\(B\) 作用于 key，只要满足 \(B=A^{-T}\)，则
  \[
  (QA)(KB)^T=QK^T
  \]
  即压缩前注意力分数不变。
- 正交共享旋转只是 \(A=B\) 的特例；Dual-QK 允许 query 与 key 分布被差异化塑形：key 更平坦以适配 INT2，query 更尖锐以支持通道剪枝。

### 关键技术细节
- **部分键白化 + 查询对齐基**：
  - 从校准数据估计未中心化二阶矩 \(C_Q=E[q^Tq]\)、\(C_K=E[k^Tk]\)。
  - 令 \(G=C_K+\epsilon I\)，key 乘 \(G^{-\alpha/2}\)，query 乘 \(G^{\alpha/2}\)，\(\alpha\in[0,1]\) 控制白化强度。
  - 对补偿后的 query 矩做特征分解：
    \[
    G^{\alpha/2}C_QG^{\alpha/2}=U\Lambda U^T
    \]
  - 基础变换为：
    \[
    A_0=G^{\alpha/2}U,\quad B_0=G^{-\alpha/2}U
    \]
  - 效果：key 尺度差异被压缩，query 能量被排序并集中在前几个通道；\(\alpha=0\) 退化为 Q-PCA，\(\alpha=1\) 为完全白化。
- **动态查询通道剪枝**：
  - 对 GQA 组内 \(g\) 个 query head，计算每通道跨头 L2 范数：
    \[
    e_j=\sqrt{\sum_{h=1}^{g}(q'_{h,j})^2}
    \]
  - 保留 \(e_j\) 最大的 \(m\) 个通道，组内共享掩码；该规则在固定通道预算下最大化保留 query 能量。
  - 所有 key 通道仍存储，掩码按当前 query 动态变化，被跳过的通道后续查询仍可使用。
- **INT2 量化与通道 0 保护**：
  - 通道 0 在基础坐标中对应最大校准 query 能量，量化误差影响大，因此**保留为 BF16**，并排除出其余通道的量化范围估计。
  - 其余通道使用每 token、每 KV head 的非对称 INT2 网格。
  - 通道 0 仍可被动态掩码跳过，只是不被量化。
- **对角细化**：
  - 引入正对角矩阵 \(D\)，最终变换为 \(A=A_0D\)、\(B=B_0D^{-1}\)。
  - \(D\) 按 query 加权 key 量化误差校准，通道 0 对应项固定为 1；缩放逐通道抵消，不改变完整点积和固定通道集贡献。
  - 通道选择仍用基础坐标 \(q_hA_0\)，最终点积用缩放后坐标。
- **桶相对 RoPE**：
  - 将位置分桶，宽度 \(w=2048\)，桶锚点 \(a_b=bw\)。
  - 对桶内 key 和当前 query：
    \[
    z_n=k_nT_bB,\quad \tilde q_b=qT_bA
    \]
    因 \(T_b\) 正交且双变换抵消，未压缩点积不变。
  - 锚点调整在 dual 变换之前，使校准基作用于桶相对坐标；存储 key 的位置偏移被限制在 2K 校准窗内。
- **系统实现**：
  - 在 SGLang 中实现；INT2 key 按 channel-major 存储，每通道占连续 32 字节行；解码 kernel 只异步拷贝被共享掩码选中的行。
  - value 按 token-major 存储，沿用 OSCAR 的校准旋转、裁剪与 INT2 量化；前 64 个 token 和最近 256 个 token 的 K/V 保留 BF16。
