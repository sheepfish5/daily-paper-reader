## 摘要
随着 LLM 处理的文本上下文规模增长，KV 缓存的大小可能超过分配给原始模型权重的内存。这会对 LLM 吞吐量产生负面影响，因为解码受内存限制，且解码开销随缓存大小增长。近期工作通过丢弃最不相关的 token 来缓解这一瓶颈。淘汰会引入矛盾：一次性决定丢弃内容可能在之后被证明有害。相反，我们关注无需淘汰 token 即可实现缓存压缩的其他选择。我们通过学习一个选择器来实现这一点，该选择器能够基于上下文生成逐层缓存配置，以逼近总体压缩预算。该选择器沿三个轴运行：跨层共享一个缓存（深度）、以更少比特进行缓存（精度），或截断低秩潜在缓存表示（秩）。我们将所得方法称为 KV-Kaizen，因为它复合了许多细粒度的逐层选择。我们观察到，如果独立且统一地对所有层采取这些干预，会限制可实现的压缩，因为它们会降低准确率。关键在于，以局部且适应上下文的方式将它们组合起来，反而能在实现大幅内存节省的同时保持准确率。在推理时，选择器在预填充之前运行一次。在指令遵循和推理任务的评估中，我们的选择器在准确率与缓存大小的权衡上达到帕累托前沿，并优于无需学习和事后基线。在长上下文任务中，KV-Kaizen 改进了淘汰方法，并可与之组合，在 14B 模型上实现解码时缓存缩小 32 倍，同时保持准确率。对于 7B 及以上参数的模型，缓存大小减少 4 倍不会造成准确率下降，并且压缩后的模型比具有相同缓存大小的更小未压缩模型更准确。总之，这些发现支持先预训练大模型，然后仅在后面对其进行压缩。

## Abstract
As the context size of text processed with an LLM grows, the size of KV caches can outstrip the memory allocated for the original model weights. This impacts LLM throughput negatively, since decoding is memory-bound and decode cost grows with cache size. Recent work alleviates this bottleneck by discarding the least relevant tokens. Eviction introduces a tension, since a one-off decision to discard content may prove detrimental later. Instead, we focus on alternative choices that can lead to cache compression without evicting tokens. We achieve this by learning a selector that is able to produce, based on context, a per-layer cache configuration towards an overall compression budget. The selector operates along three axes: sharing one cache across layers (depth), caching at fewer bits (precision), or truncating the low-rank latent cache representations (rank). We call the resulting method KV-Kaizen, for the many small per-layer choices it compounds. We observe that these interventions taken independently and uniformly over all layers limit achievable compression because they degrade accuracy. Crucially, composing them locally and adaptively to the context can instead preserve accuracy while achieving large memory savings. At inference, the selector runs once, before pre-fill. In evaluations on instruction following and reasoning tasks, our selectors reach the Pareto frontier of accuracy against cache size, against learning-free and post-hoc baselines. On long-context tasks, KV-Kaizen improves on eviction and can be composed with it, reaching a 32x smaller decode-time cache on a 14B model while preserving accuracy. A 4x cache size reduction incurs no accuracy degradation from 7B parameters up, and a compressed model is more accurate than a smaller uncompressed one with the same cache size. Together, these findings support pre-training large models and compressing them only afterwards.

# KV-Kaizen 论文总结

## 1. 核心问题与研究动机

- **KV 缓存成为长上下文推理的主要瓶颈**：随着 LLM 处理上下文增长，KV 缓存大小可超过模型权重本身。例如 Qwen2.5-14B 每 token 缓存 192 KiB，服务 32 条 8k 序列即需 48 GiB，超过 bf16 模型权重。解码每步需读取全部 KV 缓存，因此解码是内存带宽受限而非计算受限。
- **现有主流方案存在缺陷**：近期工作通过丢弃最不相关 token（eviction）来压缩缓存，但 token 重要性是查询相关的，一次性丢弃决策在后续查询中可能被证明有害。
- **本文主张非驱逐式压缩路线**：不丢弃任何 token，而是让每个被保留的 token 更便宜。具体沿三个正交轴压缩：**深度**（层间共享缓存）、**精度**（低位量化）、**秩**（低秩潜在表示截断）。
- **关键洞察**：单独且统一地对所有层施加某一压缩轴会限制可达到的压缩率并损害准确率；**局部、自适应地组合多个温和压缩**可在保持准确率的同时实现大幅内存节省——这正是"改善（Kaizen）"式小幅累积改进的隐喻。

## 2. 方法论

### 核心思想
训练一个轻量**选择器**，读取 prompt 后为每一层输出一个缓存配置动作，使整体缓存成本逼近给定压缩预算。选择器与骨干模型在 SFT 阶段联合训练，使模型适应其将要被服务时的缓存形态。推理时选择器仅在预填充前运行一次，配置在整段生成过程中保持固定。

### 动作空间（三轴统一为"每 token 比特数"）
- **深度**：每层要么生成自己的缓存（anchor），要么继承最近 anchor 的 KV（成本为 0）。
- **秩**：基于 MLA，将潜在表示 $c^{KV}_l \in \mathbb{R}^r$ 截断为前 $d$ 个坐标；非 MLA 模型先用 CARE 转换为 MLA。保留宽度集合为 $\{r/8, r/4, r/2, r\}$。
- **精度**：对称均匀量化，每 token 一个 scale，比特宽度 $b \in \{2,4,8,16\}$，前向量化-反量化、梯度直通。

单动作成本：
$$c(a) = \begin{cases} 0 & a = \text{inherit} \\ (d + d_R)\cdot b & a=(d,b) \end{cases}$$
压缩比 $\rho(a_{1:L}) = C_0 / \sum_l c(a_l)$，其中 $C_0 = L\cdot 2n_{kv}d_h\cdot 16$。动作空间大小为 $|D|\cdot|B|+1 = 17$（如图 1 所示）。

### 选择器与训练
- 架构：将骨干 token embedding 投影到 256 维，经两个双向 Transformer 块，时间轴平均池化得到共享特征 $z$；每层一个独立线性头输出 17 个动作 logits。参数量 2.6–3.7M（7B 以上占比 <0.05%）。
- 训练：Gumbel-softmax + 直通估计器，温度从 2.0 退火到 0.1，评估时用 arg max；头初始化使初始 arg max 为最不压缩动作。
- 损失函数：语言建模损失 + 速率项
  $$\mathcal{L}_{\text{rate}} = \beta \cdot \mathbb{E}_i\left|\frac{1}{\rho_i} - \frac{1}{\rho^\star}\right|$$
  其中 $\beta$ 采用自适应规则：当实际压缩未达标时增大、达标后放松，默认上限 $\beta_{\max}=10^4$，避免逐配置调参。
- **预算条件化**：将归一化目标 $\tilde\rho^\star$ 经零初始化 FiLM 层注入池化特征，使一个选择器服务多个压缩目标。

## 6. 主要结论与发现

- **4× 压缩在 ≥7B 模型上无精度退化**（表 1：7B −0.009/0.000，14B +0.040/+0.031，均在种子波动内）；3B 所有配置均落后控制。
- **组合优于单轴**：precision + depth 在非 MLA 骨干上可匹配 precision 单独的效果，而 depth 单独远落后；超过 8× 后非 MLA 骨干必须依赖 depth（至少一半层继承）。
- **长上下文**：14B 上 4× 配置在 RULER QA 达 0.614，优于 SnapKV(0.501)、PyramidKV(0.485) 和 4-bit KIVI(0.515)；与 SnapKV（keep 1/8）组合达 32× 缓存缩小且 QA 仅降 0.012。
- **优于服务更小模型**：压缩后的 7B 比同等缓存大小的 1.5B/3B 未压缩模型更准确。
- **选择器行为**：部分选择器随输入变化（最多 20/224 个不同配置），部分退化为单一全局配置；depth 被视为"最后手段"，仅在 precision/rank 无法满足预算时使用。
- **预算条件化**：{1,2,4} 范围可单选择器覆盖；更宽范围 [2,8] 需双倍训练步数，且更宽集合会导致选择器停止遵循请求、β 不收敛。
- **支持"先训练大模型、再压缩"的部署范式**。

## 7. 优点

- **统一成本模型**：将深度、秩、精度三轴归约为"每 token 比特数"这一单一标量，使跨轴比较与联合优化成为可能，动作空间定义清晰。
- **组合性设计**：三轴压缩比可相乘，且与驱逐方法正交可叠加（4× × 8× = 32×），提供灵活的部署旋钮。
- **训练与配置协同**：强调必须在目标配置下训练模型（事后套用配置会崩溃，图 3 底部），并通过直通估计器与 Gumbel-softmax 实现端到端可微选择。
- **自适应 β 规则**：避免逐配置调参，单一设置覆盖所有固定目标，显著降低实验成本。
- **预算条件化**：FiLM 注入使一个选择器服务多个硬件/精度需求，具有实际部署价值。
- **评估严谨**：所有对比在同训练配方、同注意力类的控制下进行，包含搜索基线（动态规划）与随机/均匀基线，并报告种子波动。
- **真实设备验证**：在 Apple M3 Ultra 上实测预填充时间、解码吞吐与峰值内存，而非仅理论估算。

## 8. 不足与局限

- **MLA 转换代价**：秩轴依赖 CARE 转换，转换本身损失精度（表 1：−0.105 至 −0.178），且该损失随模型规模非单调（32B 反而 −0.131），限制了秩轴在非 MLA 模型上的适用性。
- **缺乏专用 kernel**：混合宽度与比特宽度的逐层配置需要定制 kernel 才能完全兑现内存与速度收益；4-bit 缓存的去量化成本会拖慢预填充，MLA 在短序列上收益有限。
- **预算条件化的范围限制**：宽目标集合会导致选择器不遵循请求、β 不收敛（表 18），且需要更多训练步数。
- **选择器多样性不稳定**：部分选择器在测试时可被单一全局配置替代，是否可替代取决于选择器，需在代表性数据上验证，增加了部署不确定性。
- **depth 的破坏性**：depth 是"要么全有要么全无"的改变，在推理任务上代价尤其大（表 11：GSM8K 0.245 vs 0.639），仅在必须时才使用。
- **训练成本**：三轴全开时训练时间达普通微调的 1.9–3.1 倍；SFT 本身在 7B/14B 上会带来 −0.025/−0.052 的精度变化，Mistral 上达 −0.152。
- **设备基准覆盖面窄**：仅 Apple M3 Ultra、单一模型、batch size 1，未覆盖 GPU 服务场景与高并发。
- **算力细节披露有限**：仅说明 A100/H100/Blackwell 与 8 卡配置，未给出总 GPU 小时数或能耗数据。
