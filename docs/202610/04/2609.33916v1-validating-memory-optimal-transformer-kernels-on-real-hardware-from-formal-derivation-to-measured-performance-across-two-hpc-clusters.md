## 摘要
我们验证了通过数组数学（Mathematics of Arrays, MoA）推导出的 Transformer 内核的内存最优代价函数。配套论文 I–IV 将注意力前向、反向、前向+反向融合、解码以及完整模块（RMSNorm、门控 MLP）的内核形式化推导为硬件无关的规范（DNF），并通过 gamma 转换为机器特定的实现（ONF），且与 PyTorch 进行了达到机器精度的验证。本文在两个 HPC 集群（Purdue Anvil、NCSA Delta）的 CPU 和 GPU 上，用实测性能检验这些预测。三项结果尤为突出。(1) 我们发现并修复了一个 GPU 性能回退：融合前向+反向虽被证明可避免物化 O(n^2) 中间结果，但由于原子竞争，最初在 GPU 上比朴素实现更慢。性能分析确认原子指令多出 2.00 倍；针对性的 ONF 重写扭转了这一情况，带来最高 2.5 倍的加速。(2) 相同的推导因拓扑结构而产生显著不同的实际开销：在一个集群上出现 535 倍的 NUMA 局部性惩罚，而在另一个集群上仅为 <3 倍的超订，表明最优部署是机器数组结构的函数。(3) 我们报告一个部分解决的异常：相同的指称计算在 CPU 上用 C 比 Fortran 运行更快，但在 GPU 上 Fortran 比 C 更快，并将其缩小到一个主导内核和一种内存延迟停顿机制（3.17 倍的时间差距与 3.35 倍的停顿差距相符）。我们将硬件特定的优化视为一种常规的 ONF 重写，其 DNF 固定且已验证，这是一种将 AI 扩展到不断演进的硬件而无需重新推导正确性的候选方法。

## Abstract
We validate memory-optimal cost functions for transformer kernels derived via the Mathematics of Arrays (MoA). Companion Papers I-IV formally derive kernels for attention forward, backward, fused forward+backward, decode, and the complete block (RMSNorm, gated MLP) as a hardware-independent specification (DNF) transformed to a machine-specific realization (ONF) via gamma, with verification to machine precision against PyTorch. This paper checks those predictions against measured performance on two HPC clusters (Purdue Anvil, NCSA Delta) across CPU and GPU.   Three results stand out. (1) We identify and fix a GPU regression: fusing forward+backward, proven to avoid materializing an O(n^2) intermediate, initially ran slower than naive on GPU due to atomic contention. Profiling confirmed 2.00x more atomic instructions; a targeted ONF rewrite reversed it, yielding up to 2.5x speedup. (2) Identical derivations produce markedly different real costs by topology: 535x NUMA-locality penalty on one cluster vs <3x oversubscription on another, showing optimal deployment is a function of the machine's array structure. (3) We report a partially resolved anomaly: identical denotational computations run faster in C than Fortran on CPU but faster in Fortran than C on GPU, narrowed to one dominant kernel and one memory-latency stall mechanism (3.17x time gap matches 3.35x stall gap).   We treat hardware-specific optimization as a routine ONF rewrite with fixed, verified DNF, a candidate methodology for scaling AI onto evolving hardware without re-deriving correctness.
