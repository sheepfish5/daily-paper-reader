## 摘要
并发自回归推理产生了一个根本性的干扰问题：预填充一个新到达的长提示词可能会延迟已在解码请求的 token。固定预填充块可以减轻这种干扰，但最佳块大小取决于模型、硬件、负载和延迟目标。我们提出了解码延迟反馈预填充（DLFP），这是一种无模型控制器，仅改变与活跃解码重叠的预填充工作。在一个受保护的调度周期之后，DLFP 将观测到的时间间隔作为比例反馈来调整下一个预填充块的大小；孤立的预填充仍不受限制。我们在 vLLM 中实现了 DLFP，并使用开环泊松到达、精确 token 计量、原始请求轨迹和 NVIDIA 遥测对其进行评估。在单张 A100 80 GB GPU 上以 BF16 运行 Qwen3-0.6B 时，三次配对的 100 请求试验将 P99 token 间延迟分别降低了 24.8%、30.1% 和 28.2%（平均 27.7%，配对 95% 置信区间为 21.0% 至 34.3%），且输出完全一致、无失败、SLO 合规性不变。这种收益并非没有代价：平均 P99 首 token 时间增加了 34.8%，但仍处于所声明的 SLO 之内。关键的是，该机制无法泛化到 Qwen3-8B、Qwen3-32B 或双 GPU 张量并行配置。我们将失败追溯到异步调度器调用间隔，它仅是完成 GPU 迭代时间的一个代理。这一负面结果界定了该贡献的边界，并推动我们为并发 CPU 与端侧推理设计一种基于完成时间的控制器。我们不宣称移动设备性能；当前工作是一项可复现的概念验证与泛化研究。

## Abstract
Concurrent autoregressive inference creates a fundamental interference problem: prefilling a newly arrived long prompt can delay tokens for requests that are already decoding. Fixed prefill chunks reduce this interference, but the best chunk size depends on the model, hardware, load, and latency objective. We introduce Decode-Latency Feedback Prefill (DLFP), a model-free controller that changes only prefill work that overlaps active decodes. After a guarded scheduling cycle, DLFP uses the observed interval as proportional feedback to resize the next prefill chunk; isolated prefills remain unrestricted.   We implement DLFP in vLLM and evaluate it with open-loop Poisson arrivals, exact token accounting, raw request traces, and NVIDIA telemetry. On Qwen3-0.6B in BF16 on one A100 80 GB GPU, three paired 100-request trials reduce P99 inter-token latency by 24.8%, 30.1%, and 28.2% (mean 27.7%, paired 95% confidence interval 21.0% to 34.3%) with exact output agreement, no failures, and unchanged SLO compliance. The benefit is not free: mean P99 time to first token increases 34.8% while remaining inside the declared SLO.   Crucially, the mechanism does not generalize to Qwen3-8B, Qwen3-32B, or a two-GPU tensor-parallel configuration. We trace the failure to an asynchronous scheduler-call interval that is only a proxy for completed GPU iteration time. This negative result defines the boundary of the contribution and motivates a completion-timed controller for concurrent CPU and on-device inference. We do not claim mobile-device performance; the present work is a reproducible proof-of-concept and generalization study.

# 论文总结：Decode-Latency Feedback Prefill（DLFP）

## 1. 核心问题与整体含义

- **背景**：自回归 LLM 推理分为预填充（prefill）与解码（decode）两个阶段。连续批处理虽提升利用率，但将新到的长提示词与活跃解码请求混批时，预填充工作会进入关键路径，造成所有正在解码用户可感知的延迟尖峰。
- **痛点**：固定大小分块预填充虽能缓解干扰，但最优块大小随模型、硬件、负载和延迟目标变化，调参脆弱；大块导致解码停顿，小块增加调度/内核开销并把延迟转移到首 token 时间（TTFT）。
- **边缘场景动机**：笔记本助手一边生成一边索引文档、手机同时跑交互 agent 与后台摘要，均面临并发预填充/解码干扰，且受响应性、功耗、散热约束。
- **核心研究问题**：能否不依赖昂贵的逐设备延迟模型或离线校准，直接用近期观测到的延迟闭环控制预填充？
- **整体含义**：论文提出 DLFP 并在小模型单 GPU 上取得显著正面结果，但系统性地报告其在更大模型与多 GPU 上的失败，明确界定贡献边界，属于“可复现概念验证 + 泛化研究”。

## 2. 方法论

- **核心思想**：DLFP（Decode-Latency Feedback Prefill）是一个**无模型比例控制器**，仅限制与活跃解码重叠的预填充工作；孤立预填充不受任何限制。
- **激活条件**：仅当至少一个请求正在解码、且预填充将共享下一个调度周期时激活；无解码器激活时重置为初始 cap。
- **控制律（公式）**：
  - `c_{t+1} = clamp( floor_128( c_t * T / L̂_t ), c_min, c_max )`
  - `c_t`：当前预填充 cap（token 数）；`T`：目标混合迭代延迟；`L̂_t`：受保护调度周期后观测到的时间间隔。
  - 观测超过目标 → 下一块缩小；低于目标 → 下一块增大；量化到 128 token 增量以避免细粒度抖动。
- **评估参数**：`T = 80 ms`、`c_initial = 3072`、`c_min = 1024`、`c_max = 6144`。
- **调度器集成**：修改 vLLM V1 调度器；先检测运行中请求是否已完成 prompt，对运行中的分块预填充请求与新准入请求，仅在解码器活跃时将 prompt token 限制在当前 cap。
- **保持不变**：解码调度、模型权重、BF16 精度、注意力后端、采样、KV 布局、孤立预填充调度均未改动。
- **关键实现选择**：原型以 **elapsed scheduler-call cadence（调度器调用间隔）** 作为 `L̂_t`，这一代理信号是后文失败的主因。
