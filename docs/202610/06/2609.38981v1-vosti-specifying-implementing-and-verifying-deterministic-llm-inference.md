## 摘要
LLM 推理系统可能会改变批组成、提示分块、预填充/解码执行，以及 KV 缓存的重用、逐出或重计算。这些优化不应影响系统输出。包括 vLLM 的批次不变模式和 SGLang 的确定性模式在内的生产系统都以这一目标为导向，但缺乏形式化的系统级规范。我们对确定性 LLM 推理进行形式化：在固定模型和部署配置下，具有相同提示和初始采样器状态的请求在多次执行中会在对应输出位置产生按位相同的 logits。我们的测试发现，这些生产模式在某些执行变化下会产生不同的 logits。为解决这一局限，我们提出 Vosti，一个依据该规范设计并验证的推理引擎。Vosti 独立于运行时引擎状态选择内核，并将缓存的 KV 值与其逻辑 token 前缀绑定。其证明在引擎/GPU 内核边界处分解：一个 Verus 归纳证明确立了调度以及分页、前缀共享的 KV 缓存会保持输出 logits 不变，而一个 Triton 分析器证明了所选内核输出在不同批次、查询长度和分页 KV 缓存布局下按位相等。Vosti 在每种测试过的执行变化下都产生按位相同的 logits，并在解码密集型工作负载上达到与 vLLM 批次不变模式相当的性能，同时提供更强、经形式化验证的确定性保证。

## Abstract
LLM inference systems may vary batch composition, prompt chunking, prefill/decode execution, and KV-cache reuse, eviction, or recomputation. These optimizations should not affect system outputs. Production systems, including vLLM's batch-invariant mode and SGLang's deterministic mode, target this goal but lack a formal system-level specification.   We formalize deterministic LLM inference: under a fixed model and deployment configuration, requests with the same prompt and initial sampler state produce bitwise-identical logits at corresponding output positions across executions. Our tests find that these production modes produce different logits under some execution variations. To address this limitation, we present Vosti, an inference engine designed and verified against this specification. Vosti chooses kernels independently of runtime engine state and ties cached KV values to their logical token prefixes. Its proof decomposes at the engine/GPU kernel boundary: a Verus inductive proof establishes that scheduling and the paged, prefix-sharing KV-cache preserve output logits, while a Triton analyzer proves bitwise-equal selected kernel outputs across batches, query lengths, and paged KV-cache layouts. Vosti produces bitwise-identical logits across every tested execution variation and achieves performance comparable to vLLM's batch-invariant mode on decode-heavy workloads, while providing a stronger, formally verified determinism guarantee.

## 1. 核心问题与研究动机

- **背景**：现代 LLM 推理框架（vLLM、SGLang 等）为提升吞吐与显存效率，会动态改变执行方式，包括批组成（continuous batching）、提示分块（chunked prefill）、预填充/解码路径切换、投机解码、KV 缓存的重用/迁移/逐出/重计算等。
- **核心矛盾**：这些优化本应只影响性能、不影响模型输出；但实际上它们会改变 GPU 内核的 tiling 与规约顺序，以及送入内核的 token、位置、缓存前缀等输入，从而改变浮点运算顺序，产生不同的 logits。
- **现实缺口**：vLLM 的 batch-invariant 模式与 SGLang 的 deterministic 模式虽以确定性为目标，但**缺乏系统级的形式化规范**，且作者测试发现它们在部分执行变化下仍会产生 logit 不匹配。
- **影响面**：logits 不一致会干扰投机解码的草稿接受、破坏 prefill–decode 等价性、造成 RL 中 rollout 与训练的 log-prob 失配、使续写结果依赖 KV 是否被保留，并妨碍对单请求的独立复现。
- **论文贡献**：(1) 首次给出确定性 LLM 推理的系统级形式化定义；(2) 设计并验证推理引擎 **Vosti**，通过引擎不变量 + 内核关系契约证明按位确定性；(3) 在 7 个模型上通过全部 5,488 组按位比较，并在解码密集负载上取得与 vLLM 批不变模式相当的性能。

## 2. 方法论

### 2.1 系统级确定性定义（Definition 2.1）

- 固定配置 $W$（模型权重、数值 dtype、所有影响取值的平台与实现要素）。
- 每个引擎步输出一个有限偏映射 $O_i: \text{Id} \rightharpoonup (\text{Logits} \times \text{Token})$，一次可为多个请求各产出一条记录，且不规定请求间顺序。
- 对请求 $r$ 定义**每请求视图** $\text{view}_r(T)$：只保留 $r$ 的观测历史，抹去请求标识、批位置、无输出步和其他请求的输出。
- **确定性定义**：若任意两条共享配置 $W$ 的有限执行 $T_1, T_2$ 中，凡提示与初始采样器状态相同的请求 $r_1, r_2$，其视图前缀可比（$\text{view}_{r_1}(T_1) \preceq \text{view}_{r_2}(T_2)$ 或反之），则系统确定。logits 相等指**位模式相等**。
- 该定义是安全性（safety）而非活性（liveness）性质，也不等同于功能正确性——一个恒定输出错误结果的引擎也可满足该定义。

### 2.2 Vosti 的设计原则与关键机制

- **一条核心设计规则**：固定模型与部署下，运行时可变的是 token 批组成、状态存储与访问方式，但**每个位置的浮点运算序列必须保持不变**。
- **固定内核选择**：初始化时将模型绑定到不可变的运行时配置（内核特化与 tile 参数），只依赖固定模型与环境，不随 batch size、chunk size、prefill/decode 变化；运行时**不做 autotuning**，缺失配置直接拒绝而非回退。
- **精确前缀匹配**：缓存页仅对其产生它的 token 前缀可重用；用滚动哈希找候选，再校验精确 token、前缀深度与物理父页，哈希碰撞不足以支持重用；显存压力下只逐出无引用的叶节点，防止父页标识被回收。
- **缓存重用与生成分离**：调度器在注册当前步新产生的页之前先解析所有前缀命中；已计算/已注册的前缀页保持不可变，新 KV 写入私有后缀槽。

### 2.3 两层验证架构

- **引擎层（Verus 归纳证明）**：
  - 每个 GPU 操作 $K$ 用未解释函数 $f_K$ 表示单请求结果。
  - 核心定理（Theorem 4.1）：$\text{Inv}(E,W) \wedge E \xrightarrow{O} E' \Rightarrow \text{Inv}(E',W) \wedge \forall u \in \text{dom}(O),\ o_u.\text{logits} = \text{Forward}(W, r_u.\text{history})$，即每步产生的 logits 仅由请求的 token 历史决定（等价于冷启动前向结果）。
  - 采样是 logits 与显式采样器状态的确定性函数，两步结合即可推出前缀可比性。
- **内核层（Triton 分析器 + Z3）**：
  - 关系型内核契约：比较两次内核调用（如打包批 vs 单例）的选定输入/输出区域，要求**按位相等**。
  - 将带注解的 Triton 翻译为 tile 级 IR，识别控制流同构、对齐值相关操作（算子、类型、静态参数、操作数顺序），并用后向规则（elementwise、broadcast、reduction、`tl.dot` 映射到输入区域）确定必须相等的输入区域。
  - 对注意力引入**值感知区域分析**（抽象解释追踪零/一/-∞/布尔掩码/未变状态），消除对被掩码 KV 的依赖，允许「恒等步」（extra tile 全掩码、精确保持状态）放宽等范围要求，从而证明 prefill 与 decode 在相同逻辑位置产生按位相等输出。
  - 验证假设：编译器/GPU 执行、翻译器、求解器编码、结构性到值性论证等属于可信计算基；注意力假设输入相关的有限性，运行时未检查。

### 2.4 引擎不变量

- **请求与布局一致性**、**KV 值一致性**（每个存活或保留的可重用 KV 条目等于对其 token 前缀做冷前向重算得到的规范值 $f_{\text{KV}}(W, h, p)$）、**共享与写隔离**（共享/已注册前缀页不可变，可写后缀槽私有且互不相交）。
- 覆盖条件保证每个已初始化请求位置和每个保留前缀都有规范值，且不随创建请求的完成而消失（图 2 展示 share/retain/evict/reuse+recompute 四个阶段的义务延续）。

- **确定性实验**：7 个模型 × 784 组 = **5,488 组按位比较**，覆盖批组成、分块、prefill–decode、前缀重用四类执行变化，测试提示长度刻意取在批、分块与注意力窗口边界附近。

## 6. 主要结论与发现

- Vosti 在全部 7 个模型、5,488 组比较中实现**按位相同的 logits**。
- 生产确定性模式存在范围局限：
  - Llama3.1-8B 上 vLLM 两种后端与 SGLang deterministic FA3 全部匹配，但 SGLang deterministic Triton 在 prefill–decode 仅 3/384、前缀重用仅 13/14；
  - Gemma3-4B 上四种生产确定性配置在每一类中均出现不匹配。
- 不匹配源于形状相关的内核特化与不同执行路径下注意力规约算术的差异，属于**范围限制而非必然的 bug**。
- 性能：Vosti 的解码吞吐为 vLLM 批不变模式的 **1.36–3.19×**，agentic 会话完成时间快 **1.14–2.20×**；但预填充吞吐低于两引擎，整体仍慢于默认模式与 SGLang deterministic 模式。原因在于 Vosti 与 vLLM 不变模式都用 Triton matmul，但 Vosti tile 更小，利于解码而不利于预填充。

## 7. 优点

- **首次给出系统级形式化规范**，把「确定性」从工程经验提升为可验证的安全性性质，并明确其不蕴含功能正确性。
- **规范与验证分层清晰**：引擎层用 Verus 证明调度与分页前缀共享缓存保持 logits，内核层用 tile IR + Z3 证明不同 batch/query 长度/物理页布局下选定输出按位相等，两层在未解释函数 $f_K$ 处对接。
- **不牺牲关键优化**：保留连续批处理、分块预填充与 KV 缓存重用，仅约束会影响浮点结果的内核选择，工程上更易落地。
- **KV 缓存不变量设计精巧**：将缓存值绑定到逻辑 token 前缀，并让义务在请求完成后继续存活，同时以「仅逐出无引用叶节点」保证父页标识不被回收，天然覆盖了共享、保留、逐出、重算四阶段。
- **值感知分析**处理注意力因果性，通过识别「恒等步」放宽等范围要求，避免因掩码导致过度保守的失败。
- **归因实验有说服力**：对生产引擎的不匹配给出了可复现的机理解释，而非笼统归因。
- **代码开源**（https://github.com/QDelta/Vosti）。

## 8. 不足与局限

- **确定性 ≠ 功能正确性**：论文明确承认 Vosti 的验证不保证输出符合模型语义，且确定性保证限定在固定模型、dtype、内核配置、编译器版本与硬件平台内，不跨平台/跨 dtype 成立。
- **可信计算基较大**：Triton 编译器、注解翻译器、张量表示对应关系、结构性到值性的论证、引擎/内核接口、CUDA 调用假设等均属可信；注意力还假设输入相关的有限性而**运行时未检查**。
- **运行时无回退/调优**：固定内核与 tile 意味着无法按负载切换更优实现，缺失配置直接拒绝，可能牺牲部分场景性能；跨内核的关系验证被列为未来工作。
- **架构覆盖有限**：仅支持单 GPU；不支持线性注意力（如 Gated DeltaNet）、MoE（数据相关路由与专家容量限制会引入批依赖）与多 GPU 张量并行/流水线/分布式 KV 缓存。
- **实验覆盖有限**：仅 7 个模型、BF16、单卡 H200；测试虽针对边界但非穷尽，作者自述「通过测试不等于确定」；未报告重复运行与统计置信度；性能对比中未充分覆盖长上下文高并发等更多负载形态。
- **性能取舍明确**：预填充吞吐低于 vLLM 与 SGLang，整体慢于默认模式与 SGLang deterministic 模式，仅在解码密集场景优于 vLLM 批不变模式。
- **安全性边界**：Vosti 约束的是输出值，缓存重用带来的时序侧信道与服务顺序泄露（如 PromptPeek）不在其保证范围内。
