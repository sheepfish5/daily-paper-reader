## 摘要
端侧大语言模型（LLM）服务是本地优先个人智能的基石，为用户提供数据主权、强隐私保障，并摆脱云 API 的延迟与成本。尽管 KV 缓存被广泛用于降低长上下文推理延迟，但现有设计主要针对具有动态执行环境和充足内存带宽的云 GPU 进行优化。这些架构假设在移动 NPU 上并不成立，因为移动 NPU 上的计算图必须静态编译，且内存容量和 I/O 带宽都受到严重限制。在这项工作中，我们提出了一种面向移动端的前缀与非前缀 KV 复用的计算-存储协同设计。我们首先提出一种图内机制，将选择性 KV 重计算映射到静态 NPU 图上，从而调和算法的动态性与 NPU 的静态性。我们进一步开发了一种图间调度器，利用动态规划优化块合并并最小化填充。为解决移动端带宽限制，我们引入了一种分层 KV 管理器，其具有树-哈希-语义混合结构，并配合成本感知的预取和淘汰策略。我们还构建了一个二维流水线，将 KV 加载、重旋转和存储与 NPU 执行重叠，从而隐藏数据移动延迟。在代表性端侧工作负载和 LLM 上的实验表明，与无复用和仅前缀缓存相比，我们的设计将首 token 时间（TTFT）降低了 40-60%。

## Abstract
On-device large language model (LLM) serving is a cornerstone of local-first personal intelligence, offering users data sovereignty, strong privacy guarantees, and freedom from cloud API latency and cost. Although KV caching is widely used to reduce latency in long-context inference, existing designs were primarily optimized for cloud GPUs with dynamic execution environments and abundant memory bandwidth. These architectural assumptions do not hold on mobile NPUs, where computation graphs must be statically compiled and both memory capacity and I/O bandwidth are severely constrained. In this work, we present a compute-storage co-design for mobile-centric prefix and non-prefix KV reuse. We first propose an intra-graph mechanism that maps selective KV recomputation onto static NPU graphs, reconciling algorithmic dynamicity with NPU staticity. We further develop an inter-graph scheduler to optimize chunk merging and minimize padding with dynamic programming. To address mobile bandwidth limitations, we introduce a hierarchical KV manager featuring a tree-hash-semantic hybrid structure, along with cost-aware prefetching and eviction policies. We also build a two-dimensional pipeline that overlaps KV loading, rerotation, and storage with NPU execution, hiding data-movement latency. Experiments across representative on-device workloads and LLMs show that our design reduces time-to-first-token (TTFT) by $40-60\%$ compared with no reuse and prefix-only caching.

## 1. 核心问题与整体含义

- **背景**：端侧 LLM 服务是"本地优先个人智能"的基础，具备数据主权、隐私保障、离线可用、低延迟等优势（如 Apple Intelligence 端侧 3B 模型、Google AI Edge Gallery、ClawMobile 等）。
- **核心痛点**：端侧应用的 prompt 构建方式天然产生**长上下文 + 跨请求重复上下文**（长对话历史、文档 QA 重复检索、Agent 重复加载技能/工具定义）。prefill 延迟即 TTFT 随长度近线性增长，超过 2k token 即达数秒，移动 NPU 比云 GPU 慢 2–5×。
- **已有方案不适配**：云侧 KV 复用（vLLM/SGLang 前缀缓存、CacheBlend 非前缀复用、Mooncake/RAGCache/LMCache）面向 GPU 动态执行与高带宽，直接移植到移动端**根本不可行**：
  - 计算侧：移动 NPU 基于固定形状矩阵单元、**必须静态预编译计算图**，与选择性重计算带来的 5 类动态性冲突（输入形状、重算选择、数值范围、末 token 选择、复用模式动态性）。
  - 存储侧：移动内存容量与带宽比云低数个量级（LPDDR ~60 GB/s vs HBM 1–3 TB/s；Flash ~300–500 MB/s），KV 搬运开销可能吃掉复用收益。
- **整体含义**：论文构建了**首个面向移动 NPU 的端侧前缀 + 非前缀 KV 复用系统**，通过计算–存储协同设计，把动态 KV 复用算法适配到静态量化 NPU 执行模型，同时尊重端侧带宽与容量约束。

## 2. 方法论

### 核心思想
跨层协同：**图内**把动态选择性重计算静态化，**图间**用动态规划调度，**存储层**用分层混合索引与成本感知策略，**流水线**隐藏数据搬运延迟。

### 关键技术细节

- **图内设计（§4.1）——调和动态性与静态性**
  - **Chunk–Pad–Mask**：将非前缀 token 切分为固定长度切片，不足则 padding；用 valid mask 在 KV 偏差计算与 Top-K 前排除 padding token，并**强制选中最后一个 token**以生成正确 logits。
  - **Scatter–Gather**：把重算的高偏差 token KV 写回复用缓存，替换对应条目。
  - **图尺寸优化**：以代表性负载的 token 长度分布 `freq(n)` 最小化期望延迟，`Latency_G(n) = ⌈n/L_G⌉ · Latency_G(L_G)`，`E(Latency_G) = Σ freq(n)·Latency_G(n)`；限制为 32 的倍数以匹配 Qualcomm HMX tile，最优解位于 per-token 延迟曲线拐点（取 L_P=128、L_S=512）。
  - **混合精度量化**：KV 偏差计算与 Top-K 用 **FP16**（其余为 W4/AUINT16/KVINT8），并乘缩放因子 `1/√D_head` 防 FP16 溢出，解决偏差张量数值范围 0–2000 且输入相关的动态性问题。

- **图间设计（§4.2）——动态规划 chunk 合并**
  - 关键观察：**新 token 可安全并入选择性重计算（SR）图**（新 token 必被选中重算），从而填补欠载的 SR 调用、减少 prefill 图调用与 padding。
  - DP 转移：`T[i] = min{ T[i − l_s(i)] + t_s, T[i − l_p(i)] + t_p }`，其中 `l_s(i)` 为满足容量与最小重算比 r 约束下可吸收的最长后缀（新 token 至多占 `⌊q·r⌋`），`l_p(i)` 为 prefill 图可打包的最长后缀。
  - 示例中 prefill 调用由 4 次降至 2 次，约省 25% 延迟。

- **分层 KV 存储（§5）**
  - **NPU KV Manager**：CPU–NPU 共享 buffer（~10¹ MB 量级），运行会话 KV 常驻。
  - **CPU KV Pool**：~10² MB 哈希表（按数据库 row ID 索引），存新生成或预取的 KV chunk，内存压力下触发淘汰。
  - **Flash KV DB**：SQLite 仅存元数据（chunk key、prompt hash、局部性统计、文件路径），**KV 张量以独立文件存在文件系统**，避免大 BLOB 碎片与写放大。
  - **树–哈希–语义混合索引**：前缀树支持前缀复用；64-bit 哈希支持相同 chunk 快速查找；稀疏关键词 embedding + 截断稠密 embedding 支持子块级语义候选；用**后缀自动机线性时间 LCS**（期望 O(|X|+|Y|)）确认可复用子串。

- **预取与淘汰（§5.3、附录 E/F/G）**
  - 局部性得分 `R(c) = w_s·R_s + w_t·R_t + w_m·R_m`（空间/时间/语义），预取只用空间+语义避免污染内存。
  - 淘汰按 `R(c)·C(c)` 排序；CPU 池淘汰成本主要是前缀 chunk 的重载延迟（非前缀 chunk 可被流水隐藏，近似为 0）；Flash 淘汰成本 = 重算成本 + **前缀链级联失效成本** `C_cascade`。

- **计算–存储流水（§6）**
  - **IO–CPU–NPU 二维流水**：沿 chunk 与 model shard 两个维度重叠；KV 去量化/RoPE 重旋转/SpinQuant 重量化等访存密集操作放 CPU，与 NPU 执行异步重叠（shard 级并行使前缀加载延迟降 4×）。
  - **异步懒存储**：新 KV 先标脏留在 CPU 池，空闲时后台批量序列化到 Flash，与 decode 重叠。

## 6. 主要结论与发现

- **延迟**：相比 no reuse 实现 1.5×–5.4× prefill 加速、TTFT 降 40%–60%；相比 prefix caching 加速 1.3×–2.5×。分负载：HotpotQA 降 32–56%，LoCoMo 降 42–65%，SkillsBench 降 68–81%。
- **质量**：准确率下降 ≤4%；而 `full reuse` 因直接复用非前缀 KV 导致约 30% 质量崩溃，且因重旋转开销暴露在关键路径上，仅比本方案快 12%。
- **能耗**：平均功耗基本持平（6.34 W vs 6.68 W），prefill 能耗降低 52%（HotpotQA）/ 67%（LoCoMo）/ 77%（SkillsBench）。
- **敏感性**：复用比越高、prompt 越长收益越大；3072 token 下 75% 前缀复用降延迟 67.4–78.3%，100% 前缀复用降 94.1–99.7%；非前缀 100% 复用降 44.9–67.9%，残余延迟来自重算开销。
- **消融**：满配下 NPU 执行占 TTFT >95%，说明复用开销基本被隐藏；去掉图尺寸优化、chunk 合并、CPU 池、Flash 混合结构、成本感知淘汰、二维流水、异步存储分别带来 1.21×–2.33× 延迟劣化（其中去掉 Flash 混合结构近 2×、去掉异步存储近 2×）。

## 7. 优点

- **问题识别

**问题识别**：准确抓住了端侧 LLM 服务中被云侧研究长期忽视的结构性矛盾——"prompt 构建天然重复"与"NPU 必须静态编译"之间的张力，而不是简单地把云侧 KV 复用方案做工程降级。

- **洞察深刻**：把 KV 复用拆解为"计算侧动态性"与"存储侧带宽/容量"两个正交障碍，并指出移动 NPU 的 5 类动态性（输入形状、重算选择、数值范围、末 token 选择、复用模式）是移植失败的根本原因，这一分类本身具有方法论价值。
- **设计自洽**：Chunk–Pad–Mask 把动态选择"藏"进静态图；DP chunk 合并利用"新 token 必被重算"这一性质填补欠载调用，逻辑简洁且可证明无损；混合精度仅对偏差计算/ Top-K 放开到 FP16，是精准的最小化妥协。
- **系统完整性**：从图内 → 图间 → 存储 → 流水线形成闭环，而非只解决单点；二维流水与异步懒存储把"复用带来的搬运开销"真正压到关键路径之外（消融显示满配时 NPU 执行占 TTFT >95%）。
- **工程落地性强**：选择 ExecuTorch + Qualcomm HTP 这一真实可部署栈，在 3 款商用手机上验证，且模型为现成开源 LLM 的 INT4 量化，复现门槛相对可控。
- **评价指标全面**：同时报告 TTFT、生成质量与能耗，尤其能耗维度在端侧研究中常被忽略，而 prefill 能耗降 52%–77% 对电池续航意义直接。
- **诚实性**：明确说明未与 vLLM/SGLang/LMCache/RAGCache 直接对比及其原因（不支持移动硬件），并统一基线存储后端以保证公平。

## 8. 局限性与可改进之处

- **场景约束偏窄**：所有实验均为 **batch size = 1** 的单请求场景，未讨论并发/多会话共享同一 NPU 时的调度与缓存争用；移动端虽以单用户为主，但后台 Agent 并发调用并非罕见。
- **数据集规模有限**：400 / 74 / 39 条的样本量偏小，尤其 SkillsBench 自建集仅 10 技能 + 39 指令，统计显著性未报告（无置信区间或方差）。
- **`full reuse` 基线处理存在选择性**：该基线在质量测试后被排除出后续延迟/能耗对比，虽给出理由，但读者无法看到其在完整矩阵下的表现，削弱了"非前缀复用必须重算"这一核心论点的对比强度。
- **超参数敏感性未充分展开**：L_S=512、L_P=128、r=0.25 为固定值，论文未系统报告这三个关键超参对延迟/质量的影响曲线；r 直接决定重算比例，其取值鲁棒性对实际部署至关重要。
- **离线开销缺失**：图尺寸优化依赖代表性负载的 `freq(n)` 分布，需要离线画像；编译期与校准期开销、以及负载分布漂移时的适配成本均未量化。
- **Flash 侧寿命与耐久性未评估**：KV 张量以独立文件持续写入 Flash，长期运行下的写放大、擦写寿命与文件系统碎片问题只有定性讨论（用独立文件规避 BLOB 碎片），缺少实测。
- **安全与隐私维度未触及**：KV 缓存落盘至 Flash 意味着对话/文档的中间表征被持久化，端侧"数据主权"叙事下，缓存加密与清除策略值得专门讨论。
- **模型与量化格式覆盖有限**：以 INT4 为主，未验证 INT8/混合量化或 MoE 结构（如 Qwen3-MoE 端侧变体）下的适用性。

## 9. 可复现性评估

- **积极因素**：基座引擎（ExecuTorch）、NPU 后端（Qualcomm HTP）、模型（Qwen3 / Llama3.2 系列开源权重）、数据集（HotpotQA、LoCoMo）均为公开可得，硬件为商用机型，理论上具备复现基础。
- **风险点**：核心实现依赖 Qualcomm 私有编译工具链与 HMX tile 特性（如 32 的倍数约束），非高通平台难以直接迁移；论文未提及代码/配置是否开源。
- **关键细节缺失**：DP 的 `t_s`、`t_p` 实测方式、局部性权重 `w_s/w_t/w_m` 的具体取值、淘汰阈值与预取触发条件等工程参数未完整给出，复现时需重新调参。
- **建议**：若作者能开源 ExecuTorch 侧的 Chunk–Pad–Mask 与 Scatter–Gather 算子实现，以及 SQLite 元数据 schema，将显著提升该工作作为端侧 KV 复用基线的价值。

## 10. 与相关工作的定位

- **相对云侧 KV 复用**：vLLM/SGLang 的前缀缓存、CacheBlend/Prompt Cache 的非前缀复用、Mooncake/LMCache/RAGCache 的存储层级，均假设 GPU 动态执行与高带宽互联；本文的价值在于证明"把复用搬回端侧"不是性能问题而是**执行模型兼容性问题**。
- **相对端侧推理优化**：多数端侧工作聚焦算子融合、量化、稀疏化等**单请求内**优化；本文聚焦**跨请求**状态复用，二者正交、可叠加。
- **相对静态图优化**：已有静态化手段（padding、mask、固定 shape）多用于单次推理；本文将其扩展为"选择性重计算"这一本质动态算法的静态化范式，Chunk–Pad–Mask 具有可迁移性。
- **相对语义缓存**：语义缓存通常作用于请求级（命中则整段复用或重算），本文下沉到**子块级**并配合后缀自动机 LCS 精确确认，粒度与正确性保障更强。

## 11. 启示与后续方向

- **范式层面**：在静态加速器上部署动态算法，可行路径是"把动态性转化为可静态表达的形式（padding+mask+强制选择）"，而非等待硬件支持动态 shape；这一思路可推广到动态稀疏、投机解码、MoE 路由等端侧场景。
- **系统层面**：计算–存储协同的收益高度依赖"搬运是否可被隐藏"，因此**流水线设计应与复用算法同层设计**，而非事后优化。
- **待探索问题**：
  - 多请求并发下的 KV 复用调度与 NPU 时分复用；
  - 负载分布漂移时的在线图尺寸自适应；
  - KV 落盘的加密、TTL 与合规清除；
  - 与端侧 LoRA/多适配器切换的联合缓存策略；
  - 在非高通 NPU（Apple ANE、联发科 APU）上的可移植性验证。

## 12. 一句话总结

本文首次系统性地回答了"如何在必须静态编译的移动 NPU 上做动态 KV 复用"，通过 Chunk–Pad–Mask、DP chunk 合并、树–哈希–语义混合索引与二维流水的跨层协同，在几乎不损质量（≤4%）的前提下实现 1.5×–5.4× prefill 加速与最高 77% 的 prefill 能耗下降，为端侧长上下文与 Agent 负载提供了可落地的复用基础设施。
