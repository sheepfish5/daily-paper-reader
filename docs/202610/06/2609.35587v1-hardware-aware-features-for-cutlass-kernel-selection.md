## 摘要
像 CUTLASS 这样的 GPU 库对单个操作会暴露数万个语义等价的内核，这使得穷举式自动调优代价高昂，且无执行选择十分困难。现有的解析式选择器需要手工设计的性能规则，而基于学习的选择器直接作用于原始配置参数，必须从数据中推断硬件后果。我们引入一种面向 CUTLASS 内核选择的硬件感知表示，用可静态计算的、由候选配置引发的硬件行为估计来增强候选配置。我们构建了一个包含 490 万个 CUTLASS 内核的数据集，并训练梯度提升和神经网络学习排序模型来对每个问题内的候选进行排序。在留出的穷举评估问题上，相较于结构基线，硬件感知表示将选择遗憾最多降低 40%，相较于 NVIDIA 的矩阵乘法启发式方法降低 64.2%。我们进一步评估了 CUTLASS GEMM 中数据高效的跨精度和 epilogue 融合迁移，表明显式表示候选配置引发的硬件行为为学习式内核选择提供了有用的归纳偏置。

## Abstract
GPU libraries such as CUTLASS expose tens of thousands of semantically equivalent kernels for a single operation, making exhaustive autotuning expensive and execution-free selection difficult. Existing analytical selectors require hand-designed performance rules, while learned selectors operate on raw configuration parameters and must infer hardware consequences from data. We introduce a hardware-aware representation for CUTLASS kernel selection that augments candidate configurations with statically computable estimates of induced hardware behavior. We construct a dataset of 4.9 million CUTLASS kernels and train gradient-boosted and neural learning-to-rank models to rank candidates within each problem. On held-out exhaustive evaluation problems, hardware-aware representations reduce selection regret by up to 40\% relative to structural baselines and 64.2\% relative to NVIDIA's matrix-multiply heuristics. We further evaluate data-efficient cross-precision and epilogue-fusion transfer within CUTLASS GEMM, showing that explicitly representing candidate-induced hardware behavior provides a useful inductive bias for learned kernel selection.

## 1. 核心问题与研究动机

- **背景**：现代 GPU 库（如 CUTLASS）对单个 GEMM 操作会暴露数万个语义等价的 kernel。以 BF16 SM90 GEMM 为例，原始参数笛卡尔积达 2,138,400 种组合，经静态合法性/共享内存过滤后仍保留约 242,971 个有效配置（每种 layout 约 61,000 个）。
- **问题**：性能差异极其悬殊——在 GH200 上，同一 shape/layout 下最优与最差有效 kernel 吞吐量相差可达 1070×；平均仅 **2.4%** 的配置落在 oracle 的 5% 以内；随机选择只能达到 oracle 的 28.5%，固定最优配置也只有 71%。因此 kernel 选择不是"四舍五入的误差"，而是会浪费大量硬件预算。
- **现有方法的两难**：
  - **解析式选择器**（如 nvMatmulHeuristics、TritonBLAS）：依赖手工性能规则，速度快但脆弱，需要大量架构知识，且随硬件/库演进需不断更新。
  - **学习式自动调优器**：用原始问题维度和模板参数表示候选，模型必须从数据中自行推断这些参数对硬件行为的后果——原始参数是硬件效果的"糟糕描述"。
- **核心主张**：将"配置对硬件做了什么"（诱导的硬件行为）显式暴露为可静态计算的特征，让模型学习这些机制之间的交互，而非从原始参数重发现硬件行为。这结合了解析式的架构归纳偏置与数据驱动的适应性。

## 2. 方法论

### 2.1 核心思想
对每个候选配置 $c$、问题 $p$、硬件 $h$，构造特征向量 $x = \phi(p, c, h)$，完全由问题描述、配置参数和硬件常量静态计算，**不依赖任何运行时计数器**。选择问题被简化为"问题内排序"：$\hat{c}(p) = \arg\max_{c \in C(p)} f_\theta(x(p,c,h))$。

### 2.2 特征构造的实证依据（Profiling 分析）
- 采集 **408 个 Nsight Compute profile**（GH200，17 个 shape），按 (M,N,K,layout) 分组计算组内 Spearman 相关 $\rho_g$。
- 关键发现：很多指标在全池相关中表现优异，但固定问题后失去排序能力（"问题规模效应"）。例如 `sm_active_pct` 全局 $\rho=+0.910$，组内仅 $-0.001$；`l2_read_sectors` 从 +0.942 降至 −0.102。
- 真正在组内保持相关的只有 **`dram_throughput_pct`（+0.408）** 和 **`tensor_active_pct`（+0.392）**——成功候选需同时维持内存系统与 tensor core 流水线活跃。因此需为产生这些效果**机制**构造静态代理。
- 还区分了"症状"与"可控原因"：如 barrier stall 全局 $\rho=+0.894$ 但组内仅 +0.156，属执行后状态，不适合作为选择特征；pipeline depth 与 long-scoreboard stall 组内相关 −0.357，但与吞吐仅弱相关。
- **Regime 依赖性**：$T_K$ 的效果随几何形状剧变（wide +0.549，square +0.116，tall +0.021），说明需同时暴露候选选择与决定其解释方式的问题量。

### 2.4 关键公式（文字说明）
- **波量化**：$n_M=\lceil M/T_M\rceil$、$n_N=\lceil N/T_N\rceil$、$n_K=\lceil K/T_K\rceil$；边界浪费 $w_M=(n_M T_M-M)/M$；SM 波数 $q_{SM}=\lceil n_M n_N/(S_{SM} b_{res})\rceil$；末波效率 $\eta_{last}=n_M n_N/(q_{SM} S_{SM} b_{res})$；Stream-K 代理 $\text{streamK\_applicability}=\max(0, 1-\eta_{last})$。
- **算术强度**：问题级 $I_{problem}=2MNK/(b_A MK + b_B KN + Q_{epilogue})$；tile 级 $I_{mainloop}=2T_M T_N/(T_M b_A + T_N b_B)$（注意 $T_K$ 被约掉，说明 $T_K$ 并非算术强度代理，而是影响每 stage 存储与流水线同步粒度）。
- **Re-streaming**：$r_{stream}=(n_N b_A MK + n_M b_B KN)/(b_A MK + b_B KN)$，区分被 LLC 吸收与反复从 HBM 取数的场景。
- **资源压力**：每 stage 共享内存 $B_{stage}=T_M T_K b_A + T_N T_K b_B$；总需求 $B_{smem}$、占比 $f_{smem}$、SMEM 限制常驻数 $b_{smem}=\lfloor C_{smem}/B_{smem}\rfloor$；寄存器代理 $r_{proxy}=T_M T_N/T_{block}$、限制 $b_{reg}$；最终 $b_{res}=\min(b_{smem}, b_{reg}, b_{arch})$（分离两个界，可区分寄存器受限与 SMEM 受限）。
- **流水线平衡**：$t_{producer}=n_{SM}B_{stage}/BW_{TMA}$，$t_{consumer}=2T_M T_N T_K/(n_{consumer}P_{WGMMA})$，比值 $r_{pc}=t_{consumer}/t_{producer}$；填充比例 $f_{fill}=\min(S,n_K)/S$；摊销 $a_{stage}=n_K/S$；交互项 $S\cdot f_{smem}$ 捕捉 stage 悬崖与"大 $T_K$ 迫使流水线变浅"的机制。

### 2.5 数据采集与采样策略
- **Shape 选择**：3 维 anchor grid $[32,16384]^3$（步长 32，约 1.34 亿格点）。最终 593 个 base shape × 4 layout = 2372 组，包括 297 内部随机 + 172 边界极端 + 92 anchor 邻居 + 32 transition（roofline 脊线 BF16 算术强度 ≈247.3 flop/byte、50 MiB LLC 边界）。
- **候选采样**：默认预算 2000/组（最大 shape 1000，异常/transition shape 3000）。
- **采样策略对比**：Uniform、Static top-B、**Biased-diverse（75% 取自静态分数高的区域 + 25% 均匀探索）**。静态分数 $s_{sample}=\frac{n_c}{W S_{SM} c_M c_N}\cdot S\cdot\sqrt{T_M T_N T_K}$。
- 结论：默认预算 2000 时，biased-diverse 将采样遗憾从 8.5% 降至 0.9%（相对降低 89.4%），观察到 5% 内 kernel 的概率从 25.6% 提升到 91.3%。纯 exploitation（α=1）虽指标最好但不可用作训练策略（会缺少坏 kernel 样本）。
- **采集优化**：批量编译（共享库 + 索引分发）、可执行缓存（配置哈希命名）、缓冲区缓存（预分配显存池）、节点本地数据库、编译与 benchmark 并行（CPU worker 池 + 每 GPU 常驻消费进程 + 崩溃恢复监控）。
- 最终数据集约 **490 万个已测量 kernel**。

### 2.6 模型与训练
- **监督标签**：组内归一化吞吐 $y(g,c)=\hat{T}(g,c)/T^\star_g$；排序监督用"不确定度带合并"生成离散 relevance grade（相邻吞吐差 < $2\sqrt{\hat\sigma_i^2+\hat\sigma_{i+1}^2}$ 则合并为同 band），$G_{max}=31$，默认压缩到 $B=2$ 个 top-focused band。
- **Model A（XGBoost）**：listwise NDCG（默认）、pairwise、pointwise MSE 三种目标；原生类别处理；搜索空间见表 10。
- **Model B（MLP）**：per-column 标准化 + one-hot；三种损失：MSE、RankNet、LambdaRank（含 ΔNDCG 加权与 "needle guarantee"：涉及 top-8 的 pair 必保留）。
- **Ridge 基线**：同一特征矩阵上的线性回归，测试"硬件感知表示的贡献"与"模型非线性表达力"的分离。
- **超参搜索**：Optuna TPE，最小化 shape-grouped 交叉验证的选择遗憾 CV（同一 base shape 的 4 个 layout 必在同折）；Model A 5 折，Model B 搜索用 3 折 × 2 seed，胜出配置再以 5 折 × 3 seed 复验。
- **目标指标**：选择遗憾 $R(g;f_\theta)=1-y(g,\hat{c}(g))$，并报告均值、中位数、95 分位、最大值、Top-1、Top-5、Within-5%。

- **穷举集（68 group）**：MLP(full) 均值遗憾 **6.2%**、中位 2.6%、Within-1% 36.8%、Within-5% 63.2%、Top-1 27.9%；XGBoost(full) 6.4%；MLP(struct) 7.4%；XGBoost(struct) 10.7%；nvMMH top-1 **17.3%**、best-of-K 12.0%；Ridge(full) 23.7%、Ridge(struct) 60.8%；解析分数 63.7%；Random 71.5%。
