## 摘要
长上下文大语言模型（LLMs）已在广泛任务中展现出强大能力，但不断增长的 KV 缓存带来了显著的内存和推理开销。现有一次性 KV 缓存压缩方法通常在前填充（prefill）后立即进行不可逆的驱逐，而此时尚无来自实际生成阶段的任何信号。我们的定量分析表明，实际生成阶段的早期查询所提供的注意力信号与后续解码注意力更为一致，且最大的单步增益出现在预填充-解码边界处。基于这一观察，我们提出 DeferKV，将驱逐决策从预填充结束处移至第一个真实解码步骤，并时序性地结合提示侧与解码侧的观察，从而更好地使 KV 重要性估计与后续生成需求对齐。DeferKV 无需额外训练、草稿模型或未来查询预测模块，因此简单且易于部署。在 LongBench、RULER 和 Needle-in-a-Haystack 上的实验表明，DeferKV 在 KV 缓存压缩下持续提升模型性能，同时保持较低的推理延迟。

## Abstract
Long-context large language models (LLMs) have demonstrated strong capabilities across a wide range of tasks, but the growing KV cache introduces substantial memory and inference overhead. Existing one-shot KV cache compression methods typically commit to irreversible eviction immediately after prefill, before any signal from actual generation becomes available. Our quantitative analysis shows that early queries from the actual generation stage provide attention signals that are more consistent with subsequent decode attention, with the largest single-step gain occurring at the prefill-decode boundary. Based on this observation, we propose DeferKV, which moves the eviction decision from the end of prefill to the first real decoding step and temporally combines prompt-side and decode-side observations, thereby better aligning KV importance estimation with subsequent generation requirements. DeferKV requires no additional training, draft model, or future-query prediction module, making it simple and easy to deploy. Experiments on LongBench, RULER, and Needle-in-a-Haystack demonstrate that DeferKV consistently improves model performance under KV cache compression while maintaining low inference latency.

## 一、核心问题与整体含义

- **研究背景**：长上下文大语言模型（LLMs）在文档问答、多文档摘要、代码理解、检索增强生成和复杂推理等任务上表现优异，但 KV 缓存随序列长度线性增长，成为显存与推理吞吐的主要瓶颈，尤其在显存受限设备和 高并发服务场景中更为突出。
- **核心问题**：现有一次性（one-shot）KV 缓存压缩方法（如 SnapKV）普遍在 prefill 结束后、解码开始前立即执行**不可逆的 KV 驱逐**，其关键假设是——prompt 末尾的观察窗口查询足以反映后续解码的真实注意力需求。
- **问题本质**：作者通过定量分析发现该假设在长文本生成任务中并不总成立。实际生成阶段的首个解码查询（first real decode query）所诱导的注意力分布，比 prompt 末尾 32 个 prefill 查询聚合得到的分布，与后续解码注意力更一致（在 GovReport + Qwen3-8B 上，首次解码查询的 2 倍误差内一致率为 52.0%、Pearson 相关系数 0.685，而 prompt 末尾 P32 仅分别为 31.8% 和 0.301）。
- **整体含义**：论文重新审视了"何时执行不可逆驱逐"这一基础设计选择，指出 prefill–decode 边界处存在最大的单步信号增益，主张将压缩时机后移以对齐真实的生成需求，为 one-shot KV 压缩提供了一种简单、轻量、可部署的新范式。

## 二、方法论

### 2.1 核心思想
- 将 KV 缓存压缩的决策点从 **prefill 结束处** 推迟到 **第一个真实解码步骤之后**，利用目标模型自然产生的首个解码查询（无需预测或辅助模型）作为生成侧信号。
- 通过**时序加权**融合 prompt 侧与 decode 侧观察，强调靠近解码阶段的查询、折扣较早的 prompt 查询。

### 2.2 三项关键观察（支撑方法设计）
- **观察 1（Prefill-to-Decode 注意力漂移）**：从最后一个 prefill 查询（r = −1）到第一个真实解码查询（r = 1），JSD-Based Similarity 提升 0.056，Top-B KV 选择召回率提升 0.052，表明解码查询揭示了 prefill 未捕获的生成特定访问需求。
- **观察 2（首解码步增益最大）**：所有相邻查询位置中，prefill–decode 边界的单步增益最大；后续相邻解码位置的平均增益仅 0.009（JSD）和 0.007（召回率）。因此首个解码查询在 KV 选择质量与系统开销之间取得最佳折中。
- **观察 3（时间相关性衰减）**：越靠近解码阶段的查询与参考注意力分布越一致，因此应对靠近解码的查询赋更大权重。

### 2.3 技术流程（算法说明）
1. **获取首个解码查询**：对 prompt X = {x₁,…,x_N}，由目标模型 p_θ 生成第一个 token y₁，再将其喂入模型执行第一次标准解码，得到各层首个真实解码查询 q^ℓ_dec,1（及对应的 k^ℓ_dec,1、v^ℓ_dec,1）。
2. **构建解码感知观察窗口**：给定窗口大小 W，将首个解码查询与最后 W−1 个 prompt 查询组合：
   Q^ℓ_obs = [q^ℓ_{N−W+2}, …, q^ℓ_N, q^ℓ_dec,1]，保持原窗口大小不变。
3. **计算注意力权重**：A^ℓ = Attention(Q^ℓ_obs, K^ℓ)，保留模型原有的可见性约束；a^ℓ_{i,j} 表示第 i 个观察查询对第 j 个 prompt Key 的注意力权重。
4. **时序加权聚合**：对第 j 个 prompt token 的重要性得分 s^ℓ_j = Σ_{i=1}^{W} η^{W−i} · a^ℓ_{i,j}，其中 η ∈ (0,1] 为时序折扣因子；首个解码查询权重为 1，越早的 prompt 查询被指数折扣。当 η = 1 时等价于均值聚合（在排序意义上）。
5. **缓存选择与构建**：沿用底层驱逐方法的局部平滑（平均池化，kernel=5）、预算分配与选择策略，仅替换其原本的 prompt-only 重要性分数。定义历史候选集 C = {1,…,N−W+1} 与受保护近期集 R = {N−W+2,…,N}；从 C 中 Top-K 选择 B−W+1 个位置（B 为该层 prompt-KV 预算），与 R 合并排序后得到 I^ℓ；最终将保留的 prompt KV 与首个解码步的 k^ℓ,1、v^ℓ,1 拼接，形成后续生成所用的压缩 KV 缓存。
6. **无需训练、草稿模型、辅助网络或未来查询预测模块**，也不修改模型架构，仅调整初始压缩时机并复用模型自然产生的解码查询。

### 2.4 超参数
- 观察窗口 W = 32；时序折扣因子 η = 0.7（跨模型、任务统一设定）；平均池化 kernel = 5；压缩延迟步数 d = 1（默认）。

## 六、主要结论与发现

- 将不可逆驱逐推迟到首个真实解码步，能显著改善 KV 重要性估计与后续生成需求的对齐。
- **LongBench**：在所有 6 个模型–预算组合中平均分最高；紧张预算（64L）下相对最强基线最高提升 **3.58%**（Qwen3-8B）；预算增大到 512L 后各方法差距收窄，但 DeferKV 仍保持最优并逼近 Full KV。
- **RULER**：平均准确率较最强基线提升 **8.03%**；即使在 128K 上下文（保留不足 1% KV 缓存）下仍维持有效检索能力（69.04 vs. 基线最高 62.06）。
- **NIAH**：B_total = 128L 下平均检索得分 0.892，优于 LookaheadKV（0.833）与 SnapKV（0.660）；B_total = 1024L 下得分 0.990。
- **效率**：端到端延迟 11.56s，与 SnapKV 相当、低于 LAQ/SpecKV/LookaheadKV；峰值显存 22.84 GiB，低于 LAQ 和 SpecKV，整体在显存与延迟之间取得良好平衡。
- **延迟步数分析**：d 从 1 增至 4 仅带来约 0.55% 的相对分数提升，而延迟增加约 1.63%，故默认 d = 1。
- **兼容性**：与 PyramidKV、AdaKV、ChunkKV 集成后平均分分别提升约 4.89%、4.68%、5.63%，说明方法具有通用性。

## 七、优点

- **时机视角新颖**：首次系统性地重新审视"驱逐时机"这一被忽视的设计维度，用实证数据（JSD + Top-B 召回率）清晰刻画了 prefill–decode 注意力漂移。
- **方法极简且轻量**：无需额外训练、草稿模型、辅助网络或未来查询预测，仅需对现有推理流程做微小改动，工程落地门槛低。
- **即插即用**：可与 SnapKV、PyramidKV、AdaKV、ChunkKV 等多种现有框架无缝集成，仅替换重要性分数。
- **实验扎实**：3 个模型 × 3 个 benchmark × 多档预算，加上 360 实例的观察性分析、消融、敏感性、随机解码与效率分析，验证维度较全面。
- **性能与效率平衡**：在紧张预算下收益最明显，同时在延迟与显存上保持竞争力，适合内存受限与高并发场景。
- **对随机解码的鲁棒性**：在 T = 0.2 和 T = 0.8 采样下仍保持相对优势，说明改进不局限于确定性解码。

## 八、不足与局限

- **内存缩减被推迟**：DeferKV 需要在首个解码步期间保留完整 prompt KV 缓存，显存收益延后到后续解码阶段才体现；在极端显存受限场景中，这一"峰值内存窗口"可能成为部署障碍。
- **架构适配性有限**：实验仅覆盖标准逐 token KV 缓存 + softmax 注意力架构；对 MLA（Multi-head Latent Attention）或混合线性注意力模型，可能需要架构特定适配。
- **超长上下文下部分任务仍失效**：RULER 的 MK-NIAH-3 等子任务在 64K/128K 下所有方法（包括 DeferKV）得分接近 0，说明多键检索类任务仍是瓶颈。
- **实验覆盖的偏差风险**：
  - 消融与超参数敏感性仅在 Qwen3-8B + LongBench + 128L 下进行，跨模型/跨预算的消融缺失。
  - NIAH 仅在 Mistral-7B-Instruct-v0.3 上评估，未覆盖其他模型。
  - 主实验主要报告平均值，未提供方差/显著性检验。
- **算力报告不完整**：未明确 GPU 数量、总训练/评估时长；对涉及训练的基线（SpecKV、LookaheadKV）也未报告训练开销。
- **观察性分析的样本量**：360 实例来自 3 模型 × 4 数据集 × 30 样本，规模适中但不算大，结论的统计稳健性有待更大规模验证。
- **首解码查询质量依赖**：方法效果依赖首个生成 token 的质量，尽管作者验证了随机解码下的鲁棒性，但在高温度采样或首 token 质量较差时仍可能存在性能波动风险。
