## 摘要
投机解码通过使用轻量级草稿提出多个词元以并行验证，从而加速自回归生成。然而，现有方法通常需要额外的草稿模型或权重表示，在资源受限设备上引入不可忽视的内存开销。自投机方法降低了这一开销，但仍面临草稿质量、目标质量和存储效率之间的权衡。我们提出BitNest，一种比特嵌套投机解码框架，将低精度草稿直接嵌入更高精度的目标表示中。BitNest并非从预定义目标中派生草稿，而是先构建一个强大的低精度基座，再通过残差细化恢复更高精度的目标，使两个模型共享单一物理权重表示。BitNest进一步将这种渐进精度设计扩展到KV缓存，以支持长上下文推理。在多个7B--8B边缘友好型LLM和多样化工作负载上，BitNest实现了95.2%的平均投机接受率，同时很好地保持更高精度模型的质量，并相较于FP16自回归解码带来1.48--1.61倍的端到端加速。在所有代表性自投机基线均支持的LLaMA模型上，BitNest也取得了一致具有竞争力或更高的解码加速。

## Abstract
Speculative decoding accelerates autoregressive generation by using a lightweight draft to propose multiple tokens for parallel verification. However, existing methods often require an additional draft model or weight representation, introducing non-negligible memory overhead on resource-constrained devices. Self-speculative approaches reduce this overhead, yet still face trade-offs between draft quality, target quality, and storage efficiency. We propose BitNest, a bit-nested speculative decoding framework that embeds a low-precision draft directly into the higher-precision target representation. Instead of deriving a draft from a predefined target, BitNest first constructs a strong low-precision base and then recovers the higher-precision target through residual refinement, enabling both models to share a single physical weight representation. BitNest further extends this progressive-precision design to the KV cache for long-context inference. Across multiple 7B--8B edge-friendly LLMs and diverse workloads, BitNest achieves an average speculative acceptance rate of 95.2% while closely preserving higher-precision model quality, and delivers 1.48--1.61x end-to-end speedup over FP16 autoregressive decoding. On the LLaMA models supported by all representative self-speculative baselines, BitNest also achieves consistently competitive or higher decoding speedup.

## 1. 核心问题与整体含义（研究动机与背景）

- **背景**：LLM 自回归解码受限于高计算成本、模型与 KV-cache 的巨大内存占用以及高内存带宽需求，在单卡、消费级 GPU 和边缘设备上尤为突出。
- **投机解码的两难**：
  - 传统方案（小模型草稿、EAGLE、DFlash 等）需要**额外的草稿网络/参数/专用表示**，在内存紧张设备上与目标模型、KV-cache 直接争夺内存预算。例如 FP16 下 7B 模型已接近 16GB 设备容量。
  - **自投机方案**（层跳过/早退、量化类）虽免去独立草稿模型，但仍存在权衡：LayerSkip 等把草稿效率与预测质量耦合；QSpec 让目标共享低比特表示（目标被限制在 W4）；QuantSpec 保留额外的低精度草稿权重。
- **核心追问**：能否用**单一物理模型表示**同时支撑轻量草稿与高质量目标，且不增加内存、仍保持足够高的草稿-目标一致率（接受率）？
- **整体含义**：论文提出 **Bit-Nested Speculative Decoding（比特嵌套投机解码）** 新范式——低精度草稿被物理地"嵌套"在高精度目标表示内部，而非作为独立模型存在；并进一步把嵌套原则扩展到 KV-cache 以服务长上下文。

## 2. 方法论

### 2.1 核心思想
- 与"从既定目标派生草稿"相反，BitNest 采用**基座优先（base-first）**构造：先优化一个强 W4 基座，再仅对**量化残差**做精炼以恢复高精度目标，从而保证草稿是目标表示的**精确子集**。
- 变换流程：`W --R--> W' --QbW--> W_base + rW 位精炼 --> W_target`。本文实例化 **bW = rW = 4**，即 W4 草稿视图 + W8 目标视图。

### 2.2 权重建构（W4/W8 实例）
- **等价旋转**：先用 SpinQuant 类函数保持旋转 R1/R2 折入预训练权重，得 `W' = Fuse(W; R1, R2)`，抑制激活/隐状态离群值。
- **构造 W4 基座**：对 `W'` 用 GPTQ（group size 128）量化，得整数码 `q4 ∈ [-8,7]` 与分组尺度 `s4`，草稿权重 `W_draft = q4·s4`；**此后 q4、s4 固定不再改动**。
- **固定基座精炼**：残差 `ΔW = W' − W_draft`；精炼尺度取 `s_ref = s4/16`；4-bit 精炼码
  - 当 `q4 = −8` 时 `q_r = clip(round(ΔW/s_ref), 0, 7)`（非对称约束，防止组合整数码越过 int8 下界）；
  - 当 `q4 > −8` 时 `q_r = clip(round(ΔW/s_ref), −8, 7)`。
- **目标重建**：`W_target = q4·s4 + q_r·s_ref = (16·q4 + q_r)·s_ref`，即 W8 目标由基座与精炼位组合恢复，基座未被修改。

### 2.3 双平面权重存储（Dual-Plane Weight Storage）
- 关键观察：**逻辑上从 W8 降到 W4 并不自动等于访存下降**——内存按字节寻址，若基座与精炼共处一个字节，草稿仍会取到精炼位。
- 方案：把基座与精炼分别打包成两个**独立可寻址的 4-bit 位平面**，N 个权重各占 N/2 字节。
  - 草稿路径：只读基座平面 → 4 bit/weight 权重码流量；
  - 验证路径：读两个平面 → 恢复 W8 目标。
- 精炼无需额外尺度元数据（`s_ref = s4/16` 由基座尺度推导）。
- 实现上用自定义 Triton kernel 支持 dual-plane GEMM 与 flash decoding；激活采用 per-token INT8。

### 2.4 上下文感知的 KV 嵌套
- KV 写入时做在线、逐 token、逐 KV 头的对称 RTN 量化：`s = max|x|/7`，`q4 = clip(round(x/s), −8, 7)`，草稿 KV `x̂_draft = q4·s`；残差再以 `s/16` 量化得 `q_r`，目标 KV `x̂_target = (16·q4 + q_r)·s/16`。
- 解码流程：草稿只读 KV4 基座平面，验证读双平面恢复 KV8；草稿阶段为候选 token 生成的 KV 是临时的，验证时重算，**保留被接受的前缀、丢弃被拒绝后缀**。
- 策略：**短上下文**草稿与验证都用 KV8（保一致率）；**长上下文**切换为 KV4 草稿 + KV8 验证（降 KV 流量）；另提供 **Recent-N** 中间策略（最近 N 条 KV 以高精度供草稿读，更早的走低精度基座）。

## 6. 主要结论与发现

- **加速**：在 4 个模型 6 个负载上相对 16-bit 自回归解码取得 **1.48–1.61×** 端到端加速；在全部基线均支持的 LLaMA 模型上，加速比一致高于 QSpec、QuantSpec 与 Draft & Verify（如 LLaMA-2-7B 上 1.50–1.61× vs QSpec 1.35–1.46×）。
- **质量保持**：BitNest 目标质量接近 FP16 与独立 W8A8（如 LLaMA-3-8B GSM8K 49.8% vs W8A8 50.0%），显著优于 W4 目标（W4A8 仅 41.4%）。
- **接受率**：跨 4 模型 6 负载平均 **95.2%**，模型均值 94.8%–95.7%，说明 W4A8 草稿与 W8A8 目标对齐良好。
- **内存**：嵌套权重占 6.22 GiB，与独立 W8 模型相同；而"独立 W4 草稿 + INT8 目标"需 9.38 GiB（约 8412 bit/weight → 8 bit/weight）。32K 上下文峰值内存 21.0 GiB，低于 QSpec 24.0 GiB 与 QuantSpec 25.1 GiB。
- **长上下文**：双 KV8 时加速比从 4K 的 1.57× 降至 32K 的 1.38×；改用 KV4 草稿 + KV8 验证后在 32
