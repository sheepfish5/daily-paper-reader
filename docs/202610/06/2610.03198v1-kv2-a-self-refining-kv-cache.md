## 摘要
键值（KV）缓存的内存占用限制了长上下文模型的实际使用，并且当一个预填充上下文之后需要服务许多不同查询时，它会主导成本。在这种可复用设置中，查询无关的压缩在成本与质量之间进行权衡：轻量级估计器成本低但准确性较差，而全上下文重建评分更准确，却会重新处理整个提示。我们提出 KV$^2$，一种基于选择性重建的查询无关 KV 缓存压缩方法。KV$^2$ 首先使用轻量级代理评分器识别上下文中信息量大的 token，然后仅重新处理该子集以计算最终逐出分数。在 RULER、Needle-in-a-Haystack 和 LongBench 上，随着预算收紧，KV$^2$ 相对基线的优势不断扩大：在 RULER 16K 上，当 KV 缓存预算为 2% 时，它相比次优基线将平均分数提高了 40 个百分点以上；在 LongBench 上，它在 2%-10% 预算范围内取得了最高平均分，且压缩阶段运行时间和峰值内存均低于全上下文重建。因此，可复用的 KV 缓存压缩无需重新处理完整上下文。我们的代码可在 https://anonymous.4open.science/r/KVsquared-0B97 获取。

## Abstract
The memory footprint of the key-value (KV) cache constrains the practical use of long-context models, and it dominates cost when one prefilled context must later serve many different queries. In this reusable setting, query-agnostic compression trades cost against quality: lightweight estimators are cheap but less accurate, whereas full-context reconstruction scoring is more accurate yet reprocesses the entire prompt. We introduce KV$^2$, a query-agnostic KV-cache compression method based on selective reconstruction. KV$^2$ first uses a lightweight proxy scorer to identify informative in-context tokens, then reprocesses only this subset to compute final eviction scores. On RULER, Needle-in-a-Haystack, and LongBench, KV$^2$'s margin over baselines widens as the budget tightens: on RULER 16K at a 2% KV-cache budget it improves the average score over the next-best baseline by more than 40 percentage points, and on LongBench it attains the highest average across 2%-10% budgets at lower compression-stage runtime and peak memory than full-context reconstruction. Reusable KV-cache compression thus does not require reprocessing the full context. Our code is available at https://anonymous.4open.science/r/KVsquared-0B97.

- **研究背景**：长上下文大模型推理中，KV 缓存随上下文长度线性增长，内存占用成为部署瓶颈。尤其当一次预填充的上下文需要服务多个后续查询时，缓存会被长期复用，成本进一步放大。
- **核心矛盾**：查询无关（query-agnostic）KV 缓存压缩存在质量与成本的两难：
  - 轻量代理评分器：便宜，但精度有限。
  - 全上下文重建评分：更准确，但需要重新处理整个 prompt，压缩阶段开销高。
- **论文定位**：提出 `KV$^2$`，一种基于“选择性重建”的查询无关 KV 缓存压缩方法。核心主张是：可复用 KV 缓存压缩不需要重处理完整上下文，只需重建一小部分信息量高的 token 即可获得高质量逐出分数。
- **整体含义**：在极端压缩预算下，选择性重建能显著优于轻量启发式方法和全上下文重建基线，同时降低压缩阶段运行时间与峰值内存，对长上下文、多查询复用场景具有部署价值。

## 2. 方法论

- **核心思想**：两阶段压缩。
  - **Stage 1：查询选择**：用轻量代理评分器识别上下文中信息量高的 token，作为后续重建查询。
  - **Stage 2：缓存评分**：只重处理这些被选中的查询，对完整缓存做选择性重建，计算最终逐出分数。
- **整体流程**：
  1. 预填充得到完整 KV 缓存 `KV_c`。
  2. 保留开头少量 sink token。
  3. 将可压缩部分分块为 `C1, ..., CM`，每块大小不超过 `m`，默认 `m = 4K`。
  4. 对每个块，用代理评分器计算 token 重要性。
  5. 选择 top-`nq` 个 token 作为重建查询集合 `Qr`，`nq = max(floor(ρ|Cr|), 1)`，`ρ` 为查询选择比例，默认与最终保留 KV 预算一致。
  6. 将这些重建查询附加在预填充缓存之后，赋予紧接上下文的 position ID，并在因果掩码下对完整缓存做前向。
  7. 最终评分只限于当前块：对每个缓存位置 `i`，取其被任意重建查询关注的最大注意力值作为分数：
     - `s_{i,ℓ,h} = max_{j=1..nq} a^{(ℓ,h)}_{ji}`
  8. 合并所有块的局部分数，sink token 固定为最高分，再按目标预算逐出最低分条目。
- **关键设计**：
  - **全局条件、局部评分**：重建查询可以看到整个上下文，但最终打分只作用于当前块，避免全局重建的昂贵开销。
  - **max 聚合**：只要任一重建查询强依赖某缓存位置，该位置就会被保留，而非要求所有查询一致。
  - **模块化代理**：Stage 1 可使用 KeyDiff、Knorm、CUR、StreamingLLM、Random 等代理评分器，默认 KeyDiff。
  - **迭代自精炼**：Stage 2 输出与 Stage 1 代理信号同粒度，可替代代理进入下一轮；单遍是默认配置，多遍为可选扩展。
- **复杂度**：
  - 代理评分：`O(nc)`。
  - 重建前向：总成本约为 `O(ρ nc² + ρ² nc m / 2)`。
  - 分数提取：每块 `O(ρ m²)`，总计 `O(ρ m nc)`。
  - 相比 KVzip 对整块所有 token 重建，KV² 只重建代理选中的比例 `ρ`，因此压缩阶段成本随 `ρ` 缩放。
