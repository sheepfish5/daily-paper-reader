## 摘要
由大语言模型（LLM）驱动的智能体会话通常在模型推理与工具使用之间交替进行，并在连续多轮中累积长历史。高效地服务这些会话需要减少注意力计算并保留历史键值（KV）缓存以避免重计算。近来，前沿开源LLM采用稀疏注意力，通过仅选择部分历史来降低计算量，而SSD为存储KV缓存提供了比CPU DRAM更廉价的替代方案。然而，稀疏KV选择依赖于模型推理过程中临时产生的中间值，因此迫使SSD读取位于推理关键路径上。这些读取还会因SSD中的碎片化访问和读写干扰而进一步变慢。为应对这些挑战，我们提出Janus，一个面向稀疏注意力LLM、以SSD为中心进行KV存储的智能体服务框架。Janus聚焦于追加预填充，其处理每轮新增输入，并占据大部分历史KV加载。为将SSD读取移出关键路径，Janus基于更早的中间值运行模型自身的KV选择模块，无需额外训练即可预测KV需求。预测的读取与模型计算重叠，任何预测未命中都会在注意力执行前取回，以保持模型输出不变。为提升SSD效率，Janus合并相邻读取，将分散的KV页在CPU上打包为顺序写入，并在读取活跃时限制后台写入。在三个模型和三个智能体轨迹上，Janus在首令牌延迟方面最高优于现有工作1.57-3.69倍（平均1.22-1.85倍），同时保持解码效率。

## Abstract
Agentic sessions driven by Large language models (LLMs) often alternate between model inference and tool use, accumulating long histories across successive rounds. Serving these sessions efficiently requires reducing attention computation and retaining history key-value (KV) caches to avoid recomputation. Recently, frontier open-source LLMs adopt sparse attention to reduce computation by selecting only part of the history, while SSDs provide a cheaper alternative to CPU DRAM for storing KV caches. However, sparse KV selection depends on the ad hoc intermediate values during model inference, so it forces SSD reads to lie on the inference critical path. These reads are further slowed by fragmented accesses and read-write interference in SSDs.   To address these challenges, we present Janus, an agentic serving framework for sparse attention LLMs with SSD-centric KV storage. Janus focuses on append prefill, which processes each round's newly added inputs and accounts for most history KV loading. To move SSD reads out of the critical path, Janus runs the model's own KV selection module on earlier intermediate values, predicting KV demand without additional training. The predicted reads overlap with model computation, and any prediction misses are fetched before attention executes to preserve model outputs. To improve SSD efficiency, Janus coalesces adjacent reads, packs scattered KV pages into sequential writes on the CPU, and limits background writes while reads are active. Across three models and three agentic traces, Janus outperforms existing works by up to 1.57-3.69 times (1.22-1.85 times on average) in terms of the time to first token latency, while maintaining decode efficiency.

## 1. 核心问题与整体含义

**研究背景与动机：**

- **智能体会话的工作负载特征**：LLM 驱动的智能体在推理与工具调用之间交替，形成多轮长会话。论文实测三条智能体轨迹发现，中位历史长度分别达 77K、131K、70K token，且呈现"长输入、短输出"的不对称模式——追加查询长度是模型输出长度的 3–20 倍。
- **两个关键观察**：
  - **观察 1：追加预填充（append prefill）主导 KV 加载**。约 99% 的解码阶段所需历史 KV 已在追加预填充阶段加载完毕，后续解码步骤大多复用 HBM 中已有缓存，几乎不触发额外 SSD 读取。这使优化目标从解码转向追加预填充。
  - **观察 2：智能体会话放大 KV 读取**。由于多轮特性，同一历史 KV 会被后续多轮反复选中重载，累计读量达写量的 3.9–23.5 倍，且随轮次增加而扩大。
- **核心矛盾**：稀疏注意力（如 DeepSeek-V4、GLM-5 系列采用）依赖推理过程中的临时中间值来决定选择哪些历史 token，导致系统只能在索引器（indexer）执行完毕后才知晓该读什么，**迫使 SSD 读取落入推理关键路径**（实测占追加预填充耗时的 17.5–36.3%）。
- **叠加挑战**：
  - **非连续 I/O**：稀疏选择导致 SSD 读碎片化；PagedAttention 导致写碎片化。
  - **读写干扰**：SSD 内部资源竞争使读带宽下降近 60%，而智能体工作负载恰恰是读密集型。
- **成本动机**：DRAM 与 SSD 的每 GB 成本相差约两个数量级（256GB DDR5 约 $8,500–14,350，30.72TB NVMe SSD 约 $14,500–16,000），SSD 中心化 KV 存储更具成本吸引力。
- **整体含义**：论文提出 **Janus**——一个面向稀疏注意力 LLM、以 SSD 为中心 KV 存储的智能体服务框架，通过预测式 KV 加载与 SSD 友好的 I/O 调度，将稀疏 KV 读取移出关键路径，使 SSD 中心化 KV 存储对长时智能体会话变得实用。

## 2. 方法论：核心思想与关键技术

### 2.1 核心思想

在追加预填充阶段，**复用模型自身的索引器模块作为免训练预测器**，提前若干层预测目标层的 KV 选择，从而为 SSD 读取创造与模型计算重叠的时间窗口；预测未命中部分通过纠正读保证输出无损；同时针对 SSD 的碎片化 I/O 与读写干扰进行系统性优化。

### 2.2 关键技术细节

**（1）免训练前瞻预测（Training-free Lookahead Prediction）**

- 设预测距离为 $d$，在较早层 $\ell-d$ 处，将目标层 $\ell$ 的索引器作用于该层隐藏状态 $h^{(\ell-d)}_t$，同时保留目标层的索引器键 $z^{(\ell)}_s$，得到预测选择：

$$\hat{S}^{(\ell)}_t = \text{Idx}^{(\ell)}\left(h^{(\ell-d)}_t, \{z^{(\ell)}_s\}_{s=1}^{P}; k\right)$$

- 对每个目标层预取预测并集 $\hat{S}^{(\ell)}$，与正常模型执行并行推进。
- 当层 $\ell$ 计算出精确选择 $S^{(\ell)}$ 后，仅对缺失项 $S^{(\ell)} \setminus \hat{S}^{(\ell)}$ 发起**纠正读**，保证模型输出无损。
- 不引入辅助模型、无需训练或离线校准，预测距离 $d$ 即为重叠窗口。

**（2）模型对齐的预测距离**

- 实验发现：$d$ 越小精度越高，召回率对 $d$ 相对不敏感；两个指标在短距离处饱和，饱和点与模型架构对齐：
  - **DeepSeek-V4 系列**：交错稀疏-密集注意力（相邻稀疏层间隔两层），饱和距离 $d=2$。
  - **GLM-5.2**：IndexShare 设计（4 层共享选择），饱和距离 $d=4$。
- 该设置下三模型召回率均 >96%，DeepSeek-V4 冗余 <5%，GLM-5.2 冗余 <10%。

**（3）免同步并行预测（Synchronization-free Parallel Prediction）**

- 传统查询并行划分和索引器键并行划分都会引入跨 GPU 同步点，反而拖慢预测。
- Janus 采用**索引器键并行 + 局部 top-k/N**：每张 GPU 基于自己负责的历史分片，为每个追加 token 生成局部 top-k/N 列表，直接计算本地并集并独立触发预取，**无需全局同步**。
- 由于不同分片覆盖不相交的历史 token，不会产生重复读取；近似误差在合并所有追加 token 的选择后被大幅稀释。
- 实测：在 8 GPU 上，GLM-5.2 加速 2.8×，DeepSeek-V4-Flash 加速 2.3×，召回率几乎不变，精度略降。
- 附带收益：每张 GPU 只需加载自身分片的本地选中 KV，**同时并行化了预测与 SSD 读取**。

**（4）SSD I/O 优化**

- **尽力而为的读打包（Best-effort Read Packing）**：将 KV 选择转为按地址排序的唯一 SSD 块列表，识别最大连续块段，每段只发一条读命令（如 3 个连续块用 1 条请求完成），减少 NVMe 命令数与设备队列压力；不合并未选中块，完全分散时自然退化为块粒度读。
- **CPU 辅助的写打包（CPU-assisted Write Packing）**：PagedAttention 产生的分散 GPU 页先异步传入受限的 CPU 暂存缓冲（实测 16 GiB 即可服务 DeepSeek-V4-Pro 这类 1.6T 模型），由 CPU 按 token 顺序重排后以单次顺序请求写入 SSD。避免 GPU 端打包与模型执行争抢 SM 和内存带宽，同时生成的连续 SSD 布局为后续读打包所用。
- **阶段感知的写限流（Phase-aware Write Capping）**：写消息切分为 256MB 块，写前探测是否有在途读；若有则限制后台写带宽至 512 MB/s（每 SSD），恢复约 90% 读带宽，且不永久牺牲写吞吐。

**（5）实现细节**

- 44K 行 Python + C++/CUDA 代码，集成 Tutti 支持 GPU 发起的 SSD I/O，CPU-SSD 写用标准 POSIX I/O。
- 后端引擎为 vLLM（兼容 SGLang），支持 DeepSeek-V4 与 GLM-5 系列。
- 对确定性加载（索引器键、密集注意力层 KV、滑动窗口 KV）做逐层预取；纠正读期间调用前瞻预测以隐藏预测开销；KV 聚集用 GPU 拷贝引擎完成，避免 SM 争用。

- **预测开销极小**：预测本身仅占追加预填充耗时的 0.3–1.2%，且小于精确索引器耗时，验证免同步并行预测的有效性。

- **端到端服务**：P95 TTFT 相比 Tutti 提升 1.05–1.51×，LMCache 提升 1.31–3.04×，Janus base 提升 1.01–1.68×；P95 TPOT 与各基线基本持平，说明解码效率未因预测机制受损。
- **读/写打包消融**：读打包与写打包两者均启用时 P95 TTFT 退化最小；仅启用其中一项或全部禁用都会导致明显退化，验证两项优化互补——写打包生成的顺序布局为读打包提供连续段基础。
- **写限流消融**：不设上限时读带宽被写流量严重挤占；512 MB/s 上限在恢复约 90% 读带宽的同时仅造成可接受的写吞吐损失，是综合最优的折中点，更严格的上限（256/128 MB/s）反而因写积压拖累整体。
- **预测质量**：预测距离 $d$ 与模型架构对齐时，三模型召回率均 >96%，冗余控制在 5–10% 以内，说明"索引器复用"这一免训练预测器在稀疏注意力架构上具有结构性适配性。
- **免同步并行预测**：8 GPU 上实现 2.3–2.8× 预测加速，召回率几乎不变，证明去掉跨 GPU 同步点对隐藏预测开销至关重要。

## 7. 局限与潜在问题

- **评估环境的单一性**：全部实验在单台 8× H200 服务器、单一 SSD 型号（KIOXIA CD8P-R）上完成，未验证多节点分布式部署、异构存储介质或网络存储场景下的有效性。SSD 中心化方案的收益是否在分布式 KV 存储（如跨节点共享）中依然成立，尚不明确。
- **模型覆盖的架构依赖**：Janus 的预测有效性直接依赖稀疏注意力索引器与目标层选择之间的相关性（即饱和距离与模型架构对齐）。对未采用索引器式稀疏选择的模型（如纯滑动窗口、纯密集注意力、或索引器与选择层距离很远的架构），该方法的适用性和预测距离选择缺乏指导。
- **预测精度与输出无损的边界**：虽然纠正读保证了输出无损，但预测精度下降会直接转化为更多纠正读，进而削弱性能收益。论文未给出预测精度低到何种程度时 Janus 会退化为接近 Janus base 的临界分析。
- **写打包的 CPU 内存依赖**：CPU 辅助写打包需要约 16 GiB 暂存缓冲，虽然论文称对 1.6T 模型也足够，但在更极端的页分散程度或更高并发下，该缓冲可能成为瓶颈，论文未做压力测试。
- **轨迹代表性**：三条轨迹中两条由公开基准（SWE-Bench-Pro、Terminal-Bench）合成生成，仅一条为专有工业轨迹，可能无法完全代表真实生产环境中智能体会话的长度分布、工具调用模式与并发特征。
- **缺少与预测式预填充基线的直接对比**：论文仅在正文定性讨论 ECHO、InfiniGen 等工作，未在统一实验平台上做定量对比，使得"免训练预测"相对已有预测方法的优势缺少直接的实验证据。
- **能耗与成本模型缺失**：论文以 DRAM/SSD 每 GB 成本差异作为动机，但未报告实际部署的能耗、SSD 磨损（写入放大）或总体拥有成本（TCO）数据，成本论证停留在单价层面。

## 8. 总体评价与启示

**贡献定位**：Janus 是一篇系统与算法协同设计的服务工作，其核心洞见——**"复用模型自身的索引器作为免训练预测器，把 SSD 读从关键路径上挪走"**——既简洁又具有架构层面的适配性。它没有发明新的稀疏注意力机制，而是把稀疏注意力的"选择先于读取"这一结构特性转化为系统优化的杠杆，这是该工作最具启发性的地方。

**方法论价值**：

- **预测式加载而非预加载全部**：与 Tutti 加载全部历史 KV 相比，Janus 承认稀疏注意力的选择性并主动预测，避免了"全量读取"的带宽浪费；与 Janus base 的"先选择后读取"相比，它通过前瞻预测制造了重叠窗口。这一"预测—纠正"的两段式设计在不牺牲正确性的前提下获得了延迟收益，是工程上稳健的取舍。
- **免同步并行预测**：识别出"预测本身也会被同步点拖慢"这一隐蔽问题，并用"索引器键并行 + 局部 top-k/N + 本地并集"的近似策略化解，兼顾了并行加速与精度稀释，体现了对分布式推理细节的深入把握。
- **SSD 友好的 I/O 设计**：读打包、CPU 辅助写打包、阶段感知写限流三项优化分别针对非连续读、非连续写、读写干扰三个已识别挑战，且相互支撑（写打包的顺序布局为读打包服务），形成了闭环。

**潜在影响**：随着智能体会话长度持续增长、稀疏注意力成为前沿模型标配，SSD 中心化 KV 存储的性价比优势将更加突出。Janus 展示了一条不依赖硬件扩容、不依赖模型重训练的路径，对推理服务系统的工程实践具有直接参考价值。

**适用边界提示**：Janus 的收益高度依赖"模型采用索引器式稀疏注意力"且"索引器与选择层距离可对齐"这两个前提。对于密集注意力模型或索引器设计差异较大的架构，需要重新评估预测距离与收益空间。
