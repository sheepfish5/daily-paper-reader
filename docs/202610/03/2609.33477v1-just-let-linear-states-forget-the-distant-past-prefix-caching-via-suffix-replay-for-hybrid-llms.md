## 摘要
混合 LLM 将全注意力层与线性注意力层交错，以降低长上下文推理成本，但这种结构使前缀缓存变得复杂。全注意力 KV 缓存可按 token 寻址，而线性注意力层维护的循环状态无法回滚到任意前缀边界。现有系统会物化循环状态检查点，从而将前缀复用限制在与检查点对齐的位置。

我们提出 SuffixReplay，这是首个让混合 LLM 能够在每个缓存支持的页边界复用已缓存前缀、而无需物化循环状态检查点的前缀缓存系统。我们的关键洞察是：就让线性状态遗忘久远过去。现代线性注意力机制利用循环衰减和门控来削弱旧输入的影响。因此，SuffixReplay 不是对每个前缀边界进行检查点，而是通过仅重放该层输入隐藏状态的近期后缀来近似匹配边界处的状态，并将这些后缀保留为锚点。在算法层面，SuffixReplay 结合逐层与逐 token 的锚点稀疏性以及有界重放预算，以控制存储、计算和质量。在系统层面，它使用独立管理的锚点边车和流水线化重放路径，将锚点移动和状态重建与原生服务流水线重叠。我们在三个混合 LLM 上评估 SuffixReplay：OLMo-Hybrid-7B、Qwen3.5-4B 和 Qwen3.6-27B-FP8。在这些模型上，SuffixReplay 在 LongBench 和 RULER 上平均保持全量预填充质量的 91.4–100%，而摊销后的每 token 存储量仅为 SGLang 默认 8192-token 检查点缓存的 0.36–0.51 倍。集成到 SGLang 后，SuffixReplay 在分支工作负载上将中位 TTFT 降低 15–70%，在工作集超过 HBM 时维持 SGLang 吞吐量的 2.3–4.3 倍，并在高命中续写流量上与 SGLang 持平。

## Abstract
Hybrid LLMs interleave full-attention layers with linear-attention layers to reduce long-context inference cost, but this structure complicates prefix caching. Full-attention KV caches are token-addressable, whereas linear-attention layers maintain recurrent states that cannot be rolled back to arbitrary prefix boundaries. Existing systems materialize recurrent-state checkpoints, restricting prefix reuse to checkpoint-aligned positions.   We present SuffixReplay, the first prefix caching system that lets hybrid LLMs reuse cached prefixes at every cache-supported page boundary without materializing recurrent-state checkpoints. Our key insight is to just let linear states forget the distant past. Modern linear-attention mechanisms use recurrent decay and gating to attenuate the influence of old inputs. Therefore, instead of checkpointing every prefix boundary, SuffixReplay approximates the state at a matched boundary by replaying only a recent suffix of the layer's input hidden states, which we retain as anchors. At the algorithmic level, SuffixReplay combines layer-wise and token-wise anchor sparsity with a bounded replay budget to control storage, computation, and quality. At the system level, it uses an independently managed anchor sidecar and a pipelined replay path to overlap anchor movement and state reconstruction with the native serving pipeline. We evaluate SuffixReplay on three hybrid LLMs: OLMo-Hybrid-7B, Qwen3.5-4B, and Qwen3.6-27B-FP8. Across these models, SuffixReplay retains 91.4-100% of full-prefill quality on average across LongBench and RULER, while using only 0.36-0.51x the amortized per-token storage of SGLang's default 8192-token checkpoint cache. Integrated into SGLang, SuffixReplay reduces median TTFT by 15-70% on branching workloads, sustains 2.3-4.3x SGLang's throughput when the working set exceeds HBM, and matches SGLang on high-hit continuation traffic.

# 论文总结：Just Let Linear States Forget the Distant Past: Prefix Caching via Suffix Replay for Hybrid LLMs

## 1. 核心问题与研究动机

- **背景**：LLM 应用从单轮指令跟随扩展到多轮对话、RAG、工具型 agent 与多 agent 工作流，带来长上下文、重复调用与高并发。模型侧用**混合架构**（全注意力 FA 层 + 线性注意力层交错）降低长上下文推理成本；系统侧用**前缀缓存**复用共享前缀、避免重复 prefill。二者本应互补。
- **核心矛盾**：标准前缀缓存抽象是为 FA-only 模型设计的。
  - FA 模型的 KV 缓存**按 token 寻址**，任意前缀边界都能直接复用（论文称为 *continuous prefix caching*，实际支持位置为页边界）。
  - 线性注意力层把前缀压缩成**定长循环状态**，通过 in-place 更新推进；一旦状态推进到更后位置，就**无法代数回滚**到任意更早前缀。
- **现有方案的代价**：Marconi、Sparse Prefix Caching、SGLang 等通过**物化循环状态检查点**来对齐复用边界，使混合模型的前缀复用"离散化"——只有端点与检查点对齐时才能复用。
- **为何不能简单加密检查点**：以 Qwen3.5-4B 为例，一个线性状态检查点约 **49 MiB**，而单 token KV 仅约 **32 KiB**，前者约为后者的 **1500 倍**。密集检查点还会带来写入、传输、索引与管理的巨大开销。
- **研究目标**：在不物化循环状态检查点的前提下，让混合 LLM 的**每个缓存支持的页边界**都可复用，达到与 FA-only 模型同等细粒度。

## 2. 方法论

### 2.1 核心思想（"让线性状态遗忘久远过去"）

- 线性层状态是输入隐藏状态的确定性函数：`S_j = f(h_1, ..., h_j)`，因此理论上可**重放前缀输入**重建任意边界状态，但全前缀重放复杂度 O(j)，对长上下文不可接受。
- 现代线性注意力（Mamba2 的 per-head decay、Gated DeltaNet 的 decay + rank-one erase）通过**循环衰减与擦除门**逐步削弱久远输入的影响，故：
  `S_j ≈ S'_j = f(h_{j-k+1}, ..., h_j)`
  即**只重放近期 k 个后缀锚点**即可近似真实状态；重放代价取决于后缀长度 k，而非前缀长度 j，且**不修改模型本身**。

### 2.2 三项设计约束（R1–R3）

- **R1 质量**：重建状态须为全前缀状态的足够准确代理，LongBench/RULER 平均保留 ≥90% 全量 prefill 质量。
- **R2 存储**：重放输入的额外存储不得超过 SGLang 默认 8192-token 检查点间隔的摊销开销，即 `B_anchor ≤ B_ckpt / 8192`。
- **R3 服务性能**：TTFT、吞吐、容量不得劣于 SGLang 原生前缀缓存路径。

### 2.3 算法设计

- **逐层稀疏锚点（Layer-wise）**：混合模型把连续线性层分组、由 FA 层分隔。只在**每组入口**存一个锚点（而非每线性层一个），层向开销从 O(L) 降到 O(G)；重放**只执行组内线性计算、跳过 FA 层**，代价取决于重放长度而非匹配上下文长度；每组从自身入口锚点重启，**误差不跨组传播**。
- **逐 token 稀疏锚点（Token-wise）**：锚点密度 ρ = 1/16，且与缓存引擎暴露的**页边界对齐**。比较两种布局：均匀采样（每 16 token 一个）vs **密集采样（每 64-token 页的最后 4 行）**；同密度下密集采样质量更稳定（RULER-vt 16K 上 91.8% vs 82.5%），故采用密集布局。重放长度以**锚点数**而非原始 token 数计量。
- **有界重放预算**：命中前缀长度 n 时 `k = min(0.05n, k_max)`；质量扫描显示 Qwen 两模型 k=128 即达标，OLMo-Hybrid-7B 需 k=512。主服务实验取保守上限 k_max = 512（4B）/ 256（27B）。
- **算法—系统契约**：算法输出"每个缓存页关联哪些锚点、每次命中需要哪些近期锚点及对应重放长度桶"，系统负责存储、取回、调度与执行。

### 2.4 系统设计（SGLang v0.5.18 上实现）

- **锚点边车（anchor sidecar）**：锚点块挂在**同一 radix-tree 节点**上、共享 KV 页的准入与驱逐决策，但使用**独立内存池与放置策略**（逻辑关联与物理管理解耦）。锚点可驻留 host DRAM 而对应 KV 页仍在 HBM；ρ=1/16、页大小 64 时每页恰含 4 个锚点，无需额外对齐元数据。
- **锚点写入**：把目标选择移出前向，写入移入 **CUDA graph**。host 预计算每步目的地址表（未采样位置写 scratch 地址），异步上传，graph 内 indexed copy 直写设备端 sidecar；prefill 时先压缩采样 token 再写、整页锚点齐全后 flush；decode 时按请求槽增量更新。避免"每请求-层一次 host 调用"（朴素实现使 decode 吞吐下降 3.3%@ρ=1/8、12.1%@ρ=1/2）。
- **流水线取回与重放**：radix 匹配后立即在**专用 copy stream** 异步取锚点，与调度和 KV backfill 重叠；重放在 **replay stream** 上按组顺序执行，forward stream 只在遇到消费该组状态的首层时等待（**层粒度交接**）。
- **批量重放**：把同 batch 多请求的后缀打包成一次变长执行，用设备端边界划分段与目的状态槽，padding 段用 sentinel 槽号；按总打包长度分桶预捕获 graph（Qwen3.5-4B 共 48 个 graph、约 1.1 GB 设备显存，共享内存池）。
- **失效安全（fail-closed）**：非页对齐命中、锚点缺失/未发布、pending 队列满、重放 hook 不可用 → 一律回退全量 prefill；超出桶范围 → eager replay。
- **多轮活状态快路径**：上一轮活状态仍在则直接续写、跳过重放；但活状态只是 best-effort，驱逐不影响正确性，重放路径始终是正确性路径。
- **实现规模**：引擎侧约 **1.2K 行**，改动 17 个既有文件 + 2 个新文件；通过 cache-component 接口挂载，禁用时 stock SGLang 不变；**不修改任何注意力或循环状态 kernel**。
