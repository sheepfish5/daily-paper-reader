## 摘要
推测解码通过低成本地草拟未来 token 并用目标模型并行验证，从而加速大语言模型推理。块草稿器在一次前向传播中为整个未来 token 块打分，然而标准解码只验证得分最高的链，并丢弃其他候选。由于这些候选已经完成打分，验证更多候选只会增加目标模型计算，而不会带来额外草拟开销。我们提出 CAST（Cost-Aware Speculative Trees，成本感知推测树），它将这些候选打包成一棵树，并在单次目标模型前向传播中验证，同时不改变目标模型、草稿器权重和解码规则。为决定树应该有多宽，CAST 会在新增候选带来的预期收益超过其增加的验证时间时继续添加候选。因此，树的宽度可根据延迟测量自适应于每种部署，而无需扫描不同宽度。我们在三个 GPU 世代、两个模型家族上跨五个领域评估 CAST。在其预测宽度下，CAST 在全部八种设置中都快于标准链，最高提升 43%。我们还发现，最佳宽度强烈依赖于部署。当验证成本在某个内核边界处跃升时，128-token 树仅比标准链快 2%，而预测宽度下的树快 20%。此外，我们证明 CAST 在贪心解码和采样解码下均不改变目标输出分布。代码见 https://github.com/js-lee-AI/CAST。

## Abstract
Speculative decoding accelerates large language model inference by drafting future tokens cheaply and verifying them with the target model in parallel. Block drafters score a whole block of future tokens in one forward pass, yet standard decoding verifies only the top-scoring chain and discards the other candidates. Because these candidates are already scored, verifying more of them adds target computation but no extra drafting. We introduce CAST (Cost-Aware Speculative Trees), which packs these candidates into a tree and verifies it in a single target pass, leaving the target model, drafter weights, and decoding rule untouched. To decide how wide the tree should be, CAST adds candidates while the expected gain from the next one outweighs the verification time it adds. The width therefore adapts to each deployment from a latency measurement, without sweeping over widths. We evaluate CAST across five domains on three GPU generations and two model families. At its predicted width, CAST is faster than the standard chain in all eight settings, by up to 43%. We also find that the best width depends strongly on the deployment. Where verification cost jumps at a kernel boundary, a 128-token tree is only 2% faster than the standard chain, whereas the tree at the predicted width is 20% faster. Furthermore, we prove that CAST leaves the target output distribution unchanged under both greedy and sampled decoding. Code is available at https://github.com/js-lee-AI/CAST.

## 1. 核心问题与整体含义（研究动机与背景）

- **推测解码（Speculative Decoding, SD）** 通过轻量草稿器提出未来 token，再由目标模型一次前向并行验证，在不改变输出分布的前提下加速 LLM 推理。
- **块草稿器（如 DFlash）** 在一次前向传播中即为整块未来 token（L+1=16）的每个位置输出完整词表分布，草拟成本极低。
- **关键浪费**：标准解码只保留每个位置的最可能 token，验证这条 top-1 链，其余**已被打分的候选全部丢弃**。一旦目标模型拒绝链中较早的 token，本轮只能提交极少数 token，即使目标想要的 token 就在被丢弃的候选中。
- **核心洞察**：这些候选已经完成打分，验证更多候选只增加目标模型的计算量，**不增加草拟开销**——这与自回归草稿器（EAGLE 系列，每加宽一层需多一次草稿步）的成本结构截然不同。
- **新的开放问题**：树应该有多宽？验证成本高度依赖部署（GPU 型号、并发请求数、甚至在某些 GPU 上跨内核边界时跳变），现有自适应树方法（面向 EAGLE 等自回归草稿器）不能直接迁移。
- **整体含义**：CAST 提出一种**成本感知的解码策略**，把块草稿器丢弃的候选回收为待验证树，并让树宽随部署自适应，且**不改变目标模型、草稿器权重与解码规则**。

## 2. 方法论

### 核心思想
- 每轮只运行一次不变的块草稿器，用草稿器各位置概率的**连乘**为候选序列打分，保留得分最高的序列构成**前缀闭包（prefix-closed）树**，由目标模型在**一次祖先掩码前向**中验证。
- 树宽由一个**边际收益-成本停止规则**决定，规则只需要草稿器分数与一次短延迟探测，无需扫描宽度。

### 关键技术细节

- **候选打分（plug-in score）**：长度 d 的候选序列 $y_{1:d}$ 的得分 $\hat{\pi}(y_{1:d}\mid x,b)=\prod_{j\le d} q_j(y_j\mid x,b)$，仅用于排序，不假设目标分布按位置因子分解。

- **打包验证等价性（Lemma 1）**：把 pending root b 与所有非根节点按祖先先于后代顺序打包，用只允许关注自身祖先的注意力掩码，一次前向即可**精确复现** N+1 次独立自回归前向的 logits。

- **预算最优树（Theorem 1）**：在固定前缀信念 ρ（沿前缀非增）下，期望接受长度可分解为节点质量之和 $\mathbb{E}_\rho[A(S)]=\sum_{v\in S}\rho(v)$；因此在固定预算 N 下，**取质量最大的 N 个字符串即为最优且前缀闭包**。Corollary 1 用 $\hat{\pi}$ 作为 ρ 给出 DFlash 的 plug-in 最优树；Proposition 1 给出该树相对 oracle 的遗憾上界（对称差上的估计误差之和）。

- **成本感知停止规则（Theorem 2）**：设 g(N) 为最优 N 节点树的期望接受长度（增量即第 N 大前缀质量 ρ(N)，g 凹），轮次时间 $\ell(N)=c_{\text{draft}}+h(N)+\ell_{\text{tgt}}(n_0+N)$，若 h+ℓ_tgt 局部仿射、斜率 c₁≥0，则吞吐 $(g(N)+1)/\ell(N)$ 单峰，**当且仅当**
  $$\rho(N+1)\ \ge\ \frac{g(N)+1}{\ell(N)}\cdot c_1$$
  时加入第 N+1 个节点不降低吞吐。规则含义：**只要下一个候选的前缀质量超过"系统每秒产出 token 的交换率 × 每节点成本"，就继续加节点**。实验中 c₁ 取探测测得的仅前向斜率（低估 c₁，误差由扫描实验界定）。

- **采样解码（Theorem 3）**：T>0 时使用**提案感知的随机树验证器**（无放回的递归推测采样，SpecInfer/SpecTr 风格），在拒绝时更新残差分布 $\mu\leftarrow(\mu-\tilde q)^+/\|(\mu-\tilde q)^+\|_1$，证明提交 token 的分布与目标温度 T 下的自回归采样**完全一致**。

- **负载下共享预算（Proposition 2/3）**：B 个并发请求共享验证器预算 M，期望接受长度可加，**全局 best-first 扩展**在不相交候选森林上最优；批处理停止规则把 (g(N)+1) 替换为 (G(M)+B)，允许各请求宽度不等，B=1 时退化为 Theorem 2。

- **CAST 解码器流程**：保留每位置 top-K=8 → best-first 按 $\hat{\pi}$ 递减扩展（最小堆）→ 打包 [b, z₁…z_N] 用祖先掩码一次验证 → 沿树下行，提交被接受路径 + 目标选定 token 作为新 pending root → 压缩 KV 缓存并追加特征缓存。

## 6. 主要结论与发现

- **预测宽度下 CAST 在全部 8 个设置中都快于标准 DFlash 链**，平均增益 20–36%，单领域最高 **43%**；Qwen3-8B/4B 在 H100 SXM 平均 5.62× 加速（相对 AR）。
- **最佳宽度强烈依赖部署**：Blackwell-8B 在 n=128 处存在内核/tile 边界导致验证成本跃升，128 树仅比链快 2.4%，而预测宽度 N*=63 快 19.8%；H100 SXM 曲线平坦，规则选到 N*=127。
- **预测宽度在 8 个设置中有 6 个与扫描 oracle 完全一致**，最差差距 1.7 个百分点。
- **树形状本身即有效**：相同 16 packed tokens 下，仅改变形状（N=15 树 vs 链）即带来 5.9–29.2% 加速。
- **输出分布不变**：fp32 下与自回归逐 token 一致；bf16 仅在 top-2 logits 接近平局时因舍入产生差异；采样下总变差 fp64 为 0.003（低于蒙特卡洛下限 0.013），bf16 为 0.004。
- **负载下无单一静态宽度最优**：最佳静态宽度随并发从宽树（B≤8）退化为链（B≥16）；全局 best-first 共享预算分配相对最优静态宽度提升 goodput 中位 7.0%（B=16）、13.7%（B=32）。
- **可迁移性**：对 DART 这一架构不同的单遍草稿器，63 节点树把提交轮长在 GSM8K 提升 40%、HumanEval 提升 34%；对 LLaMA-3.1-8B，CAST 平均 3.87× 快于 AR，比 60-token EAGLE-3 树快 30–60%（EAGLE-3 每轮需 8 次草稿步，CAST 只需 1 次）。

## 7. 优点

- **改动面极小**：不改变目标模型、草稿器权重、特征缓存契约与解码规则，可直接插入现有 DFlash 推理栈。
- **理论完整**：给出了"选哪些节点"（Theorem 1 最优性）、"选多宽"（Theorem 2 单峰性与停止规则）、"分布是否保真"（Theorem 3）、"负载下如何分配"（Proposition 2/3）四条完整的理论链。
- **成本模型来自实测**：宽度决策基于真实延迟探测（含内核边界跳变这类工程现实），而非纯理论或扫参，且扫描只用于验证而非选参。
- **评测维度丰富**：3 代 GPU、2 个模型家族、2 种草稿器架构、5 个领域、贪心与采样、离线重放与在线计时、batch-1 与并发负载，并配有 bootstrap 置信区间与多次重复。
- **诚实报告**：明确指出 co-tenant GPU 负载会放大增益，故采用空闲 GPU 的保守测量；给出长前缀、MoE、线性注意力混合目标的边界行为。

## 8. 不足与局限

- **评测范围有限**：解码实验使用 ≤8B 的密集目标，仅附加一个 30B MoE（3B 激活）目标；未覆盖更大规模密集模型或真实生产 serving 栈。
- **计时口径**：只报告 decode-only 稳态 ms/token，作者明确声明**不是 serving 吞吐或成本结论**；未报告端到端延迟、吞吐、能耗或显存开销。
- **树最优性受限**：仅在保留的 K=8 top-K 宇宙内、对 plug-in 信念最优；由于 DFlash 边缘分布不是路径条件化的，深层分支仍暴露于标定误差（Proposition 1 的遗憾界依赖这一误差）。
- **依赖单遍草稿器假设**：自由加宽的论证要求草稿器一次前向给全部候选打分；多步细化的草稿器会重新引入草稿侧宽度成本。
- **继承 DFlash 约束**：需要已训练的 head 与 feature-cache 契约，不解决 DFlash 训练成本或 block size 变更问题。
- **负载实验原型化**：batch 实验为密集原型（right-pad 到最大宽度会产生 padding tax），varlen 验证器为自实现 Triton kernel；连续批处理实验规模较小（200 请求），结论的普适性有待更大规模验证。
- **潜在偏差风险**：预测宽度阈值（如 0.015）来自离线 GSM8K 分数，跨部署只改成本斜率；若 c₁ 被低估（忽略 h 的非负斜率），规则倾向于选得过宽，论文用扫描实验界定该误差，但未给出正式保证。
- **对比基线覆盖**：主要与 DFlash 链和 EAGLE-3 对比，未与同期并发工作（如 D-cut、AdaFlash、BlockPilot、SMART）做直接实验对比，仅作文字讨论。
