## 摘要
日益增长的大语言模型应用对高效推理提出了需求。在高并发场景下，块扩散投机解码面临验证填充、候选被拒，以及可变前缀与固定形状计算图不兼容等问题。统一截断会牺牲本可接受的词元。我们提出 DScale，它保留草稿模型的架构、权重与完整草稿长度。一个独立的 112K 参数预测器既不需要置信度校准，也不需要预先准备硬件速度曲线。路径感知分块减少了填充。动态验证长度（DVL）分配将已评分的各前缀打包进原生验证容量的一半。固定地址工作区在复用已捕获计算图的同时，将不断变化的边界贯穿验证与接受过程。在张量并行度为 1 的 A100-40GB 上，Qwen3-8B 与 Qwen3-4B 覆盖四个数据集和 8–32 的并发度，并复用各自目标模型的冻结预测器。在这些配置下，几何平均吞吐量相较 DFlash 分别提升 43.9% 和 48.8%，相较 DSpark 提升 22.2% 和 37.7%，相较 Domino 提升 24.4% 和 32.0%，同时请求延迟更低。累积消融实验表明，依次加入这三个机制可逐级提升几何平均吞吐量，而预算调整则改善了可接受词元的保留率。GPU 性能分析显示，在 GSM8K 上完整解码步耗时相较 DFlash 降低 30.8–52.5%。

## Abstract
Growing large language model applications demand efficient inference. At high concurrency, block-diffusion speculative decoding suffers from verification padding, rejected candidates, and incompatibility between variable prefixes and fixed-shape graphs. Uniform truncation sacrifices acceptable tokens. We present DScale, preserving drafter architecture, weights, and full draft length. A separate 112K-parameter predictor requires neither confidence calibration nor hardware speed-curve preparation. Path-aware tiles reduce padding. Dynamic verify-length (DVL) allocation packs scored prefixes into half the native verification capacity. Fixed-address workspaces propagate changing boundaries through verification and acceptance while reusing captured graphs. On A100-40GB with tensor parallelism 1, Qwen3-8B and Qwen3-4B cover four datasets and concurrency 8-32, reusing each target's frozen predictor. Geometric-mean throughput gains across these configurations are respectively 43.9% and 48.8% over DFlash, 22.2% and 37.7% over DSpark, and 24.4% and 32.0% over Domino, with lower request latency. Cumulative ablations show that adding the three mechanisms successively increases geometric-mean throughput, while budget adjustment improves accepted-token retention. GPU profiling shows that complete decode-step time on GSM8K decreases by 30.8-52.5% relative to DFlash

## 1. 核心问题与整体含义（研究动机与背景）

- **背景**：LLM 服务在高并发下需要低延迟与高吞吐，但自回归解码每步只生成一个 token，顺序执行限制速度。投机解码用小型草稿模型生成候选、由大目标模型并行验证，是主流加速路径。
- **具体场景**：DFlash 采用块扩散（block diffusion）草稿器，一次并行前向生成完整候选块（W=16 个验证槽：1 个已知锚点 + 15 个新候选），目标模型一次性验证。
- **性能剖析**：在 Qwen3-8B / GSM8K / A100 / TP1 / 并发 16 下，目标验证图占 GPU 核函数总时间的 **83.3%**，草稿图 10.9%，图外核函数 5.7%。即验证侧是主导瓶颈。
- **三个相互关联的挑战**：
  - **挑战 1：工作负载形状与瓦片不匹配**。预填充与验证共用同一套注意力瓦片布局（A100 上 128 行），但验证每请求仅提供 W=16 行，导致每请求每头 **112 行（87.5%）被掩码**，掩码不压缩编译后的瓦片与中间数组。
  - **挑战 2：请求级接受长度可变**。固定宽度无法匹配请求差异；固定宽度实验显示所有小于 16 的宽度吞吐均低于全宽（宽度 8 吞吐下降 15%，平均进度由 5.92 降至 4.96），而宽度 14 仅减少 12.5% 的验证槽。真实接受长度只有验证后才知道，统一截断会牺牲可接受 token。
  - **挑战 3：动态前缀与固定验证图接口不兼容**。请求边界每步移动（如长度从 [4,12,8] 变为 [10,8,6]），补齐回等宽接口会恢复浪费；CPU 重切片会把主机工作放到 GPU 关键路径上；DSpark 的桶粒度导致细粒度剪枝只换来桶级容量下降（111→97 行仍选 112 槽图）。
- **整体含义**：目标是在**保留草稿器架构、权重与完整草稿长度**的前提下，为每请求分配更小的验证容量，同时让变化的请求边界在紧凑执行与已捕获图重放中一致传递。作者指出草稿侧信号（Top1–Top2 logit gap）与接受长度正相关（Spearman ρ=0.741 / 0.722），且无需依赖草稿器训练。

## 2. 方法论：核心思想与关键技术

**核心思想**：DScale 是构建在 SGLang v0.5.14 上的“免草稿训练”运行时，复用 DFlash 草稿器，仅训练一个独立 **112K 参数预测器**（每个 target–drafter 对训练一次），在不做置信度校准、不准备硬件速度曲线（SPS）的前提下，把每请求候选前缀打包进原生验证容量的一半（8N 槽）。系统目标为：

- max_π Σ_r OutputTokens_r(π) / ElapsedTime(π)

**三大机制：**

- **路径感知瓦片路由（Path-aware Tile Routing）**
  - 按路径选择瓦片高度：验证路径 ℓmax ≤ W=16 时选 B=16；预填充与长查询保留硬件选的 Bhw=128 以维持 KV 复用。
  - 网格为 (Nrun, H, ⌈ℓmax/B⌉)，每计算块处理一个请求的一个头。
  - 行容量与填充率：rows(ℓ,B)=B⌈ℓ/B⌉，padding(ℓ,B)=1−ℓ/rows(ℓ,B)；ℓ=16、B=16 时无填充。

- **动态验证长度（DVL）预算分配**
  - 容量定义：Mbs = W·Nbs/2，Mlive = W·N/2 = 8N，满足 Σki = Mlive，ki ∈ [1, W]。
  - **接受预测器**：每请求构造 1735 维特征 = 270 维置信特征（15 个草稿位置 × 18 个偏好/不确定性值：最高 logit、与 rank2–16 的 15 个 gap、top token log-prob、熵）+ 960 维隐状态投影（15×64）+ 480 维 logit 投影（15×32）+ 25 维批上下文。经 1735–64–15 的 MLP（ReLU）输出每位置预测，Sigmoid 得分数。
  - **单调性约束**：q0=1，qj = min(qj−1, σ(predLogits_j))，通过累积最小值强制前缀分数非增。
  - **初始长度**：ˆℓi = Σ q_{i,j}，k(0)_i = min{W, max{1, ⌊ˆℓi + 1/2⌋}}。
  - **预算分配器**：以最大化 ΣΣ q_{i,j} 为目标，从种子出发按 Δ = Mlive − Σki 调整：Δ>0 时增加“下一槽增益 q_{i,ki}”最大的请求；Δ<0 时删除“末槽损失 q_{i,ki−1}”最小的请求尾；在决策图内的单个 GPU 计算块完成，无主机往返与块间同步。Proposition 1 证明其保持前缀与锚点、在 |Δ0| 次更新内满足预算，并在相应约束下最大化目标函数。
  - **Flat-buffer packer**：以前缀和偏移 offset_i = Σ_{j<i} kj 将 token、位置、KV 引用按相同行映射写入固定地址缓冲；非活跃长度置零、偏移置 Mlive、尾部填占位符。
  - **复杂度**：Work_DVL = O(Nbs·d·h + N·Nbs·W² + Mbs·Nbs)；W=16 时调整次数 ≤ 7N。实测分配器（预测器+预算分配+打包）占 c=8 解码步时间 **3.08%（8B）/ 4.08%（4B）**。

- **面向不规则决策的图集成（Graph Integration）**
  - 固定地址工作区：跨步保持各张量的地址与形状不变。
  - 桶选择 Nbs = min{b ∈ B | b ≥ N}；容量满足 Mlive + 8(Nbs−N) = 8Nbs = 16Nbs/2，即 DFlash 同请求桶容量的一半。
  - Algorithm 2：对每个桶只捕获一次决策图（Features→DVL）与验证图（Target→Accept→Output），此后每步仅重放；用 offset/ki 设置 qStart/qEnd，按 ctxLen 收集已提交上下文 KV，掩码 valid_i(j) 筛选有效行；**无需 CPU 长度回读或切片重建**，无固定宽度补齐。
  - **前缀验证器**：确定性 top-1 候选以概率 P(x) 接受，首个拒绝处从去掉 x 并重归一化的目标分布中抽取后继 token；若 ki−1 个候选全部通过则用原始目标分布；接受 token 加后继构成下一锚点。DVL 长度选择与接受随机数独立，输出分布正确性由补充材料推导。状态提交在捕获之外执行。
