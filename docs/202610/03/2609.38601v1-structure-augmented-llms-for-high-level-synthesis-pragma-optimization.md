## 摘要
编译指示插入决定了高层次综合（HLS）设计的质量。选择合适的编译指示需要专家知识，并需要对循环嵌套、数据依赖和内存布局进行推理。尽管现有大语言模型（LLM）在代码生成方面展现出潜力，但它们缺乏显式的程序结构感知，限制了其推荐有效编译指示的能力。我们提出 PRISM，一种新颖的结构增强大语言模型，通过为预训练且冻结的代码大语言模型加入编译器级结构推理来弥合这一差距。它结合三种层次化程序表示——抽象语法树（AST）、控制流图（CFG）和数据流图（DFG）——将它们注入特定的 Transformer 层，同时将原始代码 token 保留在单独的流中。注入点处的交叉注意力门控允许在结构信号无帮助时回退到预训练表示。在 HLS-Eval 上的零样本评估中，PRISM 综合出的内核数量是 Llama3-8B 的 3.5 倍（26.9% 对 7.7%）；在它确实成功的那些内核上，其生成的设计在几何平均上比 GPT-5-mini 的快 2.31 倍。在智能体流程中，PRISM 代码生成在优化复杂代码时优于其他基线，并将 HLS-Eval 套件上的平均归一化改进提升至 26.4%。

## Abstract
Pragma insertion drives the quality of high-level synthesis (HLS) designs. Choosing the right directives demands expert knowledge and reasoning about loop nesting, data dependences, and memory layout. While existing large language models (LLMs) show promise in code generation, they lack explicit program-structure awareness, limiting their ability to suggest effective pragmas. We present PRISM, a novel structure-augmented LLM that closes this gap by adding compiler-grade structural reasoning to a pretrained, frozen code LLM. It combines three hierarchical program representations, Abstract Syntax Tree (AST), Control-Flow Graph (CFG), and Data-Flow Graph (DFG), injecting them into a specific transformer layer while keeping original code tokens in a separate stream. The cross-attention gate at the injection point allows falling back to the pretrained representation when its structural signal is unhelpful. On zero-shot evaluation in HLS-Eval, PRISM synthesizes 3.5\times as many kernels as Llama3-8B (26.9\% vs. 7.7\%), and on the kernels where it does succeed, it produces designs that are 2.31\times faster (geomean) than GPT-5-mini's. In the agentic flow, the PRISM codegen outperforms other baselines when optimizing complex code and drives the average normalized improvement across the HLS-Eval suite to 26.4\%.

## 1. 核心问题与整体含义（研究动机与背景）

- **HLS 中 pragma 决定硬件质量**：高层次综合把硬件设计抽象到 C/C++ 层，但最终硬件质量几乎完全由少量优化指令（pragma）决定。一个循环是否流水线化、展开程度如何、数组如何分区，会影响吞吐、延迟和资源占用，且常常相差一个数量级。
- **典型失效模式**：一个错误的 `ARRAY_PARTITION` 会让流水线循环因存储带宽而"饥饿"；在带有循环携带依赖的循环上加 `PIPELINE` 会使启动间隔（II）从 1 个周期膨胀到数十个周期。
- **现有方法的局限**：
  - 主流的 HLS 设计空间探索（DSE）方法（AutoDSE、GNN-DSE、HARP、IronMan）依赖 GNN 代理模型对**固定候选配置**进行打分或排序，是判别式模型，无法直接生成新的 pragma，仍需外部搜索循环。
  - LLM 擅长通用代码生成，但只把程序视为**线性 token 序列**，缺乏显式的控制流与数据流视图，因而经常产生非法或次优的 pragma，直到综合阶段才失败。
- **核心洞察**：LLM 应当"看到"编译器用于保证正确性和推理性能的层次化结构——AST、CFG、DFG——这正是 HLS 专家一眼就能做出的推理（如数组相互独立、无循环携带依赖，从而允许 II=1 流水线与数组分区）。

## 2. 方法论：PRISM 的核心思想与关键技术

### 2.1 总体架构

PRISM（**P**ragma **R**easoning via **I**ntegrated **S**tructural **M**odels）在**预训练且冻结**的代码 LLM 上增加显式结构视图，分为四个阶段：

1. 从源内核 $s$ 提取三种互补图：AST、CFG、DFG。
2. 每种图由各自独立的 **GATv2** 编码器处理，得到固定长度嵌入 $z_g \in \mathbb{R}^{256}$。
3. 三个嵌入拼接后投影为 $k=128$ 个**图 token** $T \in \mathbb{R}^{k \times d}$，位于 LLM 的嵌入空间。
4. LLM 文本隐状态通过**门控交叉注意力**模块关注 $T$，富化后的状态送入后续 Transformer 层解码。

基座模型实例化为 **Llama-3.1-8B-Instruct**（隐藏维度 $d=4096$），全部权重冻结，仅训练图编码器、投影器、交叉注意力与门控参数以及 LoRA 适配器。

### 2.2 两条设计原则

- **结构与指令解耦**：文本流承载指令与内核，图流承载正交的编译器级视图，两者在融合前保持分离，而不是把图序列化进 prompt；让二者各用独立参数学习，并显式学习其交互。
- **保留预训练模型**：任何覆盖原权重的结构注入都是"用一种能力换另一种能力"。因此冻结基座，仅通过门控残差路径引入结构信号，使门控无效时模型精确退化为原始 LLM。

### 2.3 图构建

- **AST**：捕捉层次化语法（循环嵌套、下标表达式、算符结构）。
- **CFG**：记录执行路径（基本块、回边、分支条件），使循环迭代次数与嵌套易于观察。
- **DFG**：表示定义-使用关系，暴露循环携带依赖和数组读写模式。
- Python 内核用原生 `ast` 模块提取 AST，CFG/DFG 由该树单次遍历构建；C/C++ 提取流程见 2.7。
- 每个节点特征由节点类型的 one-hot、表层 token 的哈希、节点度数拼接而成，得到节点特征矩阵 $X_g \in \mathbb{R}^{n_g \times f}$ 和边索引 $E_g$。

### 2.4 每图独立 GNN 编码器

每个图由独立的 GATv2 卷积栈编码（选用 GATv2 是因为其**动态注意力**可表达边条件重要性，例如 CFG 中单条回边需主导循环表示）。结构为：第一层 4 头多头注意力，第二层投影为单头，应用图归一化后池化为图级向量：

$$z_g = \mathrm{Pool}\big(\mathrm{GraphNorm}(\mathrm{GATv2}(X_g, E_g))\big), \quad g \in \{ast, cfg, dfg\}$$

三图用独立参数并行编码，避免跨模态污染，便于后续融合模块学习显式交互。

### 2.5 图融合与 Token 生成

三图向量拼接为 $z = [z_{ast}; z_{cfg}; z_{dfg}] \in \mathbb{R}^{768}$，由可学习的图 token 生成器扩展为 LLM 嵌入空间中的 $k=128$ 个 token：

$$G = \mathrm{MLP}\big(\mathrm{Proj}(z) + P\big), \quad G \in \mathbb{R}^{128 \times 4096}$$

其中 $P$ 是 $k$ 个 token 槽位上的可学习位置嵌入。将单个 768 维描述符扩展为 $k$ 个 token（而非一个），使交叉注意力层有多个结构"槽位"可关注，作者发现这是让模型把不同结构侧面路由到生成内核不同部分的必要条件。

### 2.6 门控交叉注意力注入

**在 layer 0 注入**，以保证所有后续层都收到富化表示。设文本隐状态 $H \in \mathbb{R}^{m \times d}$、图 token $G \in \mathbb{R}^{k \times d}$：

$$A = \mathrm{softmax}\left(\frac{(HW_Q)(GW_K)^\top}{\sqrt{d_k}}\right)GW_V$$

$$\gamma = \sigma\big(\mathrm{MLP}([H; A])\big)$$

$$H' = \gamma \odot A + (1-\gamma) \odot H$$

其中 $\sigma$ 为 logistic 函数，$\odot$ 为 Hadamard 积。$\gamma \in (0,1)$ 按位置、按通道控制结构信号的准入量：当 $\gamma \to 0$ 时该层退化为恒等映射，模型精确表现为预训练 LLM。这既保证不覆盖基座编码能力，也保证训练稳定——网络可以忽略无用的图信号而非被迫使用。

### 2.7 微调与跨语言结构迁移

- **微调**：端到端训练但冻结基座；LoRA 适配器挂在 Transformer 层，仅更新适配器、三个 GNN 编码器、token 生成器、交叉注意力与门控参数。由于各组件收敛速率不同（随机初始化的 GNN 比已收敛骨干上的 LoRA 学习更快也更嘈杂），**每个组件使用独立学习率调度**，使结构通路与文本通路同步推进。
- **训练语料**：InstructCoder（超过 114k 条指令-输入-输出 Python 三元组，用于代码编辑、优化与重构），**没有**在 C/C++ HLS pragma 语料上额外微调。
- **跨语言迁移**：因图编码器在 Python 上训练，应用到 C/C++ 时需桥接两种"图语言"——先剥离宏、pragma 和注释，在清理后的代码上重建 AST/CFG/DFG，并把 C 节点类型映射到 Python 节点类型词表，使编码器接收到训练分布内的嵌入。映射不完美，C 中显式变量声明与初始化在 Python 中无对应物，这构成了残余误差来源。所有实验中保留**无 pragma 的裸内核**作为结构源。

3. **结构在哪里起作用**：PRISM 在 MachSuite 上优于 gpt-oss-20b（43.8% vs 31.2%），因循环与数组模式足够丰富；在 PolyBench 上落后（规则嵌套循环下规模本身就够用）；在 CHStone 上跌至 **0%**，因该 benchmark 富含 C 特有构造（struct、typedef、显式指针算术），Python 训练的图编码器无对应物——这正是跨语言迁移方案预测的失败模式。
