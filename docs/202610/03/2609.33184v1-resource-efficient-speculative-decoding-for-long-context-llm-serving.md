## 摘要
投机解码通过并行验证来自草稿模型的多个 token，减少对目标模型的顺序调用。然而，KV Cache 的增长限制了受限 GPU 内存下的长上下文服务。将 KV 卸载到 CPU 内存可缓解这一压力。然而，现有卸载方案在注意力计算前恢复完整 KV 历史，未能充分利用同一验证轮次内跨查询 KV 共享的收益。现有并行投机解码方法还忽视了在受内存带宽限制的目标验证等待历史 KV 时闲置的 GPU 计算能力。我们提出 SpecStream，一种投机解码系统，它无需等待完整 KV 历史恢复便开始验证，并利用 KV 传输期间的计算气泡在同一批 GPU 上进行并发草稿生成。它仅卸载目标模型已提交的历史，使候选回滚保留在 GPU 本地。每个流式传输的 KV 块服务该轮次中的所有查询，并通过在线 softmax 保持完整注意力。目标优先调度在资源限制下控制草稿模型的并发执行，以约束其对目标验证的干扰。实验表明，SpecStream 在有限 GPU 内存下支持更多并发请求的同时，保持任务质量接近 SGLang 投机解码。在不同数据集上，对于 Qwen3 和 InternLM2.5，其相比卸载基线分别实现了平均 1.41× 和 1.32× 的吞吐量加速。与在分离的目标和草稿 GPU 上进行并行投机解码相比，SpecStream 将每 GPU 输出吞吐量平均提升 55.4%。

## Abstract
Speculative decoding reduces sequential Target model calls by verifying multiple tokens from the Draft model in parallel. Yet KV Cache growth limits long-context serving under constrained GPU memory. Offloading KV to CPU memory relieves this pressure. However, existing offloading schemes restore the full KV history before attention and fail to fully exploit the benefits of KV sharing across queries within a verification round. Existing parallel speculative decoding methods also overlook idle GPU compute capacity while memory-bandwidth-bound Target verification waits for historical KV. We present SpecStream, a speculative decoding system that begins verification without waiting for the full KV history to be restored and exploits compute bubbles during KV transfers for concurrent drafting on the same GPUs. It offloads only Target-committed history, keeping candidate rollback local to the GPUs. Each streamed KV chunk serves all queries in the round, with online softmax preserving full attention. Target-priority scheduling controls Draft concurrent execution under resource limits to constrain interference with Target verification. Experiments show that SpecStream maintains task quality close to SGLang speculative decoding while supporting more concurrent requests under limited GPU memory. Across different datasets, it achieves average throughput speedups of 1.41$\times$ and 1.32$\times$ over the offloading baseline for Qwen3 and InternLM2.5, respectively. Compared with parallel speculative decoding on separate Target and Draft GPUs, SpecStream improves output throughput per GPU by an average of 55.4%.

## 1. 核心问题与整体含义（研究动机与背景）

- **背景**：长上下文 LLM 服务中，KV Cache 随序列增长持续占用显存（约 $M_{KV}(B,C)\approx 2BLn_{kv}d_h b_e C$），而解码阶段每步只推进少量 token 却反复访问历史 KV，显存容量与数据搬运成为核心约束。
- **投机解码的双刃性**：它通过 Draft 模型一次生成多个候选、Target 一次前向并行验证，减少顺序 Target 调用；但每轮验证仍依赖历史 KV，且 Draft/Target 双方的权重、KV、候选状态与执行缓冲区同时争抢显存，可能更早触达显存上限。
- **现有卸载方案的缺陷**：
  - 必须等当前层完整 KV 历史恢复到 GPU 后才开始注意力计算，传输时间随上下文线性增长并落在 Target 验证的关键路径上；
  - 未区分"已提交 KV"与"未验证候选 KV"的生命周期，可能为最终被拒绝的候选做无效搬运与 CPU 侧清理；
  - 忽视同一验证轮内 $q$ 个 query 共享同一段已提交历史这一可摊销的复用机会（$D_{token}(q)\approx D_H / E[U(q)]$）。
- **算力浪费**：卸载引入 H2D 传输后，计算等待约 $G\approx \max(0, T_{H2D}-T_{attn})$，形成"计算气泡"——拷贝引擎在搬数据，而计算单元空闲。现有并行投机方案（MineDraft、SPECTRE、SwiftSpec）依靠额外 GPU 或跨批流水线掩盖草稿延迟，并未直接利用这些气泡在同批 GPU 上推进 Draft。
- **整体含义**：论文主张把 KV 访问方式与投机执行方式联合设计——以"完整投机轮次"而非"存储位置迁移"为单位优化，从而在有限显存下同时缓解容量瓶颈与带宽瓶颈。

## 2. 方法论：核心思想与关键技术

**核心思想**：Target 验证不等完整 KV 恢复即可开始，边传输边计算；同时把传输等待期变成 Draft 的候选生成进度。系统由三个组件构成，实现在 SGLang 0.5.17 上。

### 2.1 提交感知、免回滚的 KV 分层（Commit-Aware Rollback-Free KV Tiering）

- 按 Target 提交边界把每个请求的 KV 划分为三段，满足 $0\le H\le C_r\le L_r$：
  - **Sealed History $[0,H)$**：迁移已完成的不可撤销历史，驻留 CPU；
  - **Active Tail $[H,C_r)$**：近期已提交 KV，驻留 GPU；
  - **Speculative Frontier $[C_r,L_r)$**：未验证候选 KV，驻留 GPU。
- 迁移终点由 $E=\max\big(H,\ g\cdot\lfloor \max(0,C_r-T)/g\rfloor\big)$ 决定，仅当 $E>H$ 时异步拷贝 $[H,E)$；完成后才推进边界 $H$ 并回收 GPU 空间。超参为保留目标 $T$（Active Tail 长度）、迁移粒度 $g$。
- **免回滚保证**：轮末提交前缀长度 $C'_r\ge C_r$，回收区间 $[C'_r,L_r)$ 与 $[0,H)$ 交集为空。候选拒绝只影响 GPU 上的投机后缀，无需跨设备回滚或 CPU 副本清理；批量迁移还降低了碎片化传输与元数据开销。

### 2.2 面向多查询验证的 KV 流式执行（KV Streaming for Multi-Query Verification）

- **分块 + 全查询组共享**：把当前层 Sealed History 沿 token 位置切成 $J$ 个连续 chunk，块 $j$ 到达 GPU 后即以整个查询组 $Q\in\mathbb{R}^{q\times d_h}$ 计算 $S_j=QK_j^{\top}/\sqrt{d_h}$。一次传输服务本轮全部 $q$ 个查询，处理完即可释放暂存缓冲区接收下一块。
- **在线 softmax 保持精确注意力**：为每个 query/head 维护三元组 $(m,\ell,a)$（历史最大分数、相对指数的分母和、加权值分子），初值 $(-\infty,0,0)$。
  - 块内局部状态：$m_j=\max(S_j)$，$\ell_j=\sum_k e^{S_{j,k}-m_j}$，$a_j=\sum_k e^{S_{j,k}-m_j}V_{j,k}$；
  - 跨块合并：$m'=\max(m,m_j)$，$\alpha=e^{m-m'}$，$\beta=e^{m_j-m'}$，$\ell'=\alpha\ell+\beta\ell_j$，$a'=\alpha a+\beta a_j$；
  - 处理完 CPU 历史后再以因果掩码处理 GPU 上的 Active Tail 与 Speculative Frontier，最终输出 $O=a/\ell$。
  - 由于分子分母使用同一组缩放因子，分块归约在实数域等价于一次性全历史 softmax，仅改变浮点累加顺序。
- **流水线化传输**：双暂存缓冲 + 独立拷贝/计算流实现传输与计算重叠；相邻块合并为传输批以摊销拷贝提交、同步与内核启动开销；当前层释放缓冲后预取下一层历史，与当前层剩余注意力、输出投影和前馈重叠。
- **Cohort 批处理**：把调度批次内"同层、同验证宽度、同数据类型、同 KV 头数与头维度、同 chunk 大小"的任务合并为同一批处理核；各请求保留独立 KV 索引、绝对位置与在线 softmax 状态，从而提升内核并行度并摊销准备/同步/启动成本。
- **I/O 感知的动态验证宽度**：以估计的"每有效输出 token 时间"选择 $q^*=\arg\min_{q\in Q}\big(\hat T_{round}(q)/\hat U(q)\big)$，候选集合为 $\{2,4,6,8\}$；利用历史传输、验证、Draft 生成与拒绝纠正成本估计，记录不足时先做有限采样，且仅当收益超过切换阈值才改变宽度以抑制频繁抖动。
