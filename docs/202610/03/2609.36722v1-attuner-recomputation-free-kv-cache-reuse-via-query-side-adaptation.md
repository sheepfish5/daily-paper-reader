## 摘要
大型语言模型（LLM）智能体会反复将可复用内容（如技能、文档和记忆条目）加载到当前上下文中。为每个请求重新编码这些内容会浪费计算。位置无关缓存（PIC）通过独立编码每个制品并在任意位置复用其键值（KV）状态来缓解这一问题，但与完整上下文预填充相比会带来质量损失。现有方法通过恢复全局位置 ID 或重新计算选定的 token 来弥补这一损失。在本工作中，我们分离出损失的来源，发现位置不匹配的影响较小，且独立缓存的制品保留了忠实的表示：读取给定制品时基本保持准确，只有当模型必须在多个制品之间进行选择时性能才会下降。此外，在缓存 KV 不变的情况下，将 PIC 的注意力分数替换为完整预填充的分数即可恢复性能，从而将失败定位到注意力而非 KV 重计算。受此启发，我们提出 Attuner，一种学习读取冻结制品缓存的查询侧适配方法。Attuner 在查询投影中插入低秩适配器，并通过将完整预填充的分布蒸馏到学生模型中进行训练。它训练少于 0.05% 的模型参数，并且在推理时既不需要缓存重计算，也不需要完整上下文参考。在 Qwen3-4B 和 Qwen3-8B 上，涵盖技能、文档、记忆和代码的七个基准中，Attuner 在域内和域外设置下均显著优于先前的 PIC 基线，达到与完整上下文预填充相当的质量，同时提供高达 3.73 倍的加速。

## Abstract
Large language model (LLM) agents repeatedly load reusable content, such as skills, documents, and memory entries, into the current context. Re-encoding this content for every request wastes computation. Position-independent caching (PIC) alleviates this by encoding each artifact independently and reusing its key-value (KV) states at arbitrary positions, but it incurs a quality loss relative to full-context prefill. Existing methods repair this loss by restoring global position IDs or recomputing selected tokens. In this work, we isolate the source of the loss, finding that the positional mismatch has minor effect, and independently cached artifacts retain faithful representations: reading a provided artifact stays largely accurate, and performance degrades only when the model must select among multiple artifacts. Moreover, replacing PIC's attention scores with full-prefill scores recovers performance with the cached KV unchanged, localizing the failure to the attention rather than KV recomputation. Motivated by this, we propose \textsc{Attuner}, a query-side adaptation method that learns to read a frozen artifact cache. \textsc{Attuner} inserts low-rank adapters into the query projections and is trained by distilling full-prefill distribution into the student. It trains fewer than 0.05\% of the model parameters and, at inference, requires neither cache recomputation nor a full-context reference. On Qwen3-4B and Qwen3-8B across seven benchmarks covering skills, documents, memory, and code, \textsc{Attuner} substantially outperforms prior PIC baselines in both in-domain and out-of-domain settings, matches full-context prefill quality while providing up to $3.73\times$ speedup.

# ATTUNER 论文深度总结

## 1. 核心问题与研究动机

- **背景**：LLM 智能体在运行时会反复加载可复用内容（技能描述、文档、记忆条目等，统称"制品 artifact"）到当前上下文中。为每个请求重新编码这些制品会造成大量重复计算，并显著抬高首 token 延迟（TTFT）。
- **现有方案及其瓶颈**：
  - 传统前缀缓存（RadixAttention、Prompt Cache）要求可复用内容在请求间占据相同前缀位置，而智能体工作负载中制品的种类、顺序、位置均由检索/路由/规划动态决定，该假设难以成立。
  - 位置无关缓存（PIC）通过独立编码每个制品并复用其 KV 状态解决位置依赖问题，但相比完整上下文预填充（Full prefill）存在明显质量损失。
  - 已有修复方法分为两类：**推理时修复**（恢复全局位置 ID、重计算选定 token，如 CacheBlend、EPIC、AgentKVShift、CacheSlide）和**缓存侧训练**（修改编码器、链接 token 或缓存表示，如 KVLink、COMB）。
- **核心洞察（本文的出发点）**：作者通过控制实验分离 PIC 质量损失的来源，发现：
  1. **位置不匹配影响很小**：PIC-Pos（按目标位置独立编码）在多制品任务上仅带来边际变化。
  2. **缓存表示本身是忠实的**：单制品场景下"证据利用"能力损失很小，说明独立缓存的 KV 仍能忠实保留制品内容；性能下降主要出现在需要**在多个制品间选择**（artifact discovery）的多制品场景。
  3. **失败在注意力而非 KV**：在保持 PIC 缓存 KV 不变的前提下，将注意力分数替换为全预填充的分数（路由 oracle），任务性能即可恢复（如 MuSiQue EM 从 34.84 恢复到 47.91，接近 Full 的 47.79；BigCodeBench pass@1 从 38.98 恢复到 44.53，接近 Full 的 43.63）。
- **整体含义**：质量损失定位在"如何读取缓存"（注意力路由）而非"缓存中存了什么"，从而开辟了一条**不改写缓存、不重计算、只适配查询侧**的免重计算复用路径。

## 2. 方法论

### 2.1 核心思想
- 保持制品 KV 缓存**完全冻结、原样复用**（由未适配的基座模型离线构建），仅让**在线 token 的查询投影**学习如何正确读取这些缓存。
- 通过**全上下文教师的输出分布蒸馏**，让 PIC 学生学会在固定缓存上进行有效的注意力路由。

### 2.2 关键技术细节
- **查询侧低秩适配（Query-Side LoRA）**：在每一层 Transformer 的冻结查询投影上叠加低秩更新：
  - \(\tilde{q}_{\ell,t} = W_Q^\ell h_{\ell,t} + \frac{\alpha}{r} B_\ell A_\ell h_{\ell,t}\)
  - 其中 \(A_\ell \in \mathbb{R}^{r \times d_{model}}\)、\(B_\ell \in \mathbb{R}^{d_q \times r}\) 为可训练矩阵，\(r\) 为秩，\(\alpha\) 控制更新尺度。
  - 适配后的查询随后经过模型原有的查询归一化与 RoPE，再进入注意力计算。
  - 初始化：\(A_\ell\) 用 Kaiming 均匀初始化，\(B_\ell\) 置零（初始更新为零），仅训练 \(A_\ell, B_\ell\)，基座模型全部冻结。
  - 适配器**仅对未缓存 prompt token 和生成 token 启用**，缓存制品的 KV 保持不变；在线状态及其新产生的 KV 在适配后的计算下继续演化。
- **为什么查询侧适配能保留缓存复用**：查询是运行时为在线 token 计算的，而缓存中的 K/V 无需任何改动即可直接复用，因此适配不会破坏缓存的构造与复用。
- **训练目标（全上下文分布蒸馏）**：冻结的 Full-context 教师与学生接收相同输入、条件于相同响应前缀，最小化响应位置上的 KL 散度：
  - \(L(\phi) = \mathbb{E}_{(X,Y)\sim D_T}\left[\frac{1}{|Y|}\sum_{t=1}^{|Y|} D_{KL}\left(sg\left[p_\theta^{Full}(\cdot|X,Y_{<t})\right] \,\|\, p_{\theta,\phi}^{PIC}(\cdot|X,Y_{<t})\right)\right]\)
  - 其中 \(\phi=\{A_\ell,B_\ell\}\) 为适配器参数，\(sg\) 停止教师梯度；仅监督输出分布（不直接监督注意力权重），prompt 位置不计入损失，每个请求等权。
- **部署**：训练完成后适配器可合并进查询投影 \(W_Q^\ell \leftarrow W_Q^\ell + (\alpha/r)B_\ell A_\ell\)，推理时既不需要 Full-context 教师，也不需要缓存重建。

## 6. 主要结论与发现

- **损失来源定位**：PIC 质量损失主要来自注意力路由（如何读取缓存），而非缓存 KV 表示本身；位置对齐不能一致地缩小差距。
- **恢复路径有效**：在缓存 KV 不变的前提下恢复 Full 路由，可将任务性能恢复到接近 Full 水平（MuSiQue EM 34.84→47.91，BigCodeBench pass@1 38.98→44.53）。
- **ATTUNER 效果**：
  - 域内平均分相比 PIC 提升 **5.13 分（Qwen3-4B）** 和 **7.77 分（Qwen3-8B）**，与 Full 的差距缩小到 1.61 和 0.51 分。
  - 域外任务（TheoremQA、CHAMP，未参与训练）平均分相比 PIC 提升 3.02 和 3.51 分，显示可迁移性。
  - 达到与 Full prefill 相当的质量，同时保留 1.79×（4B）和 2.45×（8B）的域内几何平均加速；TTFT 相比 PIC 仅增加 1.8% 和 0.5%。
  - 训练参数少于模型总参数的 **0.05%**。
- **消融发现**：
  - 训练数据越多，恢复越充分（MuSiQue 1,024 例即从 48.70 提升到 56.40，8,192 例达 61.15，匹配 Full 的 61.01）。
  - 只适配一半层（L16–33 或 L18–35）也能大幅恢复（F1 65.14 / 63.34 vs PIC 49.00），无需逐层复现 Full 计算。
  - 同一适配器在 PIC 下的增益（域内平均 +5.13）远大于在 Full 下的增益（+0.17），说明提升主要来自"适配独立缓存读取"而非通用任务能力提升。
  - 注意力输出对齐在中间层改善（MuSiQue 0.903→0.927，BigCodeBench 0.932→0.949），但末层反而变差，说明恢复不要求逐层精确复现 Full。

## 7. 优点

- **问题定位精准**：通过精心设计的对照实验（单/多制品、位置对齐、路由 oracle、组件替换）层层剥离损失来源，把"缓存表示问题"与"注意力读取问题"清晰区分，结论有说服力。
- **方法简洁且部署友好**：仅训练查询投影的低秩适配器，参数量 <0.05%；推理时适配器可合并进权重，既不需要教师模型，也不需要重计算或缓存重建，与现有 PIC 服务栈兼容。
- **效率与质量兼顾**：在匹配 Full 质量的同时保持近 PIC 的 TTFT，明显优于所有免训练修复基线的质量-延迟权衡，且 TTFT 显著低于质量相当的 KVLink（不到其一半）。
- **泛化性验证**：单一适配器跨技能、文档、记忆、代码四类制品共享，且在未参与训练的域外任务上仍有提升。
- **分析层次丰富**：除任务指标外，还提供表示级证据（注意力输出余弦相似度、输出 KL、逐请求恢复图），并诚实报告末层对齐变差等反例。

## 8. 不足与局限

- **场景覆盖

- **场景覆盖**：评测集中在技能、文档、记忆、代码四类制品，且每请求制品数量有限（2–8 个）；未覆盖多模态制品、工具调用轨迹、长链推理中间状态、跨会话长期记忆、数百级制品库检索等更复杂的智能体场景，也未评估制品顺序高度动态变化、制品频繁增删改或缓存命中率波动较大的情况。
- **训练数据与教师依赖**：虽然部署时不需要教师，但训练阶段仍需 Full-context 教师对 12K 请求逐 token 前向并产出分布，且训练样本需与目标制品类型有一定匹配；论文虽验证了域外任务的可迁移性，但未系统分析训练分布与目标分布偏移到何种程度时适配会失效。
- **算力披露不足**：如第 4 节所述，GPU 型号、数量、训练时长、教师前向开销均未量化，难以评估训练成本、碳足迹与在更大模型上的可扩展性；论文也未讨论当基座模型从 4B/8B 扩展到 70B 或 MoE 架构时，查询侧低秩适配是否仍以同等比例参数生效。
- **系统层面评估缺失**：TTFT 在 batch size 1、无并发、单 GPU 同步计时的理想条件下测量，未覆盖真实服务中的连续批处理、动态请求到达、缓存换入换出、显存压力与吞吐-延迟权衡；适配器合并后对量化推理、KV 缓存分页（如 PagedAttention）的兼容性也未验证。
- **适配器设计空间未充分探索**：仅适配 q_proj 的 LoRA，未系统对比适配 k_proj/o_proj、MLP 层、更高秩、不同 α/r 组合或按层自适应分配秩的方案；层范围消融只对比了两个半层区间，未回答“最少需要适配多少层”这一部署关键问题。
- **缓存来源假设较强**：方法默认制品 KV 由未适配的同一基座模型离线构建且保持逐 token 对齐；若缓存来自量化模型、不同版本模型、蒸馏模型或经过压缩/合并的 KV，查询侧适配能否补偿表示差异尚无证据。
- **基线公平性仍有残留问题**：AgentKVShift 为论文重实现，CacheBlend/APE 经过 Qwen3 适配，KVLink/COMB 虽共享训练样本数与更新次数，但可训练参数量与每步计算量不同；论文虽已声明，读者仍不宜把这些数字直接当作原系统的服务性能。
- **潜在风险与失败模式**：查询侧适配会改变在线 token 的注意力分布，进而改变其新生成 KV 的分布，可能对超长生成、多轮自回归累积误差或需要严格位置推理的任务产生未测影响；论文的注意力输出对齐分析也显示末层对齐反而变差，说明“分布蒸馏成功”与“逐层注意力复现”之间并非单调关系。
- **评测指标维度有限**：主要报告任务准确率/F1/EM 与 TTFT，缺少吞吐、显存占用、缓存命中率、端到端延迟分布（P50/P99）、成本归一化质量等系统级指标，也未报告多次运行的方差或统计显著性检验（仅部分诊断给出配对 bootstrap 区间）。

## 9. 总体评价与启示

ATTUNER 的核心贡献不在于提出一个更复杂的缓存修复算法，而在于**把 PIC 质量损失归因问题讲清楚**：通过单/多制品对照、位置对齐、路由 oracle 与组件替换四层诊断，将“缓存里存了什么”与“如何读取缓存”解耦，并证明后者才是主要瓶颈。基于这一洞察，论文给出了一条极简的工程路径——冻结缓存、只训练查询侧低秩适配器、用全上下文教师做输出分布蒸馏——在质量上逼近 Full prefill，在延迟上保持接近 PIC，且训练参数不足模型总参数的 0.05%，部署时可合并进权重，不需要教师、不需要重计算、不需要缓存重建。

从更广的视角看，这项工作提示：**位置无关缓存的可用性上限可能不由缓存表示精度决定，而由查询侧的路由能力决定**；未来若能把查询侧适配与更激进的缓存压缩、跨模型缓存共享、动态制品库检索结合，或许能在不牺牲质量的前提下进一步压低智能体推理成本。同时，论文在算力披露、系统级评测、适配器设计空间与缓存来源鲁棒性上的空白，也为后续工作留下了明确的验证清单。
