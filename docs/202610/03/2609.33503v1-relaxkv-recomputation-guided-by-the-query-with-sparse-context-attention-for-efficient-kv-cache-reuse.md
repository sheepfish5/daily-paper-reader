## 摘要
跨请求 KV 缓存降低了检索增强生成（RAG）的预填充成本，但传统前缀缓存严重限制了跨请求的缓存复用。位置无关缓存（PIC）通过复用独立块消除了这一限制，但其 KV 状态缺失跨块交互。现有方法通过选择性重计算 token 状态来恢复这些缺失的交互，但主要将重计算预算用于选择要重计算哪些状态，而将重计算上下文固定为完整因果前缀。我们提出 RelaxKV，其将选择性缓存修复建模为对修复目标和重计算上下文的联合分配问题。在用户查询引导下，RelaxKV 识别层特定的修复目标，并将其重计算限制在与查询相关的上下文中，从而减少注意力计算。在四个解码器模型上，15% 锚点比例下的 RelaxKV 在所有模型上相比 ProphetKV 提升了 LongBench 的总体性能。在 Qwen3-14B 上，在 5%-30% 锚点比例扫描中，RelaxKV 相比 ProphetKV 提供了更强的质量-TTFT 权衡，并在 16K 和 32K 上下文长度下于 RULER-MV 和 LV-Eval 上取得了最佳选择性结果。受控消融进一步证明了重计算上下文选择的重要性。

## Abstract
Cross-request KV caching reduces the prefill cost of Retrieval-Augmented Generation (RAG), but conventional prefix caching severely limits cache reuse across requests. Position-Independent Caching (PIC) removes this constraint by reusing independent chunks, but their KV states miss cross-chunk interactions. Existing methods selectively recompute token states to recover these missing interactions, but primarily allocate the recomputation budget to selecting which states to recompute, while fixing the recomputation context to the full causal prefix. We introduce RelaxKV, which formulates selective cache repair as a joint allocation problem over repair targets and recomputation context. Guided by the user query, RelaxKV identifies layer-specific repair targets and restricts their recomputation to a query-relevant context, reducing attention computation. Across four decoder models, RelaxKV at a 15% anchor ratio improves aggregate LongBench performance over ProphetKV on all models. On Qwen3-14B, RelaxKV provides a stronger quality-TTFT trade-off than ProphetKV across a 5%-30% anchor-ratio sweep, and achieves the best selective results on RULER-MV and LV-Eval at 16K and 32K context lengths. Controlled ablations further demonstrate the importance of recomputation context selection.

# RelaxKV 论文深度解读

## 1. 核心问题与研究动机

- **背景**：检索增强生成（RAG）中，不同请求常检索到重叠的文档块，跨请求复用 KV 缓存可显著降低 prefill（预填充）开销。
- **痛点一**：传统前缀缓存（prefix caching）仅在请求共享相同前缀时可复用，跨请求复用受限。
- **痛点二**：位置无关缓存（PIC）将上下文切分为独立块并分别预计算，从而解除前缀限制，但各块的 KV 状态在独立编码时**缺失跨块交互**，直接拼接得到的 `K_naive ≠ K_full`，引入近似误差。
- **现有修复方法的局限**：CacheBlend、EPIC、KVShare、ProphetKV 等选择性缓存修复方法，其预算**只用于选择"重计算哪些 token 状态"**，而一旦选中，该 token 在重算时仍要 attend 到**完整因果前缀**。于是即便目标集很小，注意力计算量依然庞大。
- **核心洞察**：选择性缓存修复实际上存在**两个可独立优化的维度**——(a) 修复目标选择（决定重算哪些状态）；(b) 重计算上下文选择（决定重算时能读到哪些 KV 列）。现有工作只优化了前者。
- **整体含义**：RelaxKV 将缓存修复重新建模为**修复目标 × 重计算上下文的联合分配问题**，由用户查询引导，同时压缩"重算的行"与"读取的列"，从而在质量—延迟权衡上取得更优解。

## 2. 方法论

### 2.1 核心思想
- 用**用户查询对可复用缓存的注意力**作为信号，在**每一层独立**挑选修复锚点；深层被选中的 token 必须"回填"前序层才能到达该层，由此导出**层特定的活跃修复目标**；所有层锚点的**并集**构成**共享的、查询相关的重计算上下文**。
- 每层只有活跃目标执行 Transformer 块，且只 attend 到该上下文中的因果合法位置，KV 更新集合由 `R_l` 直接确定，无需额外选择步骤。

### 2.2 关键技术细节与公式

**(1) 逐层查询注意力打分**：对层 `l`、上下文位置 `i`，在头和查询位置上取平均并做 Min-Max 归一化：
`a_{l,i} = MinMax( (1/(H_Q)) Σ_h Σ_t A_l[h,t,i] )`

**(2) 逐层锚点选择**：每层独立取 Top-k，`k = max(1, round(r·T_c))`，其中 `r` 为锚点比例、`T_c` 为上下文 token 数；得到 `S_l`（修复锚点集合）。

**(3) 依赖闭包与活跃目标**：对每个 token 定义其最高被选层 `h_i = max{l : i ∈ S_l}`；定义并集 `U = ∪_l S_l`；活跃修复目标 `R_l = {i ∈ U : h_i ≥ l}`。即 token 一路活跃到其最高选中层，之后退出活跃集。

**(4) 因果重计算上下文**：对位置 `p` 的活跃目标，`C_l(p) = U ∩ {j : j ≤ p}`。即只读取并集中的因果前置位置，而非完整因果前缀。

**(5) 混合 KV 更新语义**：重算时对上下文位置 `j ∈ C_l(p)`，
- 若 `j ∈ R_l ∩ C_l(p)` → 使用新算的 `(K^new, V^new)`；
- 若 `j ∈ C_l(p) \ R_l` → 复用 `(K^naive, V^naive)`。
重算产生的新 KV 覆写对应缓存条目，其余条目保留原值；位置 ID 保持不变，因此 RoPE 的相对偏移不受影响。

**(6) 算法流程**（Algorithm 1 概要）：
1. 用 `q` 跑一遍 `K_naive`，得到逐层分数 `a_{l,i}`；
2. 每层 Top-k 得到 `S_l`，计算 `U` 与各 token 的 `h_i`，导出 `R_l`；
3. 逐层：对 `R_l` 计算 Q/K/V → gather 并集中缓存 KV → 用新算 KV 替换 `R_l` 中的条目 → 因果注意力限制在 `C_l(p)` → 走原样的输出投影、残差、归一化与 MLP → 更新缓存；
4. 返回修复后的缓存。

**(7) 成本刻画**：注意力上下文暴露用因果注意力边数 `E_unmasked(R,C) = Σ_l Σ_{p∈R_l} |C_l(p)|` 度量；投影/MLP 工作量正比于 `Σ_l |R_l|`。注意名义锚点比例 ≠ 实际上下文比例 ≠ 活跃目标比例。

### 2.3 关键对照设计
- **RelaxKV G**（匹配目标诊断对照）：保留 ProphetKV 的全局修复目标 `P` 与缓存更新掩码，**只替换重计算上下文**为 RelaxKV 的 `C_l(p)`，用于隔离上下文选择的作用。
- **Full-Prefix Control**：相同活跃目标，但重算时使用完整因果前缀，用于隔离上下文限制的质量—成本影响。

## 6. 主要结论与发现

1. **质量上不劣于甚至优于最强基线**：15% 锚点比例下，RelaxKV 在四个模型上的 LongBench 聚合分数均超过 ProphetKV，且接近 Full Recompute 参考。
2. **长上下文优势更明显**：Qwen3-14B 在 RULER-MV 32K 上达 95.00（ProphetKV 91.17，RelaxKV G 92.00）；LV-Eval 16K/32K 上 token F1 为 28.71/25.40，优于 ProphetKV 的 24.78/19.32，为最佳选择性结果。
3. **上下文选择本身即有效**：在固定 ProphetKV 目标时，仅替换重计算上下文（RelaxKV G）仍能保持与 ProphetKV 相近的聚合质量，说明上下文限制不会损害质量。
4. **上下文构造是关键设计变量**：在锚点、活跃目标、名义上下文规模都固定时，Global Sparse / Layerwise Sparse / RelaxKV 三者重算延迟相近，但任务质量差异显著——"保留哪些 KV 位置"本身就是重要设计选择。
5. **查询相关的稀疏上下文具有隐式去噪/过滤效应**：上下文越长、干扰越多，把重算限制在查询相关上下文越能保住质量。
6. **限制上下文能带来直接成本收益**：在相同活跃目标下，RelaxKV 相比 Full-Prefix Control 降低平均重算延迟 9.9%–23.2%，质量差距仅 0.45–1.00 分。
7. **扩大全局修复目标收益有限**：Llama-3.1-8B 上把全局目标比例从 20% 提到 Target-Union，RULER-MV TTFT 从 361.58 ms 涨到 914.47 ms（2.53×），而 LongBench 平均分仅从 57.84 变到 58.10，且非单调——说明单纯增加目标数量并不能替代层特定修复调度。
8. **chunk size 影响**：所有复用类方法随 chunk 增大而改善（大块保留更多块内交互），RelaxKV 在各档 chunk 下均为最优或接近最优。

## 7. 优点

- **问题建模有洞察力**：把选择性缓存修复从"一维目标选择"扩展为"目标 × 上下文"的**二维联合分配**，视角新颖，且抓住了现有方法普遍忽视的注意力列维度。
- **方法简洁、即插即用**：不修改模型权重、不改动缓存构造，仅做在线选择性重算，工程可落地性强；算法步骤清晰（Algorithm 1 完整可复现）。
- **诊断性实验设计扎实**：RelaxKV G（匹配目标对照）与 Full-Prefix Control 分别隔离了"上下文选择"和"上下文限制"的贡献，消融逻辑严密；对名义比例 vs 实际计算量的区别有明确交代。
- **评估协议规范**：统一 prompt、分词、权重、chunk 与样本，剔除检索延迟，采用实测 TTFT 而非理论 FLOP 作为效率指标。
- **长上下文收益一致性**：随上下文变长优势扩大，且跨 4 个模型均能维持，泛化性较好。

## 8. 不足与局限

- **模型覆盖不均衡**：长上下文核心结论（RULER-MV 4K–32K、LV-Eval、预算核算、上下文消融）几乎全部基于 Qwen3-14B，跨模型的长上下文验证不足。
- **名义比例不可比带来的公平性风险**：RelaxKV 用 15% 锚点、基线用 20% 修复比例，但锚点在深层会触发前序层回填，实际活跃目标与上下文并集比例可达 40%–80%（如 Qwen3-14B 在 8K RULER-MV 上并集 63.05%、活跃目标 42.85%），因此"15% vs 20%"并非等价计算量比较，容易误读效率优势。
- **效率度量的近似性**：作者自承 `E_unmasked` 只是结构指标而非精确 FLOP（GQA 需把 KV 头展开，因果掩码条目仍可能产生 kernel 开销），故只能依赖实测延迟。
- **缓存修复的近似性未消解**：重算过程中使用"新算 + 缓存"混合 KV，且已退出活跃集的 token 在更深层仍以 naive KV 参与后续重算，这是 RelaxKV 的固有近似；论文未给出该近似的误差界或理论分析。
- **依赖 RoPE 位置对齐这一前提**：文中假设缓存块可用最终全局位置 ID 预计算、且重定位后可通过旋转恒等对齐，该前提对非 RoPE 或位置编码不同的模型适用性未知。
- **TTFT 协议偏理想**：batch size 1、单条请求、缓存常驻 GPU、预热后测三次，未涉及批处理、并发、显存压力等真实服务场景；跨请求复用率、缓存淘汰等系统层面问题未讨论。
