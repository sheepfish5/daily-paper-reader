## 摘要
生产环境中的LLM服务栈将推理引擎的本地前缀缓存与共享KV缓存层结合，以实现全集群范围的复用。本地缓存按适配器、权重配置和共享域区分请求，但共享层可能仅以token内容和粗粒度模型元数据作为条目键。这一边界抹除了溯源信息，并让相同token在不兼容的计算或共享上下文中发生碰撞。我们将这一组合缺口称为溯源盲复用，并首次对其进行系统研究。对三个vLLM连接器的源码审计证实了这种结构性遗漏，而运行时实验在vLLM和两个SGLang版本、来自7个系列的12个模型（0.5B-32B）以及160多种配置上复现了该问题。跨适配器碰撞将准确率从0.94降至0.64，不兼容的KV表示使推理准确率降至零，盐值省略则使93%的提示可通过时序识别。我们将缺失的保证形式化为KV溯源契约：对于声明的维度注册表，共享键必须在计算溯源和共享溯源上单射，且标识跨工作进程稳定。因此，任何具有稳定标识的维度都可以添加，而无需连接器特定的键逻辑。规范描述符将每请求和每工作进程的溯源信息绑定到查找键和存储键中，而差分检查器检测那些改变KV状态但不改变键的维度。在vLLM和SGLang 0.5.20中跨三条缓存路径实现后，溯源绑定消除了不安全复用，同时保留了合法共享。命中路径延迟变化保持在0.34 ms以内，且低于运行间波动；保留量随溯源多样性增长。

## Abstract
Production LLM serving stacks combine an inference engine's local prefix cache with a shared KV-cache tier for fleet-wide reuse. The local cache distinguishes requests by adapter, weight configuration and sharing domain, but the shared tier may key entries only by token content and coarse model metadata. This boundary erases provenance and lets identical tokens under incompatible computational or sharing contexts collide. We call this composition gap provenance-blind reuse and present its first systematic study. A source audit of three vLLM connectors confirms the structural omission, while runtime experiments reproduce it across vLLM and two SGLang releases, 12 models from 7 families (0.5 B-32 B), and over 160 configurations. Cross-adapter collisions reduce accuracy from 0.94 to 0.64, incompatible KV representations reduce reasoning accuracy to zero, and salt omission enables 93% prompt identification from timing. We formalize the missing guarantee as the KV provenance contract: for a declared dimension registry, shared keys must be injective over computational and sharing provenance, with identities stable across workers. Any dimension with a stable identity can therefore be added without connector-specific key logic. A canonical descriptor binds per-request and per-worker provenance into lookup and store keys, while a differential checker detects dimensions that change KV state without changing the key. Implemented in vLLM and SGLang 0.5.20 across three cache paths, provenance binding eliminates unsafe reuse while preserving legitimate sharing. Hit-path latency changes remain within 0.34 ms and below run-to-run variation; retention grows with provenance diversity.

# 论文总结：Preserving Provenance in Shared KV Caches for LLM Serving

## 1. 论文的核心问题与整体含义

- **研究背景**：生产级 LLM 服务栈普遍采用两层 KV 缓存复用架构：
  - **本地前缀缓存**（vLLM 的 PagedAttention 块哈希、SGLang 的基数树）：按请求的完整服务上下文（适配器、权重配置、共享域盐值）区分请求，仅限单 worker 内复用。
  - **共享 KV 缓存层**（LMCache、Mooncake、vLLM SharedStorageConnector、SGLang HiCache）：跨 worker 复用已计算的 KV 状态，键仅由 token 内容和粗粒度模型元数据派生。

- **核心问题——溯源盲复用（provenance-blind reuse）**：
  - 本地缓存能区分的请求，在共享层可能因 token 相同而碰撞。
  - 引擎与连接器在"等价性"定义上不一致：引擎按请求上下文区分，连接器仅按 token 和模型元数据等价。
  - 共享键相等既不能推出计算等价，也不能推出共享许可。
  - 论文将此前零散报告为独立 bug 的问题（适配器冲突、精度、版本、KV 表示、租户盐）统一为一个**引擎—连接器边界上的缺失接口契约**。

- **整体含义**：
  - 该问题不是某个连接器的缺陷，而是**内容寻址缓存的固有结构性缺陷**（源码审计三个独立实现的 vLLM 连接器，键派生方式一致）。
  - 带来两类后果：**完整性/可用性失效**（无对手即可发生）与**机密性泄漏**（跨实例时序侧信道）。
  - 论文首次系统研究该组合缺口，并提出形式化契约与实现方案。

## 2. 论文提出的方法论

- **核心思想**：将缺失的保证形式化为 **KV 溯源契约 C(D)**——对声明的维度注册表 D，共享键必须在计算溯源和共享溯源上单射。

- **两个不变量（公式说明）**：
  - **计算不变量**：若两配置产生不同 KV 状态，则派生不同键：
    - `KV(x, c1) ≠ KV(x, c2) ⟹ Key(x, c1) ≠ Key(x, c2)`
  - **许可不变量**：若两配置不允许共享，则派生不同键：
    - `¬ShareAllowed(c1, c2) ⟹ Key(x, c1) ≠ Key(x, c2)`
  - 契约对 D 参数化：任何具有**单射且跨 worker 稳定标识**的维度都可扩展，无需修改连接器键逻辑（命题 1 给出证明思路）。

- **规范实现**：
  - 使用**长度前缀编码器 enc** + 抗碰撞哈希 H，共享键为：`Key(x, c) = f(x, H(enc(id1(c(d1)), …, idn(c(dn)))))`，f 为连接器原生键函数。
  - **两个生命周期层次**：
    - **每请求字段**：适配器身份（vLLM 用适配器名；SGLang 用适配器内容指纹——张量名/dtype/形状/字节+语义配置字段）、租户盐值。
    - **每 worker 字段**：权重精度、权重版本、KV 表示（读**解析后的实际值**而非启动字符串，因 `auto` dtype 可能解析不同）。
  - **跨站点一致性**：调度器（lookup）与 worker（store）必须使用同一描述符，否则单点注入会静默破坏同源复用。
  - **连接器集成**：连接器只消费描述符的规范摘要而非字段值；LMCache 打包进 150 字节字段（用 22 字符 base64 编码 128 位摘要 + 模型身份固定长度哈希，代表键 89 字符）；SGLang HiCache 替换单一命名空间种子即可覆盖 lookup/write/promotion/restart 四条链。

- **差分遗漏测试**：
  - 固定 token 与其他维度，仅变化维度 di，若 `KV(x,c) ≠ KV(x,c[di↦v'])` 且 `Key(x,c) = Key(x,c[di↦v'])`，则报告该维度被遗漏。
  - 离线形式在 CPU float32 上逐层比较真实注意力状态；在线形式比较两 worker 写入共享存储的页面字节。

## 6. 论文的主要结论与发现

- **跨源复用确实发生**：在共享键遗漏的每个维度上都复现，且贯穿 0.5B–32B 全尺寸。
- **正确性影响分三个严重等级**：
  - **权重精度**：改变输出文本但不显著降低准确率（意外结果）。
  - **适配器身份与权重版本**：统计显著、任务与模型相关的损害。跨适配器使准确率从 0.94 降至 0.64（100 条短评），IMDB 上 0.945→0.715（28.5% 被重新标注为播种方策略，p<10⁻⁹）；权重版本在 0.5B 上损失 14.3 个百分点，32B 上衰减至不显著（p=0.39）。
  - **KV 表示**：情感准确率降至约 0.47，推理准确率**归零**；KV dtype 不匹配为加载失败（活性失效）。
- **因果性**：剂量—响应显示缓存状态本身是直接原因；低于一个 chunk 的前缀不碰撞，达到或超过即碰撞，生产共享前缀（数百 token）必然触发。
- **部署发生率**：上界 83.5%，交错流下界 1.5%；负载均衡 4 worker fleet 约 10%，sticky 路由几乎为 0；前缀多样性升高时负载均衡率升至 16%。
- **机密性**：共享层丢弃盐值使引擎本地隔离失效，远程攻击者仅凭 TTFT 对 N=10 完全识别、N=100 达 93%。
- **绑定效果**：五个维度全部消除不安全复用（跨配置外来 token 降为 0），保留同源共享（624/768 token 全前缀命中）；命中延迟变化 ≤0.34 ms，低于运行间波动；存储随溯源多样性线性增长；固定预算下绑定会增加驱逐压力（TTFT 0.024→0.065 s，吞吐 42→15 req/s）。

## 7. 优点

- **问题识别系统且统一**：将此前零散 bug 归因为单一接口契约缺失，并给出形式化定义（Definition 1、2）。
- **形式化 + 可测试性**：契约参数化、可扩展（命题 1），差分遗漏测试使"遗漏绑定"可被直接证伪。
- **跨引擎跨版本实现验证**：vLLM 与 SGLang、三条缓存路径、两版本，证明非单实现缺陷。
- **严谨的实验设计**：配对矩阵、独立进程隔离、反平衡、McNemar 检验、剂量—响应因果分析、位置控制。

- **安全与正确性双视角**：同时刻画完整性与机密性后果。
- **开销可忽略**：请求级摘要 12.7 μs，相对存储往返数十毫秒可忽略。

## 8. 不足与局限

- **实验覆盖**：
  - 发生率为受控构造上界/下界，非真实生产 trace 推导（trace 缺溯源标签）。
  - 吞吐、驱逐实验仅在 vLLM 0.9.2 测量。
  - 仅单主机 worker + 独立缓存服务器，未验证多主机 fleet。
  - 差分检查器是**验证工具而非发现工具**：只能评估已声明的候选维度，不能发现未枚举的配置空间（如论文自身在离线检查中故意保留的 rotary base）。
- **泛化性约束**：
  - 跨版本复用依赖架构兼容（缓存张量需适配检索方），且版本需在缓存前缀答案上分歧才显现损害；一致版本不显害。
  - 每维度身份选择影响正确性，需由差分检查器对精确 KV 状态验证。
- **偏差风险**：
  - 任务选择影响结论（GSM8K 短问题约 70 token，损害不显著；长文档/含判别内容前缀才显害）。
  - 精度维度在测试负载上无显著准确率损失，可能掩盖某些场景风险。
  - SGLang 0.5.20 已部分缓解适配器（uuid handle），但"名字+路径"句柄对字节替换盲目，且过度分离。
- **应用限制**：
  - 绑定后存储随溯源多样性线性增长，固定预算下会引发 thrashing，需按预期多样性扩容。
  - 需修改引擎请求记录与连接器键逻辑，存在部署改造成本。
  - 哈希身份仅近似理想契约（碰撞概率忽略不计）。
- **未量化项**：训练/适配器微调算力、多主机网络开销、长期运行的存储成本曲线。
