## 摘要
动态层跳过通过允许每个 token 仅执行模型层的一个子集来减少 LLM 计算量。然而，现有跳层器依赖专门的生成循环，无法与现代服务引擎集成。因此，执行更少的层并不一定能转化为更低的服务延迟：FlexiDepth 在 Llama-3-8B 的 32 层中平均跳过 8 层，但其标准生成循环的解码速度却比基础模型慢 14.6--21.0%。我们提出 vSkipper，这是一个虚拟化层，使动态跳层器能够以可插拔方式接入服务引擎，同时保留连续批处理、固定形状批次、分页 KV 缓存和已捕获的解码图。在每个路由层，vSkipper 根据跳层器的决策对 token 分组，并且仅在预测有利时才使用路由执行。我们在 SGLang 中实现了 vSkipper，并在相同提示、到达模式、输出长度和启动设置下，将发布的 FlexiDepth 检查点与上游 SGLang 进行评估。在上游负载曲线的拐点处，vSkipper 将 GSM8K 上的平均端到端延迟降低 36.8%，将 BBH 上的平均端到端延迟降低 13.6%。在饱和状态下，它将请求吞吐量分别提升 11.3% 和 7.4%。与检查点自身的质量损失相比，服务过程未增加统计上可分辨的质量损失。在合成跳过策略、两个 Qwen3 跳层器和三种 GPU 上，我们展示了无需针对特定工作负载调优即可复用。据我们所知，vSkipper 是首个在现代 LLM 服务引擎中通过逐 token 内部层跳过实现服务效率增益的系统。代码作为 SGLang 分支在 https://github.com/AKafakA/sglang-vskipper/tree/vskipper-ref 开源。

## Abstract
Dynamic layer skipping reduces LLM computation by allowing each token to execute only a subset of the model's layers. However, existing skippers rely on specialized generation loops and do not integrate with modern serving engines. As a result, fewer executed layers do not necessarily translate into lower serving latency: FlexiDepth skips 8 of Llama-3-8B's 32 layers on average, yet its standard generation loop decodes 14.6--21.0% more slowly than the base model. We present vSkipper, a virtualization layer that makes dynamic layer skippers pluggable in serving engines while preserving continuous batching, fixed-shape batches, paged KV caching, and captured decode graphs. At each routed layer, vSkipper groups tokens by the skipper's decision and uses routed execution only when predicted to be profitable. We implement vSkipper in SGLang and evaluate the released FlexiDepth checkpoint against upstream SGLang under identical prompts, arrivals, output lengths, and launch settings. At the knee of upstream's load curve, vSkipper reduces mean end-to-end latency by 36.8% on GSM8K and 13.6% on BBH. Under saturation, it increases request throughput by 11.3% and 7.4%. Serving adds no statistically resolved quality loss beyond the checkpoint's own. Across synthetic skip policies, two Qwen3 skippers, and three GPUs, we demonstrate reuse without workload-specific tuning. To our knowledge, vSkipper is the first system to realize serving-efficiency gains from per-token interior layer skipping within a modern LLM serving engine. The code is open-sourced as an SGLang fork at https://github.com/AKafakA/sglang-vskipper/tree/vskipper-ref

# vSkipper 论文总结

## 1. 核心问题与整体含义（研究动机与背景）

- **背景**：动态层跳过（dynamic layer skipping）允许每个 token 只执行模型的部分层，从而减少计算量。FlexiDepth 等方法通过为每个 token 添加轻量路由器，平均跳过 Llama-3-8B 的 20–30% 层，且不替换 Transformer 主干。
- **核心问题**：现有跳层器依赖**专用的研究型生成循环**，无法接入现代服务引擎（Orca、vLLM、SGLang）。这些引擎围绕"批内所有 token 遍历所有层"这一假设组织 kernel、元数据、页表和捕获图（captured graph）。
- **现象（Saved FLOPs ≠ Saved Time）**：论文复现了 FlexiDepth 的公开检查点，尽管平均跳过 8/32 层，其标准生成循环的解码吞吐反而比基础模型**慢 21.0%（batch size 1）和 14.6%（batch size 8）**。原因是：batch size 1 时路由开销抵消节省；batch size 8 时批仍要遍历所有 token 所需层的**并集**，拆分批次又牺牲批宽度。
- **整体含义**：缺的不是"跳过什么"，而是**层跳过与服务引擎批处理、缓存管理、执行机制之间的接口**。论文主张把动态跳层从"模型层问题"重新定义为"服务执行问题"，并声称 vSkipper 是首个在现代 LLM 服务引擎中通过逐 token 内部整层跳过实现服务效率增益的系统。

## 2. 方法论

### 核心思想
- 引入一个**服务虚拟化层**，把 skipper 变成服务引擎的可插拔组件：跳过策略只负责"每个 token 在哪里跳过"，vSkipper 负责把它翻译成引擎可执行的批次、缓存与图操作。

### 关键机制
- **RUN / Project-Only 接口**：在每个被路由的层，每行（row，一个 token 的隐状态）被赋予 RUN（完整计算）或 Project-Only（跳过）决策。
- **Route tape（路由磁带）**：每层每行的设备驻留掩码。捕获图将其作为**数据**消费，因此路由可逐 step 变化而无需主机同步或重新捕获图。
- **Project-Only 路径**：跳过的 token 不能简单绕过——未来 token 的注意力需要该层的 KV 存在。因此跳过行仍**写入本层的 K/V 投影到 KV cache**，丢弃注意力输出，并运行 skipper 的 projector（如 FlexiDepth 的 adapter，按路由器权重 $w \in [0,1]$ 混合）代替 MLP。这既省去该行的 attention KV 读取，在 compute-bound 时还省去被绕过的算术。
- **Packed cohorts（打包队列）**：每层从 tape 派生 RUN 与 Project-Only 两组行及其设备端标量计数，把行 gather 折叠进 operand load、加权 scatter 折叠进 epilogue，使 cohort GEMM 以**队列大小而非批大小**为界；attention 保持原启动形状，仅屏蔽跳过行的 KV 读取。
- **Captured execution**：两种模式在固定批大小下捕获（A100 上最多 1024 行）；routed graph 内每层走混合队列路径，并用**设备端条件 CUDA-graph 节点**为"无行跳过"的常见 step 提供 all-RUN 快路径。
- **Prefill**：同一接口与队列，每 prompt token 一行；因输入尺寸可变而位于捕获之外，使用 cuBLAS + 相同 gather/scatter。

### 正确性不变量
- **Invariant 1：每层写自己的 KV**。位置 $t$、层 $\ell$ 的缓存必须由该层自己的 K/V 投影产生，否则分页 KV 与前缀复用会出错。Project-Only 路径正是为保持此不变量而设计。
- **Invariant 2：行元数据永不陈旧**。所有行→内存映射（attention 元数据、KV 页映射、gather/scatter 映射）在行集合可能变化的任何位置都从当前 tape 在设备端重新派生，避免请求读到他人 KV 页。

### 盈利感知模式切换
- 路由模式有**固定 per-step 成本 $\tau$**，只有节省超过成本时才盈利。预填充模式在准入时固定，解码模式在 prefill 后设定，最多从 dense **单向提升**一次为 routed，之后不再回退。
- **解码阈值（roofline 推导）**：在设备的 ridge point 以下，解码受权重带宽限制，跳过行只省其 KV 读取。设 $L_r$ 路由层数、$s$ 投影决策比例、$b$ 每 token 每层 KV 字节数，则盈利条件为
  $$V > V^* = \frac{\tau \cdot BW}{s\,L_r\,b} \approx 158\text{k resident tokens（A100）}$$
  其中 $\tau=2.67$ ms、$s=0.5$、$L_r=16$、$b=4$ KB。实际服务阈值形成**滞后带**：$V\ge200$k 启用、$V\le160$k 停止（规则预测误差在 2% 内）；其他设备按规则推出（H100 270k/340k、A6000 60k/80k）。
- **预填充规则**：当批次 prompt token ≥ 1536 且预估 Project-Only 份额 > 0.35 时使用路由模式；份额每 64 个准入批次探测一次。这些常数跨工作负载固定。

### 实现
- 作为 SGLang 的 fork，**不改动其多进程架构、准入控制与内存管理**；scheduler 额外记录每请求模式（并作为前缀复用的 key）；routed-layer hook 支持 Llama-3 与 Qwen3 系列；启动时拒绝任何动作超出 {RUN, Project-Only} 的策略。

### 对比方法与消融
- **baseline**：upstream SGLang（独立 checkout）。
- **vSkipper arms**：served hybrid（带切换）、always-route（关闭切换）。
