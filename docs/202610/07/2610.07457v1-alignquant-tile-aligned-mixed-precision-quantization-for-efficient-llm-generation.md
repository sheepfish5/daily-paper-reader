## 摘要
细粒度混合精度量化有望实现高效的大语言模型推理，但局部精度选择可能与规整的GPU存储和计算单元相冲突。这种精度边界不匹配限制了将压缩转化为实际加速。我们提出AlignQuant，一种训练后量化方法，它使用GPU兼容的二维权重瓦片作为精度分配、紧凑存储和执行的共同单元。这种共享划分使精度能够在输出通道内跟随敏感性。联合预填充/解码校准在量化激活下，利用由语言模型损失梯度加权的投影输出扰动来评估精度降低。阶段归一化分数在模型级权重存储预算下，优先为对任一阶段重要的瓦片分配更高精度。每个瓦片存储一种选定的表示，而阶段专用内核复用打包后的模型，并扩展低位宽权重，以8位激活进行INT8计算。在涵盖3B至14B参数的四个LLM上，AlignQuant相比BF16实现了最高2.50×的生成加速，同时保持模型质量。评估进一步覆盖三种GPU以及长达64K token的上下文。这些结果表明，通过共享瓦片单元，局部精度灵活性与规整的GPU执行可以共存。实现见 https://github.com/HanzhiZhang-Ulrica/AlignQuant。

## Abstract
Fine-grained mixed-precision quantization promises efficient large language model inference, but local precision choices can conflict with regular GPU storage and computation units. This precision-boundary mismatch limits the translation of compression into practical acceleration. We introduce AlignQuant, a post-training quantization method that uses GPU-compatible two-dimensional weight tiles as the common unit of precision allocation, compact storage, and execution. This shared partition lets precision follow sensitivity within output channels. Joint prefill/decode calibration scores precision reductions using projection-output perturbations weighted by language-model loss gradients under quantized activations. Phase-normalized scores prioritize higher precision for tiles important to either phase under a model-wide weight-storage budget. Each tile stores one selected representation, while phase-specialized kernels reuse the packed model and expand lower-bit weights for INT8 computation with 8-bit activations. Across four LLMs spanning 3B to 14B parameters, AlignQuant achieves up to $2.50\times$ generation speedup over BF16 while preserving model quality. Evaluations further cover three GPUs and contexts up to 64K tokens. These results show that local precision flexibility and regular GPU execution can coexist through a shared tile unit. The implementation is available at https://github.com/HanzhiZhang-Ulrica/AlignQuant.

# AlignQuant 论文深度总结

## 1. 核心问题与整体含义

- **研究动机**：大语言模型（LLM）推理日益受限于参数存储、内存流量与计算开销，训练后量化（PTQ）是降低这些成本的核心手段，但量化误差使精度保持成为关键挑战。
- **背景矛盾**：均匀比特量化在固定精度下优化表示；混合精度量化利用权重敏感度差异，在存储预算下为敏感区域分配更高精度。然而，**细粒度精度边界一旦跨越规整的 GPU 存储或计算单元，就会产生"精度边界不匹配"（precision-boundary mismatch）**，使压缩难以转化为实际加速。
- **现有方案的权衡**：通道级/输出特征级方法保持规整划分，但将不同敏感度的权重耦合到同一比特宽度；更细粒度方法（量化组、硬件对齐块）暴露更多局部选择，却需额外的重排序、混合格式或专用执行支持；系统导向量化器则需联合设计低位格式、权重布局、反量化与 GPU 数据通路。
- **核心问题**：如何让敏感度驱动的局部精度选择，既能保留在紧凑权重存储中，又能直接用于 GPU 执行？

## 2. 方法论

### 2.1 核心思想
以 **GPU 兼容的二维权重瓦片（2D weight tile）** 作为精度分配、紧凑存储与执行的**统一单元**。每个瓦片独立选择 4-bit 或 8-bit，使精度可在输出通道内部随敏感度变化，同时保持规整的存储/加载单位。

### 2.2 关键技术细节

**（1）瓦片对齐的精度分配（离线）**
- 将所有权重矩阵划分为等大小二维瓦片，模型级瓦片集合记为 $T$；目标 4-bit 瓦片比例为 $\rho$。
- 候选构造：对权重施加瓦片对齐的正交输入/输出变换（沿 $K$ 的 $V$、沿 $N$ 的 $U$），得到对称的 4-bit 与 8-bit 候选，并用 FP64 网格搜索拟合各自最优缩放因子。
- 变换对齐瓦片边界，保证每个变换后的权重瓦片落在其分配的精度区域内。

**（2）联合 prefill/decode 损失感知评分**
- 局部输出扰动：替换瓦片 $t$ 的 8-bit 候选为 4-bit 候选，产生的投影输出变化为
  $\Delta\tilde{Y}^{p,c}_t = \hat{X}^{p,c}_t (\hat{W}_{4,t} - \hat{W}_{8,t})^\top$
- Fisher 加权：用对角线经验 Fisher（语言模型损失梯度）对平方输出扰动加权，捕捉瓦片内所有权重共同变化的下游影响：
  $F^p_t = \frac{1}{2}\sum_{c\in C^p} n_c \|\nabla_{\tilde{Y}_t} L_c \odot \Delta\tilde{Y}^{p,c}_t\|_F^2$
- 阶段归一化与联合：各阶段分数除以该阶段模型级总分数后取最大值，使两阶段可比并保留任一阶段的高相对敏感度：
  $F_t = \max_{p\in\{pre,dec\}} \frac{F^p_t}{\sum_{t'} F^p_{t'}}$
- 分配：将全局得分最低的 $\text{round}(\rho|T|)$ 个瓦片设为 4-bit，其余为 8-bit。由于等面积瓦片每次替换节省相同字节，全局排序决定固定高精度预算的落点。

**（3）紧凑混合精度表示**
- 每个瓦片存储一种选定的整数表示 + FP32 重建缩放；每字节存两个有符号 4-bit 或一个 8-bit 值。
- 4-bit 与 8-bit 瓦片分别放入连续缓冲区，用 1-bit 精度标签选择缓冲区，行偏移 + 前序同精度瓦片计数定位。
- 标称整数权重存储为 $8-4\rho$ bits/权重，完整打包还含缩放、索引元数据。

**（4）阶段专用直接执行**
- 激活统一量化为 8-bit（按 64 特征 × 行分组），4-bit 权重在加载时保持打包、片上扩展为有符号 INT8，8-bit 权重直接作为 INT8 操作数，两者共享 INT8 算术。
- **Prefill**：Tensor Core INT8 MMA，短 prefill 片上准备操作数；长 prefill（$M'\geq1024$）按投影调用一次性展开到临时 INT8 缓冲，跨激活行组复用。
- **Decode**：$M=1$ 的矩阵-向量负载，直接加载打包瓦片、片上展开，用 DP4A 每指令累加四个 8-bit 乘积到 INT32，在输出特征与输入列组上并行。
- **输出重建**：每个瓦片乘积先 INT32 累加，再用激活/权重缩放恢复，按固定顺序做 FP32 分块归约，最后用输出变换 $U$ 还原。
- **共享激活准备**：Q/K/V 或 gate/up 等兼容投影共享一次输入变换与量化。

## 6. 主要结论与发现

- **核心结论**：通过共享瓦片单元，局部精度灵活性与规整 GPU 执行可以共存；精度单元应同时服务于敏感度评估与高效执行。
- **加速效果**：Llama-3.2-3B 上达 132.28 tok/s，为 BF16 的 2.27×、GPTQ 的 2.75×；跨模型 TPOT 相对 BF16 提速 1.53×–2.50×；H100 NVL 达 167.49 tok/s，RTX 4090 达 180.64 tok/s。
- **质量保持**：在多数基准上取得量化方法中最低困惑度与最高/并列最高精度；LAMBADA、WinoGrande 等显著优于结构化与随机放置对照。
- **长上下文优势**：64K 时 LooGLE-SD 得 48.06（BF16 为 48.81，AWQ 为 41.69），随上下文增长对 AWQ 的优势从 2.35 扩大到 6.37 分；LongEval 最长输入下与 BF16 同为 48%，远超 MixLLM（40%）与 AWQ（31%）。
- **存储与能耗**：常驻显存从 5.99 GiB 降至 2.72 GiB，能耗最低；16K prompt 下峰值显存约为 BF16 的一半。
- **敏感度局部性**：约 59.81%–90.17% 的输出瓦片行同时包含 W4/W8，说明通道内局部精度选择被广泛使用。

## 7. 优点

- **设计统一性**：精度分配、存储布局与执行共享同一二维瓦片划分，从根本上缓解"精度边界不匹配"，避免了异构格式的额外重排/索引开销。
- **评分方法严谨**：以瓦片级整体替换的输出扰动（含误差增强/抵消项）配合 Fisher 损失梯度加权，并将 prefill/decode 归一化后取最大，兼顾两阶段；附录给出完整推导与固定预算最优性论证。
- **系统落地完整**：从打包位序、索引公式、INT8 MMA/DP4A 调度、共享激活准备到 CUDA Graph，形成可复现的端到端方案，并开源实现。
- **实验维度丰富**：跨 4 个模型、3 种 GPU、4 类消融、多种预算与校准规模，覆盖通用质量、长上下文、吞吐/延迟/能耗/显存多维指标。
- **实用性**：仅需 64 条校准样本、单一紧凑模型即可服务两阶段，校准数据敏感度低（SD 0.03–0.11 个百分点）。

## 8. 不足与局限

- **精度空间受限**：仅考虑 {4-bit, 8-bit} 权重 + 统一 8-bit 激活，未探索 2/3/6-bit 或混合激活精度，也未与 MX/微缩放等硬件格式结合。
- **PTQ 固有局限**：无量化感知训练或参数微调，对极低比特或更敏感任务的适用性未验证。
- **对照公平性存疑**：部分基线（如 SFMP）使用解量化后端，其系统性能可能低于专门实现；未与 QServe、Atom 等系统级协同设计量化器在同等条件下对比。
- **评测覆盖不均**：主文以 Llama-3.2-3B 为主，其余模型结果多置于附录；未覆盖 MoE 架构、多模态或更长（>64K）上下文。
- **硬件覆盖有限**：仅在 NVIDIA A100/H100/RTX 4090 验证，未涉及其他厂商加速器或边缘设备。
- **超参依赖**：瓦片尺寸、4-bit 比例、校准集合与变换种子等需预设或搜索，论文未系统报告这些超参的跨模型敏感性（仅瓦片尺寸与校准规模有消融）。
- **系统开销细节**：长 prefill 的临时 INT8 缓冲会额外占用 $BRC + 4RC + 4(R+1)$ 字节，其与 batch/序列长度交互的开销边界讨论较少。
- **资源报告缺失**：未披露校准/打包的离线耗时与算力消耗，限制了部署成本评估。
