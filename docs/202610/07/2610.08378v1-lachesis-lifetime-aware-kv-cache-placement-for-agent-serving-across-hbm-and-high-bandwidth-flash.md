## 摘要
大语言模型（LLM）服务正日益被智能体工作负载所主导，在这些工作负载中，智能体及其子智能体在多次请求间将上下文累积为 KV 缓存，消耗大量内存。高带宽闪存（HBF）是一种有前景的解决方案，它以 HBM 级别的读带宽提供高一个数量级的容量，但其有限的写入耐久性是关键限制因素。我们的核心洞察是，KV 缓存应根据其生命周期在 HBM 与 HBF 之间进行放置。将生命周期较短的数据放在 HBM 中，可使 HBM 吸收更多智能体运行期间的写入，从而减少发送到 HBF 的写入量。由于智能体服务中 KV 缓存的生命周期由 harness（编排智能体的程序）决定，我们分析了其行为，并识别出生命周期产生差异的三个维度：时间、结构和跨 worker。在这些观察的指导下，我们提出 Lachesis，一个位于智能体 harness 与服务引擎之间的生命周期感知 KV 缓存放置层。在写入时，它根据生命周期将每个段放置在 HBM 或 HBF 中，并在该段不再被读取后释放其块。在基于 trace 的模拟中，与 HBM 优先放置相比，Lachesis 将 HBF 寿命延长了 1.19–3.13 倍，达到 3.3–12.2 设备年。即使在严格 SLO 所允许的满载下 24×7 连续运行，在多智能体 trace 上，HBF 的寿命仍超过其五年保修期。

## Abstract
Large language model (LLM) serving is increasingly dominated by agentic workloads, in which agents and their sub-agents accumulate context as KV cache across many requests, consuming substantial memory. High-bandwidth flash (HBF) is a promising solution, providing an order of magnitude greater capacity at HBM-class read bandwidth, but its finite write endurance is the key limiting factor. Our key insight is that KV cache should be placed across HBM and HBF by its lifetime. Placing shorter-lived data in HBM lets HBM absorb more of an agent run's writes and sends less of them to HBF. As the lifetime of KV cache in agentic serving is dictated by the harness, the program that orchestrates the agents, we analyze its behavior and identify three axes along which lifetime diverges, temporal, structural, and inter-worker. Guided by these observations, we present Lachesis, a lifetime-aware KV cache placement layer between the agent harness and the serving engine. At write time, it places each segment in HBM or HBF according to its lifetime, and frees its blocks once the segment is no longer read. In trace-driven simulation, Lachesis extends HBF lifetime by 1.19-3.13x over HBM-first placement, reaching 3.3-12.2 device-years. Even under continuous 24x7 operation at the full load a tight SLO admits, HBF outlasts its five-year warranty on the multi-agent trace.

## 1. 核心问题与整体含义（研究动机与背景）

- **背景：智能体服务的内存容量墙**
  - LLM 服务正从无状态请求转向智能体（agentic）工作负载：一个 agent 在单个用户任务上跨越多次 LLM 请求，并将累积的上下文以 KV cache 形式持续保留，还可派生并发子智能体（sub-agent）。
  - 与传统请求"一个上下文只活一次请求"不同，agent 的 KV cache 可存活远超写入它的那次请求，甚至直到会话结束，导致同时驻留的 KV 体量远超常规服务。
  - 智能体工作负载的峰值上下文长度约为传统聊天负载的 **29×**（如 SWE-bench 45K、GAIA 69K tokens），而模型权重也已超过单卡 HBM 容量（图 2）。
  - 现有 KV 优化（量化、压缩、驱逐、稀疏注意力）只能降低常数因子或读开销，无法消除容量墙。

- **HBF 的机遇与瓶颈**
  - 高带宽闪存（HBF）基于 NAND，单栈容量约为 HBM 的 **16×**，并可提供 HBM 级别的顺序读带宽，是缓解容量墙的有力方案。
  - 关键限制是**写入耐久性**：NAND 只支持有限次 P/E 周期，若像 DRAM 一样吸收大量写入，会在服役寿命的一小部分内被磨损。
  - 早期 HBF 设计（H3、FLINT 等）只放只读数据（模型权重、预计算 KV）；后续工作（如 Kyung et al.）按**读写比（ρ_R/W）**选择 KV 放入 HBF，但该判据针对无状态请求，不适用于有状态的智能体会话。

- **核心洞察**
  - KV cache 应按**生命周期（lifetime）**在 HBM 与 HBF 间放置：短寿命数据留在 HBM，让 HBM 吸收更多写入，从而减少到达 HBF 的写入量、延长其寿命。
  - 在智能体服务中，KV 生命周期由 **harness**（编排 agent 的程序）决定，因此可通过分析 harness 行为在写入前预知寿命。
  - 论文识别出寿命差异的三个维度：**时间轴（temporal）、结构轴（structural）、跨 worker 轴（inter-worker）**。

## 2. 方法论：核心思想、关键技术细节与流程

### 2.1 核心思想
- 提出 **Lachesis**：位于 agent harness（如 OpenHands SDK、AOrchestra、Claude Code）与 serving engine（如 vLLM、SGLang）之间的**生命周期感知 KV cache 放置层**。
- 在 KV **写入前**决定其去 HBM 还是 HBF；在段（segment）不再被读取时立即释放其块。
- 只覆盖 KV，模型权重的只读映射与激活保持原状。

### 2.2 关键概念
- **Context segment（上下文段）**：一组共享同一生命周期的 token，由 harness 在 **context boundary（上下文边界）**处整体丢弃。
- **三条寿命差异轴**（表 1）：
  - **时间轴**：turn 结束时 harness 剥离 reasoning 内容。reasoning-laden 段仅活一个 turn，却占该 turn 写入 token 的 **66–83%**；reasoning-stripped 段寿命长 **7.6–17.2×**（可分离度 0.96–0.99）。
  - **结构轴**：sub-agent 返回时其段被丢弃，仅结果并入 lead-agent 段。lead-agent 段寿命长 **4.0–6.1×**（worker）/ **4.7–38.3×**（reviewer）；但 lead-agent 有 **71–88%** 寿命处于未被读取的等待期，故其 ρ_R/W 与 worker 重叠（0.25–0.60）——说明**复用率不能作为寿命代理**。
  - **跨 worker 轴**：同属 sub-agent 类，但 worker 寿命 p10–p90 相差 **3.7–23.6×**，写量相差 2.8–22.5×，二者 Kendall τ 为 0.51–0.72。寿命无法事后预知，但**相对顺序可在 spawn 时预测**。

### 2.3 两条放置路径
- **确定性路径（deterministic path）**——覆盖时间轴与结构轴：
  - 短寿命段（reasoning-laden、sub-agent/reviewer）→ HBM；长寿命段（reasoning-stripped、lead-agent）→ HBF。
  - 依据 harness 固定的段类别，边界到达即释放。
- **预测性路径（predictive path）**——覆盖跨 worker 轴：
  - 在每个 worker spawn 时，用其 **spawn record**（Instruction、Context、Tools、Model 及会话位置）构成"spawn signal"。
  - 预测器为 **ridge 回归线性模型**，输入为长度、工具指示、会话位置、词袋哈希；**只消费排序，不估计具体寿命值**。
  - 将预测寿命最短者优先准入 HBM，其余放 HBF；**k 由 HBM 空闲容量动态决定**，而非固定参数。
  - reviewer 在 worker 之后才 spawn，故 Lachesis 先为 reviewer 预留 HBM 容量再计 k。

### 2.4 系统接口与数据结构
- **Segment table**：每个活段一行，含段 id、段类别、关闭它的上下文边界、所持 KV 块 id；表大小与活块数成正比。
- 对 serving engine 仅两个调用：
  - `alloc(tier)`：从指定层（HBM/HBF）的空闲链表取一块；
  - `free([block ids])`：在上下文边界（而非 recency 策略等待的"不活跃"之后）释放块，各自归还来源链表。
- engine 只需为异构内存**每层各维护一个空闲链表**，其余不变；HBM 空闲链表空时从 HBF 分配。

### 2.5 关键公式
- 归一化寿命（参考时钟为 PD 分离部署中的 decode 节点）：
  - **T_norm(s) = G_dec(s)·TPOT_ref + N_obs(s)·TTFT_ref + Λ_tool(s) + Λ_user(s)**
  - 其中 TPOT_ref = 0.2 s，TTFT_ref = 1.0 s；Λ_tool、Λ_user 为建模量。
- 读写比：
  - **ρ_R/W(s) = V_R(s) / V_W(s)**，V_W(s) = N_W(s)·V_token_KV；V_R(s) 只计 decode 阶段读取（附录 B）。

## 3. 实验设计

### 3.1 平台与硬件配置
- **仿真**：serving engine 用 **Frontier**（调度器、请求队列、带 block-hash 前缀缓存的 KV 管理器、按 KV 块预算表达容量）；硬件用 **LLMSimulator**（含 HBF 扩展，编译算子内核 + roofline 内存定价）。

### 3.3 对比方法与指标
- **Baseline**：HBM-first placement（有 HBM 空闲块就放 HBM，否则放 HBF）——即无 Lachesis 时引擎的默认行为。

## 6. 主要结论与发现

- **寿命延长**：相对 HBM-first，Lachesis 将 HBF 寿命
