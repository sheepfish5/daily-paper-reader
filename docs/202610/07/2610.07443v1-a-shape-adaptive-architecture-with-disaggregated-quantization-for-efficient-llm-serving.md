## 摘要
大语言模型（LLM）已成为现代AI应用的支柱，但高效推理仍面临重大挑战。其自回归生成将执行过程分为两个阶段：以大型GEMM为主的预填充阶段，以及以小型GEMV为主的解码阶段。现代服务系统进一步通过连续批处理和预填充-解码分离引入复杂性，导致动态工作负载和阶段分离。然而，现有加速器仍与这些系统级行为匹配不佳，造成LLM服务效率低下。在本工作中，我们提出DynaCore，一种通过系统-架构协同设计实现高效LLM服务的统一架构。我们观察到，脉动阵列执行的计算瓦片（即其最小高效单元，MEU）横跨GEMM的全部三个维度。DynaCore沿全部三个维度重塑MEU：在空间上，它非对称地在阵列宽度与高度之间进行权衡，提升权重交付，同时保持输入路径不变；在时间上，Split-K将归约映射到阵列上，通过阵列已有的互连来折叠部分和。为利用阶段分离，我们进一步提出分离式量化，对预填充应用双边量化，对解码应用仅权重量化，并采用内积混合精度数据通路，使输出位宽不随精度变化。随后，运行时调度框架为每个批次选择一个MEU。基于真实世界服务轨迹的评估表明，相较于量化加速器和可重构加速器，DynaCore显著降低了服务级延迟，使TTFT分别改善3.50倍和2.97倍，使TPOT分别改善36.55倍和8.02倍。

## Abstract
Large language models (LLMs) have become the backbone of modern AI applications, but pose significant challenges for efficient inference. Their autoregressive generation divides execution into two phases: prefill, dominated by large GEMMs, and decoding, dominated by small GEMVs. Modern serving systems further introduce complexity through continuous batching and prefill-decoding disaggregation, leading to dynamic workloads and phase separation. However, existing accelerators remain poorly aligned with these system-level behaviors, resulting in inefficiencies in LLM serving.   In this work, we present DynaCore, a unified architecture for efficient LLM serving via system-architecture co-design. We observe that the compute tile a systolic array executes, its Minimum Efficient Unit (MEU), spans all three GEMM dimensions. DynaCore reshapes the MEU along all three: spatially it trades array width against height asymmetrically, raising weight delivery while leaving the input path untouched, and temporally Split-K maps the reduction onto the array, folding partial sums through the interconnect the array already has. To exploit phase separation, we further propose disaggregated quantization, applying dual-side quantization to prefill and weight-only quantization to decoding, with an inner-product mixed-precision datapath that keeps output width invariant to precision. A runtime scheduling framework then selects an MEU per batch. Evaluation with real-world serving traces shows that DynaCore substantially reduces service-level latency over quantization and reconfigurable accelerators, improving TTFT by 3.50x and 2.97x and TPOT by 36.55x and 8.02x, respectively.

# DynaCore 论文总结

## 1. 核心问题与整体含义

- **研究背景**：LLM 自回归推理分为两个本质不同的阶段：
  - **Prefill**：并行处理全部输入 token，以大 GEMM 为主，计算密集、利用率高。
  - **Decoding**：逐 token 生成，以小 GEMV 为主，内存带宽受限、并行度低、硬件利用率差。
- **系统级挑战**：
  - **连续批处理（CB）** 使 GEMM 形状随活跃 token 数动态变化。
  - **预填充-解码分离（PDD）** 将两阶段部署到不同设备，缓解干扰，但带来阶段比例动态变化和资源不均衡。
- **现有加速器错配**：
  - 脉动阵列通常为大型 GEMM 优化，面对 decoding 的窄 GEMV 时大量 PE 空闲。
  - 量化策略通常在全阶段采用统一配置（如 W8A8 或 W4A16），但 prefill 偏计算、decoding 偏带宽，统一配置次优。
  - 现有可重构阵列多只对称重塑空间维度 \(m,n\)，无法覆盖 decoding 所需的“扁平”形状。
- **整体含义**：论文提出 **DynaCore**，通过系统-架构协同设计，统一支持 prefill 与 decoding，并适配 CB 与 PDD 带来的动态负载。

## 2. 方法论

### 2.1 核心思想：沿 GEMM 三维重塑 MEU

- 定义 **最小高效单元（MEU）**：\(MEU = m \times n \times k\)。
  - \(m,n\) 为空间维度，由阵列组织决定。
  - \(k\) 为时间/归约维度，取决于操作数交付与传播方式。
- 利用率公式：
  \[
  U = \frac{\min(M,m)\cdot \min(N,n)}{m\cdot n} \cdot \frac{K}{K+k}
  \]
  其中前项为空间利用率，后项为时间利用率。
- DynaCore 同时重塑 \(m,n,k\)，而非仅调整空间维度。

### 2.2 空间非对称重塑

- 每个 DynaPE 通过 selector 选择权重来源：
  - 来自上方 PE：继续复用权重流。
  - 来自权重缓冲区：开启新的逻辑行。
- 若断言 \(g\) 行，则：
  \[
  m = S/g,\quad n = gS,\quad m\cdot n = S^2
  \]
- **非对称性**：
  - 权重路径需要 \(g\) 条并发流，压力增大。
  - 输入路径仍为单一广播流，保持不变。
- **Tall GEMM**：\(M,N\) 均较大，采用方形配置，权重和输入双向复用。
- **Flat GEMM**：\(M\) 小于阵列维度，减少 \(m\)、增大 \(n\)，将释放的行用于扩展输出列。
- 同一 \(S \times S\) 核心可在 \(S \times S, S/2 \times 2S, \dots, 1 \times S^2\) 间连续切换。

### 2.3 时间维度 Split-K

- 当 \(M < m\) 且 \(N < n\) 时，空间重塑无法充分利用阵列，此时利用仍较大的 \(K\)。
- 将阵列沿 \(K\) 分为 \(t\) 组，每组计算同一输出瓦片的部分和：
  \[
  m\cdot n\cdot t = S^2,\quad k = t\cdot \max(m,n)
  \]
- **Tick-Tock 归约**：
  - 最后一组作为目标累加器。
  - 其他组的部分和逐行向下传递。
  - tick：向下移动一行，不累加。
  - tock：到达对应组时累加。
  - 复用阵列已有的垂直互连，不增加专用加法树。
- 输出路径不增宽，归约与排空在同一阶段完成。

### 2.4 分离式量化

- **Prefill**：采用双边量化 W8A8，提高计算吞吐。
- **Decoding**：采用仅权重量化 W4A16，降低权重带宽压力。
- **内积混合精度数据通路**：
  - 传统外积方案会将输出瓦片从 \(1\times1\) 扩展到 \(2\times2\)，需要更多累加器。
  - DynaCore 将释放的低精度乘法器用于 \(K\) 方向相邻操作数。
  - FP16 乘法由多个 4-bit 子乘法器组合；INT8 模式复用其中大部分结构。
  - 输出仍为单个 32-bit 结果，输出宽度和数量不随精度变化。
- 与空间重塑和 Split-K 对齐：
  - 非对称重塑增加权重带宽需求，W4A16 正好缓解权重路径。
  - Split-K 将多余 PE 用于 \(K\)，内积混合精度将多余乘法能力也用于 \(K\)。

### 2.5 运行时调度框架

- 三层结构：
  - **主机系统调度**：长期 PDD 设备比例分配；短期 CB 批次组织。
  - **编译层**：为每个批次选择 MEU 配置。
  - **加速器**：按配置执行。
- **Pyramid packing**：
  - 将批次分解为多个 MEU，而非强制单一形状。
  - 例如 \(M=11\) 在 \(4\times4\) 核心上分解为 \(4\times4,4\times4,2\times8,1\times16\)。
  - 优先使用较大配置，减少全扁平配置比例以降低权重流量和能耗。
- **配置搜索**：
  - 在 \(m\cdot n\cdot t=S^2\) 约束下搜索 \(n,t\)。
  - 目标函数：\(\tau \cdot (T_{lat}[m,n,t] + \lambda T_{eng}[m,n,t])\)。
  - 离线 profiling 建立延迟/能量表，运行时查表。
