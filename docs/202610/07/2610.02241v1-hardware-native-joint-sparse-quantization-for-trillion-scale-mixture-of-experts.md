## 摘要
混合专家（MoE）架构使前沿语言模型能够扩展到万亿级参数，但其部署受到巨大内存占用和内存带宽限制的制约。尽管现代加速器提供了稀疏张量核心（SpTC），可通过低精度半结构化稀疏降低权重存储并提高吞吐量，但将其用于MoE仍具挑战，原因是模型质量会显著下降，且缺乏分组稀疏GEMM原语。我们提出了一种端到端软硬件协同设计框架，可将专家权重压缩为硬件原生的低精度稀疏表示，并在SpTC上加速其执行。在算法层面，我们的框架通过连续重参数化松弛离散半结构化支撑选择，从而在路由器加权重建目标下实现与量化权重的可微联合优化，并支持可扩展的专家并行压缩。在系统层面，我们开发了定制分组稀疏GEMM内核，专为SpTC上的低精度稀疏MoE推理而设计。在参数量从300亿到1万亿的MoE模型上，我们的框架将当前最优的联合稀疏量化精度最多提升4.35个百分点，同时保持原始模型性能的96.09%。在NVIDIA B200 GPU上，我们的内核相较厂商基线最高提升1.65倍，将服务吞吐量提升1.18倍，并将端到端延迟最多降低4.03倍。这些结果表明，软硬件协同设计是实现可扩展且高效MoE部署的切实可行路径。

## Abstract
Mixture-of-Experts (MoE) architectures allow frontier language models to scale to trillions of parameters, but their deployment is constrained by massive memory footprints and memory-bandwidth limitations. Although modern accelerators provide Sparse Tensor Cores (SpTCs) that reduce weight storage and increase throughput through low-precision semi-structured sparsity, exploiting them for MoEs remains challenging because of substantial model-quality degradation and the lack of grouped sparse GEMM primitives. We present an end-to-end hardware-software co-design framework that compresses expert weights into hardware-native, low-precision sparse representations and accelerates their execution on SpTCs. Algorithmically, our framework relaxes discrete semi-structured support selection through continuous reparameterization, enabling differentiable joint optimization with quantized weights under a router-weighted reconstruction objective and scalable expert-parallel compression. Systemically, we develop a custom grouped sparse GEMM kernel tailored to low-precision sparse MoE inference on SpTCs. Across MoE models ranging from 30 billion to one trillion parameters, our framework improves state-of-the-art joint sparse-quantization accuracy by up to 4.35 percentage points while preserving 96.09% of the original model's performance. On NVIDIA B200 GPUs, our kernel outperforms the vendor baseline by up to $1.65\times$, increasing serving throughput by $1.18\times$ and reducing end-to-end latency by up to $4.03\times$. These results establish hardware-software co-design as a practical path toward scalable and efficient MoE deployment.

## 一、核心问题与整体含义（研究动机与背景）

- **背景**：MoE 架构已成为扩展前沿语言模型的主流范式，可将参数量推向万亿级，同时通过动态专家路由保持每 token 推理 FLOPs 可控。但部署面临严峻瓶颈——尽管每 token 只激活少量权重，服务仍需在设备内存中常驻**全部专家池**，内存占用随总参数而非激活参数增长（如 Kimi-K2.5 总参数 1T、每 token 仅激活 32B，但 INT4 权重包约 595 GB）。
- **硬件机会**：现代加速器（NVIDIA Blackwell）提供稀疏张量核心（SpTC），原生支持细粒度半结构化（N:M）稀疏低精度矩阵乘法，可在压缩权重存储的同时提升吞吐。例如 Blackwell 上 NVFP4/MXFP4 结合 paired 4:8 稀疏可提供高达 18 PFLOP/s，为稠密路径的两倍。
- **两大缺口**：
  1. **保真度难题**：在"半结构化稀疏 + 低精度量化"的复合约束下，跨多样专家表示保持模型质量极为困难。现有联合稀疏量化方法（JSQ、OBR、SGPTQ）主要面向稠密 LLM，在万亿级 MoE 上是否可行尚不明确。
  2. **执行栈瓶颈**：MoE 推理依赖 grouped GEMM 批量处理路由相关 token，但现有分组 GEMM 内核仅针对稠密格式，**缺乏公开可用的分组稀疏 GEMM 路径**来直接支持 paired 4:8 NVFP4 表示。
- **整体含义**：论文主张必须通过**软硬件协同设计**，使 MoE 压缩与路由执行同时对齐硬件原生表示约束，才能把 SpTC 的理论能力转化为实际的存储压缩与执行加速。

## 二、方法论

### 2.1 核心思想
提出 **MoESQ** 端到端框架，由两部分构成：
- **算法层**：学习硬件原生的稀疏量化专家权重表示；
- **系统层**：在 SpTC 上执行同一表示的定制分组稀疏 GEMM 内核。

### 2.2 问题形式化
- 目标是最小化目标模块的重建误差：`min L(Ŵ) = ||f(X;W) − f(X;Ŵ)||²_F`，约束 `Ŵ ∈ C := S ∩ Q`。
- `S` 为硬件可接受的半结构化稀疏模式集合（如 paired 4:8），`Q` 为可接受量化值及共享缩放因子集合（如 NVFP4）。
- 由于支撑选择、量化表示与共享尺度估计紧耦合，构成**离散组合优化难题**。

### 2.3 可微松弛（Gumbel–Softmax 重参数化）
- 将权重矩阵按结构化组划分，每组约束为预定义模式集 `P` 中的一种（paired 4:8 下 m=8、|P|=6，每组保留 2 个相邻对）。
- 引入 logit 矩阵 `A ∈ R^{R×P}`，通过 Gumbel 噪声 + Softmax 构造松弛支撑掩码：`π = softmax((A + G)/τ)`，`Z[r] = Σ_p π_{r,p} ρ_p`。
- 温度 `τ_t` 随训练退火趋近 0，使松弛掩码收敛为确定的 one-hot 模式选择。

### 2.4 联合量化耦合
- 引入辅助全精度矩阵 `V`，与松弛掩码结合得软掩码权重 `Y_t = Z_t ⊙ V`。
- 量化算子 `Q_w` 计算局部缩放因子 `s_{t,b} = Scale_w(Y_t[b])`，并将归一化权重投影到目标值网格：`Q_w(Y_t)[b] = s_{t,b} · Π_{G_w}(Y_t[b]/s_{t,b})`。
- 反向传播中将缩放因子视为常数，对不可微投影采用 **STE（直通估计器）**，使重建损失**联合更新支撑 logit A 与辅助权重 V**，确保候选支撑在其量化约束实现下被直接评估。

### 2.5 可扩展的逐块专家压缩（Algorithm 1）
- 沿用 GSQ 的逐块逐专家分解：在第 l 块，路由器为专家 e 分配 token 集 `X_{l,e}` 与门控系数 `w_{l,e}`，以未压缩专家输出为重建目标 `Y_{l,e}`。
- 将每个专家重构为统一的 **gate–up–down 块**，各投影独立维护支撑 logit 与潜在权重，并在重建循环内进行动态激活量化 `Q_a`。
- **路由器加权重建目标**：`L^{rw}_{l,e}(θ̂) = ||diag(w_{l,e})(Y_{l,e} − f^{Q_a}_{l,e}(X_{l,e}; θ̂))||²_F`，即按路由门控系数缩放每个 token 残差。
- 块内专家跨设备**并行独立优化**，完成后组装并生成下一块的校准输入，使每块观察到压缩前缀累积的误差。

### 2.6 实现细节
- 路由器与非专家参数固定；初始化自 SGPTQ 解；每次精炼前向重算量化尺度。
- NVFP4 尺度计算：`Scale_w(Y_t[b]) = Π_{E4M3}(γ_t·||Y_t[b]||_∞/6)/γ_t`，`γ_t = 448·max_b||Y_t[b]||_∞/6`（6 为 FP4-E2M1 最大值，448 为 FP8-E4M3 最大值）。
- 精炼后取每组最高 logit 模式，重算最终尺度，打包为 **E2M1 值 + 稀疏元数据 + 每 32 个逻辑权重一个 UE4M3 尺度**。

### 2.7 分组稀疏 GEMM 内核
- 将 Blackwell 块缩放稀疏 MMA 主循环与 CUTLASS 的分组问题抽象、持久化调度器结合。
- 因稀疏 MMA 要求稀疏矩阵为左操作数 A，将 `W_e` 置于 A，计算 `Y_e^T = W_e X_e^T`；该变换是**零拷贝**的（行主序 X_e 与列主序 B 布局一致，列主序结果与期望的行主序 Y_e 一致）。
- 权重离线打包，激活在运行时量化为 32 元素尺度块；MMA 内部应用两个操作数的块尺度，epilogue 将张量级尺度合并为每专家因子 `α_e` 后再将 FP32 累加器转为 BF16。

- **精度**：

- **端到端服务**（8×B200，vLLM + DP=8×EP）：
  - **Decode 阶段**：相比稠密 NVFP4 CuTeDSL 基线，吞吐提升约 **1.4–1.6×**，TPOT 同步下降；相比 Marlin INT4 与 Humming INT2 基线亦有明显优势。
  - **Prefill 阶段**：吞吐提升幅度与 decode 相近，验证分组稀疏 GEMM 在长序列、大 batch 下同样有效。
  - 由于路由、调度、批处理与 token 合并逻辑被固定，性能差异可归因于专家表示与稀疏内核本身，属受控对比。

  - **路由器加权目标**相比均匀目标带来稳定精度增益，说明按门控系数缩放 token 残差能让压缩更聚焦于对最终输出贡献大的 token。
  - **联合更新支撑 A 与潜在权重 V**显著优于仅更新 V，证明让候选支撑在其量化约束实现下被直接评估，是避免"稀疏模式选择与量化表示错配"的关键。

- **更广压缩对比**：
  - 相比 2-bit GSQ（稠密 INT2 W2A16），MoESQ 在相近或更低的平均位宽下取得更高精度，且具备原生 SpTC 执行路径。
  - 相比 REAP（50% 专家剪枝 + INT4），MoESQ 在保留更多有效容量的同时避免了剪枝带来的专家覆盖损失。

## 七、局限性与开放问题

- **压缩范围有限**：仅压缩路由专家 FFN 权重，注意力、共享专家、路由器、嵌入与 LM head 均保持参考精度；未验证对注意力层或共享专家施加同格式压缩的可行性。
- **硬件依赖**：方法强依赖 Blackwell 的块缩放稀疏 MMA 与 paired 4:8 NVFP4 支持，在缺乏原生 SpTC 的加速器上难以直接复现其执行收益。
- **校准数据敏感性**：压缩质量依赖校准集分布（LLM compression calibration + OpenThoughts-114k + FineWeb-Edu 的 10:45:45 混合），跨领域迁移时的稳健性未做系统评估。
- **对比公平性**：作者主动披露与 SGPTQ 的对比非算力匹配（SGPTQ 为一次性 512 序列，MoESQ 额外精炼 10 epoch × 8192 序列），因此该对比旨在隔离优化配方所达解的质量，而非等压缩成本下的质量。
- **失败模式分析**：附录 C.3 对 JSQ 的非终止生成做了定性与定量剖析（88.3% 截断率、精度崩溃至 17.24%），指出退化源于长程生成动态被破坏（重复、不终止），而非普通答错；这提示联合稀疏量化在 MoE 上需特别关注生成稳定性。
- **资源披露**：论文给出各模型压缩的墙钟时间与设备数量，但未披露总 GPU 小时数或碳成本，能效测量亦限于单卡 B300 的整板 NVML 读数。

## 八、总体评价与启示

- **核心贡献**：MoESQ 首次将"硬件原生半结构化稀疏 + 低精度量化"的联合表示学习，与"分组稀疏 GEMM"的执行路径打通，形成算法–系统闭环，使 SpTC 的理论算力真正转化为万亿级 MoE 的存储压缩与推理加速。
- **方法亮点**：Gumbel–Softmax 可微松弛将离散支撑选择与量化尺度估计解耦为可联合优化的问题；路由器加权重建目标与逐块逐专家并行压缩使方法可扩展至 1T 参数规模。
- **实验强度**：跨 30B / 397B / 1T 三个尺度、通用知识与推理双维度、含消融与失败模式剖析，并辅以内核级与端到端服务评测，覆盖较为完整。
- **实践意义**：为万亿级 MoE 的部署提供了一条可落地的软硬件协同路径——在保持参考精度 89%–96% 的同时，获得 1.35–1.65× 内核加速与约 1.4× 能效提升，且端到端服务吞吐显著改善。
- **启示**：未来 MoE 压缩研究应把"执行栈可行性"纳入算法设计的一等约束，避免产生无法被现有内核高效执行的表示；同时需关注长程生成稳定性这一在联合稀疏量化下易被忽视的失效维度。
