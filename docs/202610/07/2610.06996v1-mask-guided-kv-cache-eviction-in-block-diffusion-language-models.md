## 摘要
块扩散语言模型在整个生成过程中维护大型键值（KV）缓存，并在每个去噪步骤都对其执行注意力，这限制了内存容量和生成速度。降低这些开销需要决定哪些历史 token 用于当前块去噪（选择），以及哪些保留在内存中供未来块使用（驱逐）。我们提出 MaskAhead，一种无需训练的方法，通过单一基于掩码查询的排序机制同时解决这两个任务。当前块的掩码指导选择，而对即将到来的掩码块的探测指导驱逐。两者均根据 KV 条目对注意力输出的估计贡献对其进行排序。我们的量化变体 Q-MaskAhead 直接从低比特 KV 计算选择和注意力，在很大程度上保留所选择的条目。在 Fast-dLLM-v2、DreamReasoner 和 LLaDA2.0-mini 上的实验涵盖长生成推理、长提示问答和“大海捞针”检索。在长提示问答上，相对于稠密推理，MaskAhead 平均将 KV 内存减少 9.5 倍，平均 F1 损失 1.2 个点。Q-MaskAhead 将减少幅度提高到 20.1 倍，平均 F1 损失为 2.3 个点。在 batch-32 系统性能剖析中，MaskAhead 相对于稠密推理实现了 1.23 倍的端到端加速和 1.68 倍的解码阶段加速。

## Abstract
Block diffusion language models keep a large key-value (KV) cache throughout generation and attend to it at every denoising step, limiting both memory capacity and generation speed. Reducing these costs requires deciding which past tokens to use for denoising the current block (selection) and which to keep in memory for future blocks (eviction). We propose MaskAhead, a training-free method that solves both tasks with a single mask-query-based ranking mechanism. Current-block masks guide selection, while probes of upcoming masked blocks guide eviction. Both rank KV entries by their estimated contribution to the attention output. Our quantized variant, Q-MaskAhead, computes selection and attention directly from low-bit KV, largely preserving the selected entries. Experiments on Fast-dLLM-v2, DreamReasoner, and LLaDA2.0-mini cover long-generation reasoning, long-prompt question answering, and needle-in-a-haystack retrieval. On long-prompt QA, MaskAhead reduces KV memory by $9.5\times$ on average with a 1.2-point mean F1 loss relative to dense inference. Q-MaskAhead increases the reduction to $20.1\times$ with a 2.3-point mean F1 loss. In a batch-32 systems profile, MaskAhead achieves $1.23\times$ end-to-end and $1.68\times$ decode-stage speedups over dense inference.

## 一、核心问题与整体含义（研究动机与背景）

- **背景**：扩散语言模型（dLLM）通过反复对掩码位置去噪实现并行解码，但并行解码会削弱同时预测 token 之间的依赖，因此当前系统普遍采用**块扩散（block diffusion）**：按块顺序生成，块内 token 并行去噪。块扩散恢复了因果前缀，也随之恢复了 KV 缓存。
- **核心痛点**：随着 prompt 与回答增长，每个新块都保留更多 KV 条目，每个去噪步骤都要读取更长的前缀。长上下文推理为同一段历史**付两次代价**——常驻缓存的显存占用，以及反复读取缓存的带宽/延迟开销。
- **两类决策的区分**（本文的关键切入）：
  - **选择（selection）**：当前块剩余去噪步骤要读哪些历史条目，是**临时读**，可随块刷新；
  - **驱逐（eviction）**：哪些条目要永久留在显存中供未来块使用，是**不可逆决策**。
- **已有工作的空白**：
  - 稀疏读取类方法（MAGE、HERALD、SparseD、FlashBlock）只减少读取，**完整前缀仍常驻 GPU**；HERALD 只是把全量缓存卸载到主机内存，并未物理驱逐。
  - 全注意力 dLLM 的驱逐方法（Sparse-dLLM、MaskKV）不适用于块扩散——后者掩码只出现在活跃块内，且不断把已定稿输出追加进精确缓存，需要**循环式、前瞻性**的驱逐。
  - 自回归（AR）驱逐方法（StreamingLLM、H2O、LookaheadKV、Expected Attention、LAQ、DapQ、CAOTE）必须在**不知道未来 query** 的前提下做保留决策。
- **核心洞察与整体含义**：块扩散在生成未来块之前就允许一次“query 探针”——掩码位置会暴露**以已知前缀为条件、由模型导出的 query**。本文用这些 query 作为驱逐的**前瞻预测信号**，同时用当前块 query 选择临时读取，从而在一个统一机制中同时解决选择与驱逐，并把“稀疏读取 / 驱逐 / 量化”三种能力首次合并（见论文 Table 1）。

## 二、方法论

### 2.1 形式化设定
- 设 $I_{t,\ell,h}$ 为块 $t$、层 $\ell$、KV 头 $h$ 的活跃前缀条目集合。
- 读集合 $R_{t}\subseteq I_t$，受读预算 $k_t$ 约束；保留集合 $S_{t}\subseteq I_t$，受保留预算 $C_t$ 约束。读缓冲在驱逐前采集，因此当前块仍能访问所选条目；保留集合须服务后续块以及下一个检查点的首步。
- 两个理想目标分别最小化两类误差：
  - $\mathcal{L}_{\text{read}}(R_t)$：对块 $t$ **后续去噪步骤 query 集合** $Q^{later}_t$ 的注意力输出误差；
  - $\mathcal{L}_{\text{retain}}(S_t)$：对块 $t+1$ 至 $t+E$ **实际实现 query** $Q^{realized}_j$ 的误差。
  - 作者明确声明：这只是**决策视野的描述，并非实现所精确优化的目标**（尤其 $Q^{realized}_j$ 在决策时未知）。
- **诊断实验（Figure 1，MATH-500 全缓存轨迹，n=30）**：当前块第 8 步，共享读集合覆盖 97.75% 前缀注意力质量，同预算下重新选择为 98.50%（n=29）；**一个块之后**旧集合覆盖降至 74.69%，**四个块后**仅 62.16%。这说明块内复用足够好，跨块会显著衰减，因此**每块刷新读选择**是必要的。

### 2.2 打分函数：注意力输出敏感度
- 单条目删除并重归一化后可得恒等式：
  $\;\lVert o_q - o_{q,-i}\rVert^2 = \dfrac{p_{q,i}}{1-p_{q,i}}\,\lVert v_i - o_q\rVert^2$
  即**相同注意力质量的不同条目，对输出的影响可以不同**（value 与当前输出的偏离程度起作用）。
- 面向 query 群体的池化打分：
  - $a_i(\mathcal{Q}) = \frac{1}{|\mathcal{Q}|}\sum_{q\in\mathcal{Q}} p_{q,i}$（query 群体上的平均注意力权重）
  - 注意力质心 $c(w)=\frac{\sum_j w_j v_j}{\sum_j w_j}$
  - 打分 $f_i(w) = w_i \lVert v_i - c(w)\rVert^2$（用相关性加权的 value 偏离量）
- 作者强调：该恒等式只适用于**单条目删除**，并不真正求解子集选择问题，它只是打分的动机。

### 2.3 两个 query 视野 + 算法流程
- **读打分**：$s^{\text{read}}_i = f_i\big(a(Q^{(1)}_t)\big)$，使用块 $t$ **首个全掩码步骤**的 query。
- **保留打分**：$s^{\text{retain}}_i = f_i\big(\sum_{m=1}^{M} a(Q^{(m)}_t)\big)$，累加当前块与未来 $M-1$ 个块的掩码探针 query。
- **算法流程（Algorithm 1）**：
  1. 对活跃缓存 $I_t$ 执行块 $t$ 首个全掩码步骤，收集 $Q^{(1)}_t$；
  2. 按 $s^{\text{read}}$ 取 top-$k_t$ 组成**临时读缓冲**；
  3. 若 $t$ 是驱逐检查点：在块 $t+1,\dots,t+M-1$ 放置掩码做**无写入探针**（不追加 KV、不产出草稿 token），得到 $Q^{(2..M)}_t$；
