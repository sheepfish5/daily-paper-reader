## 摘要
现代GPU越来越多地将张量核心集成到执行流水线中。尽管总体张量吞吐量持续增长，得益于操作数供给从Ampere中的基于寄存器发展到Hopper和Blackwell中的无冗余、基于内存的供给方式，但高效编排现代AI工作负载的完整张量计算流水线仍然具有挑战性。我们确定基本瓶颈是固定并行性和粗粒度调度，这两者都被现代AI工作负载所暴露，这些工作负载将各种非GEMM操作与GEMM交织在一起。为了高效编排张量计算，我们提出了FIBER，一种扩展GPU SIMT（单指令多线程）模型的新架构。其基本执行实例——纤程（fiber）——与私有寄存器所有权解耦，仅携带最少的控制状态，同时通过共享视图访问SM的寄存器。这实现了动态并行扩展、细粒度的寄存器级数据流调度，并为矩阵操作数供给提供了一种无冗余的替代方案。我们扩展了ISA、微架构和编译器，以实现共享寄存器寻址、无冲突的操作数传递和基于纤程的程序映射。在典型的混合精度LLM服务场景中，FIBER在Ampere上实现了2.25倍的端到端加速（原始FP16计算为1.15倍），在Hopper和Blackwell上分别实现了1.8倍和2.09倍的加速，内核级提升高达2.49倍。

## Abstract
Modern GPUs increasingly integrate Tensor Cores into the execution pipeline. Although aggregate tensor throughput continues to grow, aided by an operand supply that has evolved from register-based in Ampere to redundancy-free, memory-based in Hopper and Blackwell, efficiently orchestrating the complete tensor compute pipeline for the modern AI workloads remains challenging. We identify the fundamental bottlenecks as fixed parallelism and coarse-grained scheduling, both of which are exposed by modern AI workloads that interleave diverse non-GEMM operations with GEMM. To orchestrate tensor computation efficiently, we propose FIBER, a new architecture that extends the GPU SIMT (single instruction, multiple thread) model. Its basic execution instance, the \emph{fiber}, is decoupled from private register ownership, carrying only minimal control state while accessing an SM's registers through a shared view. This enables dynamic parallelism scaling, fine-grained register-level dataflow scheduling, and offers a redundancy-free alternative for matrix operand supply. We extend the ISA, microarchitecture, and compiler to realize shared-register addressing, conflict-free operand delivery, and fiber-based program mapping. Under a typical mixed-precision LLM serving scenario, FIBER achieves a 2.25x end-to-end speedup on Ampere (1.15x for the original FP16 computation), with 1.8x and 2.09x on Hopper and Blackwell respectively, and kernel-level gains up to 2.49x.

## 1. 论文的核心问题与整体含义（研究动机和背景）

- **背景**：现代 GPU 加速器（如 NVIDIA Tensor Core、AMD Matrix Core）的矩阵计算吞吐量持续增长，尤其从 Ampere 时代的寄存器操作数供给，演进到 Hopper/Blackwell 时代的共享内存/张量内存（SMEM/TMEM）操作数供给，实现了**无冗余（redundancy-free）** 的矩阵操作数加载方式，解决了纯 GEMM 场景下寄存器供给的带宽瓶颈。
- **核心问题**：尽管 Tensor Core 的峰值算力不断提升，现代 AI 工作负载（尤其是 LLM 推理）**并非纯 GEMM 负载**，而是由 GEMM 与非 GEMM 操作（如 Softmax、RoPE、SiLU、归一化等）**交织混合**而成。论文识别出当前 SIMT 执行模型下编排完整张量计算流水线的两个根本瓶颈：
  - **固定并行度（Static Parallelism）**：SIMT 模型中线程数量与私有寄存器预算在启动时固定，无法适应不同计算阶段对并行度与寄存器的动态需求；CUDA Dynamic Parallelism 依赖有显著开销的嵌套内核启动，无法在单内核内灵活调整。
  - **粗粒度调度（Coarse-grained Scheduling）**：自 Hopper 起，TC 的数据流以 warp-group 粒度、基于阶段（phase）的粗粒度批量同步来组织（如 `wgmma` + `mbarrier` + `named_barrier`），依赖跟踪粒度粗糙，导致同步开销增大（论文分析 FA4 中同步停顿占 CPI 的 26%），且编程复杂性高。
- **整体含义**：论文主张需要**重新思考执行实例与寄存器之间的绑定关系**，提出一种新的 GPU 执行模型，使并行度可以动态扩展、数据流调度可以在寄存器粒度进行细粒度编排，同时保留无冗余的 TC 操作数供给。

## 2. 论文提出的方法论：核心思想、关键技术细节

### 核心思想
提出 **FIBER** 架构——一种**线程-寄存器解耦（Thread-Register Decoupled）** 的 GPU 执行模型，扩展 SIMT 模型。其核心概念为：

- **Fiber（纤程）**：新的基本并行执行实例，携带极少的架构状态（PC、标识符、控制标志），**不拥有私有寄存器**；SM 内的所有 fiber 通过**共享寄存器视图（shared register view）** 访问统一的物理寄存器文件。
- **Weft（纬纱）**：由以锁步方式执行同一指令的 32 个 fiber 组成，类比 SIMT warp，但具有共享寄存器语义。
- 该模型使调度器可以在运行时动态调整活跃 fiber 数量（不再受启动时私有寄存器分配限制），支持更大规模的驻留并行度，并支持跨 fiber/weft 的寄存器级数据流与细粒度依赖跟踪。

### 关键技术细节

1. **ISA 扩展（3 类）**：
   - **共享寄存器寻址**：利用 SASS 编码中仅有的 13 个未用位，将源操作数寄存器字段扩展到 11 位（32 对齐的向量寄存器粒度，覆盖 SM 内 2048 个向量寄存器），其中每源操作数增加 2 位选择子分区（subpartition）+ 1 位使能信号；目标寄存器仍保持本地子分区写入（远程写被禁止，由编译器改写为远程读 + 本地写）。
   - **SET_FIBER_NUM 指令**：支持动态并行度——所有 fiber 同步到达该指令后，硬件按立即数配置活跃 fiber 数量；增加时初始化新 weft 上下文并置 PC 为当前指令（spawning fibers），减少时屏蔽多余上下文。
   - **扩展 DEPBAR 指令**：支持细粒度跨 fiber 依赖跟踪——寄存器忙位图包含 **empty**（数据尚未就绪）和 **full**（数据正在被读取/使用）两组状态；指令通过 set/clear 操作来协调跨 weft 的寄存器级数据流。

2. **微架构增强**：
   - **Selector（选择器）**：根据源操作数扩展位确定访问哪些子分区寄存器组的 8 个读端口。
   - **Crossbar（交叉开关）**：4×4 的 32 通道交叉开关，将远程子分区的操作数路由到请求子分区。
   - **Read Port Arbiter（读端口仲裁器）**：解决跨子分区共享寄存器访问带来的端口冲突，采用旋转起始位置（rotating start）保证公平性，并利用相同地址检测避免不必要的停顿。
   - **Register Busy Bitmap（寄存器忙位图）**：两组各 2048 位的位图，分别对应 empty 和 full 状态，支持寄存器粒度的跨 fiber 依赖跟踪；默认由硬件自动维护，也可通过 DEPBAR 指令显式覆盖。
   - **动态并行度支持**：调度器维护最多 64 个 weft 上下文/子分区（类比基线 GPU 每 SM 48 warp），上下文开销与基线相当。

3. **软件栈（编程模型与编译器）**：
   - **CUDA-native 模式**：兼容现有 CUDA 程序，寄存器视为私有，通过源到源变换插入 `SET_FIBER_NUM` 和固定子分区偏移。
   - **FIBER-native 模式**：通过 `__pool__` 声明共享寄存器，暴露 SM 级统一寄存器视图；程序员可动态指定 fiber 数量、使用 `set_busy_bit()` 手动管理寄存器依赖状态；编译器负责共享寄存器的分配（空闲列表 + 活跃性分析）、MMA 操作数放置以最小化 bank 冲突，以及远程写的等价改写。

## 6. 论文的主要结论与发现

- FIBER 在典型混合精度（W4A16）LLM 服务场景中，对 Ampere、Hopper、Blackwell 分别实现 **2.25×、1.8×、2.09×** 端到端加速；FP16 原始计算对应为 1.15×、1.13×、1.11×。
- 内核级增益最高达 **2.49×**（Ampere 混合精度 FFN）。
- 注意力前向在 Ampere/Hopper/Blackwell 上分别加速 1.42×/1.57×/1.4×，TC 利用率超过 95%；纯 GEMM 投影无明显加速（<1.1×），因为已受 TC 算力饱和限制。
- 消融实验表明：DP 是最大贡献者（对多数负载带来显著收益），FS 对同步开销大的负载（如投影）效果最好，RS 对交织操作密集的负载（如 MQA、混合精度计算）增益明显。
- 硬件开销极小：总面积增加 <0.1%，功耗增加 <0.4%（每 SM 面积 5308.1 μm²，功耗 10.75 mW，延迟 0.34 ns）。
- 即使在极紧张的硬件预算下（无 crossbar、无 busy bitmap），DP 仍可保证，仅需 1 位地址扩展。

## 7. 优点

- **问题识别精准**：用数据（活寄存器跟踪、CPI 分解）清晰地量化了静态并行度和粗粒度调度两个瓶颈。
- **架构设计巧妙**：在现有 SASS 编码仅有 13 位未用空间和物理寄存器按子分区组织的双重约束下，利用 32-lane 对齐访问模式（只需 11 位地址）和禁止远程写（由编译器改写）两个洞察，实现了共享寄存器寻址，设计非常务实。
- **与现有硬件高度兼容**：保留原有物理寄存器组织和流水线，新增模块简单（选择器、交叉开关、仲裁器、位图），硬件开销极低；同时保持与 CUDA SIMT 程序的完全兼容。
- **实验设计严谨**：a) 使用 GTSim 模拟器（经过跨代际验证，误差可控）；b) 三重机制（DP/FS/RS）的逐步消融；c) 概念验证 oracle 实验先行，为设计目标提供数据支撑；d) RTL 综合验证硬件开销可行性；e) 覆盖推理、训练、解码多种场景。
- **编程模型清晰**：`__pool__` + `set_fiber_num` + `set_busy_bit` 三个原语简洁且表达能力充分；CUDA-native 模式促进采用。
- **提供通用设计原则**：解耦执行实例与寄存器所有权这一思想具有一定普适性，对后续 GPU 架构发展（如 Blackwell tensor memory）有参考价值。

## 8. 不足与局限

- **纯模拟验证**：FIBER 的性能均由 GTSim 模拟器产生，未进行真实硬件流片或 FPGA 原型验证；模拟器虽然校准了基线，但对 FIBER 新硬件机制的建模准确性缺少实测对照。
- **编译器实现深度不足**：编译器部分描述较粗略，未说明实际工具链实现方式和端到端编译效果；寄存器分配和远程写改写等核心 pass 的复杂度、对代码生成质量的影响缺少定量评估。
- **工作负载覆盖面有限**：仅评估了 Llama 模型和类 FlashAttention 负载，未覆盖视觉 Transformer、MoE、推荐系统等更广泛工作负载；对解码阶段的加速效果较弱（1.12×），说明 FIBER 对非 TC 密集、内存受限场景的普适性有限。
- **未考虑可扩展性问题**：对于更大规模 GPU（更多 SM）或更宽 TC 时的扩展性、跨 SM 共享寄存器的可行性未深入讨论。
- **潜在公平性问题**：Hopper/Blackwell 基线的注意力实现分别使用 FA3/FA4，但未在同一硬件上对比不同注意力版本；FA3报告的 TC 利用率比 FA2 低，可能受算法-硬件配比影响，与 FIBER 的比较中基线选择可能存在偏差。
- **动态并行的软件语义尚不清晰**：动态调整 fiber 数量时，寄存器状态的保存/恢复、fiber 间通信的语义边界等细节未充分展开；多个 FIBER-thread 共享 SM 时的资源分区策略也未明确。
- **多精度和数值精度**：混合精度（W4A16）的数值精度、误差传播等未涉及，仅关注性能。
