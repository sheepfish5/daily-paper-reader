## 摘要
高性能GPU内核支撑着现代深度学习和科学计算。随着工作负载日益多样化以及GPU硬件的快速演进，开发高效的自动化GPU内核生成与优化方法变得愈发重要。现有的基于大语言模型（LLM）的方法通常在固定的实现空间内进行优化，这限制了优化灵活性或搜索效率。我们提出了\textsc{HIERA}，一种用于GPU内核优化的层次化搜索空间规划框架。\textsc{HIERA}构建了契约增强的任务规范，在PyTorch算子、CUDA库和自定义CUDA内核之间选择合适的实现空间，并利用性能分析反馈和专家知识来指导结构化的迭代优化。在KernelBench上跨多个不同工作负载级别和基础LLM的实验表明，与现有的无训练方法相比，\textsc{HIERA}在整体实现有效性、样本效率和优化性能方面表现更强，同时无需额外模型训练即可与基于训练的CUDA-L1相媲美。针对科学计算中专用模板算子的案例研究进一步实现了比cuDNN高\(1.53\times\)的加速，展示了该通用框架在标准机器学习工作负载之外的潜力。

## Abstract
High-performance GPU kernels underpin modern deep learning and scientific computing. As workloads become increasingly diverse and GPU hardware evolves rapidly, developing efficient methods for automated GPU kernel generation and optimization has become increasingly important. Existing LLM-based methods typically optimize within a fixed implementation space, limiting either optimization flexibility or search efficiency. We propose \textsc{HIERA}, a hierarchical search-space planning framework for GPU kernel optimization. \textsc{HIERA} constructs contract-augmented task specifications, selects an appropriate implementation space across PyTorch operators, CUDA libraries, and custom CUDA kernels, and uses profiling feedback and expert knowledge to guide structured iterative refinement. Experiments on KernelBench across multiple various workload levels and base LLMs show that \textsc{HIERA} delivers stronger overall implementation validity, sample efficiency, and optimization performance than existing training-free methods, while remaining competitive with the training-based CUDA-L1 without additional model training. A case study on a specialized stencil operator from scientific computing further achieves a \(1.53\times\) speedup over cuDNN, demonstrating the potentiality of the general framework beyond standard machine-learning workloads.

## 1. 论文的核心问题与整体含义

- **研究背景**：高性能 GPU 内核是现代深度学习和科学计算的基础。现有库原语（如 cuBLAS、cuDNN、PyTorch 算子）难以覆盖日益多样化的专用工作负载，且硬件快速演进使手工优化成本高昂。
- **核心问题**：现有基于 LLM 的 GPU 内核优化方法通常在一个**固定的实现空间**内进行搜索（例如只允许自定义 CUDA，或只允许高层算子），导致两个问题：
  - 高层原语空间虽实现简单，但可能丢失自定义融合、形状特化等优化机会；
  - 纯 CUDA 空间自由度大，但搜索空间庞大且低层决策耦合，在有限预算下容易产生大量编译/正确性失败，且 profiling 反馈无法跨空间指导实现粒度选择。
- **整体含义**：论文主张将“实现空间选择”本身作为显式的优化决策，提出 HIERA，一个跨实现空间（PyTorch 算子、CUDA 库、自定义 CUDA 内核）进行层次化规划的工作负载感知框架，以在有限搜索预算下平衡实现可靠性与优化性能。

## 2. 论文提出的方法论

- **总体流程**：HIERA 包含四个核心阶段：
  1. **契约增强任务规范**：将 KernelBench 任务转换为明确的可调用接口、参数语义、编译规则和验证行为，固定外围文件（`torch_demo.py`、`cpp_source.cpp`、`groundtruth.py` 等），模型只生成 `cuda_source.cu`。
  2. **跨粒度搜索空间规划**：Search-Space Decision Agent (SSDA) 在三个嵌套实现空间中选择一个：
     - `pure CUDA`（仅自定义 CUDA 内核）；
     - `CUDA libraries`（额外允许 cuBLAS 等优化库）；
     - `CUDA libraries with PyTorch operators`（进一步允许高层 PyTorch 算子）。
  3. **领域引导的优化方向剪枝**：SSDA 从五个方向中评分并选择主方向：
     - 控制流与边界特化 (C)；
     - 线程/线程束级并行 (P)；
     - 内存事务效率 (M)；
     - 数据复用与移动流水线 (R)；
     - Tensor Core 与指令流水线利用 (T)。
     随后 Strategy Planning Agent (SPA) 将方向转化为具体策略，Optimization Agent (OA) 生成下一轮候选。
  4. **反馈驱动的迭代优化**：候选经编译、正确性验证、延迟测量和 NCU profiling，保留最强候选作为下一轮父本，形成闭环。

- **数学形式**：优化目标为在预算 B 内寻找满足约束且加速比最大的候选实现，加速比定义为参考实现延迟与候选实现延迟之比。

## 3. 实验设计

- **Benchmark**：KernelBench 前三个级别，共 250 个任务：
  - Level 1：100 个算子级任务；
  - Level 2：100 个融合算子任务；
  - Level 3：50 个模型级工作负载。
- **对比方法**：
  - KernelBench-Caesar（官方迭代工作流，无训练）；
  - CUDAForge（Coder–Judge 固定 CUDA 空间的反馈优化）；
  - CUDA-L1（基于对比强化学习的训练型方法，仅作参考，不随 base LLM 变化）。
- **基础 LLM**：DeepSeek-V3.2、Qwen3.6-Plus、Gemini-3.6-Flash。
- **实验设置**：每任务最多 18 个候选（3 轮 × 6 个），温度 0.3，FP32，A100 GPU；评估指标为 fast 0（有效实现比例）、fast 1（超过参考比例）、fast 2（2× 加速比例）。
- **专项实验**：
  - 固定实现空间对比：在 90 个抽样任务（每级 30 个）上比较 Pure CUDA、CUDA Libraries、CUDA Libraries + PyTorch、HIERA；
  - 消融实验：HIERA w/o Contract（去掉契约增强）和 HIERA w/o Planning（去掉层次规划）；

## 6. 论文的主要结论与发现

- HIERA 在有限预算下显著优于无训练基线：
  - B=1 时 fast 0 为 71.6%，fast 1 为 32.4%，分别比 KernelBench-Caesar 高 30.8 和 22.4 个百分点，比 CUDAForge 高 52.4 和 13.6 个百分点；
  - B=18 时 fast 0 为 92.4%，fast 1 为 60.4%，同样领先。
- 在 fast 1（实际加速）指标上，HIERA 在无训练方法中始终第一，表明其不仅提高正确率，更能转化为实际性能提升。
- 与训练型 CUDA-L1 相比，HIERA 无需额外训练，在 Level 1 和 Level 2 的平均指标上反而超过 CUDA-L1。
- 实现空间选择影响巨大：Pure CUDA 虽可达最大加速（9.32×），但均值中位数低、方差大；混合空间更稳定；HIERA 通过自适应选择获得了最高均值（1.42×）和中位数（1.15×），同时方差比 Pure CUDA 降低 23.4%。
- 消融实验表明：契约增强主要提升实现可行性（尤其复杂任务），层次规划主要提升加速效果（如 Level 2 的 fast 1 从 6% 提升至 62%）；两者互补。
- 案例研究：stencil 计算从初始 13.71 ms 降至 4.71 ms，比 cuDNN（7.23 ms）快 1.53×。
