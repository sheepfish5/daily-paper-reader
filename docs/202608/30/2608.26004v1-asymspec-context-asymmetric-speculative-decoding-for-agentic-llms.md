## 摘要
Agentic大语言模型流水线在检索、工具使用和多轮交互过程中积累上下文，导致推理成本不断攀升。为控制延迟，实际部署中常对输入进行压缩，但这会降低任务准确率。投机解码（SD）无损加速生成，但其前提是草稿模型和验证模型共享相同上下文，这使SD无法解决准确率与开销之间的权衡问题。我们提出AsymSpec，一种打破这种对称性的非对称投机解码框架：轻量级草稿模型读取完整输入，而大型验证模型在压缩视图上运行。草稿模型通过对比式δ-对数几率融合来引导验证模型，并由一个发散感知接受门调控，以保持验证稳定性和高草稿接受率。在四项Agentic能力和两个端到端Agent基准上的评估显示，AsymSpec平均达到全上下文准确率的约90%，在孤立文本能力上以0.2–0.3倍计算成本实现1.3–1.7倍吞吐量加速。这些结果表明，恰恰在压缩丢弃关键推理信号时，非对称上下文访问能带来显著收益。

## Abstract
Agentic LLM pipelines face escalating inference costs as context accumulates across retrieval, tool use, and multi-turn interactions. To control latency, deployments routinely compress inputs, but this degrades task accuracy. Speculative decoding (SD) accelerates generation losslessly, yet it assumes the drafter and verifier share an identical context, preventing SD from resolving the accuracy-overhead trade-off. We propose AsymSpec, an asymmetric speculative decoding framework that breaks this symmetry: a lightweight drafter reads the full input while the large verifier operates on the compressed view. The drafter steers the verifier via a contrastive $δ$-fusion of logits, modulated by a divergence-aware acceptance gate that preserves verification stability and high draft acceptance rates. Evaluated across four agentic capabilities and two end-to-end agent benchmarks, AsymSpec reaches $\approx 90\%$ of full-context accuracy on average, delivering $1.3$--$1.7\times$ throughput speedups at $0.2$--$0.3\times$ the compute cost on isolated text capabilities. These results show that asymmetric context access yields substantial gains precisely when compression discards critical reasoning signals.

## 1. 论文的核心问题与整体含义

- **研究动机**：Agentic LLM 流水线（检索、工具调用、多轮对话等）中，上下文随每一步执行不断累积，导致前向计算成为主要延迟瓶颈，推理成本急剧上升。
- **现有应对方式的矛盾**：为控制延迟，部署中普遍对输入进行压缩（如摘要、截断、保留 API 签名等），但压缩会丢弃对任务精度至关重要的细粒度信息，形成“精度-开销”的两难。
- **投机解码（SD）的局限**：SD 能无损加速生成，但所有现有 SD 方法都隐含假设草稿模型（drafter）与验证模型（verifier）处理相同的输入上下文。因此 SD 只能加速固定目标分布，无法恢复被压缩模型丢失的信息——要么双方承受全上下文成本，要么双方接受压缩损失。
- **论文的核心洞察**：计算开销存在结构性不对称——每步延迟由大型验证模型主导，轻量草稿模型开销可忽略。因此可以只压缩验证模型的输入来获得大部分延迟节省，同时让草稿模型读取完整输入来弥补信息损失。
- **整体含义**：AsymSpec 打开了一个全新的工作点——以压缩验证器的成本获得接近全上下文的准确率，为 Agentic LLM 的高效推理提供了一种“非对称上下文访问”的新范式。

## 2. 方法论

### 2.1 核心思想
- 打破 SD 的对称上下文约束：验证模型 L 严格运行在压缩视图 x_comp 上，草稿模型 S 读取完整输入 x_full。
- 利用轻量草稿模型的双重前向：在同一解码步中，S 分别处理 x_full 和 x_comp，产生两个 logits 向量 a 和 b，其差值 δ = a - b 被定义为“上下文增益信号”，用于引导验证模型。

### 2.2 关键技术细节
- **对比式 δ-fusion**：
  - δ = a - b 消除了草稿模型自身的上下文无关偏好，隔离出由完整输入带来的信息增益。
  - 当草稿被拒绝时，将 δ 以权重 β 融合进验证模型的 logits：输出 argmax(t + βδ)。
- **Context-Divergence Acceptance（CDA）门**：
  - 使用逐位置 Jensen–Shannon 散度（JSD）衡量全/压缩视图输出分布差异 D_i。
  - 有效接受阈值为 γ_eff(i) = γ · exp(−D_i)，利用 JSD 的严格上界 ln2 保证 γ_eff ∈ [γ/2, γ]，无需额外超参数。
  - 当上下文发散较大时，阈值放宽，允许更多包含上下文增益的草稿通过，保持验证稳定性与高接受率。
- **算法流程**（每步）：
  1. S(x_full) 自回归采样 K 个草稿 token，记录对应位置 logits a。
  2. S(x_comp) 计算相同 K+1 位置 logits b。
  3. L(x_comp) 并行评分所有草稿，得到 logits t。
  4. 计算 δ_i、D_i、γ_eff(i)，并按接受准则逐位置接受草稿。
  5. 首个拒绝位置发射 δ-fusion 后的 token，否则发射验证模型的最终 token。
- **跨模态扩展**：由于 δ 和 γ_eff 完全在输出词汇空间计算，草稿模型可以换成视觉-语言模型处理原始图像，验证模型仍为文本-only 模型处理标题/OCR 文本，投机循环不变。

## 6. 主要结论与发现

- AsymSpec 在四类文本 Agentic 能力上，以 0.2–0.3× 的 FLOPs 成本达到全上下文准确率的约 90%（59%–94% 的 Floor–Ceiling 差距闭合）。
- 吞吐加速 1.3–1.7×（超过 Ceiling），计算节省显著（API-Bank 低至 0.19×）。
- 精度恢复程度随压缩严重性**单调**变化：压缩越激进，AsymSpec 相对 Floor 的提升越大；压缩接近无损时（如 MultiChallenge）增益自然消失，证明机制针对的是信息丢失而非任务过拟合。
- 跨模态设置中，视觉-语言草稿可将文本-only 验证器扩展到视觉推理任务，MathVista 上比对称 SD 高 10.1 点。
- 端到端 agent 循环中，AsymSpec 在上下文章节在线重新压缩的条件下仍保持高草稿接受率（0.88–0.90），且精度不退化（GAIA 24.2%，SimpleQA 65.0%，均超过或持平可用全上下文参考）。
- 消融证明：CDA 门与 δ-fusion 缺一不可；same-model cross-context 的 δ 来源（a−b）显著优于 raw-aug（a）和 SCD-style（t−b）；跨家族 Qwen–Llama 组合也可获得恢复收益。

## 7. 优点

- **打破了 SD 的对称上下文约束**，提出“轻量草稿读全、重型验证读压缩”的全新框架，概念清晰且具通用性。
- **对比式 δ-fusion 设计精巧**：同模型在两个上下文上的 logits 之差可有效抵消草稿自身偏好，纯粹提取上下文增益信号。
- **CDA 门参数自由**：利用 JSD 的有界性推导出 γ_eff = γ·exp(−D) 的闭式形式，无需逐数据集调参，且具有合理的数学公理化推导。
- **跨模态扩展自然**：在输出词表空间操作，使视觉-语言草稿和文本-only 验证器协同工作，拓展了应用范围。
- **实验设计全面系统**：从静态能力到动态 agent 循环，从同族到跨家族模型，从机制消融到压缩器/超参数鲁棒性，证据充分。
- **提供了清晰的决策准则**：压缩损失越严重，AsymSpec 收益越大，便于实际部署判断何时使用。

## 8. 不足与局限

- **信息恢复上限**：受压缩视图保留的信息量和草稿模型容量约束，无法完全重建多跳推理链或细粒度像素级线索，跨模态设置中上限受图像-标题翻译质量限制。
- **适用范围受限于 logits 访问**：需要验证模型的 logits，因此不适用于仅暴露生成文本的专有 API。
- **仅支持贪心解码（τ=0）**：虽然作者论证了 agentic 工作流对结构化输出确定性的要求，但缺乏对随机采样场景的形式化推广。
- **跨家族可迁移性不足**：Qwen–Llama 组合需显式词汇对齐，恢复效果随模型对变化，通用性有限。
- **计算资源信息缺失**：未报告 GPU 型号/数量/时间，难以评估实际部署成本。
- **端到端延迟受多重因素影响**：真实 agent 循环中的 wall-clock 还包括工具执行和网络 I/O，AsymSpec 仅优化 LLM 推理瓶颈；GAIA 文件子集上 VL-2B 草稿甚至低于 Floor（因 2B 文本容量不足）。
- **部分实验报告完整性稍弱**：MultiChallenge 使用 llm-judge 的单次运行，未报告多 judge 方差；MathVista 与 GAIA file 子集的参考上界定义与主实验不完全一致。
