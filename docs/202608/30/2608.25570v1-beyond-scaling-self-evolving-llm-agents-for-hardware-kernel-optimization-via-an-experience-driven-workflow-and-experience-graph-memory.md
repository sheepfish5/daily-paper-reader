## 摘要
硬件内核优化需要重复的编译、正确性测试、性能剖析与修订。LLM智能体可以自动化该过程的某些部分，而更强的基础模型、更长的上下文窗口以及更长的执行周期已改善了单个任务内的优化效果。然而，仅凭这些进展并不能让智能体从已完成的优化运行中学习。现有的内核优化智能体很少保留某个决策、其观察到的执行反馈，以及后来使用该证据的后续决策。保留所有先前的轨迹也不切实际，因为不断扩大的历史记录会与当前任务争夺上下文。我们提出了KOPE，一种用于硬件内核优化的经验驱动框架。KOPE在经验图内存中记录带有正确性与性能反馈的优化轨迹，然后通过主动上下文管理与注入，在固定的token预算下检索相关经验。该图保留了决策顺序、观察到的结果以及替代分支，使得在目标硬件上收集的证据能够为后续的优化步骤和任务提供信息。在相同的GLM-5.2设置下，KOPE每个算子加速比的几何平均值是最强竞争基线CANNBot的1.54倍。在完整的53算子消融实验中，主动上下文管理与注入将通过率从60.0%提升至84.6%，将评估器报告的正向字段几何平均值从0.0382提升至0.0661，并将优化token消耗从15.9B降至1.113B（相对于被动智能体主导的上下文构建）。启用经验图内存将全套通过率从55.2%提升至84.6%，并在有效计时比较中产生1.43倍的几何平均加速比。这些结果支持在基础模型保持固定的情况下，通过外部经验进行持续优化。

## Abstract
Hardware kernel optimization requires repeated compilation, correctness testing, profiling, and revision. LLM agents can automate parts of this process, and stronger foundation models, longer context windows, and longer execution horizons have improved optimization within individual tasks. These advances alone do not enable an agent to learn from completed optimization runs. Existing kernel-optimization agents seldom preserve a decision, its observed execution feedback, and the later decisions that use that evidence. Retaining every prior trajectory is also impractical because an expanding history competes with the current task for context. We present KOPE, an experience-driven framework for hardware kernel optimization. KOPE records optimization trajectories with correctness and performance feedback in Experience Graph Memory, then uses Active Context Management and Injection to retrieve relevant experience under a fixed token budget. The graph retains decision order, observed outcomes, and alternative branches, allowing evidence collected on the target hardware to inform later optimization steps and tasks. Under the same GLM-5.2 setting, the geometric mean of KOPE's per-operator speedups is $1.54\times$ that of CANNBot, the strongest competing baseline. In a complete 53-operator ablation, Active Context Management and Injection raises pass rate from 60.0\% to 84.6\%, increases the evaluator-reported positive-field geometric mean from 0.0382 to 0.0661, and reduces optimization token consumption from 15.9B to 1.113B tokens relative to passive agent-led context construction. Enabling Experience Graph Memory raises full-suite pass rate from 55.2\% to 84.6\% and yields a $1.43\times$ geometric-mean speedup on valid timing comparisons. These results support continual optimization through external experience while the foundation model remains fixed.

## 1. 核心问题与整体含义

- 硬件内核优化是高度依赖专家经验的过程，需要反复进行编译、功能测试、性能剖析与代码修订。
- 现有 LLM 智能体（如 ASTRA、CANNBot、CUDA-Agent 等）通过更强的基础模型、更大的上下文窗口和更长的执行轨迹改善了**单个任务内**的优化效果，但存在一个关键缺陷：**无法从已经完成的优化运行中积累并复用经验**。
- 简单保留所有历史轨迹也不可行，因为不断膨胀的历史记录会与当前任务争夺有限上下文，反而恶化性能（引用 "Lost in the Middle" 与 RULER 的研究）。
- 核心研究问题：**在硬件公开训练数据稀缺的场景下，如何让 LLM 智能体将探索过程中的执行反馈转化为可复用知识，并跨优化步骤、跨任务地加以应用？**
- 论文提出 **KOPE**（Knowledge-driven Optimization with Persistent Experience）框架，在不更新基础模型参数的前提下，通过外部经验驱动的方式实现"自进化"，回答了上述问题。

## 2. 方法论

### 核心思想

- KOPE 将每次优化尝试视为一次**学习事件**：执行反馈不仅用于修复当前候选内核，还作为持久化证据影响后续决策。
- 核心原则：**正确性优先于性能**。候选内核只有在通过编译与数值正确性验证、且确实改善目标指标时，才替换当前最优实现；失败的尝试同样作为负例被保留。
- 基础模型参数保持固定，"自进化"体现在**外部经验**（图记忆）的持续更新与选择性注入。

### 形式化描述

每轮迭代可表示为：

- `z_t,k = R(s_t,k, M_t,k)`：检索相关经验
- `C_t,k = I(s_t,k, z_t,k; B)`：在预算 B 下组装提示
- `a_t,k = π_θ(C_t,k)`：固定参数的 LLM agent（π_θ）产生候选动作
- `y_t,k = E(a_t,k)`：执行环境返回编译诊断、正确性与性能反馈
- `M_t,k+1 = U(M_t,k, s_t,k, a_t,k, y_t,k)`：更新持久记忆

任务间经验持续传递，`M_t+1,0 = M_t,K_t`。

### 经验图内存（KOPE-Mem）

- **双表示机制**：每个事件同时记录为（1）追加式 Markdown 探索日志（Journal）——包含策略、代码变更、验证状态、测量与解读；（2）结构化 JSON 案例（Case）——包含算子、输入场景、优化思路、前后代码、反馈、正确性、绝对加速比、置信度及 provenance 标识。
- **决策-结果有向图**：节点为决策+结果，边表示优化状态上的继承/分支关系；当前为有向无环森林（每个节点至多一个前驱、多个后继），边记录血统而非因果断言。
- **图感知检索与排序**：先按精确过滤（算子、优化层、思路 ID、结果标签）建立候选池，再由语义检索补充跨任务可迁移的 Journal/摘要；然后计算**折扣下游结果分数**：
  - `d(v) = 0.5·r_v + 0.5·γ·Σ_{u∈succ(v)} d(u)`，γ = 0.7
  - `r_v` 为步骤加速比（绝对加速比 / 前驱加速比），由结果标签（effective / partial / ineffective / negative）分桶，置信度作为桶内排序依据

### 主动上下文管理与注入

- **动态上下文分层**（按优先级而非永久存储位置）：
  - **Hot**：内核规范、当前最优代码、最新反馈、优化目标（必须包含）
  - **Warm**：针对当前状态检索到的案例、日志摘要、程序性知识（含成功动作与失败模式）
  - **Cold**：更广泛的文档、跨类别经验、较旧摘要
- **预算感知组装**：可用知识预算 `B_k = max(0, W − S − G − R)`（模型窗口 − 系统提示 − 生成预留 − 近期保留），依次满足 Hot 载荷、Warm 上限 `Q_w`、Cold 上限 `Q_c`。
- 该方法在**模型调用前选择外部材料**，与推理时的 KV-cache 淘汰（Bui et al. 2026）作用阶段不同，可以互补。

## 6. 主要结论与发现

- **系统级优势**：在 GLM-5.2 下，KOPE 全套 53 个算子中发现 52 个算子、通过 897 例（84.6%），CANNBot 仅通过 613 例（57.8%）；KOPE 算子的加速几何均值是 CANNBot 的 **1.54 倍**。在 Deepseek-V4-Pro 下，KOPE 通过率领先 34.5 个百分点。
- **主动上下文管理生效**：pass rate 从 60.0% 提升至 84.6%（+24.6pp），分数从 636.00 增至 2004.49，正字段几何均值提高 1.73 倍，同时 token 消耗减少 93.0%（15.9B → 1.113B）。
- **经验图内存生效**：启用后 pass rate 从 55.2% 提升至 84.6%，412 对配对计时上几何平均加速 **1.434 倍**。
- **CUDA-Agent 在稀疏语料场景失败**：GLM-5.2 只达到 14.7% 通过率（156 例），Deepseek-V4-Pro 仅 9.1%（96 例），两种配置均未解决任何完整算子，说明模型能力与任务内细化不足以应对目标硬件公开语料稀缺的场景。
- **跨硬件经验迁移（RISC-V 附录）**：Ascend 来源的记忆将 K3 通过覆盖从 60.3% 提升至 83.3%，但固定交集上的性能反而下降 62.5%（几何均值 0.388× → 0.145×），说明**可行性知识比性能知识更可移植**；加入 K3 目标侧经验后，覆盖达到 92.2%，固定交集几何均值恢复提升到 0.786×。

## 7. 优点

- **研究问题聚焦且有价值**：不同于大多数工作追求更强模型或更大上下文，KOPE 聚焦"从已完成任务中学习并复用经验"，切中硬件内核优化的真实痛点。
- **经验表示设计巧妙**：同时使用叙事日志（Journal）与结构化案例（Case）双重表示，兼顾语义检索质量与结构化图检索需求；provenance 边记录决策顺序和分支而不做因果断言，谨慎合理。
- **上下文预算机制可操作性强**：hot/warm/cold 三层动态准入机制 + 显式 token 预算公式，实现简单、可解析、可复现。
- **实验分析公正**：多处主动承认条件指标的局限，明确区分"覆盖性"与"条件性能"，不夸大结果；用 exact-intersection 与全套分母进行双重验证。
- **补充跨硬件实验**：RISC-V 附录改变了硬件、内核语言、编译器路径与评测 harness，且结果（可行性迁移 ≠ 性能迁移）具有明显的洞察价值，增强了框架的泛化声称。
- **研究对象具有时效性**：针对华为 Ascend NPU 生态这一公开优化语料稀缺的场景，具有实际意义。

## 8. 不足与局限

- **统计力度有限**：所有配置都只有一个运行结果，无法估计方差，重复运行与置信区间缺失；作者承认这一点，但仍是较大的方法学局限。
- **性能量化不完美**："绝对速度"的正字段几何均值存在选择偏差（缺失和非正字段被排除）；L4 图内存消融结论仅基于 28 对配对用例，置信度有限。
- **主动上下文消融粒度粗**：只对比"被动 vs 主动"整体效果，未剥离检索排序、压缩、注入各自贡献，机制内部贡献不清晰。
- **跨硬件迁移非一一对应**：对比涉及多个变量同时变化（硬件、语言、编译器、评估 harness），无法归属于单一因素。
- **显式因果识别缺失**：图结构中边缘记录"血统"而非因果效应，论文也明确说 d(v) 只是检索启发式而非因果估计。
- **在线学习上限未实现**：`Q_w`、`Q_c` 等超参固定，在线自适应学习这些上限不在当前实现范围内。
- **工程细节未披露**：未说明底层 LLM 推理成本、GPU（或 NPU）资源数量、运行时长等可复现性关键信息。
- **CUDA-Agent 对比的公平性问题**：该工作流原本针对 NVIDIA GPU 设计，在 Ascend 环境表现差可能部分源于工具链适配不足，而非方法本身的缺陷；作者给出了解释但无法完全排除。
- **目标平台范围仍有限**：主体实验仅覆盖 Ascend NPU 与 CANN Bench 一个基准；虽然 RISC-V 附录扩展了平台，但仍是有限数量的验证。
