## 摘要
三角方程多右端项求解（TRSM）是一种基本的BLAS三级运算，是LU/Cholesky分解、稀疏直接求解器和矩阵求逆的基础。本文研究的左侧下三角情形中，高效的GPU实现仍具挑战性，因为前代替换引入了严格的行间依赖，而对于双复数等宽数据类型，共享内存过于稀缺而无法同时容纳两个操作数矩阵。本文提出HSMA-TRSM，一种面向NVIDIA A100、NVIDIA H800和Hygon DCU Z100加速器上左侧下三角TRSM的层次化共享内存感知优化框架。对于小规模情形（m,n≤64），我们通过循环展开和指令重排设计了流水线式计算-内存重叠机制，并提出双线程组七级流水线策略以应对双复数类型的共享内存限制。对于大规模问题，我们引入对角块解耦优化，其对角块求逆具有O(IB)的共享内存占用，从而能够根据矩阵规模与硬件特性自适应选择块大小。基于离线剖析和在线查找的编译期配置选择框架，为每个平台选择最优块大小，且零运行时开销。在NVIDIA A100、H800和Hygon DCU Z100上的评估表明，HSMA-TRSM相比cuBLAS达到2.05倍的峰值加速，相比rocBLAS达到2.06倍。在共享内存受限的双复数小规模情形以及自适应分块改进GEMM主导更新的大型实数类型情形中，加速效果最为显著，而在某些情形下成熟的厂商内核留下的优化空间较小。

## Abstract
Triangular Solve with Multiple Right-hand Sides (TRSM) is a fundamental BLAS Level-3 operation that underpins LU/Cholesky decomposition, sparse direct solvers, and matrix inversion. In the left-side lower-triangular case studied in this paper, efficient GPU implementation remains challenging because forward substitution introduces strict row-wise dependencies, and shared memory is too scarce to hold both operand matrices for wide data types such as double complex. This paper presents HSMA-TRSM, a hierarchical shared memory-aware optimization framework for left-side lower-triangular TRSM on NVIDIA A100, NVIDIA H800, and Hygon DCU Z100 accelerators. For the small-scale regime (m,n<=64), we design a pipelined compute-memory overlap mechanism through loop unrolling and instruction reordering, and propose a dual thread-group seven-stage pipeline strategy to address shared memory constraints for double complex types. For large-scale problems, we introduce a diagonal block decoupling optimization with an O(IB)shared-memory footprint for diagonal block inversion, enabling adaptive block size selection based on matrix scale and hardware characteristics. A compile-time configuration selection framework based on offline profiling and online lookup selects the optimal block size per platform with zero runtime overhead. Evaluated on NVIDIA A100, H800, and Hygon DCU Z100, HSMA-TRSM achieves peak speedups of 2.05xover cuBLAS and 2.06xover rocBLAS. The gains are strongest in shared-memory-constrained double-complex small cases and in large real-type cases where adaptive blocking improves GEMM-dominated updates, while mature vendor kernels leave less optimization headroom in some regimes.

# GPU平台上面向TRSM的层次化共享内存感知优化——论文详细总结

## 1. 论文的核心问题与整体含义（研究动机和背景）

- **TRSM（Triangular Solve with Multiple Right-hand Sides）** 是BLAS Level-3的核心运算，广泛应用于LU/Cholesky分解、稀疏直接求解器、矩阵求逆和最小二乘问题中，其执行效率直接影响上层应用的整体性能。
- **数学形式**：求解 *op(A)X = αB*，本文聚焦**左侧下三角情形**，即通过前代替换逐行求解，存在严格的行间串行依赖链，给GPU并行化带来本质困难。
- **三大挑战**：
  1. **小规模（m, n ≤ 64）共享内存受限**：DCU每线程块64KB、A100/H800每线程块48KB的共享内存预算，难以同时容纳矩阵A和B；双复数（16字节/元素）的64×64矩阵单独占用64KB，直接使双缓冲方案在NVIDIA平台上不可行。
  2. **大规模固定分块策略不优**：rocBLAS固定分块大小为128，忽略矩阵规模与硬件差异；传统融合对角块路径需要O((I_B)²)共享内存，限制了分块大小的进一步扩大。
  3. **现有优化多针对单一架构**，缺乏跨平台（NVIDIA与Hygon DCU）的性能可移植性。
- **核心意义**：通过层次化、共享内存感知的优化框架，在多个GPU平台上显著提升TRSM性能，为内存受限的稠密线性代数内核提供可移植的优化范式。

## 2. 论文提出的方法论（核心思想、关键技术细节）

论文提出 **HSMA-TRSM** 框架，以矩阵规模64为统一分界，将问题划分为小规模与大规模两个优化域，并针对数据类型进一步细分。

### 2.1 小规模优化（m, n ≤ 64）

- **共享内存直接求解策略**（适用于Float、Double、Float Complex）：
  - 矩阵A完全驻留共享内存；矩阵B的32列分块驻留片上。
  - **逐行前代替换**：当前行求解结果结合A的对应列，更新未求解行；不同列可并行。
  - **循环完全展开 + 指令重排**：将下一行的加载提前、已求解行的写回延后，形成更深的“加载-计算-写回”流水线，隐藏访存延迟（Algorithm 1）。
- **双线程组七级流水线策略**（专用于Double Complex）：
  - 将64KB共享内存划分为4个16KB子区，矩阵A按2×2分块、B按4×1分块。
  - 128个线程分为两个线程组：一组负责访存操作，一组负责计算，实现计算与内存的完全重叠。
  - 七级流水线阶段：加载A11+B1+B2 → 求解并写回B1 → 流式加载A21、A22 → 用A21×B1,2更新剩余子块 → 加载B3、B4 → 求解B3、B4 → 写回。

### 2.2 大规模优化（m > 64 或 n > 64）

采用两阶段阻塞算法：

- **阶段一：并行对角块求逆**。三角阵A沿对角划分为多个I_B×I_B对角块D_t，各块相互独立，可并行求逆。
- **阶段二：顺序GEMM更新与求解**。第r个块的求解为：先执行GEMM更新（B_r ← B_r - A_{r,[0:r]} × X_{[0:r]}），再用预求逆矩阵执行对角块求解（X_r = D_r^(-1) × B_r）。K维度随迭代线性增长。

**关键优化——对角块解耦**：
- 传统算子融合方案需4×(I_B)²×sizeof(datatype)共享内存（如I_B=64时双复数需256KB），严重限制分块大小。
- 论文将计算流解耦为**纯回代的对角块求逆算法**，数据加载粒度细化到**列级**，共享内存占用降至**O(I_B)**（只需2×I_B×sizeof(datatype)）。
- 引入**双缓冲机制**：两块缓冲区交替计算当前列与预取下一列，实现访存与计算异步重叠，共享内存仍保持4×I_B的O(I_B)复杂度。

**自适应分块算法**：
- 两阶段策略：**离线剖析 + 在线查找**。预构建阶段遍历候选分块大小（32/64/128/256等），记录各“规模×数据类型”组合的最优分块；运行时仅通过哈希表查找最近规模的最优配置，**零运行时调优开销**。

## 7. 优点（方法与实验亮点）

- **层次化分治策略**：以规模和数据类型的双重维度划分优化路径（完全共享内存驻留、部分驻留、分区流水线、大规模分块），设计细致且针对性强。
- **复杂度显著降低**：对角块求逆共享内存从O(I_B²)降到O(I_B)，从理论上突破了分块大小的片上资源瓶颈，是大规模性能提升的关键。
- **零运行时开销的可移植调优**：离线剖析+在线查找表方案避免了运行时自调优开销，是工程上高效的跨平台解决方案。
- **边界情形处理巧妙**：64×64双复数恰好占满64KB共享内存的极端情形，七级双线程组流水线设计精准切中痛点。
- **实验平台多元**：覆盖NVIDIA（Ampere/Hopper）与国产Hygon DCU，验证了跨架构可移植性。
- **数值稳定性经过验证**：给出与cuBLAS的范数相对误差，增强结果可信度。
