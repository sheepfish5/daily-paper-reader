## 摘要
长语音输入使得KV缓存成为语音大语言模型的主要内存开销。仅预填充的KV压缩方法一旦驱逐音频KV位置便永久丢弃，解码期间无从恢复。我们表明这在长语音上较为脆弱：预填充注意力集中于音频开头附近（注意力汇效应），而解码期注意力分布广泛，二者排名重叠度低。我们提出WnW（增减型KV缓存），通过离线校准将KV头分类为锚定、潮汐和固定三类角色。锚定头保留在GPU上，作为解码期重要性观察者；潮汐头在CPU端保留互补副本，并根据聚合的锚定头分数逐块召回；固定头仅保留GPU子集，其余永久丢弃。在LibriSpeech-Long上使用两个3B骨干模型（Voxtral-mini-3b和Qwen2.5-Omni-3B），WnW在仅将20%音频令牌保留在GPU上的情况下保持接近全缓存的精度，而仅预填充的基线无法终止。结果可泛化至语言、任务和领域偏移，且测量显示CPU-GPU召回增加的解码期开销很小。

## Abstract
Long-form audio inputs make the KV cache the dominant memory cost of speech LLMs. Prefill-only KV compression methods permanently discard audio KV positions once evicted, with no pathway to recover them during decoding. We show this is fragile on long-form audio: prefill attention concentrates near the audio start (an attention-sink effect), while decode-time attention distributes broadly, and the two rankings overlap weakly. We propose WnW (Waxing-and-Waning KV cache), which classifies KV-heads into anchor, tidal, and fixed roles via offline calibration. Anchor heads remain on GPU and serve as a decode-time importance observer; tidal heads keep a CPU-resident complement that is recalled chunk-by-chunk based on aggregated anchor-head scores; fixed heads keep only an on-GPU subset, with the rest permanently discarded. On LibriSpeech-Long with two 3B backbones (Voxtral-mini-3b and Qwen2.5-Omni-3B), WnW preserves near-Full-Cache accuracy while keeping only 20% of audio tokens on GPU, where prefill-only baselines fail to terminate. Results generalize across language, task, and domain shifts, and CPU-GPU recall adds little decode-time overhead in our measurements.

## 1. 核心问题与研究动机

- **长语音输入使 KV 缓存成为内存瓶颈**：语音 LLM 每秒产生 12.5–25 个音频 token，一段 10 分钟音频即占据 7,500–15,000 个 KV 位置，音频 KV 通常占全缓存量的 70–80%。在固定 GPU 内存下，能否压缩音频 KV 直接决定批处理规模与服务吞吐。
- **现有静态压缩方法存在结构性缺陷**：H2O、SnapKV、Ada-KV、AudioKV 等主流方法均在预填充阶段一次性决定保留位置，之后永久丢弃其余位置，解码期间没有恢复通路。这隐含一个前提假设——**预填充注意力能预测解码期注意力**。
- **长语音音频下该前提不成立**：论文通过实证发现，预填充注意力高度集中在音频开头（注意力汇效应，前 10% 位置占 47.9% 注意力质量），而解码累积注意力分布近似均匀；两者 top-K 位置的 Jaccard 重叠度仅 0.187（K=100）和 0.240（K=500），远低于可支持静态保留的阈值。预填充基线的失败模式为 WER 超过 100% 甚至无法终止生成。

## 2. 方法论：WnW 核心思想与关键技术

### 2.1 核心思想

WnW 的核心是**将最终保留决策延迟到解码期**，利用语音解码时注意力随内容推进的时间对齐特性，在解码动态中实现"增减"式 KV 管理，而非在预填充阶段就做出不可逆选择。

### 2.2 离线头部分类（Head Functional Triage）

通过离线校准，将每个 KV 头按 **VS × HS** 重要性打分划分为三类角色：

- **Anchor 头（锚定头）**：顶部 `n_anchor=5` 个语音头。完整保留全部音频 KV 于 GPU，其解码期注意力作为全局"重要性观测器"。
- **Tidal 头（潮汐头）**：其余语音头（总数 `n_voice`）。GPU 保留部分 + CPU 保留互补副本，解码时按需召回、定时释放。
- **Fixed 头（固定头）**：非语音头。仅保留预填充期 top-k 子集，其余永久丢弃，无召回通路。

两个打分信号：

- **Voice Score (VS)**：头注意力落入当前答案 token 对应时间区间（WhisperX 对齐）的命中率，衡量"音频内容接地性"。
- **Head Sensitivity (HS)**：答案 token 损失对音频 key 向量梯度的 ℓ2 范数，衡量"该头音频 KV 对质量的关键程度"。

保留率控制：`retention_i = min(s_i_norm · λ, 1.0)`，超参数 `λ` 整体缩放 GPU 保留比例，`n_voice` 控制可召回头的数量。

### 2.3 预填充压缩与解码期块交换

**预填充阶段**：

- Anchor 头全量保留；Tidal/Fixed 头按**段内 top-k**（每 `n_s` token 段内保留 top ⌊retention·n_s⌋ 位置）选择，保证时间覆盖均匀，避免整段被驱逐。
- Tidal 头未选中位置存至 CPU；Fixed 头未选中位置永久丢弃。

**解码阶段**：

- 每步计算 anchor 头的 softmax 注意力权重并聚合为逐位置分数 `A_τ^(s)`，再按块取均值得到块分数。
- 每步选出 top-k（k=3）块；属于这些块但不在 GPU 上的 tidal 头段从 CPU 召回；连续 δ=3 步未被选中的段从 GPU 释放，但 CPU 副本保留可再次召回。
- 块大小为 4 秒窗、2 秒步长重叠，以段为粒度加载/驱逐。

## 6. 主要结论与发现

- **WnW 在极低保留率下保持近全缓存精度**：两个 3B 模型上、r_GPU 从 0.8 降至 0.2 时，WnW 与 Full Cache 的 WER 差距始终在 ~1–1.6 分以内（Voxtral 上通常还略低于 Full Cache）；而 Ada-KV 和 AudioKV 在 r_GPU≤0.4 时 WER 超过 100% 甚至无法终止。
- **基线性能排序稳定**：Ada-KV ≫ AudioKV > ArkVale > WnW，精确对应"不可逆静态压缩 < 可召回但无头部分类 < 可召回 + 语音感知引导"的结构层次。
- **泛化性成立**：LibriSpeech 校准的头角色在法语 ASR、翻译、医疗领域均有效；跨校准数据集的 WER 变化不超过 1.12 点，76/85 个潮汐头保持一致。
- **召回开销低**：tidal 头数量扩大 6.7 倍时，CPU→GPU 传输仅从 0.05 增至 1.04 MB/步，解码中位数时间变化 < 5%。
- **超参数鲁棒**：块大小（0.96s–7.68s，8× 范围）与 anchor 数量（5–20，4× 范围）的 WER 波动不超过 ~0.3 点。

## 7. 优点

- **问题定位扎实**：通过定量测量（注意力质量集中度、Jaccard 重叠、逐头分布）直接证伪了静态压缩的前提假设，为方法设计提供坚实经验依据。
- **语音专属设计**：利用语音 token 时间有序、词对齐的结构特性，以 anchor 头注意力作为解码期重要性信号，而非通用的 query-抽象摘要相似度，是音频 KV 管理领域首次引入**"可召回 + 解码驱动"**的机制。
- **统一分类框架**：VS（注意力接地性）与 HS（梯度敏感性）的乘积同时捕捉"注意力漂移程度"与"损失关键度"，两者缺一不可（消融证明单独使用任一信号显著退化）。
- **工程友好**：无需训练，离线校准即可确定角色；块交换粒度覆盖与 δ=3 的释放延迟设计抑制了抖动；对超参数不敏感，便于实际部署。
- 兼容性声明清晰：明确说明与 KV 量化正交，可叠加使用。

## 8. 不足与局限

- **高保留率下召回通路闲置**：当 λ 饱和时所有 voice 头保留率削到 1，CPU 分区空置，未发挥设计潜力。论文仅提出解耦 `n_voice` 与 `λ` 的方向，未阐述具体解耦方式。
- **召回调度朴素**：未使用 CUDA stream 等与注意力计算重叠的异步机制；当前数据未使其成为瓶颈，但更大模型或更高召回频率下开销可能放大。
- **任务覆盖有限**：仅评估转写和翻译；语音 QA、对话、摘要等非转写任务依赖底层模型成熟度，尚未验证。
- **架构不适用性**：WnW 仅适用于具有自回归解码 + 长度依赖音频 KV 缓存的架构，不适用于 cross-attention（Whisper）、transducer 或 state-space 模型。
- **流式场景未覆盖**：尽管论文推测可扩展到流式识别架构，但实验中仅评估离线解码，无实证支撑。
- **大规模验证尚不充分**：24B 实验仅在 r_GPU≈20% 单点、单骨干上完成，且未报告该模型上的消融与效率数据；绝对 WER 相比 3B 模型离 Full Cache 差距更大（5.59 vs ~0.6 点），说明方法在强模型上仍有改进空间。
- **对比公平性有一定瑕疵**：对基线的修改（如限制为音频 KV 区域、统一 WhisperX 阈值）是合理的，但 AudioKV 结果复现困难且存在较大差异，可能引入潜在的不公平因素；AffPool 属于 token 合并而非 KV 逐出，其压缩语义不同，直接横向对比的价值有限。
