## 摘要
学习型 KV 缓存驱逐经常面临软到硬的不匹配：在训练期间，可微门控通常衰减 token 贡献，而推理只在 KV 条目被物理移除时才节省内存。我们探究注意力基础是否影响这种软到硬的过渡。使用在 OpenWebText 上训练的 GPT-2 规模 Transformer，我们进行了受控的 2×2×2 对比，涵盖注意力类型、学习门控和位置编码。尽管 sigmoid 注意力作为密集语言模型表现较差，但学习型硬驱逐改变了有用的工作点：sigmoid 门控模型在删除 KV 条目时，相对其自身的无驱逐参考，困惑度变化可忽略不计。在相同密集骨干上的匹配实时缓存协议下，学习型 sigmoid 门控比我们的 H2O 和 KeyDiff 实现获得更低的困惑度，而 softmax 门控并不统一地胜过这些事后方法。结果表明，注意力归一化可以显著影响训练时软门控是否能干净地迁移到硬 KV 删除。

## Abstract
Learned KV-cache eviction often faces a soft-to-hard mismatch: during training, differentiable gates typically attenuate token contributions, whereas inference saves memory only when KV entries are physically removed. We ask whether the attention substrate affects this soft-to-hard transition. Using GPT-2-scale Transformers trained on OpenWebText, we run a controlled $2\times2\times2$ comparison over attention type, learned gating, and positional encoding. Although sigmoid attention is worse as a dense language model, learned hard eviction changes the useful operating points: sigmoid-gated models delete KV entries with negligible PPL change relative to their own no-eviction references. Under a matched live-cache protocol on the same dense backbones, learned sigmoid gates obtain lower PPL than our H$_2$O and KeyDiff implementations, whereas softmax gates do not uniformly beat these post-hoc methods. The results suggest that attention normalization can substantially affect whether a training-time soft gate transfers cleanly to hard KV deletion.

## 1. 论文核心问题与整体含义

论文聚焦于学习型 KV 缓存驱逐中一个关键且普遍存在的矛盾：**软到硬不匹配（soft-to-hard mismatch）**。具体来说：

- **训练阶段**：可微分的软门控只能衰减 token 的贡献（如在注意力 logits 上加偏置、缩放 value），但 KV 条目仍留在内存中，并未实现真正的内存节省。
- **推理阶段**：内存只有在 KV 条目被**物理删除**时才能被释放，这需要将软门控转为离散的硬删除操作。
- **核心问题**：是否存在某种注意力归一化基座（attention substrate），使得训练时的软门控能更干净、更无损失地迁移到推理时的硬删除？

论文的总体含义在于：**注意力归一化机制本身是决定软门控能否顺利迁移为硬 KV 删除的关键因素**。它提醒研究者，KV 缓存驱逐不应仅被视为推理时的事后启发式方法，而应与注意力机制进行架构层面的协同设计。该研究将 KV 驱逐问题从"推理优化"重新定位为"架构协同设计"问题。

## 2. 方法论

### 2.1 核心思想

作者提出，不同注意力归一化方式（softmax 的**行归一化** vs. sigmoid 的**非行归一化**）会从根本上影响门控信号的质量。在 softmax 中，抑制一个 token 会将注意力质量重新分配给其他 token（因为每行总和必须为 1）；而 sigmoid 注意力没有这一约束，门控可以主要衰减目标 token 自身的贡献，更接近硬删除的效果。

### 2.2 实验设计框架

采用 **2×2×2 因子设计**，共 8 个模型单元：

| 因素 | 取值 |
|------|------|
| 注意力类型 | softmax / sigmoid |
| 门控方式 | 稠密（无门控）/ 学习门控 |
| 位置编码 | RoPE / NoPE（无旋转位置编码） |

### 2.3 关键技术细节

- **模型架构**：GPT-2 风格 decoder-only Transformer，12 层、12 头、d_model=768、d_ff=3072、序列长度 512。
- **QK-RMSNorm**：所有变体在计算注意力分数前先对 query 和 key 做 RMSNorm。
- **Sigmoid 注意力**：使用逐 query 的负偏置 b(i) = −log(i+1) 以稳定期望行质量，避免注意力总和过大。
- **门控注入**：每层（除最后一层）产生 token 级门控值 g ∈ (0,1)，通过两个通道注入下一层：
  - 注意力 logits：z_ij ← z_ij + log(g_j + ε)
  - 值向量：v_j ← g_j · v_j
  - 其中 ε = 10⁻⁸ 防止 log(0)。
- **推理时物理驱逐**：设置阈值 τ，对 g_j < τ 的 KV 条目在 prefill 后和 decode 过程中物理删除。
- **训练目标**：交叉熵 + 门控均值预算项，λ = 0.03，在训练中把门控推向较小值。

### 2.4 评估协议

- 每个测试序列分割为 384 token 的 prefill 前缀 + 128 token 的 decode 窗口，仅在 decode 窗口计算 PPL。
- 在验证集上进行阈值网格搜索（15 点，τ ∈ [0, 0.9]），选择满足 ΔPPL < 0.1 的最高压缩率的 τ*。
- 与事后基线（H₂O、KeyDiff）比较时，**匹配最终实时缓存大小**——基线在对应的稠密骨干上以相同的最终缓存大小运行。

### 3.1 数据集与基准

- **训练数据**：OpenWebText 的 10 亿 token 训练集，训练 3 个 epoch（约 30 亿 token 暴露）。
- **验证集**：10 万 token；**测试集**：100 万 token。
- **评估指标**：decode 窗口上的困惑度（PPL）与物理 KV 压缩率。

### 3.2 对比方法

### 3.3 三个机制诊断

1. **随机支持移除探针**：随机移除 K/V 位置，测量注意力输出的相对扰动。检验 sigmoid 是否只是"天然更容忍删除"。

3. **Token 选择性**：将 token 分为内容词、停用词、标点、换行、空白、数字等类别，统计各类别的平均门控值。

## 6. 主要结论与发现

### 6.1 稠密基线结果

在无驱逐的稠密模型中，**softmax 仍优于 sigmoid**：
- SM RoPE：22.079 vs. Sig RoPE：22.440（差 0.361 PPL）
- SM NoPE：23.398 vs. Sig NoPE：24.603（差 1.205 PPL）

### 6.2 学习型硬驱逐改变了有用的工作点

| 模型 | τ* | 压缩率 | 相对无驱逐参考的 ΔPPL |
|------|-----|---------|-----------------------|
| SM+G RoPE | 0.010 | 19.2% | +0.435 |
| **Sig+G RoPE** | **0.050** | **19.8%** | **−0.016（实质无损失）** |
| SM+G NoPE | 0.010 | 10.2% | +0.178 |
| **Sig+G NoPE** | **0.050** | **32.2%** | **+0.034（仅小幅增加）** |

### 6.3 匹配缓存大小下与事后基线比较

- **软注意力骨干上**：H₂O 优于学习型门控（22.145 vs. 22.514）。
- **Sigmoid 骨干上，模式反转**：Sig+G RoPE（22.424）和 Sig+G NoPE（24.637）都低于匹配的 H₂O 和 KeyDiff 基线。
- 结论：同一个简单的软到硬规则在 softmax 下表现不佳，但在 sigmoid 下变得有用。

### 6.4 机制层面的发现

- **不是对任意删除的稳健性**：随机移除 K/V 时，sigmoid 在大移除率下反而比 softmax 更敏感（p=0.5 时扰动为 3.666 vs. 1.131），因此 sigmoid 的优势是"学习型删除"特有的，不是泛化的鲁棒性优势。
- **行和自由度是关键结构差异**：sigmoid 注意力允许各查询位置承载不同的注意力质量（CV ~0.44-0.48），软门控可以"局部衰减"而不强制整行重新归一化。
- **门控具有 token 选择性**：停用词和新行获得最低门控（更易被删除），空白 token 获得最高门控（最受保留），表明学习到的策略是语义驱动的非均匀删除。

## 8. 不足与局限

### 实验覆盖方面

- **规模有限**：仅 123M 参数的 GPT-2 规模模型，未验证更大模型（如 1B/7B/70B）上是否仍成立；LLM 的优势通常在大规模下才显现，而门控行为很可能随模型规模变化。
- **上下文过短**：序列长度仅 512，对于 KV 缓存驱逐的主要应用场景——长上下文推理——验证不足。在 4K/32K/128K 上下文中，驱逐策略的收益和门控行为可能完全不同。
- **单一数据集与种子**：仅在 OpenWebText 上训练，未验证其他文本分布（代码、多语、数学）上的表现；单种子无法评估训练方差。

### 门控设计方面

- **单一门控参数化**：固定使用 token 级门控 + 双通道注入（logits + 值）+ λ=0.03，未消融仅 logits vs. 仅值 vs. 双通道的效果差异。
- **固定阈值选择规则**：ΔPPL < 0.1 的截止值是任意选择，未尝试每层不同阈值、不同预算系数 λ 或更细的阈值网格。

### 基线比较方面

- **H₂O 配置未调优**：重型命中/近期 token 的拆分比例固定为 50/50，未在验证集上调优，可能低估了 H₂O 的性能。
- **未报告 wall-clock 速度**：论文只报告 PPL 和压缩率，不含实际的推理加速数据；作者也承认未实现针对 sigmoid 门控路径的融合算子，因此系统级收益尚不清楚。
- **小负 ΔPPL 的可解释性**：Sig+G RoPE 相对稠密基准略有改善（22.424 vs. 22.440），作者承认这不代表真实的语言建模收益，但读者需要谨慎，不应过度解读这一微小差异。

### 基准问题

- **不是 SOTA 基准**：仅与 H₂O 和 KeyDiff 两个基线比较，缺乏与更新的方法（如 DuoAttention、KV-Distill、Fast KVzip 等）的对比。论文中的基线是为研究目的配置的基本参考点，而非完全优化的生产级最优实现。
