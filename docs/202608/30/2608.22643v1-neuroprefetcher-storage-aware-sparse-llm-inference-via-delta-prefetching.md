## 摘要
在边缘设备上部署大型语言模型日益受到模型大小与可用内存之间不断扩大的差距的限制。现有的方法如量化、小型模型和卸载可以提高有效内存限制，但它们仍然假设模型可以被压缩或分区以适应某个预算。我们针对更难的模型超出内存的设置，在此设置中，模型在整个执行过程中仍然大于驻留内存，存储成为关键路径上权重的主动来源。我们观察到自回归解码期间的MLP活动具有很强的时间局部性：大约82-85%的活跃神经元从一个令牌持续到下一个令牌。这意味着当前令牌所需的大部分稀疏权重已经驻留，只有新需要的行必须从存储中获取。我们提出了NeuroPrefetcher，一个存储支持的大语言模型推理系统，通过预测性增量预取来利用这一特性。在第0层之后，一个占用基础模型参数2.86%的GPU驻留预测器，在一次前向传播中预测所有下游MLP层的稀疏活动。运行时将这些预测与驻留的GPU缓冲区进行比较，并仅为传入的增量行发出应用程序调度的NVMe读取，用显式的、模型感知的权重移动取代被动的操作系统需求分页。在真实的统一内存边缘硬件上，NeuroPrefetcher在受限的内存预算下比llama.cpp实现了7.9-12.0倍的加速。

## Abstract
Deploying large language models on edge devices is increasingly limited by a widening gap between model size and available memory. Existing approaches such as quantization, smaller models, and offloading can raise the effective memory limit, but they still assume that the model can be compressed or partitioned to fit within some budget. We target the harder model-exceeds-memory setting, in which the model remains larger than resident memory throughout execution and storage becomes an active source of weights on the critical path. We observe that MLP activity during autoregressive decoding has strong temporal locality: approximately 82-85% of active neurons persist from one token to the next. This means that most sparse weights needed for the current token are already resident, and only the newly needed rows must be fetched from storage. We present NeuroPrefetcher, a storage-backed LLM inference system that exploits this property through predictive delta prefetching. After layer 0, a single GPU-resident predictor, occupying 2.86% of base model parameters, predicts sparse activity for all downstream MLP layers in one forward pass. The runtime compares these predictions against resident GPU buffers and issues application-scheduled NVMe reads only for incoming delta rows, replacing reactive operating-system demand paging with explicit, model-aware weight movement. On real unified-memory edge hardware, NeuroPrefetcher achieves 7.9-12.0x speedup over llama.cpp across constrained memory budgets.

### 一、核心问题与整体含义（研究动机与背景）

- **核心问题**：在边缘设备（如 Jetson 系列）上部署 LLM 时，模型规模增长速度（约每代 10×）远超边缘设备内存增长速度（约 2×），导致模型远超物理内存，无法完全驻留内存。
- **现有方法的不足**：量化（GPTQ/AWQ）、小型模型（Phi-3/MobileLLM）和卸载系统（llama.cpp、FlexGen）均假设模型可以通过压缩或分区"适配"在内存预算内；但当模型在**整个执行期间始终大于驻留内存**时，这些方法失效。此时存储（NVMe）成为关键路径上的活跃权重来源。
- **被动分页的性能瓶颈**：以 llama.cpp 为代表的系统在超内存场景依赖操作系统需求分页（demand paging），导致高频页错误、CPU I/O 等待高企、GPU 利用率极低（Jetson 上 CPU iowait 达 77%，GPU 仅为 3%）。推理瓶颈从计算转移到被动的权重移动。
- **关键洞察**：自回归解码中 MLP 激活存在强时间局部性，**约 82–85% 的活跃神经元从前一个令牌持续到下一个令牌**。即当前令牌所需的大部分稀疏权重已在 GPU 中，仅需从存储中拉取新增的"增量行"（delta rows）。
- **论文定位**：面向"模型超出内存"这一被现有系统忽略的硬场景，提出显式的、模型感知的权重移动机制，替代被动的操作系统分页。

### 二、方法论：核心思想、关键技术细节与流程

#### 核心思想：预测性 Delta 预取（Predictive Delta Prefetching）

1. 在 Layer 0 之后，用单个 GPU 驻留预测器**一次性预测**所有下游层（Layer 1–31）的 MLP 稀疏激活模式（centroid ID）；
2. 运行时将预测的活跃集与当前 GPU 驻留的权重行做集合差，得到**增量（delta）**；
3. 仅对增量行发起显式的 NVMe 异步读取，在 GPU 执行密集前缀时预取到缓冲区，实现计算与 I/O 重叠。

#### 关键技术细节

| 组件 | 技术细节 |
|---|---|
| **离线稀疏质心准备** | ① 对 MLP 激活做分位数阈值化（式 1）强制执行稀疏，控制活跃神经元预算（K_max）；② 对阈值化后的二值掩码做**聚类**，形成稀疏质心词表（如 K=512 个质心），将预测空间从逐神经元决策压缩为逐层质心选择。 |
| **共享激活预测器** | 输入为 Layer 0 提取的 5 类特征（token embedding、pre-attention LayerNorm、attention-head 草图、post-attention RMS norm、gate 质心 ID）；结构为"4+1 个投影块 → 8T 维融合 → 4-block 残差 trunk → 62 个输出头（31 层 × gate/up）"；参数量 206.8M（占基础模型的 2.86%，FP16 占 414 MB）；带标签训练，损失为 gate 与 up 质心 ID 的交叉熵之和。 |
| **Delta 计算** | 每层活跃集 A_t^(l) 由 gate 和 up 质心掩码取交集得到；进出增量按式 (2)(3) 做集合差：D_in = A_t \\ A_(t-1)（从 NVMe 取入），D_out = A_(t-1) \\ A_t（释放槽位）；用 slot map S^(l) 维护每个神经元的驻留槽位。首个 token 冷启动加载完整活跃集，之后只走 delta 路径。 |
| **I/O 路径** | ① 离线将 MLP 权重重排为**神经元连续布局**（gate/up/down^T 三行 24.5 KiB 连续存放）；② 运行时对活跃神经元 ID 排序、合并连续区间；③ 通过 **io_uring + O_DIRECT**（队列深度 256）异步提交 NVMe 读取；④ 读取先落入 **cudaHostRegisterMapped 映射的 host staging 缓冲**（保证 Cache 一致性，避免 Jetson 统一内存直通 I/O 的脏数据问题）；⑤ 用融合 deinterleave+scatter 的 CUDA kernel 将行写入 GPU 活跃行缓冲。 |
| **内存自适应 Dense/Sparse 划分** | 前 d 个 MLP 层完全驻留内存（dense），后 N−d 层以固定容量活跃行缓冲运行（sparse）；d 通过自动扫描选择最大的可驻留密集前缀；内存越紧，d 越小，更多层转为稀疏模式，但保持行粒度增量流而非整层 NVMe 读取。 |

#### 流程（每 token）

1. dense 执行 Layer 0，提取特征；
2. 预测器输出所有下游层的 gate/up 质心 ID；
3. 运行时计算增量，调度 NVMe 读取；
4. CUDA scatter 将行写入缓冲区；
5. 执行稀疏后缀层（Attention 全量驻留，仅 MLP 稀疏）。

### 六、主要结论与发现

1. **在模型超出内存区间（9.0–13.2 GiB CUDA 内存）**，NeuroPrefetcher 相比 llama.cpp 实现 **7.9–12.0× 加速**（如 14 GiB 内存档从 0.34 tok/s 提升至 3.22 tok/s）。
2. **Delta 复用率**：82–85% 的稀疏后缀行从前一 token 复用，每 token 仅需从 NVMe 读取 15–18% 的新增行；最紧内存档下每 token 读体积约 1 GiB，最宽约 103 MiB（远低于整体 13.49 GiB 模型足迹）。
3. **延迟构成**：NVMe I/O 占每 token 延迟的 80–87%，GPU 计算与预测器开销均为次要；存储移动仍是主要瓶颈。
4. **质量表现**：预测器质心选择准确率约 99%（误选极少）；Mistral-7B 在 d=20 时保持约 95–96% 的 HellaSwag 准确率保持率，Llama-3-8B 约 92–93%；增加密集前缀 d 是提升质量的直接控制旋钮。
5. **Dense/Sparse 划分存在三区行为**（上升、峰值、下降）：d 过小则 I/O 过大，d 过大则稀疏层缓冲区被剥夺导致整层 NVMe 回退；最优 d 随稀疏度下降而减小（62%→d*=14，50%→d*=8，31%→d*=2）。
6. **20 系统能力研究**表明：主流系统在统一内存边缘设备上的"模型超出内存"场景普遍不可用（内存分配失败、统一内存假设不匹配、缺少 ARM 版本），NeuroPrefetcher 是该场景下唯一专门设计的稀疏存储后端执行引擎。

### 七、优点

- **问题定位精准**：切入现有系统均回避的"模型始终大于内存"硬场景，具有差异化价值。
- **Delta 预取机制新颖高效**：利用 token 间活跃神经元的时间局部性，把"每次读一堆"转化为"只读新增行"，在 I/O 路径上做减法，比整层预取/页缓存等方法更高效。
- **一次性全局预测**：仅用 Layer 0 特征、单个 2.86% 参数量的预测器即可输出全部 31 层的活跃集，比 DejaVu 等逐层预测更早暴露 I/O 计划，使预取有足够时间窗口。
- **存储布局协同设计**：神经元连续布局 + 合并/排序 + io_uring 异步调度 + 融合 scatter kernel，构成了完整的存储侧优化管线。
- **工程层面的正确性处理**：针对 Jetson 统一内存的 Cache 一致性约束，用 mapped pinned staging 规避直接 I/O 的脏数据风险，体现了实际部署的严谨性。
- **量化友好**：与量化正交，适用于量化后仍然超内存的部署，适用范围广。
