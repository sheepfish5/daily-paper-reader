## 摘要
现代LLM服务部署必须同时满足来自不同用户层级的异构服务级目标（SLO），这些用户层级涵盖从对延迟敏感的API调用到后台批处理。Llumnix提出了一种动态的、支持迁移的多实例调度器，用于LLM推理，通过统一的“空闲度”度量实现负载均衡、碎片整理、优先级排序和自动扩缩容。然而，Llumnix的优先级模型仅限于两个级别（高和普通），这种抽象过于粗粒度，无法表达生产部署中常见的更丰富的SLA类别。在这项工作中，我们扩展了Llumnix的优先级模型以支持任意数量的层级，并使用高保真LLM推理模拟器Vidur，在三种现实优先级分布（均匀分布、高斯分布、企业分布）下评估了这种扩展的效果。我们在Vidur的层级调度框架内实现了具有指数衰减的每层余量、感知层级的调度顺序以及完整的Llumnix迁移管线。我们将扩展后的调度器与INFaaS（全局路由基线）、vLLM、Orca和Sarathi-Serve（每副本基线）进行比较，扫描了从1到10的优先级级别。我们的实验表明，四个优先级层级能取得最佳的成本效益权衡，与INFaaS相比，预填充平均加速比最高达8.3倍，端到端P99加速比最高达3.1倍，每延迟成本改善46%至68%，同时保持跨层级的强SLO区分度。我们进一步表明，该系统在10个优先级级别下仍能保持这些收益，不会出现尾部延迟崩溃，开销主要集中在预填充阶段。

## Abstract
Modern LLM serving deployments must simultaneously satisfy heterogeneous service-level objectives (SLOs) across a diverse population of user tiers, ranging from latency-critical API calls to background batch processing. Llumnix introduced a dynamic, migration-capable multi-instance scheduler for LLM inference that achieves load balancing, defragmentation, prioritization, and auto-scaling through a unified "freeness" metric. However, Llumnix's priority model is restricted to two levels (high and normal), an abstraction too coarse to express the richer SLA classes common in production deployments. In this work, we extend Llumnix's priority model to support an arbitrary number of tiers and evaluate the effects of this extension under three realistic priority distributions (uniform, Gaussian, enterprise) using Vidur, a high-fidelity LLM inference simulator. We implement per-tier headroom with exponential decay, tier-aware dispatch ordering, and the full Llumnix migration pipeline inside Vidur's hierarchical scheduling framework. We compare our extended scheduler against INFaaS (global routing baseline), vLLM, Orca, and Sarathi-Serve (per-replica baselines), sweeping priority levels from 1 to 10. Our experiments demonstrate that four priority tiers yields the best cost-effectiveness tradeoff, achieving prefill mean speedups of up to 8.3x and end-to-end P99 speedups of up to 3.1x over INFaaS with cost-per-latency improvements of 46 to 68%, while preserving strong SLO differentiation across tiers. We further show that the system sustains these gains at 10 priority levels without tail latency collapse, with overhead concentrated in the prefill phase.

## 1. 核心问题与整体含义

- **研究背景**：LLM 推理服务面临请求长度不可预测、到达模式突发性强、用户延迟需求多样等挑战。传统单实例调度器（如 vLLM、Orca、Sarathi-Serve）主要面向同质工作负载，一旦请求被分发到某个副本就不再迁移，难以应对跨实例负载不均、内存碎片化以及高优先级请求的重新隔离。
- **已有方案**：Llumnix 通过“freeness”统一度量实现了动态迁移、负载均衡、碎片整理、优先级隔离和自动扩缩容，但其优先级模型仅支持 **高/普通两级**，这种二元抽象过于粗糙，无法表达生产环境中常见的多级 SLA 类别（如 platinum、gold、silver、standard、free-tier）。
- **核心研究问题**：对于支持迁移的 LLM 服务系统，**合理的优先级层数是多少？隔离余量（headroom）应如何在各层之间分配？**
- **整体含义**：本文是 Llumnix 的多层优先级扩展，在 Vidur 模拟器中系统验证了“4 层优先级性价比最优”这一结论，为实际生产部署的多级 SLA 调度提供了实用指导。

## 2. 方法论

### 核心思想
- 将 Llumnix 的二元优先级推广为 **K 个优先级层**（K≥2），每层拥有独立的 headroom 预算，通过指数衰减分配；并保留完整的迁移、负载均衡与自动扩缩容机制。
- 关键权衡在于：层数越多，SLA 区分越精细，但每层只要有请求就会占用 headroom，导致虚拟使用量增大、有效批处理容量下降。

### 关键技术细节
- **Freeness 度量**（与 Llumnix 一致）：

  F = (M − Σ_r V(r)) / B

  其中 M 为 KV-cache 块容量，V(r) 为请求的虚拟使用量，B 为当前批次大小。
- **请求虚拟使用量 V(r)**（K 级扩展后）：
  - 队首请求（HoL）：记为 demand；
  - 排队中：记为 0；
  - 运行中：physUsage(r) + 对应优先级 headroom H(p,i)；
  - 实例 draining：记为 ∞。
- **每层 headroom 指数衰减公式**：

  H_p = M · h_max · e^(−λp)

  其中 h_max = 0.20（tier 0 预留 20% 容量），λ=1.0，使最低优先级层 headroom 趋近于 0。
- **虚拟 headroom 总量**：只要某层存在至少一个请求，就计入该层完整预算 H_p，而非按请求数分摊。
- **优先级感知分发**：全局调度器严格按优先级从高到低分发，层内 FCFS；选择 freeness 最高且非 draining 的副本。
- **迁移机制**：基于时间间隔（50ms）和负载不均衡阈值（ΔF≥0.3）触发；优先迁移排队请求（无 KV 状态），其次是低优先级、KV  footprint 小的运行请求；运行中请求采用多阶段 KV-cache 迁移，迁移期间继续解码，仅最终切换时短暂重入队。
- **自动扩缩容**：使用排除 headroom 的“normal-priority freeness”做决策，避免优先级隔离被误判为容量不足造成误扩容。

### 算法流程（文字描述）
1. 请求到达后按优先级进入全局调度器待分发队列。
2. 调度器按优先级顺序选择副本：arg max F 且非 draining。
3. 各副本 Llumlet 维护优先级队列，计算虚拟使用量并周期性上报 freeness。
4. 调度器周期性检查迁移条件（时间/负载差），触发源副本选择候选请求进行多阶段迁移。
5. 自动扩缩容组件根据集群平均 normal-priority freeness 触发扩容或缩容。

## 6. 主要结论与发现

- **4 个优先级层为最优性价比点**：三种分布下均成立，K=4 时 E2E P99 加速最高可达 **3.13×**，E2E mean 加速最高约 **2.9×**，cost-per-latency 改善达 **46–68%**。
- **Prefill 平均加速显著**：最高 **8.3×**（Uniform 10K），明显超过 Llumnix 原论文的 ≤2.2×，归因于迁移驱动的负载均衡有效避免了 prefill 突发在单副本上的“车队效应”。
- **高负载下收益下降**：15K 请求时 prefll P99 加速降至 2.0–3.2×，因为近饱和时所有副本都接近容量上限，迁移空间变小。
- **10 层优先级下系统仍稳定**：无尾延迟崩溃，但开销集中在 prefill 阶段；decode 阶段性能不受影响甚至略优。
- **优先级粒度与负载存在交互**：收益在中等负载下最明显；近饱和时应配合主动扩缩容。

## 8. 不足与局限

- **模拟器局限**：Vidur 无法捕捉 PCIe/NVLink 带宽、CUDA kernel

- **模拟器局限（续）**：Vidur 无法捕捉 PCIe/NVLink 带宽、CUDA kernel 级调度开销、内存拷贝延迟等硬件层面的细节，因此多阶段 KV-cache 迁移的实际成本可能被低估；在高并发、多实例真实部署中，迁移带来的通信干扰与 kernel 抢占效应可能改变结论。
- **迁移机制的无障碍假设**：论文假设迁移可随时触发且无额外注册/同步开销，但真实系统中迁移涉及全局路由表更新、连接迁移、目标端内存预分配等成本，本文未对这些开销建模或做敏感性分析。

- **参数未做系统消融**：headroom 指数衰减参数（h_max=0.20、λ=1.0）、迁移间隔（50ms）、不均衡阈值（ΔF=0.3）均采用固定值，未给出这些参数在真实工作负载下的敏感性实验结果。
- **未讨论跨区域/多租户场景**：所有实验均假设单集群、单租户；多租户下优先级隔离需与配额、计费、公平性约束耦合，本文未涉及。

## 9. 实用建议与部署启示

- **优先级层数选择**：建议从 **3–4 层** 起步。K<3 时多级 SLA 表达力不足，K>4 时额外层带来的 headroom 预算消耗会抵消收益，且运维复杂度上升。
- **Headroom 分配策略**：高层级应预留较大隔离空间（本文推荐最高层预留 20% 容量），低层级 headroom 指数衰减至接近 0；建议按实际流量分布重新标定 h_max 与 λ，而非直接采用默认值。
- **迁移策略**：迁徙应优先挑选**排队中请求**（零 KV 状态迁移成本）；运行中请求只在负载极不均衡时迁移，且优先迁移低优先级、KV footprint 小的请求，以最小化迁移中断。
- **自动扩缩容与优先级解耦**：扩缩容判断应使用剔除 headroom 后的 “normal-priority freeness”，否则高优先级流量会被误判为容量不足，导致过度扩容。
- **生产环境部署顺序**：若现有系统为 Llumnix 二元优先级，可先扩展为 3 层（如 premium / standard / batch），在真实流量中观察 TTFT/TBT 分层效果后，再逐步增加到 4 层。
- **近饱和场景的预期管理**：当集群持续高负载（利用率 >85%）时，优先级分层收益会显著收窄，此时应优先依赖主动扩缩容而非调度迁移。

## 10. 总体评价

本文在系统设计上延续了 Llumnix 的迁移式调度思路，将其优先级模型从二元扩展为可配置的多层结构，并通过 Vidur 模拟器给出了清晰、可操作的层数推荐。核心贡献不在于理论创新，而在于**为生产级多级 SLA 调度提供了一个经过系统验证的工程指南**：4 层优先级能在精细度与开销之间取得最优平衡，且该结论在多种负载分布下均保持稳健。尽管存在模拟器保真度、基线公平性和参数敏感性的局限，论文的实验广度、代码开源性与实践导向性使其对 LLM 推理基础设施的研发具有较强参考价值。对于希望将多级 SLA 落到实际推理系统中的工程师而言，本文给出的“层数选择 + headroom 分配 + 迁移优先级 + 扩缩容解耦”组合拳，是一个值得借鉴的落地模板。
