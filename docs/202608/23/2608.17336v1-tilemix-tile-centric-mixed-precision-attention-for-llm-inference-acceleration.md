## 摘要
在大型语言模型（LLM）的长上下文预填充阶段，由于密集自注意力需要计算二次方规模的查询-键得分，因此会产生大量的计算和内存流量。现有方法要么采用统一的低精度路径，要么选择性地处理token交互，而未能在融合的密集注意力中针对硬件对齐的得分tile实现空间精度路由。我们提出了TileMix，一种以tile为中心的精度路由内核，它将数值精度转化为融合密集注意力中得分tile组上的可执行空间决策。TileMix将注意力矩阵划分为硬件对齐的得分tile，将路由决策打包为紧凑的位掩码，并通过FP16或INT8得分计算来调度每个tile组，同时两条路径共享并更新在线softmax状态。可扩展的精度分组使得每个路由位可以控制多个相邻的键tile，从而在长上下文场景下保持硬件对齐的计算tile和紧凑的元数据。通过对所有合法tile组进行路由，TileMix保留了密集的token连接性，无需训练，并支持分组查询注意力、可变长度批次以及INT8键/值缓存。在LongEval、LV-Eval以及A100预填充基准测试中，针对LLaMA、Qwen和Vicuna模型，TileMix恢复了在统一INT8下丢失的长上下文质量，并相比FP16提高了预填充吞吐量，从而在不同模型家族中实现了可控的精度-效率权衡。实现代码可在 https://github.com/HanzhiZhang-Ulrica/TileMix 获取。

## Abstract
Long-context prefill in large language models (LLMs) incurs substantial computation and memory traffic because dense self-attention computes quadratic query-key scores. Existing methods either use a uniform low-precision path or select token interactions, leaving spatial precision routing over hardware-aligned score tiles outside fused dense attention. We introduce TileMix, a tile-centric precision-routing kernel that makes numerical precision an executable spatial decision over score-tile groups within fused dense attention. TileMix partitions the attention matrix into hardware-aligned score tiles, packs routing decisions into compact bitmasks, and dispatches each tile group through FP16 or INT8 score computation while both paths update a shared online-softmax state. Scalable precision grouping lets each routing bit govern multiple adjacent key tiles, preserving hardware-aligned compute tiles and compact metadata at long contexts. By routing all legal tile groups, TileMix preserves dense token connectivity, requires no training, and supports grouped-query attention, variable-length batches, and INT8 key/value caches. Across LongEval, LV-Eval, and A100 prefill benchmarks on LLaMA, Qwen, and Vicuna, TileMix recovers long-context quality lost under uniform INT8 and improves prefill throughput over FP16, yielding a controllable accuracy-efficiency frontier across model families. The implementation is available at https://github.com/HanzhiZhang-Ulrica/TileMix.

## 1. 核心问题与整体含义（研究动机和背景）

- **问题根源**：在长上下文LLM推理的**预填充阶段**，密集自注意力需计算二次方规模的查询-键得分矩阵（O(L²)），导致巨大的计算量和显存访问开销，成为长文本处理的核心瓶颈。
- **现有方法的三条路线与局限**：
  - **低精度量化**（如INT8）：通常采用**全图统一低精度**或按算子/阶段划分精度，未能在硬件对齐的二维得分tile级别进行空间精度路由。
  - **稀疏化方法**（如BigBird、MInference）：通过选择部分token交互降低计算量，但会**改变注意力图连接性**，可能丢失重要信息。
  - **IO感知融合注意力**（如FlashAttention）：通过tile切分和在线softmax提升访存效率，但算术路径（精度）在**内核调用级固定统一**。
- **核心空白**：缺乏一种将**数值精度作为可执行空间决策**（spatial decision）融入融合密集注意力内核的机制——即在保留全部合法token连接的前提下，对硬件对齐的得分tile组分配不同算术精度（FP16/INT8）。
- **TileMix的意义**：填补上述空白，首次将精度的空间路由（precision routing）下沉到FlashAttention风格的融合内核内部，形成一个无需训练、保留密集连接、可在精度与效率间灵活权衡的推理加速方案。

## 2. 论文提出的方法论

### 2.1 核心思想

- **以tile为粒度的精度路由**：将注意力矩阵划分为硬件对齐的二维得分tile（BLOCK_M × BLOCK_N），对每个tile组（tile group）独立分配FP16或INT8查询-键得分计算路径。
- **密集连接保持**：不删除任何合法token交互，只改变其算术路径，因此不引入稀疏性，精度路由和token连通性解耦。
- **共享在线softmax状态**：FP16与INT8两条得分路径在**同一在线softmax循环**中交替执行，共同更新行最大值、归一化器和输出累加器，且所有中间状态保持FP16。

### 2.2 关键技术细节

**（1）Tile划分与双层循环结构**
- 注意力矩阵按查询tile（外循环）和键/值tile（内循环）流式切分，遵循FlashAttention的内存层次优化策略。
- 每个Triton程序实例负责一个查询tile行，内循环从HBM流式加载键/值tile到SRAM和寄存器。

**（2）路由策略与位掩码编码**
- **路由决策**：二进制映射R，按KV头、查询tile行和键tile组索引；`R=1`表示走INT8路径，`R=0`表示走FP16路径。
- **位掩码打包**：每个查询tile行的所有tile组决策打包为一个64位整数，元数据规模仅为O(H_k·T_m)，开销极小。
- **常数时间查找**：内循环中通过一次移位与掩码操作（`(b >> g_j) & 1`）即可获得路由决策，保证延迟关键循环的低开销。
- **可扩展精度分组（Grouping）**：当序列变长时，通过分组因子g让一个路由位控制g个相邻键tile（g·BLOCK_N键token），从而在长上下文下保持64位字长覆盖全部区间，同时保留底层硬件计算tile尺寸不变。

**（3）FP16/INT8异构执行对齐**
- **INT8路径**：对Q和K做块级absmax对称量化（BLK_Q=128，BLK_K=64），使用INT8 Tensor Core MMA指令计算，INT32累加后，乘以块级缩放因子δ_Q·δ_K并除以√d，恢复为浮点得分。
- **FP16路径**：执行常规FP16矩阵乘并除以√d。
- 两条路径输出的得分进入**同一FP16在线softmax状态**，后续指数归一化与输出聚合完全共享。

**（4）灵活性与实际部署支持**
- **分组查询注意力（GQA）**：映射到同一KV头的多个查询头共享路由决策。
- **可变长度批处理**：通过flattened输入与cu_seqlens前缀和元数据实现无线程束（padding-free）执行。
- **INT8键/值缓存接口**：支持decode阶段的INT8 K/V缓存，K8参与INT8得分计算，V8在芯片上转换为FP16后参与PV聚合。
- **两种操作数准备模式**：quantize-once（预量化并复用紧凑INT8张量与缩放因子）与fused on-the-fly（片内即时生成INT8操作数），适应不同内存与性能需求。

## 6. 论文的主要结论与发现

- **均匀INT8对长上下文过于粗糙**：One（100% INT8）在多数数据集上准确度显著低于FP16，尤其在64k语境下差距明显，表明统一低精度路径无法保持长上下文质量。
- **TileMix混合精度恢复质量**：在相近或更高的INT8覆盖下，TileMix各布局普遍超越One，部分配置（如SpTrans在factrecall_en 16k）甚至**超过FP16基线**，证明空间精度路由比均匀低精度更优。
- **预填充吞吐显著提升**：在4k token下，SpTrans75达到31.80K tokens/s，而FlashAttention仅14.33K tokens/s、One为29.80K tokens/s——TileMix不仅超越FP16基线，还可匹敌甚至超越统一INT8的端到端效率。
- **精度-效率前沿可控**：通过INT8覆盖比例和路由布局，可以实现从“全FP16质量”到“近似INT8吞吐”的连续调优，为部署提供灵活性。
- **布局-任务交互**：不同布局在不同任务/模型上表现各异，如SpTrans在事实召回任务上有跨模型一致的显著优势，说明布局选择和任务特性相关，单一最优布局可能不存在。
- **路由对高重要性注意力有保护作用**：SpTrans25仅将约8.5%的heavy-hitter重要性质量暴露到INT8，远低于名义25%覆盖率，说明结构化空间路由在不动态检测的情况下自然保护重要交互。

## 7. 优点

- **概念创新性强**：首次将数值精度作为可执行的空间决策集成到融合注意力内核中，开辟了介于“全低精度”和“全高精度”之间的精细精度-效率调节维度。
- **工程优化精细**：位掩码打包+常数时间移位查询，使路由开销近乎为零；分组因子g的设计让64位掩码覆盖任意长度上下文；共享在线softmax保证了两条异构路径的无缝融合。
- **实用性突出**：免训练、支持GQA、变长批处理、INT8 KV缓存，并附带完整开源实现；设计了quantize-once与fused on-the-fly两种模式，兼顾性能和内存。
- **实验设计严谨**：端到端计时包含所有辅助开销，避免了只报MMA吞吐的常见误导；对比基线涵盖FP16、FlashAttention、均匀INT8、稀疏方法和专用INT8内核，公平且全面；数值分析从多维度（深度、精度、覆盖、大模型）验证稳定性。
- **理论分析到位**：通过heavy-hitter暴露度分析实证了静态结构化路由能在不解耦在线检测的条件下自动保护高重要性注意力质量，提供了解释性洞见。

## 8. 不足与局限

- **硬件和格式受限**：当前实现针对NVIDIA A100的FP16/INT8 Tensor Core路径优化，其他格式（FP8/INT4）和硬件平台需要额外适配。
- **路由策略静态化**：所有评测配置基于预先定义的静态模板，不随输入内容或任务特性自适应；虽然论文提及内核接口可接受自适应策略，但未验证实际采用动态路由时的收益与可行性。
- **注意力质量-任务覆盖窄**：实验集中于检索/QA等单轮长上下文任务，未覆盖需要生成能力或迭代推理的场景；决策质量在更复杂任务（如长文档摘要、多轮对话）上的效果有待验证。
- **上下文最长64k**：未覆盖当前业界关注的128k/256k/1M级上下文场景，在极长序列下的位掩码分组分析和吞吐表现缺乏直接证据。
- **稀疏基线比较争议**：TileMix计算量（FLOPs）远高于稀疏方法，但端到端TOPS对比中未见对操作数对比或公平FLOPs归一化讨论；论文的TOPS计算基于统一密集操作数，可能对稀疏方法不公平。
- **论文自身承认的限制**：TileMix目标定位于长上下文预填充的向前推理，目前未覆盖训练、微调或decode阶段的全面优化。
