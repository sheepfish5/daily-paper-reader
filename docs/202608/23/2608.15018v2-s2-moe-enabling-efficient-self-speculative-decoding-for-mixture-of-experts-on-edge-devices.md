## 摘要
在边缘设备上部署大型语言模型（LLM）进行推理，由于严格的内存和带宽限制而颇具挑战。尽管推测解码和混合专家模型（MoE）已被提出用于提升推理效率，但简单地将两者结合往往会引发过度的验证开销和较差的专家复用，限制了它们在内存受限的边缘场景中的有效性。在本工作中，我们提出S2-MoE，一种针对边缘设备上MoE推理的高效自推测解码框架。S2-MoE通过路由感知的自适应推测扩展减少冗余验证，通过复用感知的专家门控提升验证效率，并通过共享上下文对齐草稿与目标执行。在llama.cpp中实现，S2-MoE在多种MoE模型和数据集上的边缘设备中，相较标准自回归解码实现了最高5.3倍的加速（平均约2.0倍）。代码可在https://github.com/angerybob/S2-MoE获取。

## Abstract
Deploying large language models (LLMs) for inference on edge devices is challenging due to severe memory and bandwidth constraints. While speculative decoding and Mixture-of-Experts (MoE) have been proposed to improve inference efficiency, naively combining them often incurs excessive verification overhead and poor expert reuse, limiting their effectiveness in memory-bound edge settings. In this work, we propose S2-MoE, an efficient self-speculative decoding framework for MoE inference on edge devices. S2-MoE reduces redundant verification through routing-aware adaptive speculative expansion, improves verification efficiency with reuse-aware expert gating, and aligns draft and target execution via shared context. Implemented in llama$.$cpp, S2-MoE achieves up to $5.3\times$ speedup (about $2.0\times$ on average) over standard autoregressive decoding across diverse MoE models and datasets on edge devices. Code is available at https://github.com/angerybob/S2-MoE.

- **核心问题**：在边缘设备（如 Jetson 系列）上部署大语言模型（LLM）进行推理时，内存带宽是主要瓶颈。边缘推理通常以极小批量甚至单批模式运行，参数复用率低，导致吞吐量受限。
- **吞吐量分解视角**：论文将吞吐量建模为 `吞吐量 = 输出密度（tokens/迭代）/ 参数密度（GB/迭代） × 带宽`。要提升吞吐量，要么提高每次迭代生成的 token 数量（输出密度），要么降低每次迭代访问的参数量（参数密度）。
- **两种现有技术的互补性与矛盾**：
  - **推测解码（Speculative Decoding, SD）**：通过轻量草稿模型生成候选 token，再由目标模型并行验证，提高输出密度；
  - **混合专家（Mixture-of-Experts, MoE）**：每次只激活部分专家，降低参数密度。
  - 但两者简单组合在边缘场景下效果不佳：MoE 模型中草稿 token 可能激活不同的专家集合，导致验证阶段专家参数复用率极低，验证开销大幅增加；被拒绝的草稿 token 所触发的专家激活更成为纯冗余计算。
- **现有方法的不足**：
  - 依赖外部草稿模型的方法在 MoE 上难以同时做到轻量和高对齐；
  - 基于置信度的扩展/剪枝策略（如 EAGLE-3）无法反映专家级别的验证代价——置信度相似的 token 可能触发完全不同的专家激活模式，验证开销差异悬殊；
  - 自推测解码虽可从目标模型自身构造对齐良好的草稿，但在 MoE 中仍面临草稿保真度损失、过度冗余验证和专家复用不足三重挑战。
- **论文目标**：提出一个同时保证高草稿保真度、低冗余验证和强参数复用的推测解码框架，使 MoE 推理在边缘设备上获得实质加速。

## 2. 方法论：核心思想、关键技术细节与算法流程

论文提出 **S2-MoE**，由三个互补的组件构成：

### 2.1 路由感知自适应推测扩展（Routing-aware Adaptive Speculative Expansion）

- **核心思想**：草稿树的扩展不应仅依据 token 置信度，而应同时考虑验证开销，即基于"效用"（Utility）进行贪心扩展，避免高成本低收益的候选分支。
- **期望收益**：对深度 k 处的草稿 token $i$，其接受概率近似为前缀置信度 $p_i = \prod_{j=1}^{k} p_{i,j}$，期望收益定义为：
  $$B_i = p_i \cdot T_{\text{AR}}$$
  其中 $T_{\text{AR}}$ 是目标模型单步自回归解码的平均延迟。
- **路由感知代价估计**：加入 token $i$ 的边际验证代价为：
  $$\Delta C_{\text{ver}}(i|S) = \left| E_i \setminus \bigcup_{j \in S} E_j \right| \cdot T_{\text{exp}}$$
  其中 $E_i$ 为 token $i$ 预测激活的专家集合，$S$ 为已选草稿 token 集合，$T_{\text{exp}}$ 为额外激活一个专家带来的延迟。总扩展代价为：
  $$C_i = \Delta C_{\text{ver}}(i|S) + C_i^{\text{draft}}$$
- **自适应扩展准则**：效用函数 $U_i = B_i / C_i$，当 $U_i \geq 1$（期望收益超过估计代价）时贪心纳入候选。
- **与基线策略的对比**：固定宽度扩展（无剪枝）验证所有候选，冗余激活多；纯置信度剪枝对低成本候选识别不足；S2-MoE 综合考虑接受概率与边际专家激活成本，在收益/代价权衡上更优（图 4）。
- **代价模型准确性**：与实测验证延迟对比，$R^2$ 达 0.943–0.999，MAPE 为 0.8%–4.5%，说明路由信息可准确预测验证开销。

### 2.2 复用感知专家门控（Reuse-aware Expert Gating）

- **核心思想**：MoE 模型相邻 token 常被路由到不同专家，导致验证阶段参数复用极低。该组件通过有界软性路由偏置，促使草稿 token 在验证时更多地共享已激活的专家。
- **跨 token 专家重要性聚合**：对每个 token $b$，以置信度权重 $w_b$ 加权其门控 logits $\ell_{b,e}$，聚合得到专家 $e$ 的重要性分数：
  $$g_e = \sum_{b \in \mathcal{B}} w_b \cdot \ell_{b,e}$$
  高置信度 token（更可能被接受）的专家偏好获得更大权重。
- **全局优选专家选择**：选取 $E^* = \text{TopCap}(\{g_e\})$，其中 $|E^*| \leq \text{cap}$ 且 $\text{cap} \geq k$（$k$ 为每 token 激活专家数），确保原始 top-k 专家仍可被选中，约束偏置范围。
- **软路由偏置**：对每个 token $b$ 的门控 logits 注入加法偏置：
  $$\ell'_{b,e} = \ell_{b,e} + \lambda_b \cdot \mathbb{1}[e \in E^*]$$
  其中 $\lambda_b$ 正比于 token $b$ 的 top-1 专家与第 $k+1$ 个专家之间的分数差，使偏置主要作用于 top-k 边界附近的"边缘专家"，不过度扰动主导路由决策。
- **关键性质**：该偏置仅影响边缘专家选择，几乎不改变高置信 token 的原始路由；同时实际验证代价不会超过第 2.1 节基于原始路由的估计（估计偏保守）。
- **实现**：融合 CUDA kernel，开销可忽略。示例中激活专家从 6 个降至 4 个，显著提高参数复用。

### 2.3 上下文对齐自推测解码（Context-aligned Self-speculative Decoding）

- **核心思想**：草稿模型与目标模型共享统一 KV Cache，避免草稿独立维护上下文导致误差跨迭代累积。
- **流程**：目标模型先处理 prompt 建立 KV cache；推测生成时草稿直接读取共享上下文；草稿产生的 KV 更新临时写入、验证前回滚，仅被接受的 token 写入共享缓存。
- **效果**：将草稿误差限定在单个推测步内，阻止长期解码中的分布漂移（图 2(g) 中 KL 散度增长显著受抑制）。

### 2.4 系统实现

- 完整集成于 **llama.cpp** 解码流水线，支持 NVIDIA Jetson Orin 与 RTX 4090。
- 实现**专家级参数 offload**：非专家和共享参数常驻设备内存，单个专家参数按需动态加载；频繁激活的专家根据离线 profiling 驻留内存。比起 llama.cpp 原生的层级 offload，更适配 MoE 的稀疏激活特性。

  - RTX 4090 上 Qwen3-30B-A3B 达到最高 **3.79×** 加速，验证了方法对更大模型和更高带宽设备的扩展性；
  - GPT-OSS-120B 离线统计复用率为 96%，实际加速 1.89×–2.74×，说明专家复用策略在大规模 MoE 上依然有效。
- **消融与机制验证**：
  - 三个组件各自贡献：路由感知扩展（+15.98%）、复用感知门控（+10.39%）、上下文对齐（+5.92%），叠加后总提升约 38.16%（MT 任务）；
  - 上下文对齐显著降低 Mean KL（LongBench 上降至接近 AR 的水平），证实其控制草稿误差累积的有效性；
  - 自适应扩展在 **验证代价降低 30%以上** 的同时保持了与固定宽度扩展几乎相同的接受长度；
  - 复用感知门控将专家复用率从 42.3% 提升到 87.4%，且对下游任务质量无实质影响；
  - 敏感性与开销分析表明，$k_{\text{draft}}$ 与 reuse cap 在较宽范围内性能稳定。

## 7. 结论与贡献

- **主要贡献点**：
  - 提出面向边缘 MoE 推理的 **S2-MoE** 框架，将推测解码优化从“访问更少参数”和“生成更多 token”的二选一视角，转变为对两者联合收益/代价的统一建模，填补了推测解码在 MoE 边缘场景下缺失路由感知的空白；
  - 设计了**路由感知的自适应草稿扩展**，将验证代价分解为专家激活的边际成本，实现数据无关、可解释的扩展决策；
  - 设计了**复用感知的专家门控**，通过软偏置提升跨 token 参数复用，且训练无关、近乎零开销；
  - 设计了**上下文对齐自推测解码**，有效消除长程草稿分布漂移，在长上下文中显著降低质量退化；
  - 在 llama.cpp 上实现完整的 **专家级 offload 推理系统**，验证了 S2-MoE 在真实边缘硬件上的加速效果（最高 3.79× vs AR，1.72× vs EAGLE-3）。
- **可复现性**：论文公开了基于 llama.cpp 的系统实现与评测脚本，复现难度低。
- **潜在意义**：S2-MoE 的理论框架——将路由信息作为推理代价先验并纳入解码策略——不仅适用于 MoE 推测解码，亦可拓展到 MoE 模型量化、层剪枝、设备调度等多个方向，为“成本感知”的推理优化提供了范式参考。

## 8. 局限性

- 自适应扩展的代价模型依赖对硬件延迟参数（$T_{\text{AR}}$、$T_{\text{exp}}$）的离线 profiling，设备更换后需重新标定，未讨论标定误差对性能的鲁棒性边界。
- 复用感知门控是以“牺牲少量原始路由保真度”换取参数复用，论文仅以分布距离指标间接验证质量损失，未在更敏感的任务（如多步推理、复杂指令跟随）上直接测量偏置带来的端到端质量影响。
- 验证实验全部基于 4 个 MoE 模型，其中 3 个为开源社区主流模型、1 个为设计代际较新的模型，覆盖面有限；未涉及更细粒度专家（如 fine-grained expert）或深层 MoE（如 DeepSeek-V3-R1）等最新架构。
- 未报告功耗、能效比或内存带宽实测利用率等边缘部署关键指标。
- 论文使用单次运行的 Tok/s 数字作为主要比较依据，缺乏多次运行方差，削弱了结论在真实不稳定边缘硬件上的稳健性论证。

## 9. 个人评论与启发

- **强项**：S2-MoE 的直觉非常清晰、设计模块之间互相咬合——路由感知扩展负责“不选亏本 token”，复用感知门控负责“让确定要验证的 token 少付代价”，上下文对齐负责“让草稿路径与目标路径尽量一致”，三者在问题空间上有明确分工，而非简单叠加；实验设计也系统性地回应了每个模块的独立价值。
- **启发**：
  - 论文展示了“将系统级瓶颈（内存带宽）转化为算法级信号（专家激活代价）”的建模思路，对边缘 LLM 优化研究有较强借鉴价值；
  - 其效用函数 $B_i/C_i$ 的框架可以泛化为更一般的“先验代价/期望收益”解码准则，例如扩展到量化感知（不同层的 bit 宽度不同）或内存感知（不同阶段带宽争用）的推理调度场景。
- **可改进建议**：重复跑实验并报告方差；补充功耗/能效对比；在 DeepSeek-V3、Qwen3-MoE 等更大规模/更新架构的模型上验证；将代价模型从线性近似扩展到考虑带宽争用的非线性模型；讨论标定漂移和参数敏感性的理论边界。

## 10. 综合评分

- **新颖性（5/5）**：首次将路由感知的代价建模引入 MoE 推测解码的草稿扩展决策，设计层面有明确的理论动机和系统性拆解。
- **完整性（4/5）**：方法、系统实现、评测、消融、敏感性分析齐全，但缺少方差报告、功耗数据和部分最新架构验证。
- **写作质量（4.5/5）**：动机叙述清楚、公式与动机对应良好、图表设计直观；图表数量较多，部分附录数据归纳可再精炼。
- **可复现性（4.5/5）**：基于 llama.cpp 集成且公开代码与配置，复现成本低；硬件特定参数需要自行 profiling，但论文给出了详细说明。
- **实用性（4.5/5）**：training-free、即在即用，对 Jetson 等边缘平台的 MoE 推理有明显工程价值。
- **总体评分（4.5/5）**：一篇结构完整、动机充分、方法新颖且工程落地扎实的高质量系统论文，主要扣分点在于实验统计严谨性与对最新大规模 MoE 架构的验证不足。
