## 摘要
我们提出了MoNe，一种轻量级模块化神经记忆，可附加到任何冻结的预训练Transformer上，无需重新训练即可实现长上下文推理。MoNe通过测试时学习具有层局部梯度更新的快速权重神经记忆网络，以固定大小分段读取上下文；在推理时，记忆仅从查询词元生成键和值，无需重新读取上下文词元。这种两阶段设计将推理成本与上下文长度解耦，实现了O(N)预处理和O(1)查询成本，峰值GPU内存不随N增长。在128K词元时，与ICL相比，MoNe将计算量和峰值GPU内存均减少约80%，且仅增加6.4%的参数开销。MoNe能够泛化到远超骨干网络原生窗口的上下文长度，在RULER的大海捞针和单词提取基准上取得了强劲性能，而ICL在这些基准上性能急剧下降。

## Abstract
We present MoNe, a lightweight modular neural memory that attaches to any frozen pretrained Transformer to enable long-context inference without retraining. MoNe reads context in fixed-size segments via test-time learning of fast-weight neural memory networks with layer-localized gradient updates; at inference, the memory generates keys and values from the query tokens alone, with no context tokens re-read. This two-phase design decouples inference cost from context length, achieving $O(N)$ preprocessing and $O(1)$ query cost with peak GPU memory that does not grow with $N$. At 128K tokens, MoNe reduces both compute and peak GPU memory by approximately 80% compared to ICL with only 6.4% parameter overhead. MoNe generalizes to context lengths far beyond the backbone's native window, achieving strong performance on needle-in-a-haystack and word extraction benchmarks from RULER, where ICL degrades sharply.

- **研究动机**：随着 LLM 在个性化助手、文档问答、智能体系统等场景中处理日益增长的长上下文，传统的 In-Context Learning（ICL）存在两大瓶颈：①自注意力的 FLOPs 随序列长度呈二次增长（O(N²)）；②KV 缓存随上下文长度线性增长，在移动设备等资源受限硬件上难以承受。此外，小型模型即使在原生窗口内也难以从长提示中可靠提取信息。
- **现有方案的不足**：

- **核心含义**：MoNe 提出了一种轻量级"插件式"模块化神经记忆，使得推理成本与上下文长度解耦（O(N) 预处理 + O(1) 查询成本），同时保持峰值 GPU 内存不随 N 增长，并且能泛化到远超骨干模型原生窗口的上下文长度。

## 2. 论文提出的方法论

- **核心思想**：在冻结的预训练 Transformer 的每一解码器层上附加一个快速权重神经记忆模块。通过测试时学习（test-time learning）将长上下文压缩为记忆中的快速权重；推理时，仅由查询词元生成固定数量的记忆词元，无需重新读取任何上下文词元。
- **两阶段设计**：
  - **测试时学习阶段**：将上下文 C 划分为 S 个固定大小（T=512）的非重叠分段，逐段顺序处理。每个分段的隐藏状态经冻结的骨干权重（Wq、Wk、Wv）投影后，通过**层局部梯度更新**（layer-localized gradient updates）更新快速权重 W(l)，总计算量为 O(N)。
  - **推理阶段**：查询词元通过 Wq 投影后，仅用于读取快速权重状态 W(l)_S，生成固定大小的记忆词元（每个层 T 个），再经 Wk、Wv 投影后与查询自身的 K、V 拼接参与注意力计算。查询成本为 O(1)，与上下文长度无关。
- **关键公式与机制**：
  - **记忆模块**：每层使用 SwiGLU MLP，M(x; W(l)) = W_out^⊤(SiLU(W_in x) ⊙ W_gate x)，三矩阵均为 R^{dh×dh}，相比线性映射具有更强表达能力。
  - **关联记忆损失**：ℓ(l)_{s,j} = −(v(l)_{s,j})^⊤ M(k(l)_{s,j}; W(l))，即最大化记忆输出与目标值的内积，直接将"键→值"关联印刻到快速权重中。
  - **梯度更新**：W(l)_s = W(l)_{s−1} − μ(l)_s，其中 μ(l)_s 聚合逐 token 学习率和数据相关的动量衰减；梯度完全由本层前向激活计算，不跨层传播（∂ℓ(l)/∂W(l') = 0, ∀ l' ≠ l），实现真正的模块化。
  - **位置编码**：采用**分段局部 RoPE**（plocal = j mod T），位置索引始终落在 [0, T) 范围内，与总上下文长度无关；推理时查询长度 Q ≪ T，自动落在同一范围内，无需位置插值，从而实现 32× 的超窗口泛化。
  - **训练方式**：LoRA 适配器和元参数（η(l)、动量投影、输出缩放）通过离线生成损失训练，部署时冻结；测试时仅快速权重更新，运行的是固定预学习算法。
- **附加开销**：仅 6.4% 的参数开销（每 8 层约 1260 万参数，占骨干大小的约 2.1%）。

## 3. 实验设计

- **骨干模型**：Qwen2.5-0.5B-Instruct（24 层解码器，隐藏维度 d，冻结权重）。
- **数据集 / 基准**：RULER benchmark（长上下文评测标准）中的三个任务：
  - **S-NIAH**（单针大海捞针）：随机深度嵌入单个键值对，按子串精确匹配（Sub-EM）评估。
  - **MK-NIAH**（多键大海捞针）：在 Paul Graham 散文片段中散布四个键值对，查询一个键的值，其余为干扰项，Sub-EM 评估。
  - **FWE**（高频词提取）：Zipfian 分布合成 6 字符词，需识别频率最高的 3 个词，按变量召回率评估。
- **上下文长度设置**：划分为窗口内（4K、8K、16K、32K）和超窗口（48K、64K、96K、128K）两组，共 8 种长度；训练上下文最长 4K。
- **对比方法**：
  - **ICL**：完整上下文直接作为提示。
  - **RAG**：128 token 分块 + BGE-Large 嵌入，取 top-K（K ∈ {1, 4, 8}）块拼接，报告每长度下最优分数。
- **训练数据**：每个 N ∈ {2,...,8}（对应 1K–4K）生成 30K 样本；评估每组 100 样本。

## 6. 论文的主要结论与发现

- **性能优势**：MoNe 在 S-NIAH、MK-NIAH、FWE 三个任务上，从 4K 至 128K 的所有长度上几乎保持满分（0.94–1.00），而 ICL 在超过 32K 原生窗口后急剧崩溃（如 MK-NIAH 128K 时降至 0.00）。
- **对比 RAG**：RAG 在需要全上下文综合的任务上表现平稳但始终受限（MK-NIAH 最高 0.92，FWE 约 0.60），无法超越 MoNe 的综合推理能力。
- **效率优势**：128K 时，MoNe 相比 ICL 总 FLOPs 降低约 81%（149.61 T vs 786.33 T），峰值 GPU 内存降低约 80%（1.41 GB vs 7.07 GB），且峰值显存**不随上下文增长**（32K 和 128K 均为 1.41 GB）。
- **超窗泛化**：仅在最多 4K 上下文中训练，却可泛化到 128K（32× 外推），无需额外训练或位置插值，得益于分段局部 RoPE。
- **架构选择**：全层覆盖（24 层）+ T=512 是性能-效率最优配置。

## 7. 优点

- **即插即用**：可附加到任何冻结的预训练 Transformer 上，无需修改骨干权重或重新训练，兼容性极强。
- **真正的成本解耦**：O(N) 预处理 + O(1) 查询 + 常数峰值显存，从根本上解决了长上下文推理的成本瓶颈。
- **超窗口泛化能力**：无需长上下文训练即可实现 32× 外推，极大拓展了模型的可用上下文范围。
- **模块化设计精妙**：层局部梯度更新使每个记忆模块独立学习，既高效又具备理论上的可扩展性。
- **实用特性**：快速权重状态可跨多个查询复用、可随新上下文增量扩展而无需重处理旧内容，适合持续学习和个性化场景。
- **消融实验扎实**：对层覆盖和段大小两个关键设计维度做了系统性分析，为实践提供了清晰指导。

## 8. 不足与局限

- **模型规模验证有限**：仅在 Qwen2.5-0.5B 小型骨干上验证；更大模型（7B、70B 级）上的效果和效率尚未验证，结论普遍性存疑。
- **任务类型局限**：RULER 的 S-NIAH / MK-NIAH / FWE 属于受控合成检索任务，与自然语言长文档 QA、多文档推理、真实对话历史等复杂场景尚有差距（作者也在 Limitations 中承认这一点）。
- **RAG 基线可能未达最优**：RAG 使用固定 128 token 分块和 BGE-Large 嵌入，未尝试查询改写、重排序或更优的混合检索策略；K 的上限为 8，可能限制其上限表现。
- **缺乏多数据集交叉验证**：未在 LongBench、ZeroSCROLLS、HotpotQA 等经典长上下文基准上评估，实验广度不足。
- **训练数据量与随机性**：训练集每长度 30K、测试集每长度 100 样本；未报告多次运行的标准差或置信区间，对结果稳定性的论证不足。
