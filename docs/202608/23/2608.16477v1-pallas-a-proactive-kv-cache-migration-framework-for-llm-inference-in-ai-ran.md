## 摘要
AI-RAN 将大语言模型（LLM）服务带到移动用户附近，但蜂窝切换可能使活跃请求与其推理状态分离：用户连接到目标基站（gNB），而庞大且不断增长的键值（KV）缓存仍留在源端。在源端保留推理可维持服务连续性，但会持续增加令牌间延迟（ITL），而在目标端恢复状态可恢复服务局部性，但需要在切换后才进行 KV 缓存传输、重计算或两者组合，这直接延长了服务中断时间（SIT）。本文提出 Pallas，一种\textit{主动式} KV 缓存迁移框架，在预测目标端提前准备好推理状态，与源端推理和令牌交付并行进行。在准备触发时，Pallas 将令牌序列划分为稳定的历史前缀和动态演化的后缀。目标端通过本地预填充重建前缀，而源端流式传输为后缀生成的 KV 块。切换时，目标端将两部分组装成最新的 KV 缓存并恢复本地解码，仅留下未完成的准备部分计入 SIT。在线调度器根据移动性预测和运行时遥测选择\textit{预取窗口}，该窗口决定切换前准备开始的时间。在三种 LLM 和 100--500~\mathrm{Mbps} 的 gNB 间链路上，我们基于 vLLM 的原型在平均 SIT 上比目标端恢复方法降低 2.28--89.68 倍，与源端转发相比平均 ITL 降低 16.0%--50.0%。

## Abstract
AI-RAN brings large language model (LLM) serving close to mobile users, but cellular handover can separate an active request from its inference state: the user attaches to a target base station (gNB) while the large and growing key-value (KV) cache remains at the source. Retaining inference at the source preserves service continuity but persistently increases inter-token latency (ITL), whereas recovering the state at the target restores serving locality but requires KV-cache transfer, recomputation, or a combination of both only after handover, directly prolonging service interruption time (SIT).   This work presents Pallas, a \textit{proactive} KV-cache migration framework that prepares the inference state at the predicted target before handover, in parallel with ongoing source-side inference and token delivery. At the preparation trigger, Pallas partitions the token sequence into a stable historical prefix and an evolving suffix. The target reconstructs the prefix through local prefill, while the source streams the KV blocks generated for the suffix. At handover, the target assembles both portions into an up-to-date KV cache and resumes decoding locally, leaving only unfinished preparation to contribute to SIT. An online scheduler selects the \textit{prefetching window}, which determines how early preparation begins before handover, based on mobility predictions and runtime telemetry. Across three LLMs and $100$--$500~\mathrm{Mbps}$ inter-gNB links, our vLLM-based prototype reduces average SIT by factors of $2.28$--$89.68$ over target-side recovery approaches and lowers average ITL by $16.0\%$--$50.0\%$ compared with source-side forwarding.

## 论文总结：Pallas：AI-RAN 中面向 LLM 推理的主动式 KV 缓存迁移框架

### 1. 论文的核心问题与整体含义（研究动机和背景）

- **核心问题**：在 AI-RAN（AI 无线接入网）架构下，大语言模型（LLM）推理服务被部署在基站（gNB）附近，以降低通信延迟。然而，用户的移动性会导致蜂窝切换（handover），即用户设备（UE）从源 gNB 连接到目标 gNB。此时，正在进行的 LLM 请求所依赖的、持续增长的键值（KV）缓存仍留在源 gNB，导致推理状态与用户分离。
- **核心矛盾（服务连续性与服务局部性）**：
    - **服务连续性**：若继续在源 gNB 保留推理，并将生成的 token 经由目标 gNB 转发给用户（如 Detour 方法），虽避免了状态迁移，但会引入额外的路由跳数，导致**令牌间延迟（ITL）持续恶化**，形成长尾延迟，难以满足交互式应用的延迟目标（如 100ms）。
    - **服务局部性**：若在目标 gNB 恢复推理状态，则需要在切换后才进行 KV 缓存的全量传输（Full-Copy）、重计算（Recomputation）或二者结合（ctHO），这会将长时间的**服务中断时间（SIT）** 置于用户感知的关键路径上。
- **关键洞察**：现有方法均将切换视为状态恢复的**触发点**，其恢复工作全部在切换后开始，导致 SIT 无法避免。论文提出应将切换视为状态准备的**截止期限（deadline）**，利用移动性预测技术在切换前主动完成大部分状态准备工作。

### 2. 论文提出的方法论：核心思想、关键技术细节与算法流程

论文提出了 **Pallas**，一种主动式（proactive）KV 缓存迁移框架，其核心思想是在预测的切换时间之前，并行地在目标端准备推理状态。

- **核心思想：切分与并行准备**。在准备触发时刻，Pallas 将由当前所有 token 组成的序列划分为两部分：
    - **稳定历史前缀（Stable Historical Prefix）**：已处理的所有 token，其 KV 状态是稳定的。
    - **动态演化后缀（Evolving Suffix）**：在触发后由源端持续生成的新 token。
- **并行状态准备流程**：
    1. **前缀重建**：源 gNB 将历史前缀的 token ID 发送给目标 gNB，目标 gNB 通过本地 prefill（预填充）重建这部分 KV 缓存。
    2. **后缀流式传输**：源 gNB 在持续生成 token 的同时，将新产生的后缀 KV cache 块通过 gRPC 异步流式传输给目标 gNB 并缓存。
- **切换与服务恢复**：在切换发生时，源 gNB 停止解码，将最终 token 序列快照和所有未同步的 KV 缓存块发送给目标。目标 gNB 将重建的前缀与接收的后缀组装成完整的 KV 缓存，并恢复本地解码。只有尚未完成的准备部分（即残差工作）计入 SIT。
- **核心机制：Prefetching-Window（预取窗口）选择**。窗口长度 ($T_w$) 是关键所在，它决定了准备开始的时间。窗口过短会导致准备未完成，SIT 变长；窗口过长则会导致历史前缀更短、增量后缀的 KV 缓存传输量更大，并造成目标端资源的过早占用。为此，Pallas 提出了一个**在线调度器（Scheduler Engine）**：
    - **成本模型**：定义了一个权衡 SIT 和早期准备暴露时间（$T_{early}$）的目标函数 $J(T_w) = \alpha \cdot T_{SIT}(T_w) + (1-\alpha) \cdot T_{early}(T_w)$。
    - **调度流程**（Algorithm 1）：
        1. 输入：移动性预测（目标 gNB，切换时间）和运行时遥测（上下文长度、prefill 吞吐、decode 吞吐、gNB 间 goodput）。
        2.  **准入决策**：检查目标 gNB 是否有兼容的 LLM 实例和充足的可用 VRAM，否则调用回退策略。
        3. **候选窗口评估**：基于预测数据（如未来的前缀长度 $\hat{L}_{hist}$），枚举一系列候选窗口并评估成本函数，选择成本最小的窗口 $T_w^*$。
        4. **触发决策**：如果预测的剩余时间小于等于选中的窗口长度，则触发并行状态准备；否则，推迟到下一个控制周期重新评估。
- **处理预测不确定性**：如果切换时间预测更新，只需调整截止期限；如果目标 gNB 预测改变，则取消旧的准备并重新执行整个调度过程，并使用“迁移纪元”防止旧数据污染。
