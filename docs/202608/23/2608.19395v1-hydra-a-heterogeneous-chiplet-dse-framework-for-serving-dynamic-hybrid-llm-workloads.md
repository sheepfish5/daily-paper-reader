## 摘要
混合Transformer-Mamba大语言模型（LLM）提升了长上下文效率，但它们异构的计算和通信模式使得高效硬件加速变得复杂。基于芯片组的架构通过集成专用计算和存储单元提供了可扩展的解决方案。然而，涵盖静态架构配置和动态运行时策略的设计空间庞大，难以穷举探索。为应对这一挑战，我们提出了HYDRA，一个面向异构芯片组系统上混合LLM服务的全面设计空间探索框架。HYDRA联合探索芯片组组成、布局、芯片间带宽配置、动态批处理和运行时调度。它集成了通信感知布局、动态批处理、弹性任务调度以及一个快速基于马尔科夫的性能估计器，能够捕获多租户运行时动态，以实现高效准确的探索。在所有工作负载中，HYDRA实现了1.55倍的吞吐量，平均首令牌时间降低43.7%，与最先进的基线相比吞吐量增益最高可达2.3倍。这些结果凸显了架构与运行时策略的协同设计对于在异构芯片组系统上高效进行大规模LLM服务至关重要。

## Abstract
Hybrid Transformer-Mamba large language models (LLMs) enhance long-context efficiency, but their heterogeneous computation and communication patterns complicate efficient hardware acceleration. Chiplet-based architectures offer a scalable solution by integrating specialized compute and memory units. However, the design space spanning static architectural configurations and dynamic runtime policies is prohibitively large to explore exhaustively. To address this challenge, we present HYDRA, a comprehensive design space exploration framework for hybrid LLM serving on heterogeneous chiplet systems. HYDRA jointly explores chiplet composition, placement, inter-chiplet bandwidth provisioning, dynamic batching, and runtime scheduling. It integrates communication-aware placement, dynamic batching, elastic task scheduling, and a fast Markov-based performance estimator that captures multi-tenant runtime dynamics for efficient and accurate exploration. Across all workloads, HYDRA delivers 1.55x the throughput and 43.7 percent lower time-to-first-token on average, with throughput gains reaching up to 2.3x compared to state-of-the-art baselines. These results highlight that co-designing architecture and runtime policies is critical for efficient large-scale LLM serving on heterogeneous chiplet systems.

- **核心矛盾**：

### 2. 论文提出的方法论

**核心思想**：将LLM服务建模为工作负载动态、异构chiplet资源、运行时批处理/调度策略三者耦合的系统，联合探索架构与运行时策略，以吞吐量（TP）和首Token时延（TTFT）为目标进行Pareto优化。

**关键技术细节**：

- **系统建模输入**：
  - 工作负载规格：模型层/块级描述（计算、存储、通信量）、数据集的prefill/decode特征、请求到达过程。
  - 系统约束：chiplet库、NoI拓扑（如2D mesh）、interposer尺寸、die面积预算。
- **设计空间定义**（宏观架构）：
  - Chiplet类型：prefill/decode优化的Attention加速器（Ap/Ad）、prefill/decode优化的Mamba加速器（Mp/Md）。
  - Chiplet组成：各类型chiplet数量。
  - NoI带宽：D2D链路带宽配置（如256/384/512/640 GB/s）。
  - 由interposer面积预算约束。
- **两阶段通信感知放置**（Section IV-A）：
  - **Step 1 HBM放置与分区**：将HBM置于interposer外环，按Mamba/Attention分组，以最大化并发请求数（`min(rM, rA)`）为目标选择分区。Mamba并发数估计公式：`rM = max(0, (NM·CHBM − LM·WM) / SM)`。
  - **Step 2 计算chiplet放置**：以加权曼哈顿距离最小化为目标，将计算chiplet就近放置于其频繁访问的HBM组周边：`argmin Σ d(p(c), h)·v(k,c)`。冲突时按chiplet组大小降序依次放置。
- **动态请求批处理**（Section IV-B）：
  - 连续批处理：请求随时按资源可用性进入活动批，无批量同步等待。
  - 准入条件：批大小不大于用户设定上限，且估计token需求不超过系统token预算。
  - 虚拟化内存块（类似vLLM）管理KV cache / recurrent state，按需分配物理内存。
  - 请求级抢占：内存不足时优先抢占生成最少token的请求。
- **弹性任务调度**（Section IV-C）：
  - 初始空间流水线映射：根据性能档案（tcomp + tcomm）构造任务–chiplet偏好分配，优化瓶颈chiplet负载（`argmin max tΩ_c`）。
  - 通信延迟模型：`tcomm(k,c) = dMan(c,mk)·Vk / BNoI`。
  - 运行时弹性调度器：监控chiplet利用率/队列状态，在负载不均衡时将任务迁移到低利用率chiplet，在温和不均衡时保留放置偏好以维持通信局部性。
- **马尔可夫性能估计器**（Section V）：
  - 将高维调度问题抽象为chiplet分配状态的连续时间马尔可夫链（CTMC）：状态`s ∈ {0,…,N}`表示分配给prefill的chiplet数，`N−s`个chiplet服务decode。
  - 状态相关服务容量：`Gp(s) = cp,P·gp,P + cp,D·gp,D`（prefill），`Gd(s) = cd,D·gd,D + cd,P·gd,P`（decode）。
  - 用流模型（fluid-queue model）近似系统动态，得到各状态占用时间比例πs，进而估算吞吐量：`Tp = Σ πs·Gd(s)`，并同步估算TTFT。
  - 定位：作为快速剪枝/排序机制，识别有前景的设计区域，再经详细模拟验证，非替代详细模拟。

### 6. 论文的主要结论与发现

- HYDRA全面优化后，平均吞吐量达基线1.55倍、平均TTFT降低43.7%，吞吐峰值增益最高2.3倍。
- 通信感知放置（CP）比Round-robin/随机放置显著降低NoI拥塞，提高通信局部性，吞吐增益3%–100%。
- 弹性任务调度（ET）比静态映射提升吞吐量3%–150%、TTFT降低1.02×–3.14×；相比work-stealing在多数场景更好，因兼顾负载均衡与通信局部性。
- 动态批处理（DB）在静态批处理之上再提升吞吐量15%、TTFT再降23%平均。
- 马尔可夫估计器与穷举Pareto前沿余弦相似度达0.9，恢复93%的最大吞吐量，探索时间从数天降至4–15分钟（相对穷举缩减2520–8520倍配置数量）。
- 专门化–泛化权衡：面向单一模型的最优配置可能在其他混合模型上严重退化（如Jamba专用配置在Nemo上仅保留0.31性能）；面向多模型的联合DSE能限制最坏情况退化≤14%，为多模型/演进模型平台提供更稳健方案。
- 核心结论：配置通信带宽、计算/存储资源与运行时动态控制策略必须协同设计，仅优化架构或仅优化运行时都不足以支撑高效混合LLM服务。

### 7. 优点

- **方法层面**：
  - 明确提出“架构–运行时协同设计”理念，联合探索chiplet组成、放置、带宽、批处理、调度五个维度，比先前工作仅聚焦单一方面更全面。
  - 将复杂动态系统抽象为低维CTMC状态空间（以chiplet分配为核心变量），配合流模型估计吞吐量/TTFT，在速度与精度间取得良好平衡，且明确阐释了估计器与详细模拟的分工（快速剪枝+详细验证），方法定位务实。
  - 两阶段放置策略（先HBM分区、再通信感知放置）将组合优化问题分解为可处理子问题，工程可行性高。
  - 弹性调度在保留初始放置通信局部性的前提下动态纠正负载不均衡，体现“静态偏好+动态修正”的设计智慧，优于纯动态迁移方案（如work-stealing）。
  - 动态批处理引入token预算、虚拟化内存块、请求级抢占等机制，直接解决多租户混合LLM服务的核心内存与批管理难题。
- **实验层面**：
  - 消融实验设计清晰（CP/ET/DB逐步叠加），能定量归因各策略的独立贡献。
  - 额外对比纳入RR、Random、FCFS、work-stealing等多个基线，验证方法稳健性。
  - 专门化–泛化研究补充了跨模型迁移分析，为实际部署决策（专用 vs. 通用）提供实证依据。
- **可用性**：开源在GitHub，支持复现与扩展。

### 8. 不足与局限

- **实验覆盖局限**：
  - 模型尺寸有限（最大7B级），未覆盖当前主流70B/百亿参数以上超大规模模型，超大模型的KV cache与通信模式可能使结论迁移受限。
  - 每种模型只配一个代表数据集组合，混合模型（Nemotron-H）与纯Transformer/纯SSM的对比不完全对称（模型参数量不同）。
  - 算力与功耗/热/可靠性等指标未纳入优化目标。论文末尾已承认此为未来工作；Chiplet系统的功耗/热在高密度集成下可能显著改变最优设计点，是现实中的关键约束。
- **方法偏差风险**：
  - 马尔可夫估计器在部分场景误差较大（如Nemotron-H–LW上B⋆吞吐量偏8%、MT偏12%），虽保留排序能力，但具体最优配置可能偏移。
  - NoI带宽从256–640 GB/s离散取值，真实系统可选带宽可能连续或受封装/引脚限制更复杂。
  - 通信延迟模型采用线性曼哈顿距离加权，忽略实际网络拥塞的非线性效应（尽管模拟阶段会捕捉拥塞，但初始映射依赖的估计可能偏离实际最佳映射）。
- **应用限制**：
  - 不支持MoE（Mixture-of-Experts）结构的显式建模，而Jamba等真实混合模型包含MoE层。
  - 未考虑多节点/跨封装扩展；仅限2.5D单interposer系统。
  - 对动态批处理的max batch size等超参数敏感，论文未提供超参数调优的详细分析。
