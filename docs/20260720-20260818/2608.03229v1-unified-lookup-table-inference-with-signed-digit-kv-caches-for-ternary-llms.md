## 摘要
三值大语言模型使其权重主导的投影变得紧凑高效，但注意力机制仍然不匹配：其K/V缓存是在线创建的，通常由独立的高精度引擎处理。单独压缩该缓存并不能解决这种不匹配。为了使用与三值投影相同的查找表机制来执行注意力，一次归约中累积的值必须保持兼容的表示形式和尺度。在因果解码过程中，键和值的这一要求也有所不同，因为新生成的值可能属于未完成的缓存块。本工作为三值大语言模型开发了一种统一的查找表推理方法。它围绕注意力的归约结构，将运行时K/V状态存储为缩放的多平面有符号数字。生成的数字平面直接被激活导出表使用，从而避免了缓存存储与注意力计算之间的密集K/V物化。该设计结合了在线K/V形成、对不完整值块的有限处理，以及用于线性投影和注意力的共享多流数据通路。约束引导搜索为目标的效率-质量权衡选择表示和执行策略。在原生和训练后三值模型上的实验验证了该方法在缓存容量、模型质量和硬件效率方面的有效性。

## Abstract
Ternary LLMs make their weight-dominated projections compact and efficient, but attention remains a mismatch: its K/V cache is created online and is typically processed by a separate higher-precision engine. Compressing this cache alone does not resolve the mismatch. To execute attention with the same lookup-table machinery as ternary projections, values accumulated in one reduction must retain a compatible representation and scale. This requirement also differs for keys and values during causal decoding, because newly generated values may belong to an unfinished cache block. This work develops a unified lookup-table inference approach for ternary LLMs. It stores runtime K/V states as scaled multi-plane signed digits organized around the reduction structure of attention. The resulting digit planes are consumed directly by activation-derived tables, avoiding dense K/V materialization between cache storage and attention computation. The design combines online K/V formation, bounded handling of incomplete value blocks, and a shared multi-stream datapath for Linear projections and attention. A constraint-guided search selects the representation and execution policy for a target quality--efficiency trade-off. Experiments on native and post-training ternary models validate the approach across cache capacity, model quality, and hardware efficiency.

# 论文总结：面向三值大语言模型的统一查找表推理与有符号数字 K/V 缓存

## 1. 核心问题与研究动机

- **背景**：三值大语言模型（如 BitNet b1.58、Spectra）将线性层权重约束为 {−1, 0, +1}，配合分组查找表（LUT）执行可获得显著的存储压缩与计算加速。然而，注意力机制中的 K/V 缓存是**在线动态生成**的，现有系统通常使用**独立的高精度（INT8/BF16）MAC 引擎**处理 QK⊤ 和 PV，形成"LUT 处理静态权重 + MAC 处理动态注意力"的**异构双引擎架构**。
- **核心矛盾**：仅压缩 K/V 缓存无法消除计算结构上的不匹配——注意力产生的部分和需要满足与 LUT 归约兼容的表示形式和尺度约束，否则每个子块都需要浮点缩放与累加，无法复用 LUT 数据通路。
- **关键难点**：QK⊤ 中每个 K token 产生一个完整分数，允许 token 局部尺度；而 PV 中一个输出值需要累加多个 token 的 V 数据，token 局部尺度会破坏归约一致性。因此 V 必须按 token 区间组织，且因果解码中新区间后缀不完整，形成动态更新难题。

## 2. 方法论

### 2.1 核心思想：块级受限有符号数字（RSD）表示

- 将 K/V 块编码为 **R 个受限有符号数字（Restricted Signed-Digit）平面**，每个平面由 {−1, 0, +1} 三值数字组成，位平面位置幂（power-of-two positions）由模板指定，每个块共享一个缩放系数。
- **关键公式**：块 b 的量化表示为 \( q_b = \sum_{r=0}^{R_b-1} 2^{p_b[r]} \)，缩放 \( s_b = \max_i|Z^{(b)}_i| / q_b \)，归一化码本为 \( \mathcal{C}_b = \{\sum_r d_r 2^{p_b[r]}, d_r\in\{-1,0,1\}\} \)。
- **统一性**：静态三值权重是 R=1 的特例，从而将线性投影、QK⊤、PV 统一到同一个 LUT 接口：\( Y = \sum_b s_b \sum_r 2^{p_b[r]} \sum_g T_g[\text{idx}_G(d_{g,r})] \)。
- 平面数 R 决定缓存占用与执行周期，指数间隙 Δ 在固定 R 下调整码本密度（不增加执行开销），二者解耦，支持混合精度策略。

### 2.2 硬件架构与数据流

- **在线编码器（DQEU）**：分组 ping-pong FIFO + 绝对最大值比较器 + 最近码字搜索 + K/V 压缩器，运行时生成打包三元地址；支持 A8（INT8 激活）和 A16（BF16 激活）两种配置。
- **V-tail 机制**：保留权威 BF16 V 尾部块（最多 BV 个 token）和两个打包 RSD 影子存储，每次追加 token 后在非活跃影子中重新编码完整前缀，原子提交后 PV 才能访问，保证尺度一致性且不重写已定稿块。
- **统一多流架构**：每个核心包含 L 对 PCU/LUT，多 RHS 流共享同一 LUT 图像；GAT 完成查表求和、PSA 完成位平面移位累加、RSU 应用块缩放、BA 完成块累加。PCU 构建下一个 LUT 与当前执行重叠（双缓冲），DQEU 编码与计算流水化。
- **硬件感知设计空间探索（DSE）**：四阶段多保真度搜索——(1) 规格输入；(2) 联合搜索空间（R、Δ、块形状、映射策略）；(3) 线性规划松弛 + 贪心修复生成候选策略，公式化模拟器评估延迟，逐步校准 NLL；(4) 部署。目标为 \( \min_{p,\pi} C(H,p,\pi) \)（延迟 → 外部流量 → GB 峰值），约束 ΔNLL ≤ ε。

## 6. 主要结论与发现

- R=3 均匀策略下所有模型在 9 个任务中保持在密集 K/V 的 **0.50 pp 内**，三平面 RSD 基本保留模型质量。
- 统一 LUT 架构相比异构基线显著降低注意力硬件开销：A8 编码逻辑仅占 LUT 核心面积的 2.2%，而基线密集注意力阵列增加 64.5%；A16 下分别为 3.9% 与 254.4%。
- **A8 配置**在 Falcon-E-3B 上实现 QK/PV 平均 **2.52× 单位面积吞吐、2.30× 单位功耗吞吐**；**A16 配置**在 OPT-350M 上实现 **4.78×、8.61×** 提升。
- 压缩 K/V 读取提高操作强度 2.38–2.50×，外部内存流量节省最高达 57.3%（OPT-2.7B），打包 K/V 足迹降至 BF16 的 21%–23%。
- DSE 选取的混合 R 策略以 0.72–1.86 pp 准确率下降换取 1.18–1.56× 吞吐提升；ε=0.08 时选择 1.123× 请求级加速，ε=0.01 收紧后选择 1.079× 但 ΔNLL 降为 0.0021，验证质量-效率可调。

## 7. 优点

- **统一的表示与执行模型**：将静态权重与动态 K/V 纳入同一 RSD 框架，创新性地解决了 LUT 引擎在注意力中不可用的问题，软件/硬件协同设计思路清晰。
- **量化-架构联合搜索（DSE）**：将混合精度分配转化为约束优化问题，多保真度流程（LP 松弛→贪心修复→模拟器→渐进 NLL 校准）兼顾搜索效率与可靠性。
- **V-tail 机制设计精巧**：用有界重编码解决因果解码中缓存块尺度漂移问题，双影子存储 + 原子提交确保一致性，重编码与计算重叠。
- **硬件评估规范**：40nm ASIC 综合 + 功耗分析 + 周期级模拟器多维度验证，与基线保持吞吐量匹配和面积公平，结论说服力强。
