## 摘要
大语言模型（LLM）智能体正将电子设计自动化（EDA）从静态RTL生成扩展到长周期、工具交互式的工作流。然而，目前尚不清楚通用型编程智能体，即使具备特定领域的EDA技能，能否可靠地执行涵盖综合、物理实现和工程变更订单（ECO）优化的端到端RTL到GDS流程。我们使用商用EDA工具，在两种时序目标下，对PicoRV32 RTL到GDS流程中的AI智能体进行了评估。我们通过端到端设计得分、阶段完成度和Token ROI（一种将设计质量与运行时间和成本相关联的成本效率指标）来评估其性能。通过比较三种智能体架构和四种基础模型，我们得出了三个实际经验教训。第一，特定领域的技能能提高智能体对单个子任务的理解，但不能确保其可靠完成长周期的EDA流程。第二，取得类似设计进展的智能体在Token ROI上仍可能相差高达141倍，这揭示了运行时间和成本效率方面的巨大差异。第三，低级别的工具接口不匹配是物理设计失败的主要来源，尤其是当Tcl命令依赖于工具版本或执行模式时。这些结果表明，稳健的智能体EDA不仅需要更强的模型，还需要结构化的工具接口、持久的设计上下文、受控的执行以及流程级别的评估。

## Abstract
Large language model (LLM) agents are extending electronic design automation (EDA) beyond static RTL generation toward long-horizon, tool-interactive workflows. Yet it remains unclear whether general-purpose coding agents, even with domain-specific EDA skills, can reliably execute an end-to-end RTL-to-GDS flow encompassing synthesis, physical implementation, and engineering change order (ECO) optimization. We evaluate AI agents on a PicoRV32 RTL-to-GDS flow using commercial EDA tools under two timing targets. Their performance is assessed using end-to-end design score, stage completion, and Token ROI, a cost-efficiency metric relating design quality to runtime and cost. Comparing three agent architectures and four foundation models, we derive three practical lessons. First, domain-specific skills improve agents' understanding of individual subtasks but do not ensure reliable completion of a long-horizon EDA flow. Second, agents that achieve similar design progress can still differ by up to 141 times in Token ROI, revealing substantial differences in runtime and cost efficiency. Third, low-level tool-interface mismatches are a major source of physical design failures, particularly when Tcl commands depend on the tool version or execution mode. These results suggest that robust Agentic EDA requires not only stronger models but also structured tool interfaces, persistent design context, controlled execution, and process-level evaluation.

## 2. 论文提出的方法论

**核心思想：**
- 将 RTL-to-GDS 流程构建为一个多阶段、工具交互式的智能体评估任务，要求智能体在真实商用 EDA 工具环境中推进单个设计，在每个阶段接收工具反馈、维持设计状态、做出适应性决策。
- 区别于静态 RTL 基准（只测生成代码的功能正确性），该方法强调**流程级评估**：不仅看最终设计质量，还看阶段进度、资源效率、失败模式。

**关键技术细节：**

- **任务设定**：以 PicoRV32（RISC-V 核）为被测设计，使用商用 55nm 工艺，设定两个时钟目标——350 MHz（宽松）和 700 MHz（严格）——以测试不同约束紧张度下的智能体表现。流程阶段包括：逻辑综合、布局规划/电源规划、布局、CTS、布线、物理感知 ECO、最终报告生成。
  
- **三种智能体架构对比：**
  1. **Claude Code (CC)**：通用命令行编码智能体，代表"无 EDA 专用执行基座"的基线。
  2. **Claude Code + EDA Skills**：在相同交互模式上加入领域专用程序性知识（流程步骤、命令、报告解读、调试方法）。
  3. **FluxEDA**：将智能体推理与工具执行分离的执行架构——通过网关调用已注册的 EDA 能力，接收标准化结果，复用持久工具会话和设计上下文，约束非法操作。

- **四种基础模型**：DeepSeek-V4、GLM-5.2、Claude Sonnet 5、Kimi K3。通过固定任务和工具环境、变化架构与模型，区分"模型能力"与"执行支撑"的贡献。

- **评分公式：**
  - 端到端得分：**S = 0.2 × S_stage + 0.8 × S_result**（式 2）
  - **阶段得分**：按顺序门控的 3 个阶段（逻辑综合、物理实现、ECO），前者完成才计入后续阶段得分。
  - **结果得分**：仅在 3 个阶段全部完成时启用，基于指标集合 M = {面积、功耗、setup WNS/TNS、hold WNS/TNS}（式 3），逐项归一化后求和（式 4），部分输出或孤立报告不能被当作有效最终设计。
  
- **Token ROI（式 1）**：`TokenROI = 归一化EDA回报 /（token 投资 × 执行时间投资）`。其中分子代表任务特定设计质量和完成度，分母惩罚过度模型交互和长时间工具运行。另有归一化 Token ROI 版本，将 token 成本与执行时间重标度到可比范围。

## 6. 论文的主要结论与发现

**核心结论：当前 AI 智能体可以完成 RTL-to-GDS，但可靠完成不取决于基础模型能力，而取决于完整智能体系统。**

**三个主要经验教训（Lessons）：**

1. **领域专用技能不保证端到端完成。**
   - 技能提升了对子任务的理解，但效果高度依赖模型和时序目标：
     - 350 MHz 下，添加 EDA Skills 使 GLM-5.2 从 13.33 提升至 95.97，但使 Claude Sonnet 5 从 87.05 降至 11.67。
     - 700 MHz 下，GLM-5.2 从 13.33 提升至 84.47，而 Kimi K3 从 82.33 降至 11.67。
   - 技能可以推荐合适的流程和命令族，但无法保证命令对当前工具版本和执行模式有效、无法保证所需数据库状态可用、无法保证错误后能恢复。
   - **同一模型在不同架构下的得分差距可达 86.27 分**（DeepSeek-V4 在 350 MHz 下，11.67 vs. 97.94），说明智能体能力是系统级属性而非模型单独属性。

2. **效率必须与已验证的进展挂钩。**
   - 原始成本和时间不足以衡量效率。Claude Code + DeepSeek-V4 是最便宜最快的配置（$0.11、58.78 分钟），但得分仅 13.33 且未完成 ECO。
   - 相同得分（13.33）的两组运行（Claude Code + DeepSeek-V4 与 CC+EDA Skills + Kimi K3）Token ROI 分别为 12.71 和 0.09，**差异达约 141.2 倍**。
   - 因此，Token ROI 必须与阶段完成率和最终质量联合解读。

3. **可操作有效性与优化有效性必须区分。**
   - 物理实现错误中，**Tcl 命令兼容性是最大错误类别，占 31.7%**——包括命令与工具版本、执行模式、MMMC 初始化、报告/导出接口不兼容等。
   - Claude Code + DeepSeek-V4 和 GLM-5.2 分别贡献了 48.7% 和 28.0% 的此类错误；EDA Skills 将其降至 10.0% 和 7.7%；**FluxEDA 将该类别错误降至 0.0%**。
   - 通用智能体常将 EDA shell 视为开放编程面，而真实动作空间受工具版本、加载设计、流程阶段和项目约定的约束。

**其他关键发现：**
- 所有 8 次 FluxEDA 运行（4 模型 × 2 目标）得分均高于 90，且全部完成三个门控阶段；而 Claude Code 系列只有 3/8 完成 ECO，CC+EDA Skills 只有 2/8 完成 ECO。
- 命令行架构的所有 6 次物理实现失败均涉及时 I/O 布局不完整（其中 1 次还失败于 CTS），标准单元布局和布线无失败。
- Kimi K3 在 FluxEDA 下表现最佳（两个目标均最高分），但在无结构化执行架构时稳定性差——说明强模型需要结构化架构支持才能产生可靠的端到端结果。
- DeepSeek-V4 成本效率最佳；GLM-5.2 跨架构适应性最强；Claude Sonnet 5 质量竞争力强但成本高。

## 7. 优点（亮点）

1. **问题定义清晰且有价值**：将 RTL-to-GDS 从"代码生成问题"重构为"工具交互式长周期智能体评估问题"，填补了静态 RTL 基准与真实芯片设计流程之间的评估空白。

2. **流程级评估方法论创新**：
   - 引入**门控阶段评分**，防止部分输出或孤立报告被当作有效设计，确保评分反映真实的端到端完成度。
   - 提出**Token ROI** 指标，联合考虑设计质量、token 投资和执行时间，更全面反映工程效率和成本效益。
   - 区分"最终正确性"与"过程级效率"，使评估能捕捉到低成本的早期失败与昂贵的试错行为之间的差异。

3. **系统性的架构×模型交叉对比**：3 种架构 × 4 种模型的实验设计能有效分离"模型能力"与"执行支撑"的贡献，结论更具说服力。

4. **失败模式分析具体且有洞察**：对物理设计错误分类（Tcl 兼容性、I/O 布局等），提供了可操作的改进方向，而非仅停留在分数层面。

5. **实践启示明确**：三个经验教训直接转化为 Agentic EDA 系统设计建议——结构化接口、持久上下文、受控执行、流程级基准——对社区有实际指导价值。

6. **比较视角完整**：将 RTL-to-GDS 与现有 RTL 基准（VerilogEval、RTLLM、RealBench、CVDP）的关系阐述清晰，定位准确，不夸大也不贬低各自的贡献。

10. **ECO 阶段复杂度偏低**：PicoRV32 规模较小，物理感知 ECO 的修改量有限，无法代表大规模 SoC 中跨时钟域、多电压域、复杂约束下的 ECO 决策难度。

## 9. 论文定位与综合评价

**在领域中的定位：**
- 本文属于 Agentic EDA 方向的早期系统性评估工作，核心贡献不在于提出一个性能更强的智能体，而在于**提出了一个可量化的流程级评估范式**——它将 RTL-to-GDS 从"模型生成能力测试"转化为"系统执行能力测试"，揭示了单纯增大模型或添加技能文档无法跨越工具环境复杂性的结论。
- 在评估基准谱系中，本文处于**静态 RTL 生成基准（如 VerilogEval）与工业 signoff 流程之间的中间层**：它不要求智能体生成正确 RTL（RTL 给定），也不要求达到流片级质量标准（评分基于报告指标而非 DRC/LVS 全部通过），而是聚焦于"在真实工具环境中把设计推进到底"的能力。

**对领域研究的贡献：**
- **方法论贡献**：提出了门控阶段评分、Token ROI、操作性有效性 vs. 优化有效性分离分析三个可复用的评估设计元素，它们不仅适用于 EDA，也对其他工具交互式长周期任务（如机器人控制、科学计算流程编排）具有借鉴意义。
- **实证贡献**：24 次系统化运行提供了"模型能力 ≠ 智能体能力"的直接证据——同一模型得分差距可达 86 分，同一架构在不同时序难度下表现反转，这些数据为后续 Agentic EDA 基础设施设计提供了可靠出发点。
- **工程启示**：FluxEDA 的"推理-执行分离"架构与 Tcl 兼容性错误归零的实验结果，为构建工业级 LLM-EDA 工具链指明了明确的工程方向：关键在于约束动作空间、持久化设计上下文、结构化反馈，而非依赖更强的通用模型。

**总体评价：**
- 这是一篇**问题意识强、实验设计系统、结论具有可操作性的高质量评估论文**。它没有夸大 LLM 在 EDA 中的作用，而是诚实承认"当前智能体在严格目标下仍无法像人类工程师一样可靠地完成全部物理设计流程"，但给出了明确的改进路径和量化基线。
- 论文的主要价值不在于"证明了某个方法最优"，而在于**为 Agentic EDA 的后续研究提供了一个可参照的评估坐标**——未来的工作可以在此基础上扩展多设计、多工艺、多工具版本的覆盖，并解决本文遗留的统计效力与开源复现问题。
- 作为该领域的早期探索，其研究边界清晰、结论克制、未来方向明确，整体上是一篇**兼具学术规范性和工程实用性的论文**。

## 10. 对未来研究的建议

基于本文的不足与结论，后续研究可以从以下方向推进：

1. **基准开源与多设计扩展**：将 PicoRV32 扩展到多个不同规模的开源 RISC-V 核（如 Ibex、Rocket、BOOM）及小型 SoC，并开源完整基准套件（含工具脚本、评分代码、日志格式），提升外部效度与可复现性。

2. **统计效力提升**：每种配置至少重复 5-10 次，报告得分分布、中位数与置信区间；控制模型采样参数和 seed，分离随机方差与系统差异。

3. **多工具、多工艺覆盖**：在不同商业 EDA 工具（如 Synopsys、Cadence、华大九天）和不同工艺节点（如 28nm、12nm）上测试，检验 Tcl 兼容性结论的工具耦合程度与泛化能力。

4. **更细粒度的消融设计**：在 FluxEDA 架构上分别打开/关闭结构化接口、持久上下文、非法操作约束，量化各模块对端到端得分的独立贡献；同时在 Claude Code 上引入"仅限合法命令"的执行约束，以区分 FluxEDA 的收益来源是工程约束还是架构本身。

5. **失败轨迹的深度分析**：对高成本失败运行（如 CC+EDA Skills + Kimi K3）做逐步骤轨迹标注，建立"错误—恢复策略—失败原因"的细粒度分类体系，为智能体的自恢复机制设计提供数据支撑。

6. **扩展到 code-grounded 与 report-grounded 任务**：引入 RTL 带缺陷修复、基于报告的自动优化（如自动 eco 优化时序违例）等任务，构建覆盖完整设计闭环的多任务基准，更全面刻画智能体在芯片设计全流程中的能力边界。

---

**一句话总结：** 本文通过系统化的 3×4 架构-模型交叉实验，证明了 RTL-to-GDS 的端到端可信完成取决于结构化执行基础设施而非基础模型本身，并为 Agentic EDA 领域提供了流程级评估方法论与可操作的改进方向。
