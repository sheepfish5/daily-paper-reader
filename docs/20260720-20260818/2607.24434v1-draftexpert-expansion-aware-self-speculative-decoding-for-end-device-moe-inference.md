## 摘要
大型混合专家（MoE）语言模型因其每个令牌仅激活一小部分专家而适合端侧部署，但其路由专家权重往往超出加速器内存。我们针对延迟敏感的单用户场景，其中路由专家按需从CPU内存分阶段加载到GPU，或从Flash加载到移动NPU。在此场景下，自推测解码面临新的瓶颈：增加草稿专家集可提高准确性，但会触发额外的专家加载，而廉价的小占用草稿则接受率低；此外，验证多令牌块会激活目标专家的并集，不再接近单个目标步骤。我们提出DraftExpert，一种用于专家卸载MoE推理的扩展感知自推测解码框架。DraftExpert通过从冻结的目标MoE中自蒸馏残差、logit/令牌和路由器一致信号，为每层训练一个轻量级驻留加速器的草稿专家。在推理时，它使用固定占用共享+前1+草稿专家的草稿器，配合置信度扩展截断和目标专家预取，而最终令牌仍由目标模型严格验证。在DeepSeek-V2-Lite和Moonlight-16B-A3B上，跨CPU-GPU和Flash-NPU卸载，DraftExpert平均提高解码吞吐量1.45倍，将草稿接受率提升至84%~87%，并实现86%~88%的预取命中率。

## Abstract
Large Mixture-of-Experts (MoE) language models are attractive for end-device deployment because only a small subset of experts is active per token, but their routed expert weights often exceed accelerator memory. We target latency-critical single-user settings where routed experts are staged on demand from CPU memory to a GPU or from Flash to a mobile NPU. In this setting, self-speculative decoding faces a new bottleneck: increasing the draft expert set improves accuracy but triggers extra expert loading, while cheap small-footprint drafts have low acceptance; moreover, verifying a multi-token block activates the union of target experts and is no longer close to one target step. We propose DraftExpert, an expansion-aware self-speculative decoding framework for expert-offloaded MoE inference. DraftExpert trains one lightweight accelerator-resident draft expert per layer by self-distilling residual, logit/token, and router-agreement signals from the frozen target MoE. At inference time, it uses a fixed-footprint shared+top-1+draft-expert drafter together with confidence--expansion truncation and target-expert prefetching, while final tokens are still exactly verified by the target model. On DeepSeek-V2-Lite and Moonlight-16B-A3B across CPU-GPU and Flash-NPU offload, DraftExpert improves decode throughput by 1.45x on average, raises draft acceptance to 84~87%, and achieves 86~88% prefetch hit rates.

# DraftExpert：面向端侧MoE推理的扩展感知自推测解码——论文总结

## 1. 核心问题与研究动机

- **背景**：大型混合专家（MoE）语言模型因每个令牌仅激活少量专家而在端侧部署中极具吸引力。然而，路由专家权重往往超过消费级 GPU 或移动 NPU 的内存容量，导致需要将路由专家卸载到 CPU 内存（CPU→GPU）或 Flash（Flash→NPU），并按需加载。
- **核心瓶颈**：在专家卸载场景下，自推测解码的三个经典成立条件均被打破：
  - **草稿必须廉价**：传统 shared+top-r 自草稿方法靠增大 r 提高保真度，但这会加载更多外部专家，使草稿成本上升，速度下降（top-1 到 top-3 的草稿加速比从 4.7× 降至 2.0×）。
  - **并行验证应接近单步代价**：MoE 并行验证一个多令牌块会激活所有令牌路由专家的并集，验证成本随块长增长，而稠密模型的验证权重可复用。
  - **接受率应足够高**：top-1/top-2 等小足迹草稿因省略路由专家残差，导致隐藏状态漂移，接受率低（top-3 也不足 50%）。
- **根本变化**：性能核心指标应从“每个目标前向通过的令牌数”变为“每个专家集扩展对应的已接受令牌数”。现有 MoE 自推测方法未针对此成本模型设计。

## 2. 方法论：DraftExpert 框架

核心思想：不提高草稿器的路由专家数，而是用轻量级驻留草稿专家恢复准确率，并通过扩展感知机制控制验证代价，最终仍由冻结的目标 MoE 严格验证。

### 2.1 固定足迹草稿路径

- 每 MoE 层增加一个轻量级“草稿专家”$E_d^l$，常驻加速器。
- 草稿计算为：shared 专家 + top-1 路由专家 + 草稿专家的组合：
  $y_l^d = S_l(h_l) + g_{l,e_1} E_{l,e_1}(h_l) + \gamma_l E_d^l(h_l)$
- 比 top-r 的草稿器仅多一个常驻模块，外部专家加载量接近 top-1。

### 2.2 自蒸馏训练信号

从冻结的完整目标 MoE 采集监督标签，目标函数为：

$L = L_{logit} + \alpha L_{tok} + \beta L_{res} + \eta L_{router}$

- **残差蒸馏**（$L_{res}$）：拟合被省略的 top-1 之外路由专家的残差（m*）。
- **logit/token 蒸馏**（$L_{logit}$, $L_{tok}$）：对齐最终预测分布与目标令牌。
- **路由器一致蒸馏**（$L_{router}$）：使草稿隐藏状态下的路由分布与目标路径一致，从而提升推理期对验证专家集预测的准确性。

### 2.3 扩展感知推理策略

- **置信度–扩展截断**：逐令牌计算草稿置信度 q_i 和预测新增验证专家数 Δ_i；当候选令牌置信度低且新增专家过多时停止扩展草稿块，避免无效验证成本。
- **草稿路由器预取**：利用与目标路由器对齐的草稿状态，在草稿阶段异步预取验证阶段可能用到的专家，与后续草稿计算重叠，减少验证加载停顿。
- **精确验证保证**：丢弃的候选不输出，所有被保留的令牌仍由冻结原 MoE 严格验证，保证最终输出与目标模型一致。

### 2.4 算法流程

- 初始化草稿块为空；用共享+top-1+草稿专家逐令牌生成候选；
- 更新预测验证专家集与边际扩展量；当满足低置信度且高扩展条件时停止；
- 异步预取预测专家；等待必要预取后，用完整 MoE 并行验证所有草稿令牌；接受与目标一致的最长前缀，重复迭代。

## 3. 实验设计

### 3.1 模型与平台

- **目标 MoE 模型**：DeepSeek-V2-Lite（DS）与 Moonlight-16B-A3B（ML），各 27 层，64 路由 + 2 共享专家，top-6 激活。
- **端侧场景**：
  - CG（CPU→GPU）：RTX 4090，BF16，PyTorch，CPU 内存驻留专家按需加载至 GPU。
  - MN（Flash→NPU）：小米 MIX Flip 2，Hexagon HTP v81 NPU，llama.cpp + Q4_0 量化，专家从 Flash 加载至共享内存。
- **评测数据**：Chat、GSM8K、MBPP、summarization、instruction following 等提示集合。
- **对比方法**：
  - AR offload：冻结完整 MoE 自回归解码基线。
  - Shared+top-r：训练自由自推测基线，r 扫 {1,2,3}。
  - DraftExpert：固定足迹草稿 + 截断 + 预取。

### 3.2 主要实验结果

- **解码吞吐**：相比 AR offload，平均提升 1.45×；其中 MN 平台提升更明显（DS 1.52×、ML 1.61×），CG 平台受 PCIe 与算力均衡影响提升相对较小（1.29×/1.36×）。
- **草稿侧**：K=4 时，DraftExpert 的唯一专家数约 88–90，接近 top-1（84–86），但接受率 83%–85%，远高于 top-3（约 44%–46%），且草稿成本仅约为 top-1 的 1.05–1.09 倍。
- **验证侧控制**：置信度–扩展截断将固定 K 的验证成本从约 2.35×–3.30× 降至 1.48×–1.76×；再加预取进一步降至 1.25×–1.40×，预取命中率 86%–88%。
- **训练目标消融**：残差与 logit/token 损失显著提升接受率（从 45%–48% 升至 79%–87%），路由一致损失将路由一致性提升到 0.85–0.86，预取命中率提升至 86%–88%。

## 6. 主要结论

- 在专家卸载的端侧 MoE 推理中，应将推测解码优化目标改为“已接受令牌 / 专家集扩展”，而非单纯“令牌 / 目标前向”。
- 固定足迹 shared+top-1+draft-expert 草稿器配合自蒸馏，可在不增加路由专家加载的前提下显著恢复接受率。
- 路由一致蒸馏使草稿状态可作为验证专家集的可信预测器，驱动动态截断与专家预取，降低验证扩展成本。
- 整体方案保证精确输出，平均吞吐提升 1.45×，接受率 84%–87%，预取命中率 86%–88%，适用于 CPU→GPU 与 Flash→NPU 两类端侧部署。
