## 摘要
大规模语言模型（LLM）的扩展要求计算系统采用多处理器芯片架构，从而提升了芯片间（C2C）通信的重要性。然而，为LLM工作负载设计高效的C2C硬件架构面临三个关键挑战：生成真实的LLM特定C2C流量、在大规模下准确模拟硬件级通信，以及高效探索指数级增长的C2C设计空间。我们提出C2C-Explorer，一个自适应贝叶斯设计空间探索（DSE）框架，它将LLM工作负载驱动的流量生成器、可扩展的互连模拟器（交换/全网格，最多512个芯片）以及指标引导评估器集成到从工作负载到硬件的优化流水线中，从而在真实LLM工作负载下实现系统性的C2C架构协同设计。经过基于FPGA的C2C原型验证，C2C模拟器在不同流量模式下的端到端时序误差为2.46%-8.23%。其混合周期和事件模型进一步将大规模模拟速度提升至纯周期精确基线模拟的7.8倍。应用于32-XPU DeepSeek-R1-671B推理工作负载时，C2C-Explorer识别出的配置将有效吞吐量提高了44.1%，并将内存减少了98.4%。C2C-Explorer为开源项目，可在https://github.com/Selinaee/C2C-Explorer获取。

## Abstract
The scaling-up of large language models (LLMs) necessitates computing systems to have multi-processor-chip architectures, elevating the importance of chip-to-chip (C2C) communication. However, designing efficient C2C hardware architectures for LLM workloads faces three key challenges: generating realistic LLM-specific C2C traffic, accurately simulating hardware-level communication at scale, and efficiently exploring the exponentially large C2C design space. We propose C2C-Explorer, an adaptive Bayesian DSE framework that integrates a LLM-workload-driven traffic generator, a scalable interconnect simulator (switch/full-mesh, up to 512 chips), and a metric-guided evaluator into a workload-to-hardware optimization pipeline, enabling systematic C2C architectural co-design under realistic LLM workloads. Validated against FPGA-based C2C prototypes, the C2C simulator achieves 2.46-8.23% end-to-end timing error across diverse traffic patterns. Its hybrid cycle and event model further accelerates large-scale simulation by up to 7.8$\times$ over a pure cycle-accurate baseline. Applied to a 32-XPU DeepSeek-R1-671B inference workload, C2C-Explorer identifies configurations that improve goodput by 44.1% and reduce memory by 98.4%. C2C-Explorer is open-source and available at https://github.com/Selinaee/C2C-Explorer.

### 一、核心问题与研究动机

随着大型语言模型（LLM）参数规模的指数级增长，其部署方式已从单加速器模式转向多节点、多加速器的"超级节点"（super-node）协同架构。这一转变带来了一个核心瓶颈：**芯片间（Chip-to-Chip, C2C）通信在LLM工作负载中日益占据主导地位**。研究表明：

- 在训练场景下，通信开销占迭代时间的比例超过90%；
- 在推理场景下，通信开销占端到端延迟的比例超过50%。

然而，为LLM工作负载设计高效的C2C硬件架构面临三大挑战：

1. **难以生成真实的LLM特定C2C流量**：不同并行策略（数据并行、张量并行等）在Megatron、DeepSpeed等框架中产生不同的集合通信模式，但将高层级的GPU间流量分解为物理互连结构上的C2C流量路径，是一个复杂的拓扑依赖过程。
2. **大规模多XPU硬件仿真缺失**：跨层协议复杂度高，缺乏对"横向扩展系统"中"纵向扩展芯片"互连行为的仿真支持。
3. **C2C设计空间指数爆炸**：虚拟通道（VC）、调度器、帧大小、信用额度（credit）等硬件参数与LLM工作负载、网络拓扑等多重因素耦合，组合空间巨大。

现有工具均无法同时解决上述问题：LLM仿真框架（Vidur、SimAI、vTrain）缺少物理硬件路径建模；NoC仿真器（BookSim、Garnet）面向片上互连；系统级仿真器（ns-3、OMNeT++）无法捕获C2C硬件级行为。

### 二、方法论：C2C-Explorer框架

C2C-Explorer是一个**自适应贝叶斯设计空间探索（AB-DSE）框架**，将"工作负载到硬件"的优化流水线分为四个核心模块：

#### 1. 流量生成器（Traffic Generator）

基于SimAI生成的XPU级P2P流迹，经三个紧密耦合阶段转换为AXI精确的C2C流量：

- **P2P→C2C流映射**：根据目标拓扑（全网格或交换架构）和C2C端口数，将每个P2P流分配到各端口形成子流，保持依赖顺序。
- **C2C→块转换（双流控语义）**：将每个C2C流分割为固定大小的块（chunk），在**BDP驱动的滑动窗口**机制下注入流水线，窗口大小为：
  W = ⌈(BW·RTT·C)/(N^α)⌉ 或等价的 ⌈(RTT/(C/BW)+Δ)·(N/α)⌉
  同时使用**基于信用的背压机制**（credit-based backpressure）建模物理链路行为。
- **块→AXI命令发射**：发送端将每个块扩展为AXI写突发（1个aw请求+n个w节拍+wlast），接收端发出b响应完成确认，还原真实的AXI突发语义。

#### 2. C2C模拟器

采用**混合建模策略**：对C2C端口采用周期精确建模（cycle-accurate），对Ethernet/交换机采用事件驱动建模（event-driven），兼顾时序精度与扩展性。

核心架构为7级流水线（S1–S7），覆盖三类设计轴：
- **Packetization（分包）**：S2/S6，AXI通道→AXI flit→MAC帧的打包与解包
- **Scheduling（调度）**：S1/S3，AXI级调度器与MAC级VC调度
- **Resource-Allocation（资源分配）**：S3–S5，VC数量、信用额度、交换机VOQ仲裁

支持多达512个XPU、数千条C2C链路，支持switch和full-mesh两种拓扑，构建于SimPy之上并采用PyPy JIT加速。可调参数涵盖：chunk_size（2KB/4KB/8KB）、MAC_frame_size（2KB/4KB）、VC_pair_nums（1–32）、credit（4KB–32KB）及多种调度策略（DRR、LQ、RR、SP、DQD、FCFS、WRR等）。

#### 3. 评估器（Evaluator）

从5个维度评估配置：**吞吐量（goodput）、P50延迟、P99延迟、公平性、缓冲区使用量**。通过归一化加权求和得到标量分数S：
- Goodput直接奖励（40%权重，最大化）
- P50（15%）、P99（25%）、公平性（5%）、buffer使用量（15%，均最小化）

#### 4. 自适应贝叶斯搜索引擎（AB-DSE）

算法流程（Algorithm 1）：

1. **C2C可行性剪枝**：应用硬件约束（如chunk_size ≥ 2×MAC_frame）消除解析上被支配的组合，将设计空间从2394压缩至1152个配置。
2. **LHS多样性初始化**：使用拉丁超立方采样生成初始配置，逐一仿真评估。
3. **贝叶斯优化循环**：在高斯过程代理模型上通过期望改进（EI）准则迭代选点，更新历史并搜索最优配置。
4. 预算耗尽后输出最高评分配置x*。

### 六、主要结论与发现

1. **模拟器精度与性能**：端到端时序误差2.46%–8.23%，验证了混合建模方法的有效性；混合模型在512 XPU规模下实现7.8×加速，且PyPy JIT可额外提供最高1.78×加速。
2. **分包参数规律**：goodput随MAC帧增大先快速上升后饱和（遵循MAC效率公式 (L−H)/L）；chunk尺寸达到约2×MAC帧大小时性能趋于饱和，更大的chunk通过摊销AXI事务开销提升吞吐。
3. **调度策略规律**：DRR-2KB表现最佳（相比RR提升1.99×goodput），WRR和SP次之（1.12×/1.82×）；过大量子（DRR-8KB）反而因头阻塞（HoL blocking）降低4.06% goodput。
4. **VC资源分配规律**：流量越不平衡，对VC数量的敏感度越高；重不平衡（R=64）场景下VC数需接近并发流数才能避免性能崩塌——该行为由有效不平衡度公式 Reff ≈ 1+(R−1)(C/NV−1)/(C−1) 刻画。
5. **端到端优化收益**（最优vs最差可行设计）：
   - DeepSeek-R1 dispatch：goodput +14.7%，P50/P99延迟 −12.6%，buffer −75%
   - DeepSeek-R1 combine：goodput +44.1%，P50/P99延迟 −30.4%，buffer −98.4%
   - LLaMA3.1：goodput +51.7%，P50/P99延迟 −68.7%
   - Qwen3：goodput +50.5%，P50/P99延迟 −64.3%，buffer −96.9%
6. **设计空间特征**：参数敏感性分析显示无单调趋势，最优配置高度依赖具体工作负载，证明联合优化的必要性；分包参数影响最大，AXI侧调度影响大于MAC侧仲裁；VC=1虽在buffer成本上最优但工作负载均偏好多VC设计。

### 七、优点

1. **填补空白**：首次提出面向LLM工作负载的C2C硬件级仿真与DSE框架，弥合了系统级LLM仿真与NoC仿真之间的鸿沟。
2. **真实硬件验证**：基于FPGA搭建400Gbps真实原型进行精度标定，而非仅进行理论推导，增强了模拟器可信度。
3. **混合建模创新**：周期精确端口建模+事件驱动交换机调度的混合策略，在保持链路级保真度的同时实现大规模加速，是该领域的巧妙设计。
4. **双流控保真**：应用级滑动窗口+链路级信用背压的双层流控语义，配合AXI精确事务建模，能真实还原跨层交互时序。
5. **全局视角的用户案例**：包含训练与推理两大类场景，覆盖DeepSeek、LLaMA、Qwen等多个主流模型，并提供了可复现的量化收益。
6. **开源可复现**：框架开源，降低了该领域后续研究的门槛。

### 八、不足与局限

1. **规模验证缺口**：精度验证仅在4-XPU小规模原型上完成，512-XPU规模的加速数据缺乏真实硬件对照，"仿真精度在更大规模下能否保持一致"未得到实证。
2. **用户案例规模有限**：32-XPU测试规模无法完全代表"100k XPU"大规模云系统的实际通信特征。
3. **FPGA原型代表性**：FPGA原型对标ETH-X协议，未覆盖NVLink、UALink、UB等其他C2C协议族，协议覆盖范围有限。
4. **流量真实性依赖上游**：LLM流量生成依赖SimAI的trace，SimAI对真实分布式训练的建模误差会传播到C2C-Explorer的评估结果中。
5. **部分实验控制变量较窄**：调度策略实验仅在单一消息大小（64KB）下进行；AB-DSE未与随机搜索或网格搜索做基线对比，难以量化贝叶斯优化的独立增益。
6. **评估指标权重的主观性**：评分函数中权重分配（如goodput 40%、P99 25%）基于用户场景设定，不同权重可能显著改变最优配置，缺乏敏感性分析。
7. **场景覆盖有限**：LLM推理场景中未考虑KV缓存、动态批处理等系统级因素对通信模式的影响；训练场景也仅限于梯度all-reduce，未覆盖专家并行等更复杂组合。
