## 摘要
逻辑综合将RTL设计转换为门级网表，其中PPA结果对优化命令的选择高度敏感，使得综合调优既具有高维度又成本高昂。以往的方法分为两类：自动化方法在固定动作空间内进行黑盒搜索，决策级可解释性有限；基于LLM的方法通常预先生成静态脚本，无法适应不断变化的电路状态。我们提出了SynAct，一种自适应闭环LLM推理-行动智能体，它迭代地诊断实时综合报告，并基于当前电路状态、检索到的工具知识和历史优化经验进行推理，以发出有针对性的命令。SynAct专注于改善时序，特别是最差负裕量（WNS），同时保持面积和功耗的平衡权衡。在14个设计上使用商业综合工具进行的实验表明，SynAct将平均WNS降低到引导综合的27%。

## Abstract
Logic synthesis transforms RTL designs into gate-level netlists, where PPA results are highly sensitive to the choice of optimization commands, making synthesis tuning both high-dimensional and expensive. Previous approaches fall into two categories: automated methods, which perform black-box search over fixed action spaces with limited decision-level interpretability, and LLM-based methods, which typically generate static scripts upfront and cannot adapt to evolving circuit states. We present SynAct, an adaptive closed-loop LLM reasoning--acting agent that iteratively diagnoses live synthesis reports and reasons over the current circuit state, retrieved tool knowledge, and historical optimization experience to issue targeted commands. SynAct focuses on improving timing, particularly worst negative slack (WNS), while maintaining balanced area and power trade-offs. Experiments on a commercial synthesis tool across 14 designs show that SynAct reduces average WNS to 27% of that from bootstrap synthesis.

# 2. 方法论

## 2.1 核心思想

- 将综合优化建模为马尔可夫决策过程（MDP），状态为当前网表与 PPA 报告，动作是可执行的综合命令，转移函数由综合工具实现，奖励为 PPA 指标的加权聚合。
- 以 ReAct 为骨架，采用多智能体协作（AutoGen 风格）：Analysis Agent 负责诊断，Optimization Agent 负责生成命令，Candidate Selection 负责筛选并执行最佳安全命令。

## 2.2 关键技术细节

- **Analysis Agent（分析智能体）**：
  - 分为 Preprobe 和 Postprobe 两个阶段；
  - Preprobe 解析当前报告，识别时序瓶颈，并主动生成 `analyze_*` 探针命令（如 `analyze_clock_timing`、`analyze_inst`）以获取更细粒度信息；
  - Postprobe 结合探针结果输出结构化诊断，包括关键路径、模块假设、建议策略等。

- **Optimization Agent（优化智能体）**：
  - 输入为诊断结果、用户请求、GraphRAG 检索到的工具文档和 BO 种子建议；
  - 生成两类候选命令：RAG 引导的 `C_RAG` 和 BO 种子修正后的 `C_BO`；
  - 每个候选附带解释性 rationale，提高可解释性。

- **Candidate Selection（候选选择）**：
  - 先做安全过滤：WNS 超过预设阈值（如 -20 ps）或奖励低于 bootstrap 的 0.2 倍则剔除；
  - 剩余候选按评分公式选择：

    `score(C) = r(C) + κσ(z) − ρ(C)`

    其中 `r(C)` 是奖励，`σ(z)` 是 BO 代理模型的局部不确定性，`ρ(C)` 惩罚近期重复动作；

  - 奖励函数定义为：

    `r = exp(−Σ wi·log(1 + err_i))`

    其中 `err_i` 根据 WNS/TNS（取正偏差）和面积/功耗（归一化超量）计算，权重 `wi` 偏向用户指定的主目标。

- **GraphRAG 知识引导**：
  - 构建三层知识图谱：优化场景、可执行命令、可配置变量；
  - 使用 LLM 提取实体与关系，形成层内（命令-命令、变量-变量）和层间（场景-命令、场景-变量）连接；
  - 检索时先由诊断生成场景描述，用 EDA 定制嵌入模型做语义匹配，选出 top-k 场景，再扩展相邻命令与变量；
  - 相比传统 RAG 或直接喂全部文档，GraphRAG 提供更结构化、更精简的情境知识。

- **BO 引导的经验精炼**：
  - 使用 GrammarVAE 将合成命令编码为连续潜在向量，保持语法有效性与语义局部性；
  - 在潜在空间维护一个轴对齐的信任区域（trust region），用奖励加权的 RBF 代理模型拟合历史经验，并通过 UCB 采集函数选择下一个潜在点；
  - 解码后得到 BO 种子命令 `\hat{C}_{BO}`，再由 Optimization Agent 结合文档修正为工具可用命令；
  - 算法 1 给出了每轮迭代的完整流程：拟合代理 → 采样 UCB → 解码 → 执行评估 → 记录经验 → 更新信任域。

# 8. 缺点与局限性

- **依赖商业工具的可交互会话能力**：SynAct 需要综合工具支持逐步执行命令并返回 PPA 报告；若工具只能批量运行或频繁重启开销巨大，其闭环优势将大幅削弱。
- **运行时间开销较高**：SynAct 每轮需生成并评估 10 个候选，且 84.85% 的时间消耗在综合工具评估上；在大型设计上总运行时间约为 ChatLS 的 3.4 倍，可能不适用于快速迭代的开发场景。
- **LLM 成本与不确定性**：每个设计平均约消费 139k token，且依赖外部 LLM API；不同模型、不同版本的行为差异可能影响复现性，工业部署存在成本与延迟风险。
- **实验范围有限**：仅在单一商业工具（AltiSyn®）和 ASAP7 7nm 开源 PDK 上验证，未覆盖多工具、多工艺节点；基线方法（ChatLS 复现版、CBTune 手工 7 命令）可能存在不公平比较。
- **奖励设计与目标偏置**：奖励函数中的权重由用户指定，对多目标权衡的适应性有限；论文主要验证了 WNS 主导的场景，对面积、功耗同时作为主目标的情形未充分测试。
- **未披露部分算力细节**：未说明 GrammarVAE 训练的具体耗时、LLM 调用的延迟分布、GPU 数量等，影响他人对总资源成本的完整评估。

# 9. 总结与评价

SynAct 将逻辑综合优化从静态脚本生成和黑盒搜索扩展为“感知-诊断-行动-观察”的闭环 LLM 智能体框架，在 WNS 与 TNS 上取得了显著的相对改善，同时维持面积和功耗基本不变。其核心贡献在于将知识图谱检索（GraphRAG）与贝叶斯优化的经验引导无缝集成到 LLM 的推理循环中，既提高了决策的可解释性，又保留了利用历史经验进行局部精调的能力。尽管运行时间与 LLM 调用成本较高，实验验证范围有限，但该方法在自动化 EDA 调优领域展示了一种有前景的新范式，尤其适合对时序收敛要求高、允许较长综合时间的先进工艺设计场景。未来工作可进一步降低评估成本、扩展到多工具平台并增强多目标自适应能力。
