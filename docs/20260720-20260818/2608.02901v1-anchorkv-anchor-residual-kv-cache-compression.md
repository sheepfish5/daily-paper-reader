## 摘要
键值（KV）缓存是长上下文 LLM 推理中的主要内存瓶颈。现有方法从两个相反的方向来应对：驱逐方法会永久丢弃令牌，一旦被丢弃的令牌后来被证明至关重要，就会降低性能；而量化方法虽然以低精度保留所有令牌，但压缩效果有限。我们提出 AnchorKV，这是一种压缩方案，可将缓存缩小 20 倍，且不会丢弃任何令牌。AnchorKV 使用一小部分精确存储的锚点来表示缓存，通过每个令牌最相似的锚点来表达其他所有令牌，并且仅优化那些近似值对模型输出影响最大的令牌。AnchorKV 在不同模型和数据集上持续保持准确性，在 70B 规模下保留了完整缓存分数的 99%，同时以极小成本存储整个上下文。

## Abstract
The key-value (KV) cache is the primary memory bottleneck in long-context LLM inference. Existing approaches attack it from opposite ends: eviction methods permanently discard tokens, degrading performance whenever a discarded token later proves essential, while quantization methods retain all tokens at low precision but offer limited compression. We propose AnchorKV, a compression scheme that shrinks the cache by $20\times$ without discarding a single token. AnchorKV represents the cache using a small set of anchors stored exactly, expresses every other token through its most similar anchor, and refines only those whose approximation most affects the model's output. AnchorKV consistently preserves accuracy across models and datasets, retaining 99% of the full-cache score at the 70B scale, while keeping the entire context at a fraction of its cost.

## 1. 核心问题与研究动机

- **背景**：长上下文推理已成为 LLM 应用的常态，KV 缓存随上下文长度和 batch size 线性增长，并在每个解码步骤被完整读取。在 128K 上下文下，单条 Llama-3.1-8B 请求的 KV 缓存可达 16 GiB（bf16），与模型权重相当，因此 KV 缓存成为决定设备可承载请求数和解码速度的主要瓶颈。
- **现有方法的两难**：
  - **驱逐方法**（如 H2O、SnapKV、PyramidKV、AdaKV）：通过打分保留子集、丢弃其余 token，理论上压缩比无上限，但丢弃决策发生在查询到来之前，一旦被丢弃的 token 后被需要，性能不可逆地受损。
  - **量化方法**（如 KIVI、KVQuant、TurboQuant）：保留所有 token 但降低位宽，精度随压缩加深而下降，实际压缩比通常被限制在约 5×，难以从根本上解除内存约束。
- **AnchorKV 的目标**：在不丢弃任何 token 的前提下实现激进压缩（20×），并保持接近完整缓存的精度，从而同时获得驱逐方法的高压缩比与量化方法的全量可达性。

## 2. 方法论：Anchor-Residual 表示与压缩流程

### 2.1 核心思想
- 每个 KV head 在 prefill 结束时选取少量**锚点（anchors）**，以 bf16 精确存储；其余每个 token 通过与其最相似锚点的**投影**表示（一个锚点索引 + 一个标量系数），而非直接存储完整向量。
- 对投影误差最影响注意力输出的 token，额外分配**量化残差**（2-bit），以恢复其 token 特异性信息。
- 所有 token 均留在 softmax 中，压缩缓存是精确缓存的扰动而非截断。

### 2.2 表示与公式
- 给定向量 \(x_i\)，为其分配最近锚点：
  \[
  a(i)=\arg\max_{a\in A} \frac{|\langle x_i,x_a\rangle|}{\|x_i\|\|x_a\|}
  \]
- 投影系数与残差：
  \[
  \gamma_i=\frac{\langle x_i,x_{a(i)}\rangle}{\|x_{a(i)}\|^2},\quad \tilde{x}_i=\gamma_i x_{a(i)},\quad r_i=x_i-\tilde{x}_i
  \]
- 重建形式：
  \[
  \hat{x}_i=\tilde{x}_i+\mathbf{1}[i\in R]\tilde{r}_i
  \]
  其中 \(R\) 为获得残差的位置集合；键和值各自独立应用该表示，共享锚点位置但分别分配、投影并设置残差集合。

### 2.3 关键设计细节
- **锚点选择**：末尾 W 个位置（recency window）始终精确存储；其余锚点根据类 SnapKV 注意力打分（顶部 ρ=0.7）与均匀采样混合选取，兼顾注意力重要性与方向覆盖。
- **Pre-RoPE 投影**：键在 RoPE 旋转前投影，因为旋转会显著降低与最近锚点的余弦相似度（中位数下降 0.27）；解码时再将重建键旋转。
- **残差量化**：残差经随机 Hadamard 旋转后，用 per-token absmax 归一化，再以 Lloyd–Max 4 电平码本量化；2-bit 编码，每字节打包 4 个坐标。
- **注意力输出感知的残差分配**：以公式 (5) 的注意力输出一阶扰动展开为基础，推导每个 token 的 key channel 与 value channel 效用（Eq. 6），在跨 head 池化后按效用从大到小分配残差预算。每个 layer 的 key 和 value 各得 \(\lfloor N/2\rfloor\) 个残差槽位。
- **字节预算控制**：用户仅设置一个参数 θ（保留缓存比例），精确字节核算将 θ 转为残差数量 N（Eq. 9），保证实际占用不超过预算。
- **解码实现**：Triton 编写的 FlashAttention 风格分块 kernel，直接读取压缩表示、按需重建键值，不物化稠密缓存。

- 在 9 个模型–基准组合中，AnchorKV 在 10× 与 20× 压缩下均取得最高分数。

## 7. 优点

- **方法设计优雅新颖**：锚点-残差表示兼具驱逐的压缩比与量化的全量可达性，且每个 token 通过自己的投影系数保持可区分性，不会坍缩成相同表示。
- **不丢弃 token 的原则性保证**：论文给出输出误差界（Theorem 1），将误差分解为 attention-weighted 的 value 误差与 worst-case 的 key 误差，从理论上解释为何"保留全部 token"比驱逐更安全。
- **残差分配具有正交性**：以注意力输出的一阶扰动为效用指标分配残差，而非单纯依赖注意力分数或残差范数，消融实验证明该策略在 20× 时优势最明显。
- **超参极少且固定**：用户只需设置压缩率 θ，其他超参全固定，便于实际使用。
- **工程实现扎实**：Triton kernel 直接从压缩表示解码，不物化稠密缓存，并给出详细内存核算、端到端开销与并发分析。
- **实验覆盖面广**：三个模型规模、三个基准、逐任务分析、多组消融与效率测量，整体充分。
- **跨规模趋势清晰**：精度随模型规模提升，与"缓存越贵、AnchorKV 越有用"的论点契合。

## 8. 不足与局限

- **依赖 observation window 假设**：残差效用估计使用最近 W 个查询作为未来查询的代表，与驱逐方法共享相同假设；若解码查询关注的模式与 prefill 尾部明显不同，残差分配可能次优（尽管不会丢失 token）。
- **确定性覆盖不足**：论文未报告置信区间、多次随机种子下的方差，单次 greedy 解码统计效力有限。
- **TurboQuant 非官方复现**：原论文未公开代码，作者基于社区实现复现并做了适配调整，可能引入与官方不完全一致的偏差。
- **缺乏更长上下文 / 批处理验证**：主要评估到 128K；batch size 1；未测试多轮对话或 prompt 流式更新场景。
