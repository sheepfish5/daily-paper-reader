## 摘要
大型语言模型（LLM）日益依赖稀疏性来降低推理成本，但以往的大多数工作针对单一稀疏来源——要么是权重，要么是激活——并针对批量多用户推理进行优化。双稀疏性将非结构化权重剪枝与运行时激活稀疏性相结合，在模型规模、准确性和单用户解码延迟之间提供了有吸引力的权衡，但其表现为稀疏矩阵-稀疏向量（spMspV）工作负载，现有GPU内核对此处理不佳。我们提出Celty，一种协同设计的稀疏格式、GPU内核和SIMT微架构，用于LLM推理中的高效spMspV。在内核层面，Celty引入了一种游程长度压缩CSC（RLC-CSC）格式，能够向量化加载压缩的权重列，并利用两种稀疏来源跳过不必要的内存访问，同时使用共享内存进行分散的部分积累积。在微架构层面，Celty稀疏SIMT核心集成了流水线RLC解码器，消除了软件层面的索引重建，并重新利用本地寄存器文件进行无冲突积累——直接操作相同的RLC-CSC格式，无需数据布局更改。Celty GPU内核相比cuBLAS实现了最高2.8倍加速，相比Flash-LLM实现了2.4倍加速。借助稀疏SIMT核心，在70%双稀疏度下，相比cuBLAS加速比最高可达5.3倍。

## Abstract
Large Language Models (LLMs) increasingly rely on sparsity to reduce inference cost, but most prior work targets a single sparsity source-either weight or activation-and optimizes for batched multi-user inference. Dual-sparsity, which combines unstructured weight pruning with runtime activation sparsity, offers a compelling tradeoff among model size, accuracy, and latency for single-user decoding, but formulates as a Sparse Matrix-Sparse Vector (spMspV) workload that existing GPU kernels handle poorly. We propose Celty, a co-designed sparse format, GPU kernel, and SIMT microarchitecture for efficient spMspV in LLM inference. At the kernel level, Celty introduces a Run-Length Compressed CSC (RLC-CSC) format that enables vectorized loading of compressed weight columns and exploits both sparsity sources to skip unnecessary memory accesses, with shared memory used for scattered partial-product accumulation. At the microarchitecture level, the Celty Sparse SIMT Core integrates a pipelined RLC decoder to eliminate software-level index reconstruction and repurposes local register files for conflict-free accumulation-operating directly on the same RLC-CSC format without data layout changes. The Celty GPU kernel achieves up to 2.8x speedup over cuBLAS and 2.4x over Flash-LLM. With the Sparse SIMT Core, speedups reach up to 5.3x over cuBLAS at 70% dual-sparsity.

- **背景**：大语言模型（LLM）在个人设备上的单用户解码场景面临模型体积大和内存带宽受限两大瓶颈。稀疏性可以同时减少模型存储和计算量，是重要的优化方向。
- **已有方法的不足**：
  - 结构化剪枝（如 ShortGPT、BlockPruner）容易加速但精度损失严重；
  - 非结构化权重剪枝（SparseGPT、Wanda）精度保留好，但在 GPU 上加速收益有限，且多数工作面向批量多用户推理（spMM），不适合单用户解码；
  - 激活稀疏性可以跳过整列权重，但无法压缩模型体积。
- **双稀疏（Dual-Sparsity）**：将非结构化权重剪枝与运行时激活稀疏性结合，形成 **稀疏矩阵-稀疏向量（spMspV）** 计算。它在模型体积、精度和单用户解码延迟之间具有良好的权衡，但现有 GPU 内核（包括 spMM、spMV、spMspV）无法高效处理这种中等稀疏度（30%–70%）的负载。
- **本文意义**：Celty 是首个针对双稀疏 LLM 推理中的 spMspV 负载，将**稀疏格式、GPU 内核和 SIMT 微架构**进行协同设计的工作。其核心价值在于为单用户解码场景提供了一条从存储格式到硬件执行的全栈加速路径。

## 2. 论文提出的方法论：核心思想、关键技术细节

Celty 采用三层协同设计：

### 2.1 RLC-CSC 稀疏格式
- 提出 **游程长度压缩的 CSC 格式（Run-Length Compressed CSC, RLC-CSC）**。
- 将权重矩阵按列压缩，每个非零值对应一个 n-bit 游程编码的索引，表示其前面零的个数；间隙超过 \(2^n-1\) 时插入零填充项。
- 采用 4-bit RLC-CSC，在 50% 稀疏度下压缩效率约 63%，且与 bitmap 格式的部署期压缩效率接近（约 64%）。
- 关键优势：RLC-CSC 保持索引和非零值的一一对应关系，支持固定宽度的向量化加载，避免了 bitmap 无法确定非零个数的问题。

### 2.2 Celty spMspV GPU 内核
- **数据流设计**：每个 warp 共享同一个输入激活值 \(b\)，若 \(b\) 为零则整 warp 跳过对应权重列，避免 warp divergence。
- **循环分块（Split-K）**：每个 warp 负责一个 2D tile，覆盖 256 行（M 维度），并在 K 维内循环 64 列；内循环大小设为 64，平衡并行度与原子合并开销。
- **向量化加载**：FP16 下使用 128-bit 向量加载，每个线程一次加载 8 个连续权重；采用 ROMA 反向偏移内存对齐保证向量访问对齐。
- **分散累加**：通过 warp 内前缀和重建绝对行索引（Algorithm 1），将部分积累加到共享内存（SMEM）缓冲区，最后一次性写回全局内存，相比直接全局原子累加平均提速 14.4 倍。

### 2.3 Celty Sparse SIMT 微架构增强
- **寄存器文件累加**：将输出向量按 SM 子分区划分到不同 SIMT core 的本地寄存器文件中，替代 SMEM 累加，消除 bank conflict，并降低访问延迟。
- **硬件 RLC 解码器**：集成 3 级流水线 RLC 解码器，每周期可重建 8 个绝对行索引，代替软件前缀和与 shuffle 指令；解码结果与广播基地址相加形成寄存器文件写地址。
- **跨线程交错编码**：RLC 解码器的 8 个输入来自不同线程 lane，离线压缩时交错排列，保证流水线利用率和正确性（累加顺序无关）。
- 硬件仅增加不到 0.01% 的芯片面积，且可直接在原有 RLC-CSC 格式上工作，无需数据布局转换。

- **总体评价**：Celty 是一篇思路清晰、工程完成度较高的系统协同设计工作。它准确抓住了"单用户解码 + 双稀疏"这一真实但被低估的负载，并自底向上地完成了格式、内核、微架构的闭环设计，避免了常见的"算法与硬件脱节"问题。
- **最具启发性的点**：将原本在 GPU 上昂贵的索引解码（前缀和 + shuffle）下沉到专用硬件单元，同时用寄存器文件替代共享内存做累加——这种"用极小面积换取关键路径加速"的权衡思路，比单纯堆砌稀疏张量核更具可落地性。
- **对读者的建议**：若关注的是纯软件层面的 LLM 加速，可重点阅读第 3–5 节的 RLC-CSC 格式与 spMspV 内核设计；若关注体系结构创新，则第 6 节的 Sparse SIMT 增强（RLC 解码器、寄存器文件累加）是核心；若关注模型精度与稀疏度的权衡，第 7 节的端到端评估已给出较为直观的结论。
- **未来方向**：将 Celty 与量化、KV-cache 稀疏、投机解码等手段联合优化；将 RLC-CSC 扩展至结构化稀疏或 2:4 模式；在真实 FPGA/小芯片上流片验证硬件结果；探索其在多模态模型和更长上下文场景下的表现。
