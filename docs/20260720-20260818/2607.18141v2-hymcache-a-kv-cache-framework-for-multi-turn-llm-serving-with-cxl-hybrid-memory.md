## 摘要
长上下文、多轮和智能体式LLM工作负载越来越多地重用先前处理过的上下文，使得KV缓存重用对于减少冗余计算至关重要。然而，这种重用将瓶颈转移到存储和提供可重用KV状态的存储层，且该层需具备集群规模。GPU HBM和主机DRAM成本过高，难以扩展到TB级共享上下文容量，因此推动了由低成本、高容量介质构建的远程存储层的出现。本文提出HyMCache，一种集成CXL混合内存（CXL-HM）用于多轮LLM服务的KV缓存框架。CXL-HM在CXL接口后结合少量设备内DRAM与大规模SSD支持容量。通过利用多轮KV缓存访问的读主导、可预测和仅追加特性，HyMCache重新思考了CXL-HM内的DRAM管理，以高效支持TB级SSD支持的KV重用。它使用请求级前缀预取和机会性写缓冲将延迟关键读取分阶段调入设备DRAM，从而实现以SSD成本获得DRAM规模的KV缓存效率。我们在真实CXL-HM原型上，在单聚合器和PD分离两种服务配置下评估了HyMCache。在相同DRAM预算下，HyMCache在单节点服务中性能优于本地LMCache 3.0倍，在PD分离服务中优于1.45倍。与1 TB分布式DRAM Mooncake相比，HyMCache性能降低约30%，但使用DRAM减少16倍。

## Abstract
Long-context, multi-turn, and agentic LLM workloads increasingly reuse previously processed context, making KV-cache reuse essential for reducing redundant computation. However, this reuse shifts the bottleneck to the memory tier that stores and serves reusable KV states at cluster scale. GPU HBM and host DRAM are too costly to scale to TB-scale shared context capacity, motivating remote tiers built from lower-cost, higher-capacity media. This paper presents HyMCache, a KV-cache framework that integrates CXL-hybrid memory (CXL-HM) for multi-turn LLM serving. CXL-HM combines a small amount of in-device DRAM with large SSD-backed capacity behind a CXL interface. By exploiting the read-dominant, predictable, and append-only nature of multi-turn KV-cache access, HyMCache rethinks DRAM management within CXL-HM to efficiently support TB-scale SSD-backed KV reuse. It uses request-level prefix prefetching and opportunistic write buffering to stage latency-critical reads in device DRAM, enabling DRAM-scale KV-cache efficiency at SSD-level cost. We evaluate HyMCache on a real CXL-HM prototype under both single-aggregator and PD-disaggregated serving configurations. Under the same DRAM budget, HyMCache outperforms local LMCache by 3.0x in single-node serving and 1.45x in PD-disaggregated serving. Compared with 1 TB distributed-DRAM Mooncake, HyMCache incurs about 30% lower performance but uses 16x less DRAM.

## 2. 方法论：核心思想与关键技术

### 2.1 核心思想
- 多轮 KV-Cache 访问具备三个显著特征：**读主导且只读**（reused KV 不修改）、**可预测**（前缀缓存查找能提前暴露 KV 消费顺序）、**仅追加写**（新 KV 只在每轮生成时写入）。
- 基于这些特征，HyMCache 摒弃了通用 CXL-HM 设备中"透明 LRU 缓存"的 DRAM 管理方式，改为**显式管理的 KV 对象暂存空间**：将少量设备 DRAM 作为"延迟隐藏窗口"，而 SSD 容量作为大规模 KV 存储池。

### 2.2 关键技术细节

**① 请求级前缀预取（Request-level Prefix Prefetching）**
- 通过多轮前缀缓存查找获取请求将要消费的 KV 对象有序列表，将该列表以预取命令形式传递给 CXL-HM 设备。
- CXL-HM 设备内部预取器在远端 RDMA 读到来之前，提前将 KV 对象从 SSD 暂存到设备 DRAM，从而隐藏 SSD 读取延迟。
- 提供三个对象级生命周期 API：`chm_prefetch_object()`、`chm_prefetch_wait()`、`chm_prefetch_release()`，构成"发起—等待—释放"的有界预取流水线。

**② 机会性写缓冲（Opportunistic Write Buffering）**
- 新写入的 KV 与当前请求的正确性无关，只影响未来重用，因此写不进入延迟关键的读路径。
- 设备 DRAM 预留小型写侧缓冲，异步、分批、在读压力低时刷入 SSD；缓冲满时允许跳过或延迟写入，避免 SSD 端读写交叉干扰。

**③ 固定深度暂存窗口（Latency-hiding Staging Window）**
- 内部 DRAM 不作为总 KV 足迹的容量缓存，而是保持一个有界预取深度（默认约 128 MB/请求，按 KV 块大小调整），实现"流式暂存"：预取→消费→释放→继续预取的流水线，使有限的 DRAM 支撑无限增长的语义前缀。

**④ 软件栈集成（Dynamo + vLLM）**
- 新增四个模块：
  - **HyMCache Master**：全局 KV 元数据管理与远程地址解析，将 KV 标识映射为 `(node_id, addr, length)`；写路径按请求粒度分配目标节点，读路径批量返回远程描述符。
  - **HyMCache Lookup**：早期远程命中匹配，分批发起元数据查询，提前发出预取命令（默认每请求最多 32 块）。
  - **HyMCache KV Connector**：轻量挂接 vLLM KV 传输回调，负责 RDMA GET/PUT 和 5 GB CPU 侧暂存缓冲，不改变 vLLM 默认执行路径。
  - **HyMCache KV Manager**：位于 CXL-HM 设备侧，按请求分配预取窗口、协调并发请求间预取资源、通过 NUMA 分配接口管理统一 CXL-HM 地址空间。
- **故障回退机制**：远端 KV 未在 10 秒超时内就绪时回退到普通重计算，与 Mooncake 默认配置一致。

**⑤ 统一地址空间与异构 KV 支持**
- 多个 CXL-HM 设备各作为一个 CPU-less NUMA 节点，通过 RDMA 注册为统一内存区域；请求级 NUMA 分配保证同请求的 KV 块在同一个设备上，支持模型异构 KV 对象大小共存。

## 6. 主要结论与发现

1. **CXL-HM 可提供接近 DRAM 的性能、SSD 级成本**：同等 DRAM 预算下，单节点性能是本地 LMCache 的 3.0 倍；PD 分离配置下是 LMCache 的 1.45 倍。
2. **与 1 TB 分布式 DRAM Mooncake 的对比**：HyMCache 性能低约 30%，但 DRAM 用量减少 16 倍（FPGA 原型成本仍比 1 TB RDIMM 便宜约 2.8–3.8 倍）。
3. **传统 LRU 式 CMM-H DRAM 缓存不适用于 KV 工作负载**：一次命中模式（one-hit-wonder）污染缓存，缓存容量再大也只能推迟、不能消除性能崩塌。
4. **预取显著提升性能**：预取开启提升微基准随机读带宽 37%、LMSYS 峰值带宽接近 200 Gbps 网络极限、端到端时间降低 14%。
5. **NVMe-oF 存储路径效率不足**：文件系统栈使顺序读带宽从 23 GB/s 降至 6.5 GB/s，需要 DPU 或专用优化，而 CXL-HM 以内存语义绕过文件系统。
6. **机会性写策略降低对 transfer-buffer 的依赖**：在 10 GB transfer-buffer 下，Mooncake 性能出现严重退化，而 HyMCache 几乎不受影响。

## 9. 值得注意的隐含假设与可复现性提示

- **工作负载假设**：HyMCache 高度依赖"前缀缓存查找可以提前暴露 KV 消费顺序"这一前提。如果请求复用模式碎片化严重（如随机短前缀重用），预取的提前量不足，效果会明显下降。论文未给出此类退化场景的定量分析。
- **RDMA 与 CXL 路径的协同依赖**：预取流程假设远端 RDMA GET 到达 CXL-HM 设备时，数据已从 SSD 提升到设备 DRAM。这要求预取命令的传递延迟 + SSD 读取延迟 < 应用层 RDMA 请求的到达间隔，否则退化为直接读 SSD。论文未给出 SSD 在随机小读（4 KB 级）下的延迟数据。
- **可复现性**：论文基于 vLLM、Dynamo、NIXL 等开源组件，但 CXL-HM 设备是其自研 FPGA 原型，外部研究者难以复现设备端预取器和 KV Manager 的固件逻辑；软件部分若开源则有较好的复现基础。

## 10. 结论强度与适用边界

- **结论强度**：论文的核心主张——"CXL 混合内存以接近 DRAM 的性能、SSD 的成本服务多轮 KV 缓存"——在其实验配置下是成立的，且消融实验（预取开关）有力支持了机制有效性。但需注意，性能优势的幅度（3.0x/1.45x）是与特定基线（本地 LMCache）相比，且对比环境中 NVIDIA A100 + 200 Gbps RDMA 已是高配，在低配网络（如 25 Gbps）或更差 SSD 上，结论可能缩水。
- **适用边界**：
  - 最适合**多轮对话、agent 工作流、长前缀复用**场景；
  - 对**单轮长上下文生成**（首次写入无重用）无优化意义；
  - 对**高并发短前缀随机复用**场景，预取提前量可能不足，收益有限；
  - 对**写密集工作负载**（如持续滚动写入且无重用）反而不如简单重计算。

## 11. 给读者的实践建议

- **若从事 LLM 推理系统研发**：可借鉴其"预取流水线 + 有界暂存窗口"的思路，即使不采用 CXL-HM，也可在现有 NVMe SSD 缓存层上实现类似的显式预取管理，以接近论文中部分收益。
- **若关注存储硬件方向**：论文证明了对 KV 对象做对象级、语义感知的缓存管理远优于透明 LRU 块缓存，这是 CXL 内存设备未来固件设计的重要参考。
- **若评估是否部署 CXL-HM**：建议先做自身工作负载的前缀复用度分析（复用比例、访问顺序可预测性、KV 块大小分布），再对照论文图 13 的预取敏感度结果做预估。

## 12. 总评

HyMCache 是一篇工程完成度高、写作逻辑清晰的系统论文。它瞄准了一个真实且快速增长的痛点（多轮 LLM 的 KV 缓存容量瓶颈），提出了一个硬件/软件协同的解决方案（应用感知的 CXL 混合内存管理），并用真实硬件原型验证了可行性。与纯 DRAM 分布式缓存（Mooncake）相比，它以可接受的性能代价换取了数量级的成本下降；与纯 SSD 远程存储相比，它通过预取和内存语义绕过了文件系统开销。其最主要的价值在于揭示了一个设计原则：**在成本敏感的 LLM 推理存储层级中，"少量快速介质做有界暂存 + 大容量慢速介质做持久存储 + 应用级预取调度" 是比"扩大 DRAM 缓存容量"更经济的路线**。局限在于验证规模有限、FPGA 原型与商用 ASIC 存在差距，以及 NVMe-oF 对比基线不够公平，但这些不足以动摇其核心结论。作为一篇面向系统与存储社区的研究，它为该方向后续工作提供了坚实的起点。
