## 摘要
大规模LLM推理面临内存墙问题。KV缓存需要每秒数百GB的数十TB容量，然而目前没有任何内存层能够同时满足这两项要求。对配备多种LLaMA模型的多代GPU系统的特征分析表明，主机内存检索相对重新计算可实现高达100倍的加速，但仅支持数十名并发长上下文用户。电CXL池化在理论上弥合了这一差距，但交换机延迟、线缆传输距离限制和功耗扩展问题阻碍了实际的TB级部署。我们提出了Marvell光子结构存储设备，这是一种光子-CXL混合架构，用无源光纤混洗替代电交换机，通过无交换机的全交叉拓扑在16台主机间提供32 TB共享内存。仿真结果表明，与电CXL池相比，延迟降低了超过50%。模拟结果显示，PF存储设备通过将多轮对话工作负载的首令牌时间提升6.6倍，消除了缓存逐出悬崖效应。

## Abstract
LLM inference at scale faces a memory wall. The KV cache demands tens of terabytes at hundreds of gigabytes per second, yet no current memory tier delivers both at once. Characterization across multi-generation GPU systems with various LLaMA models shows host memory retrieval achieves up to 100x speedup over re-computation but supports only tens of concurrent long-context users. Electrical CXL pooling theoretically bridges this gap, but switch latency, cable reach limits, and power-scaling issues prevent practical TB-scale deployments. We present the Marvell Photonic Fabric Memory Appliance, a photonic-CXL hybrid architecture replacing electrical switches with a passive fiber shuffle to deliver 32 TB shared memory across 16 hosts via a switch-free full- crossbar topology. Emulation results demonstrate over 50 percent latency reduction versus electrical CXL pools. Simulation results show that the PF Memory Appliance eliminates cache eviction cliffs by improving time-to-first-token by 6.6x for multi-turn conversations workloads.

## 一、核心问题与整体含义（研究动机和背景）

- **内存墙困境**：大规模LLM推理面临严峻的KV缓存内存瓶颈。主流模型支持超过100万token的上下文窗口（如Claude Opus、Gemini 3、GPT-5.4、LLaMA 4），KV缓存需求巨大——以LLaMA 70B为例，每个token需约328KB（BF16、80层、8个KV头、128维），长上下文多用户场景下轻松达到TB级内存需求。
- **现有内存层级无法兼顾容量与带宽**：论文通过实证表征揭示：
  - **GPU HBM**：带宽极高但容量极其有限（通常80GB），只能容纳少量并发长上下文用户。
  - **主机DRAM**：检索KV缓存比GPU重新计算快最多100倍，但单机容量（约2TB）仅支持数十个并发长上下文用户。
  - **SSD存储**：容量几乎无限，但带宽瓶颈（比CPU-GPU带宽低10–15倍），加载KV缓存甚至可能比完全重新计算更慢（某些短上下文场景出现0.38×–0.53×的减速）。
- **电气CXL的局限性**：虽然CXL共享内存（如TraCT、Beluga）在网络栈消除和KV共享方面有显著优势，但电气CXL存在三大根本限制：
  - 交换延迟：每跳70–500 ns；
  - 线缆传输距离有限（仅数米），需高功耗重定时器；
  - 功耗随端口数和速率超线性增长，难以实现TB级规模的内存池。
- **核心研究问题**：需要一种新的内存层级，能够**同时**提供数十TB容量和超过100GB/s带宽，以支撑生产级大规模LLM推理。

## 二、方法论

### 1. 核心思想
提出**Marvell Photonic Fabric (PF) Memory Appliance**——一种光子-CXL混合架构，用**无源光纤混洗（passive fiber shuffle）**替代电气CXL交换机，构建无交换机的全交叉（full-crossbar）拓扑，实现16台主机间32TB共享内存池。

### 2. 架构关键设计
- **系统组成**：16个PF内存模块，每个模块是CXL 3.1 Type-3设备，通过PCIe Gen6接口连接主机；每个模块包含：
  - 7.2 Tbps光子连接带宽；
  - 2个HBM3E堆栈（各36GB，作为直写缓存或额外池化内存）；
  - 8个DDR5接口，支持最多2TB DDR5内存；
  - 光学PIC中介层和光纤阵列单元。
- **互连拓扑**：16×16无源光纤混洗，形成256条光学路径的全网格拓扑，任意主机可直接访问任意内存模块，无需中间交换。
- **PF-NIC适配卡**：PCIe Gen6/CXL 3.1适配卡，桥接主机CXL接口与光子互连，提取CXL.mem事务字段并转发为光子结构数据包。
- **关键器件选择**：采用GeSi电吸收调制器（EAM）而非微环谐振器（MRR）或马赫-曾德尔调制器（MZM），兼顾热稳定性、小尺寸（亚100μm）和高调制效率。
- **软件集成**：通过CXL Type-3设备的标准枚举流程（DVSEC、CEDT、CFMWS），以Device-DAX模式暴露内存；支持与vLLM（KV Connector）、SGLang（HiCache后端）、NVIDIA Dynamo（NIXL后端插件）等框架的无修改集成。

### 3. 关键公式
- **KV缓存检索加速比**：S = T_compute / T_memory
- **计算时间**：T_compute = b(2sP + 2s²n_head·h_head·L) / MFU（其中b为批次大小，s为提示长度，P为参数量，n_head为注意力头数，h_head为头维度，L为层数，MFU为模型浮点利用率）
- **内存检索时间**：T_memory = K + bs/α（K为固定开销，α为每token加载成本）
- **延迟分解**：T = T_CXL_req + T_mem + T_CXL_resp

## 六、主要结论与发现

1. **主机内存检索KV缓存**：实现最高100×加速（LLaMA-405B），加速比随模型规模、上下文长度和批次大小增加。
2. **SSD检索**：加速有限（最大9.7×），短上下文场景甚至减速，仅适合延迟不敏感的离线场景。
3. **MoE变体**：由于稀疏专家激活降低计算基线，缓存检索相对优势低于同等规模密集模型。
4. **PF Memory Appliance延迟**：空闲状态写224ns、读283ns；负载状态下写集中在210–250ns，读集中在275–290ns（尾部至320ns）；对比电气CXL池的800–900ns，**延迟降低超过50%**。
5. **带宽表现**：16端口全部实现100%带宽利用率，每端口持续25.6GB/s。
6. **端到端效果**：PF Memory Appliance消除缓存驱逐悬崖，300路并发时TTFT保持平坦（约2,690ms），而基线在同场景下从8,156ms恶化到约17,700ms（**6.6×差距**）；前缀缓存命中率从82%骤降至6.35%。

## 七、优点

1. **问题定位精准**：通过大规模实证数据量化了容量-带宽缺口，为架构设计提供了坚实基础。
2. **创新架构突破**：用无源光纤混洗替代电交换机的思路简洁而根本，同时解决延迟、距离、功耗三大瓶颈。
3. **多层级评估体系**：实测（主机/SSD检索）+硬件仿真（带宽/延迟）+端到端系统模拟，三层验证形成完整证据链。
4. **软件兼容性设计**：利用CXL标准和现有框架接口实现无缝集成，无需修改引擎内部。
5. **工程可行性保障**：选用EAM调制器兼顾热稳定与尺寸，分离PIC/ASIC制造工艺优化各自性能。
