## 摘要
混合注意力大语言模型将全注意力与循环线性注意力相结合，以降低长上下文推理成本，但其自回归解码仍然受内存限制。树推测解码提供了一种有吸引力的加速路径，但现有的树推测系统是基于全注意力模型的键值缓存设计的。在混合模型上，它们逐分支地遍历循环层，并为每个提议节点物化完整状态，导致验证延迟和瞬态内存随树和批次大小扩展不佳。我们提出了Bole，一种内核-运行时协同设计，为混合注意力LLM实现高效的树推测。Bole将线性注意力循环转换为树结构的闭合形式，并通过资源高效的GPU内核实现，并行验证所有提议节点，将线性注意力树验证加速3.4-7.7倍。它无损地将推测状态更新编码为令牌级因子，仅重建采样后选择的状态，将瞬态状态内存减少82-99倍，并为KV缓存释放GPU容量。它集成到SGLang（一个广泛部署的生产级LLM服务引擎）中，将高效状态管理与针对完整混合前向计算的批次级验证预算相结合。在四个模型、两个GPU平台和多种数据集上，Bole实现的离线解码吞吐量最高可达自回归解码的4.72倍，是最强树推测基线吞吐量的2.03倍。在在线智能体工作负载下，与最强树推测基线相比，它分别将TTFT和TPOT降低了67.6%和49.9%。

## Abstract
Hybrid-attention large language models combine full attention with recurrent linear attention to reduce long-context inference costs, yet their autoregressive decoding remains memory-bound. Tree speculative decoding offers an attractive acceleration path, but existing tree-speculation systems are designed around the key--value caches of full-attention models. On hybrid models, they traverse recurrent layers branch by branch and materialize a full state for every proposal node, causing verification latency and transient memory to scale poorly with tree and batch sizes. We present Bole, a kernel--runtime co-design that enables efficient tree speculation for hybrid-attention LLMs. Bole transforms the linear-attention recurrence into a tree-structured closed form and realizes it with a resource-efficient GPU kernel, verifying all proposal nodes in parallel and accelerating linear-attention tree verification by 3.4--7.7$\times$. It losslessly encodes speculative state updates as token-level factors and reconstructs only the state selected after sampling, reducing transient state memory by 82--99$\times$ and freeing GPU capacity for KV caches. Its integration into SGLang, a widely deployed production LLM serving engine, couples efficient state management with a batch-wide verification budget calibrated to the complete hybrid forward. Across four models, two GPU platforms, and diverse datasets, Bole delivers up to $4.72\times$ the offline decode throughput of autoregressive decoding and up to $2.03\times$ that of the strongest tree-speculative baseline. Under online agent workloads, it reduces TTFT and TPOT by up to $67.6%$ and $49.9%$, respectively, over the strongest tree-speculative baseline.

### 1. 核心问题与整体含义（研究动机与背景）

- **研究背景**：混合注意力大语言模型（Hybrid-Attention LLMs）将全注意力层与循环线性注意力层交织，例如 Qwen3.5 和 Kimi Linear 等模型。这种设计在降低长上下文推理成本的同时，其自回归解码环节仍然是**内存带宽受限**的，每一次输出 token 都需要一次完整的目标模型调用，导致推理效率低下。
- **核心问题**：树推测解码（Tree Speculative Decoding）是加速推理的有效手段，但现有树推测系统（如 SpecInfer、DeFT、STree、AdaServe、SGLang 等）都是围绕全注意力模型的 KV Cache 设计的。在混合注意力模型上，它们面临三个严重瓶颈：
  - **串行递归（L1）**：每个提议节点依赖父节点的循环状态，必须逐分支地顺序执行，树规模增大时线性注意力层耗时占比急剧上升（从树的 8 节点时的 4% 上升到 64 节点时的 27%）。
  - **状态爆炸（L2）**：为每个提议节点物化完整的状态快照，内存开销随树规模和批次大小线性增长（如 122B 模型在 8 个请求 × 32 节点时消耗 36 GiB），严重挤压 KV 缓存容量。
  - **变量化的验证容量（L3）**：额外 token 并非无限“近乎免费”，超过硬件相关的阈值（如 A100 约 128 行、GB10 约 256 行）后，延迟随 token 数线性增长，且该阈值与 GPU 平台、批次大小、KV 长度和树结构均有关联。
- **核心挑战**：需要同时解决树耦合的循环依赖、分支选择前的状态发散，以及多种算子（全注意力、线性注意力、MLP）耦合且配置相关的成本模型问题。

### 2. 论文提出的方法论

Bole 采用**内核–运行时协同设计**，通过三大机制解决上述挑战：

#### (1) 并行树求解器（Parallel Tree Solver）

- **核心思想**：将线性注意力（Gated DeltaNet, GDN）的循环递归转换为**树结构的闭式方程**，使所有提议节点可以从一个固定的“树前状态”并行求解，不再需要逐节点遍历。
- **定理 1（闭式树验证）**：将串行树执行转化为如下形式（所有符号见表 II）：
  $$
  O = D_P Q S_{pre} + C(I+G)^{-1}D_\beta \left( V - D_P K S_{pre} \right)
  $$
  其中：
  - $D_P Q S_{pre}$ 是共享状态的衰减读出；
  - $R = D_\beta(V - D_P K S_{pre})$ 形成局部增量；
  - $(I+G)^{-1}$ 将增量沿祖先节点传播；
  - $C$ 执行所有读出。
- **三个关键引理**：
  - **Lemma 1（路径因子化状态）**：将每个节点的前后状态分解为共享状态与路径上历史 token 增量之和；
  - **Lemma 2（祖先掩码校正系统）**：将增量化简为 $(I+G)U = R$ 的线性系统，G 的稀疏模式精确对应树拓扑的祖先依赖；
  - **Lemma 3（深度有界幂零性）**：由于 G 严格下三角、深度为 d，所以 $G^{d+1}=0$，$(I+G)^{-1}$ 展开为最多 d 项的有限多项式。
- **GPU 内核实现（值切片并行验证内核）**：
  - 将 value 维度分为 $N_v$ 个 tile，每个 tile 由一个 CTA 处理，覆盖全部树节点；
  - 树相关的因子 G、C 由单个 factor producer 统一构造，被所有 tile CTA 复用；
  - 有限 Neumann 传播（$Z^{(m+1)} = -GZ^{(m)}$）在片上完成，中间结果不写回 HBM；
  - 通过二维资源切片（$b_v$ 控制 CTA 数量，$b_k$ 控制片上占用）平衡并行度与资源复用效率。

#### (2) 因子化状态生命周期（Factorized State Lifecycle）

- **无损编码**：不再为每个候选分支保存完整状态快照，而是仅保存一个**不可变的已提交状态**加上**token 级因子**（P、K、U），空间复杂度从 $O(H d_k d_v)$ 每分支降至 $O(T H(d_k+d_v+1))$。
- **提交重建**：采样确定接受路径后，仅需一次批量矩阵乘法即可精确重建接受路径的最终状态：
  $$
  S_{new} = P_a S_{pre} + (D_a K_a)^\top U_a
  $$
- **三种生命周期分层**：已提交状态（跨轮持久）、因子（仅当轮、采样后回收）、短期工作区（单层即焚），实现固定容量的工作区分层复用。

#### (3) 硬件感知的批次级验证预算（Hardware-Aware Verification Budget）

- **离线校准**：对每个执行配置（模型、GPU、并行度、批次/ KV 长度桶、树模板）评测完整混合前向延迟，选取不超过普通解码延迟（$1+\epsilon$ 倍）的最大验证节点数 $B_{ver}(c)$。
- **在线分配**：以草稿模型的路径累计概率 $\rho(v)$ 为全局评分，在跨请求之间分配有限预算；由概率单调性保证每个请求选中的节点保持前缀连通性。

#### 生产级集成

- 将 Bole 集成到 SGLang（约 6.2k 行 Python/Triton 代码），实现 CUDA Graph 原生的扁平化非规则森林执行、跨层统一状态提交、以及无气泡的 GPU 流水线（选择、物化、验证、采样、提交全部在 GPU 上完成，消除主机同步间隙）。

### 6. 主要结论与发现

- **端到端性能**：Bole 在所有 28 个离线配置中一致优于所有基线。对 SGLang-AR 的几何平均加速比 2.74 倍，对最强树推测基线 1.26 倍；峰值加速在 A100 上为 3.62×/1.41×/1.39×（对 AR/Tree/AdaServe），在 GB10 上分别为 4.72×/2.03×/2.06×。
- **内核加速**：完整 GDN 验证核心较串行路径加速 3.4–7.7 倍（批次 16 时达最高），节点级并行度提升占用率 3.6–7.9 倍，L1/共享内存吞吐提升 1.8–4.1 倍。
- **内存优化**：瞬态状态内存减少 82–99 倍（实测非缓存推测开销降低 74.0–88.5%，释放 6.26–18.58 GiB），使 27B 模型在批次 8 下可运行而不 OOM（两个基线均 OOM）。
- **在线服务质量**：与最强树推测基线相比，TTFT 降低 61.3–73.3%，TPOT 降低 28.9–49.9%；前缀缓存命中率提升至 90.8%（A100）/92.6%（GB10），较树基线恢复 21.1–34.3 个百分点的缓存命中率。
- **理论等价性**：Bole 的闭式求解与顺序执行在代数上精确等价，不引入近似误差，保持目标模型的输出分布不变。

### 7. 优点与亮点

1. **算法理论贡献扎实**：通过定理+三个引理的严格推导，将线性注意力的树状递归化为精确闭式解，为后续内核设计提供了理论支撑，且不改变模型语义。
2. **内核–运行时协同设计**：不是孤立的优化，而是算法、GPU 内核、运行时调度三个层面联合设计，解决的是从状态表示到容量分配的整体链路问题。
3. **精准识别硬件特性**：通过图 1 的三项量化分析和图 11 的敏感性实验，清晰论证了“额外 token 并非总是近乎免费”的硬件相关阈值效应，并据此设计预算校准机制。
4. **无损与生产可用**：因子化状态无损编码、CUDA Graph 原生支持、无气泡 GPU 流水线，直接集成进 SGLang 生产引擎，具备真实部署价值。
5. **实验严谨性**：在多种模型规模、两代 GPU 架构、四种数据集和在线智能体负载下均验证了一致的加速比，并通过消融隔离了每个设计的单独贡献。

### 8. 不足与局限

1. **模型覆盖有限**：所有实验仅使用 Qwen3.5 系列（GDN 架构），未在 Kimi Linear 等其他混合注意力架构上进行验证，泛化性有待进一步确认。
2. **AdaServe 基线非原版**：因 AdaServe 开源实现不支持混合模型，作者自行移植优化，可能与原系统的优化程度存在差异，对比公平性有一定风险。
3. **硬件代表性局限**：仅测试了 A100（数据中心 Ampere）和 GB10（边缘低带宽统一内存）两类平台，未覆盖 Hopper（H100）等新一代数据中心 GPU，也未讨论多节点分布式场景。
4. **离线实验的同质性**：CPU scheduler 与 GPU execution 的流水线在连续批处理下虽然整体吞吐一致，但离线实验固定批大小，未系统验证不同到达速率或混合 SLO 请求下的影响。
5. **状态提交的数学细节**：论文对带 grouped key heads 的因子共享仅一笔带过，未深入讨论该情境下的实现细节、开销和边界条件。
6. **资源调度粒度**：硬件感知预算为离线离线校准的静态容量，未讨论在线动态负载变化时的自适应调整机制（虽然有硬件相关的校准，但缺少在线自适应能力）。
