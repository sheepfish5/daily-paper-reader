## 摘要
尽管二元量化在理论上承诺为大型语言模型（LLM）带来极致的压缩与加速，但现有研究往往忽视了专用硬件内核的必要性，因而由于持续依赖昂贵的浮点运算或运行时反量化开销，未能释放全部加速潜力。为弥合这一差距，我们提出了FluxBin（基于灵活查表法的超低位宽执行与二元基），这是一种算法-内核协同设计，将训练后量化与高度优化的CUDA内核相结合。在算法层面，我们引入了解耦行列二元分解以增强表示能力，同时保持硬件效率，并辅以Hessian引导的显著性感知混合基，以保留关键信息。在内核层面，我们实现了一种带尺度融合的查表构建方法以减少浮点运算，并采用虚拟列映射将不规则、稀疏且显著的矩阵转换为密集执行。大量评估表明，FluxBin在各种模型架构上实现了高达5.92倍的加速和10.19倍的能耗节省，同时提供与深度微调方法相当的精度。这有效地使得70B规模模型能够在单个A100 GPU上部署，内存减少4倍。代码可在https://github.com/nicyyyy/FluxBin获取。

## Abstract
While binary quantization theoretically promises extreme compression and acceleration for Large Language Models (LLMs), existing research often overlooks the necessity of specialized hardware kernels, thus failing to unleash the full acceleration potential due to persistent reliance on expensive floating-point arithmetic or runtime dequantization overheads. To bridge this gap, we propose FluxBin (\textbf{F}lexible \textbf{L}UT-based \textbf{U}ltra-low-bit e\textbf{X}ecution with \textbf{Bin}ary bases), an algorithm-kernel co-design that synergizes post-training quantization with a highly optimized CUDA kernel. Algorithmically, we introduce Decoupled Row-Column Binary Decomposition to enhance representational capacity while maintaining hardware efficiency, complemented by a Hessian-guided saliency-aware hybrid bases that preserve critical information. At the kernel level, we implement a Lookup Table Building Approach with Scale Fusion to reduce floating-point arithmetic, featuring a Virtual Columnar Mapping that transforms irregular, sparse, and salient matrices into dense execution. Extensive evaluations demonstrate FluxBin achieves up to $5.92\times$ speedup and $10.19\times$ energy savings across diverse model architectures, delivering comparable accuracy to heavily fine-tuned methods. This effectively enables the deployment of 70B-scale models on one single A100 GPU with a $4\times$ memory reduction. Code is available at https://github.com/nicyyyy/FluxBin.

  3. 低比特内核实现低效，现有 LUT 内核难以处理混合精度带来的不规则访存，且缺乏针对超低位 PTQ 场景的优化。

## 2. 论文提出的方法论

### 2.1 算法层：FluxBin 量化方法

- **解耦行列二元分解（Decoupled Row-Column Binary Decomposition）**
  - 将稠密权重矩阵 \(W \in \mathbb{R}^{M \times N}\) 近似为若干二元基的线性组合，每个基允许**行缩放 \(\alpha_r\)** 和**列缩放 \(\alpha_c\)**：
    \[
    \hat{W}^{(k)} = (\alpha_r^{(k)} \alpha_c^{(k)\top}) \odot B^{(k)},\quad B^{(k)} \in \{-1,+1\}^{M\times N}
    \]
  - 该结构比仅行缩放的方法更好地捕捉 LLM 权重的各向异性分布。

- **参数优化**
  - 通过交替最小化求解 \(\{\alpha_r, \alpha_c, B\}\)；
  - 固定其它变量时，行/列缩放因子有闭式解（论文公式 5）；
  - 对多个基（\(K_b \ge 2\)）进行联合优化，而非贪心逐阶提取，通过穷举 \(2^{K_b}\) 种符号组合确定最优二元基（论文公式 6）。

- **结构化显著性搜索（Structural Saliency Search）**
  - 基于最优脑量化（OBQ）框架，利用 Hessian 逆 \(H^{-1}\) 估计权重敏感性；
  - 定义列级显著性得分 \(S_j = \sum_i W_{ij}^2 [H^{-1}]_{jj}^2\)；
  - 按组（group size \(g\)）选择每组成显著性得分最高的 \(s\) 列，得到掩码 \(M\)。

- **显著性感知混合基（Salient-Aware Hybrid Bases）**
  - 最终量化权重 = **全局基**（Global Base）+ **显著细化**（Salient Refinement）：
    \[
    \hat{W} = \sum_{k=1}^{K_b} Q(W;\Theta_k) + \sum_{k=1}^{K_s} Q(R_{\text{base}};\Phi_k) \odot M
    \]
  - 全局基负责整体近似，显著细化针对高敏感列进行残差补偿，兼顾精度和存储效率；
  - 整个方法是**纯 PTQ**，无需微调或蒸馏。

### 2.2 内核层：FluxBin LUT 内核

- **LUT 构建与尺度融合（LUT-BSF）**
  - 将输入划分为长度为 \(\mu\) 的子向量；
  - 构建 LUT 时直接将列缩放 \(\alpha_c\) 融合进查表值，消除 GEMV 主循环中的浮点乘加运算；
  - LUT 条目计算：\[
    \text{LUT}[p] = \sum_{n=1}^{\mu} (X_{\text{sub}}[n]\cdot \alpha_{c,\text{sub}}[n]) \cdot (2b_n(p)-1)
    \]

- **LUT 读取与归约**
  - 压缩后的 Uint32 权重直接作为位模式，通过位运算提取子块索引 \(p\)，查表得到部分和；
  - 查表结果乘以行缩放并在寄存器中累加，最后写回全局内存。

- **虚拟列映射（VCM）**
  - 针对显著细化分支的稀疏列（由 \(I_{\text{sal}}\) 定义），将其逻辑稀疏列重映射到物理稠密矩阵 \(B_{sd}^{(k)}\)；
  - 运行时通过翻译层收集对应激活和缩放因子；
  - 将“逻辑稀疏”转化为“物理稠密”执行，避免不规则访存，并复用全局基的稠密内核。

- **矩阵分块**
  - 权重矩阵分为 \(M_{\text{tile}} \times N_{\text{tile}}\) 瓦片，映射到 GPU 线程块；
  - 每块构建共享内存中的 LUT，供块内所有线程查询；
  - 默认配置为 \(M_{\text{tile}}=128, K_{\text{tile}}=64, \mu=8\)。

## 6. 主要结论与发现

- **加速与能效**：FluxBin 在 LLaMA-2 上实现最高 **5.92× 端到端加速**和 **10.19× 能耗节省**（对比 FP16）；解码阶段在 BS=1 时亦有 6.3×–6.6× 加速。
- **内存压缩**：实现约 **4× 显存减少**，使 70B 模型可在单张 A100 上推理（FP16 下 OOM）。
- **精度-速度最优权衡**：在 LLaMA-2-7B 上，FluxBin-2b-s16-g128 的平均零样本准确率为 59.15%，与深度微调的 QuIP#（59.41%）相当，且吞吐量显著更高；在速度-精度二维图上占据右上角（高精度+高速度）区域。
- **架构泛化**：在 LLaMA-3.1 和 Qwen3 上同样保持优势，尤其是对敏感模型，FluxBin 的混合基策略比 AQLM/FlexRound 高 17–31 个百分点的准确率。
- **加速来源**：
  - 权重压缩降低 HBM 内存流量（2-bit 约 8× 压缩）；
  - LUT 查表将 \(\mu\) 次 FMA 替换为 1 次共享内存访问，计算复杂度降低 \(\mu/K_b\) 倍（默认 4×）；
  - 用 SRAM 查表替代 ALU 繁重的位运算和类型转换，减轻计算部件压力；
  - 该加速与 batch size 无关，故大 batch 下依然保持优势。

## 7. 优点

- **算法-内核协同设计**：真正将 PTQ 方法与专用 CUDA 内核结合，而不是停留在“模拟量化”仿真层面，落地性强。
- **纯 PTQ、训练免费**：快速部署，无需微调或蒸馏，适合实际生产环境。
- **混合精度高保真**：通过 Hessian 引导的显著性感知混合基，实现了类似微调方法的精度，同时保持极低位宽。
- **VCM 高效处理稀疏性**：将稀疏显著列转化为稠密计算，避免了不规则访存和额外开销，使混合精度分支几乎“零成本”集成到统一内核。
- **丰富的实验验证**：覆盖多模型结构、多任务、多配置，并提供深入的 kernel 级剖析（延迟、TFLOPS、功率、能耗、共享内存分析）。
- **开源代码**：可复现性较好。

## 8. 不足与局限

- **共享内存约束**：LUT 大小随子向量长度指数增长（\(2^\mu\)），在共享内存较小的硬件上必须降低 \(\mu\) 或 batch size，可能影响加速效果。
- **纯 PTQ 精度上限**：虽然是训练免费且精度与微调方法相当，但与花费大量算力微调的方法相比仍有细微差距；论文也承认未来可结合轻量参数高效微调进一步缩小差距。
- **实验测量公平性风险**：对比方法的吞吐量未统一说明是否使用相同的 CUDA Graphs 优化和 batch 调度，可能存在框架差异导致的速度偏差。
- **单卡场景**：仅在单张 A100 上验证，未涉及多卡张量并行/流水线并行下的表现；而实际超大模型部署常需要多卡，尚未检验其通信开销对 LUT 内核的影响。
