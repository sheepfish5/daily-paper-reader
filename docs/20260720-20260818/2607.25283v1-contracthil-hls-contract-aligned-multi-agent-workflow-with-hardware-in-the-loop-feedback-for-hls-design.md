## 摘要
本文提出了ContractHIL-HLS，一种面向实际高层次综合（HLS）工程的契约对齐多智能体工作流。该工作流有三项贡献。首先，它引入了一种结构化契约作为语义对齐和任务执行工件，将自然语言需求转化为明确的接口、约束、验证检查和回滚规则。其次，它将硬件信息纳入反馈回路，通过将HLS、Vivado、PYNQ运行时、功耗和故障证据反馈到生成过程中，将LLM辅助的HLS从内核代码扩展到系统和板级闭环。第三，它按语义降级和执行任务而非对话角色来分解智能体：契约智能体将自然语言降级为契约，HTML智能体将契约渲染为持久的结构化HTML，硬件在环智能体利用实测证据实现并修订设计。我们从两部分评估ContractHIL-HLS。在94个可本地执行的HLS-Eval任务上，结构化契约提供了最大的小设计增益，将估计的单样本测试平台通过率从64.0%提升到70.2%；完整流程达到70.4%的pass@1和76.6%的pass@5。由于HLS-Eval不涉及板级设计，我们还在一个经板级测试的ML-KEM/ML-DSA后量子密码（PQC）安全消息加速器上验证了ContractHIL-HLS，其中保留的双比特流组织将六条消息的平均文本运行时间从207.3 ms降至52.4 ms，且两个映像上的布线WNS均为正，同时保持了解密消息验证。我们在BJUT-CS316-LAB/ContractHIL-HLS开源了我们的工作（https://github.com/BJUT-CS316-LAB/ContractHIL-HLS）。

## Abstract
This paper presents ContractHIL-HLS, a contract-aligned multi-agent workflow for practical high-level synthesis (HLS) engineering. The workflow makes three contributions. First, it introduces a structured contract as the semantic-alignment and task-execution artifact that translates natural language requirements into explicit interfaces, constraints, validation checks, and rollback rules. Second, it incorporates hardware information into the feedback loop by feeding HLS, Vivado, PYNQ runtime, power, and failure evidence back into generation, thereby extending LLM-assisted HLS from kernel code toward system- and board-level closure. Third, it decomposes agents by semantic lowering and execution tasks rather than by conversational roles: a Contract Agent lowers natural language into the contract, an HTML Agent renders the contract as persistent structured HTML, and a Hardware-in-the-Loop Agent implements and revises the design with measured evidence. We evaluate ContractHIL-HLS in two parts. On 94 locally executable HLS-Eval tasks, the structured contract provides the largest small design gain, improving the estimated single-sample testbench pass rate from 64.0% to 70.2%; the full flow reaches 70.4% pass@1 and 76.6% pass@5. Because HLS-Eval does not exercise board-level design, we also validate ContractHIL-HLS on a board tested ML-KEM/ML-DSA post-quantum cryptography (PQC) secure-message accelerator, where the retained dual-bitstream organization reduces six-message average text runtime from 207.3 ms to 52.4 ms with positive routed WNS on both images while preserving decrypted-message verification. We open-source our work at BJUT-CS316-LAB/ContractHIL-HLS (https://github.com/BJUT-CS316-LAB/ContractHIL-HLS).

- 实际 HLS 工程中，设计需求需要跨迭代地保持**接口契约、EDA 工具收敛性、主机控制逻辑、内存所有权和 FPGA 部署测量结果**的一致性，而现有工作通常只以提示文本或源代码快照作为跨阶段的状态载体，工具反馈（HLS 报告、Vivado 实现结果、板级运行数据）很少成为闭环中的一等公民。

### 2. 论文提出的方法论

**核心思想**
将自然语言需求转化为**结构化契约（Contract）**，并以**持久化 HTML 工件**形式在智能体间传递，最后用硬件在环反馈驱动实现与修订——形成“需求 → 契约 → HTML → 实现 → 测量 → 回滚”的闭环。

**智能体划分（按语义降级与执行任务，而非对话角色）**
- **Contract Agent（契约智能体）**：将自然语言需求降级为结构化工程契约，不写代码。契约形式化表示为 C = ⟨R, I, F, H, K, O, V, B⟩：
  - R：角色/平台（role/platform）
  - I：公共接口（public interface）
  - F：功能意图（functional intent）
  - H：硬约束与负约束（hard/negative constraints，如禁止动态分配、STL、递归）
  - K：与起始代码和 testbench 的兼容性
  - O：优化意图（optimization intent）
  - V：验证证据（validation evidence，如 CSim/CSynth 日志）
  - B：回滚策略（rollback policy）
- **HTML Agent**：将契约渲染为结构化 HTML 工件（含稳定章节、表格、锚点、检查清单、测量字段和回滚规则），供人类工程师检查、智能体消费、脚本解析/diff。
- **Hardware-in-the-Loop Agent**：基于 HTML 工件和硬件反馈生成有边界的 HLS/Tcl/主机脚本/文档修改方案。

**硬件在环修订循环**
- 候选代码经过独立脚本的逐步门控验证：Can Parse → Can Compile → Can Pass TB → Can Synth；部署类任务还需通过 Vivado 实现和 PYNQ 板级测量。
- HLS/Vivado/板级运行/功耗/失败证据被回馈到生成与回滚决策中；候选若在测试平台、时序、资源或 EDP 门控上失败，不能静默成为下一上下文状态。
- 契约区分**不变规则**（如密码学数据流、公共接口）与**平台选择**（如位流切分、缓存放置、DSP 绑定），使同一源工程可在不同板卡上剪枝或加宽数据通路。

**三类评估范式对比**
- **Direct**：原始 HLS-Eval 风格任务提示。
- **Contract**：仅添加 Contract Agent 的结构化字段。
- **ContractHIL-HLS**：额外添加 HTML 交接与硬件在环提示。
