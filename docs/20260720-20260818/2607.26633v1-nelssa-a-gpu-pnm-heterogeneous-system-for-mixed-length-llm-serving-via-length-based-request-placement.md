## 摘要
现代LLM及其智能体应用正在拓宽服务工作负载的范围，上下文长度从几百个token到几十万个不等。由于这些请求经常在同一服务窗口内交错，LLM服务系统必须处理高度异构的混合长度工作负载。这种混合长度工作负载暴露了以GPU为中心的服务架构的根本性低效，其吞吐量依赖于大型、受内存限制的批次。在本文中，我们提出了NELSSA，一种将GPU与真实世界的近内存处理(PNM)加速器设备集成的LLM服务系统，以高效支持混合长度工作负载。NELSSA采用基于长度的请求放置，将短上下文请求路由到GPU，将长上下文请求路由到PNM层，并结合运行时迁移以适应动态上下文增长而无需重新计算。我们将NELSSA原型实现为一个端到端系统，在PNM上实现设备级稀疏注意力、GPU解码内核，以及一个主机端运行时，通过支持RPC和RDMA的CXL基础设施协调调度和跨层内存移动。在混合长度LLM工作负载中，与仅GPU基线相比，NELSSA将解码吞吐量提高了高达5.5倍（token/秒），并将P99延迟降低了高达15倍。我们的端到端原型和实验结果表明，通过基于CXL的解聚实现的GPU-PNM集成服务，是一种可扩展且灵活的LLM基础设施的有前景的系统范式，可支持不断演变的工作负载。

## Abstract
Modern LLMs and their agentic applications are broadening the range of serving workloads, spanning context lengths from a few hundred tokens to hundreds of thousands. As these requests frequently interleave within the same serving window, LLM serving systems must handle highly heterogeneous mixed-length workloads. Such mixed-length workloads expose fundamental inefficiencies in GPU-centric serving architectures, whose throughput depends on large, memory-constrained batches. In this paper, we present NELSSA, an LLM serving system that integrates GPUs with real-world Processing-near-Memory (PNM) accelerator devices to efficiently support mixed-length workloads. NELSSA employs length-based request placement to route short-context requests to GPUs and long-context requests to the PNM tier, incorporating runtime migration to accommodate dynamic context growth without recomputation. We prototype NELSSA as an end-to-end system, implementing device-level sparse attention on PNM, GPU decode kernels, and a host-side runtime that orchestrates scheduling and cross-tier memory movement over a CXL-enabled infrastructure with RPC and RDMA support. Across mixed-length LLM workloads, NELSSA improves decode throughput by up to 5.5x in tokens/sec and reduces P99 latency by up to 15x compared to GPU-only baselines. Our end-to-end prototype and experimental results suggest that integrated GPU-PNM serving, enabled by CXL-based disaggregation, is a promising system paradigm for scalable and flexible LLM infrastructures that support evolving workloads.

## 1. 核心问题与整体含义（研究动机与背景）

- **背景**：随着以 ChatGPT 为代表的生成式 AI 向智能体（Agentic）应用演进，LLM 服务负载的上下文长度差异急剧扩大。真实生产环境中，请求长度从几百个 token 到超过 100K token 不等，短请求与长请求频繁交错出现，形成 **混合长度（Mixed-Length）工作负载**。
- **核心痛点**：以 GPU 为中心的传统服务架构在这种负载下存在根本性效率问题：
  - 长上下文请求的 KV cache 占用巨大，迅速耗尽 GPU HBM 容量，导致有效批大小坍缩、吞吐量骤降，甚至出现 **队头阻塞（Head-of-Line Blocking）**，拖累短请求的尾延迟。
  - 长上下文解码注意力是典型的 **内存受限（Memory-Bound）** 任务，HBM 容量和带宽同时饱和，而张量核心利用率极低，存在结构性资源错配。
- **现有方案的不足**：
  - KV cache 压缩/量化：以精度损失换取容量，存在固有精度—容量权衡；
  - CPU offloading：受 PCIe 带宽瓶颈限制，且注意力最终仍需回到 GPU 执行；
  - 已有的 PNM 方案：要么只针对长请求优化而忽视短请求，要么假设静态请求长度，缺乏端到端系统集成。
- **论文立场**：问题本质不是"KV cache 存在哪里"，而是 **"注意力在哪里执行"** —— 即执行放置问题。作者主张将 PNM 视为长上下文注意力的**一级执行引擎**，而非辅助卸载设备。

## 2. 方法论：核心思想、关键技术细节

### 2.1 总体思路

NELSSA 将 GPU 与真实 PNM 设备集成，采用 **基于长度的请求放置（Length-based Request Placement）**：

- **短请求**（序列长度低于阈值 \(T_{\text{input}}\)）→ GPU，使用 FlashAttention 稠密注意力；
- **长请求**（超过阈值）→ PNM 层，执行稀疏注意力；
- **运行时迁移**：应对生成过程中上下文动态增长，无需重算。

### 2.2 三条设计原则

1. **执行放置由请求长度决定**：单一策略无法覆盖全谱段，需按硬件特性划分；
2. **一旦迁移到 PNM 层，执行不再返回 GPU**（单向交接原则），从结构上消除互联往返开销；
3. **异构系统架构**：GPU 负责短注意力与全部 FFN 计算，PNM 专责长上下文稀疏注意力，实现专业化分工。

### 2.3 关键技术细节

**(1) 路由阈值推导（\(T_{\text{input}}\)）**：基于硬件性能特征建立解码注意力延迟模型，求取 GPU 稠密注意力和 PNM 稀疏注意力两条路径的交叉点：

- GPU 路径：\(T_{\text{GPU}}(L) = \frac{L \cdot M_{kv}}{BW_{\text{GPU}}}\)
- PNM 路径：\(T_{\text{PNM}}(L, N)\) = 质心相似度搜索 + \(\frac{L \cdot S \cdot M_{kv}}{N \cdot BW^{\text{eff}}_{\text{PNM}}}\) + 通信开销 \(T_{\text{comm}}(N)\)
- 令两者相等求出交叉点 \(L_{\text{crossover}}(N)\)，即为路由阈值。该值随 PNM 设备数 \(N\) 增大而向更短序列移动——单设备时交叉点超出实际工作负载范围，因此采用多 PNM 设计。

**(2) 分离式混合路由（Split-Batch Hybrid Routing）**：
- QKV 投影和 MLP 计算对长短请求**统一在 GPU 上全局批处理**，仅注意力阶段发生分支；
- 长请求注意力分两块：GPU 处理含 sink token 和近期 token 的局部窗口，PNM 异步执行基于查询驱动聚类选择的全局稀疏注意力；
- 两部分结果通过 **Online Softmax（LSE）合并**，数学上等价于对并集做完整注意力；
- 短请求的 MLP 计算不会被 PNM offloading 阻塞。

**(3) 无缝后台迁移（Seamless Background Migration）**：
- 迁移候选：上下文长度超过 \(T_{\text{input}}\) 的请求；抢占即将发生时，选择累积上下文最长的请求优先迁移；
- 通过后台流异步传输历史 KV cache 到 PNM 节点，**不中断 token 生成**；
- 交接后 GPU 仅保留轻量级质心元信息（Centroid Meta-Info），立即回收 KV 内存；
- 交接后新产生的 KV cache 按预定义 chunk 周期性聚类、增量追加，摊薄聚类开销。

**(4) KV 分区策略**：采用 **按头分区（Head-wise Partitioning）**，所有 PNM 模块处理相同的聚类列表但只计算分配到的注意力头，保证负载均衡（避免聚类集中导致的倾斜）。

**(5) 系统架构**：基于 prefill-decode 分离，增加三级组件：
- **Prefill Node**：对所有请求做 prefill，长请求并行执行分段 K-means 聚类（开销约占 prefill 的 2%）；
- **Decode GPU Node**：短请求 FlashAttention + 全部 FFN；
- **NELSSA Node**：高容量内存节点，通过 RoCEv2 连接，多个 PNM 模块并行执行稀疏注意力；
- 控制路径走 gRPC/TCP，数据路径走 RoCEv2 RDMA，实现 OS 内核旁路。

## 6. 主要结论与发现

1. **吞吐量**：相比 1× GPU 基线最高提升 **5.5×**，相比 2× GPU 基线最高提升 **3.6×**；在 GPU-only OoM 的配置下 NELSSA 仍可服务；
2. **尾延迟**：P95 TPOT 降低 **6.2×**，P99 TPOT 最高降低 **15×**；
3. **HoL 缓解**：NELSSA 保持 GPU 内存余量，维持高位运行批大小，队列不积压；长请求占比越高，优势越明显；
4. **动态迁移**：在 1:2 输入输出比场景下吞吐提升 29%，避免预emption；后台 KV 迁移不引入明显解码抖动；
5. **精度**：selection ratio ≥ 4% 时与 GPU-only 基线精度持平；
6. **通信开销**：最严苛条件下跨节点通信仅占总延迟 ≤2.1%，网络非瓶颈。

## 7. 优点

- **问题选得准**：瞄准混合长度负载这一真实且日益紧迫的服务瓶颈，动机数据充分；
- **端到端落地**：不同于多数 PNM 工作停留在仿真，NELSSA 真机实现了完整服务栈（RDMA、gRPC、CXL、多 PNM 调度）；
- **硬件感知的阈值推导**：路由边界由解析模型从设备特性导出，而非启发式拍脑袋，具备可迁移性；
- **单向交接原则**：从结构上消除迭代式中断（swap/recompute），设计思想简洁有力；
- **分离式架构**：严格的架构隔离（数据摄取路径与计算路径分离）+ 各层独立扩展，工程上务实；
- **评估方法论**：微指标实测 + 测量校准系统仿真相互印证，提升了有限硬件条件下的结论可信度。

## 8. 不足与局限

- **原型硬件受限**：PNM 设备仅 32 GB 内存，无法直接实测高容量场景；512 GB 行为依赖投影外推，存在不确定性；
- **仿真依赖**：系统级吞吐仿真基于测量校准，而非全硬件实测；网络敏感性为纯分析结果；
- **工作负载代表性有限**：混合长度负载为合成构造，未使用真实生产追踪做端到端验证；
- **精度验证较窄**：仅 2 个 RULER 子任务，不足以全面支撑"无精度损失"的结论；
- **模型与规模有限**：仅评测 Llama3-8B 单模型，未覆盖更大规模（如 70B+）或多模型混布；对超大 batch、多租户、多 NELSSA 节点扩展的验证尚缺；
- **部分拆解估算保守性不确定**：PNM-overhead、Transfer 等组件取实测均值恒定外推，若数据量增大时行为变化，投影误差可能被低估；
- **编排层动态调整只作为未来工作**：真实多租户环境中工作负载倾斜可能饱和某一层，论文未给出自适应路由的完整方案或实验。
