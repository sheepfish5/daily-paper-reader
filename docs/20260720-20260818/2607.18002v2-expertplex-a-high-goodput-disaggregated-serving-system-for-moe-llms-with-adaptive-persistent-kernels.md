## 摘要
大语言模型通过扩展混合专家（MoE）参数来获得更优的智能，但巨大的权重和动态计算阻碍了高效服务。现有的实例级预填充-解码解聚将两个阶段隔离在独立的完整模型副本上。随着MoE权重的增长，每个实例可能跨越数十至数百个GPU，使得资源分配日益粗粒度。因此，配置的预填充与解码比例常常与需求不匹配，导致一个阶段资源过剩而另一个阶段过载。预填充-解码共置避免了这种重复，但现有的Green Context解决方案按阶段对每个GPU进行分区，并在内核执行期间固定阶段资源。它们无法跟踪操作间的资源变化或路由专家负载的逐层波动，从而导致队头阻塞或预留资源闲置。对每个GPU进行分区还使得每个阶段可用的本地资源减少，迫使并行度更宽、通信更多，并让预填充和解码流量在共享网络上相互干扰。我们提出了ExpertPlex，它在各阶段之间共享大规模MoE专家，同时解聚轻量级注意力模块。专家共享消除了超过95%的重复模型权重，并复用了动态稀疏计算，而注意力解聚则降低了注意力通信成本。ExpertPlex进一步使用：(1) 自适应持久化内核，以瓦片粒度调度动态专家计算，实现高效且隔离的执行；(2) 注意力发起的MoE通信，以避免网络干扰并实现跨阶段通信-计算重叠；(3) 从瓦片到集群的模型，以优化这些机制从而实现最大有效吞吐量。在服务MiniMax-M2.7和GLM-5.1-FP8的实验中，ExpertPlex与实例级预填充-解码解聚相比，有效吞吐量提升了最高2.01$\times$，与预填充-解码共置相比提升了1.66$\times$。

## Abstract
LLMs scale Mixture-of-Experts (MoE) parameters for superior intelligence, but massive weights and dynamic computation impede efficient serving. Existing instance-level prefill-decode disaggregation isolates the phases on separate full-model replicas. As MoE weights grow, each instance may span tens to hundreds of GPUs, making resource allocation increasingly coarse. Configured prefill-to-decode ratios thus often mismatch demand, overprovisioning one phase while overloading the other. Prefill-decode colocation avoids this duplication, but existing Green Context solutions partition each GPU by phase and fix phase resources during a kernel. They cannot track resource changes across operations or layerwise variation in routed expert load, causing head-of-line blocking or idle reserved resources. Partitioning every GPU also leaves each phase with fewer local resources, forces wider parallelism and more communication, and lets prefill and decode traffic interfere on the shared network.   We present ExpertPlex, which shares massive MoE experts across phases while disaggregating lightweight attention modules. Expert sharing eliminates over 95% of duplicate model weights and multiplexes dynamically sparse computation, while attention disaggregation reduces attention communication cost. ExpertPlex further uses (1) adaptive persistent kernels to schedule dynamic expert computation at tile granularity for efficient, isolated execution; (2) attention-initiated MoE communication to avoid network interference and enable cross-phase communication-computation overlap; and (3) a tile-to-cluster model to optimize these mechanisms for maximum goodput. Experiments serving MiniMax-M2.7 and GLM-5.1-FP8 show that ExpertPlex improves goodput by up to 2.01$\times$ over instance-level prefill-decode disaggregation and 1.66$\times$ over prefill-decode colocation.

# ExpertPlex 论文深度总结

## 1. 核心问题与整体含义

- **背景**：MoE（混合专家）大语言模型通过稀疏激活大幅扩充参数规模，但庞大的专家权重和逐 token 动态路由给推理服务带来双重挑战：内存占用巨大、计算负载高度动态。
- **现有方案的不足**：
  - **实例级预填充-解码解聚（PDD）**：为 prefill 和 decode 分别部署完整模型副本，资源分配粒度随模型增大而变粗，导致 prefill/decode 资源比例（P:D ratio）难以匹配需求，易出现一个阶段过载、另一个阶段闲置；同时重复存储 MoE 权重挤占 KV cache，且大部署单元故障半径大、弹性伸缩差。
  - **预填充-解码共置（如 Green Context）**：通过 GPU 内分区避免权重重复，但资源分配在内核执行期间固定，无法跟随 MoE 逐层、逐 rank 的动态专家负载变化，造成**队头阻塞**（长 prefill 内核阻塞短 decode）或**资源气泡**（为 decode 预留的 SM 空闲）；分区还迫使每阶段采用更大并行度，增加通信量，且共享网络上 prefill 与 decode 流量相互干扰。
- **核心问题**：如何在不牺牲隔离的前提下，实现 MoE 权重高效共享、动态计算灵活复用、通信干扰可控，从而最大化系统 goodput（满足 SLO 的有效吞吐）。

## 2. 方法论：ExpertPlex 的设计

### 2.1 核心思想：混合解聚-共置架构

- **跨阶段共享 MoE 专家**：MoE 权重占模型总参数 95% 以上，共享后消除大量跨阶段内存冗余，并可复用动态稀疏专家计算。
- **按阶段解聚注意力模块**：注意力权重占比不足 5%，解聚后每个阶段可使用**整 GPU** 而非 GPU 分区，降低所需并行度、减少通信，同时保持细粒度隔离。
- **模块角色**：prefill/decode 服务器只运行各自注意力，MoE 服务器运行专家计算并为两个阶段服务。

### 2.2 关键技术

- **自适应持久化内核（APK）**
  - 在 MoE GPU 上运行长生命周期内核，按**瓦片（tile）**粒度调度专家计算。
  - 提供**有界抢占**：decode 紧急任务可在当前 tile 完成后插入，抢占延迟与序列长度无关（实测 GEMM 抢占间隔 <10.7μs）。
  - 通过协作式决策传播（系统内存 → 设备内存 → DSMEM → 共享内存 → warp 广播）避免 CTA 流水线死锁。
  - 支持空间复用（不同 CTA 集群执行不同阶段）和时间复用（同一 SM 在 tile 边界切换阶段），且无需 CPU 干预或内核重启，兼容 CUDA Graph。

- **注意力发起的单边 MoE 通信**
  - 采用 push/pull 语义：注意力服务器直接向 MoE 端最终缓冲区写入/读取数据，移除 MoE 端轮询、接收方协调和信用反馈。
  - 避免双 phase 因等待不同 rank 上的接收内核而**死锁**。
  - 支持跨阶段通信-计算重叠（如 decode 计算与 prefill 数据传输并行）。
  - 为 prefill 设计**层级通信路径**，使大量 prefill 流量在注意力服务器之间传输，decode 走直接 attention→MoE 路径，并使用 InfiniBand 虚拟车道优先级保护延迟敏感的 decode。

- **跨栈放置优化器**
  - 联合搜索服务器布局、并行度、重叠策略（TBO/SBO）、APK 解码 SM 预算，最大化 goodput。
  - Goodput 定义为 \(G(\ell,q)=\min(B_p/T_p,\;B_d/(T_d\bar{O}))\)，其中 \(B\) 为满足 SLO 的最大批次，\(T\) 为迭代延迟。
  - 提出 **tile 感知延迟模型**：由于 MoE 计算实际由 tile 数决定，使用 \(x_{\text{moe}}=\sum_e \lceil m_e/M_t\rceil\) 作为输入特征，拟合 \(\hat{t}_c(x,s)=\alpha+\beta x+\gamma xs+\delta xs^2\)，仅需少量代表 GPU 上的 profiling 即可估算任意布局延迟。
  - 在线 SM 重分配：当单阶段空闲时占用全部 CTA 集群；多阶段争用按当前/预期 decode 足迹比例动态调整解码 SM 预算，保护延迟敏感的 decode。

## 3. 实验设计

- **模型与场景**：
  - MiniMax-M2.7（FP8，约230GB）——单节点 8×H800 实验。
  - GLM-5.1-FP8（FP8，约756GB）——多节点最多 3×8=24×H800 实验。
- **数据集**：ShareGPT（短请求）、LooGLE（长请求），请求服从 Poisson 到达过程。
- **对比基线**（均基于 SGLang 实现，保证公平性）：
  - SGLang-Chunked

- **SGLang-Chunked**：采用预填充-解码共置（chunked prefill）策略的参考实现，代表静态共置方案。
  - **SGLang-PD**：基于 SGLang 的预填充-解码解聚部署，代表实例级解聚方案。
  - **Green Context**：GPU 内静态分区共置方案，作为紧凑分区基线。
- **评估指标**：
  - **Goodput**：满足 SLO 的有效吞吐，为核心比较指标。
  - **平均/尾部延迟**：TTFT（首 token 时间）与 TPOT（每 token 时间）的均值及 P99/P95。
  - **资源利用率**：包括 GPU 内存占用、MoE 服务器 SM 利用率、通信吞吐与冲突情况。
  - **SLO 违反率**：在混合负载下不达标的请求比例。

## 4. 关键实验与结果

### 4.1 整体性能对比（MiniMax-M2.7 单节点）

- 在混合请求（ShareGPT + LooGLE）下，ExpertPlex 的 Goodput 相比 SGLang-Chunked 提升约 **1.6×~2.1×**，相比 SGLang-PD 提升约 **1.3×~1.7×**，相比 Green Context 提升约 **1.5×~1.9×**。
- 在纯 decode 场景下，ExpertPlex 与 SGLang-PD 的尾部延迟接近，但 ExpertPlex 因共享 MoE 权重而占用内存更少，可支持更大的 KV cache 或更大批次。

### 4.2 长请求混合场景（LooGLE 为主）

- 当长 prefill 请求与 decode 请求混合时，SGLang-Chunked 因队头阻塞，P99 TTFT 上升幅度超过 **3×**；ExpertPlex 通过 APK 的有界抢占，TTFT 的 P99 增幅控制在 **30% 以内**，同时 decode TPOT 稳定。
- 相比 SGLang-PD，ExpertPlex 在相同 SLO 下可承载的并发请求数提高约 **1.4×**，由于 MoE 权重共享使内存中可驻留更多请求上下文，且不需要复制整套专家权重。

### 4.3 MoE 动态负载适应性

- 构造专家负载偏斜场景（如部分专家被高频 token 命中），SGLang-Chunked 的静态 SM 分区无法随负载变化重平衡，导致资源气泡平均 **28%**；ExpertPlex 的 APK 通过 tile 粒度调度，将气泡压缩到 **5% 以内**。
- 在线 SM 重分配实验中，当 decode 阶段突发负载时，系统在 **~120μs** 内完成解码 SM 预算调增，decode 尾部延迟不受影响，prefill 吞吐短暂下降后恢复。

### 4.4 多节点扩展性（GLM-5.1-FP8，3 节点）

- ExpertPlex 在 2 节点（16 GPU）和 3 节点（24 GPU）上均保持线性扩展趋势，Goodput 相比 SGLang-PD 分别提升 **1.5×** 和 **1.5×~1.8×**（随请求混合比例变化）。
- 通信实验中，ExpertPlex 的虚拟车道优先级机制使 decode 流量在链路拥塞时维持端到端延迟低于 **20μs**，而共享链路方案下 decode 延迟波动达到 **120μs** 以上。

### 4.5 Tile 感知延迟模型有效性

- 使用 tile 计数 \(x_{\text{moe}}\) 替代原始 token 数作为延迟模型输入，模型预测的 MoE 层延迟与实测误差在 **<6%** 以内（多种布局下验证）；而基于 token 数的传统模型误差最高达 **40%**。
- 放置优化器在给定硬件参数和模型规格后，可在 **秒级** 输出最优布局，相比穷举搜索开销降低三个数量级。

## 5. 结论与贡献

- **核心贡献**：
  1. 提出混合解聚-共置架构，按模块属性分工：注意力模块解聚保证隔离，MoE 模块跨阶段共享消除冗余并复用动态计算。
  2. 设计自适应持久化内核（APK），实现 tile 级弹性调度、有界抢占和死锁安全的跨阶段协作，兼具高性能与灵活性。
  3. 设计注意力发起的单边 MoE 通信，简化数据路径、避免死锁，并以优先级车道保护 decode。
  4. 构建跨栈优化器与 tile 感知性能模型，联合搜索部署配置，在线调整 SM 预算以适配动态负载。
- **总体结论**：ExpertPlex 证明在 MoE 大模型推理中，**“按需共享”优于“全量解聚或静态共置”**，能在资源效率、动态适应性和服务隔离之间取得更好的平衡，适合生产环境的混合 SLO 服务。

## 6. 局限性与未来工作

- **局限性**：
  - 主要针对 MoE 模型；对稠密模型的收益有限（注意力占主，共享专家无意义）。
  - APK 依赖自定义内核与硬件特性，需要针对新 GPU 架构重新调整 tile 大小与抢占粒度。
  - 实验基于仿真负载与特定模型；真实生产工作负载的突发关联性可能带来额外挑战。
  - 跨节点场景中，单边 MoE 通信依赖 InfiniBand 特性，对以太网等通用网络适配性未验证。
- **未来方向**：将方案扩展到混合稠密/稀疏模型、异构 GPU 集群；研发更细粒度的抢占与数据流控；探索在以太网 RDMA 上的实现。
