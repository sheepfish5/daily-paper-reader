## 摘要
通过强化学习（RL）对大型语言模型（LLM）进行后训练已显著提升了代码生成能力。为绕过评论网络的重内存占用，当前最先进的框架采用无评论者范式，如基于规则验证沙箱的组相对策略优化（GRPO）。然而，将这些框架应用于底层系统编程（如CUDA内核生成）时面临严峻挑战：二元通过/失败奖励导致严重的信号稀疏性，而多轮环境反馈循环则遭受高昂的编译延迟和跨轨迹奖励稀释。在本工作中，我们提出LEAP（基于自适应剪枝的轻量环境反馈），一种可扩展且计算高效的多轮RL框架，专门针对底层硬件加速器对齐进行优化。LEAP引入了难度条件剪枝（DCP），一种动态门控机制，能够自适应地从多轮扩展中截断简单及过度灾难性任务，将资源密集的编译和硬件探索仅集中于高价值、复杂任务。为在不进行手动超参数工程的情况下充分操作这些路径，我们提出一种基于排名的奖励公式。通过在GRPO rollout组内从成对锦标赛结果中推导无尺度的相对优势，我们的方法内在惩罚简单提示上的令牌低效性，同时最大化困难分布上的学习梯度。实证评估表明，LEAP在首轮熟练度和稳健的多轮调试韧性方面表现优异，同时比未剪枝的多轮基线收敛更快，为底层代码RL建立了一种实用范式。

## Abstract
Post-training large language models (LLMs) via reinforcement learning (RL) has significantly advanced code generation capabilities. To bypass the heavy memory footprint of critic networks, current state-of-the-art frameworks leverage critic-free paradigms like Group Relative Policy Optimization (GRPO) tied to rule-based verification sandboxes. However, applying these frameworks to low-level systems programming, such as CUDA kernel generation-presents severe challenges: binary pass/fail rewards introduce severe signal sparsity, while multi-turn environmental feedback loops suffer from prohibitive compilation latencies and reward dilution across trajectories. In this work, we introduce LEAP (Lean Environment-Feedback via Adaptive Pruning), a scalable and computationally efficient multi-turn RL framework optimized for low-level hardware accelerator alignment. LEAP features Difficulty-Conditioned Pruning (DCP), a dynamic gating mechanism that adaptively cuts off simple and overly catastrophic tasks from multi-turn expansion, focusing resource-heavy compilation and hardware exploration exclusively on high-value, complex tasks. To fully operationalize these paths without manual hyperparameter engineering, we propose a Rank-Based Reward formulation. By deriving scale-free relative advantages from pairwise tournament outcomes within the GRPO rollout group, our method inherently penalizes token inefficiency on simple prompts while maximizing learning gradients on challenging distributions. Empirical evaluations show that LEAP achieves superior first-turn proficiency and robust multi-turn debugging resilience while converging faster than unpruned multi-turn baselines, establishing a practical paradigm for low-level code RL.

## 1. 核心问题与整体含义

- **研究动机**：大型语言模型在代码生成任务上的后训练高度依赖强化学习。以 GRPO 为代表的无评论家方法虽然避免了 PPO 的 critic 内存开销，但其“二元通过/失败奖励”在低层系统编程任务（尤其是从零生成 CUDA 内核）中会造成严重的奖励稀疏性；同时多轮环境反馈虽能模拟人类调试过程，却面临编译/执行延迟极高、以及“最终奖励跨轨迹传播导致奖励稀释”两大问题。
- **整体含义**：现有代码 RL 框架多面向 Python 等轻量解释型语言，验证速度快，但无法直接迁移到 CUDA 内核生成这类真实生产级、需要硬件编译与执行的场景。LEAP 试图在保持多轮调试能力的同时，大幅降低训练开销，并缓解简单任务上“过度依赖多轮修正”的退化现象。

## 2. 方法论

LEAP 基于标准 GRPO 框架，核心改动集中在两个模块：**难度条件剪枝（DCP）** 与 **基于排名的奖励函数**，并辅以**按轮次折扣的优势分配**。

- **难度条件剪枝（DCP）**
  - 核心思想：简单任务本身已有充足成功轨迹、信号稠密；困难任务信号稀疏，需要多轮调试；而过于困难的任务当前模型几乎无法解决，多轮探索只会浪费资源。
  - 实现方式：对一个 prompt 采样 G 条 rollouts，统计失败条数 `Nfail(q)`。当 `τmin ≤ Nfail(q) ≤ τmax` 时，该组进入多轮调试；否则跳过多轮，只做单轮优化。
  - 效果：简单问题被迫学习单轮直接正确，避免依赖多轮修正；极端困难问题不进入高成本调试环路；只有中等难度、有恢复价值的任务才消耗编译与硬件验证资源。
- **基于排名的奖励（Rank-Based Reward）**
  - 取代人工设定“魔法数字”的 scalar 奖励。将同组 rollouts 按“首次通过 > 第二轮通过 > … > 最终失败”排序，赋离散等级：第 m 轮成功为 `M−m+1`，最终失败为 0。
  - 通过两两锦标赛计算每个 rollout 的相对优势：`R_i = (N_worse − N_better) / (G−1)`，结果落在 [−1, 1]。
  - 自适应特性：当问题简单、组内首次通过者多时，第二轮成功会被自动惩罚（促使模型追求首轮效率）；当问题困难、失败者占多数时，第二轮成功会被自动奖励（保留调试学习的梯度信号），从而避免手工调参和梯度塌缩。
- **折扣化的按轮优势分配**
  - 对正优势轨迹，早期轮次的优势按折扣因子衰减，越接近最终成功的轮次获得越高权重；负优势轨迹则对所有生成轮次等权施加惩罚。
  - 这样既保留轨迹级偏好信号，又避免奖励在跨轮次传播中被稀释。

## 6. 主要结论与发现

- LEAP 在 KernelBench 上取得最高首轮准确率（Overall Turn 1：70%，高于 Baseline 66%、MURPHY 67.6%、Dr.Kernel 68.4%），第三轮准确率 80.8%，与 Dr.Kernel 80.4% 相当并略高。
- LEAP 训练更高效：单步时间约 700s，明显低于 MURPHY 和 Dr.Kernel 的约 950s；收敛到同等精度快约 1.93 倍；Turn Per Pass 最低（1.77），说明每个成功样本平均消耗轮数最少。
- DCP 消融显示：仅让中等/偏难任务进入多轮调试（≥50% 剪枝设置）效果最好，最终精度 80.8%，优于“全量多轮”配置（80.4%）和“只剪枝难题”配置（77.6%），验证了“简单任务单轮信号已够、困难任务多轮回报有限”的核心假设。
- 基于排名的奖励相比静态 scalar 奖励（GRPO-MT），在各难度层级上均有提升，尤其 Level 3 第 1 轮从 26% 提升到 30%，说明动态基线能更好平衡首轮效率与多轮调试能力。
- 训练过程观察表明：LEAP 相比 GRPO-MT，能将有效学习信号更均衡地分配到不同难度样本上，避免简单样本占据过多梯度。

## 7. 优点

- **结构合理**：将“多轮调试”从无差别全量展开改为按难度自适应门控，既保留复杂任务所需的密集调试信号，又避免简单任务上的冗余编译和计算浪费。
- **奖励设计简洁且自适应性**：基于组内相对排序而非绝对标量，避免手工搜索奖励系数，且理论上具备“简单任务惩罚多轮、困难任务奖励多轮”的自动调节机制。
- **工程可行性高**：在真实 CUDA 编译/执行环境下提出可落地的多轮 RL 方案，对比 MURPHY 需要树搜索的昂贵方案，LEAP 更贴近生产实践。
- **综合评估较全面**：同时报告精度、训练时间、轮次效率、消融分析和训练过程组成，论证维度较丰富。
