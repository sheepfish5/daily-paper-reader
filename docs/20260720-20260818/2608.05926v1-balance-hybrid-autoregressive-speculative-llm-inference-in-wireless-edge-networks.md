## 摘要
边缘推理是一种有前景的范式，可在下一代移动网络中提供大语言模型（LLM）推理服务。LLM推理主要依赖两种方法：自回归解码（AD）顺序生成输出令牌，导致长延迟；推测解码（SD）通过使用小语言模型（SLM）生成多个草稿令牌供LLM验证来加速推理，但会产生额外的内存成本。由于这种延迟-内存权衡，在有限的边缘计算资源下，单独采用任何一种方法都无法高效服务具有异构需求的用户。为了解决这一挑战，我们提出了一种用于边缘LLM推理的混合自回归-推测式推理（BALANCE）框架。在BALANCE中，边缘服务器同时托管SLM和LLM，将每个用户分配到AD或SD，并同时执行这两种模式。为了最大化服务的用户数量，我们构建了一个任务吞吐量最大化问题，以在用户延迟要求和服务器内存约束下，联合确定用户调度以及AD和SD之间的计算资源分配。由于该问题是NP-hard的，我们开发了一种多项式时间算法，将原始问题转化为两个子问题，并获得具有常数近似保证的次优解。实验表明，BALANCE始终优于传统的AD和SD，并显著提高了任务吞吐量。

## Abstract
Edge inference is a promising paradigm to provide large language model (LLM) inference services in next-generation mobile networks. LLM inference mainly relies on two approaches: Autoregressive decoding (AD) generates output tokens sequentially, resulting in long latency; Speculative decoding (SD) accelerates inference by using a small language model (SLM) to generate multiple draft tokens for LLM verification, but incurs extra memory costs. Due to this latency-memory tradeoff, neither approach alone can efficiently serve users with heterogeneous demands under limited edge computing resources. To address this challenge, we propose a hybrid autoregressive-speculative inference (BALANCE) framework for edge LLM inference. In BALANCE, an edge server hosts both an SLM and an LLM, assigns each user to AD or SD, and performs the two modes simultaneously. To maximize the number of served users, we formulate a task throughput maximization problem to jointly determine user scheduling and computing resource allocation between AD and SD under user latency requirements and server memory constraints. Since the problem is NP-hard, we develop a polynomial-time algorithm that transforms the original problem into two sub-problems and obtains a sub-optimal solution with a constant approximation guarantee. Experiments demonstrate that BALANCE consistently outperforms conventional AD and SD and significantly improves task throughput.

## 1. 核心问题与整体含义

**研究动机**：边缘推理是下一代移动网络中提供大语言模型服务的关键范式。LLM推理主要依赖两种方法：

- **自回归解码（AD）**：逐token顺序生成输出，延迟高，但内存开销相对低。
- **推测解码（SD）**：先用小语言模型（SLM）生成草稿 token，再由 LLM 并行验证，可显著降低延迟，但需要同时加载 SLM 和 LLM，引入额外内存开销。

**核心矛盾**：上述两种方式形成“延迟-内存”权衡——AD 内存友好但延迟大，SD 延迟低但内存开销高。在资源受限的边缘服务器上，单独使用任一方式都无法高效服务具有异构延迟需求和计算偏好的多个用户。实验数据显示，SD 相比 AD 可降低 39.1% 的端到端延迟，但 GPU 内存消耗增加 18.3%，这一权衡亟需系统级优化。

**研究目标**：设计一种混合推理框架，让边缘服务器同时支持 AD 和 SD 两种模式，通过联合优化用户调度与资源分配，在满足用户延迟需求和服务器内存约束的前提下，最大化服务用户数量（任务吞吐量）。

## 2. 提出的方法论

### 2.1 核心思想：BALANCE 框架

边缘服务器同时托管一个 LLM（Llama-2-7B）和一个 SLM（TinyLlama-1.1B），将用户分配到 AD 或 SD 模式，两种模式并行执行、互不干扰。同一模式的用户采用批处理（batching）方式进行推理，以提高吞吐量。

### 2.2 系统建模

论文构建了完整的系统模型，包括：

- **通信模型**：正交频分多址（OFDMA），考虑上行输入上传时间和下行输出下载时间，延迟与输入输出 token 长度、带宽及频谱效率相关。
- **计算模型**：基于 Transformer 架构，对 QKV 投影、多头注意力计算、输出投影和前馈网络等矩阵乘法操作进行细粒度的工作负载建模。分别定义 AD 模式的 LLM 预填充和逐解码步工作量，以及 SD 模式的 LLM/SLM 预填充、SLM 草稿生成和 LLM 并行验证工作量。
- **内存模型**：考虑了模型权重存储和 KV 缓存的峰值内存消耗，涵盖 LLM、SLM、AD 模式和 SD 模式各自的 KV cache 需求。

### 2.3 问题建模（P1）

以最大化服务用户数为目标，联合优化：
- AD 模式用户调度变量 \(x_k\)
- SD 模式用户调度变量 \(y_k\)
- GPU 计算资源分配比例 \(z\)（AD 获得 \(z\)，SD 获得 \(1-z\)）

约束条件包括：每用户至多分配一种模式、端到端延迟上限 \(T_k\)、GPU 总内存容量上限 \(Q\)。该问题被证明是 **NP-hard**。

### 2.4 算法设计（核心贡献）

**问题转化与分解**（P1 → P2 → P3）：

1. **引入内存分配变量 λ**：将总内存约束解耦为 AD 和 SD 各自的独立内存约束，使 P1 等价转化为 P2。
2. **固定 (z, λ)**：将 P2 简化为 P3——在给定计算和内存分配下，仅做用户调度决策。
3. **分解两个子问题**（P3.1 和 P3.2）：
   - **P3.1（AD 子问题）**：通过枚举最大输入长度、最大输出长度、延迟预算和上传时间，筛选候选用户，按延迟贡献排序后贪心选取，由 Algorithm 1 求解。
   - **P3.2（SD 子问题）**：类似思路，但额外考虑预期接受率 \(A_k\) 换算的 SD 迭代次数，用户按延迟贡献排序同时保持内存消耗单调性，由 Algorithm 2 求解。

**整体算法（Algorithm 3）**：枚举所有可行的 \((z, \lambda)\) 组合，分别调用 Algorithm 1 和 Algorithm 2 求解 AD 和 SD 的用户调度，选取总服务用户数最多的解。

**理论保证**：
- Algorithm 3 提供 **1/2 常数近似保证**（即所得解的服务用户数 ≥ 最优解的 1/2）；
- 时间复杂度为 \(O(K^6 \log K)\)，具有多项式级复杂度。

## 7. 优点

- **问题洞察清晰**：识别并形式化了 AD 与 SD 之间的延迟-内存权衡，提出了统一的混合框架，而不是简单二选一。
- **系统建模细致**：对两种模式的通信、计算、内存、延迟进行了完整的数学建模，工作负载分析具体到 Transformer 的矩阵乘法层粒度，具有较强的工程参考价值。
- **理论保障完备**：不仅证明 NP-hard，还提供常数近似保证（1/2 近似比）和多项式复杂度（\(O(K^6 \log K)\)）分析，为实际部署提供了性能底线。
- **算法设计巧妙**：通过引入辅助变量 λ 将复杂约束解耦，再分解为两个可独立求解的子问题，利用单位利润和排序贪心策略，在复杂度可控的前提下达到近似最优。
- **实验验证充分**：与最优解（穷举搜索）对比，验证了近似算法的实际性能损失极小；消融实验有效拆分了各设计模块的贡献。
- **适用性广**：BALANCE 可退化到单模式（AD-only 或 SD-only），因此对资源量不同的边缘服务器均有适用性。

## 8. 不足与局限

- **场景假设较理想化**：假设用户能精确上报输入/输出长度，实际系统中需依赖预测模型，预测误差未被考虑；用户数量规模有限，最大 70 个用户对真实大规模边缘场景可能不够。
- **计算资源分配粒度受限**：假设 z 只能取离散值，虽然便于实现，但与连续最优之间可能存在性能差距。
- **内存建模简化**：仅考虑权重和 KV cache，未考虑推理过程中的激活值（activation）内存、临时缓冲区、框架开销等。
- **实验验证的局限**：
  - 仅在单 GPU（RTX 4090）上部署，未验证多 GPU 或不同显存配置下的可扩展性；
  - 未使用真实 LLM 应用数据集（如对话、代码生成等），所有参数为合成生成；
  - SD 的草稿长度固定为 1，未探讨自适应草稿长度对系统性能的影响。

- **未考虑动态性**：假设用户延迟要求和任务长度静态已知，未处理用户动态到达/离开的场景；SD 接受率假设在一个范围内，但未建模其与输入内容、模型能力的相关性。
