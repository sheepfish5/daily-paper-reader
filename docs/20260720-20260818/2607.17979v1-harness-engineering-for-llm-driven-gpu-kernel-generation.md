## 摘要
大语言模型（LLMs）可以辅助GPU内核生成，但其实际效果取决于生成的代码能否被可靠地约束、验证、性能分析和选择。本文介绍了在NVIDIA Blackwell B200 GPU上举行的MLSys 2026 FlashInfer AI内核生成竞赛中，一个以测试框架为中心的LLM驱动GPU内核优化系统。该系统将评估测试框架与基于性能分析的优化控制器分离：测试框架负责编译、正确性、符合官方标准的计时和产物存档，而控制器则将性能分析器和工作负载证据转化为有界候选生成决策。人工编写的技能捕获操作符约束、参考资料、性能分析流程和提升规则，而Codex和Claude Code代理在这些约束内生成候选内核。在五个操作符定义中，保留的官方对齐工件相对于提供的FlashInfer基线实现了1.62倍、18.05倍、29.68倍、1.12倍和13.70倍的平均延迟加速。在评估的定义中，代理辅助内核优于全代理工件，表明专家提供的优化方向、高质量参考资料和工作负载上下文对于可靠的AI驱动内核优化仍然至关重要。

## Abstract
Large language models (LLMs) can assist GPU kernel generation, but their practical effectiveness depends on whether generated code can be reliably constrained, validated, profiled, and selected. This paper presents a harness-centered system for LLM-driven GPU kernel optimization in the MLSys 2026 FlashInfer AI Kernel Generation Contest on NVIDIA Blackwell B200 GPUs. The system separates an evaluation harness from a profile-backed optimization controller: the harness enforces compilation, correctness, official-aligned timing, and artifact archival, while the controller turns profiler and workload evidence into bounded candidate-generation decisions. Human-authored skills capture operator constraints, references, profiling procedures, and promotion rules, while Codex and Claude Code agents generate candidate kernels inside those constraints. Across five operator definitions, the retained official-aligned artifacts achieved mean-latency speedups over supplied FlashInfer baselines of 1.62x, 18.05x, 29.68x, 1.12x, and 13.70x. The Agent-Assisted kernels outperform the Full-Agent artifacts across the evaluated definitions, indicating that expert-provided optimization directions, high-quality references, and workload context remain critical for reliable AI-driven kernel optimization.

## 1. 核心问题与整体含义

- **研究背景**：随着 LLM 推理系统对专用算子的依赖日益加深（如 MoE 路由、稀疏注意力、top-k 索引构造、门控循环状态更新等），GPU 内核的生成与优化成为影响端到端性能的关键。LLM 编程代理（如 Codex、Claude Code）能在一定程度上自动生成内核代码，但存在两大瓶颈：
  - **不可靠**：生成的代码容易在编译、数值正确性、工程打包、延迟稳定性等方面失败；
  - **缺乏系统性约束**：仅靠提示词（prompt）驱动的一次性尝试，难以形成可持续、可复现、可验证的优化闭环。
- **核心主张**：LLM 驱动内核优化的有效性，不取决于模型本身，而取决于 **harness engineering（测试框架工程）** ——即人类如何设计约束、反馈回路、验证机制和择优规则。该文将评估 harness 与优化控制器分离，形成“编译→正确性→profiling→全量扫描→择优归档”的闭环，从而把 LLM 搜索转化为可审计、可衡量的系统工程。
- **整体含义**：提出一种可迁移的智能体辅助内核优化范式。在该范式中，人类负责定义目标、资源、反馈回路和审核规则，而 LLM 代理在既定边界内做有界的实现搜索。这一范式在 MLSys 2026 FlashInfer AI Kernel Generation Contest（NVIDIA Blackwell B200 GPU）的五个算子定义上得到验证，相对 FlashInfer 基线实现 1.12×–29.68× 的平均延迟加速。

## 2. 方法论

### 2.1 总体架构：评估 harness 与优化控制器分离

- **评估 harness（Evaluation Harness）** 负责测量层职能：
  - 打包候选代码；
  - 在目标容器中进行预编译与正式编译；
  - 执行正确性检查；
  - 按照官方对齐协议测量 B200 延迟（CUDA 13.2、PyTorch 2.12、Triton 3.6、cupti-python 计时、隔离运行）；
  - 归档 benchmark JSON、profiler 摘要、运行日志等工件。
- **优化控制器（Optimization Controller）** 负责决策层职能：
  - 将 Torch Profiler/NCU 证据转化为瓶颈状态；
  - 匹配历史状态，选择本轮唯一优化假设；
  - 生成有界候选；
  - 监督平台期（plateau）、回退（regression）和循环；
  - 记录并更新轨迹记忆（trajectory memory），避免重复探索失败路线。

### 2.2 三层 Skill 体系（可复用的执行手册）

| Skill 层 | 作用 |
|---|---|
| **通用 CUDA 内核优化技能** | 定义 Model/ModelNew 契约、正确性与性能评估、NCU/NSYS 性能分析、两阶段搜索（先探索后利用）、可复用候选导出 |

| **统一 CUDA 优化控制器** | 状态提取→状态匹配→单方向优化选择→候选生成→轨迹监督→知识库更新→基于 manifest 的断点续跑 |

### 2.3 核心算法流程（Algorithm 1：Agent-Assisted Harness Loop）

1. 初始化记忆（定义 D、工作负载 W、语言 L、硬件 H、FlashInfer 基线 B），当前解 Sol₀ ← 基线；
2. 每轮循环：
   - 控制器提取当前状态 sᵢ；
   - 代理生成候选集合 Cᵢ；
   - 对每个候选执行**代表性门控（RepGate）**，通过者记录 profiler 摘要；
   - 从通过候选中选择最佳，执行**全量扫描（FullSweep）**；
   - 仅在满足择优门控（全分布延迟改善且无正确性回退）时提升为新的 Sol；
   - 更新记忆 M；若出现平台期，由人类介入调整方向；
3. 返回全部候选中的最佳正确解及完整工件档案。

### 2.4 关键设计理念

- **工作量驱动的形状调度（Workload-Grounded Shape Dispatch）**：从竞赛工作负载 UUID、JSON 形状轴和实测延迟分布中归纳优化区间，仅在 profile 与延迟证据明确指向不同瓶颈时才引入形状专属路径。
- **抗噪声的择优策略（Noise-Resistant Promotion）**：候选提升必须依据全部工作负载的延迟证据、配对基线、正确性通过率与必要的重复验证，而禁止依据单点加速即做全局推广。
- **硬件感知的语言选择**：Triton 用于快速原型与分组 GEMM；CUDA C++ 用于共享内存、launch 属性和底层指令控制；CuTe/CUTLASS 用于 Blackwell 张量核心显式布局（如 DSA top-k、GDN prefill 的 chunked 内核）。
- **人类引导的平台期恢复（Human-Guided Plateau Recovery）**：代理无法继续提升时，人类通过切换 GPT/Claude 模型族、请求子代理互审、补充参考内核或文档、更换实现语言等方式重新引导搜索。

## 7. 优点

1. **视角新颖且系统性强**：将“harness engineering”作为独立研究对象，把测量与决策解耦，形成闭环工程框架，而不仅是 prompt 技巧或模型能力分析。
2. **工程可复现性高**：代码、技能模板、harness 和归档工件全部开源（GitHub），提供脚本化的 SKILL.md 式控制协议，非一次性实验代码。
3. **多证据维度的实验支撑**：正确性、延迟、profiling（NCU/Torch Profiler）、消融、轨迹分析、高试次重放等多层证据互相印证。
4. **诚实披露失败模式**：DSA top-k 的 trial-budget 数值问题被单独剖析，给出概率模型（P_detect = 1−(1−p)^n）、边界条件（γ(s) > 2ϵ）和保守 fallback 方案，在学术诚信方面表现出色。
5. **对比设计清晰**：Full-Agent 在同一官方协议下的最终评估提供了明确对比基线，避免“自吹自擂”。
6. **实践洞察丰富**：从语言选择（Triton/CUDA/CuTe）到分派策略，再到注册压力与 waves/SM 的细粒度分析，对真实 GPU 优化有直接的指导意义。

## 8. 不足与局限

1. **外部有效性有限**：实验仅限 FlashInfer 竞赛的五类算子，无法推广到更广泛的 GPU 内核生态；加速比也仅适用于该竞赛的工作负载分布。
2. **未披露算力总预算**：缺少 GPU 数量、机时、总能耗等关键成本数据，难以评估该方法的实际经济可行性。
3. **人力依赖未量化**：论文承认人类设计 harness、选择参考、调整策略和最终择优是核心贡献，但未量化每算子所需人工时数，使其“可复制性”打折。
4. **结果非官方 leaderboard 分数**：仅为本地的“官方对齐”测量，竞赛侧验证（尤其 DSA top-k）已显示可能的偏差，最终分数可能存在出入。
5. **低试次验证存在漏检风险**：默认 3 次 trial 的验证策略虽有利于迭代速度，但可能漏掉稀有的 top-k 边界错误；论文已通过附录 E 的模型与重放证据说明此点。
6. **Full-Agent 对比的公平性受到限制**：Full-Agent 轨迹显示部分算子在相对较少的迭代（如 GDN Decode 仅 10 轮）后就结束，且 trace-local 与 FI-relative 的最优点不一致，存在预算/搜索方向配置不够公平的可能。
7. **缺乏多随机种子/多轮重复的统计报告**：每算子的延迟统计未给出跨运行的标准差或置信区间，不利于判断差异的显著性。
