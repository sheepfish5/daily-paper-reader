## 摘要
大型语言模型（LLM）推理服务日益受到内存而非计算的限制。随着长上下文和长形式推理工作负载变得越来越普遍，键值（KV）缓存在LLM令牌生成（即解码）期间主导了内存占用和内存流量。特别是，HBM容量已成为稀缺且昂贵的资源，严重限制了推理批处理大小和系统吞吐量。本文提出了OasisKV，一种以内存为中心的LLM推理系统设计，通过在LLM解码期间将完整KV缓存存储与HBM解耦，缓解了HBM容量压力。由于解码时的注意力天然稀疏，OasisKV仅在HBM中保留最相关令牌的KV条目用于注意力计算。我们观察到，使用推测解码（SD）起草的前瞻令牌可以提前准确预测未来的重要令牌。OasisKV采用高效的注意力后台流水线来识别重要的KV块。然后在下一步解码使用之前，从更高容量的内存层级（例如主机或远程内存）预取这些块，并将其暂存到HBM中。我们基于vLLM实现了OasisKV。在2048令牌的KV预算下，前瞻预测足够准确，可将精度保持在完全注意力的0.7个点以内。这使得OasisKV能够将稀疏性转化为吞吐量收益：在推理工作负载上，相对于密集vLLM，加速1.69倍，精度损失0.1个点；在多GPU长上下文服务中，加速可达2.1倍。在预填充-解码分离下，OasisKV实现了约2倍的密集吞吐量，同时每个请求的KV量减少6.5-9.7倍，并且与完全KV传输相比，解码节点主机内存减少2.2-2.6倍。

## Abstract
Large language model (LLM) inference serving is increasingly constrained by memory rather than compute. As long-context and long-form reasoning workloads become more prevalent, the key-value (KV) cache dominates both memory footprint and memory traffic during LLM token generation, i.e., decode. In particular, HBM capacity has become a scarce and costly resource that heavily limits inference batch size and system throughput. This paper presents OasisKV, a memory-centric LLM inference system design that alleviates HBM capacity pressure by decoupling full KV-cache storage from HBM during LLM decoding. Because decode-time attention is naturally sparse, OasisKV keeps only the KV entries of the most relevant tokens in HBMs for attention computation. We observe that future important tokens can be predicted accurately in advance using lookahead tokens drafted by speculative decoding (SD). OasisKV employs an efficient attention background pipeline to identify important KV blocks. They are then prefetched from higher-capacity memory tiers (e.g., host or remote memory) and staged in HBMs before being used in the next decode step.   We implement OasisKV based on vLLM. The lookahead prediction is accurate enough to keep accuracy within 0.7 points of full attention under a 2,048-token KV budget. This lets OasisKV turn sparsity into throughput gain: $1.69\times$ over dense vLLM on the reasoning workload at 0.1 points of accuracy loss, and up to $2.1\times$ on multi-GPU long-context serving. Under prefill--decode disaggregation, OasisKV reaches about $2\times$ dense throughput while admitting each request with $6.5$--$9.7\times$ less KV and holding $2.2$-$2.6$ less decode-node host memory than full KV transfer.

## 1. 论文的核心问题与整体含义（研究动机与背景）

- **核心问题**：现代 LLM 推理已从“算力受限”转向“内存受限”。随着长上下文、Agent 式推理等负载的普及，KV 缓存（Key-Value Cache）在解码（decode）阶段同时主导了 GPU HBM 的容量占用和内存带宽消耗。HBM 容量有限且昂贵，直接限制了服务系统的批处理规模与吞吐量，成为“内存墙”瓶颈。
- **现有方案的不足**：
  - **稀疏注意力**（如 Quest、NSA）虽然可以减少 KV 读取量，但仍需在 HBM 中保留完整 KV 缓存，无法解决容量问题。
  - **KV 检索**（如 ShadowKV、InfiniGen）将完整 KV 放到主机内存，但按需获取 KV 会处于解码关键路径上，传输延迟直接影响 TPOT。
  - **KV 预取**（如 SpeCache、FreeKV）尝试用预测提前获取 KV，但已有预测器要么需要针对性训练（缺乏通用性），要么使用当前 token 的 query 作为代理信号，预测准确性不足，且缺少生产级跨层内存管理能力。
- **论文目标**：提出 OasisKV，将完整 KV 缓存从 HBM 解耦，在解码期间仅保留最相关 token 的 KV 块在 HBM 中，并通过“前瞻稀疏预取”（lookahead sparse prefetching）把未来需要的 KV 块提前从 CPU 内存或远程内存取回，从而在不显著损失精度的情况下大幅提升解码吞吐量，并支持多 GPU 与预填充-解码（PD）分离部署。

## 2. 方法论：核心思想、关键技术细节与流程

### 2.1 核心思想
- **利用投机解码（speculative decoding, SD）的 draft token 作为“前瞻信号”**：SD 已逐渐成为主流服务技术，其生成的未来 token 可以不经过额外训练就准确预测下一步注意力需要访问的 KV 块。
- **将“预取重叠”、“前瞻驱动的 KV 稀疏预测”和“稀疏-精度权衡”作为一个联合系统优化问题**：通过异步流水线让 KV 传输隐藏在解码计算之后，从而实现低延迟、大容量、低流量的 KV 管理。

### 2.2 关键技术细节

**（1）低开销的前瞻注意力（Look-ahead Attention）**
- 在单一前向传播中，同时计算当前 token 与 draft token 的 query，共享同一套 KV 工作集。
- Draft query 在稀疏 KV 上传播后，其预测的 top-K 块与真实下一 token query 的 top-K 集合有极高一致性（各层平均 98.74% 重合，逐层不低于 98.2%）。
- 为了对非驻留块进行全局排序，OasisKV 在 HBM 中保存“压缩 key”摘要（采用 Quest 风格，每个逻辑块只存坐标最小值和最大值），使得 draft query 可以快速扫描所有块并完成 top-K 排序，无需恢复完整 key。
- 压缩 key 缓存只占完整 KV 缓存大小的 1/16，容量和读取开销都很低。

**（2）完全异步的后台流水线**
- 流水线分为三个阶段：top-K 预测 → KV 选择 → KV 传输。每层独立，三个阶段可在不同 CUDA 流上并发执行。
- 各层间的任务相互独立，因此可以实现层间重叠；每层只在自己的 KV 传输完成后才被注意力消费，通过 CUDA event 进行层内同步。
- 稳定状态下流水线完成间隔为 `T_pipe = max(T_pred, T_select, T_transfer) ≤ Δ_prefetch`，即受最慢阶段限制。

**（3）Delta 选择与上限淘汰（Capped Eviction）**
- 通过比较预测集与当前驻留集，只传输缺失的块，避免重复流量。
- 对每个 KV head，每步最多允许 `C` 个新块从 CPU 传入 GPU，同时从驻留块中选择最久未被选中的块作为淘汰对象，形成“一进一出”的配对传输计划。
- 该策略将每步 PCIe 流量限制在固定预算内，防止传输延迟拖慢解码。

**（4）头级映射与 KV 管理**
- 在原有 GPU/CPU 页表之上增加一层“头级逻辑到逻辑映射”，使不同 KV head 可以拥有不同的稀疏块集合。
- 保持原始页表不变，更新时只需修改头级映射和 GPU 内容；在张量并行（TP）下，各 GPU 可以独立更新本地 KV head 的映射，无需跨 GPU 同步。
- 请求在上下文长度超过阈值后，从密集解码切换到稀疏解码，全量 KV 复制到 CPU 内存，GPU 保留历史选择块和局部窗口。

**（5）远程部分获取（Remote Partial Fetching, RPF）**
- 在 PD 分离场景下，解码节点只在请求准入时接收“部分 KV”：首步解码所需 KV 块、压缩 key 缓存和 draft token 的 KV 状态。
- 解码过程中，如果 top-K 选择漂移到解码节点内存中没有的块，则从预填充节点的 staging pool 通过 RDMA/网络读取，并聚合按层批量传输。
- 每个 KV 块最多跨网络传输一次，从未被选中的块永不传输，从而显著降低 TTFT 和解码节点主机内存占用。

## 6. 主要结论与发现

- OasisKV 可以显著缓解 HBM 容量限制：在 vLLM 基础上实现 1.69×（Qwen3-8B 推理负载）至 2.1×（合成负载）的吞吐提升，精度损失仅 0.1–0.7 点。
- 在多 GPU（TP8）长上下文服务中，吞吐提升最高 2.1×。
- 在 PD 分离场景下，吞吐约为密集方案的 2.1–2.3 倍，且每请求 KV 传输量减少 6.5–9.7 倍，解码节点主机内存占用减少 2.2–2.6 倍。
- 预测准确性高：draft query 预测的 top-K 块与真实下一 token top-K 块逐层一致率 98.2%–99%+，平均 98.74%。
- 跨层异步流水线有效隐藏预取开销，且上层淘汰策略将 PCIe 流量控制在合理范围：fetch cap 为 0.05 时，吞吐比 fetch-all 提高 2.5 倍，精度几乎不变。
- 远程部分获取能把网络流量从短时突发转变为均匀分布，降低峰值带宽要求，并显著减少解码节点内存压力。

## 7. 优点

- **利用现有投机解码产物，不引入额外训练**：将 SD 的 draft token 转化为精准的 KV 访问预测信号，通用性强。
- **系统设计一体化**：同时解决预测、预取、放置、调度四个层面的问题，而非仅做算法层面的稀疏注意力。
- **生产级集成**：在 vLLM 上实现，沿用原有页表和调度机制，通过头级映射实现稀疏工作集，无需破坏现有执行路径。
- **科学的带宽管理**：上限淘汰策略与异步流水线相结合，把“带宽预算”作为显式约束，避免传输成为解码关键路径。
- **PD 分离下的远程部分获取设计**：从网络传输与主机内存两个维度同时减少开销，具备实际部署价值。
- **实验全面**：覆盖不同模型规模（8B–235B）、不同任务（推理、长上下文、长输出）、不同部署形态（单机、多机、PD 分离），并充分考虑公平性（同栈对比）。

## 8. 不足与局限

- **部分对比不完整**：与 ShadowKV、InfiniGen、FreeKV 的性能对比中，许多配置因对方无法运行而缺失，影响结论的普适性。
- **框架差异带来的公平性疑问**：OasisKV 与 Quest/FreeKV 的精度对比虽然强调“同栈内比较”，但不同 serving 栈（HF vs vLLM）的绝对分数本来就不同，实际差异可能不完全来自稀疏算法本身。
- **依赖投机解码**：虽然 SD 日益流行，但若部署环境不支持 SD（如无合适 draft 模型或 MTP 头），OasisKV 的前瞻信号会失效。
- **未实现 prefix caching**：文中仅用解析模型估计 RPF 的 TTFT 收益，没有在真实系统中验证与 prefix cache 结合的效果。
- **忽略非典型注意力模式**：实验覆盖了数学推理、科学推理和长上下文理解，但未覆盖代码生成、Agent 工具调用等高度动态的注意力模式；在这些场景下 top-K 预测精度可能下降。
- **只使用 H100 平台**：未在 AMD、Habana 等非 NVIDIA 硬件上验证，UVA/RDMA 等实现可能依赖特定生态。
- **KV 块粒度固定**：论文使用 16-token 块和一个 top-K 预算，未探索不同块大小或动态预算对精度和性能的影响。
