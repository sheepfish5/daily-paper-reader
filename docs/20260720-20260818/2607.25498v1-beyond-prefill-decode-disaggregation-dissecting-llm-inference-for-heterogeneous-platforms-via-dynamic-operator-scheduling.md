## 摘要
预填充-解码分离（PD）和基于roofline的算子放置是跨异构系统划分大语言模型（LLM）推理的常见策略，但在实践中往往不够充分。端到端延迟还取决于工作负载形态、运行时设备争用以及持久化权重布局。我们提出了DOPS（动态算子调度），一种硬件感知的闭环框架，联合优化算子调度和块级权重布局。DOPS构建了阶段感知的有向无环图（DAG），并整合了两个组件：用于动态算子到设备放置的Bifocal调度器，以及用于在严格内存约束下选择硬件高效权重布局的权重布局仲裁器（WLA）。在结合神经处理单元（NPU）和存内处理（PIM）设备的代表性异构系统上，与PD基线相比，Bifocal实现了1.20倍至2.23倍的几何平均加速。WLA在Bifocal/Linear基础上额外提供了1.28倍至1.33倍的几何平均加速。DOPS还支持对LLM服务的工作负载敏感性和硬件可扩展性进行系统分析。源代码可在https://github.com/YIAI-02/TriForm获取，可视化工具演示见https://youtu.be/Ya_oMCyYno0。

## Abstract
Prefill-decode disaggregation (PD) and roofline-based operator placement are common strategies for partitioning Large Language Model (LLM) inference across heterogeneous systems, but they are often insufficient in practice. End-to-end latency also depends on workload shape, runtime device contention, and persistent weight layout. We present DOPS (dynamic operator scheduling), a hardware-aware, closed-loop framework that jointly optimizes operator scheduling and blockwise weight layouts. DOPS constructs a stage-aware directed acyclic graph (DAG) and integrates two components: the Bifocal scheduler for dynamic operator-to-device placement and the Weight Layout Arbiter (WLA) for selecting hardware-efficient weight layouts under strict memory constraints. Across representative heterogeneous systems combining neural processing units (NPUs) and processing-in-memory (PIM) devices, Bifocal achieves geometric-mean speedups of 1.20$\times$ to 2.23$\times$ over the PD baseline. WLA provides an additional geometric-mean speedup of 1.28$\times$ to 1.33$\times$ over Bifocal/Linear. DOPS also supports systematic analysis of workload sensitivity and hardware scalability for LLM serving. The source code is available at https://github.com/YIAI-02/TriForm, and the visualization tool is demonstrated at https://youtu.be/Ya_oMCyYno0.

**研究背景：**

- 大语言模型（LLM）推理已成为 AI 部署的核心环节，但服务成本与延迟是主要瓶颈，尤其是在受功耗和面积约束的边缘平台。
- LLM 推理分为两个特征迥异的阶段：**Prefill（预填充）**——高算术强度、密集 GEMM 主导；**Decode（解码）**——逐 token 生成、带宽受限、反复读取权重与不断增长的 KV Cache。
- 现有主流策略是 **Prefill–Decode Disaggregation（PD）**——将两阶段拆分到不同设备或资源池，以及基于 **roofline 模型**的静态算子放置。

**核心问题与动机：**

1. **PD 粒度过粗**：对整个阶段做统一设备分配，无法适应算子级别的异构特性。
2. **roofline 模型过于乐观**：
   - 有效内存带宽并非设备局部常数，取决于设备间传输、异构内存路径和缓存驻留情况。
   - 峰值算力高估了非线性算子、短 decode kernel 的实际可达性能（图 3b 显示 Ascend 910B 上 roofline “甜点”随工作负载大小移动）。
   - 静态 roofline 忽略设备利用率、排队、重叠和数据驻留等时间维度因素（图 3c）。
3. **无单一静态放置策略全场景最优**：图 1(b) 实证表明，最佳算子映射随 prefill 长度、decode 长度、batch size 变化，决策边界不规则且非单调。
4. **权重布局与算子调度相互耦合**：NPU 偏好块状 fractal 布局（如 ZZ、NZ、ZN），PIM 偏好 bank/channel 感知布局。单份设备无关拷贝需反复 re-layout，双份设备专属拷贝则导致内存翻倍，在边缘内存预算下不可行。

**提出的核心问题：**

- **Q1**：NPU–PIM 设计对目标负载何时真正有益？
- **Q2**：在不同负载配置下，应如何调度算子以获得最优性能？
- **Q3**：如何在降低 re-layout 开销的同时，避免双份拷贝的全额内存成本来选择持久化权重布局？

## 二、论文提出的方法论

### 2.1 DOPS 框架总体架构

DOPS 是一个**硬件感知的闭环优化框架**，将模型、硬件和工作负载信息组织成闭环优化循环（图 4）。

- **输入**：LLM 模型卡（含量化、稀疏化配置）、硬件抽象（NPU–PIM 拓扑、性能模型）、工作负载配置（prefill 长度、decode 长度、batch size、优化目标与 SLO）。
- **构建**：阶段感知的计算图 DAG，每个顶点代表可调度任务（算子），边编码数据依赖与数据传输（激活传输、KV Cache 更新、权重加载、re-layout 操作）。
- **输出**：算子放置与执行调度、优化后的块级权重布局、模拟端到端延迟。
- **闭环验证**：将调度与布局部署到目标硬件，测量实际延迟并回馈比较。

### 2.2 Bifocal 调度器（动态算子放置）

**问题形式化：**
- DAG G = (V, E)，设备集 K = {NPU₀, NPU₁, …, PIM₀, PIM₁, …}
- 每个算子 v ∈ V 有设备相关执行延迟 pᵥ(k)，每条边 (u,v) 有数据传输延迟 qᵤᵥ(k, ℓ, dᵤᵥ)
- 目标：找到算子到设备的映射 σ，最小化 makespan T = τᵗ_c
- 约束：数据依赖（前驱完成 + 传输时间）、设备可用性（avail(k)）、完成时间 = 开始时间 + 执行时间 + 缓存导致的权重重加载开销

**核心评分函数（Bifocal Score）：**

```
Score(v, k) = C_near(v, k) + C_far(v, k)
C_near(v, k) = (1-γ)·EFT(v, k) + γ·T̂H(v, k)
C_far(v, k) = B_phase(v, k) + B_token(v, k)
```

**Near-focus（近焦）分量：**
1. **EFT（最早完成时间）**：结合前驱到达时间、设备可用性、执行时间和权重重加载惩罚。
2. **T̂H（DAG 窗口项）**：对至多 H 个后继顶点做轻量级 lookahead 模拟，枚举合法设备类型分配，最小化模拟完成时间。

**Far-focus（远焦）分量：**
1. **B_phase（相位复用偏置）**：匹配调度局部的权重-设备一致性提示（θ），避免频繁设备切换；prefill 阶段对能整体容纳模型权重的设备类给予负偏置。
2. **B_token（token 摊销偏置）**：利用剩余 decode 水平线 Rᵢ，将一次性迁移/重载开销摊销至未来 token，允许为长期更低平均成本接受当前较高成本。

**调度流程（Algorithm 1，类 HEFT 的 list scheduler）：**
- 维护就绪任务集合 R 与系统状态 s（设备可用性、缓存状态、提示图 H 和 θ）
- 每轮对每个就绪任务遍历所有合法设备评估 bifocal score，选择全局分数最小的 (v*, k*) 提交
- 提交后更新调度状态、设备可用性、缓存状态和提示图

### 2.3 Weight Layout Arbiter（WLA，权重布局仲裁器）

**问题形式化：**
- 权重划分为稳定块 B，映射 φ: B → F，F = {Linear, NPU_OPT, PIM_OPT}
- 目标：最小化 Bifocal 预测的 makespan T(φ)，在离散 Cartesian 积 F^|B| 上搜索

**两阶段块坐标搜索策略：**
1. **外阶段（Dominance Assignment，优势分配）**：
   - 从 Bifocal 最新调度中提取每个权重块的设备加载压力统计（归一化 ℓ̃_b,NPU 与 ℓ̃_b,PIM）
   - 按优势关系粗粒度重新分配格式：NPU 压力主导→NPU_OPT，PIM 压力主导→PIM_OPT，否则保留 Linear
2. **内阶段（Targeted Refinement，定向精化）**：
   - 构建候选集（当前格式与加载行为不一致的块）
   - 对每个候选块固定其他块，显式评估 φ(b←f) 的两个替代格式
   - 仅当预测 makespan 降低超过阈值 ε 时接受翻转
   - 接受后重新调用 Bifocal 评估

### 2.4 其他关键技术细节

- **通信拓扑**：支持全连接拓扑和星型拓扑（经 host 路由），采用 LogGP 风格链路模型，考虑共享管线争用。
- **算子切分**：支持行式切分（独立分片）与列式切分（插入 reduce、all-reduce、gather、scatter 通信任务）。
- **MoE 建模**：插入 router 顶点，显式建模 token-to-expert 路由、top-k 专家选择及 dispatch/combine 依赖。
- **性能模型校准**：NPU 使用校准 roofline 模型，含饱和逻辑函数拟合利用率、CANN 启动开销；PIM 使用算子级模型和 AiM 模拟器验证。

## 六、论文的主要结论与发现

1. **动态算调度的有效性强**：
   - Bifocal 在 HP₃₂ 上对 Qwen-1.8B 达到 2.23× 几何平均加速比，Llama-7B 达 1.20×（详细验证最高 1.47×/2.41×）
   - 静态策略无一能全场景主导，决策边界不规则

   - WLA 相比 Bifocal/Linear 额外提供 1.28×–1.33× 几何平均加速
   - 大幅接近双份拷贝的理想上界（Bifocal/Dual），却无需双倍内存
3. **共利用率是关键指标**：动态调度不追求单一设备的最高利用率，而是最大化两设备的时间重叠（co-utilization）
4. **硬件扩展的边际收益规律**：
   - 更长 prefill/decode → 最优 PIM 容量点右移
   - 更大 batch → 延迟 PIM 容量收益
   - 更大模型 → 需要更大 PIM 容量
5. **消融结果**：
   - token 摊销项最关键（移除损失 16.0%–25.6%）
   - 相位复用项（移除损失 7.0%–10.0%）
   - DAG 窗口 lookahead 项（移除损失 6.4%–11.8%）
6. **动态负载下依然有效**：BurstGPT trace 上 TTFT/TBT/E2E 的 P50 与 P90 均改善

## 七、优点（亮点）

### 方法设计层面

1. **问题形式化清晰**：将 LLM 异构推理建模为“算子调度 + 权重布局”耦合优化问题，数学定义严谨（约束、目标函数明确）。
2. **Bifocal 评分的创新性**：
   - “近焦 + 远焦”双重视角突破传统 HEFT 的局部最优局限
   - token 摊销偏置巧妙地利用 LLM decode 的自回归特性
   - DAG 窗口 lookahead 以低成本捕获下游争用
3. **闭环工作流**：从输入→优化→模拟→部署→验证形成完整回路，便于模型校准与迭代改进。
4. **模块化与扩展性**：DAG 构建器支持算子切分、MoE 路由、不同后端粒度，硬件抽象支持多级性能模型（roofline、算子级、代码片段级、E2E 测量）。
5. **开源开放**：提供完整代码仓库和可视化调度回放工具，利于复现与社区发展。

### 实验评估层面

6. **验证体系完备**：模拟与硬件验证双重报告，并提供模拟-验证偏差分析（−4%～+6%）。
7. **硬件可扩展性洞察**：边际收益分析提炼了 4 条可操作的系统设计规律。
8. **工作负载覆盖全面**：包含合成扫描与真实 trace 两类负载，兼具广度和真实性。

## 八、不足与局限（续）

### 偏差风险层面（续）

4. **性能模型偏差的潜在来源**：论文报告模拟-验证偏差为 −4%～+6%，但该偏差是在两个小模型、少量配置上统计的。对于更大模型（Llama-70B、Mixtral-8×7B），其层数更深、权重规模更大、流水线重叠行为更复杂，roofline 模型中的饱和逻辑函数和启动开销拟合是否仍能保持同样精度存在不确定性。此外，PIM 的算子级模型基于 AiM 模拟器校准，模拟器与实际芯片的时序差异未在真实 AiM 硬件上直接验证。

5. **调度器启发式缺乏最优性保证**：Bifocal 评分是多种启发式项的加权组合，权重 γ 和偏置项的缩放方式依赖人工调参。论文未报告这些超参数在不同硬件拓扑、不同模型规模下的敏感性分析，也未与精确求解器（如 MILP）或最优性下界进行对比，调度的次优性幅度未知。

### 系统假设层面

6. **假设硬件先验已知且模型卡准确**：DOPS 是离线优化+在线执行架构，其有效性依赖性能模型对硬件的准确刻画。若硬件行为随温度、频率缩放或内存扰动变化，离线校准的模型可能失真，框架缺少在线自适应重新校准机制。

7. **调度器为离线决策**：Bifocal 是每轮批处理开始时执行一次的离线调度器，对动态负载的适应性依赖于重现调度（re-schedule），但对在线到达而导致的调度扰动、排队偏移、超时抢占等场景的处理细节描述有限。

8. **未探讨多租户与公平性问题**：论文场景为单服务单租户的 batch serving；多模型共享同一 NPU–PIM 资源池时，调度目标需叠加公平性与租户隔离约束，本框架未覆盖。

9. **权重布局搜索的局部性**：WLA 的两阶段搜索是坐标下降式局部搜索，可能陷入较差局部最优；虽对比了双份拷贝上界，但未与随机重启、贝叶斯优化或遗传算法等全局搜索基线对比，难以判断局部搜索与全局最优的差距。

## 九、改进建议

### 方法层面

1. **引入自适应超参数机制**：将 Bifocal 评分中的 γ、相偏置/令牌偏置强度与硬件实测数据联动，通过在线贝叶斯优化自动调节，减少人工调参成本。
2. **扩展最优性对比**：对小规模 DAG 引入 ILP 精确求解，量化 Bifocal 与最优解的差距；对大规模 DAG 引入列生成或图神经网络-Gurobi 混合方法作为更强基线。
3. **鲁棒性校准**：增加模型参数规模、温度变化、DVFS 状态下的性能模型误差敏感性分析，必要时引入在线测量反馈闭环（如每 N 步用真实延迟修正模型参数）。

### 实验层面

4. **增加硬件多样性**：至少补充 HBM-PIM（如 Samsung Aquabolt-XL）或 LPDDR-PIM 的模拟对比，验证 DOPS 对不同 PIM 特性的普适性。
5. **补齐大模型端到端验证**：Llama-70B 在较小 PIM 容量下无法单设备容纳时，应至少实现在 Ascend 910B 上的 NPU-only 运行验证，并将模拟延时的误差单独量化。
6. **补充能效分析**：结合 NPU/PIM 的 TDP 与实测功耗模型，报告 energy-delay product (EDP) 或 energy-per-token 指标，回应边缘部署的功耗约束。
7. **增加多租户场景实验**：模拟两个模型并发共享 NPU–PIM 池的场景，报告公平性（如 Jain's index）与性能隔离效果。

## 十、论文的学术价值与实操意义

### 学术价值

1. **填补了 LLM 推理异构调度的粒度空白**：现有工作多停留在阶段级（PD 分离）或规则级（Attention/FFN 分离），DOPS 首次将粒度推进到**算子级动态调度**并形式化求解。
2. **提出“计算-数据结合”的布局-调度联合优化范式**：将权重布局决策从执行阶段“解耦”出来并纳入全局优化目标，形成调度器与布局仲裁器的两阶段闭环，为后续工作提供了可复用的系统架构。
3. **提供了丰富的工程实现细节**：包括 LogGP 链路模型、共享管线争用、行/列切分的通信任务建模、MoE 路由建模等，可作为 NPU-PIM 模拟器的参考实现。

### 实操意义

1. **对系统设计者**：边际收益规律给出了 PIM 容量配置的实用指南（如 prefill 更长时 PIM 容量需求更大、batch 更大时 PIM 收益延迟出现），可直接指导边缘推理硬件选型。
2. **对平台软件栈开发者**：开源的调度器+布局仲裁器+可视化工具链，为 NPU-PIM 混合编程框架（如 CANN 扩展）提供了可直接借鉴的调度算法与接口设计。
3. **对模型部署工程师**：Bifocal/WLA 提供了一条“不需要双份权重拷贝”的省内存路径，在边缘内存预算紧张时具有实际落地价值。

## 十一、读后总结（关键问题回答）

回到论文开头提出的三个研究问题：

- **Q1（异构设计何时有益）**：当目标负载处于“NPU 算力充足但带宽受限”与“PIM 算力受限但带宽充足”之间的平衡区间时，NPU-PIM 系统以高共利用率获得超过任一单设备的吞吐；且该收益随负载参数（prefill 长度、batch size、解码长度）以非单调方式变化，需动态决策。
- **Q2（如何调度算子）**：采用近焦（EFT + DAG 窗口 lookahead）+ 远焦（相位复用 + token 摊销）组合评分，进行 list scheduling；前者捕获局部延迟，后者捕获跨 token 的持久性收益，二者结合优于任何单一静态规则。
- **Q3（如何降低 re-layout 开销）**：通过 WLA 的“优势分配 + 定向精化”两阶段搜索，仅对负载压力显著偏向某一设备族的权重块分配对应专属布局，其余保持线性布局；以与双份拷贝接近的性能（1.28–1.33× 额外加速）换取接近单份拷贝的内存成本。

**总体判断**：这是一篇系统设计和体系结构方向的优质工作。其核心贡献不在于提出一个全新的算子调度算法，而在于将 LLM 推理的算子调度、异构设备特性和权重布局三者耦合问题系统性地建模并给出了一套完整的工程解决方案。方法设计精巧，实验覆盖较充分，开源性好，结论对实际系统构建有直接指导价值。主要遗憾在于硬件验证范围偏窄、对能耗指标的缺失以及对启发式最优性缺乏定量分析。
