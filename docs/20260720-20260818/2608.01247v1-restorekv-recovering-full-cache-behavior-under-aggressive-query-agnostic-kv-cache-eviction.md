## 摘要
无查询感知的KV缓存驱逐会压缩一次上下文，并将所得缓存重复用于任意后续查询，但在严格的预算下性能可能会崩溃。现有方法主要改进保留哪些原始KV对。我们引入RestoreKV，通过在同一总KV预算下用学习恢复来补充这种基于选择的方案。我们的关键洞见是，虽然通过驱逐丢失的信息是上下文特定的，但生成其紧凑补全的机制可以在上下文之间共享。上下文预填充后，少量恢复token在单次LoRA自适应传递中关注完整的KV缓存，生成一个紧凑的、上下文条件的恢复缓存。基础重要性评分器和驱逐规则保持不变，适配器在所有后续查询和解码中禁用。RestoreKV通过从冻结的全缓存模型进行参数高效的自蒸馏训练，仅优化0.4%的参数，且不需要任务特定调优。在四个骨干和四个长上下文基准上，RestoreKV大幅减少了压缩引起的性能下降。在Qwen3-4B上，它在五种基础驱逐方法的60个配对、预算匹配设置中改善了59个；在5%预算下，它将KVzip在RULER-4K上的准确率从38.2提高到73.2。应用于KVzip+时，RestoreKV在KVPress基准的16倍压缩下达到86.4的RULER准确率，同时在32K上下文评估中增加了不到0.5%的一次性缓存构建开销。我们的项目页面可在https://paper.pnu-cvsp.com/RestoreKV/获取。

## Abstract
Query-agnostic KV cache eviction compresses a context once and reuses the resulting cache for arbitrary future queries, but performance can collapse under tight budgets. Existing methods primarily improve which original KV pairs are retained. We introduce RestoreKV, which complements this selection-based formulation with learned restoration under the same total KV budget. Our key insight is that, although the information lost through eviction is context-specific, the mechanism for generating its compact complement can be shared across contexts. After context prefill, a few restore tokens attend to the full KV cache in a single LoRA-adapted pass, generating a compact, context-conditioned restore cache. The base importance scorer and eviction rule remain unchanged, and the adapters are disabled for all subsequent queries and decoding. RestoreKV is trained through parameter-efficient self-distillation from the frozen full-cache model, optimizing only $0.4\%$ of the parameters and requiring no task-specific tuning. Across four backbones and four long-context benchmarks, RestoreKV substantially reduces compression-induced degradation. On Qwen3-4B, it improves 59 of 60 paired, budget-matched settings across five base eviction methods; at a $5\%$ budget, it raises KVzip from $38.2$ to $73.2$ on RULER-4K. Applied to KVzip+, RestoreKV reaches $86.4$ RULER accuracy at $16\times$ compression on the KVPress Benchmark, while adding less than $0.5\%$ one-time cache-construction overhead in a 32K-context evaluation. Our project page is available at https://paper.pnu-cvsp.com/RestoreKV/

# RestoreKV 论文详细中文总结

## 一、核心问题与研究动机

- **背景**：大语言模型依赖长上下文，而 KV 缓存随序列长度线性增长，成为推理的主要内存瓶颈。KV 缓存驱逐通过在预填充后仅保留部分 KV 对来降低这一成本。
- **核心问题**：在**无查询感知（query-agnostic）**的驱逐设置下（即上下文只压缩一次、结果缓存可复用于任意后续查询），当缓存预算非常紧张时，压缩后模型的性能会急剧崩溃。现有方法（如 KVzip、KVzip+、ContrastKV 等）的核心思路都是"**选择更好的子集**"——即改进重要性评分以决定保留哪些原始 KV 对。但无论选择多么精准，在激进压缩下，仅靠"选择"本身无法阻止信息丢失带来的性能塌方。
- **论文的核心洞见**：虽然驱逐丢失的**信息内容**是上下文特定的（不同上下文丢失的关键信息不同），但生成丢失信息之**紧凑补全的机制**（即如何从完整缓存中提炼一个小的恢复性缓存）可以跨上下文共享。这启发了一种全新思路：**与其只学"保留什么"，不如同时学习"如何生成一小块上下文相关的补偿缓存"**。
- **整体含义**：RestoreKV 将 KV 缓存压缩从纯"选择"范式扩展为"选择 + 恢复"范式，在严格预算下显著缩小了压缩模型与全缓存模型之间的性能差距。

## 二、方法论

### 2.1 核心思想

RestoreKV 是一个**与既有驱逐方法正交的即插即用组件**：它保留原有重要性评分器和驱逐规则不变，仅在驱逐前额外生成一小块紧凑的、上下文条件化的"恢复缓存"（restore cache），用于补偿被驱逐信息带来的损失，并在**同一总 KV 预算**内与保留的上下文缓存组合。

### 2.2 关键技术细节

1. **可学习的恢复 token 嵌入**：引入 n 个可学习 token 嵌入 E ∈ R^{n×d}（默认 n=8）。在上下文预填充之后，这些恢复 token 以因果注意力的方式访问**完整** KV 缓存 C，执行一次前向传播，为每层每个 KV 头产生一个 KV 对，形成恢复缓存 C_res（大小 nLH）。
2. **LoRA 适配的恢复过程**：仅在这一步使用 LoRA（rank=8，α=16），对注意力与 MLP 投影施加低秩适配；上下文预填充、后续所有 query 处理和解码阶段都使用冻结的原始骨干网络。
3. **预算匹配（Budget Matching）**：从总预算 B 中先预留 nLH 个槽位给恢复缓存，基础驱逐器用保留的上下文 KV 对填充剩余的 B−nLH 个槽位，总缓存大小不变，query 阶段内存成本与基线完全一致。
4. **训练目标——全缓存自蒸馏**：用冻结的全缓存模型作为教师，学生使用预算匹配后的缓存评估同一段答案，优化两者的对称 KL 散度（symmetric KL divergence）。训练中 KV 预算比例从 U(0.025, 0.25) 均匀采样，使单一恢复机制同时支持多种缓存预算。训练只更新恢复 token 嵌入和 LoRA 参数（约占 Qwen3-4B 的 0.4%），骨干和基础驱逐器保持冻结。
5. **推理流程**：每次遇到新上下文时，先执行一次 n-token 的 LoRA 恢复传递生成 C_res，再与保留缓存拼接构成最终缓存；此后 LoRA 关闭，后续推理与基础方法完全相同。恢复缓存是上下文相关的，但生成机制（token 嵌入 + LoRA 权重）是跨上下文共享且经过离线训练的。

## 三、实验设计

### 3.1 数据集与基准

- **RULER-4K**：13 任务的合成基准（检索、追踪、聚合），固定 4K 上下文，遵循 KVPress 官方评估协议。
- **QASPER**（LongBench）：面向科学论文的自由问答，平均约 5K token。
- **QuALITY**：长文章多项选择阅读理解，约 6K token。
- **LongHealth**：临床病历上的多项选择 QA，约 11K token。
- 附录补充：**LongBench** 全部 16 个任务；**SCBench** 9 个长上下文任务（平均约 104K token，用于验证长程泛化）。

### 3.2 模型与对比方法

- **骨干模型**：Qwen3-0.6B/4B/8B、Llama-3.1-8B-Instruct（全部冻结）。
- **基础驱逐方法**（5 种）：KVzip、KVzip+、ContrastKV，以及 SnapKV 和 H2O 的无查询感知适配版本。
- **附加对比**：与合成缓存方法 Attention Matching（AM-fast）比较；与学习型评分器 Fast KVzip 组合验证；同时报告全 KV 缓存上界。
- **公平性保证**：所有配对对比均在**完全相同的总 KV 预算**下进行（RestoreKV 预留的槽位从原有预算中划出）；重要性评分器和驱逐规则均未改动。

### 3.3 训练数据

训练集包含 6,248 个上下文-查询对，来源于 LongAlpaca（2,488）、PG-19（2,260）和 Tulu-3 FLAN（1,500），上下文长度 512–15,237 token，覆盖事实性、摘要、多跳、方法、比较等查询类型。

## 六、主要结论与发现

1. **一致性改进**：在四种骨干、四个基准、五种驱逐方法下，RestoreKV 均显著缩小了与全缓存性能的差距，预算越紧提升越大。Qwen3-4B 在 5% 预算下将 KVzip 的 RULER-4K 准确率从 38.2 提升至 73.2；KVzip+ 在 16× 压缩下达 86.4。
2. **增益来源定位**：注意力侧的 LoRA 适配（而非恢复 token 嵌入中的通用记忆）是恢复性能的主要来源；固定嵌入 + LoRA 即可达到完整配置 96% 的提升。全上下文条件化提供额外约 8.8 个点的补充收益（r=0.05）。
3. **上下文注意力的恢复**：RestoreKV 将被驱逐缓存抑制的上下文注意力从 0.56% 恢复至 1.30% 的平均注意力质量，并将最终预测分布与全缓存模型的 KL 散度从 7.3 降至 3.8。
4. **开销极小**：一次性缓存构建开销 <0.5%，query 阶段零额外 KV 内存和解码成本，且与学习型评分器（Fast KVzip）可组合使用。
5. **局限性发现**：恢复机制会适配训练时的驱逐器特性（训练-推理驱逐器不匹配时增益减弱）；RoPE 位置偏移本身不能解释性能提升。

## 七、方法的优点

- **范式创新**：首次从"选择"视角转向"选择 + 恢复"视角，思想简洁且与现有方法正交，可作为通用插件。
- **严格预算匹配**：不增加 query 阶段的任何内存或计算成本，对比公平。
- **参数高效**：仅 0.4% 可训练参数、单卡两小时训练，训练成本极低；无需任务特定微调。
- **即插即用**：不改变任何既有评分器/驱逐规则，兼容选择式与学习式评分方法，且对骨干规模（0.6B–8B）不敏感。
- **分析扎实**：通过多组控制实验清楚分离了各组件贡献，排除了位置偏移等混杂因素，验证了方法的真实有效性。
- **长程泛化能力**：仅在 ≤15K token 数据上训练，即可在约 104K 上下文的 SCBench 上带来一致提升。

## 八、不足与局限

- **基准覆盖偏差**：主实验集中在英文的问答、检索、阅读理解场景（RULER、QASPER、QuALITY、LongHealth），未覆盖多语言、代码生成、对话、开放式生成等场景；LongBench 结果虽有补充但总体仍是英文主导。
- **训练数据域限制**：训练仅来自 LongAlpaca、PG-19、Tulu-3 FLAN 三个来源，且最大上下文仅 15K token；领域分布和长度覆盖可能影响实际部署中的泛化。
- **跨驱逐器迁移有限**：训练-推理驱逐器不匹配时增益显著下降（r=0.05 时从 73.2 降至 42.0），意味着**每个（模型 × 驱逐器）组合需要单独训练**，增加了部署成本。
- **与强基线并非全面领先**：与 AM-fast 的比较中，在较宽松的 LongHealth 预算下 AM-fast 更优；论文未展示与更多合成缓存方法（如 STILL、Cartridges、VECTOR 等）的系统化对比。
- **训练细节的未完整披露**：论文虽给出训练报告，但未公开代码和训练数据；教师响应生成、过滤标准等细节依赖附录，复现门槛较高。
- **部分性能指标仍低于全缓存模型**：在 5% 预算下虽大幅提升（如 RULER 从 38.2 到 73.2），与全缓存（约 90+）仍有明显差距；在极紧预算下恢复能力仍有上限。
- **仅单一 GPU 环境验证**：未在多卡、生产级推理框架（如 vLLM、TensorRT-LLM）中验证实际端到端收益。
- **解码策略单一**：所有实验均为贪婪解码；采样解码下的表现未知。
