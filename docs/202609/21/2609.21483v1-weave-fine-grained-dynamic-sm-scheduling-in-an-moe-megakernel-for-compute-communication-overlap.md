## 摘要
在专家并行（EP）下，混合专家（MoE）推理将每个 MoE 层转变为具有高昂分发与合并通信开销的分布式计算。当前最先进的系统通过通信-计算重叠来降低这一开销，将 GPU 的 SM 分别划分给通信和计算。然而，这种方法仍在两个维度上造成 GPU 资源浪费。在空间维度上，最优的 SM 划分取决于每一层的路由结果，并因层和 GPU 而异，因此固定策略会与工作负载不匹配，从而浪费 NVLink 带宽或计算吞吐。在时间维度上，复杂的 MoE 数据依赖会引入气泡，使 SM 空闲。我们提出 Weave，据我们所知，这是首个执行细粒度动态 SM 调度的 MoE 重叠系统——在运行时根据路由结果逐层、逐 GPU 进行决策。一旦路由完成，每一层的通信量和计算量便已知；Weave 通过运行在持久化巨核内的轻量级成本模型来利用这种可预测性：空间调度器将 SM 划分为通信工作单元和计算工作单元，以匹配通信/计算吞吐比；时间调度器则协调这两组工作单元，以最小化 SM 空闲。在 4 块 H100 SXM GPU 上，针对六个主流 MoE 模型，Weave 相较于五个最先进的基线，实现了 2.89 倍的 MoE 层几何平均加速和 1.33 倍的端到端几何平均加速。

## Abstract
Mixture-of-Experts (MoE) inference under expert parallelism (EP) turns each MoE layer into a distributed computation with costly dispatch and combine communication. State-of-the-art systems reduce this cost through communication-computation overlap, splitting the GPU's SMs for communication and computation respectively. However, this approach still leaves GPU resources wasted along two dimensions. Spatially, the best SM split is determined by each layer's routing result and varies across layers and GPUs, so fixed policies mismatch the workload and waste either NVLink bandwidth or compute throughput. Temporally, complex MoE data dependencies introduce bubbles that leave SMs idle.   We present Weave, to our knowledge the first MoE overlap system that performs fine-grained dynamic SM scheduling - deciding per layer and per GPU by routing results at runtime. Once routing completes, each layer's communication and computation volumes become known; Weave exploits this predictability through a lightweight cost model running inside the persistent megakernel: a spatial scheduler partitions SMs into communication workers and computation workers to match the communication/computation throughput ratio, and a temporal scheduler coordinates the two worker groups to minimize SM idleness. On 4x H100 SXM GPUs across six mainstream MoE models, Weave achieves a 2.89x geometric-mean MoE-layer speedup and a 1.33x geometric-mean end-to-end speedup over five state-of-the-art baselines.

## 一、核心问题与研究动机

### 研究背景
- **MoE 推理的通信瓶颈**：在专家并行（EP）下，每个 MoE 层变为分布式计算，包含跨 GPU 的 **dispatch**（将 token 发送到目标专家所在 GPU）与 **combine**（聚合专家输出并返回原 GPU）。已有工作指出 dispatch 与 combine 可占 MoE 层延迟的 **40%**。
- **硬件趋势加剧矛盾**：BF16 算力增长快于 NVLink 带宽（A100→B200 算力 3.2×/2.3×，带宽仅 1.5×/2.0×），通信成为越来越关键的瓶颈。
- **现有重叠方案的三类模式**：
  - **(i) 无显式 SM 划分**（如 TD）：通信与计算串行，仅靠全局抢占在算子边界重叠。
  - **(ii) 静态 SM 划分**（如 DeepEP、PK）：编译期固定通信 SM 数（如 H100 上固定 20/132），对所有层一视同仁。
  - **(iii) 粗粒度动态**（如 Comet）：按迭代（而非按层）从预剖析库选择 SM 比例。

### 核心洞察与两个浪费维度
- **关键洞察**：路由完成后，每层的通信量与计算量即已确定，调度可基于此可预测性在线决策。
- **空间维度**：最优通信/计算 SM 比例由每层路由结果决定，且逐层、逐 GPU 变化。论文实测 DSv2 单层中每 GPU 最优 `c*` 在 **12–36** 间波动，而 DeepEP 固定 20、Comet 固定 18，导致瓶颈 GPU 分别慢 **1.33×** 和 **1.18×**。
- **时间维度**：即使 SM 划分合适，MoE 数据依赖（up GEMM 需等 dispatch 完成、combine 需等 down GEMM 完成）仍造成通信 SM 在中间计算阶段的大段空闲（**mid bubble**）。

## 二、方法论

### 核心思想
在单个持久化 **megakernel** 中，将 MoE 层的五个操作（dispatch、GEMM0、SiLU_Mul、GEMM1、combine）全部融合；路由完成后，由 megakernel 序言中的**轻量级成本模型**在微秒级内联合决策两个变量：
- **`c`**：通信 SM 数量（空间划分）
- **`K`**：流水线 chunk 数（时间协调）

输出每层、每 GPU 的执行计划（SM 角色分配、chunk 数、偷取 tile 数）。

### 3.1 空间调度器（Spatial Scheduler）
- 定义符号：`N` 为可用 SM 总数，`c` 为通信 SM 数，`H` 为隐藏维，`I` 为专家中间维，`B = 2H` 字节为单 token 通信量。
- 路由后可得：`X_local`（本地 token）、`X_in`（路由到本地专家的远端 token）、`X_uniq_in`（去重后的远端 token）。
- **工作量公式**：
  - `W_comp = (X_local + X_in) · 6HI` FLOPs
  - `W_dispatch = X_uniq_in · B` bytes
  - `W_combine = X_in · B` bytes
- **时间分量**：
  - `T_comp = W_comp / TFLOPS(N−c)`
  - `T_comm = (W_dispatch + W_combine) / BW(c)`
  - `T_tail = (1−α) · W_combine / BW(c)`，其中 `α` 为 tile 级重叠比（经验校准）
- **优化目标**：`T_total = max(T_comp + T_tail, T_comm)`，求解 `c* = arg min T_total`。

### 3.2 时间调度器（Temporal Scheduler）
- **Chunk Pipeline**：
  - 将 GEMM0、SiLU_Mul、GEMM1、combine 切分为 `K` 个独立 chunk（dispatch 不切分），使 combine 能插入 GEMM 中间执行。
  - 引入 `eff_chunk(K) ∈ (0,1]` 修正因子刻画切分带来的 GEMM 吞吐下降（K=8 时下降约 27%）。
  - 修正后：`T_comp(c,K) = W_comp / (TFLOPS(N−c) · eff_chunk(K))`；`T_tail = (1−α)·W_combine / (BW(c)·K)`。
  - K 的权衡：K 越大尾延迟越小，但 GEMM 吞吐退化越严重。
- **Bubble Stealing**：
  - dispatch 结束后、combine 开始前的空闲窗口，让通信 SM 偷取 GEMM tile。
  - 计算偷取量：先算 `t_comm(c) = W_comm / BW(c)`，期间 comp SM 完成 `W_partial(c) = t_comm(c) · TFLOPS(N−c)`，剩余 `W_steal(c) = max(0, W_comp − W_partial(c))`，则每 SM 偷取 `n_steal(c) = W_steal(c) / (N · W_tile)` 个 tile。
  - 设计要点：偷取窗口集中在 dispatch 之后（而非分散在各 chunk 的 combine 间隙），避免角色反复切换。

### 3.3 联合搜索 (c*, K*)
- 将 K 相关定义代入总时间：`T_total(c,K) = max(T_comp(c,K) + T_tail(c,K), T_comm(c))`，联合求解 `(c*,K*) = arg min T_total(c,K)`。
- 实测 (c,K) 网格呈**单峰最优**（DSv2-Lite seq=8192 时 `c*=40, K*=4`，1.365 ms），证明必须联合搜索。

### 实现细节
- 基于 **ParallelKittens (PK)** 实现，单持久化 megakernel，grid size = N = 132（H100）。
- block 索引 < `c*` 为通信 SM，其余为计算 SM；tile 分配用 `atomicAdd` 动态调度。
- 将 dispatch 侧 token 去重融合进 megakernel，重复 token 直接从本地 HBM 读取，避免冗余传输与 HBM 轮询。
- 最终 combine 由全部 N 个 SM 参与，消除尾延迟。
