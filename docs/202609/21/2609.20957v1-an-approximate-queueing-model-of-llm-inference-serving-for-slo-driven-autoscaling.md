## 摘要
LLM服务器的性能模型既支持延迟评估，也支持面向服务等级目标（SLO）的自动扩缩容控制器设计以及推理优化。我们在马尔可夫假设下，用一个可处理的近似排队模型对预填充（prefill）和解码（decode）操作的多路复用执行进行建模。三个参数刻画一个模型-加速器组合，即每次迭代的基线开销、每token计算成本和每token键值（KV）缓存访问成本。该模型将每次迭代工作量的均值分析（mean-value analysis）与用于批次占用的状态依赖马尔可夫链相结合，以预测平均首token时间（TTFT）和token间延迟（ITL）。我们通过实测验证这些预测，并表明这三个参数可从观测到的延迟中估计得到。在覆盖轻到中等负载的输入/输出长度和到达率网格上，对于在H100 GPU上运行的Llama-3.1-8B和Qwen2.5-14B，平均ITL的相对误差分别约为5%和8%，相应的TTFT误差分别为14%和16%。随后，我们实现了一个自动扩缩容控制器，它利用该模型在工作负载变化时调整推理服务器副本数量。在H100 GPU的OpenShift集群上，它在两个延迟目标下跟踪四倍负载增长，在127个控制周期中有7个周期未满足其中一个目标，其控制回路内预测的TTFT和ITL中位误差分别至多为5%和9%。现有自动扩缩器中的解码吞吐量分析器不考虑延迟目标，在相同控制器和负载下于128个控制周期中有27个未满足目标，同时少配置了4%和28%的副本。

## Abstract
Performance models of LLM servers support both latency evaluation and the design of controllers for autoscaling against service level objectives (SLOs) and for inference optimization. We model the multiplexed execution of prefill and decode operations with a tractable, approximate queueing model under Markovian assumptions. Three parameters characterize a model-accelerator pair, namely a baseline per-iteration overhead, a per-token compute cost, and a per-token key-value (KV) cache access cost. The model combines a mean-value analysis of per-iteration work with a state-dependent Markov chain for batch occupancy to predict mean time to first token (TTFT) and inter-token latency (ITL). We validate these predictions against measurements and show that the three parameters can be estimated from observed latencies. Over a grid of input and output lengths and arrival rates spanning light to moderate load, the relative error of the average ITL is about 5% for Llama-3.1-8B and 8% for Qwen2.5-14B running on an H100 GPU, and the corresponding TTFT errors are 14% and 16%.   We then implement an autoscaling controller that uses the model to adjust inference-server replica counts as the workload changes. On an OpenShift cluster of H100 GPUs it tracks a fourfold load ramp under both latency targets, missing one in 7 of 127 control cycles, and its in-loop predictions carry median errors of at most 5% for TTFT and 9% for ITL. A decode-throughput analyzer from an existing autoscaler, which takes no latency target, misses 27 of 128 cycles under the same controller and load while provisioning 4% and 28% fewer replicas.

# 论文详细总结：面向SLO驱动自动扩缩容的LLM推理服务近似排队模型

## 1. 核心问题与整体含义（研究动机与背景）

- **背景**：LLM推理服务（聊天机器人、编码助手、AI搜索等）对延迟敏感，服务等级目标（SLO）约束响应延迟。请求率波动且每个请求消耗大量计算与内存带宽，提供商通过在多GPU/TPU上复制模型来承载负载。
- **核心矛盾**：副本过多浪费昂贵算力，副本过少导致排队与SLO违规。资源分配必须理解到达率、请求大小与服务策略如何共同决定延迟——本质上是排队问题。
- **现有方法缺陷**：
  - 阈值型自动扩缩器（如基于KV缓存利用率）只是延迟目标的间接指标，同一KV利用率可对应不同TTFT/ITL，且只能事后响应。
  - 黑盒性能预测器需要为每个"模型-加速器"组合做大量测量标定。
- **论文目标**：构建一个**可处理的解析排队模型**（三参数）预测TTFT与ITL，并将其嵌入**SLO驱动的自动扩缩容控制器**，直接以延迟目标为约束选择副本数。

## 2. 方法论：核心思想与关键技术细节

### 2.1 核心思想
- 将连续批处理（continuous batching）下prefill与decode的多路复用执行，建模为**每迭代工作量的均值分析** + **批次占用的状态依赖Markov链**。
- 用三个模型-加速器参数将"工作量"换算为墙钟时间：
  - **α**：每次迭代的基线开销（kernel启动、同步屏障、权重加载）。
  - **β**：每token前向计算时间（受加速器峰值浮点吞吐支配）。
  - **γ**：每token KV缓存访问时间（受内存带宽支配）。

### 2.2 每迭代工作模型
- 请求状态空间：`A = {01, 02, ..., 0c, 1, 2, ..., m}`，其中`0j`为第j个prefill chunk，`k`为第k个decode步；各状态等概率，`p_a = 1/(c+m)`。
- **Prefill chunk j 的工作量**：`W_0j = βn/c + γjn/c`（随j增长，后期chunk更偏内存受限）。
- **Prefill总工作量**：`W_pref = βn + γn(c+1)/2`。
- **Decode step k 的工作量**：`W_k = β + γ(n+k)`。
- **Decode总工作量**：`W_dec = βm + γm(n + (m+1)/2)`。
- **总工作量**：`W_total = β(n+m) + γ[n(c+1)/2 + m(n + (m+1)/2)]`。
- **每并发请求边际成本**：`δ = W_total/(c+m)`。
- **迭代时间线性模型**：`T(X) = α + Xδ`（X为活跃请求数）。

### 2.3 状态依赖Markov链
- 以系统内请求数`i`为状态的生灭链（birth-death chain），最大批大小`B`，到达率`λ`，状态i下每请求离开率`μ(i)=1/τ(i)`。
- **服务时间**：`τ(i) = (c+m)T(i)`，其中`T(i)=α+iδ`。
- 稳态概率`π_i`由平衡方程给出，利用`g(i)=λ/(iμ(i))`递推。
- **利用率**：`ρ = λτ(B)/B`，仅当`ρ<1`存在稳态。

### 2.4 延迟指标
- **Prefill延迟**：`T_p(i) = cT(i-1) + W_pref`。
- **ITL**：`T_ITL(i) = T(i-1) + (1/m)ΣW_k`。
- 在均值批大小`X`处评估：`T_ITL(X) = (S - T_p(X))/m`，`T_TTFT = W + T_p(X) + T_ITL(X)`（W为排队等待时间，S为平均服务时间，由Little定律得）。

### 2.5 分块prefill的均值场近似
- 通过token预算`M`求解条件均值场，得到有效prefill迭代数`c(i)`：
  - 解方程`Mc² + Φ_i c - nm = 0`，`Φ_i = m(M-i+1) - in`。
  - `c_min(i)`为上述方程正根，`c(i) = ⌈c_min(i)⌉`。
- 无限token容量时`M→∞`，`c(i)=1`（prefill单迭代完成）。

### 2.6 参数估计（在线自校准）
- **初始拟合**：累积若干控制周期观测后，用Nelder-Mead优化最小化TTFT与ITL的**相对误差平方和**，变量按初值缩放以保持单纯形条件良好。
- **在线滑动窗口估计**：每控制周期用最近`N_w`个观测重跑优化，以前一参数向量初始化单纯形；排除`ρ≥1`的饱和周期。

## 6. 主要结论与发现

- **模型精度**（离线）：ITL相对误差Llama-3.1-8B约**4.6%**、Qwen2.5-14B约**7.9%**；TTFT误差分别约**13.6%**与**15.8%**。
- **参数物理可解释**：
  - β从2.01e-2升至3.68e-2（比值1.83），与参数量比1.75一致；对应约80%峰值算力。
  - γ从5.52e-5升至8.48e-5（比值1.54），与层数比1.5一致；对应约71%峰值带宽。
- **闭环控制**：
  - 排队模型analyzer：TTFT-bound场景7/64违规，ITL-bound场景0/63违规，合计**7/127**。

  - 控制回路内预测中位误差：TTFT≤5%，ITL≤9%。
- **机理发现**：TTFT-bound场景中吞吐analyzer把KV利用率推到0.74并形成194请求队列，导致大幅TTFT超限；ITL-bound场景中即使无排队，更高活跃批大小也推高迭代时间——说明"用实测ITL算解码容量"不等于满足ITL目标。
- **总体结论**：呈现**容量-延迟权衡**而非某一方全面占优；排队模型analyzer把TTFT/ITL目标作为显式约束，吞吐analyzer不接收延迟目标。

## 7. 优点

- **轻量可解释**：仅三参数即可刻画模型-加速器对，参数具有物理意义，可跨模型架构缩放验证。
- **解析可处理**：均值分析+一维状态依赖Markov链保持闭式/低成本，适合控制器内对每个候选副本数快速评估。
- **在线自校准**：滑动窗口+Nelder-Mead在线刷新参数，适应KV压力与批组成漂移，避免黑盒预测器逐部署训练。
- **直接SLO控制原语**：可对候选副本数预测两种延迟并选最低成本满足约束的方案，而非事后阈值响应。
- **公平的对比设计**：共享collector/actuator，隔离analyzer差异，并指出吞吐analyzer无延迟目标的不对称性。
- **物理合理性检验**：将拟合β、γ对照H100算力/带宽，且拟合过程不知晓硬件规格，构成可失败的检验。

## 8. 不足与局限

- **到达过程假设过强**：泊松到达（CV固定为1）比生产trace（如Azure、BurstGPT）更不突发；在突发到达下等待时间/TTFT预测偏乐观，高负载时尤甚。
- **均值请求近似**：所有请求用平均输入/输出长度，闭环实验每场景固定长度对，未验证宽/多模态长度分布下精度。
- **未覆盖饱和区**：剔除最接近饱和的运行，精度结论仅限轻到中等负载；`ρ≥1`时稳态链无定义。
- **均值占用近似**：用均值批大小X替代占用分布，饱和附近误差可能放大。
- **实验统计强度弱**：闭环每场景单次运行，无方差/置信区间；仅一个模型-加速器对。
- **对比不完整**：只实现吞吐analyzer的副本逻辑，未评估完整WVA（路由/调度缺失），且其15个参数保持上游默认、未调优。
- **控制设计缺口**：ITL-bound场景中无排队也会超ITL，说明仅靠吞吐估计不足，需混合analyzer。
- **参数敏感性未知**：未研究校准窗口、重置准则、利用率目标、排队排水因子等对决策的影响。
- **缺少核级验证**：β、γ的物理含义仅通过宏观数值对照，未与kernel级profiling严格交叉验证。
