## 摘要
大语言模型（LLM）正迁移到移动设备上，以处理文本、图像、视频和音频等日益多样的工作负载。这些应用通常需要长上下文，使得键值（KV）缓存成为主要的内存瓶颈，因为它随序列长度线性增长，并在每个解码步骤中被访问。先前工作通过低秩压缩、令牌驱逐或闪存卸载来减少 KV 缓存占用，但由此产生的重建开销、不可逆的令牌丢失或 I/O 停顿可能抵消节省内存带来的收益。我们提出 TierKV，一种基于预测式多层级缓存优化（PMCO）的移动端 LLM 推理框架。在解码开始之前，PMCO 从预填充隐藏状态预测未来的缓存需求，并在设备内存和精度预算下，将令牌联合分配到精确、低秩和闪存卸载层级。该公式保留对完整上下文的访问，消除了反应式驱逐的循环依赖，并采用闭式求解器在运行时选择层级边界和逐层秩。在三款移动 SoC 上的八个文本、视觉和音频模型中，TierKV 相比现有移动端 LLM 框架将预填充吞吐量提升至多 17.6 倍，将驻留 RAM 的 KV 缓存减少 12.5–34%，从而在相同内存预算下支持显著更长的上下文，同时仅带来轻微精度下降。

## Abstract
Large language models (LLMs) are moving onto mobile devices for increasingly diverse workloads over text, images, video, and audio. These applications often require long contexts, making the Key-Value (KV) cache a dominant memory bottleneck because it grows linearly with sequence length and is accessed at every decoding step. Prior work reduces KV-cache footprint through low-rank compression, token eviction, or flash offloading, but the resulting reconstruction overhead, irreversible token loss, or I/O stalls can offset the benefit of saving memory. We present TierKV, a mobile LLM inference framework built on Predictive Multi-Tier Cache Optimization (PMCO). Before decoding starts, PMCO predicts future cache demand from prefill hidden states and jointly assigns tokens to exact, low-rank, and flash-offloaded tiers under the device memory and accuracy budgets. This formulation retains access to the full context, removes the circular dependency of reactive eviction, and admits a closed-form solver that selects tier boundaries and per-layer ranks at runtime. Across eight text, vision, and audio models on three mobile SoCs, TierKV improves prefill throughput by up to 17.6x over existing mobile LLM frameworks, reduces RAM-resident KV cache by 12.5-34%, thereby enabling substantially longer contexts under the same memory budget, while incurring only minor accuracy degradation.

## 1. 核心问题与整体含义

- **研究动机**：LLM 正从云端迁移至移动设备，文本、图像、视频、音频等应用常需要长上下文。长上下文使 KV 缓存随序列长度线性增长，并在每个解码步被读取，成为端侧推理的主要内存瓶颈。
- **端侧约束尤为严苛**：移动 SoC 内存带宽低于服务器 GPU，且与 OS、系统服务共享 DRAM。以 OnePlus 12（12 GB 物理 RAM）为例，系统强制预留约 4.7 GB，稳定可用预算仅约 6.8 GB；Llama-3.2-3B 在 32K 上下文下仅 KV 缓存就需约 1.8 GB。超出预算会触发 Low Memory Killer（LMK）直接终止应用。
- **现有方案的三类痛点**：
  - 低秩压缩（SVD、xKV、PaLU、LoRC）：多依赖静态秩或按层深度选秩，且重建常发生在解码关键路径上，在 OnePlus 12 上平均增加约 30% 计算开销。
  - 令牌驱逐（H2O、SnapKV 等）：造成不可逆信息丢失，长程依赖任务上质量下降明显。
  - 闪存卸载：受带宽与闪存延迟限制；MHA2MLA 等潜注意力转换虽省内存，但引入随上下文线性增长的逐 token GEMV，实测在 100/900 token 时吞吐分别下降 46%/75%。
- **整体含义**：论文将移动端 KV 缓存管理重构为“预测式资源分配”问题而非事后压缩决策——在解码前预测请求的缓存需求，联合决定 token 的存储层级，从而在内存、精度与延迟之间取得更好的平衡。

## 2. 方法论

### 2.1 核心思想：预测式多层级缓存优化（PMCO）

- **三层缓存抽象**（沿序列维度由两个边界 $n$、$m$ 划分）：
  - **Tier-0（精确）**：token $t \in (0, n]$ 保持 FP16 不压缩，保护对压缩敏感的位置（如 attention-sink 早期 token）。
  - **Tier-1（压缩）**：token $t \in (n, m]$ 以 SVD 低秩形式驻留内存，采用逐层秩 $R_l$。
  - **Tier-2（卸载）**：token $t \in (m, L]$ 存放于闪存，保持全秩（仅占磁盘，不占 RAM），限制内存增长。
- **完整上下文保留**：不同于驱逐，三层设计不永久丢弃任何 token，避免反应式驱逐的循环依赖。

### 2.2 问题形式化

- 解码步延迟由三段构成：$T_{total} = T_{attn}(n) + T_{svd}(m-n, R) + T_{io}(L-m)$。
- 常驻内存：$M_{total} = M_w + M_{buf} + M_{T0}(n) + M_{T1}(n,m,R)$，Tier-2 不计入。
- 优化目标：
  - $\min_{n,m,R} T_{total}(n,m,R)$
  - s.t. $M_{total} \le M_{limit}$，$0 < n < m \le L$，$\mathcal{F}(n,R) \ge \text{AccThreshold}$。
- **解空间**：由于 $\{R_l\}$ 离线校准，在线决策空间为 $O(L^2 \cdot |\mathcal{R}|)$；精度主要由压缩等级与精确比例决定（可回归拟合），给定 $R$ 后延迟与内存对 $(n,m)$ 近似仿射，问题退化为几何问题。

### 2.3 预测式缓存配置

- **训练无关的长度预测**：
  - 复用 prefill 阶段已产生的隐藏状态，以输出 logit 熵 $\mathcal{E}_t$ 作为重要性权重 $\alpha_t$，构造提示指纹 $z_{prompt} = \sum_t \alpha_t h_t$（借鉴 EGTP 思路）。
  - 在设备端历史数据库 $\mathcal{M}$ 上做 k-NN 余弦检索，对相似历史提示的输出长度取平均得到预测长度 $\hat{L}_{gen}$。
  - 无需离线训练或辅助模型参数。
- **线性化成本模型**：离线微基准测试 KQV GEMV、FFN GEMM、SVD 重建 GEMM 等约占 90% 计算量的核，得到 $T_{est}$、$M_{est}$ 的线性模型；精度拟合为 $A_{est}(R|L,n) = k_L \cdot R + b_L$。
- **闭式求解器**：对每个候选 $R$，归一化延迟与内存项并求平衡轨迹 $\alpha \cdot T_{est}/T_{max} = \beta \cdot M_{est}/M_{limit}$，化简为 $(n,m)$ 平面上的线性方程，与可行多边形求交得到候选 $(n^*, m^*)$；枚举全部 $R$ 取最低延迟可行解，在线耗时 <0.1s。随后执行可行性循环，若超预算则将 $m$ 逐步回退（更多卸载至 Tier-2）。

### 2.4 运行时设计

- **融合分裂路径注意力（Fused Split-Path Attention）**：
  - 采用 K/V 联合 SVD 分解，共享低秩潜空间 $Z_{SK}$。
  - 单一 online-softmax 外层循环同时处理精确块与压缩块；压缩块的 key 在片上 SRAM 重建（$K_{recon} = Z_{SK}^\top \cdot W_{uk}$），不写回全局内存。
  - **潜空间 V 累加**：因 $V_{rec} = Z_{SK}^\top W_{uv}$，将 $P \cdot V_{rec}$ 重结合为 $(P \cdot Z_{SK}^\top) \cdot W_{uv}$，先在潜空间累加 $O_{latent}$，层边界处仅做一次投影。V 路径复杂度从 $\mathcal{O}(L \cdot z \cdot d)$ 降至 $\mathcal{O}(L \cdot z + z \cdot d)$，在 Llama-3.2-1B、50% 秩下减少约 45% FLOPs；两步投影避免 GQA 下 $W_{uv}$ 按 query head 复制带来的 4× 参数膨胀。
- **执行流水线（I/O–计算重叠）**：
  - 观察：闪存预取产生的气泡按逐层固定节奏出现，可作为周期性计算资源而非一次性 scratch 窗口。
  - **非对称 K/V 调度**：延迟关键的 $K_{recon}$ 派发进气泡（softmax 依赖它）；潜空间 V 累加写入逐层缓冲，$O_{latent} \cdot W_{uv}$ 投影推迟到层边界，不占用气泡容量。
  - PMCO 选出的 $R$ 同时决定 Tier-1 内存、每块 $K_{recon}$ 成本及其对气泡的适配度，$K_2(R)$ 即在此重叠调度下测得。
- **自动调优内核**：针对 GEMM/GEMV 搜索 workgroup tile、SIMD 向量宽度、循环展开、跨步访问、本地缓存等参数，在目标设备上编译运行并用 L2 误差校验，1–4 次预热即可收敛（Adreno 740 与 750 收敛到不同的展开因子与访存模式）。
