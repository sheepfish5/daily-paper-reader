## 摘要
现代高性能 GPU 计算将张量划分为分块，以利用数据重用和并行性。单个分块计算会先于完整张量计算完成，从而为计算与通信的重叠创造机会。然而，计算与通信进度之间的不匹配会限制这些机会。当没有数据就绪时，通信会停顿；而当数据突发到达时，通信又可能滞后。通信还可能因消耗共享资源而拖慢计算，抵消重叠带来的收益。我们提出 Entwine，它协调分块计算顺序、细粒度通信和 SM 资源分配，以最小化整体完成时间。Entwine 重新排序分块计算，以更规律的节奏产生用于通信的数据。Entwine 将此调度与基于 SM 的细粒度通信相结合，以低延迟、低开销处理分块结果。由于通信内核也会消耗 SM 资源，Entwine 协调二者的分配，以在通信进度与计算减速之间取得平衡。在具有代表性的张量并行 LLM 工作负载上，Entwine 相比 cuBLAS+NCCL 实现了 1.232 倍的几何平均加速（最高 1.433 倍），并在几何平均上比最先进的重叠基线高出 3.1-9.8%。我们将在论文发表后开源我们的实现。

## Abstract
Modern high-performance GPU computations partition tensors into tiles to exploit data reuse and parallelism. Individual tile computations complete earlier than the full tensor computation, creating opportunities to overlap computation and communication. However, a mismatch between computation and communication progress can limit these opportunities. Communication stalls when no data is ready, and may lag when data arrives in bursts. Communication can also slow computation by consuming shared resources, offsetting the benefits of overlap.   We present Entwine, which coordinates tile computation order, fine-grained communication, and SM resource allocation to minimize overall completion time. Entwine reorders tile computation to produce data for communication at a more regular pace. Entwine couples this schedule with fine-grained SM-based communication to process tile results with low latency and low overhead. Since the communication kernel also consumes SM resources, Entwine coordinates their allocation to balance communication progress against computation slowdown. Across representative tensor-parallel LLM workloads, Entwine achieves a geomean speedup of 1.232x (up to 1.433x) over cuBLAS+NCCL, and outperforms state-of-the-art overlap baselines by 3.1-9.8% in geomean. We will open-source our implementation upon publication.

# Entwine 论文深度总结

## 1. 核心问题与研究动机

- **背景**：大语言模型（LLM）通过张量并行分布到多 GPU 上，层内 GEMM 的计算结果需要通过 ReduceScatter 等集合通信在设备间交换与归约。该通信在顺序执行下可占端到端延迟的 11.0%–40.2%（中位数 23.3%）。
- **机会**：高性能 GEMM 将输出划分为分块（tile），各分块完成时间不同，因此已完成分块可在整体 GEMM 结束前就启动通信，形成计算-通信重叠。
- **两个耦合挑战**：
  - **供给不规律**：按输出分区连续遍历时，生产者在较长区间内只计算本地保留分区，不产生需跨 GPU 传输的数据，造成通信"供给缺口"；分组通信（如 FlashOverlap 按波组释放）又会让已完成分块等待同组中无关输出。
  - **重叠与减速的权衡**：重排计算顺序可能降低数据重用，并发传输与归约又竞争 SM 资源与内存带宽，会拖慢后续分块生产。重叠收益必须超过计算减速代价。
- **整体含义**：论文主张将**分块生产顺序、分块级通信粒度、SM 资源共享**三者联合协调，并以**端到端延迟**（而非 GEMM 吞吐或通信尾延迟单独指标）作为优化目标。

## 2. 方法论

### 2.1 核心思想
Entwine 针对 GEMM–ReduceScatter 这一具体且广泛使用的实例，同时协调：交错式分块生产顺序、独立的细粒度分块通信、共享 SM 池下的资源分配，以最小化端到端完成时间。

### 2.2 关键技术细节

- **交错式生产顺序（Interleaved Production）**
  - 生产者按逻辑块顺序循环遍历各输出分区，使本地保留分块与需跨 GPU 传输的分块交替出现。
  - 映射公式：对逻辑位置为 `p` 的块，其目标 rank `d = p mod W`，分区内块索引 `ℓ = ⌊p/W⌋`（W 为 GPU 数）。
  - 所有 rank 使用相同映射，保证同一分块的贡献出现在对应逻辑位置，目的端任务顺序可跟随共同生产顺序。

- **独立分块通信（Independent Tile Communication）**
  - 每个通信任务归约一个输出分块，依赖各 rank 各一个生产者块提供的贡献，无需等待目的分区其余分块。
  - 生产者完成输出存储后发布完成信号 `F[r,d,t]`（system-scope release store）；消费者在读取前轮询本地与对端 flag（system-scope acquire load），经 CTA 同步后开始归约，保证读后于写。
  - 消费者块按 tile 索引递增顺序处理任务，块间独立推进，无需逐 tile 内核启动。
  - 归约单元为 128×128 输出 tile；生产者块覆盖 128×128 或 128×256 输出，使通信粒度与 GEMM 块形状解耦，保留数据重用。

- **共享 SM 执行与通信预算**
  - 一个计算内核与一个通信内核并发执行，共享同一 SM 池；块退出后资源可供任一内核的待处理工作使用。
  - **通信预算 `x`**：通信内核网格大小（即并发通信块上限），受分区 tile 数限制；线程数 `b` 控制块内并行度与资源需求。
  - 通信块在等待输入期间保留 SM 资源，因此预算必须为计算留出产能；网格大小在单次调用内恒定，但常驻通信块数随准入/完成动态变化，不固定预留 SM。
  - GEMM 运行于默认优先级流，归约内核运行于高优先级流，使待处理归约工作优先获得 SM 容量。

- **端到端优化**
  - 离线 profiling 联合评估 GEMM 配置、通信预算 `x` 与线程数 `b`，选择**并发执行下端到端延迟最低**的组合，而非仅优化 GEMM 吞吐或通信尾延迟。

- **通信带宽分析**
  - 远程读取量：`V_comm = (W−1)/W · MN·s`（s 为元素字节数）。
  - GEMM 延迟：`T_G(x,K) = 2MNK / Φ(x,K)`，其中 `Φ` 为并发执行下的实际吞吐（含通信导致的减速）。
  - 平均所需带宽：`B_req(x,K) = (W−1)/W · s·Φ(x,K) / (2K)`。
  - 结论：K 增大在不增加通信量的前提下延长计算窗口，降低所需带宽；较慢的 GEMM 也会降低所需带宽，因此配置选择必须看端到端延迟。

### 2.3 实现要点
- 原型基于 CUTLASS GEMM + CUDA 归约内核，面向 NVIDIA SM80 GPU、单 NVLink 域。
- 输出分区行数与输出宽度为 128 的倍数；部分输出与发布 flag 置于对称 CUDA IPC 堆，贡献与 flag 在所有 rank 的堆中偏移一致，归约器直接按偏移读取对端内存。
- 每次调用前重置 flag 并同步；GEMM 与归约内核在公共起始事件后于独立 CUDA 流上启动，内核启动用 CUDA Graphs 捕获以减少主机启动开销。
- 用自定义 CUTLASS thread-block swizzle 实现交错遍历；epilogue visitor 发布完成信号。

## 6. 主要结论与发现

- 在主套件 15 个负载上，Entwine 相比 cuBLAS+NCCL 实现 **1.232× 几何平均加速（最高 1.433×）**，在 13/15 负载上优于三种重叠基线；相比 FlashOverlap、Async-TP、FLUX 的几何平均延迟分别降低 8.88%、6.17%、2.96%。
- 重叠效率（无竞争 GEMM 时间 / 端到端延迟）几何平均达 **0.946**。
- 层级别：相比 FLUX 在 8K、16K 序列长度分别降低 8.1%、6.5%（4K 时 FLUX 低 5.8%）。
- 消融结论：交错顺序在 K=512 与 2048 分别带来 1.277× 与 1.267× 端到端改进（尾延迟降低 98.5% 与 97.6%）；tile 级释放优于分组/分区/整体释放；共享 SM 比静态分区在 K=2048 与 512 分别提升 1.185× 与 1.066×。
- 带宽匹配：所需与实测带宽最大差 3.0%、中位差 0.37%，说明所选配置能以约等于所需速率推进通信。
- 通信并发并非越大越好：更大预算可缩短通信尾，但可能因拖慢计算而使端到端延迟不再下降（如 K=768 时 32→48 CTA 尾延迟几乎消失但总延迟不变）。
- 适用区间：相比 FlashOverlap 的加速比在 1.19–2.37 波区间跨越 1，相比 FLUX 在 9.48–18.96 波区间跨越 1；并行宽度越大，Entwine 相对基线的几何平均优势越明显（对 FlashOverlap 从 2 GPU 的 1.0204× 增至 8 GPU 的 1.0975×）。

## 7. 优点

- **问题拆解清晰**：将重叠问题归纳为"供给规律性"与"重叠 vs 减速"两个耦合挑战，并分别给出机制。
- **粒度解耦设计**：分块级通信独立于 GEMM 块形状与更大通信组，避免等待无关输出，同时保留数据重用。
- **以端到端延迟为统一优化准则**：相比单独优化 GEMM 吞吐或通信尾延迟更贴合实际收益，并有带宽分析（式 4）解释配置行为。
- **资源共享而非静态划分**：共享 SM 池 + 通信预算 + 流优先级，比固定 SM 预留更适应执行过程中计算/通信需求的动态变化。
- **实验较全面且公平**：多 K、多形状、多并行宽度、波数范围扫描，逐项消融，基线使用原生实现并统一调优。
- **实现细节完备**：给出内存序（release/acquire + CTA barrier）、IPC 堆、CUDA Graphs、CUTLASS swizzle 等可复现细节，并承诺开源。
