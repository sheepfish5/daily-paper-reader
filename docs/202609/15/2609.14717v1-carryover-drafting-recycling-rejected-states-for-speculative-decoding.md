## 摘要
推测解码通过并行验证多个草拟 token 来加速 LLM 推理，使单次目标前向传播能够接受多个 token。从设计上，验证过程会为被接受和被拒绝的 token 都计算表示。然而，传统草拟器仅保留被接受 token 的表示，使得验证器在被拒绝 token 上花费的大量计算实际上被浪费。我们发现，这些在目标前向传播过程中生成但被丢弃的隐藏状态保留了关于未来 token 的有用信息，可改进后续草拟。然而，实现这一机会面临两个不同挑战。在推理阶段，回收开销会增加草拟延迟，从而削弱因接受长度增加而获得的加速。在训练阶段，标准并行草拟器训练不会产生与推理对齐的被拒绝状态，而通过顺序 rollout 获取这些状态又会牺牲跨训练位置的并行性。我们提出 Carryover Drafting，它同时解决这两个挑战。Carryover 将被拒绝的目标隐藏状态回收为临时 KV 上下文，使草拟器能够有选择地关注它们。它复用草拟器现有的接口，仅添加一个可学习嵌入来区分被拒绝状态与已提交上下文。额外的 KV 上下文在每轮草拟时被替换，使其长度以一个提议块为界。我们提出并行 草拟—验证—草拟 训练，使草拟器接触到与推理对齐的被拒绝状态，同时保持跨训练位置的并行性。在 DFlash 以及一个源自 DSpark 的半自回归草拟器上、跨两个目标模型进行的实验表明，这一简单的 Carryover 机制相比相应基线将平均接受长度提高了 6.5--14.7%，将端到端 vLLM 加速提高了 7.9--14.4%，在翻译任务上加速增益达到 28.8%。

## Abstract
Speculative decoding accelerates LLM inference by verifying multiple drafted tokens in parallel, allowing a single target forward pass to accept several tokens. By construction, verification computes representations for both accepted and rejected tokens. Yet, conventional drafters retain only the representations of accepted tokens, leaving the substantial verifier computation spent on rejected tokens effectively wasted. We find that these discarded hidden states generated during target forward retain useful information about future tokens that can improve subsequent drafts. However, realizing this opportunity poses two distinct challenges. At inference, recycling overhead can increase drafting latency, diminishing the speedup gained from increased acceptance length. During training, standard parallel drafter training does not produce inference-aligned rejected states, while obtaining them through sequential rollouts would sacrifice parallelism across training positions. We introduce Carryover Drafting, which addresses both challenges. Carryover recycles rejected target hidden states as temporary KV context, allowing the drafter to selectively attend to them. It reuses the drafter's existing interface and adds only a single learned embedding to distinguish rejected states from committed context. The additional KV context is replaced each drafting round, keeping its length bounded by one proposal block. We introduce parallel draft--verify--draft training that exposes the drafter to inference-aligned rejected states while preserving parallelism across training positions. Experiments with DFlash and a DSpark-derived semi-autoregressive drafter across two target models show that this simple Carryover mechanism improves average acceptance length by 6.5--14.7% and end-to-end vLLM speedup by 7.9--14.4% over the corresponding baselines, with speedup gains reaching 28.8% on translation.

## 一、核心问题与研究动机

- **背景**：自回归 LLM 每个前向传播只生成一个 token，推理速度受限于串行生成。推测解码（Speculative Decoding）通过让轻量 drafter 一次提出多个 token，再由 target 在一次前向传播中并行验证并接受多个 token 来加速。
- **核心矛盾**：验证过程（verification）在构造上会为**被接受**和**被拒绝**的 token 都计算隐藏状态，但传统 drafter（如 EAGLE、EAGLE-3、DFlash、DSpark）**只保留被接受 token 的表示**，被拒绝 token 的隐藏状态被直接丢弃，导致大量验证器计算被浪费。
- **关键洞察**：作者发现被丢弃的隐藏状态中保留了关于未来 token 的有用信息，可用来改进后续轮次的草拟质量。
- **两大挑战**：
  - **推理阶段**：回收开销（投影 + 注意力）会增加草拟延迟，可能抵消接受长度增加带来的加速；若跨轮保留被拒绝状态，KV 上下文会无限增长。
  - **训练阶段**：标准并行 drafter 训练基于录制的 target 响应，无法产生与推理对齐的被拒绝状态；若用顺序 rollout 获取，又会牺牲跨训练位置的并行性。
- **整体含义**：本文提出一种低开销、低接口改动的机制，把"被拒绝状态"从废弃物转化为可复用的草拟上下文，同时保持训练并行性。

## 二、方法论：Carryover Drafting

### 2.1 核心思想
将被拒绝的目标隐藏状态回收为**临时 KV 上下文**，通过 drafter **已有的投影接口**注入，使 drafter 用现有注意力层选择性地关注它们；每轮草拟替换该上下文，长度以一个提议块（B 个 token）为界。

### 2.2 关键技术细节

- **复用现有接口**：设第 r 轮 target 隐藏状态为 $H_r=(h_{r,1},...,h_{r,B})$。若接受 $m_r$ 个 token，则
  - $H^{acc}_r = h_{r,1:m_r}$（已接受），$H^{rej}_r = h_{r,m_r+1:B}$（被拒绝）
  - 沿用已有投影 $F$ 和每层 $K^\ell, V^\ell$：$\Phi^\ell(H) = (K^\ell(F(H)), V^\ell(F(H)))$
- **回收方程**：
  - $U_{r+1,\ell} = \Phi^\ell(H^{rej}_r + E_{carry})$
  - $ctx_{r+1,\ell} = [C_{r+1,\ell}; U_{r+1,\ell}]$
  - 其中 $C$ 为已提交的 drafter KV 上下文，$E_{carry}$ 为唯一新增的可学习嵌入（用于区分被拒绝状态与已提交上下文）。
- **轻量性设计**：
  - 仅增加一个嵌入，无额外门控/投影模块（消融显示专用投影器仅略优，故不采用）。
  - 被拒绝状态为**只读上下文**，不替换已接受 token 的隐藏状态，也不进入 target KV cache。
  - 每轮验证后**替换**上一轮的 carried-over 上下文；全接受时为空，附加上下文始终以 B 行为界。

### 2.3 并行 draft–verify–draft 训练

- 在每条录制的 target 响应 $y$ 上随机采样锚点 $a_i$（每响应 512 个）。
- **第一步（无梯度）**：drafter 生成 detached 提案 $d_i$。
- **第二步（冻结 target 验证）**：用块对角因果掩码并行验证各分支，贪心验证返回接受长度 $m_i$ 与 detached 的被拒绝隐藏状态 $H^{rej}_i$。
- **锚点移位**：$a'_i = a_i + m_i + 1$（下一个修正或 bonus 位置）。
- **第三步（有梯度）**：第二次 drafter pass 读取 $a'_i$ 处的录制前缀，接收 $H^{rej}_i$（经公式 2），对录制续写做监督；梯度只流经第二次草拟（含共享投影与 carryover 嵌入）。
- 全接受时 $H^{rej}_i=\emptyset$，退化为基线训练，仍保留监督信号。
- 关键点：**每个锚点的 transition 独立构造，训练仍跨位置并行**，且不新增 target 采样数据。

### 2.4 推理/加速模型
- 延迟与加速近似为：$L_{carry} \approx (t_{draft}+t_{verify}+t_{reuse})/\tau$，$S_{carry} \approx \tau \cdot t_{AR}/(t_{draft}+t_{verify}+t_{reuse})$。
- 说明加速需同时提高接受长度并压低 $t_{reuse}$（回收开销）。

## 六、主要结论与发现

- **主结果**：平均接受长度提升 **6.5–14.7%**，端到端 vLLM 加速提升 **7.9–14.4%**（相对对应 baseline）；翻译任务加速最高 **28.8%**（Qwen3-4B Markov，T=1）。
- 在所有 8 个数据集、2 个 target、2 种温度下接受长度均有提升；从 DFlash 到 Markov 依然有效，说明与块内依赖建模互补。
- 并发 1→32 时，两者加速均下降，但 Carryover 始终保持相对 baseline 的优势。
- **机制发现**：
  - 回收 **target 隐藏状态** 明显优于回收草拟 token 或 target token 提示。
  - 单一 carryover 嵌入几乎达到专用投影器的效果，且无需额外投影模块。
  - 被拒绝状态的有效性更依赖 **re-convergence**（是否预测到最终被提交的 token），而非被拒绝后缀长度或拒绝后接受率（归一化重收敛与数据集增益相关系数 r=0.96，去除翻译为 0.90；拒绝后接受仅 0.52/0.71）。
  - Markov 比 DFlash 产生更多重收敛位置（2.76 vs. 2.51），并在 8 个数据集中的 7 个获得更大增益，暗示更强的 drafter 会留下更有用的被拒绝状态。
  - 注意力诊断显示约 **19.78%** 的全 softmax 注意力落在 carried rows 上（15-rejected 子集为 23.40%），证明该接口被实际读取。

## 七、优点

- **接口极轻量**：只新增一个嵌入、复用全部现有投影，几乎不改变原 drafter 架构，易集成到现有 block diffusion drafter。
- **上下文有界**：每轮替换、长度以 1 个 proposal block 为界，避免 KV 无限增长；被拒绝状态只作只读上下文，不污染 target KV cache，保持推测解码分布正确性。
- **训练并行性保持**：并行 draft–verify–draft 在保持跨锚点并行的前提下获得推理对齐的被拒绝状态，避免顺序 rollout 的并行性损失，且不新增 target 采样数据。
- **理论与工程兼顾**：给出延迟/加速模型解释回收开销为何可被接受长度收益覆盖；说明为何验证仍保持目标分布有效。
- **分析扎实**：不仅报告接受长度与端到端加速，还用 matched-anchor recall、重收敛统计、注意力可视化解释"为什么有效、何时更有效"。
- **覆盖面较广**：两种 target、两种 drafter 范式、8 类任务、两个温度、多档并发，结果一致性较强。

- **未评估 confidence scheduling**：DSpark 式自适应验证长度会改变可用的被拒绝状态，作者承认需在同一调度策略下训练并重新校准阈值，故本文未做联合评估，限制了在高并发场景的实际部署结论。
- **未覆盖树解码**：与 Medusa、DDTree 等树验证结合时的分支选择策略未解决，留作未来工作。
- **仅单轮保留**：并行训练不支持超过一轮的保留；文中提到若已有 target 辅助 rollout（如 Draft-OPD）才可能实现多轮保留。
- **训练算力未披露**：未给出训练 GPU 数量、时长或总算力，难以复现和评估训练成本。
- **消融规模有限**：接口消融仅在小规模 probe（约 40K 样本、6 epoch、Qwen3-4B Markov）上进行，且未完全解耦"信息内容"与"注入方式"的影响。
- **部分机制结论为相关性**：重收敛与增益的高相关（r=0.96）是数据集层面的关联，非因果证明；翻译任务增益显著更高，可能存在任务/数据分布偏差。
- **对比范围**：仅与 DFlash、DSpark 衍生 Markov 对比，未与 EAGLE-3、Token Recycling、SD²、Lyanna 等其他回收/引导类方法直接比较。
- **依赖固定验证长度**：为公平比较关闭

- **依赖固定验证长度**：为公平比较关闭了 confidence scheduling、固定验证长度，因此结论主要适用于固定长度验证场景；在自适应验证长度（如 DSpark 的 confidence 调度）下，被拒绝状态的数量与分布会随轮次动态变化，增益是否保持、阈值是否需要重新校准尚不清楚，限制了向生产级高并发部署的直接外推。
- **评估语种与领域偏置**：benchmark 以英文任务为主，翻译虽覆盖多语但仅作为其中一类；对低资源语言、超长文档、多模态等场景的泛化能力未验证。
- **未与正交加速技术联合**：未探讨与量化、KV cache 压缩、多候选并行解码等其他推理优化叠加时的收益；实际部署中这些技术常同时启用，组合效果未知。
- **实现与硬件依赖**：延迟/加速结论基于单张 H200 的 vLLM 实现，回收开销 $t_{reuse}$ 对 kernel 融合与内存带宽较敏感，换到其他硬件或推理框架时结论可能变化。

## 九、总体评价与启示

- **定位**：本文属于"推测解码草拟质量改进"分支，与 EAGLE-3 的特征复用、Token Recycling、SD² 等思路同源，但切入点独特——不提升 drafter 容量或增加训练数据，而是把验证阶段已经算出、原本被丢弃的被拒绝隐藏状态回收为临时上下文。
- **贡献层级**：主要贡献为机制设计 + 训练对齐 + 系统级验证，属"小而美"的增量式改进；工程改动面小、与现有 block drafter 兼容，落地门槛低。
- **方法学价值**：并行 draft–verify–draft 训练范式最具复用价值——它把"推理时才能获得的状态"以保持训练并行性的方式引入训练，可迁移到其他需要推理对齐状态的 drafter 训练中。
- **证据强度**：主结果覆盖 2 target × 2 drafter × 8 数据集 × 2 温度，一致性较好；机制解释有 recall、重收敛、注意力三类分析支撑，但部分为相关性证据，消融规模偏小。
- **实践建议**：若已在用 DFlash/DSpark 类 block drafter，可在不改验证流程的前提下以极小改动接入 carryover 嵌入，优先在翻译、摘要等增益较高任务上验证；同时需重新测量 $t_{reuse}$ 与接受长度的净收益，并注意当前未支持 confidence scheduling 与树解码。
