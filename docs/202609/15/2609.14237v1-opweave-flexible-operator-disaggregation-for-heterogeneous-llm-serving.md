## 摘要
LLM 服务系统正日益将推理拆分为更细粒度的阶段，近期方法在解码阶段将注意力与 FFN 或 MoE 执行分离。这种算子级解耦服务（ODS）能够改善硬件匹配并实现独立扩展，尤其是在异构设备上。然而，现有系统固定了算子边界，并且缺乏对何时解耦能够降低服务成本的统一刻画。我们提出 OpWeave，一个面向异构 ODS 的端到端框架。OpWeave 提供了一种分析成本模型，可界定同构与异构 ODS 相对于共置服务所能获得的收益。它通过一个规律性感知的规划器联合优化算子划分与部署配置，即使对于混合注意力模型也能使搜索保持可处理。一个基于 vLLM 的运行时可在异构设备组上以灵活的算子阶段执行所合成的计划。在我们的评估中，相对于最佳可行基线，OpWeave 在同构 GPU 集群上最多将服务成本降低 1.78 倍，在异构 GPU 集群上最多降低 1.89 倍，同时满足延迟 SLO。

## Abstract
LLM serving systems increasingly disaggregate inference into finer-grained stages, with recent approaches separating attention from FFN or MoE execution during decode. This operator-level disaggregated serving (ODS) can improve hardware matching and enable independent scaling, particularly across heterogeneous devices. However, existing systems fix operator boundaries and lack a unified characterization of when disaggregation reduces serving cost. We present OpWeave, an end-to-end framework for heterogeneous ODS. OpWeave provides an analytical cost model that bounds the gains of homogeneous and heterogeneous ODS over colocated serving. It jointly optimizes operator partitioning and deployment configuration through a regularity-aware planner that keeps the search tractable even for hybrid-attention models. A vLLM-based runtime executes the synthesized plans with flexible operator stages across heterogeneous device groups. In our evaluation, OpWeave reduces serving cost by up to $1.78\times$ on homogeneous and $1.89\times$ on heterogeneous GPU clusters relative to the best feasible baseline, while meeting latency SLOs.

# OpWeave 论文总结

## 1. 核心问题与整体含义
- **背景**：LLM 推理服务成本高，解码阶段逐渐成为生成型负载的主要开销来源。现有系统多采用 prefill–decode 解耦，近期进一步在 decode 内将 attention 与 FFN/MoE 分离，形成算子级解耦服务（ODS）。
- **核心矛盾**：
  - 共置服务存在**硬件错配**：decode attention 受内存带宽限制、tensor core 利用率低；FFN/MoE 是 GEMM 密集、受益于高算力。
  - 共置服务存在**显存容量耦合**：长上下文下 KV cache 膨胀，压缩全局可行 batch size，拖累 FFN/MoE 吞吐。
  - 现有 ODS 系统如 AFD 固定 attention–FFN/MoE 边界，缺乏统一理论刻画，也难适配混合注意力模型中的层间异构。
- **整体含义**：OpWeave 提出端到端异构 ODS 框架，连接解析成本模型、部署规划器与 vLLM 运行时，支持任意连续算子划分与异构设备组执行，目标是在满足 TPOT SLO 下最小化每 token 服务成本。

## 2. 方法论
- **核心思想**：将 decode 计算按算子序列划分为多个阶段，阶段可跨层边界，并分配到不同 GPU 类型/并行策略/副本上；联合优化算子划分、硬件分配、并行度、batch 与 microbatch、流水调度。
- **理论分析**：
  - 使用 roofline 模型，定义 attention 为内存受限、GEMM 类算子为计算受限。
  - 同构 ODS 成本：`CPT_hom_j(s)=α_j m_kv(s)+2γ_j P_act`；异构 ODS：`CPT_het_j,k(s)=α_j m_kv(s)+2γ_k P_act`。
  - 共置成本含 `max(权重加载, GEMM 计算)`，GEMM 计算受限阈值 `b*=M_weights F/(2P_act β)`。
  - 定理 3.1：同构 ODS 仅在 KV cache 压力使共置 batch 低于 `b*` 后产生收益，收益随序列长度严格递增，上界为 `M/(M-M_weights)`。
  - 定理 3.2：异构收益仅在两种 GPU 于带宽效率与算力效率上形成权衡时出现；收益关于 KV 流量单峰，上界为 `(1+√η)/2`，其中 `η=(β1F2)/(β2F1)`。
  - 指出 CAD 的两大限制：阶段延迟范围可能无法重叠导致流水气泡；混合注意力层间差异使固定两阶段划分难以平衡。
- **规划抽象与算法**：
  - 引入 **partition block**：最小层对齐重复算子模式；在 block 内选择连续 stage template，并复用于所有 block。
  - 进一步用 **sub-block template** 降低搜索空间：在每个子块内选 `K` 个 owner 的连续模板，平铺到整个 partition block，`S=nK`。
  - 结构化放置：阶段按 round-robin 映射到有序设备组类型，每类型拥有固定阶段位置。
  - 优化目标：`min T_rtt Σ c_m/b_m`，约束 `T_rtt ≤ T_SLO` 与每副本权重+KV 显存约束。
  - 搜索：构造每个 owner 的 **network-safe Pareto frontier**，支配关系比较阶段延迟向量、归一化成本、GPU 数、microbatch size；再用**精确 branch-and-bound** 在 frontier 乘积上剪枝，只有存活候选进入调度模拟器。
- **运行时**：
  - 基于 vLLM，32K 行 Python/C++，每个 worker 只加载分配到的模型组件。
  - 优化包括：单次 native submission 提交整段 CUDA graph/通信/事件依赖；GPU 驻留解码，token ID 在 GPU 上生成并经 NCCL all-reduce 分发；低开销通信，打包张量、批量 NCCL、leader fanout + CUDA IPC。
