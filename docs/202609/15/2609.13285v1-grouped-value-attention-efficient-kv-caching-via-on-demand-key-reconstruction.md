## 摘要
KV 缓存是 Transformer 解码的主要瓶颈：其内存占用和缓存读取流量随序列长度增长。分组查询注意力（GQA）通过共享键值头降低该开销，但在每一步仍同时存储键和值。我们提出分组值注意力（GVA），它存储分组值，并用学习到的线性映射重建内容键。在推理时，该映射可被吸收到查询中，从而在预期的解码路径中无需物化内容键。一个小的共享解耦 RoPE 通道通过单独缓存的位置键保留位置信息。在所研究的配置中，相对于匹配的 GQA，该表示将持久缓存标量数量减少约 45–47%。在 3.5 亿参数规模、使用 300 亿 FineWeb-Edu token 训练时，16 维位置变体在五项任务上达到 44.18 的平均准确率，而 GQA 为 44.36，MLA 为 43.88。这些结果表明，在更紧凑的缓存表示下，基准准确率接近 GQA。为了将这种紧凑表示转化为更快的自回归推理，我们开发了自定义解码内核，目前正在评估其端到端推理性能，并计划不久后开源发布。

## Abstract
The KV cache is a primary bottleneck for Transformer decoding: its memory footprint and cache-read traffic grow with sequence length. Grouped-query attention (GQA) reduces this cost by sharing key-value heads, but still stores both a key and a value at every step. We introduce Grouped Value Attention (GVA), which stores grouped values and reconstructs content keys with a learned linear map. At inference, the map can be absorbed into the query, eliminating the need to materialize content keys in the intended decode path. A small shared decoupled RoPE channel retains positional information through a separately cached positional key. For the configurations studied, this representation reduces persistent cache scalars by approximately 45-47% relative to matched GQA. At the 350M-parameter scale with 30B FineWeb-Edu tokens, the 16-dimensional positional variant reaches 44.18 average accuracy across five tasks, compared with 44.36 for GQA and 43.88 for MLA. These results demonstrate near-GQA benchmark accuracy with a more compact cache representation. To translate this compact representation into faster autoregressive inference, we have developed custom decoding kernels and are currently evaluating their end-to-end inference performance with an open-source release planned soon.

## 1. 核心问题与整体含义

- **研究动机**：Transformer 自回归解码时，KV 缓存随序列长度线性增长，成为长上下文服务中的显存容量与内存带宽瓶颈。
- **现有方案**：
  - **MHA**：每个头独立缓存 K 和 V，缓存量最大。
  - **MQA**：所有查询头共享一个 KV 头，缓存显著减小，但质量与训练稳定性可能下降。
  - **GQA**：折中方案，将查询头分组、每组共享一个 KV 头，但**每一步仍同时缓存键和值**，缓存仍是两条流。
  - **MLA**：将 K 和 V 压缩为联合低秩 latent，并加一个小 RoPE 切片；缓存更小，但引入额外投影，解码路径更复杂。
- **整体含义**：论文提出 **Grouped Value Attention（GVA）**，只持久缓存分组后的 **value**，再用学习到的线性映射按需重建内容 key。其核心观点是：value 已经承载了要聚合的内容信息，key 只是用于打分；因此可以只缓存 value，把 key 重建成本转移到推理时可吸收的线性变换中，从而在保持接近 GQA 精度的同时大幅压缩缓存表示。

## 2. 方法论：核心思想、关键技术细节与算法流程

- **核心思想**：
  - 在 GQA 分组基础上，设 \(H\) 个查询头、\(G\) 个 value 组、头宽 \(d_h\)。
  - 不再缓存 grouped key，而是对每个查询头 \(h\) 学习一个线性映射 \(M_h\)，从对应组的 value 重建内容 key：
    \[
    K_h = V_{g(h)} M_h,\quad M_h \in \mathbb{R}^{d_h \times d_n}
    \]
  - 其中 \(g(h)\) 是查询头 \(h\) 所属的 value 组，\(d_n\) 是内容 key 宽度。
- **推理时吸收**：
  - 因为 \(M_h\) 在推理时固定，内容打分可以改写为：
    \[
    q_h k_{j,h}^\top
    = q_h (v_{j,g(h)} M_h)^\top
    = (q_h M_h^\top) v_{j,g(h)}^\top
    = \tilde{q}_h v_{j,g(h)}^\top
    \]
  - 其中 \(\tilde{q}_h = q_h M_h^\top\) 只需对当前查询 token 计算一次。
  - 因此解码路径**不需要物化内容 key 张量**，注意力只读取 value 缓存。
- **RoPE 兼容问题**：
  - 标准 RoPE 对查询和重建 key 施加位置旋转后，相对旋转依赖查询位置 \(t\) 与缓存位置 \(j\)，无法折叠进单一查询变换：
    \[
    q_t^{\text{rot}} (k_j^{\text{rot}})^\top
    = q_t R_{j-t} M^\top v_j^\top
    \]
  - 因此普通 RoPE 会破坏吸收。
- **解耦 RoPE 设计**：
  - 采用 DeepSeek MLA 式解耦 RoPE：
    - 内容切片：无旋转，宽度 \(d_n\)，由 value 重建：
      \[
      k^{\text{nope}}_{j,h} = v_{j,g(h)} M_h
      \]
    - 位置切片：旋转，宽度 \(d_r\)，且**跨头共享**：
      \[
      k^{\text{rope}}_j = (x_j W_r) R_j^\top
      \]
  - 分数为：
    \[
    q k_j^\top = q^{\text{nope}} (k^{\text{nope}}_j)^\top
    + q^{\text{rope}} (k^{\text{rope}}_j)^\top
    \]
  - 第一项仍可吸收；第二项使用已缓存、已旋转的共享位置 key，从而保留相对位置信息。
- **缓存大小**：
  - GQA：
    \[
    N_{\text{GQA}} = 2 T G d_h
    \]
  - GVA + 解耦 RoPE：
    \[
    N_{\text{GVA}} = T G d_h + T d_r
    \]
  - 相对比例：
    \[
    \frac{N_{\text{GVA}}}{N_{\text{GQA}}}
    = \frac{1}{2} + \frac{d_r}{2 G d_h}
    \]
  - 论文报告，在其实验配置下，持久缓存标量减少约 **45–47%**；若省略位置切片，则理想上可减半。
- **初始化与训练细节**：
  - 由于 \(K = VM\) 是“投影的投影”，默认初始化可能使 key 的尺度远低于 query，导致注意力近似均匀。
  - 论文提出尺度匹配初始化：
    \[
    M_{ij} \sim \mathcal{N}\left(0,\frac{\sigma_Q^2}{\sigma_V^2 d_{\text{in}}}\right)
    \]
    使初始 key 的 RMS 接近 query 的 RMS。
  - 可选使用 query RMSNorm；训练时仍使用标准因果注意力，位置与内容切片分别处理。
- **算法流程概要**：
  1. 计算当前 query 和 value。
  2. 将新 value 追加到 grouped value 缓存。
  3. 计算共享旋转位置 key 并追加到位置缓存。
  4. 对每个查询头，将内容 query 吸收为 \(\tilde{q}_h = q_h^{\text{nope}} M_h^\top\)。
  5. 用 \(\tilde{q}_h\) 对 value 缓存打分，用旋转 query 对共享位置 key 打分，二者相加。
  6. softmax 后对 value 缓存加权求和，得到各头输出。
