## 摘要
在专家混合（MoE）模型的单GPU长上下文推理中，需要将键值缓存（KVCache）溢出到CPU内存。溢出的KV有两个互补用途——传输到GPU进行注意力计算，或在CPU上原地计算——它们对物理状态的要求相反。二者之间的最优拆分比例随工作负载变化，但现有KVCache抽象仅对单一物理状态的单体对象提供存储语义，无法表达动态负载均衡。我们提出InplaceKVCache，这是首个在写入时即固定每个字节物理驻留状态的KVCache抽象，从而在放置后无需移动数据即可调整CPU-GPU负载均衡。它通过沿设备亲和性与访问模式两个维度的四区域布局实现这一点，将负载均衡转化为纯粹的调度问题。基于该抽象，WriteScope沿序列维度划分CPU-GPU份额，并使用可移植的roofline性能模型确定随序列长度变化的最优CPU份额，同时通过在线反馈跟踪CPU开销漂移。在三种MoE模型（DeepSeek-V2-Lite、Qwen3-30B-A3B、Mixtral-8×7B）上，在32 GB显存预算下，WriteScope支持总规模达100万token的端到端推理。在长上下文场景（≥8K）中，相比四个复现基线，它在A100上取得1.5×–2.5×的几何平均加速，在V100上取得1.4×–1.7×的加速，而vLLM、SGLang和KTransformers即使在KV预算翻倍时仍失败。一项DeepSeek-V4-Flash案例研究验证了其与原生稀疏注意力的组合。

## Abstract
Single-GPU long-context inference with Mixture-of-Experts (MoE) models requires spilling the key-value cache (KVCache) to CPU memory. The spilled KV serves two complementary purposes---transferring to the GPU for attention computation, or computing in-place on the CPU---which demand opposing physical states. The optimal split between them varies with workload, yet existing KVCache abstractions offer only storage semantics over a monolithic object of a single physical state, and cannot express dynamic load balancing. We propose InplaceKVCache, the first KVCache abstraction whose format fixes each byte's physical residency at write time, so that the CPU--GPU load balance can be adjusted without moving data after placement. It realizes this as a four-region layout along two dimensions---device affinity and access pattern---turning load balancing into pure scheduling. Built on this abstraction, WriteScope splits CPU--GPU shares along the sequence dimension, and a portable roofline performance model determines the optimal CPU share as sequence length evolves, with online feedback tracking CPU cost drift. On three MoE models (DeepSeek-V2-Lite, Qwen3-30B-A3B, Mixtral-8$\times$7B) with a 32~GB VRAM budget, WriteScope supports end-to-end inference at the 1M-token aggregate scale. In the long-context regime ($\ge$8K), it achieves geometric-mean speedups of $1.5\times$--$2.5\times$ on A100 and $1.4\times$--$1.7\times$ on V100 over four reproduced baselines, while vLLM, SGLang, and KTransformers fail even with a doubled KV budget. A DeepSeek-V4-Flash case study validates composition with native sparse attention.

## 2. 方法论

### 2.1 核心思想：写入时原则（Write-time Principle）
- 一个字节**有且只有一个最终物理驻留状态**，且该状态在**写入时**确定；物理归属由此成为**数据格式属性**而非运行时机制，负载均衡无需事后重组。
- 可行性依据：KVCache的消费是**确定性的**（不同于随机专家激活，后者只能在调度时仲裁）。

### 2.2 InplaceKVCache：四区域布局
沿两个正交维度划分——**设备亲和性 × 访问模式**：

| 区域 | 位置 | 属性 |
|---|---|---|
| Unpinned compute region | CPU | 非锁定，CPU就地计算 |
| Pinned load region | CPU | cudaHostAlloc，连续DMA源 |
| D-window offload region | GPU | 新decode KV暂存 |
| Ping-pong compute region | GPU | 覆写复用式流式加载 |

- **块（block）是统一粒度**：写入时路由、暂存、驱逐、传输共用同一粒度。

### 2.3 写入时路由流程
- **Prefill KV**：批量生成，一次性路由到最终区域（整prompt prefill无均衡问题，每层KV产生即被消费并沿空闲的D2H方向送走）。
- **Decode KV**：先进入GPU的D-window，**零H2D成本**参与GPU计算；累积 **D=256**（块大小整数倍）后整批驱逐到unpinned或pinned区，由roofline策略决定。
- **D2H方向空闲**（流水线只消耗H2D），全双工PCIe把写回隐藏在专家阶段；D在256–1024内稳态开销不变，故D是**路由粒度而非决策单元**。
- **放置后永不移动**：ping-pong区一次创建长期复用（块大小与骨架不变，仅替换数据）；CPU侧保有完整KV备份，覆写不丢数据。CPU与GPU的部分输出通过 **LSE重标定**合并，每步一次join。

### 2.4 接口与语义
- `PartitionSpec`（roofline参数、四区域、块粒度、驱逐批量）+ 四个薄操作：`init` / `append` / `views` / `flush`。
- 保证四条语义：无临时单体状态；物理隔离（各引擎只读自己区域）；零拷贝视图；精确性（无压缩/稀疏化）。

### 2.5 稀疏选择兼容
- 块对齐格式天然支持块级top-k：在load区预留staging buffer，把离散块聚合成一个连续段，一次全带宽DMA；gather带宽35.1GB/s > H2D 25.4GB/s，可被流水线隐藏。

### 2.6 负载均衡调度（公式用文字说明）
- **沿序列维切分**（而非head维）：head维在GQA下被KV头数量化（Qwen3仅4个），在MLA下共享latent而定义不清；序列维使比例连续。
- **引擎延迟模型**：
  - `T_CPU(r) = r·A·L + C_CPU`
  - `T_GPU(r) = (1-r)·B·L + C_GPU`
  - 其中A为CPU每token有效读成本，B为GPU每token传输成本（计算被传输掩盖），C为固定每步开销。
- **最优份额**：令 `T_CPU = T_GPU`，得
  `r(L) = min(1, max(0, B/(A+B) + Δ/((A+B)·L)))`，`Δ = C_GPU − C_CPU`。
  - 长序列由 `B/(A+B)` 决定收敛值，短序列由 `Δ/((A+B)L)` 刻画过渡；钳制到0/1处理无需均衡的极端配置。
- **参数处理**：B一次离线标定（格式保证每次传输形状相同：固定大小、布局、pin状态）；A随工作集与缓存局部性漂移，通过**在线滑动平均**回推（256步跨多层的采样已足够准确）。
- **边际份额策略**：不冻结固定比例，而是让连续驱逐批次的**累计CPU占比**逼近 `p = B/(A+B)`；累计份额按 `R(L) = p + (R(L0) − p)·L0/L` 移动，收敛取决于**批次几何而非统计**，初始误差在最初几个批次内衰减。初始份额 `R(L0)` 由离线标定（分钟级）给出。
