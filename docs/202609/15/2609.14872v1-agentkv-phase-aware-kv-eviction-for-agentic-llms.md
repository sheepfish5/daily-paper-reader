## 摘要
智能体式服务消耗的 token 数量可比聊天机器人负载高出若干数量级，给 KV 缓存容量与解码时带宽都带来压力。大多数 KV 驱逐方法以取自最近 token 的代表性查询对缓存键打分，其假设是未来的注意力与近期注意力相似。我们表明，智能体式生成违背了这一假设：未来的查询是 think、act、tool 及其他阶段的混合，主角度分析表明这些成分占据可测量的不同查询子空间，因此基于近期性的代表会系统性地低估即将到来的阶段所需的键。我们提出 AGENTKV，它为每个阶段维护一个小型查询缓冲区，并以这些缓冲区的并集对缓存键打分。我们进一步将 AGENTKV 实现于持久化的多轮服务路径中，该路径在轮次之间传递压缩的 KV 状态，并在线整理保留的 KV 页。在两种模型、六个任务领域以及每种三种 KV 预算的设置下，AGENTKV 的任务得分平均比 R-KV 高 5.5 分，比 Tri-attention 高 5.3 分。相对于上游的全 KV SGLang，AGENTKV 将输出 token 吞吐量最高提升 1.80 倍。代码：https://github.com/LiuTaowen-Tony/agentkv。

## Abstract
Agentic serving can consume orders of magnitude more tokens than chatbot workloads, stressing both KV-cache capacity and decode-time bandwidth. Most KV-eviction methods score cached keys against representative queries drawn from the most recent tokens, assuming future attention resembles recent attention. We show that agentic generation violates this assumption: future queries form a mixture over think, act, tool, and others phases, and principal-angle analysis shows these components occupy measurably different query subspaces, so recency representatives systematically undervalue keys that upcoming phases will need. We propose AGENTKV, which maintains a small query buffer per phase and scores cached keys against their union. We further implement AGENTKV in a persistent multi-turn serving path that carries compressed KV state across turns and compacts retained KV pages online. Across two models, six task domains, and three KV budgets each, AGENTKV improves task score by 5.5 points on average over R-KV and 5.3 over Tri-attention. Relative to upstream full-KV SGLang, AGENTKV improves output-token throughput by up to 1.80x. Code: https://github.com/LiuTaowen-Tony/agentkv.

# AgentKV：面向智能体式 LLM 的阶段感知 KV 驱逐 — 论文总结

## 1. 核心问题与整体含义

- **背景**：智能体式（agentic）推理正成为 LLM 的核心用例，但其服务成本远高于单轮聊天。智能体工作负载的 token 消耗可达传统聊天负载的 **1000 倍**，导致序列长度剧增，KV 缓存容量与解码时显存带宽成为吞吐与延迟的主要瓶颈。
- **核心问题**：现有 KV 驱逐/压缩方法大多以“最近 token”的代表性查询来估计未来注意力，隐含假设“未来注意力与近期注意力相似”。然而智能体轨迹在 **think（推理）、act（动作/工具调用）、tool（工具返回）、others（系统提示/用户问题）** 四个语义阶段之间反复切换，未来查询分布是这四个阶段的混合，并不平稳。
- **关键洞察**：作者通过 **主角度分析（principal-angle analysis）** 证明，不同阶段的查询向量占据可测量的不同子空间；因此基于近期性的代表查询会**系统性地低估**当前阶段弱相关、但未来阶段需要的键（尤其是 tool 与 others 阶段的键）。
- **整体含义**：KV 驱逐的代表查询选择应当覆盖“阶段混合分布”，而非仅依赖最近窗口；这不仅是算法问题，也需要在持久化多轮服务路径中真正落地才能转化为吞吐收益。

## 2. 方法论

### 2.1 核心思想
- 将未来查询分布 $p(q)$ 建模为**四个阶段特定查询分布的混合**，用估计器 $\hat{p}(q)$ 替代近期经验分布 $p_{\text{recent}}(q)$，并按期望注意力对候选键排序：
  $$A_i = \mathbb{E}_{q\sim\hat{p}(q)}\left[\text{softmax}\left(\frac{q^\top K}{\sqrt{d}}\right)_i\right]$$

### 2.2 阶段结构验证
- 将轨迹切分为连续阶段片段（如 think₁、act₁、tool₁），对每个片段堆叠查询向量做薄 SVD，取前 $k=5$ 个右奇异向量作为该片段的主查询方向基。
- 通过两个基的重叠矩阵 $V_{s,k}^\top V_{t,k}$ 的奇异值计算主角 $\cos\theta_i$，结果表明**跨阶段主角显著大于同阶段不同步之间的主角**，即阶段查询子空间更不重合。

### 2.3 AgentKV 算法流程
1. **在线阶段解析**（Algorithm 1）：基于 tokenizer 可见的 chat-template 标记（如 `<|im_start|>system`、`<think>`、`<tool_call>`、`<tool_response>`）做确定性解析，使用滚动前缀处理跨 token 切分的标记，无需模型侧分类器或新特殊 token。
2. **每阶段 FIFO 查询缓冲**：为每个阶段维护容量为 $\lceil q/4 \rceil$ 的最近查询缓冲区，压缩事件时取并集 $Q^{(e)} = Q_{\text{think}} \cup Q_{\text{act}} \cup Q_{\text{tool}} \cup Q_{\text{others}}$，且 $|Q^{(e)}|\le q$，与近期基线代表预算一致。
3. **统一打分**：所有候选键在同一池中按阶段感知代表的平均注意力打分，取 top-$B$ 保留，**不按阶段划分键配额**。
4. **保护性索引**：流式 sink 等受保护位置强制保留。

### 2.4 服务路径实现（Algorithm 3）
- 保留 KV 条目被 gather 到紧凑目标槽，释放页归还分配器，页表在拷贝完成后重定向；物理长度与单调递增的逻辑长度分离以保持 RoPE 偏移与未来前缀扩展。
- 兼容 chunked prefill、CUDA graph capture 与常规 decode 路径；据作者称是**首个面向多轮智能体工作负载实现持久化缓存生命周期**的 KV 驱逐系统。

## 6. 主要结论与发现

- **阶段结构真实存在**：不同 agentic 阶段的查询子空间可用主角分析区分，跨阶段主角显著大于同阶段不同步。
- **近期代表存在系统性偏差**：近期代表能保留 nearby think/act 效用，但严重漏掉较早的 tool 效用；多阶段代表将 tool 覆盖率从 **0.042 提升到 0.175（B=512）**、从 **0.117 提升到 0.416（B=1536）**。
- **任务质量提升**：平均比 R-KV 高 **5.5 分**，比 Tri-attention 高 **5.3 分**；最大且一致的收益出现在 **BFCL multi_turn**（非近期指令与工具观察跨多个阶段转换仍相关）。
- **吞吐提升**：相对上游全 KV SGLang，输出 token 吞吐最高提升 **1.80×**（H100 NVL Qwen3-32B 32k/1k）；RTX A6000 Qwen3-8B 最佳提升 1.76×（32k/1k）。
- **统一服务路径对比**：在四种硬件/上下文配置中，AgentKV 均为共享路径下吞吐最高的策略，说明阶段感知选择能转化为更低的解码 KV 读取与更高并发。
- **阶段消融**：移除任一阶段代表都会降低准确率（Drop others 最明显，35.5% vs 完整 40.0%），证明四阶段缓冲提供互补覆盖。
- **粒度权衡**：四阶段方案最佳；更细划分在固定 q 下每阶段代表不足，反而更差。
- **跨家族迁移**：在 Nemotron 上较大预算（3072/4096）分别提升 +4.5/+4.0 分，最小预算因容量受限略降 −1.0 分。

## 7. 优点

- **问题识别清晰**：用主角度分析与 utility coverage 诊断双重验证“近期代表偏差”，将直觉量化为可测量现象。
- **方法简洁通用**：阶段解析基于 chat-template 标记，无需模型侧分类器或新 token；阶段感知打分可直接替换现有 query-centric 驱逐规则，属 drop-in 替换。
- **算法与服务协同设计**：不仅提出打分策略，还实现持久化多轮缓存生命周期、在线页压缩与分配器复用，使逻辑驱逐真正转化为吞吐与并发收益。
- **统计严谨**：配对 bootstrap + 多次独立运行，明确区分“CI 支持”与“统计不可分辨”，避免过度解读。
- **消融系统全面**：覆盖代表来源、阶段内采样、查询预算、阶段组成、标签噪声、粒度、跨家族迁移等多个维度。
- **跨架构验证**：仅替换 marker table 即迁移到 Llama 架构，展示方法的可移植性。

## 8. 不足与局限

- **预算需人工指定**：AgentKV 使用手动 KV 预算，未从任务级质量或延迟目标自动选择；部署时需在验证集上调参。
- **仅适用于中等压缩比**：预算过小时缓存容量主导选择，压缩压力过弱时策略趋近全缓存、执行方差主导差异；适用工作点因负载而异（BFCL multi-turn 约 B≥3072、τ² retail 约 B≥4096）。
- **特定场景收益有限**：当任务状态已由最近工具响应或外部记忆暴露时（如 τ² airline、BFCL memory），阶段感知保留优势不明显，甚至 StreamingLLM 的 sink+recency 策略在 airline 上更好。
- **重复/退化推理轨迹问题**：阶段缓冲可能保留近重复上下文（Qwen3-8B telecom B=4096 上 AgentKV 14.0 vs R-KV 18.4，虽 CI 未分辨），需额外冗余控制。
- **算力信息不完整**：未明确 GPU 数量与并行拓扑，仅给出总 GPU 小时估计。
- **任务覆盖偏差风险**：评测集中于英文智能体工具调用场景，未涉及多语言、多模态或非工具类长程任务；`others` 阶段在部分轨迹中只有一个片段，主角分析中该对角项无法测量。
- **应用限制**：方法不改变模型权重，不引入新能力或风险，但激进驱逐可能以依赖上下文的方式降低输出质量，部署方需按自身预算验证任务级表现。
