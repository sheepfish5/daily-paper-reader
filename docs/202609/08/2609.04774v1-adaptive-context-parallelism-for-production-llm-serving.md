## 摘要
随着LLM上下文窗口的扩大和输入序列的变长，服务系统面临的计算和内存需求不断增加。上下文并行（CP）通过将输入序列分区到多个计算节点以并行化计算，因此在高效LLM服务中变得日益重要。然而，现有的支持CP的系统要么依赖静态CP配置，要么仅对活动请求或批次调整CP程度。在本文中，我们提出了Vertumnus，一套专为异构和动态演变的负载设计的自适应CP服务系统。在请求层面，Vertumnus通过一种结合预测排队延迟、缓存感知预填充时间和GPU时间成本的放置成本，在具有不同CP程度的工作节点之间路由请求。在集群层面，Vertumnus根据工作负载需求的变化，通过秒级拆分和合并操作调整工作节点构成。Vertumnus还引入了一种全局前缀缓存管理策略，该策略在具有相同或不同CP程度的工作节点间协调缓存放置与复制，在请求分配和工作节点构成变化时保持缓存局部性。在包含公共和生产负载的64-GPU集群上进行的实验表明，在最高评估负载下，与最强基线相比，Vertumnus将平均首个令牌时间（TTFT）降低最多28.1%，并将按token加权的SLO达成率提升最多13.3个百分点。

## Abstract
As LLM context windows expand and input sequences grow longer, serving systems face increasing computational and memory demands. Context parallelism (CP), which partitions the input sequence across multiple ranks to parallelize the computation, has therefore become increasingly important for efficient LLM serving. However, existing CP-enabled systems either rely on static CP configurations or adjust the CP degree only for active requests or batches. In this paper, we present Vertumnus, an adaptive CP serving system designed for heterogeneous and evolving workloads. At the request level, Vertumnus routes requests among workers with different CP degrees using a placement cost that combines predicted queuing delay, cache-aware prefill time, and GPU-time cost. At the cluster level, Vertumnus adapts the worker composition through seconds-scale split and merge operations as workload demand changes. Vertumnus further introduces a global prefix-cache management policy that coordinates cache placement and replication among workers with the same or different CP degrees, preserving cache locality as request assignments and worker composition change. Experiments on a 64-GPU cluster with public and production workloads show that, under the highest evaluated loads, Vertumnus reduces mean TTFT by up to 28.1% and improves token-weighted SLO attainment by up to 13.3 percentage points over the strongest baseline.

## 1. 论文的核心问题与整体含义（研究动机与背景）

- **背景与问题**：随着大语言模型（LLM）上下文窗口不断扩展，输入序列越来越长，推理服务面临越来越大的计算与内存压力。上下文并行（Context Parallelism, CP）通过把输入序列切分到多个 GPU 上并行处理注意力计算，成为加速长序列 prefill 的关键技术。
- **现有方案的不足**：
  - 多数现有系统在部署时静态固定每个 worker 的 CP 度（如仅支持单一 CP 度或按固定比例分配），无法适应负载随时间变化的需求；
  - 基于输入长度做规则式路由，忽略了不同 worker 当前负载和各自前缀缓存状态的差异；
  - 已有一些动态调整 CP 的工作（如 LoongServe、NanoCP）只针对活跃请求/批次做细粒度弹性调整，不维护持久化的 worker 结构，导致前缀缓存难以跨请求复用；
  - 现有工作没有回答一个核心问题：在**固定 GPU 预算**下，如何按负载演变为不同 CP 度分配 GPU 资源。
- **核心意义**：CP 度应被视为一个**集群级别的、可动态调控的资源维度**，而不是仅按请求长度静态分配。论文提出的 Vertumnus 在请求与集群两个时间尺度上进行自适应调度，在 P/D 分离的服务架构中实现按需匹配资源、缓存局部性保持与 GPU 利用率之间的平衡。

## 2. 论文提出的方法论

### 2.1 总体架构

Vertumnus 运行在 P/D（prefill/decode）分离的 LLM 服务系统的 prefill 池中，将固定数量的 GPU 划分为多个**持久化 CP worker**（每个 worker 的 CP 度固定于请求调度时间尺度上，C ∈ C）。它由三个核心组件构成：

- **请求级调度器**：为每个到达请求选择最优 CP worker；
- **集群级重配置控制器**：周期性观察负载，通过秒级拆分/合并调整 worker 构成；
- **全局前缀缓存管理器**：跨 worker 维护统一的前缀 trie，执行跨/内 CP 度复制与回收。

### 2.2 缓存感知的预填充时间模型

该模型用于统一刻画 CP 度与前缀命中对 prefill 耗时的影响：

\[
\hat{E}_C(R,P) = d + aR + bP + \frac{1}{C}\left[cR + \alpha W(R,P)\right]
\]

其中：
- \(P\) = 已缓存前缀长度，\(R\) = 未缓存后缀长度，总输入长度 \(L = P + R\)；
- \(W(R,P) = RP + R(R+1)/2\) 表示剩余的注意力计算量（未缓存 query 对缓存前缀的注意力 + 未缓存后缀内部的因果注意力）；
- \(d\) 为启动开销，\(aR\) 为不随 CP 度下降的通信/同步开销，\(bP\) 为访问缓存前缀的开销，\((cR + \alpha W)/C\) 为可并行化的计算。

模型系数通过队列空闲时的 profiling 测量拟合获得，能较好捕捉"前缀命中减少的是可并行化计算、而通信开销不会同比降低"的效应。文中报告该模型在 Qwen3-30B-A3B 上预测误差较小。基于该模型可得请求- worker 对的预测服务时间 \(s_{i,w}\)。

### 2.3 请求级调度：自适应放置成本

为每个候选 worker w 计算放置代价：

\[
J_{i,w} = q_w(t_i) + \beta s_{i,w} + \lambda \left[C_w s_{i,w} - C_{\min}\hat{E}_{C_{\min}}(R_{i,w}, P_{i,w})\right]
\]

分别对应三个维度的考量：
- **排队延迟项 \(q_w(t_i)\)**：按该 worker上未完成请求的预测剩余服务时间之和估算，防止请求因缓存命中或 CP 优势集中到过载 worker；
- **服务时间项 \(s_{i,w}\)**：由预估模型得出，当 \(\beta>1\) 时放大缓存命中带来的优势，使持有相关前缀的 worker 更容易被选中，维持前缀局部性；
- **额外 GPU 时间项**：度量在 CP 度为 \(C_w\) 的 worker 上执行（相对最小 CP 度 worker）所占用的额外 GPU 资源成本，用于权衡并行加速与资源占用。\(\lambda\) 控制资源代价的权重。

### 2.4 集群级重配置：拆分与合并

- **容量 profiling 与初始化**：离线测量每个 CP 度 worker 在满足目标 SLO 前提下的最大窗口级负载容量 \(\kappa_C\)；基于代表性历史负载确定初始 worker 构成，偏好更多大 CP 度 worker 以服务延迟敏感的长请求；
- **过渡操作**：在每个固定观察窗口（实验中 20 秒）结束时，比较估计负载 \(\hat{D}(k)\) 与容量阈值上下界：负载高于上限 → 拆分（1 个度 2C worker 变为 2 个度 C worker，增加并发服务能力）；负载低于下限 → 合并（2 个度 C worker 变为 1 个度 2C worker，为单请求提供更多并行度）；同时监测长请求占比，两个信号冲突时容量优先，且需持续多个窗口才触发转换；
- **实现机制**：所有 CP 组通信元数据在部署时预先建立；重配置通过"排空（drain）→ 切换（switch）"两阶段完成：参与 worker 停止接收新请求、排空队列后，在模型输入边界切换 CP 配置 epoch。**无需进程重启或模型权重重新加载**，KV 缓存保留在 GPU 上，但可能需按新的 CP 几何重新对齐所有权和寻址。

### 2.5 全局前缀缓存管理

- **全局前缀 trie**：管理所有 worker 的逻辑前缀结构、副本持有者、每个节点的不同 CP 度访问计数（access[z,C]）与错失收益计数（missed[z,C]），用于识别前缀在不同 CP 度 worker 上的需求分布；
- **Per-request 更新（Algorithm 1）**：请求被调度到 worker \(w_i\) 后，递增其实际复用路径上各节点的 access[z, C_{w_i}]；同时计算请求的"理想 CP 度"（移除负载项后的最优 worker 的 CP 度），对于在理想 CP 度上无副本的已有匹配前缀，按"父节点命中 vs 当前节点命中"的预测时间差累积 missed 统计——这解决了"该 CP 度没有该前缀副本时无法观察到真实访问需求"的问题；
- **周期扫描（Algorithm 2）**：每隔固定间隔扫描所有 trie 节点 × CP 度组合，生成三类动作：跨 CP 度复制（r=0 时按 missed > θ_inter）、同 CP 度复制（access > r·θ_intra）、回收（access < r·θ_reclaim），附衰减因子保证近期数据权重更高；
- **复制与回收执行**：跨 CP 度复制需按目标 worker 的 CP 几何重新划分 KV 状态，拷入的块仅限从根到目标节点路径缺失的部分；优选保留较长祖先路径、缓存充足、负载较低的 destination；回收优先选择缓存压力大的 worker 上的副本，且不能使仍保留的后代前缀失效。

## 6. 论文的主要结论与发现

- **请求级 CP 感知调度有效**：在最高请求速率下，相对最强基线，平均 TTFT 最多降低 28.1%（Qwen3-30B-A3B × Production），P90 TTFT 最多降低 55.0%（Qwen3-30B-A3B × Tool-Agent），token 加权 SLO 达成率最多提升 13.3 个百分点（Qwen3-30B-A3B × Tool-Agent）；
- **集群级拆分/合并能在秒级完成**：6 次 worker 构成转换的排空+切换总延迟为 1.1~5.1 秒（切换阶段均在一秒内），足以响应持续性的负载变化；在负载压力大时切到更多小 CP 度 worker（8CP4/1CP8）可减少 19.6% 平均 TTFT，长请求占比升高时切到更多大 CP 度 worker（2CP4/4CP8）也优于任何固定配置；
- **缓存管理改善的主要机制是扩大放置选择空间**：消融实验中命中率提升仅为约几个百分点（60 req/s 时约 10.3% TTFT 降幅来自复制带来的调度弹性），说明通过复制让调度器在"保持缓存命中"与"选择低负载 worker/合适 CP 度"之间不再二选一，比单纯提高命中率更重要；
- **单一静态配置无法适应生产负载的动态变化**：短请求主导时期需要更多小 CP worker 以提高并发度，长请求主导时期需要大 CP worker 以降低延迟；Vertumnus 能在两种需求间自适应转换。

## 7. 优点

- **问题定位准确**：抓住生产 LLM 服务中"异构动态负载 + 前缀复用 + P/D 分离"三个真实且相互交织的特征，指出静态 CP 配置的缺陷，提出的分层调度框架（请求级路由 + 集群级构成 + 缓存管理）与真实系统的控制层次自然对齐；
- **技术设计体系完整**：用统一的解析模型指标衔接三个层次（请求路由代价函数、集群容量判断、缓存复制收益计算都建立在同一个 \(\hat{E}_C(R,P)\) 之上），形成了设计上的一致性；
- **缓存需求度量设计巧妙**：对某 CP 度无副本的前缀，用"理想 CP 度下本应获得但失去了的收益"而非"该前缀在该 CP 度下被访问了多少次"来衡量跨度复制需求，解决了冷启动的因果问题；
- **工程实现复杂度高且落地性强**：在 RTP-LLM 生产级引擎上实现，需处理 pre-created 通信组、config epoch 的模型输入边界切换、KV 转换和发布/确认协议等大量工程细节；无需进程重启和权重重新加载是实用性的关键保障；
- **实验设计有针对性**：除整体性能对比外，单独用时间变化负载测试 worker 重配置场景，用消融实验验证缓存管理模块的独立价值，并给出了转换时延的细粒度分解。

## 8. 不足与局限

- **模型架构覆盖有限**：实验仅涵盖 Qwen3-30B-A3B（MoE）和 DeepSeek-V4-Flash-FP8 两种模型，没有对稠密模型的广泛验证；两种模型都偏小（A3B 为 30B 总参/3B 激活），生产级大模型和稀疏注意力架构上的效果未知；
- **受限于不支持与 LoongServe 对比**：论文承认

受限于不支持与 LoongServe 对比：论文承认 LoongServe 在弹性 CP 调整上具有较强代表性，但其公开实现不支持本文所用的 MoE 模型架构（Qwen3-30B-A3B 与 DeepSeek-V4-Flash-FP8），需要大量模型专用适配才能运行。因此本文未能与其进行端到端对比，使得"分层重配置 vs 请求内弹性扩展"两种技术路线的优劣缺乏直接的实验证据，读者难以判断 Vertumnus 相对该方向最前沿工作的真实增量；
- **性能指标的呈现偏重 TTFT，缺少吞吐/资源效率的系统性对照**：论文主要报告 TTFT 与 SLO 达成率，对整体吞吐（如 token/s/GPU）、GPU 利用率、排队长度等指标涉及较少。考虑到 Vertumnus 通过引入额外 GPU 时间成本项来抑制"过度并行"，其代价理应用更全面的效率指标来检验，但文中缺少这类数据的交叉验证；
- **容量 profiling 的静态性**：离线测定的各 CP 度 worker 容量阈值 \(\kappa_C\) 假定模型行为与硬件条件在运行时基本不变。若实际负载中请求的 prompt 结构、长度分布、缓存命中模式发生显著漂移，或者与其他模块（如 PD 分离中的 decode 池反压）耦合，这些固定阈值可能失准，论文未讨论在线的阈值自适应机制；
- **缓存复制与回收的时效粒度粗**：跨 CP 度复制/回收的决策基于周期扫描（周期尺度未明确，推测接近重配置观察窗口），在突发性的前缀热度变化面前响应可能偏慢；论文对扫描周期取值的敏感性未做分析；
- **对 decode 侧与 PD 分离整体协同的讨论较浅**：系统聚焦于 prefill 池内的调度与重配置，但 prefill 结果会传递到 decode 池，decode 池的排队状态也会影响端到端 TTFT。论文未建模这一跨池耦合，可能在 decode 池成为瓶颈时高估 prefill 侧优化的实际收益。

## 9. 综合评价与定位

Vertumnus 是一篇系统难度高、工程完成度突出的论文。它将"上下文并行度"从一个部署期确定的静态配置提升为集群运行期可动态调控的调度资源，并通过"请求级路由—集群级重配置—全局缓存管理"三层机制，在同一个解析模型的支撑下解决了负载异构性、前缀局部性与并行资源效率三者之间的矛盾。相比 LoongServe 等工作，其核心差异在于强调 worker 的持久化与缓存的可跨请求复用，避免弹性伸缩带来的缓存失效代价，这使其更贴近生产级 P/D 分离架构的实际约束。

论文的实验覆盖了两种代表性模型架构、三类负载与多个负载强度，配合针对性设计的重配置与缓存消融实验，较充分地支撑了其核心主张。局限主要在于对比基线的广度（尤其缺少与 LoongServe 的直接对比）以及指标呈现的全面性。总体而言，Vertumnus 在问题重要性、技术系统性、工程落地难度上都达到了高水平，对"如何在大规模推理集群中动态管理并行资源"这一开放问题提供了有价值的答案，也为后续研究在跨池协同、在线容量自适应、弹性与缓存复用权衡等方向留出了空间。
