## 摘要
大型语言模型（LLM）服务中输出长度的重尾分布对资源供应和集群调度提出了重大挑战。尽管输出长度预测可以缓解这些问题，但现有方法存在关键缺陷：外部代理模型会增加大量延迟且保真度通常有限，而基于内部状态的方法虽然高效，但依赖于对当前模型状态的浅层探测。我们发现了投机解码（SD）与长度预测之间的结构性联系：先进框架（如EAGLE-3）中草稿解码器产生的潜在表示编码了对生成长度具有预测性的信号。基于这一见解，我们引入了OUTLETS（基于投机解码主干的输出长度预测），它将投机主干重新用作轨迹感知的长度预测器。当其草稿表示已用于投机解码计算时，OUTLETS仅添加一个轻量级回归头，其平均绝对误差（MAE）低于所评估的方法。在饱和的分离式服务下，OUTLETS的预测使标准调度策略能够优先处理较短请求，并在解码实例间更均匀地分发请求，将短请求的P99延迟降低了34.8%。

## Abstract
The heavy-tailed distribution of output lengths in Large Language Model (LLM) serving poses major challenges for resource provisioning and cluster scheduling. Although output-length prediction can mitigate these issues, existing approaches have key drawbacks: external proxy models add substantial latency and often have limited fidelity, whereas internal state-based methods are efficient but rely on shallow probes of current model states. We identify a structural connection between speculative decoding (SD) and length prediction: latent representations produced by the draft decoder in advanced frameworks (e.g., EAGLE-3) encode signals that are predictive of generation length. Building on this insight, we introduce OUTLETS (Output-Length Prediction from Speculative Decoding Backbones), which repurposes the speculative backbone as a trajectory-aware length predictor. When its draft representations are already computed for speculative decoding, OUTLETS adds only a lightweight regression head and achieves lower MAE than the evaluated methods. Under saturated disaggregated serving, OUTLETS predictions enable standard scheduling policies to prioritize shorter requests and distribute requests more evenly across decoding instances, reducing short-request P99 latency by 34.8%.

# 论文总结：OUTLETS：基于投机解码主干的输出长度预测

## 1. 核心问题与研究动机

### 背景与问题
- LLM 推理服务中生成式模型的输出长度呈**重尾分布**，不同请求在 token 数上可相差数个数量级（如论文中 Qwen3-30B-A3B 的输出长度分布标准差普遍接近甚至超过均值）。
- 这种差分计算负载导致以下系统级问题：
  - **HOL（Head-of-Line）阻塞**：FCFS 调度下短请求被长生成阻塞，拖慢尾延迟。
  - **负载不均**：轮询（Round-Robin）调度缺少轨迹感知，无法平衡各解码实例负载，造成资源碎片化。
- 因此，**输出长度预测**成为高级调度与资源供给的核心基础能力。

### 现有方法的缺陷
| 方法类别 | 代表工作 | 主要缺陷 |
|---|---|---|
| 外部代理模型 | BERT / OPT 回归器（S3、LTR） | 延迟高、资源开销大、无法访问目标 LLM 内部状态、保真度有限 |
| 内部浅层探测 | TRAIL、ARES（MLP 附着于 LLM 隐状态） | 效率虽然高，但其探测状态是为即时 next-token 预测优化的，缺乏长程结构信号 |
| 指令引导式 | PIA | 提示修改可能影响对齐，且需在正式回复前生成预测 token，增加延迟 |

### 核心洞察
- 论文识别出投机解码（Speculative Decoding）与长度预测之间的**结构性联系**：两者都需要对未来序列演化进行建模。
- 先进 SD 框架（如 EAGLE-3）中的草稿解码器会构建**分层的 lookahead 特征**来预测未来的 token 轨迹。由于“序列终止”本身就是未来延续的属性，这些前瞻状态是长度预测的**天然载体**。
- 现有方法却从未利用过这一信号——它们要么只使用目标 LLM 的浅层隐状态，要么使用与目标模型无关的外部代理。

## 2. 方法论：OUTLETS

### 总体框架
- OUTLETS 将投机解码的草稿骨干**复用**为轨迹感知（trajectory-aware）的长度预测器，在共享计算图上增加一个轻量返回归头。
- 设计目标不是提出新的调度策略，而是研究投机前瞻特征是否能为**既有的调度机制**提供缺失的长度信号。

### 关键组件
（1）**特征融合层（Feature Fusion Layer）**
- 不同于仅使用 top-layer 隐状态，选取目标 LLM 的多个层（浅层词汇特征、中层句法、深层语义）的隐状态进行拼接并投影：
  - f_ctx = W_proj(Concat({h^(i)}))，i ∈ {2, ⌊N/2⌋, N−2}
（2）**草稿解码器层（Draft Decoder Layer）**
- 轻量 Transformer 解码器，使用**门控注意力（Gated Attention）**替代 EAGLE-3 的标准 Llama attention（以缓解 attention sink 并更好保留长程终止信号）。

（3）**双头架构（Dual-Head Formulation）**
- **草稿头**：输出 draft 分布 P_draft(y_{t+1} | y_{1:t}) = softmax(W_lm · h^draft_t)，用于投机解码的 token 提议。
- **长度回归头**：在**对数空间**回归（目标为 z = log(1 + length)，以应对重尾分布），使用 MLP 将同一草稿状态映射为剩余长度估计。

（4）**联合训练目标**
- L = L_SD + λL_len + γ‖θ_MLP‖²
  - L_SD：投机解码 KL 散度
  - L_len：对数空间 MSE
  - γ = 1e−5（L2 正则）；λ = 0.1（简单固定权重优于 Uncertainty Weighting 和 GradNorm 等自适应加权方法）

### 静态 vs. 动态预测
- **静态预测**：t=0 时，prefill 后预测总输出长度 L，用于初始化资源规划与调度决策（论文系统级评估采用此模式）。
- **动态预测**：解码过程中持续更新预测 r̂_t = L − t，在系统中可支持在线重调度（论文作为表征质量检验，未用于在线迁移）。

## 6. 主要结论

1. **投机前瞻状态提供了有效的长度预测特征来源**：草稿解码器表征显著优于直接附加 MLP 于目标 LLM 隐状态的浅层探针。在所有数据集和模型上的 MAE 均是最低。
2. **联合训练不损伤投机解码质量**：OUTLETS 与 SD-ONLY 的投机接受率几乎重合，辅助回归目标类似于“只读消费者”，不引入梯度冲突。
3. **静态预测上 OUTLETS 优于 LP-ONLY（或持平），动态预测上略逊**：静态监督稀疏时，草稿目标起到正则化作用；动态监督密集时，专用模型可更充分特化。
4. **调度信号切实有效**：在饱和分离式服务系统中，OUTLETS 驱动的 LB+SJF 相比 RR+FCFS：
   - 短请求（<800 token）P99 延迟从 59.8s 降至 39.0s（**降低 34.8%**）
   - 中长请求 P99 分别降低 19.4%（74.6→60.1s）和 2.8%（103.0→100.1s）
   - 吞吐量由 17.8k 增至 18.4k tokens/s（提升 3.3%）
   - 长任务未被饥饿，P99 反而略降
5. **草稿解码器才是长度预测精度最主要的贡献来源**：组件消融中，移除草稿解码器是导致 MAE 上升最多的改动。

## 7. 主要优点

1. **核心洞察新颖且具迁移价值**：首次系统地将投机解码的“前瞻表征”重新用于长度预测，打通了推理加速与调度控制面之间的表征通路；在共享计算图下添加回归头，边际成本很低（预测头约增加 0.7ms）。
2. **方法设计务实**：静态/动态双场景覆盖调度员的真实需求，对数空间回归适配重尾分布；固定损失权重经实验验证优于更复杂的自适应权重方法。
3. **实验体系完备**：预测精度与系统端到端性能两个层面都有严格评估；受控服务实验中引入 Oracle 与 No-prediction 边界，给出效果上界/下界，设置 5 次重复并控制浮点不确定性的做法增强了结果可靠性。
4. **训练稳定性验证充分**：对比 SD-ONLY 的接受率曲线、LP-ONLY 的回归精度，逐层分离了联合训练中的相互影响。
5. **跨域泛化初探积极**：仅用 LMSYS 聊天数据训练，长文本上限扩至 4,096 tokens 后，对 GSM8K/HumanEval 的 MAE 仅为对应平均长度的 21.8%–25.5%，提示方法有一定的通用性。

## 8. 不足与局限

1. **部署成本适用范围受限**：性能增益的“零边际成本”成立的前提是投机解码骨干已存在。作为独立长度预测器使用时，草稿骨干本身的 72.3M 参数与约 1.7ms/step 开销必须计入，可能不适配极低延迟类部署。
2. **调度范围局限**：系统实验仅使用静态预测做准入时刻的负载均衡和 SJF，未将动态预测用于在线迁移或运行时抢占；也没有实现“投机加速模式”与“饱和调度模式”的自动切换。
3. **评估范围受限**：
   - 生成长度被截断到 2,048 tokens，对超长 agentic 任务或长链推理场景的预测未验证；
   - 仅用 greedy decoding（温度=0）；采样温度、自定义 stopping criterion、直接 KV-cache 统计指标未纳入考虑；
   - 仅用 chat 数据训练后跨域到数学/代码，缺少数理类数据训练的对照组；
   - 系统实验仅覆盖 ShareGPT，缺少在 Alpaca/LMSYS 上的系统验证。
4. **动态预测的劣势未解决**：LP-ONLY 在马氏密集监督下普遍更优（但差距不大）。若未来以“动态调度”为主要目标，共享骨干可能不如专用模型。
5. **重量级基线公平性**：PIA 基线使用轻量实现（prompting 而非论文原文的重量级微调），实际部署时的 PIA 效果可能不同；系统级实验中关闭了投机加速，无法直接推断真实生产环境同时开启 SD 加速与预测调度的整体收益。
