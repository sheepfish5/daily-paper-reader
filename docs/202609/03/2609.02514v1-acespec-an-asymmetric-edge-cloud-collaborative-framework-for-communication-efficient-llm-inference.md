## 摘要
在边缘设备上部署大型语言模型（LLM）通常依赖于模型压缩或分割推理。然而，压缩会降低推理能力，而分割推理则面临严重的广域网（WAN）通信瓶颈。边缘-云投机解码成为一种有前景的替代方案，利用边缘小模型为云端验证生成草稿token。然而，在波动的WAN环境下，不可避免的预测拒绝会引发灾难性的流水线停顿和全网络回滚，抵消协作收益。为此，我们提出AceSpec，一种非对称边缘-云协作框架。AceSpec利用未饱和的边缘计算资源主动构建概率状态缓存，有效将全网流水线刷新转化为O(1)局部内存查找。为节省带宽，它采用非对称通信协议，上行传输极简主链索引，下行传输紧凑稀疏分布。此外，我们引入一种网络感知的、基于拉格朗日优化的资源分配策略，动态最大化本地缓存命中率。评估表明，AceSpec实现了高达3.52倍的吞吐量加速，并展现出卓越的带宽抗性，即使在严重受限的50 Kbps WAN条件下也能维持接近峰值的推理性能。

## Abstract
Deploying Large Language Models (LLMs) on edge devices typically relies on model compression or split inference. However, compression degrades reasoning capabilities, while split inference suffers from severe Wide Area Network (WAN) communication bottlenecks. Edge-cloud speculative decoding emerges as a promising alternative, leveraging an edge small model to draft tokens for cloud verification. Yet, over volatile WANs, inevitable prediction rejections trigger catastrophic pipeline stalls and network-wide rollbacks, neutralizing collaborative gains. To overcome this, we propose AceSpec, an asymmetric edge-cloud collaborative framework. AceSpec utilizes un-saturated edge compute to proactively construct a probabilistic state cache, effectively transforming network-wide pipeline flushes into $\mathcal{O}(1)$ local memory lookups. To preserve bandwidth, it employs an asymmetric communication protocol that transmits minimal main-chain indices uplink and compact sparse distributions downlink. Furthermore, we introduce a network-aware, Lagrangian-optimized resource allocation strategy that dynamically maximizes the local cache hit rate. Evaluations demonstrate that AceSpec achieves up to a 3.52$\times$ throughput speedup and exhibits exceptional bandwidth immunity, sustaining near-peak inference performance even under severely constrained 50 Kbps WAN conditions.

## 二、方法论：核心思想与关键技术

### 1. 核心设计思想

AceSpec以非对称架构为出发点，核心逻辑是：**将边缘闲置算力转化为网络延迟的“遮蔽层”**。它利用云验证窗口期在边缘本地主动预构建概率多分支token树缓存，使网络级流水线冲刷转化为O(1)本地内存查找，从根源消除回滚惩罚，同时以非对称通信协议大幅削减上下行数据量。

### 2. 系统架构

系统由**Edge Client**与**Cloud Server**构成：

- **边缘客户端**：承载轻量Draft SLM，集成三大子系统——树状起草器（Tree-based Drafter）、概率KV缓存管理器（Probabilistic KV Cache Manager）和本地重采样器（Local Resampler）——协同生成候选路径、构建多分支token树并执行非阻塞网络I/O；
- **云端服务器**：承载大参数目标LLM，仅作为“评估者”执行高并行验证循环，不控制最终token选择；验证失败时下发拒绝索引与稀疏目标分布。

### 3. 非对称通信协议

- **上行**：仅传输主链token索引序列（标量数组），避免传输整个树结构或稠密概率张量；
- **下行**：在拒绝时仅回传拒绝位置索引及对应的稀疏目标分布；
- 证据显示该协议使系统带宽需求降至极低，50 Kbps下仍可维持近峰值性能。

### 4. 异步多分支树构建

- 在云端turnaround窗口（T_cloud）内，边缘SLM利用空闲算力从主链各潜在拒绝深度展开多分支token树；
- 以本地草稿分布Q作为云端未知目标分布P的代理；在每个深度k排除主链token后，取残余概率质量中Top-F_k候选构建分支；
- 通过定制**树注意力掩码**（含共享前缀块、主路径分支块、后缀对角块三个子块），将所有分支打包进单次并行前向传播，避免了N次顺序前向传播，使树展开在O(1)墙钟时间内完成。

### 5. O(1)状态恢复机制（Algorithm 1）

- 云端返回稀疏目标分布后，边缘本地执行重采样得到修正token，形成验证结果w = (π, x_resampled)；
- 以w为查询键在本地树缓存T中查找；
- **缓存命中**：通过COMPACT_KV操作将命中分支的KV条目与已验证前缀对齐，失效其他分支，O(1)内存压缩消除顺序重起草代价；
- **缓存未命中**：执行KV回滚并顺序重起草。

### 6. 理论分析与最优分支分配

**吞吐公式推导（体现视角：算法系统协同设计）：**

- 定义T_naive、T_ideal、T_bubble三个系统常量，推导出加速比下界公式：
  - `S ≥ S_ideal / [1 + (1 − P_tree_hit(T)) · ρ]`
  - 其中S_ideal为完美掩蔽下的理论加速上限，ρ = T_bubble/T_ideal为回滚惩罚比；
  - 该公式将系统物理极限与算法性能分离，明确了最大化树缓存命中率是隐藏时延的前提。

**两层约束优化框架：**

1. **网络感知预算（Network-Aware Budgeting）**
   - 树构建耗时须满足T_tree_draft(B) ≤ RTT(t) + T_verify，以保证边缘执行被云turnaround时间遮蔽；
   - 通过实时探测RTT(t)推导计算预算：`B*(t) = min{B_max, T_tree_draft⁻¹(RTT(t) + T_verify)}`；
   - 网络良好时缩小树规模省电，网络波动时扩大树以缓解波动。

2. **任务感知形状分配（Task-Aware Shape Allocation）**
   - 定义分支分配向量F = [F_0, ..., F_{γ−1}]，总分配须满足预算约束；
   - 命中率建模为各深度命中概率乘积：`P_tree_hit(F) = Π [α + (1−α)R(F_k)]`；
   - 引入前缀存活概率α^k作为权重，对目标函数取对数并将R(F_k)近似为幂律分布形式（R(F_k) ≈ 1 − c·F_k^(−β)），构建拉格朗日函数求解；
   - 最终得到闭式最优几何衰减分配：`F*_k = B_alloc(t) · [(1−η)/(1−η^γ)] · η^k`，其中η = α^(1/(β+1))；
   - **核心洞见**：浅层位置更易被拒绝，应分配更多分支；随深度增加到达概率指数下降，资源应几何衰减分布。这揭示了一种“概率引导的稀疏缓存”策略：将冗余计算精准布防在最可能失守的浅层节点。

### 7. 关键优势

- **训练免费**：适用于任何现成的off-the-shelf LLM，无需微调或辅助网络；
- **原生支持随机核采样**：不同于PipeSD/E2-SCI退化为贪心解码；
- **上行流量不膨胀**：非对称协议只传主链索引。

## 六、主要结论与发现

1. **显著性能领先**：AceSpec在大部分配置中实现最优加速，最高达3.52×（LLaMA-1B/70B + HumanEval）；在GSM8K数据集上对比Vanilla Spec和Split Inf的劣势尤为明显——后两者在WAN场景下低至0.41~0.57×，足见通信墙问题的严重性；
2. **带宽免疫特性突出**：带宽从100 Mbps降至50 Kbps时吞吐几乎不变；直到25 Kbps以下才出现退化——这证明极小通信量设计切实有效；
3. **非均匀分配优于均匀分配**：消融实验中Non-Uniform在3数据集上全面领先；Uniform策略经常推高首次token延迟（TTFT），因稠密均匀树饱和边缘算力；
4. **边际收益递减规律确认**：预算从20→40提升命中率约0.125，而40→80增幅变缓，与自然语言重尾分布一致；
5. **温度鲁棒性**：温度从0.3升至1.7，命中率仅下降约7.4个百分点（0.885→0.811），但仍超81%；显示其对高随机性场景的有效覆盖；
6. **负面案例定位清晰**：Qwen-1.7B在HumanEval上0.98×低于基线——当草稿SLM较大、任务语法刚性较高时，局部树展开耗时超过云turnaround窗口，计算瓶颈从网络侧转移到边缘侧，印证网络感知预算的必要性。

1. 端到端测试覆盖多个模型家族与规模，对比了5种代表性基线方法；
2. 消融实验有效解耦了“网络预算”与“任务形状分配”各自的贡献；
3. 带宽扫描区间大（跨越4个数量级），定位了性能退化阈值，观察可重复；
4. 对负面案例做了诚实讨论与机制归因，而非选择性地回避——具备一定的客观性。

## 八、不足与局限

### 实验覆盖层面

- **网络仿真精度有限**：依赖单一tc工具，无真实互联网测试，缺乏包丢失、抖动、RTT波动等复合因素，带宽免疫结论可能过于乐观——目前证据链条局限于带宽单一维度，对“波动网络”的复杂现实刻画不足；
- **缺乏弹性场景与并发服务验证**：未测试多用户并发、突发流量、长对话等条件下的表现；
- **无真正的边缘-云计算分解分析**：AceSpec的时间分配依赖于边缘树构建≤云端验证时间的边界条件，但未报告两种不同硬件（Orin vs A100）间的时钟级细粒度分解；
- **负例解释待量化验证**：Qwen-1.7B在HumanEval退化的归因（T_tree_draft > T_cloud）是机制性推断，缺少周期级profiling数据支撑。

### 方法内在局限

- **受边缘侧前缀命中率上限制约**：AceSpec的本地缓存机制本质上依赖本地树对云端实际概率分布的覆盖；当两端分布分歧过大时缓存命中率会下降（即使从单链P(α^γ)提升为多链命中，也存在冗余度用尽的情形）；
- **内存空间开销**：多分支KV缓存需要额外显存，文中未给出量化分析——对Orin 32GB环境下缓存容量上限的讨论缺位；
- **理论假设的理想化**：跨位置条件独立假设与幂律分布近似在大规模实践中的偏差未被量化；对nucleus采样下采样截断导致的理论模型与实际不符缺乏分析。

### 应用部署层面

- **场景尚未覆盖**：未讨论模型安全（token验证策略差异）、隐私保护、断线重连、多边缘节点切换等系统工程议题；
- **硬件异质性**：仅在单一边缘硬件（Jetson Orin）做验证，对于更弱（手机SoC）或更强（工作站级）的边缘硬件缺乏结论；
- **系统性偏差风险**：模型的实验以表格性能为主，未对比生成文本质量（如人工评测、BLEU等）差异，因此无法判断AceSpec在延迟/吞吐优化之外是否存在质量折损。
