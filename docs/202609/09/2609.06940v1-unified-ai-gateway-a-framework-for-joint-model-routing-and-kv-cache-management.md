## 摘要
大语言模型（LLM）推理日益跨越在规模、能力、价格和提供方上有所不同的多种模型。这种转变给开发者带来了两种成本：一种是在众多模型之间进行选择与切换的集成成本；另一种是由于KV缓存不可用或与所选模型不兼容而需要重建KV缓存的推理成本。我们将统一AI网关定义并分析为一种部署在边缘的AI流量枢纽的系统设置。它协调终端设备、边缘资源和云端模型服务之间的模型路由、KV缓存管理和计算放置。在请求时，网关在任务质量、延迟、成本和资源约束下联合选择目标模型、执行站点和KV缓存操作。与此同时，后台缓存管理操作优化后续请求的KV缓存放置、复制、检索和生命周期决策。我们综合了关于KV缓存重用、压缩、跨模型映射、分布式存储和传输的现有证据，并讨论了将这些能力集成到一个系统中尚存的挑战。在八种典型工作负载配置下，我们的工作负载级分析模拟报告了TTFT加速1.25倍至13.28倍，以及输入成本效益1.20倍至6.16倍。

## Abstract
Large language model (LLM) inference increasingly spans models that differ in size, capability, price, and provider. This shift creates two costs for developers. One is the integration cost of choosing among and switching between many models. The other is the inference cost of rebuilding a KV cache when it is unavailable or incompatible with the selected model. We define and analyze the Unified AI Gateway as a system setting for an edge-deployed AI traffic hub. It coordinates model routing, KV cache management, and compute placement across end devices, edge resources, and cloud model services. At request time, the gateway jointly selects a target model, an execution site, and a KV cache action under task-quality, latency, cost, and resource constraints. In parallel, background cache-management actions optimize KV cache placement, replication, retrieval, and lifecycle decisions for subsequent requests. We synthesize existing evidence on KV cache reuse, compression, cross-model mapping, distributed storage, and transfer, and discuss the remaining challenges of integrating these capabilities into one system. Across eight typical workload profiles, our workload-level analytical simulation reports TTFT speedups of 1.25$\times$--13.28$\times$ and input-cost benefits of 1.20$\times$--6.16$\times$.

# 论文详细总结：Unified AI Gateway（统一AI网关）

## 1. 核心问题与整体含义

- **研究动机**：LLM 推理生态正在向多模型化演进，开发者在模型规模、能力、价格和提供方之间进行选择与切换。这种跨模型路由带来两类成本：
  - **集成成本**：在众多模型间选择与切换的工程开销；
  - **推理成本**：切换模型后，既有 KV 缓存可能不可用或不兼容，目标模型被迫对完整上下文重新执行 prefill，该重复计算可能抵消模型切换在能力或价格上的优势。
- **问题本质**：模型路由必须与 KV 缓存管理**协同决策**，但现有支持在网关服务、推理引擎和缓存系统间处于碎片化状态，路由决策可能丢弃有用状态、增大 TTFT 和输入成本、造成"缓存引发的模型锁定"。
- **核心命题**：提出 **Unified AI Gateway** 系统设置——一个部署在边缘的 AI 流量中枢，在**端–边–云连续体**上联合协调模型路由、KV 缓存管理和计算放置。
- **预期收益**：在 8 种典型工作负载下，TTFT 加速 1.25×–13.28×，输入成本效益 1.20×–6.16×。

## 2. 方法论

### 2.1 核心思想
- 将 KV 缓存视为一种**网关托管的显式基础设施资源**，而非下游实现细节。
- 在请求路径上同时执行路由决策与缓存决策，通过一个 **Global Control Plane（全局控制平面）** 完成联合优化。
- 架构上采用**端–边–云三层协同**：
  - **终端层**：发起请求、消费结果，也可承担 decode 计算；
  - **边缘层**：承载 Global Control Plane，执行 prefill、跨模型映射、缓存查找与存储，是流量与缓存管理的中枢；
  - **云层**：提供模型推理服务集群，接受网关路由。

### 2.2 关键技术细节

**双层决策结构**：
- **请求时决策**：针对每个请求，联合选择目标模型 \(M_j\)、执行站点 \(e\)、KV 缓存动作 \(a\);
- **请求流后台决策**：持续优化跨设备的缓存放置、复制、迁移和驱逐，影响后续请求的可行动作集。

**五条缓存路径**（候选中评估）：
1. 精确缓存命中 → 直接复用；
2. 跨模型映射（cache mapping）；
3. 远端缓存传输；
4. 边缘 prefill；
5. 目标端完整 re-prefill（兜底）。

**形式化优化问题**（请求时联合决策核心公式）：
\[
(j_t^*, e_t^*, a_t^*) = \arg\min_{(j,e,a) \in F_t(P_t)} \lambda_{\tilde L} \tilde L_{tjea} + \lambda_{\tilde C} \tilde C_{tjea}
\]
约束：\(L_{tjea} \le L_t\)（延迟上界），\(Q_{tjea} \ge Q_t\)（质量下界）。其中 \(F_t(P_t)\) 为可行动作集合，\(P_t\) 为当前缓存放置，\(\lambda_L,\lambda_C\) 为延迟与成本权重。

**传输延迟近似模型**：
\[
T_{\text{transfer}} \approx \frac{S_{\text{compressed}}}{B} + T_{\text{RTT}} + T_{\text{queue}} + T_{\text{copy}} + T_{\text{restore}}
\]
其中 \(S_{\text{compressed}}\) 为压缩后 KV 缓存大小，\(B\) 为带宽。

**跨模型映射使用判据**：当且仅当
\[
T_{\text{cache}}(c) + T_{\text{map}}(c) < T_{\text{recompute}}(c),\quad \varepsilon_{i\to j} \le \delta
\]
即映射+传输总成本低于目标端重算，且映射质量损失在允许范围 \(\delta\) 内时，采用映射路径。

**四大缓存能力组**：
- 跨粒度 KV 缓存复用（精确前缀→非前缀段→语义相似→多 Agent 工作流）；
- 自适应压缩（量化、低秩、混合方法，4–20× 压缩比可行）；
- 跨模型缓存映射（同架构映射与跨架构映射）；
- 分布式缓存存储与传输。

### 2.3 组件职责
论文还明确了五类组件的网关特定需求：联合路由组件、复用管理器、压缩/传输管理器、跨模型翻译器、分布式缓存存储，以及跨组件的控制平面协调（关键瓶颈是 KV 缓存传输与推理引擎内存管理（如 PagedAttention 非连续块）之间的耦合）。

## 3. 实验设计

- **评估方式**：**工作负载级解析仿真**（analytical simulation），而非真实系统原型实验。论文将通用公式实例化为标量延迟模型。
- **数据集/场景**：8 种典型工作负载配置（\(\theta_w = (L_{in}, L_{out}, h, r_{switch}, B)\)），来源如下：
  - 5 个 Preble profile（ToolBench、具身智能 Agent、编程、视频 QA、长文档 QA/LooGLE）；
  - 多轮聊天（CachedAttention 报告的 persistent dialogue hit rate）；
  - RAG（非前缀文档复用场景）；
  - 长时程编码 Agent（基于 vLLM×Mooncake 的约 80K-token、turn-30 trace，命中率 94.2%）。
- **对比基线**：**传统 AI 网关（conventional AI gateway）**——只做模型路由，兼容的同模型 KV 缓存可运行时复用，但缓存命中后发生模型切换或缓存未命中时均需目标端完整 prefill。
- **模型切换率**：25%、50%、75%（50% 对标 vLLM long-horizon agent 评估中报告的 45% 每轮切换率）。
- **核心评估指标**：
  - **TTFT 加速比**（缓存准备时间为主指标，end-to-end 加速为辅助指标）；
  - **输入成本比**（cached input 折扣设为 \(\eta=0.10\)）；
  - **E2E token 成本比**（输出 token 定价为缓存输入单价的 5 倍，\(\lambda=5.0\)）。
- **关键外部参数标定**：KV 缓存足迹 15 KB/token（混合注意力模型代表值）、压缩比 \(\rho=4\)、A100 profile 的 prefill 系数（基于 DistServe 发布工件）、带宽 \(B=8\) GB/s。

## 6. 主要结论与发现

- **性能收益广谱**：8 个工作负载在 25%/50%/75% 切换率下，TTFT 加速分别为 **1.25×–5.39× / 1.49×–9.48× / 1.74×–13.28×**；输入成本比分别为 **1.20×–2.72× / 1.41×–4.44× / 1.61×–6.16×**；E2E 成本比分别为 1.17×–2.35× / 1.35×–3.69× / 1.52×–5.04×。
- **收益随负载特征分化**：高缓存命中率 + 长上下文 + 高切换率的负载获益最大，典型如**长时程编码 Agent**（80K 上下文、94.2% 命中率），TTFT 加速 5.01×–12.87×。
- **Agentic 负载尤为受益**：长输入、短输出、外部工具暂停期间仍须保持 KV 缓存的负载（外部停顿、缓存保留、重载）协同价值最高。
- **成本效益分离**：输入成本比与 TTFT 加速同步增长；E2E 成本比受输出长度稀释，但在短输出、长输入负载中依然显著。
- **实践含义**：现有组件的单项能力已经成熟（精确前缀缓存命中率 52.4%–74.1%、压缩 4–20×、映射比 re-prefill 快 2.7–25×），但**只有联合协调模型路由与缓存处理**才能避免状态浪费和模型锁定。实现该愿景仍是一个端到端系统工程问题。

- **问题定义清晰且务实**：将"模型路由"与"KV 缓存"这两个传统上割裂的层统一为一个联合控制问题，识别出真实存在于多模型服务中的"缓存诱导的模型锁定"现象。

## 8. 不足与局限

- **缺乏真实系统实现与验证**：本文没有部署实际网关原型，所有收益均为**解析仿真的推断**；真实系统中的缓存查找失败率、元数据开销、映射质量和端到端排队效应会显著影响结论。模型层面，这是一篇偏向系统"研究议程+架构提案"的论文。
- **理想化假设较多**：
  - 假设映射总是成功、映射质量无损且映射/压缩/解压/拷贝等开销被流水线完全隐藏（\(T_{\text{map+transfer}} = T_{\text{transfer}}\)），与真实映射的能力限制（层数/头/维度不匹配时需要训练或质量损失）存在差距；
  - 同一命中率对不同路径一视同仁，未区分精确命中与非前缀命中的质量差异；
  - 采用固定的 4× 压缩比和 15 KB/token 足迹，未覆盖不同模型架构（GQA/MLA/混合注意力）的差异。
- **公平性**：对照组未优化；传统网关实际可能采用启发式缓存亲和路由（如 CacheRoute 等前缀亲和策略）。本文以"切换率"固定策略对比，可能高估了与传统最优策略之间的差距。
- **仿真模型未包含**：缓存放置/复制的后台管理开销、存储容量限制、RTT 差异、非 8 GB/s 跨域网络异构性（灵敏度分析部分覆盖但未综合）。
- **成本模型不完整**：输入成本比仅反映 token 计费，常被提及的存储生命周期费用、跨域带宽计费、能源和硬件折旧未纳入目标函数。
- **跨模型映射泛化性不足**：目前报告映射技术仅适用于同家族模型（训练-免费闭式映射）、特定适配器（LoRA）或特定模型对；在异构模型池中大规模部署的可行性远远未解决。
- **多租户与隐私隔离存疑**：边缘共享缓存引入重建攻击与时序侧信道风险（如 PROMPTPEEK、KV-Cloak 等），论文只做了列举而缺少防护方案的系统设计。
