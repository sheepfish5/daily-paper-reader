## 摘要
键值（KV）缓存是长上下文大语言模型（LLM）解码中的主要内存瓶颈：每一步都需要完整读取，因此解码受内存带宽限制。将量化后的KV缓存保存在密集的片上非易失性存储器（NVM）中，可消除片外传输。然而，现有的KV量化方法是针对GPU式内存系统设计的：KIVI附加每组元数据，使存储的KV缓存增加约25%；KVQuant保留稀疏的全精度离群值，而密集阵列无法原位容纳这些离群值。本文研究了当KV缓存驻留在固定范围转换器之后的NVM中时，这些结构会带来何种代价，并设计了一种与该接口匹配的量化方案。该架构将量化后的KV缓存存储在密集的片上NVM中，仅使用一个小型静态模拟交叉开关来执行固定旋转，并将注意力计算保留在片上数字逻辑中。随机旋转和每向量归一化使每个坐标具有相同的范围，因此一个用于键的固定码本和一个用于值的固定码本（每个码本在所有对应张量类型的token之间共享）即可服务整个KV缓存。码本阈值被一次性编程为读取转换器的参考电平，从而实现固定范围数字化，无需对每个token进行转换器重新配置。反量化是一个十六项查找表加一次范数乘法；唯一的每向量元数据是一个标量，约占3%。在3B至14B的模型以及长达32k token的上下文中，四位KV缓存在针对实际器件级别模拟的存储和交叉开关噪声下保持了准确性。KIVI和KVQuant在软件中仍然更准确；我们格式的优势在于内存接口：在映射到相同NVM时，KV读取能量比两者低3.1-3.6倍，元数据开销比KIVI低8倍。本贡献在于与NVM内存接口协同设计的KV量化，而非创造新的精度记录。

## Abstract
The key-value (KV) cache is the dominant memory bottleneck in long-context large language model (LLM) decoding: every step reads it entirely, so decoding is memory-bandwidth bound. Holding a quantized KV cache in dense on-chip non-volatile memory (NVM) removes the off-chip transfer. Existing KV quantization methods, however, were designed for GPU-style memory systems: KIVI attaches per-group metadata, adding about 25% to the stored KV cache; KVQuant keeps sparse full-precision outliers that a dense array cannot hold in place. This paper examines what these structures cost when the KV cache resides in NVM behind fixed-range converters, and designs a quantization scheme matched to that interface. The architecture stores the quantized KV cache in dense on-chip NVM, uses a small static analog crossbar only for the fixed rotation, and keeps attention in on-chip digital logic. A randomized rotation and per-vector normalization give every coordinate the same range, so one fixed codebook for keys and one for values, each shared across all tokens of the corresponding tensor type, serve the entire KV cache. The codebook thresholds are programmed once as the read converter's reference levels, enabling fixed-range digitization with no per-token converter reconfiguration. Dequantization is a sixteen-entry lookup and one norm multiply; the only per-vector metadata is one scalar, about 3%. Across models from 3B to 14B and contexts to 32k tokens, the four-bit KV cache maintains accuracy under storage and crossbar noise simulated at realistic device levels. KIVI and KVQuant remain more accurate in software; the advantage of our format lies at the memory interface: 3.1-3.6x lower KV read energy than both mapped to the same NVM, and 8x lower metadata overhead than KIVI. The contribution is a KV quantization co-designed with the NVM memory interface rather than a new accuracy record.

## 论文总结：Interface-Aware KV Cache Quantization for Dense On-Chip NVM in Long-Context LLM Decoding

### 1. 论文的核心问题与整体含义（研究动机和背景）

- **核心瓶颈**：长上下文 LLM 自回归解码过程中，每一步注意力计算都需要完整读取 KV 缓存，且 KV 缓存大小随序列长度线性增长，使得解码性能受**内存带宽**限制而非算力限制。
- **现有方案及其代价**：将 KV 缓存量化后放入**密集片上非易失性存储器（NVM）**中，可以消除片外 DRAM 传输。然而，现有主流 KV 量化方法（KIVI、KVQuant）均针对 GPU 式内存架构设计，在 NVM 接口下存在结构性不匹配：
  - **KIVI**：为每组坐标附加全精度 scale 和 zero-point 元数据，约增加 **25%** 的存储开销，且每次读取需执行逐坐标乘加重建。
  - **KVQuant**：保留稀疏全精度离群值，需要独立存储和 gather 操作；密集 NVM 阵列无法原位容纳这种不规则结构，强行去除会严重退化精度。
- **核心研究问题**：当 KV 缓存驻留在「固定输入范围转换器 + 密集 NVM 阵列」的存储接口之后，现有量化格式的元数据、稀疏结构在容量、读能量、重建成本上究竟付出多大代价？能否设计一种与该存储接口匹配的量化方案？
- **整体含义**：论文主张 KV 量化应**与 NVM 存储接口协同设计**（interface-aware co-design），而非单纯追求软件端精度最优。其价值在于能效/存储接口层面的收益：KV 读能量降低 3.1–3.6 倍，元数据开销仅为 KIVI 的 1/8。

### 2. 论文提出的方法论：核心思想、关键技术细节

#### 核心思想

通过**随机 Hadamard 旋转**与**逐向量归一化**，使所有键/值向量的每个坐标具有一致的统计范围和动态范围，从而可以用**一个固定共享码本**完成量化，且码本阈值可固化为读取转换器的参考电平，实现免逐 token 重配置的固定范围数字化。

#### 关键流程与公式

1. **旋转与归一化（式 1）**：
   \[
   \tilde{x} = \frac{Hx}{\|Hx\|}, \quad r = \|Hx\|
   \]
   - H 为随机 Hadamard 矩阵（正交、条目 ±1/√d），将向量能量均匀分散，抑制离群坐标。
   - 归一化使所有向量落在单位球面上；每个向量仅需保存一个标量范数 r。

2. **旋转保持注意力点积（式 2、式 3）**：
   - H 正交 ⇒ qᵀk = (Hq)ᵀ(Hk)，注意力可在旋转空间直接计算，无需对每次 key 读取做逆旋转。
   - 旋转施加在 RoPE 之后（与 RoPE 不交换），使共享旋转在注意力分数中自然抵消。
   - 输出投影 W_O 离线折叠为 W′_O = W_O·Hᵀ，吸收反旋转，避免每 token 逆变换。

3. **Lloyd-Max 最优标量量化（式 4、式 5）**：
   - 键/值各一个固定码本 C = {c₁,…,c₂ᵇ}，阈值 tᵢ 为相邻码字中点，码字为区间质心。
   - 码本由坐标分布 p(x) 决定，与具体 token 无关，可离线一次性求解。

4. **混合码本（hybrid codebook）设计**：
   - **键（数据无关/analytic）**：旋转后键坐标近似各向同性随机单位向量，边缘分布精确服从
     \[
     p(x) \propto (1-x^2)^{(d-3)/2}, \quad x \in [-1,1]
     \]
     随 d 增大趋于高斯分布；码本由该解析式直接推导，无需任何校准数据。实测 excess kurtosis ≈ −0.16、KL 散度 5×10⁻⁴，与解析分布高度吻合。
   - **值（单次离线校准）**：值坐标旋转后仍具重尾（excess kurtosis ≈ 2.25），解析分布拟合不足，需在 64 条短序列上做一次离线码本拟合。
   - 作者指出数据无关的键码本不仅是为省校准，也是为精度：有限校准集会引入采样误差，在校准键码本的消融实验中未见一致收益。

5. **反量化路径（式 7）**：
   \[
   \hat{x} = r \cdot [c_{i_1}, \ldots, c_{i_d}]^{\mathsf{T}}
   \]
   - 每次读取仅为一次 16 项表查找（LUT）+ 一次标量乘法，每向量唯一的元数据是单个 fp16 范数，约占总存储 **3%**

6. **硬件映射**：
   - 旋转矩阵固化在一个**静态 write-once 模拟交叉开关**上（每 cell 同一电导，符号用差分位线实现），对所有 token/head 只读不重写。
   - 码本阈值编程为感测放大器比较器的**参考电平**，读路径无需任何逐 token 配置。
   - KV 以 4 位码本索引形式写入密集 NVM 阵列，每 cell 只写一次、多次读取——避免耐久度问题与反复写入噪声。
   - 范数存储在数字 SRAM（容量约占 KV 总存储的 3.1%）。
   - 注意力计算完全保留在片上数字逻辑中。

7. **Qwen2.5 偏差处理（式 8）**：Qwen2.5 在 Q/K/V 投影中引入恒定偏置 β，旋转无法消除。因为 β 是离线已知权重，在量化前减去、反量化后加回；实际存储的是 Hβ 静态向量。Llama 无此偏置故不激活。

### 6. 论文的主要结论与发现

1. **结构不匹配确认**：KIVI 与 KVQuant 的功能结构（分组元数据、稀疏离群值）在 NVM 接口上转化为可量化的容量（至高 25%）、SRAM 面积（KIVI 噪声无关元数据需约 210 mm²）与读能量（3.1–3.6×）代价。
2. **匹配接口的量化格式有效**：固定共享码本 + 每向量单个范数标量的表示，能在 3B–14B 模型、4k–32k 上下文下以 4-bit 精度保持实用性——多值检索大部分场景 ≥94%，键的解析码本精度不低于校准码本。
3. **鲁棒性**：
   - KV 存储噪声：3% FS 以下（对应 write-verify 工艺可达容差）所有模型精度稳定，3B 最先退化，σ=5% 时下降 25.5 个百分点。
   - 旋转交叉开关：2% 电导噪声 + 6-bit DAC 下跟踪理想旋转（ARC 差距 <1 个百分点），因为交叉开关只写一次、噪声不累积或反复注入。
4. **能效优势**：KV 读能量较 KIVI 降低 3.64×、较 KVQuant 降低 3.11×；元数据为 KIVI 的 1/8；压缩带来 3.88× 存储缩小、与 fp16 直接存储相比片上面积降低 22.2×。
5. **设计边界**：32k 上下文总面积（250–428 mm²）超过单芯片预算，指示需多 die 或 3D 集成 NVM；注意 320× 的「片上 vs 片外」优势是一般片上方案的普适优势，CiM 具体贡献（旋转交叉开关+码本查找）< 读能量 1%，论文对此做了诚实区分。

### 7. 优点（方法/实验设计亮点）

- **问题定义精准**：明确将「量化格式必须匹配存储接口」提升为第一性设计约束，而非在既有 GPU 内存假设上做增量优化。
- **方法优雅且环环相扣**：
  - Hadamard 旋转一石三鸟：涂散离群值 → 统一坐标范围 → 正交性免逆旋转。
  - 归一化把码本设计从「逐 token 匹配」简化为「单球面匹配」，码本阈值直接固化为转换器参考电平，将量化器与模拟前端合为一体。
  - 键码本基于解析各向同性分布、无校准数据需求——属于少见的 data-free 精确设计而非近似。
- **诚实的精度定位**：不宣称精度优势，明确定位为「接口协同设计的量化器」而非新的精度记录。
- **对比框架完整**：同时比较等名义位宽、等存储预算、同噪声条件下的表现；分别量化软件精度与硬件接口成本两个维度，避免混淆。
- **对既有 CiM 注意力工作做了系统梳理**（Leroux 2025、X-Former、HARDSEA），区分了「KV 存于 NVM」与「注意力在 NVM 中计算」的不同技术路线。
- **噪声建模建立在既有文献共识上**（高斯器件变化模型、write-verify 3% 容差参考），参数扫描范围覆盖实际工艺点。

### 8. 不足与局限

- **软件精度存在稳定差距**：在同等位宽下 RULER-MV 与 KIVI 差距显著（3B: 80.4 vs 89.0；8B: 98.1 vs 100；14B: 94.9 vs 98.5）；匹配存储预算后 KIVI-3bit 仍占优（86.4/99.3/98.3 vs 80.4/98.1/94.9）。小模型与长上下文的合成检索是最薄弱环节。
- **KVQuant 的比较不完全公平**：在空置 KVQuant 的稀疏离群值存储、以密集型格式存储其稠密码时，精度倒塌（8B 96.5→81.2，3B 86.5→58.0）。虽然用于论证「稠密阵列无法容纳稀疏结构」，但 KVQuant 原生格式需要独立存储方可实现其精度，将之强行映射到同一阵列有「稻草人比较」之嫌。
- **无真实芯片/完整系统验证**：面积、能量全部来自 NeuroSim 22nm 解析模型；读取路径中的校准/外围电路、写端归一化硬件等被抽象化，存在模型误差风险（作者承认「解析映射成本模型」为主要局限之一）。
- **模型覆盖有限**：均限于 head dimension d=128 的中小规模模型（3B–14B），未覆盖更大的 GQA/MQA 架构变体或 d>128 的设置，Qwen2.5 偏置处理可能不适用于其他未知的架构异质。
- **σ=0 与含噪实验运行次数不对称**：σ=0 仅单次确定性运行，含噪点为三次均值，造成图 3 中小的非单调抖动源于运行间方差——虽然合理，但与主表的一致性不够严密。
- **14B 消融不完全受控**：theo/cali 变体未移除 Qwen2.5 偏差，与 half 的对比无法完全隔离码本设计的贡献。
- **容量需求仍然巨大**：即便压缩 3.88×，32k 上下文总面积超单 die 预算，规模化需依赖多 die/3D 集成方案，本文未提供系统级如何组织的具体方案。
- **通用性与端到端缺失**：未说明 KV 之外（如激活、权重）在真实硬件流水线中与 Attention 数字逻辑配合的系统级吞吐/延迟结果，因此“3.1–3.6× 读能量降低”尚未转化为端到端解码加速的实测证据。
