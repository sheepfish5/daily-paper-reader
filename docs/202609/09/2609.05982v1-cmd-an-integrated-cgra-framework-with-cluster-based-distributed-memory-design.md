## 摘要
粗粒度可重构阵列（CGRA）是在各种应用领域实现高能效和可重构性的有前途的解决方案，但其性能常常受到刚性存储器架构的限制，该架构限制了可访问数据存储器的瓦片的数量和位置。这为具有密集存储器访问的内核造成了显著的瓶颈。为了解决这个问题，我们提出了CMD，一种具有基于簇的分布式存储器设计和协同设计的编译工具链的集成CGRA框架。编译器包括一种新颖的存储器感知映射器和一个设计空间探索（DSE）机制，该机制针对特定内核确定最优存储器架构设计。实验结果表明，我们经过DSE后的CMD CGRA相对于传统CGRA实现了平均1.39倍的速度提升，同时将总面积平均降低到传统CGRA的0.912倍。

## Abstract
Coarse-Grained Reconfigurable Arrays (CGRAs) are a promising solution for achieving high energy efficiency and reconfigurability across various application domains, but their performance is often crippled by rigid memory architectures that limit the number and location of tiles that can access data memory. This creates a significant bottleneck for kernels with intensive memory accesses. To address this, we propose CMD, an integrated CGRA framework featuring cluster-based distributed memory design with a co-designed compilation toolchain. The compiler includes a novel memory-aware mapper and a design space exploration (DSE) mechanism that identifies the optimal memory architecture design for specific kernels. Experimental results show that our post-DSE CMD CGRAs achieve an average speedup of $1.39\times$ over a conventional CGRA while simultaneously reducing the total area to an average of $0.912\times$ of the conventional CGRA.

## 1. 核心问题与研究动机

传统粗粒度可重构阵列（CGRA）的性能高度依赖其存储器架构，但现有 CGRA 大多采用集中式数据存储器，存在以下两类主流访存方式，均受限于存储访问的数量和位置：
- **Tile 固定访存方式**：只有靠近数据存储器的某一行/列瓦片能访问内存，其他瓦片的数据只能靠片上路由中继，导致 II（启动间隔）增大、路由压力大。
- **HW/SW 仲裁访存方式**：每行/列每周期仅允许一个瓦片访问存储，当多个瓦片同时竞争同一行/列中有限访存端口时，访存请求被延迟或重路由。

这种“刚性/集中式”存储结构造成两个关键瓶颈：
- **II 过长**：受路由约束，即使计算资源足够，访存操作也会排队，拉长整体延迟；
- **计算效率低**：大量瓦片仅用于数据中继转发而非实际计算，浪费计算资源，且 CGRA 规模越大问题越严重。

因此，本文提出 **CMD（Cluster-based Distributed Memory）**：一种将分布式存储设计整合进 CGRA 的架构，配合协同编译框架，从根本上缓解访存瓶颈，突破传统集中式存储对并行化数据访问的限制。

## 2. 研究方法与关键技术

### 2.1 CMD 总体架构

- 采用 CPU 与 CGRA 紧耦合/松耦合协同工作方式，DMA Unit 负责数据、控制信号的加载与回传。
- 将瓦片阵列划分为**若干簇（cluster）**，每簇内的多个瓦片共享一个本地**分布式存储单元**，通过中间网络（mesh-style NoC）互联。
- 每个存储单元包含：多 bank 数据存储器（bank 数与簇大小一致）、硬件仲裁器、以及负责发送一致性信号的“一致性模块”。
- 每个瓦片沿用可重构计算设计方式：功能单元、控制存储器、交叉开关、多组寄存器和旁路缓冲。

### 2.2 存储一致性机制

- 每个变量可能被复制到多个存储单元中，从而需要跨内存的一致性管理。
- 基于类似 **MESI 协议**的状态跟踪，每个变量实例记录四种状态：Modified (M)、Exclusive (E)、Shared (S)、Invalid (I)。
- 每个存储单元通过信号包（如 68×4 bits）向集中式内存控制器发送写操作详细信息。
- **内存控制器**维护一张 `varInfoTable`，保存每个变量实例的状态、更新索引、更新值以及所在内存单元地址等。
- **四步两周期机制**：
  1. 信息分发器更新 `varInfoTable`；
  2. 广播无效化信号；
  3. 一致性管理器产生同步请求并更新状态；
  4. 将新值同步至失副本。
- 这在系统频率与性能之间取得了平衡。

### 2.3 EDFG 构造与变量建模

- 传统 DFG 无法显式表达存储变量，因此 CMD 扩展了 DFG，提出 **EDFG（Extended-DFG）**。
- 在 EDFG 中，每个访存操作（load/store）都配对一个**变量节点（variable node）**，存储变量大小、类型、名称、ID 等元数据，并在多个访存操作访问同一变量时建立多个变量节点，为映射提供灵活性。

### 2.4 Memory-Aware 映射算法

实现了算法 1（伪代码）：
- 初始化 `II` 为基于递归和资源约束的 MII（RecMII 与 ResMII 的最大值）。
- 对于每个 II，构造扩展 MRRG（EMRRG），遍历所有操作节点并计算所有可用瓦片的映射成本，使用深度优先搜索评估布线代价，选出最优瓦片。
- **变量合并机制**：若访问的变量在目标存储单元中已存在，则进行合并，避免重复存储、提高数据重用；
- **防溢出检查**：避免将变量映射到存储容量不足的存储单元中；
- **一致性规则**：
  1. 每次写操作后的两周期内不允许再访问同一变量，防止读到旧值；
  2. 同一变量的同一索引每周期只允许一次写操作，避免多副本同时写入冲突。

### 2.5 DSE 机制（Memory Architecture DSE）

- 采用**网格搜索（grid search）**方法，搜索空间包含簇大小（例如 {1,2,4,6}）与存储单元大小（由 1KB 到用户上限）。
- 对输入的一组领域/应用内 kernels，综合评估以下指标：
  - II（越小越好）；
  - Capacity Occupied Ratio 相关目标；
  - 总存储容量（越小越省面积）。
- 总成本函数为：
  \[
  cost = \frac{1}{M}\sum_{k=1}^M \left( w_1 \times II_k + \frac{w_2}{COR_k} + w_3 \times C_{total,k} \right)
  \]
  - \(w_1\) 被设为远大于 \(w_2\)、\(w_3\)，即在优先保证性能的同时兼顾硬件开销；
  - 未考虑 MUR，作者认为优化总容量与 COR 会间接使 MUR 合理。

## 6. 主要结论与发现

- **性能提升显著**：经过 DSE 的 CMD CGRA 相对传统 CGRA 平均得到 **1.39×** 加速，最高达 1.63×（2mm）。不同 pre-DSE 配置（cluster size 1/2/4/6）平均也可获得 1.33×~1.37× 的加速。
- **面积不增反降**：Post-DSE 平均面积仅为传统 CGRA 的 **0.912×**，打破“以面积换性能”的刻板印象，展现了更强的面积效率。
- **计算效率提升**：Post-DSE 设计平均计算效率达到 40.0%（最高 51.0%），相比基线提升约 1.27×，证明 CMD 使得更多瓦片真正执行计算而非数据中继。
- **存储利用率改善**：Post-DSE 平均 MUR 为 67.2%（最高 100%）；平均 COR 为 66.1%（最高 98.2%）；总存储容量平均削减 13.9×。
- **可扩展性良好**：不同规模 CGRA 下，内存控制器面积比例随阵列增大而下降，证实控制器设计具备良好的可扩展性。

## 7. 方法优点与亮点

1. **首次集成“分布式存储架构”到时空 CGRA**：CMD 跳出了集中式存储的框框，从架构层面将簇内多瓦片共享的分布式存储和编译映射结合。
2. **紧耦合“架构—编译”设计**：不是单纯做硬件修改，而是同步设计了专门的 EDFG、内存感知映射器和一致性规则，使分布式存储真正可用。
3. **轻量高效的一致性设计**：结合静态映射的单周期/固定调度特点，利用 MESI 风格协议与 varInfoTable，在只需两周期的情况下实现了跨存储单元的同步，且控制器面积占比小（0.50%）。
4. **自动 DSE 机制**：基于领域/应用的内核集合自动搜索最优配置，能很好应对不同访存模式与变量特性的差异，避免手工作坊式调参。
5. **指标多元、评估严谨**：同时考虑了性能、面积、功耗、内存利用率等，且计算了“性能面积比”这类综合指标，比单纯比较速度意义更完整。
6. **规则设计保证可执行性**：通过在编译期约束同一变量写入行为，消除了运行时一致性冲突，使整体系统保证可靠一致性。

## 8. 不足与局限性

1. **权重选择依赖人工设定**：成本函数中 \(w_1, w_2, w_3\) 的选取带有主观性，不同需求下需要重新调权重，目前论文未给出权重选择方法与敏感性分析。
2. **Benchmark 覆盖面仍有限**：10 个测试集虽覆盖 6-7 个领域，但对通用应用的普适性仍需更大规模测试，例如较多数据密集型多媒体、编解码等场景尚未纳入。
3. **未给出编译时间和 DSE 的具体端到端时间细节**：虽然实现可在数分钟内完成，但没有给出具体性能开销，难以判断在更大设计空间中是否依然低代价。
4. **公平性的潜在争议**：Baseline 采用 64KB 全局 SRAM；而 pre-DSE CMD 配置为了适配 gcn 使用了更大总容量（16KB per cluster），因此部分加速幅度来自更多存储资源，作者虽尝试通过面积效率指标弥补，但在公平设计约束下可能需重新评估。
5. **实验缺少真实硬件流片验证**：目前主要基于 RTL 综合、仿真与 CACTI 估计，缺少在全系统原型上的实测功耗/性能数据。
6. **变量合并机制的潜在访存冲突**：虽然规则在多数情况下保证了正确性，但没有讨论跨循环长生命周期、重命名场景下 EDGF 的边界情况。
7. **不支持跨簇“远距离共享变量”的优化选项**：每瓦片只能访问本簇存储单元，若某个变量仅被单个簇外部请求复用程度低，导致复制开销非最优。
