## 摘要
当智能体会话运行到百万 token 且同时驻留许多会话时，KV 缓存以及对其进行排序的索引都位于主机内存中，而为 top-k 步骤对所有 n 个键进行排序的扫描就成为限制解码的访存流量。我们提出 Fathom，一种键扫描方法，其中每个查询决定读取每个键通道的多少位。4 位 K 缓存按通道主序以位平面形式存储，因此 t 个位平面的前缀恰好是该通道的 t 位量化器；查询通过在其通道的方差加权重要性上进行反向注水来分配其位预算。在 Qwen3-8B 的百万 token 场景下，一个解码步骤的 GPU 时间比 Double Sparsity、Loki 和 SparQ r=32 的 136 位扫描快 1.67 倍；在与 SparQ 的 68 位读取（r=16）相同的 GPU 时间内，Fathom 读取的字节数少 18%，并且在七种模型与上下文设置中的六种上具有更低的注意力误差。在 RULER 风格任务上，每次逐 token 扫描都与精确 top-k 解码相匹配；在真实编码智能体会话中，Fathom 以 92 位达到最准确的 136 位扫描的步骤一致性。其存储就是量化服务栈已经持有的 4 位 K 副本；当索引驻留在 GPU 内存中时，该方法并不更快。

## Abstract
When agentic sessions run to a million tokens with many sessions resident at once, the KV cache and the index that ranks it live in host memory, and the scan that ranks all n keys for a top-k step becomes the traffic that bounds decoding. We present Fathom, a key scan in which each query decides how many bits of each key channel to read. The 4-bit K cache is stored channel-major as bit planes, so a prefix of t planes is exactly the channel's t-bit quantizer, and the query spends its bit budget by reverse water-filling over the variance-weighted importance of its channels. At one million tokens on Qwen3-8B a decode step is 1.67x faster in GPU time than with the 136-bit scans of Double Sparsity, Loki and SparQ r=32, and in the same GPU time as SparQ's 68-bit read (r=16) Fathom reads 18% fewer bytes with lower attention error on six of seven model and context settings. On RULER-style tasks every per-token scan matches exact top-k decoding, and on real coding-agent sessions Fathom reaches the step agreement of the most accurate 136-bit scan at 92 bits. The store is the 4-bit K copy a quantized serving stack already holds, and the method is not faster when the index is resident in GPU memory.

## 1. 核心问题与整体含义（研究动机与背景）

- **场景**：编码/浏览类智能体会话可持续数十万至百万 token，且服务器同时驻留多个会话。KV 缓存不再与权重同驻 GPU，而落入主机内存或更慢层级，解码步骤由跨互联（PCIe）的流量决定。
- **瓶颈转移**：解码本就是带宽受限（每步读一遍权重 + 每层读一遍 KV 缓存），卸载后 KV 读取成为主导项。top-k 稀疏注意力虽只取分数最高的 k 个键，但分数在读之前未知，因此所有方法都必须先**扫描全部 n 个键的廉价表示来排序**。
- **扫描代价随上下文线性增长**：以 Qwen3-8B（36 层、8 个 KV 头、每头 128 通道、每 KV 头 4 个查询头）32k token 为例：稠密注意力读 4.8 GB/步；top-k（k=512）取获胜行约 200 MB/步且不随上下文增长；而 Loki/Double Sparsity/SparQ(r=32) 的 136 位扫描为 160 MB/步，到 100 万 token 时膨胀到 **5.1 GB/步**。
- **现有方法的两条杠杆**：①"少打分"——按页/块/landmark 选择（Quest、ShadowKV、InfLLM）；②"少读位"——Loki（r 个主成分坐标）、Double Sparsity（离线选 c 个通道）、SparQ（按 |q| 选 r 个通道，全深度读）、2-bit thumbnail（全通道 2 位）。**但这些方法的读取深度对每个被触及的通道都是固定的**。
- **核心洞察**：量化误差每增加一位下降 4 倍；若通道 j 已读到 t_j 位，再加一位对残余分数误差的削减正比于 g_j·4^(−t_j)。重要通道的第 4 位可能不如次要通道的第 1 位值钱。按边际价值分配比特即**反向注水（reverse water-filling）**，且有闭式解。
- **整体含义**：把已有的 4 位 K 副本变成"多分辨率索引"，让每个查询按需读取深度，从而在卸载场景下直接削减成为时间瓶颈的扫描字节。

## 2. 方法论

### 2.1 位平面 K 缓存（Bit-plane store）
- 键一次性量化为 4 位：每通道均匀对称码，每 64-token 块一个 fp16 尺度。设块内绝对值最大为 a_{β,j}，格宽 s_{β,j}=a/8，码 c = clip(⌊k/s⌋, −8, 7) + 8 ∈ [0,16)，码 8 表示零，最高位是符号位。
- 块 β、通道 j 的 64 个码的第 p 位打包成一个 64 位字 P_{β,j,p}（平面）；**按通道主序存储**，故 P_{·,j,0…t−1} 在序列维上连续。
- **关键性质**：读前 t 个平面得 c(t) = c ≫ (4−t)，反量化值恰为区间 [−a, a) 上的 t 位 mid-rise 量化器（格宽 a/2^(t−1)）；t=4 时退化为原 4 位码。**前缀读是精确的低精度量化器**，无需另存低精度副本。
- 存储开销：68 字节/token/KV 头（4 位 K + fp16 块尺度）。
- **兼容性**：要求"位前缀即更粗量化器"的均匀标量码。KIVI 逐通道码、INT8 直接兼容；KLT 旋转兼容（但必须集中方差），TurboQuant 的随机旋转 + Lloyd–Max 非均匀量化不兼容；KVQuant 查表类型、RoPE 前量化、离群分量需额外处理；FP8 需实测而非 4^(−t) 的边际增益。

### 2.2 逐查询读取深度
- 共享同一 KV 头的查询头组 {q^(h)} 中，通道 j 对分数的贡献方差：
  **g_j = Σ_h (q_j^(h))² · Var(k_j)**（Var 在校准键上一次测得）。
- 读 t 个平面即 t 位均匀量化器，量化误差方差 Δ²/12 = a²_{β,j}/(3·4^t)，每加一平面误差方差除以 4；误差以 q_j 进入分数，故通道 j 的期望平方分数误差 ∝ g_j·4^(−t_j)，总误差 ∝ Σ_j g_j·4^(−t_j)。
- **反向注水闭式解**（在 Σ_j t_j ≤ B 下最小化）：
  **t_j = clip(round(log₄(g_j/θ)), 0, 4)**
  每个 t_j 是 θ 的阶梯下降函数，故总和亦然；水位 θ 取"使总和刚好不超预算的最小 θ"，用 log θ 上的约 30 次二分搜索定位。
- t_j = 0 的通道完全跳过，其余为"活跃通道"。实测均值 48 位时触及 128 通道中的 30–34 个、每个 1–4 个平面。
- **与 SparQ 的两点差别**：g_j 用键方差加权而非按 |q_j| 排序；深度是分级的而非全有全无。
- 计划由该组 G 个头共享，故 K 字节只读一次。

### 2.3 逐层预算（可选）
- 层间分数分布尖锐程度不同。贪心分配 B_ℓ ∈ {24,…,128} 至目标均值（48 或 64 位），每步把比特给"每比特误差下降最大"的层。
- 在 Qwen3 上 16k 有改善、32k 改善变小；在 Qwen2.5-7B 与 Llama-3.1-8B 上反而更差（均值 64 时最高差 1.7×/2.1×）；16k 校准的计划用在 32k 上比平坦预算差。**默认推荐平坦预算**（无需校准、无上下文长度依赖）。

### 2.4 基底规则
- 有 QK-norm 的模型（Qwen3）：原始通道已足够稀疏，旋转反而抬高误差 → 用**原始平面**。
- 无 QK-norm 的模型（Llama-3.1-8B、Qwen2.5-7B/1M）：用键的校准 KLT 基底，存 (k−μ)V 的平面，g_j = Σ_h ((q^(h)V)_j)²λ_j；不做截断（不同于 Loki），全部 D 个坐标都存，深度由查询决定。
- 每个模型在校准文本上评估两种存储后**一次性决定**。

### 2.5 主机内存存储的读取
- 整个序列作为一个通道主序块，通道 j 的前 t_j 个平面是一段连续的 t_j·n/8 字节。gather 核为每个活跃通道拷贝一段（含其尺度）到暂存缓冲，扫描在 HBM 中进行。
- 运行列表大小固定（每通道一槽，非活跃槽长度为 0），**无需主机同步**。所有基线在卸载实验中都被给予同样的传输方式。
- 实测：连续段的 Triton gather 在 4 KB–512 KB 各种 run 大小下均达 25.1–26.2 GB/s，与同字节数的单次 cudaMemcpyAsync（21.6–25.9 GB/s）相当；按 4× 步长摆放也不损失带宽。而"每 run 一次 copy 调用"在 4 KB 时只有 0.4 GB/s。
