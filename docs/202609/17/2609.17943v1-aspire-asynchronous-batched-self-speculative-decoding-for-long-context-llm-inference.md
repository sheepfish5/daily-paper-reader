## 摘要
长上下文 LLM 推理受限于注意力机制，其重复的 KV 缓存读取使解码成为内存受限型任务。自推测解码通过使用稀疏注意力生成草稿 token，并用完整注意力验证这些 token 来缓解该问题，但现有的批处理方法仍保持同步：一个批次中的所有请求共享单一的草稿-验证调度，尽管最优草稿长度在不同请求之间差异很大，且在每个请求内部也会动态变化。我们提出 ASPIRE，一个基于三个组件的非同步批处理自推测解码框架。首先，统一的混合前向传播允许生成草稿的请求和验证请求共存于同一次批处理前向传播中，从而无需全局草稿-验证阶段。其次，一个轻量级在线推测调度器利用每个请求的接受率估计和批感知成本模型，让每个请求独立选择何时进行验证。第三，草稿内刷新层在生成草稿过程中于单个指定层执行完整注意力，并在每个草稿步骤更新稀疏上下文，以减少生成草稿过程中的陈旧性。在三个模型和五个推理与长上下文基准上，ASPIRE 相比自回归基线在解码吞吐量上实现了 1.70–4.58 倍的加速，并且相比最强的先前自推测基线将平均加速比提升了约 27%。

## Abstract
Long-context LLM inference is bottlenecked by attention, whose repeated KV-cache reads make decoding memory-bound. Self-speculative decoding alleviates this by drafting tokens with sparse attention and verifying them with full attention, but existing batched methods remain synchronized: all requests in a batch share a single draft-verify schedule, even though the optimal draft length varies widely across requests and changes dynamically within each request. We propose ASPIRE, a non-synchronized batched self-speculative decoding framework built on three components. First, a unified mixed forward allows drafting and verifying requests to coexist in the same batched forward pass, removing the need for global draft-verify phases. Second, a lightweight online speculation scheduler uses per-request acceptance-rate estimates and a batch-aware cost model to let each request independently choose when to verify. Third, an intra-draft refresh layer performs full attention at a single designated layer during drafting, updating the sparse context at every draft step to reduce staleness during drafting. Across three models and five reasoning and long-context benchmarks, ASPIRE achieves $1.70$-$4.58\times$ speedup in decoding throughput over autoregressive baselines and improves average speedup by approximately $27\%$ over the strongest prior self-speculative baselines.

## 1. 核心问题与整体含义（研究动机与背景）

- **背景瓶颈**：长上下文 LLM 推理中，解码阶段的自注意力是内存受限的——每个新 token 都需读取该请求完整上下文的 KV 缓存，且 KV 缓存无法像 MLP 权重那样在批内被摊薄。随序列长度与批大小增加，注意力的内存流量持续上升而算术强度始终很低。
- **现有解法**：自推测解码（self-speculative decoding）用稀疏注意力快速"起草"多个 token，再用全注意力一次性"验证"，把昂贵的全 KV 读取摊薄到多个被接受的 token 上，因而在长上下文场景尤为有吸引力（MagicDec、Vegas）。
- **核心痛点一（同步性）**：现有批处理方法仍是**同步**的——同一批次所有请求共享一个草稿-验证调度节奏，被迫"齐步走"，导致部分请求欠草稿、部分请求过草稿。
- **核心痛点二（最优草稿长度异质且动态）**：作者实证发现，最优草稿长度在请求间差异巨大（每请求平均接受长度从 2.56 到 20.00，均值 11.51），且在单个请求内部随生成推进而剧烈波动；因此固定草稿长度（无论全局还是每请求固定）都不够。
- **核心痛点三（草稿上下文陈旧）**：Vegas 等方法只在验证边界刷新稀疏上下文，草稿阶段越往后上下文越陈旧，限制草稿长度与质量。
- **整体含义**：论文主张把"推测调度"从批级同步下沉到**请求级、步级异步**，并让草稿与验证在同一批次前向中混合执行，从而在保持验证精确性的前提下提升长上下文解码吞吐。

## 2. 方法论：核心思想与关键技术

**核心思想**：在一个统一混合批次（unified mixed batch）中，允许同一批请求处于不同推测状态——部分用稀疏上下文起草、部分用全上下文验证——再由每请求在线调度器独立决定"继续起草还是验证"，并用轻量草稿内刷新层缓解稀疏上下文陈旧。

### 2.1 统一混合前向（Unified Mixed Forward）
- 第 $t$ 步把活跃请求分为验证集合 $V_t$ 与起草集合 $D_t$。
- 起草请求：用稀疏上下文 $S_i$ 解码 **1 个** token；验证请求：用全上下文解码 $d_i+1$ 个 token（覆盖草稿前缀 + 1 个新 token）。
- 二者共用同一目标模型权重与 MLP 计算，仅注意力上下文与解码长度不同；通过在单次批前向中为每请求指定各自的注意力上下文与解码长度，既保留批处理对 MLP 的摊销收益，又让注意力保持请求专属。
- 验证后，接受 token 与验证出的下一个 token 追加进上下文并重置草稿长度；起草请求则追加 1 个 token 并把草稿长度加一。由此**彻底消除全局草稿/验证阶段**。

### 2.2 在线推测调度器（Speculation Scheduler）
- **目标草稿长度** $\gamma_i$：以 Leviathan 等人的期望推测效率为目标，令 $c_i = T^{\text{draft}}_i / T^{\text{verify}}_i$ 为草稿-验证成本比，则
  $$\gamma_i = \arg\max_{\gamma \in \{0,\dots,d_{\max}\}} \frac{(1-\alpha_i^{\gamma+1})/(1-\alpha_i)}{1 + c_i\gamma}$$
  即最大化预测的"单位时间提交 token 数"。
- **接受率在线估计** $\alpha_i$：每次验证后令 $\hat\alpha_i = a_i/\min(a_i+1, d_i)$（部分接受视为 $a_i$ 次成功加 1 次失败，全接受视为 $d_i$ 次成功），再做指数平滑 $\alpha_i \leftarrow \omega\alpha_i + (1-\omega)\hat\alpha_i$；初始由先验 $\alpha_0$ 给出，且必须至少起草 $\gamma_{\text{init}}$ 个 token 才允许验证。
- **批感知成本比估计**：设 $n_t = |D_t| + \sum_{j\in V_t}(d_j+1)$ 为总前向 token 数，将单步运行时间建模为
  $$\tau_t = \beta_{\text{model}} + \beta_{\text{mlp}}\cdot n_t + \beta_{\text{attn}}\cdot\Big(\sum_{j\in D_t}|S_j| + \sum_{j\in V_t}\ell_j\Big)$$
  其中 MLP 项随总 token 数（算力受限）、注意力项随总 KV 读取长度（内存受限）线性增长。在"全批同质副本"近似下得
  $T^{\text{draft}}_i = \beta_{\text{model}} + \beta_{\text{mlp}}B + \beta_{\text{attn}}B|S_i|$，
  $T^{\text{verify}}_i = \beta_{\text{model}} + \beta_{\text{mlp}}B(d_i+1) + \beta_{\text{attn}}B\ell_i$，
  随 $d_i$、$\ell_i$、$|S_i|$ 在线重算。系数由运行时采样轨迹拟合。
- **调度规则**：当 $d_i \ge \gamma_i$ 或 $d_i \ge d_{\max}$ 时验证，否则继续起草（见附录 Algorithm 1）。

### 2.3 草稿内上下文刷新层（Intra-Draft Refresh）
- **动机**：注意力图在层间相关性远强于跨时间（token 滞后）相关性；固定单一"晚层"来源质量-开销权衡最佳。
- **机制**：指定刷新层 $\ell_r$ 在草稿时执行全注意力并捕获注意力 logits，其余层用稀疏注意力；每个草稿步都用它刷新下一步的稀疏集 $S_i$。验证时全注意力本就计算，故复用首个与最后一个验证 token 的注意力 logits（沿用 Vegas）。
- **稀疏选择**：把 logits 经在线 softmax 转成权重 $A^{\text{src}}_{i,t,h}(u)$，token 重要性 $r_{i,t}(u) = \max_h A^{\text{src}}_{i,t,h}(u)$；按分页 KV 以页为单位聚合 $s_{i,t}(P)=\sum_{u\in P} r_{i,t}(u)$；预算 $k_i = \max(k_{\min}, \lceil \rho P_i\rceil)$，其中固定保留最近 $L$ 页保证局部连续性，其余槽位给最高分页。

### 2.4 关键超参（默认设置）
- 页大小 16，稀疏率 $\rho=7\%$，预算下限 $k_{\min}=32$，保留最近 $L=8$ 页；$d_{\max}=16$，$\gamma_{\text{init}}=3$，$\omega=0.8$，$\alpha_0=0.9$；刷新层取倒数第二层 $N-2$；用 FlashInfer JIT 内核捕获注意力 logits。

## 6. 主要结论与发现

- **加速效果**：ASPIRE 在全部模型与工作负载上优于自回归；短上下文推理上最高 2.12×/1.86×/1.80×（Qwen3-1.7B/8B/DS-Llama-8B），长上下文上最高 4.58×/2.75×/2.66×；整体平均加速 3.34×、2.08×、2.14×，相比最强自推测基线平均提升约 27%。
- **上下文越长收益越大**：从 16K 到 80K，加速比单调上升，说明统一混合草稿-验证与请求级调度在内存受限区间收益最大。
- **消融结论**：相对 ASPIRE-Fixed 的增益在短上下文很小、在长上下文显著（如 Qwen3-8B 在 LB-v2[80k-100k] 从 2.22× 提到 2.75×），说明固定草稿长度的同步推测随上下文变长愈发次优；相对 ASPIRE-FSM 的增益集中在需要同时考虑接受率与批内成本的工作负载，说明批感知成本模型有价值，而简单反馈策略在行为稳定时也具竞争力（且复杂度更低）。
- **调度器接近 oracle**：与事后 oracle 的差距为 4.7%–20.2%，平均 10.4%，长上下文三格平均 8.5%。
- **草稿内刷新有效**：无刷新时接受率随固定草稿长度增加而下滑，$\gamma=10$ 时降至 60.3%；有刷新保持 76.6%，**弥补 16.4 个百分点**的差距。刷新开销约每周期 1.03%–1.06%（16k/32k 上下文，Qwen3-8B），小模型上低于噪声底。
- **精确性**：方法按构造精确（稀疏只影响提议，验证保证输出服从目标模型分布）；实测 LongBench-v1 八任务宏平均仅差 −0.20 分（1,460 样本），差异量级与批内核浮点非确定性一致。
- **超参鲁棒性**：刷新层在 $N/4$ 至 $N-2$ 区间接受率平坦，仅在首层与末层明显下降，$N-2$ 稳健；页大小在 64× 粒度范围内吞吐波动 <9%；$\omega$ 与 $\alpha_0$ 无设定导致性能崩塌。
