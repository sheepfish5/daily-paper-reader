## 摘要
GPU 高带宽内存稀缺且昂贵，而随着聊天、智能体循环和文档问答不断累积状态，KV 缓存会消耗其中很大一部分。Mooncake、LMCache、FlexGen、InfiniGen 和 AttentionStore 等系统用 CPU DRAM 和 SSD 扩展 GPU 内存。更难的问题是：哪些块应属于每个存储层级，何时移动或逐出它们，以及预取是否有帮助。我们在一个覆盖 GPU HBM、CPU DRAM 和 SSD 的离散事件模拟器中研究这些选择，并以随机森林执行时间预测器进行校准。我们在聊天、智能体和文档问答工作负载上比较了最近使用、重用频率、预测重用，以及带预取前瞻的 EWMA 预测器。分层存储使每 GPU 支持的并发会话数提高 73.02 倍，并将每会话成本降至 1/62.04。这些收益来自 1+8+64 的层级容量，而非放置策略。在我们的设置中，批大小为 1 时解码受计算限制，因此放置策略几乎不影响吞吐量。它主要改变 PCIe 迁移流量和首 token 时间。对于聊天，最近使用产生的迁移流量是重用频率的 1/2.30。重用频率在智能体和文档问答上表现最好。现有的预测重用策略与最近使用逐字节相同，使其针对智能体的推荐实际上就是最近使用。一个真正的 EWMA 预测器会改变行为，但在原本预期预测能帮助的工作负载上，其排名仍落后于重用频率。预取的收益不足以抵偿其带宽开销。在策略与缓存大小的网格上，即使拥有未来请求知识的预言机，在迁移流量上也从未优于不预取。面向特定工作负载的放置可以减少数据移动，但预测重用和预取建议按当前实现并未得到支持。

## Abstract
GPU high bandwidth memory is scarce and expensive, and KV caches consume much of it as chats, agent loops, and document question answering accumulate state. Systems such as Mooncake, LMCache, FlexGen, InfiniGen, and AttentionStore extend GPU memory with CPU DRAM and SSD. The harder question is which blocks belong in each tier, when to move or evict them, and whether prefetching helps. We study these choices in a discrete event simulator spanning GPU HBM, CPU DRAM, and SSD, calibrated against a random forest execution time predictor. We compare recency, reuse frequency, predicted reuse, and an EWMA predictor with prefetch lookahead across chat, agent, and document question answering workloads. Tiering supports 73.02 times more concurrent sessions per GPU and lowers cost per session by 62.04 times. These gains come from tier capacities of 1 plus 8 plus 64, not placement policy. Decode is compute bound at batch size one in our setup, so placement barely affects throughput. It mainly changes PCIe migration traffic and time to first token. Recency produces 2.30 times less migration traffic than reuse frequency for chat. Reuse frequency performs best for agents and document question answering. The existing predicted reuse policy is byte identical to recency, making its agent recommendation effectively recency. A genuine EWMA predictor changes behavior but still ranks behind reuse frequency on the workloads prediction was expected to help. Prefetching does not justify its bandwidth cost. Across the policy and cache size grid, even an oracle with knowledge of future requests never beats no prefetch on migration traffic. Workload specific placement can reduce data movement, but the predicted reuse and prefetch recommendations are not supported as implemented.

# 论文总结：KV 缓存应驻留在何处？跨 GPU、CPU 与 SSD 的放置策略

## 1. 核心问题与研究动机

- **背景**：GPU HBM 是 LLM 推理中最稀缺、最昂贵的资源，而 KV 缓存是其最大消耗者。长对话、智能体循环、重复文档问答等长生命周期会话会持续累积 KV 状态，远超 HBM 容量。
- **现有方案**：Mooncake、LMCache、FlexGen、InfiniGen、AttentionStore 等系统已把 KV 块分层扩展到 CPU DRAM 与 SSD，将"重算 prefill"变成"缓存查找"。
- **核心问题**：机制已基本解决，**难点在于策略（policy）**——哪些块放在哪一层、何时提升/降级/逐出/预取，以及最优策略如何随工作负载变化。
- **整体含义**：作者认为策略空间大且权衡高度依赖工作负载的复用结构（recency 型 vs. 前缀复用型），需要以"放置策略本身"为研究对象做系统化对比。

## 2. 方法论

- **核心思想**：构建一个可配置的三层（GPU HBM / CPU DRAM / SSD）KV 缓存放置层，用离散事件模拟器研究策略空间，并以随机森林执行时间预测器进行校准。
- **缓存结构**：KV 缓存由固定大小的块组成（沿用 PagedAttention 块粒度），每块驻留于三层之一。设三层容量 $c_g \ll c_d \ll c_s$，带宽 $b_g \gg b_d \gg b_s$。
- **按访问路径（Algorithm 1）**：
  - 若块在 HBM 中 → 直接使用（命中）；
  - 否则沿层级向上取回并提升至 HBM；
  - 若 HBM 满 → 将得分最低的块降级到 DRAM（再级联到 SSD）；
  - 预取：对被预测即将使用的块提前取回；
  - 更新策略得分 $s(b)$，记录命中层级与解码停顿。
- **策略家族**：
  - **recency**（保留最近使用块，即 LRU 分层）；
  - **reuse frequency**（保留复用频率最高块，利于共享前缀）；
  - **predicted reuse**（廉价预测器，灵感来自 InfiniGen）；
  - **predictive（EWMA）**：作者自建的基于 EWMA 下次触达估计的真实预测器，可证明与 recency 不同。
- **预取机制**：带前瞻窗口，在需要之前把块上移到 HBM，以重叠传输与计算；前瞻深度在 HBM 占用与停顿避免之间权衡。
- **成本模型**：有效容量为 $c_g+c_d+c_s$，混合成本由廉价层主导；代价是未命中时的取回延迟，需由策略与预取移出解码关键路径。

## 6. 主要结论与发现

- **发现一（容量收益来自机制而非策略）**：分层使每 GPU 并发会话数提升 **73.02×**、每会话成本下降 **62.04×**，但该倍数等于层级容量倍数 $(1+8+64=73)$，在整个比例扫描中稳定在 72.68×–73.22×，**与复用结构无关**，是容量记账结果。
- **发现二（策略只管带宽与 TTFT）**：batch 1 下解码受计算限制，吞吐量跨策略几乎不变（chat 恒为 1307.60 tok/s）；策略真正控制的是 PCIe 迁移流量与 TTFT。
  - chat：recency 迁移 27.38 GB，reuse-frequency 62.99 GB，**recency 少 2.30×**且 TTFT 更优；
  - agent：reuse-frequency 49.36 GB（1.60× 优势）；
  - 文档 QA：reuse-frequency 48.23 GB（1.63× 优势）。
- **发现三（predicted-reuse 名不副实）**：已发布的 predicted-reuse 策略**与 recency 逐字节相同**（代码验证），"agent 用 predicted-reuse"实质就是 recency，而 agent 上 recency 又略逊于 reuse-frequency。作者新增的 EWMA 真实预测器确实不同，但在 agent（53.16 GB vs. 49.36 GB）和文档 QA（48.45 GB vs. 48.23 GB，近乎持平）上仍**排名第二**，chat 上更是大幅落后（57.76 GB）。预测只在**一个狭窄的中间缓存窗口**（agent）拿过第一。
- **发现四（预取不划算）**：在"投机取取与需求流量共享同一受限链路"的模型下，因果预测器在**所有网格单元**中都没能捕获预言机的正收益；连未来读取预言机也在**超过一半的单元**中慢于不预取。原因是投机取回会延迟正在等待的需求取回。
- **发现五（成本-延迟前沿近乎垂直）**：每 1k 会话成本纯由层级组合决定（与工作负载/策略无关），跨度 **8.38×**（$45,493 → $381,287），而 P99 TTFT 最多只变动其上限的 **10.1%**；最便宜组合 HBM/DRAM/SSD = **10/86/96**，且在 12 组中都是最便宜点。部署应选**便宜的 SSD 重配置**。
- **发现六（深 SSD 的 SLO 边界）**：固定 HBM=32、DRAM=64，加深 SSD 可使会话数提升 10.77×（容量驱动、跨工作负载一致）；但 **chat 与 agent 在整个扫描范围内都无法满足 SLO**，只有文档 QA 在 SSD 深度 64 块处刚好触线（余量为 0.000 ms）。
- **发现七（DRAM 才是主力层）**：获胜策略下 chat 命中分布为 HBM 23.99%、DRAM 61.87%、SSD 0.00%；agent 72.65% 来自 DRAM；文档 QA 68.48%。SSD 只是浅回退层（文档 QA 8.80%、agent 6.07%），残余需重算的未命中率约 13.62%–14.15%。
- **发现八（停顿被计算掩盖）**：每 token 计算约 13.2445 ms，取回停顿在**所有工作负载上均低于 TPOT 的 1%**，因此 TPOT 不是区分策略的好指标；有意义的差异在 TTFT 与迁移带宽。

## 7. 优点

- **问题定位清晰**：把"机制 vs. 策略"明确切分，指出容量收益是机制红利、策略是二阶的带宽-延迟决策，避免了把容量红利误算成策略功劳。
- **诚实的负面结果**：主动报告 predicted-reuse 与 recency 逐字节等价、预取连预言机都不划算、EWMA 预测器仍落败，这类"证伪式"结论对社区有实际价值。
- **方法论严谨**：
  - 对"吞吐平坦"这一现象做了协议修正，改用迁移流量作为判别量；
  - 预测器与 recency 的等价性、成本函数的组合独立性都**在代码中验证而非口头假设**；
  - 引入未来读取预言机作为上界，把预取的收益上限说清楚。
- **单会话塌缩被当作发现**：指出单条孤立长对话下所有逐出策略逐字节相同，从而"廉价 LRU 正确"是因为逐出顺序无关紧要，而非策略优越——这修正了原路线图的因果解释。
- **成本-延迟前沿分析**：揭示了近乎垂直的前沿结构，给出可操作的部署建议（SSD 重配置）。

## 8. 不足与局限

- **无真实硬件实验**：全部结论来自离散事件模拟器 + 随机森林校准，未报告 GPU 型号、数量、运行时长；真实系统的 PCIe 竞争、SSD 抖动、内核行为未被建模。
- **工作负载为合成生成**：复用结构按构造偏向匹配策略，因此策略间的分离度是**上界**；真实对话轨迹复用更低，margin 会压缩。
- **batch 1、单 GPU 设定**：解码受计算限制、停顿占比 <1%，这恰好**压低**了放置策略与预取的价值；更大 batch 或更快解码内核下结论可能反转（作者已承认）。
- **成本数据为假设值**：$/GB 来自 `cost_model.py` 默认层级，非市场报价；会话数与成本仅为容量模型输出，其可信度等于价格假设的可信度。
- **停顿归因近似**：DRAM/SSD 的停顿份额按命中率分摊，模拟器未记录具体毫秒由哪一层造成。
- **未与量化/逐出协同**：KV 量化与 eviction 会先缩小块再放置，本文将其固定以隔离放置变量，因此未验证组合效应。
- **预测器问题未解决**：作者承认"能广泛获胜的预测器仍是开放问题"，预测的价值目前仅局限于狭窄容量窗口。
- **预取模型单一**：只考察了"需求路径已占满链路"的场景；在有充足空闲带宽的系统中预取可能仍然有效，结论不宜过度外推。
