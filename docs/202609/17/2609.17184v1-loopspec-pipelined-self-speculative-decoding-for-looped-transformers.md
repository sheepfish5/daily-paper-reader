## 摘要
循环 Transformer 通过在不同循环深度上重复应用共享的 Transformer 块堆栈，以紧凑的参数规模实现强大性能。然而，由于在每个循环深度都要访问共享权重，它们比参数规模相当的标准 Transformer 模型具有更高的解码延迟。为提高解码效率，自推测解码尤其适合循环 Transformer，因为其中间循环状态可直接提供草稿预测，而无需辅助草稿模型。因此，我们提出 LoopSpec，一个为循环 Transformer 量身定制的免训练自推测解码框架。LoopSpec 从早期循环状态中提取草稿 token，并以流水线方式运行，将未来 token 的草稿生成与当前 token 的目标验证重叠。为在不过度增加计算开销的情况下提高草稿准确性，我们引入来自更深循环深度的选择性第二次提议，同时确保在贪心与采样机制下均实现无损解码。此外，我们以闭式形式推导出最优提议深度，并表明预测与测量相符。在推理和编码基准上，LoopSpec 在多种循环 Transformer 上实现了最高 6.83× 的推理加速。

## Abstract
Looped Transformers achieve strong performance with compact parameter sizes by repeatedly applying a shared stack of Transformer blocks across recurrent depths. However, they incur higher decoding latency than standard Transformer models of comparable parameter size because shared weights are accessed at every recurrent depth. To improve decoding efficiency, self-speculative decoding is particularly well suited to Looped Transformers, as their intermediate recurrent states can directly provide draft predictions without an auxiliary draft model. We therefore propose LoopSpec, a training-free self-speculative decoding framework tailored for Looped Transformers. LoopSpec extracts draft tokens from early recurrent states and operates in a pipelined manner, overlapping draft generation of future tokens with target verification of the current token. To improve draft accuracy without excessive compute overhead, we introduce a selective second proposal from deeper recurrent depth while ensuring lossless decoding under both greedy and sampling regimes. Furthermore, we derive the optimal proposal depths in closed form and show the prediction matches measurement. Across reasoning and coding benchmarks, LoopSpec achieves up to 6.83$\times$ inference speedup across diverse Looped Transformers.

# LoopSpec：面向循环 Transformer 的流水线自推测解码 —— 论文总结

## 1. 核心问题与研究背景

- **循环 Transformer 的瓶颈**：Looped Transformer（如 Ouro、Raven）通过在不同循环深度上反复复用共享的 Transformer 块，以紧凑参数量换取有效深度（如 4 个块循环 8 次 ≈ 32 层模型）。但每个 token 生成步骤都要在每一循环深度重复读取相同权重，使推理处于**内存带宽受限**状态，解码延迟显著高于参数量相当的标准 Transformer。
- **为何选择自推测解码**：循环 Transformer 的中间循环状态本身构成一系列"逐步精化"的下一 token 预测，可**直接充当草稿分布**，无需额外训练草稿模型，避免分布不匹配与额外显存开销。
- **现有方法不足**：外挂草稿模型（EAGLE-3、DFlash）需额外训练与内存；自推测方法（Draft & Verify、LayerSkip）面向标准 Transformer 的层跳过/早退，未利用循环深度的结构特性；SPEED 虽针对循环解码做流水线推测，但需定制训练且仅支持贪心解码。
- **论文目标**：提出免训练、无损、可解析配置的自推测流水线框架 LoopSpec，将"循环深度"转化为"token 位置的并行性"。

## 2. 方法论

### 2.1 核心思想
- 不等待当前 token 完成全部 R 次循环，而是在早期深度 d1（d1 < R）读出草稿并**立即启动下一 token 的计算**（子分支），让父分支继续推进至深度 R 做验证。
- 所有分支（父/子）共享同一组 Transformer 块，可在**一次批处理调用**中同时推进，形成流水线：目标计算与多条推测延续并行前进。

### 2.2 单提议流水线（d1）
- 每个活跃分支维护前缀 X(b)、隐状态 H、当前循环深度 r。
- 流程循环：① 所有活跃分支经单次批处理调用 B 前进一个循环深度；② 分支到达 d1 时读出 q1 = p_d1 并采样草稿 x̂⁽¹⁾，以 `X(b) ∥ x̂⁽¹⁾` 在深度 0 新建子分支；③ 分支到达 R 时用拒绝采样验证草稿：接受则提交并沿用其子分支（已省去 R − d1 步）；拒绝则从 p_R ⊖ q1 重采样替换 token，剪掉全部推测后代并从深度 0 重启。
- 持续接受时每 d1 步提交一个 token，但每次拒绝都会丢弃整条推测进度并需再等 R 步。

### 2.3 残差第二提议与门控机制（d2）
- **残差提议**：因第二提议仅在首提议被拒后使用，所需目标分布为 p_R ⊖ q1。在深度 d2 读出 q̃2 = p_d2，构造 **q2 := p_d2 ⊖ p_d1**，采样 x̂⁽²⁾ 作为回退分支。消融表明残差形式优于直接用 q̃2。
- **门控机制**：若每分支在 d1、d2 都分叉，分支数按延迟递推 s_k = s_{k−1} + s_{k−d2/d1} 增长（R=32, d1=2, d2=8 时峰值可达 249 条）。因此仅当 **q̃2(x̂⁽¹⁾) < q1(x̂⁽¹⁾)**（更深状态对首候选信心下降）时才开启第二提议；贪心解码下退化为 arg max q̃2 ≠ x̂⁽¹⁾。
- **级联验证**：分支到达 R 后先按 min{1, p_R(x̂⁽¹⁾)/q1(x̂⁽¹⁾)} 接受首提议；失败则对 ρ1 = p_R ⊖ q1 按 min{1, ρ1(x̂⁽²⁾)/q2(x̂⁽²⁾)} 验证次提议；两者皆败则采样 x ∼ ρ1 ⊖ q2（门控关闭时采样 x ∼ ρ1），并剪枝重启。

### 2.4 理论分析
- **Theorem 1（拒绝率）**：设 ε2 = TV(p_d2, p_R)，在残差第二提议与级联验证下，两候选均被拒的概率 ≤ ε2，**与 d1 无关**；加入门控后上界为 2ε2（仅常数倍增加）。即残差提议不劣于直接用 p_d2。
- **Theorem 2（最优深度）**：假设期望 TV 距离满足幂律上界 E[TV(p_r, p_R)] ≤ βr^(−α)，最小化期望提交 token 所需循环步数 E[C] ≤ d1 + βd1^(−α)·d2 + 2βd2^(−α)·R，可得最优深度的**闭式解**（d1*、d2* 为 α、β、R 的显式表达式）。
- 对 Raven-Llama-3.2 拟合得 β=0.175、α=1.03，理论给出 (d1*, d2*) = (1.26, 8.85)，与实测最优 (2, 8) 吻合；Raven-OLMo-2-0425 拟合得 α=1.08、β=0.207，理论 (1.41, 9.17) 同样接近实测 (2, 8)。

## 6. 主要结论与发现

- LoopSpec 在全部评测任务上一致优于标准自回归解码：**最高 6.83× 加速**（Raven-TinyLlama-3T），Raven 家族峰值 5.88×–6.83×、γ 超过 14.5；Ouro 家族最高 3.36×、γ 超过 3.5（上界 R/d1 = 4）。
- 推理模型（thinking）下最高约 2.95× 加速（贪心），采样下最高 2.83×；长链推理场景仍保持高 γ。
- 残差第二提议 + 门控持续提升加速（如 Raven-Llama-3.2 上从 3.24× 提升至 3.74×–5.00×），优于非残差第二提议。
- Token 来源分析：首提议贡献 86%–96% 的提交 token，第二提议恢复 3.5%–10.5%，仅 0.19%–2.95% 需全深度重启。
- 理论推导的最优提议深度与实测最优配置高度一致，验证了幂律 TV 衰减假设的适用性。
- 相较训练型 DFlash，LoopSpec 在 Ouro Thinking 模型上最高再快 1.7×。

## 7. 优点

- **免训练、无损**：不引入外挂草稿模型与额外训练成本，拒绝采样 + 级联验证在贪心与采样下均保持目标模型分布。
- **结构契合**：首次将循环 Transformer 的"循环深度"显式转化为流水线并行度，天然利用中间循环状态作草稿。
- **理论贡献扎实**：证明重启概率仅取决于 d2 的近似误差（与 d1 解耦），并给出最优深度的闭式解，预测与实测吻合。
- **门控设计巧妙**：以极小代价控制分支指数增长，实测将平均有效 batch size 从约 40–44 降至约 32–34，峰值从约 239/243 降至 176/191。
- **工程实现完整**：在 SGLang 上实现分支级 KV cache 管理（索引复制而非状态复制）与 CUDA Graph 多 batch 尺寸录制，解决变长分支的调度开销。

## 8. 不足与局限

- **单 batch 限制**：所有评测均为单 batch 设置，未验证多请求/高并发服务场景下的吞吐表现，流水线分支的显存与调度开销在真实 serving 中可能放大。
- **P/C 层开销未完全覆盖**：γ 只衡量循环步数节省，不含 pre/post 层计算；Raven 中 d1 过小会带来更多草稿与分支初始化开销，导致部分配置 γ 高但 wall-clock 加速低。
- **门控的代价**：门控将拒绝上界由 ε2 放宽至 2ε2，存在精度—效率折衷；门控开启频率在 Raven-OLMo 的 MATH-500 上高达 40.4%，分支控制压力较大。
- **依赖幂律假设**：最优深度闭式解依赖 TV 距离的幂律上界，该拟合仅在两个 Raven 模型上验证，其他架构/任务是否成立未知。
- **对比覆盖有限**：与 DFlash 的对比仅限 Ouro Thinking 模型；未与 SPEED 等循环结构专用推测方法直接对比（论文仅指出其需训练且只支持贪心）。
- **约束条件**：要求 d2 与 R 均为 d1 的倍数且 d1 < d2 < R，配置空间受限；定理 2 对 R 的下界条件也限制适用范围。
- **资源信息不完整**：未报告总 GPU 数量、训练时长与能耗，DFlash 复现成本难以精确评估。
