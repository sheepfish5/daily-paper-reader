## 摘要
大语言模型（LLM）正越来越多地用于软件开发，但其在复杂硬件设计中的应用仍然有限。这一差距既源于公开硬件训练数据的稀缺，也源于硬件设计所采用的方法论根本不同。特别是，将LLM应用于硬件并不仅仅需要直接生成RTL：模型还必须理解模块边界、模块间连接以及验证需求。在本文中，我们提出了一种基于LLM的硬件开发框架，采用分层中间表示（IR）和端到端多智能体工作流。其核心思想是通过两种结构化IR为LLM提供硬件设计的抽象：架构草图（Architectural Sketch），用于刻画模块拓扑与互连；操作规范（Operational Specification），用于定义各模块的功能与接口。我们的框架利用这些IR将复杂设计分解为子模块，规定每个模块的功能，并推导出每个模块应如何测试与验证。我们在框架中引入多智能体调试循环，使智能体能够获得错误反馈，并控制调试细节，例如仿真中需要探测的信号。我们在Verilog-Eval基准上评估该框架，取得了95.5%的pass@5率，超过了当前最先进的LLM生成框架。为了更好地评估在复杂、真实设计上的性能，我们引入了一个新的案例研究，涵盖从通用处理器到数字信号处理系统的应用。实验结果表明，此类复杂设计超出了现有方法的能力范围，而我们的框架是唯一能够生成功能性端到端设计的方法。我们生成的RTL遵循所有行业标准设计规则，通过lint检查，功能正确且完全可综合。

## Abstract
Large language models (LLMs) are increasingly used in software development, but their use in complex hardware design remains limited. This gap stems from both the scarcity of public hardware training data and the fundamentally different methodologies used in hardware design. In particular, applying LLMs to hardware requires more than direct RTL generation: the model must understand module boundaries, inter-module connections, and verification requirements. In this paper, we present an LLM-based hardware development framework with hierarchical intermediate representations (IRs) and an end-to-end multi-agent workflow. The core idea is to provide an abstraction of hardware design to LLMs through two structured IRs: Architectural Sketch, which captures module topology and interconnection, and Operational Specification, which defines per-module functionality and interfaces. Our framework uses these IRs to decompose a complex design into sub-modules, specify the per-block functionality, and derive how each module should be tested and verified. We incorporate a multi-agent debug loop in the framework, allowing agents to get the error feedback and control the debug details such as the signals to be probed for simulation. We evaluate our framework on Verilog-Eval benchmark, achieving a pass@5 rate of 95.5%, which surpasses current state-of-the-art LLM generation frameworks. To better assess performance on complex, realistic designs, we introduce a new case study spanning applications from general-purpose processors to digital signal processing systems. Experimental results indicate that such complex designs exceed the capabilities of existing approaches, whereas our framework is the only one capable of producing functional end-to-end design. Our generated RTL follows all industry-standard design rules, is lint-clean, functionally correct and fully synthesizable.

## 1. 核心问题与研究动机

- **背景**：LLM 在软件开发中已显著提升效率（Copilot、Cursor、Claude Code 等），但硬件设计领域应用仍有限。
- **根本原因**：
  - 公开硬件训练数据稀缺；
  - 硬件设计方法论与软件根本不同——不仅需要生成 RTL，还要理解模块边界、模块间互连与验证需求。
- **现有工作的局限**：
  - 以 Verilog-Eval、RTLLM 等 benchmark 为代表的研究，主要针对**小型、单模块**设计，远不能反映真实硬件开发的多模块、复杂算法、自研 testbench 需求；
  - 验证阶段占 ASIC 设计时间中位数的 **50–60%**，但现有工作多只关注 RTL 生成；
  - ROME、HiveGen 支持层次化分解，但依赖人工 testbench；AutoBench、CorrectBench、MAGE 支持 testbench 生成，但仅限单模块，缺乏跨模块协调的生成-验证-调试闭环。
- **核心目标**：提出一个**端到端、全自动**的 LLM 硬件开发工作流，覆盖从高层设计意图 → 架构分解 → 模块生成 → testbench 生成 → 验证 → 迭代调试的完整链路。

## 2. 方法论

### 2.1 核心思想
- 通过两种**分层中间表示（IR）**为 LLM 提供硬件设计的抽象，使其能像人类工程师一样采用“分而治之”策略：
  - **Architectural Sketch（架构草图）**：捕获模块拓扑与互连；
  - **Operational Specification（操作规范）**：定义每模块的功能、接口与操作语义。

### 2.2 关键技术细节

**IR 1：Architectural Sketch（JSON 格式）**
- 由 **Architecture Designer Agent** 从框图 + 自然语言规格生成。
- 内容：模块层次、实例名、数据连接（信号名、端口位宽）、统一握手协议（`in_valid`/`out_valid`）。
- 关键点：**只表达结构连接，不表达功能语义或控制逻辑**，处于纯 RTL 之上的抽象层。
- 消除人工 RTL 连线与端口声明需求。

**IR 2：Operational Specification（JSON 格式）**
- 由 **Function Decomposer Agent** 生成，从操作视角刻画模块功能。
- 每个模块包含：
  - **Module header**：完整 Verilog 端口接口；
  - **操作列表**：操作名、控制信号（精确触发条件，如 `cmd==2'b11 && in_valid`）、输入模式（单周期 / 多拍流式）、输出模式、文字功能描述。
- 层次化组织：顶层操作可分解到子模块子操作，实现控制与数据流向下传播。
- 同时为每个模块生成**软件参考函数** `output = F(input)`，作为验证依据。

### 2.3 多智能体工作流

**规划阶段（Planning Stage）**
- 输入：框图 + 文本规格；
- Architecture Designer → Architectural Sketch；
- Function Decomposer → Operational Specifications + 软件参考函数；
- 全程无需人工干预。

**生成阶段（Generation Stage）**
- Design Generator 依据 IR 调度各模块任务；
- **自底向上**：先生成并验证所有子模块，再集成顶层模块；
- **Testbench 自动生成**：从 Operational Specification 提取 I/O 流模式，从软件参考函数获得 `F(input)`，通过确定性方式构建 testbench（而非纯 LLM 生成），支持层次化验证（顶层调用顶层参考函数，逐层下探）。

**多智能体调试循环（Multi-Agent Debug Loop）**
- 针对 vanilla 自反思循环的两大局限：① 仅靠输出不匹配、无内部信号可见性；② 每次迭代独立、重复引入相同错误。
- 改进机制包含四类智能体/组件：
  1. **Probing Information Generator**：识别需监测的关键内部信号；
  2. **自动化脚本**：插桩 testbench 捕获这些信号，仅在跳变时记录；
  3. **Debug Advisor**：分析执行轨迹 + IR + 原 RTL + 错误信息，给出根因诊断与修复建议；
  4. **Error Fixer**：依据建议修改 RTL。
- 维护 **Debug History**（错误模式、建议、RTL 差异），避免重复错误。
- 语法错误直接回传给生成 LLM 重新生成；功能错误走多智能体调试循环。
