## 摘要
自回归大语言模型（LLM）解码在每一步都会重新读取不断增长的键值（KV）缓存，因此长上下文注意力受限于图形处理单元（GPU）内存带宽。块稀疏注意力会跳过低贡献的 KV 块，但诸如最大相对块阈值（BLASST）之类在当前查询-键（QK）乘积之后才做出决定的选择器仍会读取每个 K 块，而依据当前查询做出决定的内存内处理（PIM）过滤器会在关键路径上引入一个串行 PIM 阶段。我们提出 AMEND，一种消除这两种依赖的 GPU-PIM 注意力设计。AMEND 根据在较早步骤中审计得到的裕度来预测每个块的 BLASST 判定，因此 GPU 只获取预测为幸存者的块，而高带宽内存（HBM）中的近存储体 PIM 单元则同时为被省略的补集打分。一个栈级控制器合并两种观测结果，更新预测器，并提前生成下一步的掩码，因此每个被预测丢弃的块都会被重新观测，而不会阻塞当前 token。工作点通过受约束的贝叶斯优化在虚假丢弃预算下离线选择。在 LongBench 和 RULER 运行中，AMEND 保持了接近基线的任务质量；在批量大小为 8 的仿真中，它在 8K-64K 上下文上相比稠密注意力实现了 1.40-3.63 倍的端到端解码加速，并将动态解码能耗降低 28-66%。

## Abstract
Autoregressive large language model (LLM) decoding re-reads a growing key-value (KV) cache at every step, so long-context attention is bound by graphics processing unit (GPU) memory bandwidth. Block-sparse attention skips low-contribution KV blocks, but a selector that decides after the current query-key (QK) product, such as max-relative block thresholding (BLASST), still reads every K block, and a processing-in-memory (PIM) filter that decides from the current query places a serial PIM stage on the critical path. We present AMEND, a GPU-PIM attention design that removes both dependencies. AMEND predicts each block's BLASST verdict from margins audited at earlier steps, so the GPU fetches only predicted survivors while near-bank PIM units in high-bandwidth memory (HBM) concurrently score the omitted complement. A stack-level controller merges both observations, updates the predictor, and eagerly generates the next step's mask, so every predicted drop is re-observed without blocking the current token. Operating points are selected offline by constrained Bayesian optimization under a false-drop budget. Across LongBench and RULER runs, AMEND preserves near-baseline task quality; in simulation at batch size 8, it achieves $1.40$-$3.63\times$ end-to-end decode speedup and 28-66% lower dynamic decode energy than dense attention across 8K-64K contexts.

## 1. 核心问题与整体含义

- **研究背景**：自回归 LLM 解码每步只处理一个固定大小的 query，却要重读随序列增长的 KV 缓存，因此长上下文解码是**GPU 内存带宽瓶颈**，并主导长上下文解码时间。
- **现有块稀疏注意力的两类缺陷**：
  - **后 QK 选择器（如 BLASST）**：在读取全部 K 块、完成当前 QK 之后才能判定，虽然能跳过 softmax/V/PV，但**已经读了每个 K 块**。在 90% 块稀疏度下，K 仍占其剩余 K+V 逻辑流量的约 91%（附录 C 实测 91.1–93.3%）。
  - **当前查询 PIM 过滤器**：把全缓存评分搬到近存储体，但掩码仍由当前 query 决定，等于在"query→scores→mask→attention"这条串行链上**插入一个串行 PIM 阶段**，落在关键路径上。
- **核心洞察**：GPU 与 PIM 是两个可以并行工作的引擎，要同时利用二者就必须**打破这条串行链**。若判定由更早步骤预测而非当前 query 计算得到，GPU 就能零延迟启动预测幸存块，同时对预测丢弃块并行审计，审计结果供**下一步**使用而非阻塞当前 token。
- **可行性依据**：相邻解码步的 query 与上下文增量变化，重要区域具有持续性。作者在 Qwen3-1.7B 的 LongBench 轨迹上测得 **89.2% 的 BLASST 判定在下一步保持不变**（lag-1 翻转率按层从约 0.001 到 0.168 不等）。
- **整体含义**：论文识别了"后 QK 稀疏"与"预 QK 掩码"之间的 K 流量缺口，提出一种可审计的因果预测机制，把块稀疏决策**提前一步**，并给出 GPU–PIM 执行契约与离线工作点选择方法。

## 2. 方法论

### 2.1 核心思想
- **预测—审计闭环**：用**先前步骤审计得到的 margin** 预测每个块的 BLASST 判定，在当前 QK 之前生成幸存者掩码；GPU 只跑幸存块注意力，近存储体 PIM 并行计算被全局省略块的 QK；栈级控制器合并两路观测、更新预测器、**急切生成下一步掩码**。

### 2.2 决策参考：全缓存 BLASST
- 块 b 的当前查询块最大值 $m^\star_{t,\ell,h,b}=\max_{j\in I_b} q^\top_{t,\ell,h}k_{\ell,g(h),j}/\sqrt d$。
- 排他前缀最大值 $p^\star_{t,\ell,h,b}=\max_{b'<b} m^\star_{t,\ell,h,b'}$，上下文偏移 $\eta_t=\log(\text{TSF}/S_t)$。
- GQA 归约后的选择裕度：$\gamma^\star_{t,\ell,g,b}=\max_{h\in G(g)}(m^\star_{t,\ell,h,b}-p^\star_{t,\ell,h,b}-\eta_t)$。
- **DROP 当且仅当 $\gamma^\star<0$ 且 $S_t\ge\text{TSF}$**；块 0 强制保留。选择 BLASST 而非 Top-K 的原因：最大相对判定是**逐块比较**、历史可单独跟踪，而 Top-K 保留依赖所有块的排序。

### 2.3 因果判定预测（读侧，步骤 1○）
- 每个单元（layer, KV head, block）维护状态 $(\mu, M_2, a, c)$：margin EMA、二阶矩、丢弃连跑年龄、2-bit Schmitt 计数器；波动率 $\sigma=\sqrt{\max(M_2-\mu^2,0)}$ 由状态导出。
- 五维工作点 $\theta=(r,\delta,\alpha,R,z)$ 由离线选择冻结。
- **基础判定（式 1）**：$u_t = \mathbb{1}[a^-_t\ge r]\cdot\mathbb{1}[\mu^-_t+z\sigma^-_t<-\delta]\cdot\mathbb{1}[\text{base eligible}]$；等价实现 $q=\mu+\delta$，$q<0\wedge q^2>z^2 v$，**无需开方单元**。
- **迟滞（式 2）**：$c^+_t=\text{clip}(c^-_t+(2u_t-1),0,3)$，仅当 $c^+_t=3$ 饱和时才发出丢弃，抑制孤立翻转。
- **掩码形成（式 3）**：$P^{keep}_t=1-D^{pre}_t$，其中 $D^{pre}_t=\hat D_t\wedge\mathbb{1}[\text{seam allows drop}]$；再由幸存者 BLASST 收紧 $C^{keep}_t=P^{keep}_t\wedge\text{BLASSTKeep}_{survivor}$。硬保留包括块 0、最后一块、部分尾块、最近 R 块窗口。
- **表 1 列出各元素角色**：$\mu$（margin 而非原始分数携带时序信号）、$\alpha$（响应 vs 噪声）、$\sigma,z$（波动惩罚）、$\delta$（保守性主旋钮）、$a,r$（年龄下限）、$R$（近因窗口）、2-bit 计数器（迟滞）、seam 规则（硬强制）。

### 2.4 补集审计与状态更新（写侧，步骤 2○–5○）
- **观测洞问题**：预测丢弃的单元不再被 GPU 观测，预测器只从自选样本学习，属**选择性标签问题**；且错误丢弃不可在步内回滚，只能通过**重调后续状态**而非修复当前输出。
- **审计覆盖逻辑补集**：$A_t=\{(g,b):P^{keep}_{t,g,b}=0\wedge\text{FULL}_t(b)=1\}$，与在线观测集 $O^{online,full}_t$ 之并等于全部满块单元。
- **两路观测通道**：
  - GPU 路径（union）给出 $\gamma^U$，用于 union 内部的预测丢弃（因为别的 head 保留了该块）；
  - PIM 补集 QK 给出 $\gamma^\star$，用于全局省略块。
  - 前缀不等式保证 $p^P\le p^U\le p^\star$，$\gamma^P\ge\gamma^U\ge\gamma^\star$，故幸存者 BLASST **不会在预测幸存者中制造额外假丢弃**。
- **重构（步骤 4○）**：控制器按块序合并 GPU 与 PIM 最大值，做排他前缀与 GQA 归约，得到 $A_t$ 上的全缓存 margin 与判定；逻辑审计覆盖所有预测丢弃满块，物理 PIM QK 只覆盖全局省略块。
- **状态更新（式 8）**：$\mu^+=\alpha x+(1-\alpha)\mu^-$，$M_2^+=\alpha x^2+(1-\alpha)M_2^-$，$\sigma^+=\sqrt{\max(M_2^+-(\mu^+)^2,0)}$。表 2 规定写入规则：年龄 $a$ 跟随实际 $C^{keep}_t$ 并在最大搜索 $r$ 处饱和，审计 KEEP 重置为 0，审计 DROP 不变；计数器 $c$ 仅由判定规则写。

### 2.5 执行契约与系统映射
- **五条不变式**：掩码只用步 $t-1$ 及更早反馈；预测丢弃步内不回滚；每个预测丢弃满块被 GPU–PIM 观测划分覆盖；$O_t$ 不依赖 audit$_t$；audit$_t$ 生成步 $t+1$ 的掩码（"不等待、不修复"）。
- **依赖图**：$O_t$ 只依赖 $Q_t$ 与 $P^{keep}_t$；跨步硬依赖仅为 3○、4○ 需在步 $t+1$ 的 1○ 前完成；暴露的审计停顿 $\text{stall}_{t+1,\ell}=\max(0,T^{audit}_{t,\ell}-T^{fold}_{t+1,\ell})$。
- **硬件映射**：GPU 做幸存 QK、幸存者 BLASST、softmax、PV；AttAcc 派生的近存储体 GEMV 做 union 外块的 QK 并只返回块最大值；栈级控制器做合并、重构、状态折叠与下一步掩码。控制器仅限比较/选择、最大与前缀归约、GQA 归约、小幅饱和状态更新、bitmap 与地址处理，**无指数、除法或 softmax 数据通路**（以 AttAcc 1.38 mm² 7nm 缓冲die softmax 单元为资源预算参考）。
- **工作量守恒**：$\text{QK}_{surv}+\text{QK}_{omit}=\text{QK}_{full}$——AMEND 是把省略 QK **搬迁**到 PIM，而非删除。

### 2.6 工作点选择（离线）
- 五旋钮 $\theta=(r,\delta,\alpha,R,z)$ 通过跨 token 递推耦合，响应非单调、无可用梯度、每次评估需回放一条解码轨迹，故建模为**约束混合变量黑箱问题**，适配 **SCBO**（Scalable Constrained Bayesian Optimization）。
- 指标：假丢弃率 $F_{drop,N}$（式 9）与丢弃召回 $Q_N$（式 10），均为按实例的无加权宏平均；问题为 $\max_\theta Q_N(\theta)\ \text{s.t.}\ F_{drop,N}(\theta)\le\tau$（式 11）。
- 流程：独立 GP 拟合两个目标 → 局部信赖域内约束 Thompson 采样 → 回放更新代理与信赖域 → 冻结最佳可行点；若无可行点则**返回失败而不放宽 $\tau$**。

## 3. 实验设计

- **模型**：Llama-3.1-8B-Instruct、Qwen3-8B。
- **数据集/Benchmark**：

  - **RULER**：每模型/上下文设置 1,300 条、13 个任务；Llama 覆盖 8K/16K/32K/64K，Qwen 覆盖 32K。任务分四类：检索（8 种 NIAH 变体）、多跳追踪、聚合、问答。

- **配置**：块大小 16 token；TSF=64（BLASST/AMEND）；Quest 预算 Llama LongBench 256，Llama RULER 8K/16K/32K/64K 为 256/512/1,024/2,
