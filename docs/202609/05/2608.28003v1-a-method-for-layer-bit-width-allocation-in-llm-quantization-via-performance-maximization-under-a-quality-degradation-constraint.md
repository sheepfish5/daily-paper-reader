## 摘要
本文针对Gemma-3-1B提出了一种层位分配方法，将问题表述为在退化预算约束（允许的生成质量损失水平）下最大化性能（延迟降低）。该方法不同于文献中使用的耗时且消耗资源的均匀层量化方法（如GPTQ或AWQ），也不同于没有经过验证的性能加速效果的分配方法（如MixLLM或TorchAO）。我们应用了先前工作SA-PTQ中产生的层敏感性分布，并在TensorRT-LLM内部使用激活直通模式。根据先前步骤中引入的分组（5+5、10+10、all26），逐块单独确定每层的精度，区分FFN、Attention和lm_head对整体加速的贡献。在RTX 5090上测量了13种W8A8变体的时钟速度。我们发现，对于FFN和lm_head，量化/反量化的时间成本由整数运算的使用所补偿，而在短上下文长度下，Attention的情况则相反：额外的量化步骤会减慢执行速度。我们提出了TensorRT-LLM的SmoothQuant手动实现，由于导出失败且不适用于lm_head，该实现是必要的。在综合考虑所有三个标准且退化最小的情况下，找到的最佳解决方案是FFN 5+5加lm_head，其延迟降低了11.0%，且质量损失可忽略不计（Top-1一致性98.90%，困惑度退化+0.85%）。在FFN all26加lm_head可接受的质量损失下，发现可实现高达19.1%的加速。我们建议进一步优化：INT8融合注意力内核、KV缓存量化、使用FP8而非INT8，以及与FFN类似的部分Attention量化。

## Abstract
This paper proposes a layer bit allocation method for Gemma-3-1B, formulating the problem as performance maximization (latency decrease) given a degradation budget constraint (allowable level of generation quality loss). This approach is different from time- and resource-consuming uniform layer quantization methods that are used in the literature (like GPTQ or AWQ) or allocation methods without proven performance-accelerating effect (like MixLLM or TorchAO). The layer sensitivity profile resulting from our prior work SA-PTQ is applied using the activation pass-through mode inside TensorRT-LLM. For each layer precision is determined individually in blocks, according to a grouping introduced in the prior step (5+5, 10+10, all26), differentiating the contribution of FFN, Attention, and lm_head to the overall speedup. The clock speed was measured for 13 W8A8 variants on an RTX 5090. We find that for FFN and lm_head the time cost of quantization/dequantization is compensated for by the use of integer arithmetic, while for short context lengths, the opposite holds true for Attention: an additional step of quantization slows execution down. We propose a manual implementation of SmoothQuant for TensorRT-LLM which was necessary due to export failures, unavailable for lm_head. The best solution found under joint consideration of all three criteria with minimal degradation was FFN 5+5 with lm_head, providing an 11.0% reduction in latency with negligible quality loss (98.90% Top-1 agreement, +0.85% perplexity degradation). With acceptable quality loss for FFN all26 + lm_head, a speedup up to 19.1% was found possible. We suggest further optimizations: fused attention kernels in INT8, KV-cache quantization, using FP8 instead of INT8 and partial Attention quantization analogous to FFN.

- **研究背景**：小语言模型（sLLM，如 Gemma-3-1B）在消费级GPU上可实际部署，但其推理延迟仍制约实时应用（如游戏NPC、交互式生成）。模型约2GB（FP16），显存已不再是瓶颈，计算/访存效率成为关键优化目标。

## 2. 论文提出的方法论

### 2.1 核心思想

- 将量化问题重构为**延迟感知的位宽分配优化**：在质量退化约束下最大化推理吞吐，而非单纯最小化内存占用或权重误差。
- 基于统一分组定量评测不同量化策略的加速效果，在 FFN-only、Attention+FFN、FFN+lm_head 乃至全 INT8 的情况下对端到端性能进行实测。该量化粒度远大于以往逐层（per-layer）分配研究，使其能在可复现的商业推理引擎上得到可靠测量。

## 6. 论文的主要结论与发现

- **FFN 量化稳定加速**：FFN 5+5 → 1.031×；10+10 → 1.075×；all26 → 1.090～1.10×。量化/去量化开销被 INT8 整数运算补偿。
- **Attention 量化反而降速**：在短上下文、batch=1 场景，额外 Q/DQ 步骤产生的开销 > INT8 GEMM 节约的访存/计算量。剖析表明：决定性瓶颈是 TRT-LLM 中 masked_multihead_attention fused kernel 在 FP16 下运行，QKV 投影的 INT8 量化仅加速了规模较小的线性层；质量没有因此下降，但速度反而比不量化时低约 0.021×。因此 Attention 量化在当前工程实现下不划算（“质量可接受”与“速度无提升”是两个层面问题）。
- **lm_head 量化需手动修补**：由于 tied-embedding 的导出 bug，官方工具无法正确量化 lm_head；手工实现 SmoothQuant 后，单独量化获得 1.071× 加速，质量几乎不变（Top-1 一致率 98.90%，困惑度退化仅 +0.85%）。
- **最佳综合配置**：FFN 5+5 + lm_head = 1.110×（+11.0%），质量几乎无损失。若允许明显质量退化，FFN all26 + lm_head 可达 1.191×（+19.1%）。
- **注意力质量可接受**：attn_ffn（全部 Attention 量化）配置的生成质量未出现可辨退化。
- **硬件架构影响调度**：RTX 5090（Blackwell）上所有量化层均用 sm80_xmma_gemm_i8i8 kernel，层数越多加速越大；RTX 3070（Ampere）上多于 5 层量化会切换到较慢的 i8f32 kernel，因此 5+5 最优——说明 kernel 选择策略依赖硬件。
- **未来方向**：INT8 fused attention kernel、KV-cache 量化（INT8/FP8）、FP8（FFN 单独 FP8 得到 1.46× 加速）以及类似 FFN 的分块（blockwise）Attention 量化。

## 7. 优点

- **真实测量而非估算**：不靠 FLOPs 理论推导，而是在商业推理引擎上直接进行 wall-clock 速度测量，捕捉 Q/DQ 实际开销，避免理论推断的乐观偏差。
- **粒度适中的归因实验设计**：FFN、Attention、lm_head 分别量化后再组合，能明确对各子结构解耦收益来源（不同算子在 GEMV 场景下有着本质差异），定位瓶颈。对注意力机制的“速度倒挂”效应给出了 kernel 级解释（fused MHA 仍跑 FP16、GQA 投影矩阵偏小、Q/DQ 额外开销），有较高工程价值。
- **方法论复用性强**：SA-PTQ 的分层敏感度 + 分组（blockwise）量化配置的思路可迁移至任意现代 decoder-only LLM。
- **质量评估多维度**：SQNR、困惑度、Top-1 一致率三管齐下，将信号噪声比与文本语义漂移关联起来。
- **问题诊断细**：暴露 lm_head 的 tied-embedding 量化 bug 并提供平滑缩放的手工解决，对工程落地有直接参考价值。
- **对比有客观性**：每次引擎独立进程、同 session 统一测量流程重建，给出中位数而非均值，减少系统噪声影响；同时提供了 Blackwell 与 Ampere 两个架构的数据作为外部效度参照。

## 8. 不足与局限

- **实验场景窄**：主要聚焦 batch=1 的短上下文 decode；长上下文、大批量（如典型生产场景 bs=32/64+）尚未覆盖。作者自认，长上下文下 attention 的访存特性会根本变化，结论未必外推。
