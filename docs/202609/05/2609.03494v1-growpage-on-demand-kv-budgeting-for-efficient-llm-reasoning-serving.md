## 摘要
长输出推理使得键值（KV）缓存成为高效LLM服务的关键内存瓶颈。现有的KV压缩方法通常依赖于预定义的每请求预算，并且仅调整保留哪些KV状态，导致在解码过程中总容量固定不变。然而，推理工作负载表现出显著的需求变化：不同的请求需要不同的KV容量，并且单个请求的注意力需求在生成过程中会演变。我们提出了GrowPage，一个按需KV预算分配框架，将KV容量视为运行时资源。GrowPage维护轻量级的双时间尺度查询摘要，以捕捉近期和长期的注意力行为，并利用它们的相对注意力工作集来估计需求演变。在每个容量边界，GrowPage要么在当前分配内压缩KV状态，要么在出现更广泛需求时获取额外的物理页。通过与PagedAttention的页级内存抽象集成，GrowPage保持了连续批处理和前缀缓存。在多种模型上的推理基准实验表明，与现有方法相比，GrowPage实现了优越的性能-吞吐量权衡。

## Abstract
Long-output reasoning has made the key--value (KV) cache a critical memory bottleneck for efficient LLM serving. Existing KV compression methods usually rely on a predefined per-request budget and adjust only which KV states are retained, leaving the total capacity fixed throughout decoding. However, reasoning workloads exhibit substantial demand variation: different requests require different KV capacities, and the attention demand of an individual request evolves during generation. We introduce \textbf{GrowPage}, an on-demand KV budgeting framework that treats KV capacity as a runtime resource. GrowPage maintains lightweight dual-timescale query summaries to capture recent and long-term attention behaviors, and uses their relative attention working sets to estimate demand evolution. At each capacity boundary, GrowPage either compresses KV states within the current allocation or acquires an additional physical page when broader demand emerges. By integrating with PagedAttention's page-level memory abstraction, GrowPage preserves continuous batching and prefix caching. Experiments on reasoning benchmarks across multiple models show that GrowPage achieves a superior performance--throughput trade-off over existing approaches.

# GrowPage：面向高效 LLM 推理服务的按需 KV 预算分配（论文总结）

## 1. 核心问题与整体含义

- **背景与动机**：大型推理模型（如 DeepSeek-R1、Qwen3 等）通过生成长思维链（CoT）来完成数学推理与代码生成，输出可达数千乃至数万 token。随着 KV 缓存不断增长，GPU 上可驻留的并发请求数受限，KV 缓存成为 LLM 推理服务的核心内存瓶颈。
- **已有方法的不足**：
  - 现有 KV 压缩方法多基于预定义的**每请求固定容量预算**，只决定“保留哪些 KV 状态”，而不调整“总容量大小”，因而无法适应推理负载的**跨请求异质性**（不同请求所需 KV 容量差异很大）和**请求内时间动态性**（单个请求在解码过程中注意力集中度不断变化）。
  - 传统方法虽能降低内存，但往往与连续批处理（continuous batching）、前缀缓存（prefix caching）等现代服务机制脱节，内存节省难以转化为实际吞吐收益。
- **核心观点**：KV 容量本身应当成为**运行时可按需分配的决策变量**，而非预先固定的内存预留。GrowPage 据此提出按需 KV 预算分配框架，将 KV 容量视为动态运行时资源，根据请求实时的注意力需求进行压缩或扩容，以同时改善推理准确率和服务吞吐量。

## 2. 方法论：GrowPage 框架

### 2.1 核心思想
GrowPage 将每个请求的 KV 缓存容量作为在线决策量：在每个 KV 容量边界，动态选择 **Compress & Hold（压缩保持）** 或 **Grow by One Page（按页扩容）**；其决策依据是对请求注意力需求演变趋势的轻量级在线估计。

### 2.2 需求估计：双时间尺度查询摘要
- 维护两个指数滑动平均（EMA）查询向量，在**应用 RoPE 之前**、按 query 归一化后的空间中进行平滑：
  \[
  \bar{q}^x_t = \beta_x \bar{q}^x_{t-1} + (1-\beta_x) q_t,\quad x \in \{S,L\}
  \]
  - 短时间尺度（\(\beta_S=0.9\)）：捕捉近期注意力行为。
  - 长时间尺度（\(\beta_L=0.999\)）：提供历史性参考。
- 双尺度设计的意义：短尺度查询反映“当前”注意力需求，长尺度查询作为“历史基准”，二者比较可估计需求变化趋势；同时使用 max 融合的方式保留对任一尺度重要的 token。

### 2.3 理论与指标
- 定义 p 覆盖率注意力需求 \(D_p(a_t)\)，即需保留最大的若干个注意力权重使其累计概率达到覆盖率 \(p\)（默认 0.99）。
- **定理 3.1**：在值向量有界假设（\(\|v_i\|_2 \le V_{\max}\)）下，达到近似误差容忍度 δ 所需的最坏情形 KV 容量等于 \(D_{1-\delta/(2V_{\max})}(a_t)\)，即注意力越集中所需 KV 容量越小。
- 在各层/KV 头上聚合得到短、长时间尺度的平均工作集比例 \(r^S_t, r^L_t\)，并计算需求趋势信号：
  \[
  \Delta_t = r^S_t - r^L_t
  \]
  - \(\Delta_t<0\)：注意力趋于集中，适合压缩；
  - \(\Delta_t>0\)：工作集扩大，适合按页扩容；
  - 默认阈值 \(\tau=0\)。

### 2.4 容量控制动作
- **Compress & Hold**：在当前物理页分配不变的前提下，压缩历史 KV 状态释放出一页空闲槽位；KV 选择通过 block-local 与全局 Top-k 结合进行；保留 token 的重要性分数为 \(s_{i,\ell,h}=\max(a^S_{i,\ell,h},a^L_{i,\ell,h})\)。
- **Grow by One Page**：从全局空闲页池申请一个额外的物理页，追加到请求的 block table 中。
- **压缩后不主动缩页**，避免对活跃请求进行不可逆的 KV 二次驱逐，保证稳定性。

### 2.5 系统集成
- 与 **PagedAttention** 集成，保持页级内存抽象不变，因而天然兼容连续批处理、前缀缓存与 CUDA Graph。
- 采用**预分配查询槽位**管理辅助状态，解码路径只做轻量更新，仅在容量边界做开销较高的注意力需求估计。
- 压缩采用**异步管线**，与正常解码重叠；全局内存不足时，请求会从“扩容”自动退化为“压缩”，并允许调度器进行抢占。

## 6. 主要结论与发现

- **在服务效率方面**：GrowPage 相较 FullKV 推理，在 DeepSeek-R1-Distill-Llama-8B 和 Qwen3-8B 上平均吞吐提升约 64.3% 和 60.2%，且 Pass@1 准确率几乎不损失。
- **在与固定预算方法 Zipage 对比**：GrowPage 在所有 benchmark 上取得更好的准确率-吞吐量权衡；混合负载下同等内存可支撑更多并发请求，例如 Qwen3-8B 上平均 KV 预算 3442 时并发数 121，优于 Zipage-4096（100）并接近 Zipage-8192 的准确率，吞吐约为其 1.9 倍。
- **需求信号有效性**：双时间尺度摘要产生的 \(\Delta_t\) 对未来注意力需求变化有较强预测力，且能区分“扩容”的收益时机。
- **固定预算的根本问题**：请求的最低充分 KV 预算差异跨度大（512~8192 以上），且注意力集中度在解码中反复波动；固定预算只能在“浪费内存”与“容量不足”之间折中，按需容量控制则能动态适配。
- **系统集成可行性**：GrowPage 的在线估计与容量控制开销很小（单次事件占解码时间不到 0.14%），在不破坏 PagedAttention 生态的前提下可实现按需 KV 分配。

## 8. 不足与局限

- **算力规模有限**：所有实验仅在单张 A100（80 GB）上完成，且只验证了 8B 规模模型；对于更大的模型（如 70B+）、多卡张量并行/推理引擎（如 vLLM 集群环境）或更长上下文的通用服务场景，其适用性与收益尚不明确。
- **内存基准构建的选择偏差风险**：固定预算对比方法使用的数据集专用 KV 预算（表 5）虽按此前方法配置沿用，但仍可能对某些方法有利或不利；论文未提供对 Zipage 等其他方法在更大预算范围下更细粒度的完整 Pareto 前沿。
- **较复杂的系统调度交互**：动态调整过程中会出现 fallback 和抢占事件（例如 GrowPage 在 AMC23 上有 597 次 fallback 与 1361 次抢占；双向收缩策略使抢占增至 4668 次），说明扩容需求与全局内存管理器之间存在潜在竞争，当前实现尚未完全消除这种系统级开销。
- **双向容量回收缺失**：主设计刻意避免主动缩页，虽然在推理质量上更为稳妥，但也可能导致低需求请求长期占用已分配容量；论文仅在附录中以少量分析说明双向收缩有损性能，更精细的回收策略有待探索。
- **超参数依赖与泛化风险**：方法涉及多个超参数（EMA 衰减系数、覆盖率 p、阈值 \(\tau\)、局部配额 \(k_{loc}\) 等），虽在所选模型与数据集上表现稳定，但其对不同模型家族/注意力机制（如 MLA、稀疏注意力架构）的敏感性未充分验证。
- **随机性与评估限制**：部分数据分析基于较少样本（如 AMC23 只有 40 题）、少量固定预算等级，个别请求类别样本极少（如 AIME24 中 4K/8K 类 n=2~3），统计置信度有限。
- **对“正确性”的衡量较粗**：Pass@1 使用采样温度 0.6、每问题多次独立生成，但未就校准、奖励模型或输出自洽性做进一步验证，因此能力变化的解释力度仍有提升空间。
