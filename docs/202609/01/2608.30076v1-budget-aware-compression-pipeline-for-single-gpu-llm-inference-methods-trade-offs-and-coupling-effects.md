## 摘要
在NVIDIA GPU上单卡部署70B参数语言模型受到设备内存、长上下文吞吐量和工程集成成本的约束。我们将单GPU推理视为一个在这三个维度上的预算感知设计问题，并研究剪枝、量化和KV缓存压缩在真实执行中如何相互作用。受控消融实验表明，逐层剪枝使权重量化更加鲁棒。KV缓存稀疏化通过减少内存而不损害解码速度来补充INT8 KV量化，而静态向量量化器通常与动态缓存冲突。在这些耦合结果和显式预算跟踪的指导下，我们组装了一个实用的流水线，将70B模型压缩到约33 GB，在单个A40上处理10k token提示时维持约57 tokens/s的速度，并在常见和推理基准上将绝对准确率保持在5%以内。我们贡献了设计规则和一个可复现的评估协议，该协议联合报告质量、内存和端到端速度，并为在真实单GPU约束下的自动化流水线搜索提供了基础。

## Abstract
Single-GPU deployment of 70B-parameter language models on an NVIDIA GPU is constrained by device memory, long-context throughput, and engineering integration cost. We cast single-GPU inference as a budget-aware design problem over these three axes and study how pruning, quantization, and KV-cache compression interact under realistic execution. Controlled ablations show that layer-wise pruning makes weight quantization more robust. KV-cache sparsification complements INT8 KV quantization by reducing memory without hurting decoding speed, while static vector quantizers often conflict with dynamic caching. Guided by these coupling results and explicit budget tracking, we assembled a practical pipeline and compressed a 70B model to about 33 GB, sustained about 57 tokens/s on 10k token prompts on a single A40, and kept absolute accuracy within 5% on common and reasoning benchmarks. We contribute design rules and a reproducible evaluation protocol that jointly report quality, memory, and end-to-end speed, and we provide a foundation for automated pipeline search under realistic single-GPU constraints.

### 2.2 关键技术细节

- **权重量化（AWQ）**：4-bit 权重、FP16 激活，通过保护激活敏感通道降低量化误差，模型从 >140 GB 压缩至约 38 GB。
- **层剪枝（ShortGPT）**：基于 BI（Block Importance）系数评估层重要性；在 AWQ 之后剪枝 12.5% 的层，模型进一步降至约 33 GB。
- **KV 缓存压缩**：PyramidKV 以层次化信息漏斗机制保留重要 token，结合 INT8 逐头缩放量化，在 10k token 上下文下使峰值显存降至 39 GB 左右。
- **连续性感知层重排与规划（Continuity-aware Layer Reordering）**——论文对 ShortGPT 的改进：
  - **BI 系数**（公式 1）：衡量相邻层隐藏状态夹角的余弦相似度变化，BI 越大表示该层越重要：
    - BI_i = 1 − E[ X_i,t^T X_{i+1,t} / (‖X_i,t‖₂ ‖X_{i+1,t}‖₂) ]
  - **局部连续性系数**（公式 2）：在滑动窗口内衡量 BI 变化的平滑程度，用于识别可整块剪除的低重要性连续区间：
    - CC_local(k) = 1 − (1/(|W_k|−1)) Σ|BI_i − BI_{i−1}| / BI_max
  - **候选生成与贪心规划**：生成单层候选池（C_single）与连续块候选池（C_block），按 BI 均值和连续性阈值筛选，通过贪心算法选择 K 个剪枝区间，并对相邻选择施加连续性奖励（λ=0.1）。
  - **实验结果**：在同样剪 20/80 层的预算下，相比原始 ShortGPT，ARC-E 从 0.7012 提升至 0.7243，GPQA-D 从 0.2879 大幅恢复至 0.4091。

## 6. 论文的主要结论与发现

1. **剪枝使量化更鲁棒**：在 AWQ 量化之后施加层剪枝（而非剪枝后再量化），可缩短量化误差的传播路径，使端到端精度更稳定；反之，先剪枝后量化会破坏激活分布、恶化校准效果。
2. **KV 稀疏化与 INT8 量化存在正协同**：PyramidKV 将缓存集中在重要 token 上，INT8 量化进一步压缩剩余条目，在不损失解码速度的前提下将峰值显存降低 1.6 GB 以上。
3. **负耦合案例**：
   - 向量量化（QTIP/QuIP#）依赖静态缓存布局，与动态 KV 稀疏化（PyramidKV/SnapKV）冲突，导致编译失败或无法获得实际显存收益；
   - 非结构化稀疏（Wanda）与 AWQ 的激活感知重构不兼容，实验中导致数学提示解码不稳定、困惑度上升到数千量级。
4. **层剪枝存在极限**：ShortGPT 在 70B 上剪 25% 深度时精度骤降；但通过连续性感知层重排，可显著缓解这一退化（GPQA-D 从 0.2879 恢复至 0.4091）。
5. **端到端可达性**：最终流水线将 DeepSeek-R1-Distill-Llama-70B 压缩至约 33 GB，在单张 A40 上处理 10k token 提示时达到约 57 tokens/s，并且在 ARC、Winogrande、GPQA 等基准上绝对精度损失保持在 5% 以内。
6. **方法论启示**：压缩任务是耦合的系统设计问题，最优流水线不等于各方法单独最优的简单拼接；兼容性与预算对齐至关重要。
