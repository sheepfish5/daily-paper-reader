## 摘要
FPGA-GPP异构系统将软件灵活性与可重构硬件的性能和能效相结合。然而，确定哪些应用任务应在GPP还是FPGA上执行需要丰富的专业知识和设计空间探索，尤其是在用户目标涉及延迟、通信、资源利用率和功耗等方面有所不同时。本文提出了Gen-TAS，一种基于知识的LLM框架，用于用户特定的FPGA-GPP任务分配。通过将任务图分析与RAG相结合，Gen-TAS将LLM推理基于历史实现知识，并生成针对特定目标的多个可解释策略。人在回路选择和确定性后端将LLM生成的决策连接到可复现的FPGA SoC实现。在多个LLM上对CNN和SDR工作负载的实验证明了稳定、需求驱动的分配。在面向延迟的目标下，遵循所选策略的实现相对于相应的全GPP基线分别实现了高达2.45倍和92.53倍的加速，而其他目标选择的策略则以一定的加速性能换取FPGA-GPP通信、资源利用率或FPGA功耗。

## Abstract
FPGA-GPP heterogeneous systems combine software flexibility with the performance and energy efficiency of reconfigurable hardware. However, determining which application tasks should execute on the GPP or FPGA requires extensive expertise and design-space exploration, particularly when user objectives vary across latency, communication, resource utilisation, and power. This paper proposes Gen-TAS, a knowledge-grounded LLM framework for user-specific FPGA-GPP task allocation. By combining task-graph analysis with RAG, Gen-TAS grounds LLM reasoning in historical implementation knowledge and generates multiple explainable strategies tailored to the specified objectives. Human-in-the-loop selection and a deterministic backend connect LLM-generated decisions to reproducible FPGA SoC implementations. Experiments on CNN and SDR workloads across multiple LLMs demonstrate stable, requirement-driven allocation. Under latency-oriented objectives, implementations following the selected strategies achieve speedups of up to 2.45$\times$ and 92.53$\times$, respectively, relative to the corresponding all-GPP baselines while other objectives select strategies that trade some acceleration performance for FPGA-GPP communication, resource utilisation, or FPGA power.

# Gen-TAS 论文总结

## 1. 核心问题与整体含义

- **研究背景**：FPGA-GPP（现场可编程门阵列-通用处理器）异构系统兼具软件灵活性与硬件加速性能，但软硬件任务划分直接决定系统延迟、资源利用率、通信开销和功耗。传统的软硬件划分高度依赖专家经验，且需反复进行设计空间探索（DSE）。
- **核心问题**：用户设计目标多样（延迟、通信、功耗、资源等），现有方法无法高效、通用地根据用户需求自动生成任务分配策略。已有工作（如EcoSys、StreamBlocks）多针对特定应用或依赖分析模型，而LLM辅助EDA工具多聚焦于硬件生成而非通用软硬件划分，缺乏对FPGA-GPP任务分配问题的统一解决方案。
- **整体含义**：Gen-TAS旨在将LLM的自然语言理解、可解释推理能力与历史实现知识（知识库）相结合，实现**需求驱动的、可解释的、可复现的**FPGA-GPP函数级任务自动分配，降低FPGA异构系统设计门槛。

## 2. 方法论

- **核心思想**：知识锚定的生成式任务分配。将应用映射为有序任务图G=(T, E)，每个候选分区Pj将每个任务分配给GPP或FPGA。框架以用户自然语言需求（延迟、功耗、资源等目标）为输入，通过**RAG（检索增强生成）**从历史实现知识库中检索相关证据，驱动LLM生成多个排序候选策略，并通过确定性后端实现。

- **系统工作流**（四阶段）：
  1. **设计上下文构建**：解析用户需求，从HLS C/C++源码中提取任务级描述（操作类型、输入输出维度、精度、缓冲区大小），构建任务图并计算通信量。
  2. **Agentic AI策略生成**：将任务信息、检索到的KB证据、平台约束、设计目标输入LLM——LLM返回N个排序候选分配策略（默认N=3），每个策略附带FPGA/GPP任务集、通信边界及基于证据的文本理由。
  3. **确定性验证与实现**：自动校验分区的合法性（任务唯一分配、FPGA任务连续性等），排除重复项；用户选择后，确定性后端自动生成HLS顶层设计、测试平台、Vitis HLS/Vivado的TCL脚本以及PYNQ软件。
  4. **部署与评估**：在ZCU104板卡上通过PYNQ执行并测量延迟、资源占用和功耗。

- **知识库（KB）**：存储任务特征（计算/通信类型）和测量的分区级实现记录（延迟、LUT/FF/DSP/BRAM用量、时序、功耗、通信边界）。检索时使用**token级余弦相似度**打分，选出得分最高的12条记录作为LLM上下文。

- **关键设计决策**：
  - 人机协同：LLM生成候选策略，用户介入选择，保证可解释性与可控性；
  - 生成与实现解耦：LLM只负责建议分配，后端实现是确定性的，确保可复现性；
  - 多目标支持：将自然语言需求解析后形成具体约束（如LUT/功耗阈值），指导LLM生成满足目标的分类策略。

## 3. 实验设计

- **硬件平台**：AMD ZCU104评估板（Xilinx Zynq UltraScale+ XCZU7EV-2FFVC1156 MPSoC），Vitis HLS 2024.1与Vivado 2024.1，PYNQ运行时环境。
- **基准工作负载**：
  - **CNNImageProc**（视觉/CNN任务）：Fashion-MNIST图像分类CNN，划分为5个任务（conv1、relu_pool1、conv2、relu_pool2、dense），对应计算密集与数据密集混合结构。
  - **CAMC**（SDR任务）：基于棋盘格矩阵的自动调制分类，划分为3个任务（axis_initialisation、matrix_generation、array_product），涵盖控制、访存、矩阵运算行为。
- **用户设计目标（四种）**：约束延迟、通信感知分配、功耗优先、严格资源约束。每种目标对LUT/功耗设定不同的百分比约束阈值。
- **对比LLM**：GPT-5.6 Sol、Gemini 3.6 Flash、Claude Fable 5，三个LLM接收完全相同的输入配置。
- **对比基线**：全GPP实现与全FPGA实现，将Gen-TAS分配方案的延迟、资源与功耗相对于这两种极值进行比较。此外在表I中与已有的FPGA/FPGA-GPP划分方法（EcoSys、StreamBlocks、CariPy、SECDA-DSE）进行了定性对比。

- **充分性**：
  - 优点：覆盖多目标、多模型、多工作负载，且硬件实际部署验证而非仅仿真，结果具有较高的可信度；重复实验验证了生成稳定性。

## 6. 主要结论与发现

- **需求驱动有效**：Gen-TAS能根据不同的用户目标生成差异化的分配方案。以CNNImageProc为例，延迟目标下选择FFFFG实现2.45×加速，功耗目标下选择GGFFG将FPGA功耗降低15.9%但延迟上升；CAMC中则分别获得3.54×和92.53×的加速（后者为Gemini在通信感知目标下所选的全FPGA分区）。
- **稳定性好**：24个配置中，22个在≥4/5次运行中复现同一个主导Rank-1分区，其中15个为5/5完全一致；但某些配置（如Claude在CNN延迟目标下、GPT在CNN严格资源目标下、Gemini在CAMC通信感知目标下）一致性较差。
- **模型无关性**：不同LLM均能在统一RAG提示流下产生有效分配，但存在策略分歧，例如Gemini在CAMC通信感知目标下选择了全FPGA方案，而GPT和Claude选择了GFF。
- **可解释性与可复现性**：LLM生成的理由能够引用具体缓冲区大小、任务依赖关系和KB证据；后端确定性自动流程能将同一分区稳定复现到FPGA实现。

## 7. 优点

- **知识锚定（RAG）**：利用历史实现数据约束LLM的推理，防止随意/不落地的分配建议，提高策略可信度；
- **可解释分配**：LLM生成每个候选方案的结构化理由（依据计算量、通信缓冲、功耗资源等），促进设计者理解与信任；
- **人机协同+确定性后端**：将LLM的探索能力与人工判断、确定性工具链结合，实现较自然的端到端设计闭环；
- **多目标可定制**：自然语言设计目标直接输入，无需重新训练模型即可对不同目标生成对应策略；
- **跨LLM稳定**：实验在3种商业LLM上都验证了整体框架的有效性，说明方法具有通用性。

## 8. 不足与局限

- **实验覆盖有限**：仅CNN图像处理和SDR两类应用，未涉及更多样的嵌入式/边缘工作负载，通用性证据不够充分；
- **缺乏消融研究**：未剥离RAG、任务分析、验证步骤等模块来量化各自贡献，难以确定哪些组件是效果的关键；
