## 摘要
投机解码通过让轻量级草稿模型提出多个候选token，然后由更大的目标模型并行验证，从而加速自回归语言模型推理。然而，在第一次拒绝之后，标准的基于前缀的验证会丢弃剩余的草稿后缀，因此用于生成和验证这些位置的计算不会对解码进度产生贡献。我们以DFlash为例，表明被拒绝的后缀中的被拒绝位置仍可能与目标延续对齐，这表明草稿模型尽管存在局部token级错误，仍能保留有用的语义和结构信息。受这一观察的启发，并受到条件扩散的启发，我们引入了ReTrace，一种拒绝轨迹条件化方法，它使每个草稿块基于前一轮的被拒绝后缀进行条件化，而不是仅从新的掩码占位符生成。ReTrace保留被拒绝后缀的隐藏表示，将它们与下一个草稿块对齐，使用来自同一验证过程的目标感知校正信号对它们进行细化，并通过门控残差融合将它们纳入草稿器的输入嵌入中。由于被拒绝的token永远不会被提交，且目标端验证保持不变，ReTrace保留了投机解码的无损特性，而无需额外的模型前向传递。使用Qwen3模型在数学推理、代码生成和开放式对话方面的实验表明，与DFlash主干相比，ReTrace始终提高了平均接受长度和端到端解码速度。通过引入跨轮次条件化而不修改轮内提案生成，ReTrace在很大程度上与现有的草稿改进正交，并且可以与之结合以获得进一步的收益。

## Abstract
Speculative decoding accelerates autoregressive language model inference by having a lightweight draft model propose multiple candidate tokens, which are then verified in parallel by a larger target model. However, after the first rejection, standard prefix-based verification discards the remaining draft suffix, so the computation spent generating and verifying those positions does not contribute to decoding progress. Focusing on DFlash, we show that rejected positions in a rejected suffix may still align with the target continuation, indicating that the draft model can retain useful semantic and structural information despite local token-level errors. Motivated by this observation and inspired by conditional diffusion, we introduce~\textbf{ReTrace}, a rejected-trajectory conditioning method that conditions each draft block on the rejected suffix from the previous round rather than generating it from fresh mask placeholders alone. ReTrace retains the hidden representations of the rejected suffixes, aligns them with the next draft block, refines them using target-aware correction signals from the same verification pass, and admits them into the drafter's input embeddings through gated residual fusion. Because rejected tokens are never committed and target-side verification remains unchanged, ReTrace preserves the lossless property of speculative decoding without requiring an additional model forward pass. Experiments with Qwen3 models across mathematical reasoning, code generation, and open-ended dialogue demonstrate that ReTrace consistently improves average acceptance length and end-to-end decoding speed over its DFlash backbone. By introducing cross-round conditioning without modifying within-round proposal generation, ReTrace is largely orthogonal to existing drafting improvements and might be combined with them for further gains.

## 1. 论文的核心问题与整体含义（研究动机与背景）

- **背景**：投机解码（Speculative Decoding）通过轻量级草稿模型（draft model）生成多个候选 token，再由大规模目标模型（target model）并行验证，以此减少目标模型的自回归前向传播次数，从而加速 LLM 推理。
- **核心问题**：在标准的前缀验证机制中，一旦出现第一个不匹配的 token，草稿后缀（rejected suffix）中剩余的全部候选 token 和对应计算都会被直接丢弃。这些位置的计算已经产生，却无法转化为实际的解码进展，造成计算浪费。
- **关键观察**：论文以 DFlash（一种基于扩散模型的并行草稿器）为例，通过定性与定量分析发现——尽管被拒绝的后缀在局部 token 级别上存在错误（如重复、遗漏、预测错误），但这些位置可能重新与真实目标延续对齐，其隐藏表示中仍保留着关于目标延续的有用语义与结构信息。
- **整体含义**：被拒绝的草稿计算不应被简单丢弃，它可以被跨轮次地复用作为下一轮草稿的条件信号，从而提升投机解码的接受长度和端到端速度。该问题本质上是推理效率优化中的一个计算再利用（computation reuse）问题。

## 2. 论文提出的方法论

### 2.1 核心思想

ReTrace（**Re**jected-**Trace** Conditioning）受条件扩散模型启发，将上一轮验证中被拒绝的后缀隐藏状态视为一条"被拒绝轨迹"，将其作为下一轮草稿块生成的辅助条件。其核心原则是：

- 不改变轮内（within-round）的草稿生成方式；
- 不改变目标模型的验证规则与 token 提交过程；
- 不引入额外的模型前向传播，只复用标准草稿-验证流程中已经产生的隐藏表示；
- 保持投机解码的无损性（lossless）。

### 2.2 关键技术细节

**（1）被拒绝轨迹的构建与对齐**

- 在第 t 轮解码中，草稿模型生成 B 个候选 token 及其最终层表示：`{h^D_{t,1}, ..., h^D_{t,B}}`。
- 设目标模型接受的 token 数为 `A_t`，第一个被拒绝的位置为 `r_t = A_t + 1`。
- ReTrace 排除已接受的 token 表示（`h^D_{t,1:A_t}`）和第一次拒绝位置的表示（`h^D_{t,r_t}`，该位置由目标模型的校正 token 解决），仅保留被拒绝后缀中严格位于第一次拒绝之后的部分：`{h^D_{t,r_t+1}, ..., h^D_{t,B}}`。
- 将保留的状态对齐到下一轮草稿块的起始位置：
  ```
  m_{t+1,j} = h^D_{t,r_t+j},   1 ≤ j ≤ B - r_t
  m_{t+1,j} = 0,               B - r_t < j ≤ B
  ```

**（2）目标感知校正（Target-Aware Correction）**

- 对齐的被拒绝轨迹仅反映草稿模型的预测，可能带有失败路径的错误。
- ReTrace 利用同一轮验证中目标模型产生的表示进行校正：`u_{t+1,j}` 取目标模型在位置 `r_t + j - 1` 的最终层表示（因果模型中该状态负责预测位置 `r_t+j` 的 token）。
- 通过轻量级投影将草稿状态与目标状态配对并生成校正增量：
  ```
  c_{t+1,j} = W_c [m_{t+1,j}; u_{t+1,j}]
  r_{t+1,j} = m_{t+1,j} + β · c_{t+1,j}
  ```
- β 是校正强度系数，训练初期线性 warmup 至最大值（β_max = 1），保证优化稳定性。

**（3）门控残差融合（Gated Residual Conditioning）**

- 校正后的信号不应替代当前掩码输入，而是以门控残差形式注入草稿模型输入嵌入：
  ```
  ẽ_{t+1,j} = e_{t+1,j} + W_v · r_{t+1,j} ⊙ σ(W_g [e_{t+1,j}; r_{t+1,j}])
  ```
- 门控是向量值（vector-valued）的，逐维度控制信号的注入强度。
- `W_v` 初始化为零，使得初始状态下残差为零，草稿器从原始行为出发逐步学习条件化。

**（4）优化与推理**

- 训练时，缓存的和被复用的草稿/目标表示均被 detach（切断梯度），只优化当前轮的预测损失，目标模型冻结。
- 推理时，每个信号只保留一轮，之后被最新一轮的被拒绝后缀替换。
- 无需额外目标模型前向传播，目标端验证和提交逻辑不变。

### 2.3 与已有工作的关系

- 与 EAGLE 等自回归草稿器不同，DFlash 以并行方式生成整个块，早期局部错误不会自动污染后续所有状态，因此被拒绝后缀更适合跨轮复用。
- 与 Lyanna（Make Every Draft Count）不同，Lyanna 从可复用隐藏轨迹重新采样候选树并验证；ReTrace 不是让被拒绝状态直接产出候选 token，而是将其作为下一轮草稿的条件信号。

## 6. 论文的主要结论与发现

1. **被拒绝轨迹存在可复用的预测信息**：定量分析显示，30.4% 的被拒绝后缀位置上，目标 token 仍然是草稿模型的 top-1 预测，75.2% 落在 top-5 内；被拒绝的草稿隐藏状态与其真实目标延续的余弦相似度（0.351）显著高于随机窗口（0.128），表明存在延续特定的信息。
2. **ReTrace 能有效利用这些信息**：在 Qwen3-4B/8B 上，ReTrace 一致提升 DFlash 骨干的平均接受长度（+6.97%）和端到端加速比（+5.34%），且该提升在贪婪和随机解码下均成立。
3. **增益来自条件化而非额外训练**：以相同数据继续训练 DFlash 原始目标仅带来边际提升且快速饱和，ReTrace 的条件化机制则在训练中持续提升接受长度。
4. **开销极低**：条件化延迟仅 0.13 ms/cycle（0.40%），不增加额外目标模型前向传播，保持无损特性。
5. **与现有方法正交**：ReTrace 不加修改地叠加在 Domino 上仍能带来额外吞吐量提升，证实跨轮条件化与轮内草案改进可以互补。
6. **并发场景下依然有效**：在并发达 32 时，ReTrace 仍保持 1.62× 加速，优于 DFlash 的 1.50×，而 EAGLE-3 在并发 ≥8 时加速比降至 1 以下。

## 7. 优点

- **新颖的问题视角**：将投机解码中被丢弃的草稿计算重新定义为可跨轮复用的"条件信号"，而非简单地重新采样或缓存 token，这一视角为投机解码优化开辟了新方向。
- **方法设计精巧且工程友好**：
  - 只复用已有表示，不增加额外模型前向传播；
  - 门控残差 + 零初始化保证训练稳定性，模型从原始行为无缝过渡；
  - β warmup 进一步避免训练初期的优化扰动；
  - 信号生命周期仅一轮，实现简单且不会累积误差。
- **模块化与正交性**：ReTrace 不改动轮内草稿生成，因此可直接叠加到 DFlash、Domino 等任意改进之上，理论上还可推广到其他并行草稿器。
- **实验设计严谨**：包含预测信号分析（两层证据）、组件消融、训练对比、运行时分解、兼容性验证和并发实验，从多个维度验证了方法的有效性和实际可用性。
- **无损性保障**：由于被拒绝 token 不参与提交、目标模型验证规则不变，ReTrace 理论上完全保留了投机解码的无损特性。

- **模型范围有限**：仅在 Qwen3-4B/8B 上验证，未涵盖更大规模（如 32B/72B）或其他架构家族（如 Llama、Mistral），泛化性有待进一步验证。
