## 摘要
异构多芯粒加速器允许芯粒独立配置，以更好地匹配不同算子特征并提高推理效率。然而，异构性使得模拟器评估成本高昂，限制了硬件设计空间探索（HW-DSE）可承担的迭代次数。主流的数据驱动方法主要依赖最终指标和少量预定义状态，并且需要大量搜索迭代来隐式学习输入参数与优化目标之间的关系，因此在这种场景下效果不佳。在实践中，评估器还会生成关于执行时间线、资源利用率、内存访问和通信行为的详细报告。大语言模型（LLMs）可以将领域知识与这些报告相结合，显式地识别瓶颈位置、性能退化原因和参数调整方向，从而在有限的迭代预算内改进每个设计决策。基于这一观察，我们提出了Beacon，一种面向异构多芯粒HW-DSE的、报告驱动的LLM多智能体框架。Beacon采用分层智能体进行瓶颈定位、根因诊断和硬件候选生成，并结合分析工具箱和RAG记忆进行闭环搜索。在相同的有限迭代预算下，与随机搜索、贝叶斯优化和强化学习相比，Beacon将延迟-能耗-货币成本复合目标降低了25.1%--93.5%。

## Abstract
Heterogeneous multi-chiplet accelerators allow chiplets to be configured independently to better match different operator characteristics and improve inference efficiency. However, heterogeneity makes simulator evaluation expensive, limiting the number of iterations affordable for hardware design space exploration (HW-DSE). Mainstream data-driven methods rely mainly on final metrics and a few predefined states, and require many search iterations to implicitly learn the relationships between input parameters and optimization objectives, making them less effective in this setting. In practice, evaluators also generate detailed reports on execution timelines, resource utilization, memory accesses, and communication behavior. Large language models (LLMs) can combine domain knowledge with these reports to explicitly identify bottleneck locations, degradation causes, and parameter adjustment directions, thereby improving each design decision under limited iteration budgets. Based on this observation, we propose Beacon, a report-driven LLM multi-agent framework for heterogeneous multi-chiplet HW-DSE. Beacon employs hierarchical agents for bottleneck localization, root-cause diagnosis, and hardware candidate generation, together with an Analysis Toolbox and RAG memory for closed-loop search. Under the same limited iteration budget, Beacon reduces the composite latency-energy-monetary-cost objective by 25.1\%--93.5\% compared with random search, Bayesian optimization, and reinforcement learning.

## 2. 方法论：核心思想与关键技术细节

- **核心思想**：将HW-DSE组织为“决策—记忆—行动/观测”闭环。决策能力基于当前评估反馈生成下一搜索方向；记忆能力复用历史试验经验；行动/观测能力将搜索决策转化为可评估的硬件配置并获得反馈。
- **分层智能体框架（Agentic Search Engine）**：按硬件工程师的常见分析流程，将单次搜索决策分解为三个依次回答的问题：
  1. **模型级智能体（Model-Level Agent）**：回答“在哪里优化”，从全局执行视角比较当前、上一轮和最优配置，利用搜索上下文工具和全局分析工具，识别候选瓶颈层/算子组。它不提出硬件修改。
  2. **层级别智能体（Layer-Level Agent）**：回答“为什么是瓶颈”，对候选层进行计算、存储、通信三个维度的诊断，输出结构化的**瓶颈状态描述（BSD）**。
  3. **解决方案智能体（Solution Agent）**：回答“如何修改硬件”，将BSD与检索到的历史案例结合，使用硬件分析工具生成合法的新硬件候选。
- **ReAct风格交互**：每个智能体先通过交替“思考—工具调用—观测”收集证据，再进入最终综合阶段输出结构化JSON结果；工具调用受步骤预算约束，最终输出需通过校验。
- **分析工具箱（Analysis Toolbox）**：将评估报告、搜索状态、硬件配置封装为可调用工具，分为四类：
  - 搜索上下文工具：比较搜索状态、选择分析基准；
  - 全局分析工具：总结指标、构建执行时间线、聚合算子组、总结成本；
  - 层分析工具：层负载聚合、层细节检查、层排名视图；
  - 硬件分析工具：硬件配置总结、合法参数修改、邻域移动。
- **RAG记忆**：每个评估回合后构造“历史搜索案例”，以瓶颈键（BSD语义）和硬件键（硬件配置语义）拼接为检索向量，使用余弦相似度检索 top-5 相似案例，注入解决方案智能体上下文。检索公式可表示为：`v = [Emb(BSD); Emb(Hardware)]`。
- **评估器适配器（Evaluator Adapter）**：隔离底层模拟器格式，统一标准化指标与详细报告；将LLM输出的高层修改意图物化为合法硬件配置，并做重复检查。
- **硬件设计空间定义**：
  - 芯片数 `N ∈ 合法集合`，二维阵列形状由 `φ(N)` 确定；
  - 每个芯粒配置 `t_i = (c_i, b_i, d_i)`，分别代表计算能力、片上缓冲、数据流；
  - 系统参数 `z_sys = (z_hw, z_map)`，包括NoP/DRAM带宽等硬件参数和Tensor并行度/微批大小等映射参数；
  - 总设计空间 `Z = ∪_{N∈N} {N} × T^N × G`。
- **优化目标**：`O(z) = L(z)·E(z)·MC(z)·max(P(z), P_t)/min(P(z), P_t)`，其中L为延迟、E为能量、MC为货币成本，P为实际算力，P_t为目标算力；目标计算量要求被转换为对称的软惩罚。

## 6. 主要结论与发现

- **有效性**：在相同有限迭代预算下，Beacon相比最强传统基线，复合目标（延迟-能耗-货币成本）在64/512/2048 TOPS上分别降低**79.1%、77.0%、25.1%**；相比随机搜索、BO、RL，整体降低范围**25.1%--93.5%**。
- **发现的最优配置**：
  - 64 TOPS：2芯粒（1×2），WS×1 + OS×1，MAC=16K，GLB=8MiB，DRAM/NoP=16/32，TP=8，MB=64，MC仅$15.55；
  - 512 TOPS：8芯粒（2×4），WS×7 + OS×1，MAC=32K，GLB=8MiB，DRAM/NoP=16/32，TP=8，MB=32；
  - 2048 TOPS：32芯粒（4×8），WS×25 + OS×7，MAC=32K，GLB=16/32MiB，DRAM/NoP=64/128，TP=8，MB=32，MC=$593.69。
- **异构性设计规律**：并非OS芯粒越多越好，需要根据瓶颈层和成本反馈配置；大模型推理中WS数据流对QKV投影和FFN等权重重用型GEMM仍占主导，OS芯粒只用于注意力AV等特定形状计算。
- **搜索行为**：Beacon通常在前十几次迭代快速下降目标，然后进入精细化的成本与布局调整；能识别“资源过配”“TP与芯粒数不匹配”“带宽非瓶颈”等情况并分别调整。
- **LLM后端影响**：不同后端找到的最终设计质量大体可比且远优于非LLM基线；Gemini在本任务中目标最低（0.90×DeepSeek）且调用时间最短，但DeepSeek的API成本最低，是最经济的选择。
- **消融结论**：分层多智能体贡献最大（单智能体目标变为1.499×），RAG记忆次之（1.301×），ReAct范式也有效（1.159×）。
- **开销特点**：Beacon将LLM分析开销与模拟器评估时间控制在同一量级，而评估器仍是主导开销。

## 7. 优点

- **问题切入独特**：与现有LLM芯片设计工作关注EDA流程自动化不同，本文聚焦**架构级组合优化**，填补了LLM智能体在HW-DSE场景的空白。
- **报告驱动而非标量驱动**：将每次评估从“最终指标”扩展为“可诊断证据”，使单次评估能产生更直接的决策指导。
- **分层智能体设计**：将搜索决策拆解为“哪里—为什么—怎么改”，降低上下文压力，提高决策可解释性和可追溯性。
- **工程实现完整**：分析工具箱、RAG记忆、评估器适配器共同构成闭环，工具输出紧凑结构化，LLM只负责证据选择和决策推断，硬件合法性由确定性流程保证。
- **实验设计较全面**：覆盖多种算力量级、多种LLM后端、多种消融变体，并给出搜索轨迹分析和开销分析；对比基线从同一初始点、同一动作空间出发，保证了公平性。
- **应用潜力**：框架与具体模拟器解耦，只要评估器能返回标准化指标与报告即可接入，便于扩展到其他加速器仿真环境。

## 8. 不足与局限

- **模拟器单一性**：仅用修改后的GEMINI进行验证，缺乏多个模拟器或真实流片/硬件验证，结论的泛化能力有待确认。
- **缺乏多次重复与统计显著性**：未报告多次独立运行的标准差或置信区间，LLM的采样随机性和工具调用顺序可能影响结果稳定性。
- **LLM后端依赖**：不同后端质量、成本差异大（如Claude成本为DeepSeek约45倍），实际部署时对后端选择敏感；且论文的评估基于设定任务，未测试更多任务。
- **实验规模受限**：虽然100轮反映了“有限预算”，但未系统研究不同预算（如10轮、50轮、200轮）下的性能表现；也未比较离线代理模型方法（论文以需要大量训练数据为由排除，但可视为一种局限）。

- **成本与收益分析不完整**：论文虽报告了各LLM后端的API费用（如DeepSeek仅约4.94美元），但未系统对比“LLM分析开销+API成本”与“搜索目标改善量”之间的综合性价比，也未评估token消耗随搜索轮次的累积增长对总成本的长期影响。对于预算紧张的场景，是否值得为额外的1%目标改善支付更高后端调用费，缺乏严谨的量化论证。

- **LLM幻觉与推理可靠性未充分验证**：虽然最终硬件修改由确定性适配器校验合法性，但中间智能体对执行时间线、瓶颈状态的解读可能产生与模拟器事实不符的表述。这些问题导致其在完整提示词层面的解码复杂度不低（要求模型理解复杂系统架构），并未系统分析错误解读是否会被后续智能体传播放大。理想情况下应设计人工/自动审计机制，但论文未提供相关分析。

- **串行搜索流程限制了扩展性**：Beacon的搜索过程按轮次串行执行——每轮先完成完整评估，再由三个智能体顺序推理，最后产出下一个配置。论文未讨论若引入并行评估（同时评估多个候选项）或多采样策略，是否能进一步压缩总时长或提升探索多样性，也未分析异步更新对搜索轨迹的影响。

- **可复现性细节仍显不足**：论文虽展示了框架架构，但未公开各智能体的Prompt模板、BSD字段的完整定义与序列化格式、工具输出截断规则、RAG嵌入模型的具体选择、相似度阈值、各智能体的步骤预算分配等工程细节。对实际复现者而言，这些细节与最终性能强相关，缺失会增加复现难度。

## 9. 总结与展望

- **总结**：本文提出的Beacon是一个将LLM多智能体、RAG记忆、ReAct推理引擎和评估器适配器系统集成的报告驱动HW-DSE框架。与传统黑盒搜索方法不同，Beacon不把每个评估样本视为标量损失，而是让LLM基于细粒度执行报告进行“哪里优化—为什么是瓶颈—如何改硬件”的分层诊断，从而实现更高质量的单步搜索决策。在100轮有限评估下，其在三种算力规模上均大幅超越随机搜索、BO和RL基线，且通过消融实验证明分层智能体架构、RAG记忆和ReAct动态决策均贡献显著。该工作明确了LLM智能体在架构级硬件设计空间搜索中的独特优势——基于证据的推理能力代替隐式的数值代理建模，为后续LLM驱动的芯片设计自动化研究提供了新范式。

- **展望**：后续研究可在以下方向拓展：（1）将Beacon接入多种模拟器（如Timeloop/Accelergy、多晶粒仿真前端）乃至真实硬件原型，以验证跨平台泛化能力；（2）在多个随机种子下重复实验，报告均值与置信区间，消除LLM抽样随机性的疑虑；（3）将分层推理流程蒸馏至更小、更便宜的开源模型，降低后端API依赖成本；（4）探索异步并行搜索策略，在不增加LLM调用次数的前提下通过批量评估缩短端到端时长；（5）进一步解耦优化目标，将延迟-能耗-成本三目标从软惩罚合成扩展为Pareto前沿探索，让设计者在不同约束下获得候选集。

整体而言，尽管存在验证范围单一、统计严谨性不足、复现细节未完全公开等局限，本文的框架设计、实验结论和消融分析均具有较高的可信度与启发价值，是LLM智能体应用于硬件设计空间探索领域的一个重要且踏实的工作。
