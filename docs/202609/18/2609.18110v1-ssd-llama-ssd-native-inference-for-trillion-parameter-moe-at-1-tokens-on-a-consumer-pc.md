## 摘要
前沿开放权重语言模型越来越多地采用混合专家（MoE）架构，以扩展模型容量，同时每个 token 仅激活一小部分专家。然而，本地推理仍必须保留完整的专家池，即便经过量化，这仍远超消费级 RAM 和 VRAM 的容量。SSD 在此规模下提供了实用的容量，但要将这种容量转化为可执行的模型内存，需要高效的专家交付、对 SSD、RAM 和 VRAM 的协同管理，以及在受限带宽下的 CPU-GPU 混合执行。我们提出 SSD-LLaMA，一个 SSD 原生的本地 MoE 推理系统，通过针对专家交付优化的 SSD I/O 流水线、动态交付并保留专家的原生三级存储层次，以及均衡的 CPU-GPU 混合执行来应对这些挑战。SSD-LLaMA 执行每一个被选中的专家，不进行剪枝或替换。在三个前沿 MoE 模型系列上，相较于所评估的基线，SSD-LLaMA 将预填充 token 速率提升 1.52×–4.19×，将解码 token 速率提升 2.10×–15.58×。我们还使用单张 RTX 5090 且不超过 32GB RAM 运行万亿参数模型，达到高于 1 token/s 的速度。

## Abstract
Frontier open-weight language models increasingly use Mixture-of-Experts (MoE) architectures to expand model capacity while activating only a small subset of experts per token. Local inference must nevertheless keep the complete expert pool available, which remains far beyond consumer-grade RAM and VRAM capacity even after quantization. SSDs provide practical capacity at this scale, but turning that capacity into executable model memory requires efficient expert delivery, coordinated management of SSD, RAM, and VRAM, and CPU--GPU hybrid execution under bounded bandwidth. We present \textit{SSD-LLaMA}, an SSD-native local MoE inference system that addresses these challenges with an SSD I/O pipeline optimized for expert delivery, a native three-tier storage hierarchy that delivers and retains experts dynamically, and balanced CPU--GPU hybrid execution. \textit{SSD-LLaMA} executes every selected expert without pruning or substitution. Across three frontier MoE model families, \textit{SSD-LLaMA} improves prefill token rate by 1.52$\times$--4.19$\times$ and decode token rate by 2.10$\times$--15.58$\times$ over the evaluated baselines. We also achieve higher than 1 token/s for running trillion-parameter model with a single RTX 5090 and no more than 32GB RAM.

## 1. 核心问题与整体含义（研究动机与背景）

- **背景趋势**：前沿开放权重语言模型（如 DeepSeek-V4、Kimi-K2.7/K3、GLM-5.2）普遍采用 MoE 架构，总参数量已达万亿级（Kimi-K3 达 2.8T），但每个 token 仅激活一小部分专家（如 DeepSeek-V4-Flash 激活 13B/284B，Kimi-K2.7-Code 激活 32B/1T）。
- **核心矛盾**：MoE 的稀疏激活减少了计算量，但**完整专家池必须常驻可用**。即便 4-bit 量化后，专家池仍远超消费级 RAM/VRAM 容量（如 Kimi-K3 量化后仍需 >1TB 存储）。
- **硬件转折点**：PCIe 5.0 SSD 顺序带宽已达 14.8 GB/s，略高于单通道 DDR3-1600（12.8 GB/s），且每 GB 成本远低于 DRAM（约 $0.34 vs $14.75/$62.47），使 SSD 成为实用后备存储层。
- **三大设计缺口**：
  1. **SSD I/O 低效**：原模型布局将单个专家分散在多个张量/文件区域，mmap 触发缺页、访问碎片化、难以打满 SSD 带宽。
  2. **缺乏统一存储层级管理**：现有系统要么静态放置、要么单路径预取；预取只能回答"取什么"，无法回答"保留什么"，且预测正确也仅能隐藏约 5% 传输延迟。
  3. **CPU-GPU 负载失衡**：RAM 常驻专家被绑定到 CPU 执行，而激活专家占每 token FFN 计算的 85.7%–87.4%，导致 CPU 成为瓶颈、GPU 空转。
- **目标**：在**单张 RTX 5090 + ≤32GB RAM** 的消费级 PC 上，无剪枝/替换地运行万亿参数 MoE，并达到 1+ token/s。

## 2. 方法论：核心思想与关键技术

**核心思想**：将 SSD、RAM、VRAM 视为一个贯穿推理全过程的动态专家流水线，而非分离的存储层。

### G1：高效 SSD I/O 流水线（Section 4.1）
- **Expert-Pack 布局**：离线无损重排，将每个 (layer, expert) 的 gate/up/down 三个张量背靠背放入一个对齐块；通过 manifest 记录专家 ID → 偏移、长度、张量边界、权重格式；运行时一次 manifest 查找 + 一次 O_DIRECT 请求即可取回整个专家。
- **无损压缩与 CUDA 解码**：对每个张量用离线构建的熵表做 rANS 编码（scale 数据单独压缩）；GPU 执行时压缩权重经 H2D 传输后由 **CUDA rANS 解码器直接解压到 VRAM 缓存槽**，避免 CPU 解压和额外未压缩拷贝。SSD 流量从 8.89 降至 5.93 GB/token（−33.2%）。
- **异步投递**：持久化 io_uring worker 以有界批提交多个独立读请求；读完成即异步 H2D 到预留 VRAM 槽，不必等待整批完成；固定 pinned buffer 池提供背压；每个专家独立就绪状态，整层专家就绪后以批量 kernel 统一发射。

### G2：原生 SSD–RAM–VRAM 三层缓存（Section 4.2）
- 以**完整专家（gate-up-down 块）**为缓存粒度，SSD 存完整专家池，VRAM/RAM 作为有界缓存。
- 保留策略基于**访问频次 + 最近使用时间**：VRAM 缓存高频复用专家，RAM 缓存较低频专家；冷访问使用临时 VRAM 槽，避免单次冷访问驱逐热专家；VRAM 满时按"低频 + 久未使用"驱逐，被驱逐者若 RAM 有空间则降级保留；RAM 满时按 LRU 驱逐。
- 权重不可变，**无需写回 SSD**；两个缓存均为固定内存上限。

### G3：CPU–GPU 均衡混合执行（Section 4.3）
- **权重驻留与执行位置解耦**，在专家粒度上选择执行设备。
- 决策依据端到端 token 延迟（涵盖计算、H2D、调度、同步），在相同缓存容量与 SSD 负载下对比候选划分。
- **Prefill 优化**：将同一专家的所有 prompt 行分组为一个任务，放入共享工作队列，worker 动态领取，使专家权重"加载一次、服务多行"，避免重复读取。
- 实测结论：在评估平台上，**全 GPU 路径最优**（513.95 ms vs 分 1–6 个专家到 CPU 的 529.52–573.73 ms），故实际采用全 GPU 执行专家，CPU 负责 I/O 提交、缓存管理、缓冲调度与传输协调。

### 正确性保证
不剪枝、不替换选中专家、不修改路由权重；expert-pack 变换与压缩均无损；RAM/VRAM 固定容量、不丢弃任何选中专家。
