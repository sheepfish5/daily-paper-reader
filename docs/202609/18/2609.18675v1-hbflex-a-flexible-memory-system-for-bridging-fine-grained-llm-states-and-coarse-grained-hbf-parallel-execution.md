## 摘要
大语言模型（LLM）需要不断增长的内存容量，以容纳日益增长的模型权重和KV缓存。高带宽闪存（HBF）通过大规模平面级并行提供高内存密度和聚合读带宽，使其成为LLM服务的一个有吸引力的选择。然而，完全从HBF服务LLM会带来三个挑战：细粒度KV读取造成放置和访问不均衡，增量写入干扰前台读取，以及混合KV生命周期放大垃圾回收。混合HBM/HBF设计保留HBM以支持动态KV管理，但这种分配减少了固定封装预算下可用的HBF资源，限制了聚合HBF带宽。我们提出HBFlex，一种全HBF内存系统，针对KV读取、写入和回收进行了协同优化。HBFlex平衡KV放置和注意力访问，以提高平面利用率。它聚合增量更新，并在足够长的计算窗口内调度回写，以减少写-读干扰。它还将生命周期引导的块打包与延迟回收相结合，以减少有效页迁移。我们通过跨不同配置的踪迹驱动模拟评估HBFlex。HBFlex实现了平均吞吐量加速，相比FlashAccel最高达1.58×，相比H3最高达3.30×，这得益于更高的HBF带宽以及对动态KV缓存读取、写入和擦除的更高效管理。

## Abstract
Large language models (LLMs) require increasing memory capacity to accommodate growing model weights and KV caches. High-Bandwidth Flash (HBF) offers high memory density and aggregate read bandwidth through massive plane-level parallelism, making it an attractive option for LLM serving. However, serving LLMs entirely from HBF introduces three challenges: fine-grained KV reads create placement and access imbalance, incremental writes interfere with foreground reads, and mixed KV lifetimes amplify garbage collection. Hybrid HBM/HBF designs retain HBM to support dynamic KV management, but this allocation reduces the HBF resources available under a fixed packaging budget, limiting aggregate HBF bandwidth.   We present HBFlex, a full-HBF memory system with coordinated optimizations for KV reads, writes, and reclamation. HBFlex balances KV placement and attention accesses to improve plane utilization. It aggregates incremental updates and schedules writeback within sufficiently long compute windows to reduce write--read interference. It also combines lifetime-guided block packing with deferred reclamation to reduce valid-page migration. We evaluate HBFlex through trace-driven simulation across different configurations. HBFlex achieves average throughput speedups of up to 1.58$\times$ over FlashAccel and 3.30$\times$ over H3, benefiting from higher HBF bandwidth and more efficient management of dynamic KV-cache reads, writes, and erases.

## 2. 方法论

### 2.1 核心思想

- **全 HBF 封装**：将整个封装内存预算给 HBF，不保留 HBM，以最大化 KV 容量和 plane 级并行带宽。
- **Base-die SRAM 缓冲**：用 base die 上 SRAM 承担 HBF 读预取、decode KV 写回、hot-plane offload、GC 迁移等临时数据。
- **Prefill 与 decode 共置**：不做 prefill-decode 分离，而是让 prefill 计算提供较长的“无 HBF 读窗口”，用于排空 decode KV 写。
- **四类粒度解耦**：
  - 逻辑 KV page：运行时分配与前缀复用单位；
  - 物理 stripe：跨互补 plane 的相邻物理页组；
  - work tile：一个 attention CTA 消费的 KV 子集；
  - erase block：NAND 回收单位。

### 2.2 三项关键机制

- **HBF-aware KV placement and scheduling**
  - 将 HBF plane 划分为 Plane Group，在组内把相邻物理页条带化到不同 plane，提高并行度，同时不增大逻辑页大小。
  - 对高频共享前缀做多 PG 复制，使运行时可将前缀读重定向到负载较低的副本。
  - 运行时读均衡：将热 plane 上的超额 KV 页缓存到 base-die SRAM；按 plane 负载调度 attention chunk，贪心选择覆盖更多不同 plane 的 KV chunk，并优先复用同一请求的 query 向量。
- **Window-aware KV writeback**
  - decode 新生成 KV 先缓存在 base-die SRAM，不立即写 HBF。
  - 预取连续算子的权重到 SRAM，使计算背靠背执行，形成更长的 HBF-free 窗口。
  - 优先在 prefill 期间批量排空 decode KV 写；接近 SRAM 容量时强制写回并短暂停顿 decode，保证缓冲有界。
- **Lifetime-aware KV reclamation**
  - 将同一请求不同 Transformer 层的 KV 页尽量打包到同一 erase block，因为其生命周期相关。
  - 用 root request 起始时间估计请求系列的生命周期相似性，并传播 lifetime label 给后代请求及 KV 页。
  - 分配时优先选择 lifetime label 匹配的半满 block；分离 KV eviction 与物理回收：90% 利用率触发 eviction，95% 触发 GC，让更多页先失效再回收，降低有效页迁移。
