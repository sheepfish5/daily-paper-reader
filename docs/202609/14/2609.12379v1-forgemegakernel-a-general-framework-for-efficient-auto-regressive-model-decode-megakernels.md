## 摘要
自回归模型解码受带宽限制，因为每生成一个 token，所有权重以及键/值缓存字节都需要通过高带宽内存传输一次。巨内核是一种理想方案，但现有的自动巨内核生成方法无法同时实现跨模型的泛化能力和正确性保证。我们提出 ForgeMegakernel，它利用编码智能体为每个模型生成高性能解码巨内核。ForgeMegakernel 将一个包含十个渐进式里程碑的通用知识库与独立的中间状态测试预言相结合。这些里程碑给出了巨内核的结构特性：为每个 SM 提供细粒度指令流，用依赖计数器替代全局同步，以及使用共享内存缓冲池在 SM 之间平衡负载并提高并行度。测试预言会推导出巨内核的中间状态，并在生成过程中检查性能、错误和精度，从而保证所锻造出的巨内核正确且可信。我们在涵盖 0.6B-13B 参数的八个模型系列中的 14 个代表性解码操作上评估了 ForgeMegakernel。生成的巨内核达到了 50.5-85.9% 的 MBU，并在相同配置下相比 SGLang 0.5.18 取得了 1.21 倍的几何平均加速，相比一个巨内核编译器取得了 1.54 倍的几何平均加速。在 SGLang 内部，使用长度不一的提示在 GSM8K 上评估时，所有 14 个巨内核在答案准确率相当的情况下，解码速度均快于 SGLang 引擎。

## Abstract
Auto-regressive model decode is bandwidth-bound, since every weight and key/value-cache byte crosses high-bandwidth memory once per token. A megakernel is an ideal solution, but existing automatic megakernel generation approaches cannot achieve both generalization across models and correctness guarantees.   We present ForgeMegakernel, which generates a per-model high-performance decode megakernel using coding agents. ForgeMegakernel pairs a universal knowledge base of ten progressive milestones with an independent mid-state test oracle. The milestones provide the megakernel's structural properties: a fine-grained instruction stream for each SM, dependency counters replacing the global synchronization, and a shared-memory buffer pool for workload balance across SMs and greater parallelism. The test oracle derives the mid-states of the megakernel and checks the performance, error and precision during the generation process, guaranteeing a correct and trustworthy forged megakernel.   We evaluated ForgeMegakernel on 14 representative decoding operations across eight model families spanning 0.6B-13B parameters. The generated megakernels achieved 50.5-85.9% MBU and geometric mean speedups of 1.21x over SGLang 0.5.18 and 1.54x over a megakernel compiler under identical configurations. Inside SGLang, evaluated on GSM8K with ragged prompts, all 14 megakernels decoded faster than the SGLang engine at comparable answer accuracy.

# ForgeMegakernel 论文总结

## 1. 核心问题与整体含义

- **背景**：自回归模型解码是带宽受限（bandwidth-bound）任务。每生成一个 token，所有权重与 KV 缓存字节都需经 HBM 传输一次；算术强度接近 1 FLOP/byte，GPU 计算单元大量空闲。
- **现有瓶颈**：vLLM、SGLang 等引擎按算子逐个启动 kernel，H100 上每 token 需 280–448 次启动，其中约 158 次是 RMSNorm、RoPE、KV-store 等小 kernel，中间值反复经 HBM↔共享内存搬运，占每 token 延迟约五分之一。
- **巨内核（megakernel）的潜力与困境**：手写 megakernel 可达 H100 带宽的 74–78%，但缺乏可复用性，适配新模型需数周专家工作。自动生成路线分两类：
  - **编译器路线**（如 MPK）：规则固定，跨 cell 覆盖有限，遇规则外形状性能骤降。
  - **智能体路线**：无结构指导时生成的 kernel 普遍慢于 SGLang（几何平均仅 0.75×）。
- **两大挑战**：
  - **挑战 1**：如何构建一个支持智能体泛化、不含模型特定参数、又足够精确以指导实现与验证的知识库。
  - **挑战 2**：融合内核隐藏了中间状态，仅检查最终 logits 无法定位错误；若由智能体自行定义检查，标准不可信、可被绕过。
- **整体含义**：论文提出 ForgeMegakernel，用编码智能体 + 通用里程碑知识库 + 独立中间态测试预言，为任意自回归模型自动锻造高性能、可信的解码巨内核。

## 2. 方法论

### 2.1 核心思想
- 将“保持计算正确性”与“重组执行以保持 GPU 忙碌”分两步：先逐算子到完整解码器建立正确性，再融合为单次持久协作启动的 megakernel。
- 把性能调优分解为三个结构性义务：
  1. **每 SM 指令流**（what each SM executes）：主机把解码器编译为带操作数描述符的类型化指令，每 SM 一条流，内核内解释器分发；提供调度自由度，但本身不消除等待。
  2. **依赖计数器**（when that SM may proceed）：用生产者/消费者计数器替代 grid-wide barrier，将调度自由度转化为独立推进。
  3. **共享内存缓冲池**（where operands are staged）：缓冲区生命周期跟随指令，使第 k+1 条指令的加载与第 k 条的存储重叠。
- 三者分别覆盖“分配工作、排序工作、承载操作数移动”，共同构成充分性；但不保证具体带宽数值，仍需调优调度平衡、指令粒度与预取距离。

### 2.2 十里程碑知识库（M0–M9，Table 1）
- **M0–M4 功能前缀**：工具链、单算子、融合层、L 层堆栈、真实 checkpoint 解码，均对 float64 golden 验证。
- **M5 巨内核**：单次持久启动、无库调用，检查启动次数与禁用调用，确保 LM head 也在核内。
- **M6 指令流**：每 SM 指令流 + MBU 下限，要求 ≥5 种指令类型、每层 ≥6 条指令、队列不均衡 ≤1.35×均值。
- **M7 无栅栏**：依赖计数器 + MBU 下限，要求 0 个 grid-wide barrier、≥4L 个不同计数器、busy_frac ≥0.85、tail_spread ≤0.05（由 `%globaltimer` 时间线读取，与 CUDA-event 延迟偏差 ≤25%）。
- **M8 缓冲池**：共享内存缓冲池 + MBU 下限，源扫描确认分配。
- **M9 稳定性**（可选）：1000 步贪心运行无 NaN/Inf，相对 bf16 参考漂移 ≤5 个位置，并可自由跑到 4000 token，针对索引溢出、缓冲池碎片与计数器回绕。
- 里程碑只规定结构属性与 MBU 下限，不含模型特定参数；层数、头数、batch 等常量由智能体从模型维度推导。

### 2.3 中间态测试预言（Oracle）
- **三类互补测量 + 功能检查**（Algorithm 1）：
  1. **字节核算性能**：主机从模型配置算出每步字节数 B(b,S)（含激活参数、KV 访问、embedding 行），延迟用两点斜率 t = min_r [t_r(80) − t_r(16)]/64 消除 prefill 与长度无关开销；MBU = B(b,S)/(t·β_peak)。用 Nsight Compute 测实际字节，定义读放大 ρ，MBU ≤ ρ⁻¹（ρ=1.4 时上限约 71.4%），并强制 MBU ≤100%。
  2. **float64 参考误差**：对每层 KV 缓存（唯一必须落全局内存的中间态）与最终 logits 与 float64 前向对比。KV 距离用式 (4) 的相对误差 δ；logits 用式 (5) 在 golden top-64 上的 log-softmax 距离 ε。判据：C < 2B（KV），ε(K) ≤ 5D、ε(K) ≤ ε(SGLang)、ε_max(K) ≤ 2ε_max(SGLang)。
  3. **精度契约**：仅算子边界用 bf16，算子输入到输出之间（含累加器、norm gain、rotary table）保持 fp32。用式 (6) 回归 α = ⟨K−A, d⟩/⟨d, d⟩，α ≤0.5 通过，单位即所测偏差，无需校准。
- **三项无容差功能检查**（M5 起）：logits 有限性；KV 读边界（用 σ=100 噪声毒化写游标之后的 KV 区域，logits 须逐位不变）；每 lane 位置检查（各 lane 按各自分配位置解码，而非广播 lane 0）。
- **防篡改设计**：所有字节数、容差、float64 参考与算术宽度在 kernel 存在前由主机配置确定并哈希下发；门控不得重算；智能体仅可写 kernel 源码与笔记，修改评估器即回滚；无 float64 家族时弃权而非通过。

### 2.4 端到端生成框架
- 每轮以**全新上下文的 headless 编码智能体**开始，接收里程碑矩阵、当前里程碑、上一轮门控摘要与规则，编辑 kernel → 在 H100 上构建测量 → 保留或回滚 → 追加账本并提交。
- 只有测量值跨轮传递；每轮记录假设、代码 diff、结果、决策。
- **Review 轮**：门控只读行为，故通过后由另一个新智能体审计 diff 与 run id，查三类缺陷（越权写入、为门控输入特判获得的指标、预处理器常量显示从未编译的优化）；里程碑推进需门控通过 + review 通过。
- **部署**：作为 SGLang model class 实现 `forward(EXTEND)`（单 token 循环）与 `forward(DECODE)`（批量步），复用同一 scheduler/sampler/内存管理/detokenizer。
